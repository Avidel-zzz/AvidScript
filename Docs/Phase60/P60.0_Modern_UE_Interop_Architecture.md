# Phase 60 现代 UE 互操作架构

> 状态：架构冻结候选 v1  
> 主线：C# -> Roslyn -> descriptor/type graph -> prepared route -> UE Reflection  
> 范围：Interface、完整 Delegate、脚本默认参数、Blueprint 新声明函数、通用异步动作

## 1. 目标

Phase 60 补齐开发小型游戏时最常遇到的 UE 互操作缺口，同时保持 AvidScript 已建立的
WASM-first、ObjectHandle、Session-owned 和 backend-neutral 约束：

- C# 可对实现某个 `UInterface` 的任意 UObject 做检查、转换和接口函数调用；
- 动态单播与多播委托可订阅、解绑、执行或广播，并支持既有 ref/out 事务；
- C# 脚本定义的 `UFunction` 可把 C# 可选参数发布为真实 UE 默认参数元数据；
- Blueprint 图中新声明的 callable/event UFunction 可进入同一生成式调用与 handler 链；
- UE latent function 和 Blueprint async action 通过通用模式生成 awaitable，不逐个手写 API；
- 热路径不遍历反射、不解析 JSON，并为 interface/Blueprint 动态派发建立小型调用缓存。

本阶段不把现有能力重新实现一遍。以下基础已经存在并直接复用：

- UE 原生反射函数的 `CPP_Default_*` 采集、descriptor/hash 和 C# facade 默认参数；
- 多播事件的 Session-owned subscription、token、reload/teardown 清理和 ref/out 输出事务；
- 任意 reflected UFunction 的 prepared codec、ObjectHandle 与 `ProcessEvent` 语义调用；
- latent completion provider registry、`AvidDelayAwaitable`、payload awaitable 和受控 CPS；
- C# 脚本类型生成、稳定 ordinal、UHT shell、Blueprint 子类与 WASM 实例路由。

## 2. 不做什么

- 不为 `AActor`、`UWorld` 或项目 UFunction 逐个写 C++ wrapper；
- 不把 CLR delegate、`Task`、GC 或反射运行时嵌入 UE；
- 不绕过 UE 的 `ProcessEvent`、Blueprint override、RPC callspace 或 delegate 所有权；
- 不在热路径按字符串扫描 UFunction/FProperty；首次动态 class 命中允许冷缓存填充；
- 不宣称所有非动态原生 C++ delegate 都可由 Reflection 发现；非 UPROPERTY delegate 不属于 UE
  反射表面；
- 不在 P60 完成 Shipping、移动端 AOT、调试器或跨框架最终性能领导力，它们分别属于后续阶段。

## 3. 统一能力模型

### 3.1 Receiver compatibility

所有 UObject receiver 校验收敛为一个公共规则：

```text
class receiver     => Object->IsA(ExpectedClass)
interface receiver => Object->GetClass()->ImplementsInterface(ExpectedInterface)
```

descriptor 继续保存稳定 class path 和 object type ordinal。接口仍使用两个 32-bit cell 的
ObjectHandle ABI，不把 `FScriptInterface` 指针暴露给 guest。`avid_object_type_is_a`、prepared function
receiver、参数/返回 codec 和 delegate source 必须使用同一 compatibility helper，防止不同入口语义漂移。

`FInterfaceProperty` 在 native frame 内由 codec 构造或读取 `FScriptInterface`，guest 侧仍是类型化的
只读 handle struct。空值为 `(0, 0)`；非空值必须同时通过 generational handle 和接口实现检查。

### 3.2 Interface dispatch cache

接口调用不能直接假设 interface declaration UFunction 就是目标类最终实现。prepared route 冻结：

- interface class；
- function name 与签名指纹；
- codec program；
- 一个小型 polymorphic inline cache（PIC）。

首次遇到 concrete `UClass` 时通过 `FindFunctionByName` 解析 UE 最终函数，验证 owner 实现接口和签名兼容，
再缓存 `{ConcreteClass, ResolvedFunction}`。常见单态调用只做 class pointer 比较；PIC 溢出才走 class function
map，并记录 instrumentation。Blueprint reinstance、package reload 或 route generation 变化会整体丢弃旧计划。

### 3.3 Script UFunction default contract

UE 原生函数默认参数已经完整支持。P60 只新增 C# 脚本声明方向：

```csharp
[UFunction(BlueprintCallable = true)]
public void Launch(float speed = 1200.0f, bool homing = false)
```

Semantic 将每个可选参数规范化为 `{ordinal, name, type_id, kind, canonical_value}`。只允许能无损映射到
UHT metadata 的编译期常量：bool、整数、有限浮点、enum、string；不支持的默认值 fail-closed，而不是
静默删除。默认参数必须是尾部连续区间，不能用于 `ref/out`。

生成 shell 以 `CPP_Default_<Name>` 元数据发布默认值；该合同进入 semantic artifact、generator manifest、
native structure fingerprint、generation key 和 reload classification。方法体调用中的省略参数继续由 Roslyn
绑定为常量，不增加 Runtime ABI 分支。

## 4. Delegate value system

### 4.1 一个签名计划，两种存储策略

现有 `FAvidScriptPreparedDelegateEvent` 升级为共享 delegate signature plan：

- `FDelegateProperty`：singlecast；
- `FMulticastDelegateProperty`：multicast；
- 参数、return、ref/out 统一使用 prepared codec；
- callback 与 guest 主动 invoke 使用同一 ABI layout 和输出事务。

delegate kind 是 descriptor identity 的一部分，不能在 reload 时从 singlecast 变成 multicast。

### 4.2 订阅与所有权

多播沿用 `AddDelegate/RemoveDelegate`。单播使用显式 lease：

1. bind 前捕获当前 `FScriptDelegate` 和 property mutation serial；
2. 脚本 bind 以 Session bridge 替换当前值；
3. unbind 只在属性仍指向自己的 bridge 时恢复旧值；
4. 若外部系统已改写，脚本只释放自己的 bridge，不覆盖新 owner；
5. reload、EndPlay、world teardown 和 failed candidate 走同一清理顺序。

同一 Session 对一个 singlecast property 默认只允许一个 active script lease。重复 bind 必须显式 replace，
不能悄悄覆盖。

### 4.3 Callback 与主动调用

C# handler 继续使用 `[AvidEvent(AvidEvents.X)]`，避免 CLR delegate 和 function pointer。Facade 生成：

- multicast `SubscribeX(source)` / `BroadcastX(source, ...)`；
- singlecast `BindX(source)` / `ExecuteX(source, ...)`；
- `AvidSubscription.Cancel()` 统一解绑。

主动调用不是按 API 手写 wrapper，而是 descriptor 为每个已选择 delegate 生成稳定 ordinal 和 typed host
import。Runtime 由 ordinal 取 prepared property/signature plan，再调用 UE delegate storage。return/ref/out 在
guest 输出全部预检后一次提交；trap 或 capability 失败时回滚新借用的 handle/value token。

## 5. Blueprint 新声明函数

### 5.1 出站调用

Profile 可显式选择 `UBlueprintGeneratedClass` 自己声明的 `BlueprintCallable`/`BlueprintPure` UFunction。
生成器保存资产 class path、function identity、bytecode/signature fingerprint 和 owner generation。Runtime
仍通过 prepared `ProcessEvent` 调用，让 Blueprint override、graph bytecode 和 latent 行为由 UE 决定。

Blueprint function 不进入 native direct 或 generated-native fast path。它使用与 interface 相同的 concrete
class PIC，避免每次名称查找，同时在 reinstance 后 fail-closed 地重建计划。

### 5.2 入站 handler

现有 RPC/RepNotify handler registry 扩展为显式的 Blueprint event lane。只允许 Profile 精确选择、由目标
Blueprint class 自己声明、具有 bytecode 的 event/function；`replace/before/after`、重入 FIFO、最大深度、
原 thunk 所有权和 teardown 规则不变。

同一函数不能同时作为脚本出站调用和 `replace` 入站 handler，除非声明 `before/after` 且通过递归保护；
否则生成阶段拒绝，以免脚本调用自己形成隐式递归。

## 6. 通用异步动作

### 6.1 Latent UFunction

现有 reflected latent UFunction 已可生成 `AvidDelayAwaitable` 或 provider payload awaitable。P60 只补齐
接口/Blueprint owner、默认参数和通用类型后形成完整路径，不建立第二套 scheduler。

### 6.2 Blueprint async action pattern

对 UE 常见的 `UBlueprintAsyncActionBase` 工厂模式，生成器按结构识别而非函数名识别：

- static `BlueprintCallable` factory 返回 async action UObject；
- 返回类型具有一个或多个 `BlueprintAssignable` dynamic multicast delegate；
- completion/cancel/failure delegate 签名可由现有 codec 投影；
- action 激活、delegate 订阅和 continuation token 都由 Session owner 管理。

Facade 生成 typed awaitable/result。完成事件先进入 Session ready queue，再在安全 Tick 恢复 guest；取消、
reload 与 teardown 解除全部 delegate 并释放 action lease。多完成 delegate 的结果使用显式 outcome enum，
不靠函数名猜测成功或失败。

## 7. 模块职责

| 模块 | 所有权 |
| --- | --- |
| `AvidScriptEditor` | Reflection 选择、interface/Blueprint/delegate 投影、C# facade、脚本默认参数发布 |
| `AvidScriptBindings` | descriptor identity、receiver compatibility、prepared codec、PIC、delegate invoke |
| `AvidScriptRuntime` | Session subscription/lease、continuation、reload/teardown、guest callback 调度 |
| `AvidScript.CSharpSemantic` | C# 可选参数合同、handler/async action shape、fail-closed 诊断 |
| `AvidScript.CSharpGuest` | 已验证 callback/CPS lowering，不感知 UE pointer 或反射名称 |
| `AvidScript.UeTypeGenerator` | UHT metadata、manifest/fingerprint、生成 shell |
| VM backend | 只执行 typed import/export，不保存 UE delegate/interface 业务状态 |

依赖方向保持 `Core <- Bindings <- Runtime <- Editor`；工具链消费 schema，不反向依赖 UE Runtime。

## 8. 性能与观测

P60 新增分层 benchmark，不把功能测试冒充性能证据：

- interface 单态 PIC hit、PIC miss 与 Blueprint reinstance miss；
- multicast callback、singlecast callback、guest invoke/broadcast；
- default argument 不应改变调用 crossing 数；
- Blueprint bytecode 本体时间与 AvidScript crossing 分开报告；
- async action 创建、完成入队和 resume crossing 分开报告。

热路径门槛：PIC hit 不做字符串分配/反射遍历；delegate route 不查 JSON/stable-id map；Session token 使用
ordinal/array 或预建索引。最终跨框架领导力仍由 P65 固定 workload 关闭。

## 9. 安全与失败关闭

- guest 永远只持有 slot/generation、ordinal 和 capability token；
- interface output 必须验证对象仍实现冻结 interface；
- singlecast 恢复前必须确认自己仍拥有属性；
- delegate ref/out 先预检全部 guest 地址与 capability，再提交 native 输出；
- Blueprint reinstance 后旧 UFunction/UClass pointer 不继续使用；
- async action 的 delegate、continuation 和 UObject lease 具有同一 Session activation serial；
- schema 新字段必须进入 JSON roundtrip、canonical hash、兼容读取和 future-version rejection。

## 10. 验收边界

Phase 60 完成时应证明：

1. C# 对 native 与 Blueprint 实现的 UInterface 均可 cast 和调用；
2. singlecast/multicast 可订阅、解绑、主动执行，并覆盖 return/ref/out 的允许组合；
3. C# 脚本 UFunction 默认值在真实 UFunction metadata 与 Blueprint pin 中可见；
4. Blueprint 新声明 callable 可从 WASM 调用，新声明 event 可按显式模式进入 WASM；
5. 至少一个结构识别的 async action 从创建到 await resume 完成闭环；
6. reload/teardown 后没有旧 delegate、PIC、continuation 或 action callback；
7. 固定 .NET、PowerShell、UE5.8 no-clean UBT、完整 Automation、architecture 和性能矩阵通过；
8. 人工 Blueprint pin、PIE 交互和视觉观察仍单独记录，不由 Automation 冒充。
