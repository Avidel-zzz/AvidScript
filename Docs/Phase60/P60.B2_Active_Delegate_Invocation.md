# P60.B2 Delegate 主动调用

状态：已实现，P60.B 集中回归通过

## 本节完成内容

- 从已授权 Delegate descriptor 确定性派生 active invoke stable id、import 名称、ABI 签名与 ordinal；
- 旧 binding、lifecycle、object、factory 与 attachment ordinal 保持不变，Delegate import 只追加发布；
- C# facade 为单播生成 `ExecuteX`，为多播生成 `BroadcastX`，不引入逐 API 手写 wrapper；
- Runtime 直接消费预构建的 property、signature function、codec 与 frame layout，热路径不查反射名称；
- 单播复用既有 `ref/out/return` 原子输出事务，未绑定时以 `binding_delegate_unbound` 失败关闭；
- 多播调用 UE `FMulticastScriptDelegate`，沿用 UObject handle、写权限、Session 与 reload 合同。

## C# 使用方式

以下方法由 Binding Profile 选中的 UE Delegate 自动生成：

```csharp
AAvidScriptDelegateActor self = UE.Self;

self.BroadcastOnScriptSignal(sourceActor, 7, 1.5f);

int value = 5;
int doubled;
int result = self.ExecuteOnSinglecastSignal(ref value, out doubled);
```

当前使用显式 `BindX/SubscribeX` 与 `ExecuteX/BroadcastX`。C# `event +=`、lambda 与 closure 语法糖
尚未实现，不能把它们写进可用能力清单。

## 性能证据

UE5.8 Win64 Development、20 个 sample、每个 sample 512 次调用：

| 路径 | P50 | P95 |
| --- | ---: | ---: |
| UE 原生动态多播 | `0.000521 ms` | `0.000539 ms` |
| AvidScript prepared 主动多播 | `0.000739 ms` | `0.000761 ms` |

P50 比率为 `1.418x`，warm reflected-name lookup 增量为 `0`。该 workload 比较 UE 原生侧 prepared
路径与原生动态多播，目的是约束 binding/codec 开销；它不包含 Wasmtime crossing，也不是 Puerts、
UnLua 或 AngelScript 的同口径竞品结论。
