# P60.C2b Blueprint Async Action Runtime 闭环

## 目标

把 schema 23 生成的 `UBlueprintAsyncActionBase` 契约接入现有 prepared invocation 与 Session
continuation，不为具体异步 API 编写 wrapper，也不建立第二套异步调度器。

## 已实现

- Runtime 加载时重新验证 static `BlueprintCallable` factory、action class、outcome delegate、stable id
  与 `first_broadcast_wins` 契约，反射漂移会失败关闭；
- prepared invocation 调用工厂后，把 action、callback id 和冻结契约交给当前 Session，向 Guest 返回
  opaque continuation token；
- Session 强引用 action，并在 `Activate()` 前绑定全部 outcome delegate；
- delegate bridge 使用 token 路由回 continuation，首个广播将确定性 outcome ordinal 写入受保护 result slot；
- 同一 action 的后续广播被解绑定抑制，完成仍通过既有安全 Tick drain 恢复 C# awaiter；
- 显式取消以 `Cancelled` 状态恢复 awaiter；Session teardown 会解绑 delegate、释放 action lease，晚到广播
  不再进入队列；
- action 结束时调用 `SetReadyToDestroy()`，对象和 bridge 的所有权不泄漏到 Guest。

## 架构边界

AsyncAction 复用 `IAvidScriptBindingLatentHost` 的 Session-owned producer 入口，但不伪装成 UE latent
action。Binding 层只负责反射验证、factory 调用和 immutable contract；Runtime 层独占 action、delegate、
continuation 与 teardown 生命周期。

本小节仍只支持无参、无返回值的 outcome delegate。带 payload 的动态多播会继续在生成期以
`async_action_outcome_payload_pending` 拒绝，P60.C2c 将把参数编码进统一 result layout，并补齐 reload/
Blueprint reinstance 压力路径。

## 验证

- UE5.8 `AvidTPSTemplateEditor Win64 Development` no-clean UBT：17/17 actions，通过；
- `AvidScript.Runtime.Continuation.BlueprintAsyncAction`：`1/1 Success`；
- `AvidScript.Editor.BindingRuntime.BlueprintAsyncAction`：`1/1 Success`；
- 测试覆盖 descriptor/package load、prepared factory 调用、Session token、同步 `Activate()` 完成、首广播
  获胜、outcome result、显式取消、teardown 解绑定和晚到广播抑制。
