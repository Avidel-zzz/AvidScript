# P1.5 Windows Packaged Development Smoke

日期: 2026-07-01
状态: Done
范围: Windows packaged Development / runtime timing smoke

## 1. 目标

P1.5 的目标是在 UE5.8 Windows packaged Development 环境中验证 P1.4 的 runtime session 和 world lifecycle 能离开 Editor 后继续工作:

- packaged build 能包含 `AvidScriptRuntime` 与 Win64 WAMR 静态库。
- packaged Game world 能加载同一个内置 WASM smoke module。
- packaged Game world 能执行 `avid_on_begin_play` 与至少一次 `avid_on_tick(float)`。
- EndPlay / quit 时能释放 WAMR module instance、exec env 与 runtime lease。
- 日志中记录基础耗时, 形成后续性能基线。

## 2. 实现内容

### 2.1 Runtime timing metrics

新增 `FAvidScriptWasmRuntimeMetrics`, 并挂到 `FAvidScriptWasmSmokeResult::Metrics`:

| 字段 | 含义 |
| --- | --- |
| `RuntimeInitMs` | WAMR runtime lease 获取和初始化耗时。 |
| `ModuleLoadMs` | `wasm_runtime_load` 耗时。 |
| `ModuleInstantiateMs` | `wasm_runtime_instantiate` 耗时。 |
| `ExecEnvCreateMs` | `wasm_runtime_create_exec_env` 耗时。 |
| `BeginPlayCallMs` | guest export `avid_on_begin_play` 调用耗时。 |
| `TickCallMs` | guest export `avid_on_tick` 最近一次调用耗时。 |
| `UnloadMs` | exec env / module instance / module / runtime lease 清理耗时。 |

`FAvidScriptWasmRuntimeInstance` 新增:

- `const FAvidScriptWasmRuntimeMetrics& GetMetrics() const`
- `void Unload(FAvidScriptWasmSmokeResult& OutResult)`

旧的 `Unload()` 仍保留, 内部转调带结果的 overload, 兼容 P1.4 调用方式。

### 2.2 Packaged smoke log signal

`UAvidScriptWorldSubsystem` 在 Game/PIE 生命周期里输出三条可 grep 的 packaged smoke 信号:

```text
AvidScript packaged smoke start | world=... | module=... | runtime_init_ms=... | load_ms=... | instantiate_ms=... | exec_env_ms=... | begin_play_ms=...
AvidScript packaged smoke tick | world=... | module=... | ticks=1 | tick_ms=...
AvidScript packaged smoke stop | world=... | module=... | ticks=... | unload_ms=...
```

Tick 日志只在第一次 tick 成功后输出, 避免 packaged 运行时刷屏。

### 2.3 Automation coverage

新增 UE Automation test:

```text
AvidScript.Runtime.PackagedTimingSmoke
```

覆盖点:

- 内置 WASM module load 成功。
- runtime init / module load / instantiate / exec env creation 计时被写入 result。
- `BeginPlay` / `Tick` 成功并记录调用耗时。
- `Unload(Result)` 返回 `bUnloaded=true` 并记录 unload 耗时。

## 3. TDD / 调试记录

### RED

先新增 `AvidScript.Runtime.PackagedTimingSmoke`, 构建出现预期失败:

```text
error C2039: 'Metrics': is not a member of 'FAvidScriptWasmSmokeResult'
error C2660: 'FAvidScriptWasmRuntimeInstance::Unload': function does not take 1 arguments
```

同时验证到 UE Automation flag 只能有一个 filter type; `EngineFilter | SmokeFilter` 会触发 static assert, 因此 P1.5 test 使用 `EngineFilter`。

### GREEN

实现 metrics 和 `Unload(Result)` 后, `AvidScript.Runtime` 全量 automation 通过, 测试数量从 4 增加到 5。

### Packaged staging 调试

第一次 `BuildCookRun` 的 build 和 cook 均成功, 但 Stage 阶段失败:

```text
Failed sending oplog request to Zen at [::1]:8558: ZenServer is not running (or is not responding), even after attempting to AutoLaunch.
AutomationException ... CopyBuildToStagingDirectory.Automation.cs:line 990
```

根因判断:

- UE5.8 `BaseGame.ini` 默认 `bUseIoStore=True` 且 `bUseZenStore=True`。
- 本项目未覆盖 ProjectPackagingSettings, 因此 cook 默认使用 ZenStore。
- 当前机器上 cook 完成后, UAT Stage 读取 Zen oplog 时本地 Zen service 状态不稳定, 导致读取 cooked file manifest 失败。

处理方式:

- 保持 packaged Development / Win64 / Pak / IoStore 验证目标。
- 重跑 cook/stage/archive 时传入 `-AdditionalCookerOptions=-SkipZenStore`, 让 cook 输出 loose cooked packages 和 `packagestore.manifest`。
- Stage 后续使用 manifest 创建 pak 与 IoStore container, 不再从 Zen oplog 读取 cooked file list。

该处理是本机 UE5.8 source build 的验证约束, 不是 AvidScript runtime 失败。

## 5. 当前结论

P1.5 已验证 AvidScript runtime spike 可以进入 Windows packaged Development:

1. packaged build 能加载 `AvidScriptRuntime` 模块。
2. packaged build 能执行 WAMR backend。
3. Game world BeginPlay/Tick/EndPlay 生命周期路径在 packaged exe 中可用。
4. runtime init/load/instantiate/call/unload 已有第一版可观测耗时。
5. UE5.8 本机 packaged 验证需要记录 `-SkipZenStore` 约束, 避免 Zen oplog stage 问题误判为 runtime 问题。

## 6. 未覆盖项与下一步

P1.5 不覆盖以下内容:

- 外部 `.wasm` 文件加载与 asset pipeline。
- UObject handle ABI、binding generator、脚本组件与热重载。
- Android/iOS packaged build。
- 性能基准统计分布, 当前只是 smoke timing。

下一阶段建议进入 Phase 2 Binding And Hot Reload Spike, 从最小 UObject handle ABI 和脚本组件生命周期开始。
