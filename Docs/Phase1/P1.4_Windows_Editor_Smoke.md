# P1.4 Windows Editor Smoke

日期: 2026-07-01
状态: Done
范围: Windows Editor / PIE lifecycle smoke

## 1. 目标

P1.4 的目标是在 UE5.8 Editor 环境中把 P1.3 的一次性 WAMR smoke 扩展为可复用 runtime session, 并接入最小 PIE 生命周期:

- BeginPlay 调用 guest export `avid_on_begin_play`。
- Tick 调用 guest export `avid_on_tick(float delta_seconds)`。
- EndPlay / World cleanup 释放 WAMR module instance 与 exec env。
- PIE restart 可以重新 load / instantiate / unload。
- missing export 与 guest trap 转换为 UE log 和结构化错误, 不导致 Editor 崩溃。

## 2. 实现内容

### 2.1 Runtime session facade

新增 `FAvidScriptWasmRuntimeInstance`, 将 P1.3 的一次性 smoke 封装为可重复创建和销毁的 session:

- `LoadEmbeddedSmokeModule` / `LoadModule`: 加载内置 WASM 或调用方提供的 bytecode。
- `BeginPlay`: 调用 `avid_on_begin_play`。
- `Tick`: 调用 `avid_on_tick`, 并把 `float` delta seconds 按 WASM 参数 cell 传入。
- `Unload`: 销毁 `exec_env`, deinstantiate module instance, unload module, 释放 WAMR runtime lease。
- `IsLoaded`, `HasBegunPlay`, `GetTickCallCount`, `GetModuleId`: 为测试与后续 instrumentation 暴露最小状态。

P1.3 的 `FAvidScriptWasmRuntime::RunEmbeddedSmokeTest` 仍保留, 但内部改为通过 `FAvidScriptWasmRuntimeInstance` 执行, 避免旧 facade 与新 session API 分叉。

### 2.2 WAMR runtime lease

当前实现使用进程内引用计数保护 WAMR init/destroy:

- 第一个 session 创建时调用 `wasm_runtime_init`。
- 每个 session load 成功后持有 runtime lease。
- session unload 后释放 lease。
- 最后一个 session 释放后调用 `wasm_runtime_destroy`。

这让 Editor automation 中的多次 test case、PIE restart、错误路径都能独立清理, 避免重复 init/destroy 的生命周期混乱。

### 2.3 World subsystem lifecycle

新增 `UAvidScriptWorldSubsystem : UTickableWorldSubsystem`:

- 只支持 `EWorldType::Game` 与 `EWorldType::PIE`, 不在普通 Editor world 中启动脚本 runtime。
- `OnWorldBeginPlay`: 创建 runtime session, 加载内置 smoke module, 调用 `avid_on_begin_play`。
- `Tick`: 调用 `avid_on_tick`, 更新 tick 计数。
- `OnWorldEndPlay` / `Deinitialize`: 释放 runtime session, 记录 end play cleanup 状态。
- `FAvidScriptWorldRuntimeStats`: 暴露最小可观测状态, 用于 automation smoke。

## 3. 错误处理策略

P1.4 明确了两类最小错误分类:

| 分类 | 触发条件 | 处理 |
| --- | --- | --- |
| `missing_export` | WASM module 缺少必需 export, 如 `avid_on_tick` | 当前 script instance 跳过/停止, 输出 UE warning, 返回结构化错误。 |
| `trap` | guest 调用中触发 WASM trap, 如 `unreachable` | 停止 tick 当前 script instance, 输出 UE warning, 返回结构化错误。 |

错误消息统一包含 backend、module id、export name、category、details、next action, 便于后续接入 Message Log、asset diagnostics 或 runtime overlay。

## 4. Automation tests

P1.4 扩展 `AvidScript.Runtime` 测试集为 4 个 smoke:

| 测试 | 覆盖点 |
| --- | --- |
| `AvidScript.Runtime.MinimalWasmSmoke` | P1.3 兼容 smoke, 验证内置 WASM load / instantiate / begin play / tick / unload。 |
| `AvidScript.Runtime.SessionRestartSmoke` | 两个 runtime session 先后 load / tick / unload, 验证 restart 不复用脏状态。 |
| `AvidScript.Runtime.ErrorSmoke` | missing export 与 trap 均返回结构化错误, Editor 不崩溃。 |
| `AvidScript.Runtime.WorldSubsystemLifecycleSmoke` | 临时 PIE world 中创建 subsystem, BeginPlay load/call, Tick 调用 guest, EndPlay unload。 |

测试实现中显式设置 `World->SetBegunPlay(true)`, 因为极简 `UWorld::CreateWorld` smoke world 不会像真实 PIE 流程那样由 GameMode/GameState 路径设置 begun-play flag。UE5.8 的 `UWorld::EndPlay` 只有在 `HasBegunPlay()` 为 true 时才会分发 `WorldSubsystem::OnWorldEndPlay`。

## 6. 调试结论

P1.4 的主要调试点是临时 PIE smoke world 的 EndPlay 分发。第一次 automation 显示 runtime 实际在 cleanup/deinitialize 阶段释放, 但 `World->EndPlay()` 后测试读到的 subsystem 状态仍未更新。查阅 UE5.8 `World.cpp` 后确认: `UWorld::EndPlay` 在 `HasBegunPlay()` 为 false 时会提前返回, 不分发 `WorldSubsystem::OnWorldEndPlay`。因此 smoke test 需要在手工 `BeginPlay()` 后设置 `World->SetBegunPlay(true)` 来模拟真实 PIE begun-play 状态。
