版本: 0.2
日期: 2026-06-30
状态: Done

## 1. 目标

P1.2 的目标是为 AvidScript 建立 WAMR 第三方 runtime 的接入规则, 让 UE 插件在 WAMR 源码和静态库尚未落地时仍能编译, 并为下一步 WAMR 源码 vendoring 与最小 host API 做清晰入口。

P1.2 完成的是 ThirdParty 结构、UBT guard module 和接入方案。P1.2b 已进一步完成 WAMR 源码快照和 Win64 静态库构建。

## 4. UBT 接入策略

`WAMR.Build.cs` 是一个 External module:

- 如果 `upstream/core/iwasm/include` 和 Win64 静态库候选之一存在, 定义 `AVIDSCRIPT_WITH_WAMR=1`。
- 如果 WAMR 文件不存在, 定义 `AVIDSCRIPT_WITH_WAMR=0`, 不链接静态库。
- 当前候选库名: `iwasm.lib`, `libiwasm.lib`, `vmlib.lib`。
- `AvidScriptRuntime` 可以安全依赖 `WAMR` module, 并通过宏判断 runtime 是否可用。

这种设计让工程可以先持续构建, 再逐步引入第三方库, 避免第三方路径未准备好时整个插件不可编译。

## 6. 当前 WAMR 编译配置

第一轮只验证 host runtime boundary, 不追求完整功能:

```text
WAMR_BUILD_INTERP=1
WAMR_BUILD_FAST_INTERP=1
WAMR_BUILD_AOT=0
WAMR_BUILD_JIT=0
WAMR_BUILD_FAST_JIT=0
WAMR_BUILD_LIBC_BUILTIN=1
WAMR_BUILD_LIBC_WASI=0
WAMR_BUILD_MULTI_MODULE=0
WAMR_BUILD_SIMD=0
WAMR_BUILD_MINI_LOADER=0
```

这组配置的目标是降低可执行内存、平台权限和移动端未来风险。
