# P1.2 WAMR ThirdParty Strategy

版本: 0.1
日期: 2026-06-30
状态: Done

## 1. 目标

P1.2 的目标是为 AvidScript 建立 WAMR 第三方 runtime 的接入规则, 让 UE 插件在 WAMR 源码和静态库尚未落地时仍能编译, 并为下一步 WAMR 源码 vendoring 与最小 host API 做清晰入口。

本阶段完成的是 ThirdParty 结构、UBT guard module 和接入方案, 不是实际 WAMR runtime 执行。

## 2. 上游选择

| 项 | 选择 |
| --- | --- |
| 上游仓库 | `https://github.com/bytecodealliance/wasm-micro-runtime` |
| 第一候选版本 | `WAMR-2.4.4` |
| 接入方式 | source-vendored snapshot |
| 主要原因 | 早期 spike 需要可控源码、可控编译选项、可审查补丁、后续 Android/iOS 路径可演进。 |

备注: `WAMR-2.4.4` 是当前调研时在官方仓库可见的最新 release 候选。进入 P1.2b 时需要把实际 tag、commit hash 和 license 文件写入 `Source/ThirdParty/WAMR/README.md`。

## 4. UBT 接入策略

`WAMR.Build.cs` 是一个 External module:

- 如果 `upstream/core/iwasm/include` 和 `lib/Win64/Release/vmlib.lib` 存在, 定义 `AVIDSCRIPT_WITH_WAMR=1`。
- 如果 WAMR 文件不存在, 定义 `AVIDSCRIPT_WITH_WAMR=0`, 不链接静态库。
- `AvidScriptRuntime` 可以安全依赖 `WAMR` module, 并通过宏判断 runtime 是否可用。

这种设计让工程可以先持续构建, 再逐步引入第三方库, 避免第三方路径未准备好时整个插件不可编译。

## 5. 平台策略

| 平台 | Phase 1 策略 | 后续策略 |
| --- | --- | --- |
| Windows Editor | 第一优先级, 先接 `vmlib.lib` 静态库。 | 验证 init/load/call/unload/PIE restart。 |
| Windows packaged Development | Phase 1 后段验证。 | 确认静态库、运行时数据和 wasm module packaging。 |
| Android | Phase 3 smoke, Phase 1 保留布局。 | 增加 Android ABI 分目录, 例如 `lib/Android/arm64-v8a/Release`。 |
| iOS | 不作为 Phase 1 验收。 | 单独评估 AOT、动态加载限制、包体策略。 |

## 6. 第一轮 WAMR 编译配置倾向

第一轮只验证 host runtime boundary, 不追求完整功能:

- interpreter: enabled
- fast interpreter: enabled if supported by selected WAMR version
- AOT: deferred
- JIT: disabled
- WASI: deferred
- multi-module: deferred
- libc builtin: enabled only if minimal module需要
- threading: disabled unless required by WAMR build

这组配置的目标是降低可执行内存、平台权限和移动端未来风险。
