# P1.3 最小 WASM Host API

状态: Done
日期: 2026-06-30
范围: PC / Windows Editor runtime spike

## 1. 目标

P1.3 的目标是在不接入 UObject binding 的前提下, 验证 AvidScript Runtime 能通过 WAMR 执行一个最小 WASM guest, 并打通第一批生命周期导出:

```c
void avid_on_begin_play(void);
void avid_on_tick(float delta_seconds);
```

本阶段关注 runtime boundary, 不实现脚本文件加载、热重载、组件生命周期、完整错误分类或 C# guest toolchain。

## 2. 已实现内容

| 文件 | 作用 |
| --- | --- |
| `Source/AvidScriptRuntime/Public/AvidScriptWasmRuntime.h` | 定义 `FAvidScriptWasmRuntime` facade 和 `FAvidScriptWasmSmokeResult` 验证结果结构。 |
| `Source/AvidScriptRuntime/Private/AvidScriptWasmRuntime.cpp` | 初始化 WAMR, load/instantiate 内置 WASM, 创建 exec env, 查找并调用 `avid_on_begin_play` 与 `avid_on_tick`。 |
| `Source/AvidScriptRuntime/Private/Tests/AvidScriptWasmRuntimeTests.cpp` | 新增 UE Automation smoke test: `AvidScript.Runtime.MinimalWasmSmoke`。 |
| `Source/ThirdParty/WAMR/WAMR.Build.cs` | 为静态 `libiwasm.lib` 消费端定义 `WASM_RUNTIME_API_EXTERN=` 并在 Win64 链接 `ntdll.lib`。 |

内置 WASM 当前只包含两个空导出函数, 用于验证宿主调用链:

```wat
(module
  (func (export "avid_on_begin_play"))
  (func (export "avid_on_tick") (param f32)))
```

## 3. TDD / 调试记录

### RED

先新增 automation test, 构建出现预期失败:

```text
fatal error C1083: cannot open include file: 'AvidScriptWasmRuntime.h'
```

判断: 测试已覆盖 P1.3 需要的 runtime facade, 但实现尚不存在。

### GREEN 迭代

实现 runtime facade 后出现两类集成问题:

1. WAMR 2.4.4 的 `wasm_runtime_lookup_function` 签名为 2 个参数, 已调整调用方式。
2. Win64 静态链接时, `wasm_export.h` 默认导入 `__declspec(dllimport)` API, 导致 `__imp_wasm_runtime_*` 链接错误。已在 `WAMR.Build.cs` 中为静态库消费端定义 `WASM_RUNTIME_API_EXTERN=`。

首次运行 automation test 时发生访问冲突:

```text
Unhandled Exception: EXCEPTION_ACCESS_VIOLATION writing address ...
UnrealEditor-AvidScriptRuntime ...
```

根因: `wasm_runtime_load` 的输入参数类型是 `uint8*`, WAMR 会写入/整理输入 buffer。此前把 `const` 内置 WASM 字节通过 `const_cast` 传入, 导致 WAMR 写入插件 DLL 的只读段。修复后会先复制到 `TArray<uint8> ModuleBuffer`, 再传给 `wasm_runtime_load`。

## 5. 当前结论

P1.3 已完成最小 WASM Host API 的第一条可执行路径:

1. WAMR backend 能在 UE5.8 Windows Editor target 中静态链接。
2. Runtime 能 load/instantiate 内置 WASM 模块。
3. Runtime 能查找并调用 `avid_on_begin_play`。
4. Runtime 能以 f32 cell 参数调用 `avid_on_tick`。
5. UE Automation test 能在 Editor-Cmd 下稳定通过。

## 6. 未覆盖项与下一步

P1.3 不覆盖以下内容, 留给 P1.4 / P1.5:

- 从磁盘加载 `.wasm` 文件。
- module id、脚本资产、UObject handle ABI。
- PIE begin/tick/end 生命周期绑定。
- missing export / trap 的完整 UE log 分类和不中断策略。
- PIE stop/restart 后 runtime instance 清理。
- Windows packaged Development build。

下一步进入 P1.4 Windows Editor Smoke, 把当前 facade 接入真实 Editor/PIE 生命周期, 并补 missing export / trap smoke。
