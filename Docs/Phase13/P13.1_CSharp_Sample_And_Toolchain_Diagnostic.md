## Scope

Added a C# Actor lifecycle sample and a PowerShell build diagnostic for the current C# to WASM route.

## C# Script Shape

```csharp
using System.Runtime.InteropServices;

namespace AvidScript;

public static class ActorLifecycleScript
{
    public static int Main() => 0;

    [UnmanagedCallersOnly(EntryPoint = "avid_on_begin_play")]
    public static void BeginPlay()
    {
        Actor.SetLocation(100.0f, 200.0f, 300.0f);
    }

    [UnmanagedCallersOnly(EntryPoint = "avid_on_tick")]
    public static void Tick(float deltaSeconds)
    {
        Actor.SetLocation(100.0f + 120.0f * deltaSeconds, 200.0f, 300.0f);
    }
}
```

## Diagnostic Contract

The script writes:

```text
Saved/AvidScriptCSharpGuest/ActorLifecycle/actor_lifecycle.csharp.report.json
```

Recognized results:

- `direct_abi_built`: generated WASM has `avid_on_begin_play` and `avid_on_tick`
- `direct_abi_unsupported`: generated WASM exists but misses the direct ABI exports
- `missing_toolchain`: dotnet or .NET 8 is unavailable
- `missing_workload`: `wasi-experimental` is unavailable
- `publish_failed`: no WASM artifact was produced

## Result On This Machine

The verified .NET 8 WASI route emits `dotnet.wasm` with only `_start` and `memory`, so it is not yet a direct AvidScript ABI module.
