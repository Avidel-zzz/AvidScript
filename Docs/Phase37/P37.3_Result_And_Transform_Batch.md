# P37.3 Result Boundary 与 Transform Batch

状态：Done

## 本组目标

- 收敛 Runtime 可观察状态同步，减少 Tick 成功路径重复复制。
- 在 AvidScriptBindings 建立首个 typed Actor Transform batch contract。
- 用独立 benchmark 记录 scalar 与 batch 的纯 C++ 基线。
- 保持 VM 不依赖 UObject、AActor、FVector、FRotator 或 FTransform。

## 架构

新增职责：

- AvidScriptActorTransformBatch.h：只定义快照、批量结果和 256 项上限。
- AvidScriptActorBinding.cpp：单项 GetActorTransform，每个 handle 只解析一次。
- AvidScriptActorTransformBatch.cpp：容量检查、逐项解析、失败输出清空和成功提交。
- AvidScriptWasmRuntime.cpp：CopyObservableStateToResult 统一返回边界同步。

没有把 guest address、WAMR API 或动态反射放进 Bindings。后续 WASM adapter 必须在 VM 层验证 guest memory，再把无 UE 类型的 wire 数据交给 Runtime/Bindings。

## 语义

GetActorTransforms：

- 空批成功。
- 最多 256 项。
- 输入顺序与输出顺序一致。
- 任意 handle 失败时 fail-fast。
- 失败返回时 OutTransforms 为空，FailedIndex 指向失败项。
- 成功时 ProcessedCount 等于输出数量。

FAvidScriptObjectHandle 增加 C++20 默认相等运算，保持纯值类型语义。

## Result 热路径

Runtime lifecycle 与 event 返回边界统一调用 CopyObservableStateToResult。

Tick 正常成功路径从多次 host/timer/event state copy 收敛为返回前一次。未加载、生命周期非法、VM trap 和 Timer callback trap 仍各自在返回前同步完整诊断状态。

## 性能证据

20 samples、3 warmups、每样本 1000 iterations、64 个不同 Actor handle：

- scalar GetActorTransform：平均 0.000279 ms/transform，p95 0.000289 ms。
- batch GetActorTransforms：平均 0.000286 ms/transform，p95 0.000294 ms。
- 512 pending Timer idle Tick：平均 0.000492 ms，p95 0.000670 ms。

纯 C++ contract 下 batch 比 scalar 每项约慢 2.5%，当前不宣称性能收益。它的性能价值来自未来把 64 次 guest-to-host crossing 合并成一次；必须在 WAMR import 和 C# API 接入后做端到端 benchmark 才能确认。
