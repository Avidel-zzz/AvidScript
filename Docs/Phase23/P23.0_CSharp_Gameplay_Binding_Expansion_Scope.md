# P23.0 C# Gameplay Binding Expansion Scope

状态: Done
日期: 2026-07-06

## 目标

Phase23 扩展一个最小但高价值的 C# gameplay binding: `Actor.AddLocationOffset(float x, float y, float z)`。完成后, C# 脚本可以在 `Tick(float deltaSeconds)` 中基于当前 Actor 位置做增量移动, 不再只能每帧覆盖绝对坐标。

## 为什么先做 AddLocationOffset

当前用户最关心的是能否用 C# 写 UE 游戏逻辑, 尤其是接入 `BeginPlay` / `Tick` 等事件流程。`SetLocation` 已经证明生命周期闭环可用, 但真实 Tick 逻辑通常需要“上一帧状态 + 本帧增量”。`AddLocationOffset` 是下一步最小纵切, 能同时验证:

- C++ Actor host binding 扩展方式。
- WASM host import 注册方式。
- C# source adapter 对多种 Actor API 的解析与生成。
- Manifest/report required imports 扩展方式。
- 默认 C# 样例的 gameplay 可读性。

## 本阶段交付

- C++: `FAvidScriptActorBinding::AddActorLocationOffset(...)`。
- WASM: `actor_add_location_offset(slot, generation, x, y, z) -> i32`。
- C#: `Actor.AddLocationOffset(float x, float y, float z)` facade。
- Source adapter: 支持 `Actor.SetLocation(...)` 与 `Actor.AddLocationOffset(...)`。
- Tests: binding、WASM handler、C# sample shape、C# source adapter lifecycle。
- Docs: 更新中文 C# authoring 指南与 Phase23 实现日志。

## 非目标

- 不开放任意 UE API。
- 不做碰撞 sweep / hit result / physics movement。
- 不做移动端验证。
- 不做打包验证。
- 不做 profile 列表 UI 或 Slate 面板。

## 当前风险

`AddLocationOffset` 本阶段会复用 `SetActorLocation(..., TeleportPhysics)` 的现有移动语义, 因此它是“受控位置写入”而不是完整 UE movement/collision API。后续如果要模拟常规 `AActor::AddActorWorldOffset` 的 sweep 行为, 需要单独设计 ABI 与返回结构。
