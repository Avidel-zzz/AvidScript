# P57.3 Wasmtime Guest Memory 句柄缓存

## 1. 范围

本批次优化 Adaptive Semantic 返回值写回路径，不修改 C# 公共 API、现有
`(iiiii)i` guest-address ABI、workload、oracle 或门禁阈值。

根因调用链为：

```text
prepared reflection callback
-> IAvidScriptVmGuestMemory::WriteBytes
-> TryGetGuestMemory
-> avidscript_wasmtime_memory_data
-> wasmtime_caller_export_get / wasmtime_instance_export_get("memory")
-> wasmtime_extern_delete
```

旧实现每次返回一个 `int32` 都会按名字重新查找 `memory` 导出。Wasmtime 45 的
C API 将 `wasmtime_memory_t` 定义为 store 内索引，不携带析构资源，因此实例化时
缓存句柄是安全的。

## 2. 实现

- `AvidScriptWasmtimeInstance` 保存已导出的 `wasmtime_memory_t` 和存在标记；
- linker 实例化成功后只解析一次名为 `memory` 的导出；
- 后续读写直接使用缓存句柄获取当前 data 和 size；
- 不缓存 data 指针，`memory.grow` 后仍重新读取基址与长度；
- 没有可缓存导出时保留 caller/instance 的旧查找回退；
- instance 卸载时缓存随 instance 一起释放，reload 使用新句柄。

这项优化同时覆盖反射返回值写回、普通 guest memory 读写和 borrow 路径，不按
UE API 名称生成手写 wrapper。

## 3. 生命周期覆盖

既有 Wasmtime lifecycle fixture 新增 `avid_grow_memory` 导出，并验证：

- 初始页读写；
- guest 执行 `memory.grow 1` 后第二页读写；
- Unload 后旧 export/prepared handle 失效；
- 同一 backend reload 后新实例读写；
- 越界与 wraparound 继续拒绝。
