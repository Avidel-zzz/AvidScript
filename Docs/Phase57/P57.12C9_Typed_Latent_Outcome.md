# P57.12C9 Typed Latent Outcome 闭环

## 目标

P57.12C9 将 C8 的宿主 result slot 接入生成式 C# WASM 调用链，使显式注册 completion provider 的
latent UFUNCTION 可以返回类型化结果。脚本侧通过生成的 `AvidOutcomeAwaitable<T>` 等待，并在恢复后获得
`AvidOutcome<T>`；整个路径不依赖 UFUNCTION 名称分支，也不需要为每个 UE API 手写绑定。

生成后的调用形态如下：

```csharp
AvidOutcome<int> outcome = await WaitForScoreAsync(score);
if (!outcome.Succeeded)
{
    return;
}

int completedScore = outcome.Value;
```

这项能力只对 descriptor 中已经冻结 provider 身份与 payload 类型的 latent binding 开放。普通
completion-only latent UFUNCTION 仍返回既有 awaitable；未注册 provider 的函数不会被推断成有返回值。

## 跨层合同

Descriptor schema v13 在每个 provider binding 中冻结函数 ordinal、provider ID 与 payload TypeId。
Semantic schema 13 / profile 1.13 只接受生成器提供的四参数 `AvidLatent` 调用和准确的
`AvidOutcomeAwaitable<T>` 类型，调用者不能通过手写同名帮助器绕过合同。

continuation 恢复时，Guest callback 获得 status、result slot 与 generation。编译器生成一次
`continuation_result_read` bulk import，并把结果写入预先确定的线性内存布局；Runtime 在读取前同时校验：

- 当前 dispatch frame、lane 与 activation serial；
- continuation token、slot 与 generation；
- binding ordinal 与 payload TypeId；
- Session 所有权以及结果尚未消费。

任一身份不匹配都会 fail closed。成功读取使用 consume-and-release 语义，同一个 result slot 不能被重复读取。

## Payload 编解码

`FAvidScriptContinuationResultCodec` 与 result transaction 统一处理五类 payload：

- `AbiCells`：标量、布尔与枚举等规范 ABI cell；
- `FixedWire`：`FVector` 和递归定宽 USTRUCT 等固定布局值；
- `Object`：通过当前 Session 的 UObject capability 所有权域发布借用句柄；
- `Utf8`：发布到有界 UTF-8 capability heap；
- `Array`：发布到有界 array capability heap。

UTF-8 与数组句柄采用事务式发布；Guest callback 或结果写入失败时回滚本次新建的 heap token。对象结果沿用
现有 callback/Session 对象 capability 生命周期，不向脚本暴露原生指针。所有布局都在生成期确定，Runtime
不进行字段名查找或逐字段 UE 反射调用。

## Outcome 语义

`AvidOutcome<T>` 以 status 为权威状态。成功时 `Succeeded` 为 true 并可读取 `Value`；provider 失败、
编码失败或宿主校验失败时返回失败 outcome，`Value` 保持零初始化。结果只能在对应 continuation 的当前恢复
回调中读取，过期 token、错误 ordinal、错误 TypeId、重复读取和跨 Session 使用都会被拒绝。

本阶段仍保留 `abandon_on_cancel`：取消获胜时 continuation 不恢复，因此还不会向 C# 发送
`Cancelled` outcome。取消终态恢复、结构化异常传播以及更完整的 Task 风格组合器属于后续阶段。

## 性能设计

每个完成结果只进行一次 bulk host crossing。标量、结构体、字符串与数组都共享编译期生成的布局与统一
Runtime codec，不引入按 API 名称的适配层，也不执行运行时反射字段遍历。这为后续批量 await、对象句柄
快路径和异步调度 benchmark 留出了稳定边界。

本阶段没有重新运行冻结的 Wasmtime/V8 正式性能套件，因此不能据此宣称总体性能债务已经解决。
`P57-D06-ControlledLeadership` 继续保持 `Fixing`。
