# P57.12C11 结构化 Async Guard 实施计划

## 目标

在 P57.12C10 已完成的 `AvidOutcome<T>` 成功、失败、取消三终态之上，让受控 C# async
脚本能够直接使用顶层早退 guard：

```csharp
AvidOutcome<int> outcome = await UKismetSystemLibrary.WaitForScoreAsync(42);
if (outcome.Cancelled)
{
    return;
}
if (outcome.Failed)
{
    return;
}

UE.Self.SetActorTickEnabled(true);
await AvidContinuations.NextTickAsync();
```

本批次解决的是 outcome 已经可读取、但受控 async segment 尚不能据此改变执行路径的问题。实现继续采用
编译器生成的零 CLR 状态机 CPS，不引入按 UFUNCTION 名称的 Runtime 分支。

## 冻结语法

- guard 必须是 async 方法 body 的顶层语句；
- 只接受无 `else` 的 `if (condition) return;`，block 与单行形式等价；
- condition 必须为受支持的 `bool` 表达式；
- guard 内不能出现 await，不能捕获 lambda，也不能执行隐式 cleanup；
- guard 后可继续执行普通 segment 语句，也可调度当前 segment 的下一个受控 await；
- 任意 if/else、分支内副作用、try/finally 与循环仍 fail closed。

## 编译合同

Semantic 合同升级为 `14 / 1.14`，普通语句模型不增加并行控制字段，而是发布一个稳定的
`async_early_return_guard` operation，唯一 child 是 guard condition。schema 13 / semantic 1.13 继续可读，
但不得携带该 operation。

Guest lowering 在同一个 resume function 内按源码顺序切分基本块：

```text
segment entry
  -> lower statements before guard
  -> branch_if(condition, guard_return, guard_continue)
  -> lower remaining statements
  -> schedule next producer or return
```

所有 guard 共用当前 segment 的 return block。false 路径继续使用现有 schedule acceptance、取消绑定和
result-read 门禁；guard 不新增 host import、VM binding、result slot 或 heap allocation。

## 验收

- Semantic 覆盖合法 guard、非法 if/else 与 schema 13 fail-closed；
- Guest 覆盖 `Cancelled`/`Failed` guard、guard 后 UE 调用与下一 await 调度；
- Guest IR validator 与 WASM compiler 必须接受生成的 branch graph；
- 阶段末集中执行固定 .NET、PowerShell 合同、UE5.8 no-clean 构建、完整 Automation 和 clean
  architecture gate；
- 更新中文交付文档与 `Phase57_State.json`，`P57-D06-ControlledLeadership` 保持 `Fixing`。

## 后续边界

C11 不实现跨 await local spill、任意 if/else、异常、Task、timeout/race 组合器。下一批优先建立
Session-owned bounded async state frame，使 scalar、enum、固定 struct 与受控对象 capability 能在并发
重入下安全跨 await；再以该 frame 承载结构化并发。
