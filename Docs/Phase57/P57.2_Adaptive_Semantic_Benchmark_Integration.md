# P57.2 Adaptive Semantic 基准集成与诊断报告

## 目标

本批次把 Adaptive Semantic 从内部执行策略接入六通道真实性能基准，并确保
`semantic_vs_puerts_reflection` 的分子只来自真实
`avidscript_wasmtime_adaptive_semantic` lane。Generated S1、Native C++ 和严格
`ProcessEvent` 结果都不能替代该分子。

## 已实现内容

- 新增显式 `adaptive_semantic` lane 与请求、校准、进程结果、聚合结果合同。
- benchmark session 显式选择 `AdaptiveSemantic`，默认运行策略仍为
  `SemanticProcessEvent`。
- 每个 Adaptive sample 发布 native hit、ProcessEvent fallback、guard reject、
  semantic hit、generated hit 和 logical operation 计数。
- runner correctness oracle 根据完整 guest workload 映射推导 native 与 fallback
  期望值，不再按函数名或首个失败 workload 特判。
- Adaptive prepared call 复用 receiver cache 时，要求每个 callback 第一次调用
  revalidate，后续调用命中缓存；同时禁止 generated call-site prepare 和 journal
  slow path。
- 外部 Gate evaluator 与 runtime oracle 使用同一 Adaptive 计数口径。
- 历史 strict semantic lane 仍保留在通用 schema 和 evaluator 中，用于旧证据与
  诊断，不进入当前正式语义性能分子。

## Scalar Add 诊断结果

| Lane | P50 ns/op |
|---|---:|
| Native C++ | 1.7400 |
| Puerts V8 Reflection | 116.2891 |
| Puerts V8 Static | 32.6600 |
| AvidScript Wasmtime Adaptive Semantic | 112.4219 |
| AvidScript Wasmtime Generated S1 | 28.1100 |
| AvidScript Wasmtime Data-oriented | 28.3900 |

Adaptive Semantic / Puerts Reflection 为 `0.9667x`。这已经把 Phase 56 的
`5.8190x` 降到略快于 Puerts Reflection，但仍高于冻结门禁 `<= 0.80x`，因此
本报告不声明语义性能门禁通过。

## 正确性与路径证明

- 300/300 timed samples 正确。
- Adaptive lane 共 50 个 timed samples。
- Adaptive native hits：25,600。
- Adaptive ProcessEvent fallback hits：22,400。
- Adaptive guard rejects：0。
- `scalar_add_int32` 的 5 个 timed samples 均为 native hit，fallback 与 guard
  reject 均为 0。
- strict fallback 继续覆盖不满足当前 `int32, int32 -> int32` 资格证明的
  property、vector、object、ref/out 等调用。

## 结论与下一步

当前剩余差距约为 `19.39 ns/op`，不能通过放宽门禁或改换 Generated S1 分子解决。
下一批优化应集中在 prepared reflection hot path 的重复 receiver/class/plan
身份检查、每调用全局 guard 检查和成功路径诊断状态处理。所有优化必须保留精确
class、Game Thread、GC/PostLoad/debug、slot/generation、registry revision、reload
和严格 fallback 语义。
