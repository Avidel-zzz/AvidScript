# P57.11C 数组批量传输与正式性能证据

## 状态

P57.11C 已完成。AvidScript 的一维固定宽度数组现在可以通过共享 range ABI 在一次
host crossing 中传输连续区间；生成的 C# facade 提供显式 `Snapshot` 与 `Flush`，并保留
P57.11B3 的 `Length`、索引读写和 `Release` 兼容表面。

## 完成内容

### 六项共享 capability ABI

新增以下两个稳定 import：

- `avidscript.value_array_read_range.v1` / `avid_value_array_read_range` / `(iiiii)i`；
- `avidscript.value_array_write_range.v1` / `avid_value_array_write_range` / `(iiiii)i`。

两个 import 的物理参数均为 token、capability 起始下标、guest array reference、guest
起始下标和 count。Bindings heap、Runtime guest memory 校验、VM static catalog、WAMR native
registration 与 Wasmtime linker 使用同一参数映射。旧四项数组 package 仍可加载，新生成
package 必须精确授权完整六项。

### 有界内存与生命周期

`FAvidScriptArrayValueHeap` 新增连续 `ReadRange`/`WriteRange`，沿用每数组最多 `4096`
元素、payload 最多 `1 MiB` 和 session-owned process-unique token。Runtime 使用 64 位中间值
检查 guest/capability 区间、stride、alignment、长度头和地址空间；伪造、stale、跨 session、
负下标、越界、错误对齐与溢出均失败关闭。Host 不向 Guest 暴露长期 `TArray` data pointer。

### C# 使用方式

```csharp
int[] result = self.IntArrayRoundTrip(input, ref inOut, out int[] output);
int[] local = new int[] { 0, 0, 0 };

if (AvidScriptArray.Snapshot(result, 0, local, 0, result.Length))
{
    local[0] += 1;
    AvidScriptArray.Flush(local, 0, result, 0, local.Length);
}

AvidScriptValue.Release(output);
AvidScriptValue.Release(result);
```

这不是 CLR GC array 的伪装：`result` 是受控 capability reference，`local` 是 Guest 线性数组，
`Snapshot`/`Flush` 明确表达复制方向。真实 fixture 在 WAMR 与 Wasmtime 上都得到
`[11, 1, 2]`，释放后 live array capability 为 `0`。

## 数组正式性能协议

P57.11C 新建独立 `Phase57Array` 协议，没有修改 Phase56 与既有 Phase57 reflection workload。
正式运行使用 UE5.8 Win64 Development、Wasmtime 45 JIT 与同机 Puerts V8：

- 5 个独立 UE 进程，轮转三条 lane 的执行顺序；
- 每进程 8 次 warmup、21 次 timed sample；
- `N=1/4/16/64/256/1024`，共 `1890` 个 timed sample；
- 每个 size 比较完整 FNV-1a 输出 hash；
- Puerts 使用真实 `UE.NewArray(UE.BuiltinInt)` 与 `TArray<int32>` Reflection 往返；
- AvidScript element 与 bulk 使用同一个 Wasmtime Guest 和同一个 host capability。

| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | `532.300 ns` | `288.037 ns` | `380.322 ns` | `1.32039x` | `0.71449x` |

### 解释边界

这组 headline 衡量的是“脚本已持有容器后的一次完整读、变换、写回”数据通道。AvidScript
capability 和 Guest array 在计时前建立，计时内包含 range read/write 与 Guest 变换；Puerts
计时内包含真实 `TArray` Reflection 参数/返回值分配、native 变换和 JS wrapper 访问。因此它
能证明 bulk 数据通道相对当前 Puerts container surface 的优势，但不能替代“同一个项目
UFUNCTION 从调用到返回”的端到端 binding benchmark。已有 scalar/property/FVector/UObject
prepared reflection 数据继续承担后者的证据。

## 当前边界与下一步

- 普通 C# `result[i]` 仍走逐元素 crossing；本阶段 bulk 需要显式 `Snapshot`/`Flush`；
- 尚未实现动态 `new T[n]`、bounded Guest allocator、自动 dirty flush 与 alias barrier；
- string element、nested array、`TSet`、`TMap` 尚未接入；
- 本阶段没有改变 delegate、latent、RPC、interface dispatch、Cook/Shipping 或移动端状态；
- Wasmtime/V8 纯执行 P95 债务 `P57-D06` 仍为 `Fixing`。

下一批 P57.11D 应实现 bounded Guest allocator 与编译期 array access region，使普通 C# 数组
循环自动 materialize 一次、dirty 时 flush 一次，并用 alias/call barrier 保持语义正确。
