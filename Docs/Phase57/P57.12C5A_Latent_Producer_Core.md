# P57.12C5A 通用 Latent Producer Core 实现报告

## 状态

C5A 已完成；P57.12C5 整体仍在实现中。

本组完成 UE latent UFUNCTION await 所需的 Runtime producer 核心，但尚未对 C# 用户暴露 `FooAsync`。当前成果是后续 descriptor、Bindings executor 和编译器生成链共同依赖的通用生命周期底座，不代表任意 latent API 已经可以从脚本调用。

## 架构合同

- `AvidScriptBindings` 只发布 `BeginLatent`、`CommitLatent`、`AbortLatent` 窄接口；
- `AvidScriptRuntime` 拥有 token、lane、activation、World 与 callback proxy；
- 每个 await 独占一个 `UAvidScriptLatentCallbackProxy`，因此 UE 的 `CallbackTarget + UUID` 删除粒度等于单 token；
- callback 只向 Session ready queue 入队，不在 `FLatentActionManager` 回调栈内重入 Guest；
- active/prepared promotion、candidate discard、HostContext rebind、owner generation 失效与 World teardown 统一复用 Continuation lane 取消；
- 不按 `Delay`、`MoveComponentTo` 或其他函数名编写特殊分支。

## Reservation 事务

1. `BeginLatent` 分配 generational token 和独占 proxy，返回 callback target、execution function、UUID 与 linkage；
2. 后续 Bindings executor 将这些字段注入隐藏 `FLatentActionInfo`，再调用 `ProcessEvent`；
3. `CommitLatent` 只接受 manager 中已经注册 action，或在 `ProcessEvent` 内同步完成的 reservation；
4. 没有注册 action 的调用 fail closed，并由调用方 `AbortLatent`；
5. 同步 completion 在 commit 前只记录 pending，不提前发布给 Guest。

## 取消与回收

取消顺序固定为：proxy disarm、`RemoveActionsForObject`、ready token 清除、slot generation 轮换。由于 UE latent action 删除可能延迟到 manager 后续处理，仍有 action 的 proxy 会进入 `RetiredLatentProxies` 强引用队列，直到 manager 报告 action 数为零或 World 失效。

## 验证

新增 `AvidScript.Runtime.Continuation.LatentProducer`，直接向真实 `FLatentActionManager` 注册通用测试 action，覆盖：

- reservation 无 action 时拒绝 commit，并可 abort；
- callback 在 commit 前同步完成；
- 两个并发 await 使用不同 callback target；
- 单 token 取消不影响另一个 action；
- prepared latent promotion 后在 active lane 完成；
- candidate discard 删除 action且不产生 Guest completion；
- World teardown 清空 entry，迟到 action 保持静默。
