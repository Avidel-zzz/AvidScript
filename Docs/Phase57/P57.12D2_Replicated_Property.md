# P57.12D2 Replicated Property 完成报告

## 结论

P57.12D2 已完成项目 replicated UPROPERTY 到生成式 C# 属性的首批读写闭环。Binding Profile
选中的 `UPROPERTY(Replicated)` 与 `UPROPERTY(ReplicatedUsing=...)` 继续使用普通属性 facade、
prepared invocation 与现有 codec program，不需要为每个属性手写 Host wrapper。

getter 在 authority 与非 authority 都可用；setter 只允许 authority 执行。成功写入后，Runtime 使用
活动 `FProperty` 的 `RepIndex` 调用 UE5.8 Push Model dirty API。复制条件、连接选择、差异发送和
native/Blueprint RepNotify 仍由 UE 网络栈管理，AvidScript 不维护第二套复制状态。

## 实现范围

### Descriptor 与生成器

- binding descriptor 升级为 schema `16`，新增 `property_replication` 与 `rep_notify`。
- 复制模式、RepNotify 名称与 ClassReps 身份进入 canonical binding identity、selection hash 和
  package hash；descriptor 与活动 Reflection 不一致时失败关闭。
- replicated property 首批只接受声明于 `AActor` 或 `UActorComponent`、已进入活动
  `ClassReps` 的运行时属性。
- replicated setter 禁用 Generated S1，统一经过 prepared invocation 的 authority 与 dirty gate。
- direct setter 与 BlueprintSetter 共用复制合同；网络属性不允许绕过现有 host-write policy。

### Runtime 写入契约

- immutable invocation program 持有活动 `FProperty` 与复制合同，不在热路径按属性名称推断。
- ActorComponent 写入前解析有效 Actor owner；无 owner、错误 receiver 或失效 UObject 在突变前拒绝。
- 非 authority 写入在解码和属性突变前返回
  `binding_property_replication_authority_denied`。
- candidate 热重载上下文禁止写 replicated property，避免把不可回滚复制副作用写入候选事务。
- direct、struct、fast-path 与 `ProcessEvent` setter 只有成功完成后才标记活动 RepIndex dirty。
- authority 本地写入不会伪造 OnRep 调用；`ReplicatedUsing` 对应 native/Blueprint RepNotify 仍在
  客户端接收 UE 复制更新时由引擎触发。

## C# 使用方式

`Samples/CSharp/ReplicatedProperty` 展示普通属性语法和 authority 分支：

```csharp
public static void BeginPlay()
{
    AAvidScriptBindingRuntimeNetworkTestActor self = UE.Self;
    AActor actor = self;
    if (!actor.HasAuthority())
    {
        return;
    }

    self.ReplicatedScore = self.ReplicatedScore + 10;
    self.ReplicatedRoutedValue = 20;
}
```

项目自己的 replicated property 只要被 Binding Profile 选中、owner 与值类型满足现有
descriptor/codec 策略，就会生成相同的 C# 属性，不需要按项目 API 名称增加 Runtime 分支。

## 保留边界

- D2 不使用 Tick 轮询复制值，也未把 UE 入站 RepNotify 自动分发到 C# export。
- UE 收到 RPC 后分发到 C# handler、C# OnRep handler、FastArray、custom delta、动态 subobject、
  Iris fragment、网络预测与回滚尚未实现。
- replicated container 仍服从既有 codec 能力，没有新增特殊 delta 写语义。
- 真实网络正确性仍需要 dedicated server、listen server 与多客户端 PIE/独立进程验收；当前自动化证明
  descriptor、authority、写入和 Push Model dirty 边界，不冒充真实跨连接属性同步。
- Cook、Shipping、Android 与 iOS 仍未完成正式验收。

## 性能说明

D2 没有新增竞品 benchmark。复制发送成本与语义主要由 UE 网络栈决定；prepared invocation 避免每次按名
解析合同，但不能据此声称新的 Puerts 或 AngelScript 领先结果。`P57-D06-ControlledLeadership` 继续保持
`Fixing`，性能表继续引用 P57.11D、P57.11B1 与 P56 的冻结证据。
