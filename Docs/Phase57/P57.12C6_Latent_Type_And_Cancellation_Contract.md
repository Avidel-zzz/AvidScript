# P57.12C6 Latent 类型与取消合同

## 状态

C6A 已完成：首组开放 `bool` value 参数的 typed C# facade 与 Guest storage adaptation。
C6B enum underlying storage 正在推进。

## 目标

P57.12C5 已打通 completion-only latent UFUNCTION 的 Reflection、descriptor、Runtime transaction、
生成式 C# 与受控 await。C6 不复制普通 UFUNCTION 的类型系统，而是逐类复用已冻结的 public type、
storage type 与 ABI codec：

1. 先支持单 cell 但 public/storage 不同的 `bool -> i32`；
2. 再让 enum 使用显式 underlying storage，不依赖隐式 C# 转换；
3. 对 UObject 与固定结构体复用普通调用的 aggregate flattening plan；
4. 最后评估 capability 型 string/array，要求暂停点前完成所有权与容量验证。

每一组都必须由 descriptor 产生，不允许按 UFUNCTION 名称添加 wrapper 或 VM switch。

## C6A bool storage adaptation

生成 facade 保持用户看到的 UE 类型：

```csharp
[AvidLatent("avidscript", "avid_ue_<stable-id>")]
public static AvidDelayAwaitable WaitForFlagAsync(bool bExpected) => default;
```

私有 import 使用真实 WASM storage：

```csharp
[DllImport("avidscript", EntryPoint = "avid_ue_<stable-id>")]
internal static extern long Invoke0000(int p0, int callbackId);
```

Semantic await site 保留 `type:bool`，授权 import 保留 `type:int32`。Guest validator 只接受这一条明确的
public-to-storage 映射；lowerer 在调用前生成 bool 到 i32 的 `convert` register。任意其他类型不一致继续
fail closed。Runtime 仍使用 schema v12 的通用 bool property codec，不新增 latent 专用解码器。

测试模块的自定义 `WaitForFlag(bool)` UFUNCTION 用于证明项目自己声明的 latent API 也能经 Reflection
生成，不把 `UKismetSystemLibrary.Delay` 当成唯一特例。

## 取消合同

当前已经成立的是宿主所有权取消：

- 每次 latent 调用获得 Session generational continuation token 与独占 callback proxy；
- reservation/commit 失败会 abort，proxy 先 disarm；
- reload discard、owner generation 失效、World teardown 与 EndPlay 会取消整条所属 lane；
- UE action 延迟删除时，迟到 callback 不能重新进入 Guest。

当前尚未成立的是脚本显式取消。`await FooAsync()` 不向 C# 暴露内部 token，因此不能把已有的
`AvidContinuation.Cancel()` 文档化为 latent await 的用户 API。后续显式取消必须满足：

- token 仍由 Session 分配，不能直接暴露或复用 UE UUID；
- cancel 与 completion 竞争只有一个终态，重复调用幂等；
- prepared lane token 不得取消 active lane action；
- 取消句柄跨 reload 不可迁移，旧 generation 必须 fail closed；
- C# 表面需要零 CLR Task 依赖，并与 bounded spill/reset handshake 一起设计。

在这些条件冻结前，C6 不增加看似可用但无法覆盖竞态的 `CancellationToken` 仿制 API。

## Payload 合同

completion-only latent 不产生返回值。普通 `ref/out` 参数在 `ProcessEvent` 返回时只是调度阶段的同步
frame，不能被当作 action 完成后的 payload。未来 payload 只能来自显式的 producer completion 数据源，
并进入 Session-owned result slot；descriptor 必须冻结 payload kind、类型 identity、所有权和失败状态。

因此当前继续拒绝：latent return、ref/out、delegate payload、多执行输出 pin，以及根据函数命名猜测
完成结果。对象 payload 将复用 C2 的借用/强引用与 generational capability 规则。
