# P57.12C1 确定性 Continuation 核心实施计划

状态：实现与统一验收完成，待候选提交、架构证据与推送

## 目标

在现有 C# Guest、Runtime Session 与热重载事务之上，建立可复用的异步恢复底座。首个生产者
提供下一帧与延迟恢复，业务脚本无需手写 WASM export；后续异步资源、网络和 latent producer
统一复用同一 continuation token、分发出口与生命周期合同。

本阶段只承诺 continuation 核心和 `Delay`/`NextTick` 闭环，不把尚未实现的 C# `async/await`
状态机或异步资源加载描述为已支持。

## 冻结的 C# 接口

生成 facade 提供不透明 continuation 令牌与静态调度入口：

```csharp
private const int ResumeSpawn = 1;

[AvidTransient]
private static AvidContinuation _pending;

[AvidContinuation(ResumeSpawn)]
public static void ResumeSpawnHandler()
{
    UE.Print("resumed");
}

public static void BeginPlay()
{
    _pending = AvidContinuations.Delay(0.25f, ResumeSpawn);
}
```

- handler 必须是 `public static void`、无参数、非泛型且有具体方法体；
- callback id 必须是正整数，并在同一脚本中唯一；
- `Delay`/`NextTick` 的 callback id 必须是编译期常量，且对应一个已声明 handler；
- 保存 `AvidContinuation` 的静态字段必须标记 `[AvidTransient]`；
- `AvidContinuation.Cancel()` 对有效令牌返回 `true`，对重复、伪造或过期令牌返回 `false`；
- `NextTick` 通过 UE TimerManager 延迟到当前调用栈返回后的下一次 timer pump，不承诺跨越一个完整
  渲染帧，也不会同步重入；
- 编译器生成固定 `avid_on_continuation(i32 callbackId, i64 token, i32 status)` 出口和确定性分发，
  C1 handler 只消费 callback id；预留的 token/status 供后续结果与受控 `async/await` 状态机复用。

## 冻结的 Host ABI

| 模块 | Import | 签名 | 语义 |
| --- | --- | --- | --- |
| `env` | `continuation_delay` | `(fi)I` | `(delay_seconds, callback_id) -> i64 token` |
| `env` | `continuation_cancel` | `(I)i` | `i64 token -> 1/0` |

token 使用 session-owned slot/generation 编码；令牌不暴露 Runtime 指针、对象地址或 World 标识，
释放、失败回滚或 teardown 后旧 generation 不能重新命中新任务。

## 所有权与确定性合同

- `FAvidScriptRuntimeSession` 独占 continuation owner，并为 live/candidate Runtime 分配 active/prepared
  lane；Runtime 只转发 ABI 和调用 guest callback；
- Delay producer 使用 UE5.8 `FTimerManager`，负数和非有限延迟被拒绝；这是真实 UE deferred
  producer，不把现有 Runtime 逻辑时钟 Timer 重新包装为新能力；
- producer 完成只进入 Session ready queue，Guest 仅在 Session Tick 的安全 pump 中恢复；队列按
  `registration_serial` 稳定排序，token 身份不兼任执行顺序；C1 每个 Session Tick 最多恢复一个
  continuation，使回调触发的外层 teardown 能在下一项恢复前完成；
- callback 调用前移除 active token，因此回调内取消自身返回失败且不会重复触发；
- 候选 Runtime 的任务进入 prepared lane；候选失败只丢弃 prepared，旧 active Runtime 与 token
  不受影响；
- HostEffect commit 前验证 prepared lane；提交后只执行 fence old、切换 Runtime、失效旧 active、
  promote prepared 等不可失败步骤；
- 成功切换、`EndPlay`、Unload、owner/registry/world 环境变化都会使对应 activation 的旧任务失效；
- 每个 guest 入口使用 Session guest-operation lease；最外层退出统一刷新延迟 teardown；
- teardown 请求立即关闭新注册与事件入口，当前 continuation 回调返回后停止剩余 ready batch；
- Runtime 限制活动任务总数，容量耗尽时返回无效 token，不产生半注册状态；
- callback trap 使当前 Tick 失败，并由既有 Session 错误与恢复策略接管。

## 架构边界

- 调度、active/prepared lane 与 token 由独立 `Continuation` 模块实现，Runtime 仅负责 ABI 转发和
  VM export 调用；
- VM 后端继续使用 static host import catalog，不为 WAMR 与 Wasmtime 复制两套业务语义；
- Semantic 层拥有 handler 与调用点约束，Guest lowering 只消费已验证合同；
- 生成式 C# facade 是唯一公开入口，不新增按 UE 类型或业务事件手写 API；
- 本阶段不修改或清理 Editor target，不执行碎片化全量 Gate。
