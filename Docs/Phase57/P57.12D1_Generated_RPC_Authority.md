# P57.12D1 生成式 RPC 与 Authority 完成报告

## 结论

P57.12D1 已完成 C# 到 UE RPC 的生成式调用闭环。项目 Reflection 中被 profile 选中的
`Server`、`Client` 与 `NetMulticast` UFUNCTION 会沿用普通函数的 facade、WASM import、
prepared invocation 与 codec program，不需要为每个 RPC 增加 Host wrapper。

AvidScript 只负责固化和复核网络契约，并在不可逆副作用发生前执行安全检查。实际连接选择、
本地/远端 callspace 与网络发送仍由 UE `GetFunctionCallspace` 和 `ProcessEvent` 决定，没有复制
NetDriver、ownership 或连接路由规则。

## 实现范围

### Descriptor 与生成器

- binding descriptor 升级为 schema `15`，新增 `network_mode` 与 `network_reliable`。
- 网络模式与可靠性进入 binding identity、selection hash 与 package hash，篡改后无法复用旧包。
- Editor 从 UFunction flags 投影 `none/server/client/multicast`，并把 RPC 固定到
  `cached_process_event` executor。
- 首批只接受声明于 `AActor` 或 `UActorComponent` 的非静态、非 latent RPC；禁止返回值和
  `ref/out`，const-ref value 参数仍可使用现有 codec。
- Runtime 加载 package 时重新读取活动 UFunction flags，descriptor 与 Reflection 不一致即失败关闭。

### Runtime 调用契约

- immutable invocation program 持有网络契约，不在热路径按函数名或 class path 推断 RPC。
- ActorComponent 先解析有效 Actor owner；无 owner、错误 receiver 或失效 UObject 在
  `ProcessEvent` 前拒绝。
- Client 与 NetMulticast 只能由 authority 发起。
- 非 authority 发起 Server RPC 时，UE callspace 必须包含 `Remote`；被 UE 吸收的调用不会执行。
- candidate 热重载上下文禁止 RPC，避免把不可回滚网络副作用写入候选事务。

## C# 使用方式

`Samples/CSharp/NetworkRpc` 展示了同一个 typed Self 根据 authority 选择调用方向：

```csharp
AAvidScriptBindingRuntimeNetworkTestActor self = UE.Self;
AActor actor = self;
if (actor.HasAuthority())
{
    self.ClientApplyValue(20);
    self.MulticastAnnounceValue(30);
}
else
{
    self.ServerSubmitValue(10);
}
```

项目自己的 RPC 只要被 Binding Profile 选中、owner 与参数形状满足策略，就会生成同样的 C#
方法。`HasAuthority()` 也是普通生成式 UFUNCTION 调用，不是 D1 专用语法。

## 保留边界

- D1 只覆盖脚本主动调用 RPC，不包含 UE 入站 RPC 到 C# handler。
- Replicated Property、RepNotify、生命周期同步、网络预测与回滚未实现。
- 首批 RPC 不支持 return、`ref/out`、latent、static owner 或非 Actor/ActorComponent owner。
- 网络正确性仍需要后续 dedicated server、listen server 与多客户端 PIE/进程验收；当前自动化证明
  descriptor、authority、callspace 和副作用边界，不冒充真实跨进程网络验收。
- Cook、Shipping、Android 与 iOS 仍未完成正式验收。
