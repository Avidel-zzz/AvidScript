# P57.11B1 递归固定宽度 USTRUCT Codec 阶段报告

## 当前状态

P57.11B1 已完成。审查发现的 schema canonical layout、嵌套对象 capability、继承字段
枚举一致性和重叠输出事务四项问题均已关闭；实现候选 `4c10239 / 7569623` 已通过
UE5.8 no-clean 构建、十项 clean contract Gate、冻结 Micro 性能回归，以及 canonical
主工程完整 Automation `336/336`。测试夹具与 schema 9 新诊断顺序完成对齐后没有放宽
任何生产安全边界。

本批次让安全、固定宽度的用户 `USTRUCT` 不再依赖逐类型 wrapper。Editor 从 UE 反射元数据
生成 schema 9 字段图，Bindings 在 package load 时把字段图编译为不可变 codec program，
C# facade 生成公开值类型，调用时只向 Wasm 传递一个 guest 地址。VM 和 Runtime 不包含
具体结构体名称，也不按 benchmark 或 UFunction 名称选择路径。

## 已实现能力

### 自动反射范围

用户自定义 `UFUNCTION` 和可读写 `UPROPERTY` 中的固定宽度 `USTRUCT` 现在可以自动进入
prepared dynamic bridge。根结构体和嵌套结构体支持以下字段：

- `bool`、有符号/无符号 8/16/32/64 位整数、`float`、`double`；
- UE 枚举和 byte enum；
- `UObject` 派生引用，在线路上继续使用 slot + generation capability；
- `FVector`、`FRotator`、`FTransform`；
- 继续由上述安全字段组成的嵌套用户 `USTRUCT`。

Editor 与 Runtime 现在统一按 `IncludeSuper` 枚举字段，并验证每个字段 owner 位于目标
`UScriptStruct` 的继承链上。嵌套结构体中的对象叶会递归进入 capability class graph，
不再只收集函数顶层对象参数。UE5.8 gameplay profile 当前精确开放 9 个由该通用规则
自动覆盖的 struct-wire API；门禁冻结的是精确集合，不在生产代码中硬编码 API 名称。

函数方向覆盖 value、`const_ref`、`ref`、`out` 和 return。直接属性 getter 使用输出存储，
setter 先把完整 wire 解码到已初始化的临时结构体，全部字段成功后才通过
`CopyCompleteValue` 提交，避免半写入对象状态。

### Schema 9 与确定性身份

`FAvidScriptBindingTypeModel` 新增有序 `fields` 图，每个字段记录反射名称、child type id
和 wire offset。类型 stable id、package identity、selection identity 和 descriptor hash 都
包含完整字段图、wire size 和 alignment；字段名称、类型、offset、size 或 alignment 被
篡改后会 fail closed。schema 2-8 继续按原格式加载，非 `struct_wire` 类型不能携带
`fields`，旧 leaf stable id 不变。

字段图有三层硬限制：递归深度最多 8、节点最多 128、单个 wire payload 最多 4096 bytes。
生成端和加载端都检查 cycle、字段顺序、无空洞 canonical offset、对齐、重叠、尾部尺寸、
power-of-two alignment 和真实 UE 反射字段匹配，不能利用伪造 descriptor 把 guest bytes
写入错误的 native 字段。

### C# 使用面

生成器输出 `[StructLayout(LayoutKind.Explicit, Size = N)] readonly struct`，依赖类型先于
父类型生成。value/const-ref native import 使用 `in T`，ref/out/return 使用对应的
`ref/out T`。由于当前 Guest lowerer 使用自然布局而不消费 `FieldOffset`，wire bool 由
私有 `int` backing field 表示并通过只读 `bool` 属性暴露，保证其 4-byte ABI 不会把后续
`byte` 和 `float` 字段挤到错误位置。

测试结构体覆盖两层嵌套、scalar、enum、`FVector`、`UObject`、bool、byte 和 float；根
wire size 为 40 bytes，bool/byte/float offset 分别为 28/32/36。生成结果还覆盖函数各
方向以及 property get/set，不需要用户手写 marshal 代码。

### 执行与安全

package load 阶段把 schema 字段图和真实 `UScriptStruct/FProperty` 编译为不可变递归
program；每次调用不再重新选择字段类型。根 `struct_wire` 只占一个 guest-address cell，
地址从 64 位 cell 收窄到 32 位前必须通过范围检查。输入优先使用只读 borrow，输出预检
guest 范围后才允许 `ProcessEvent` 产生宿主副作用。

对象字段解码时验证 capability generation 和 expected class。输出对象借用属于一次
事务：任一后续字段或最终 guest write 失败都会回滚本次新增 handle。所有 ref/out/return
guest 输出范围会在 `ProcessEvent` 前统一预检，完全相同或部分重叠的区间以
`binding_guest_output_overlap` 拒绝，相邻区间允许；因此宿主副作用不会先于不可提交的
输出布局发生。旧 typed fast path 显式拒绝 `StructWire`，不会把相同的 `[i]` ABI 误识别
为 `int32`。

## 明确不支持的边界

结构体字段中的 `FName`、`FString`、`FText`、固定数组、动态数组、集合、映射、delegate、
soft/weak/lazy 引用、instanced reference，以及 transient/editor-only 字段仍被拒绝。固定
数组会返回稳定的 `fixed_array:<name>[N]` 诊断。容器、变长字符串、
delegate、latent/RPC/interface 的完整语义不会因为本批次自动放宽。普通函数参数已有的
FName value/const-ref 能力保持不变，但它还不能作为固定 wire 结构体字段。

这些限制是安全边界，不代表需要为每个 UE API 手写绑定。后续批次会继续扩充通用 codec
种类，符合类型规则的 UFUNCTION 将自动获得覆盖。

## 性能约束

P57.11B1 扩展的是 generic recursive codec，不改变 P57.10 四个 typed prepared shape 的
选择条件。最终仍必须用冻结的 `phase56.micro-formal-v1` 回归 scalar、property、vector
和 object，不能仅凭代码路径推断无回退。

最终候选本轮正式回归分别为 0.51409、0.66144、0.05573、0.53167 倍 Puerts Reflection，
对应 scalar、property、vector、object 领先 48.59%、33.86%、94.43%、46.83%。600 个目标
prepared 样本产生 96000000 次 native hit，fallback 和 guard reject 都为 0。本批次不会
用这些 Semantic 成绩关闭纯 Wasm execution debt；`P57-D06-ControlledLeadership` 继续
保持 `Fixing`。
