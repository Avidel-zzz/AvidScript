# P57.12D4 链式、Blueprint 与重入安全的入站 Handler

## 本阶段完成内容

P57.12D4 在 D3 的 Session-owned `(UFunction, UObject)` 路由上补齐三项游戏逻辑能力：

1. C# Profile schema 10 可通过 `include_handlers`、`before_handlers`、`after_handlers` 显式选择
   `replace`、`before`、`after` 语义；同一成员跨组重复会稳定失败。
2. Profile 精确授权的 Blueprint bytecode RPC/RepNotify 可以生成 descriptor 并进入同一 Runtime 路由；
   原 Blueprint 实现仍由 UE 的 `UObject::ProcessInternal` 执行，AvidScript 不解释 Blueprint bytecode。
3. guest 执行期间再次到达的入站事件不递归进入 VM，而是深拷贝参数到 Session-owned
   `FStructOnScope`，在外层 guest guard 退出后的下一次 Session tick 按 FIFO 分发。

这三项都沿用通用 Reflection descriptor、prepared codec 和生成式 C# callback，不增加项目 API 名称
分支或手写 Host import。NetDriver、callspace、复制发送、RepNotify 触发与 Blueprint 图执行权继续属于 UE。

## 使用方式

Profile schema 10 为每个 Handler 冻结一种链式策略：

```json
{
  "schema_version": 10,
  "binding_profile": {
    "classes": [
      {
        "class_path": "/Script/MyGame.MyNetworkActor",
        "before_handlers": ["ServerSubmitValue"],
        "after_handlers": ["OnRep_ReplicatedScore"],
        "include_handlers": ["ClientShowMessage"]
      }
    ]
  }
}
```

生成的 C# callback 仍使用统一的 `[AvidEvent]`：

```csharp
[AvidEvent(AvidEvents.ServerSubmitValue)]
public static void HandleServerSubmitValue(int value)
{
    AMyNetworkActor self = UE.Self;
    self.ReplicatedScore = value;
}
```

| 模式 | 执行顺序 | C# 失败语义 |
| --- | --- | --- |
| `replace` | 只执行 C# | 不执行原实现 |
| `before` | C# 成功后执行原实现 | trap/failure 抑制原实现，避免追加部分副作用 |
| `after` | 原实现完成后执行 C# | 原实现不伪装回滚，也不会重复执行 |

当 handler lane 尚未激活、对象不匹配或 Session 已卸载时，hook 退回原实现。route replacement、reload、
EndPlay 和 Session teardown 会清空 deferred queue 并恢复原 thunk。

## Descriptor 与 Runtime 合同

- descriptor schema 18 新增必需字段 `handler_mode`，并纳入 callback canonical identity、stable ID、
  selection hash 与 package hash；schema 17 及更早版本继续保持原字节与默认 `replace` 语义。
- C# emitter 的 canonical regeneration 和 Runtime authorization slice 都保留 handler mode，不能在
  build/reload 中退化为 `replace`。
- Blueprint handler 必须由 owner class 声明、拥有 bytecode，并继续满足 RPC 或 RepNotify、value-only、
  非 latent、无 return/ref/out 的现有合同。
- deferred queue 上限为 64。第 65 项会清空队列、关闭 handler lane，并向当前 tick 返回稳定的
  `inbound_handler_deferred_overflow`；旧事件不会覆盖，新事件不会在同一帧无限自激。
- deferred `before` 只有在 C# 成功后，才通过 registry 重新验证 route 所有权并调用冻结的原 thunk；
  `after` 的原实现已在事件到达时执行，不会二次调用。

## 尚未宣称完成

- 本阶段没有把单进程 hook/Session Automation 冒充为真实网络拓扑验收。Dedicated server、listen
  server 与多客户端独立进程中的 RPC、属性复制和 RepNotify 传输属于 P57.12D5。
- return/ref/out/latent handler、FastArray/custom delta、动态 replicated subobject、Iris 扩展、网络预测与
  回滚仍未支持。
- 本阶段没有新增性能 benchmark；`P57-D06-ControlledLeadership` 继续保持 `Fixing`。
