# P57.13 Cranelift Speed 单变量性能计划

## 目标

在不修改冻结 12-kernel、V8 对照、采样次数、CPU 绑定或领导阈值的前提下，把 Wasmtime v45
Cranelift profile 从 `speed_and_size` 改为官方定义的 `speed`，验证纯执行 P50/P95 是否足以关闭
`P57-D06-ControlledLeadership`。

## 约束

- 唯一 codegen 变量是 `OptLevel::Speed`；Cranelift、backtracking regalloc、inlining all、x86-64-v3、
  fixed 4 GiB wasm32 reservation、signals-based traps、alias analysis 与 parallel compilation 不变。
- Spectre heap/table mitigation 保持开启。P57.13 不以降低安全边界换取 benchmark 分数。
- Wasmtime v45 commit、补丁、Rust toolchain、DLL SHA-256 与 Cargo feature 不变，不重建第三方 Runtime。
- compiler profile id 与 runtime build identity 必须升级；旧 JIT/serialized artifact 因 provenance 不同而
  fail closed，不允许复用旧 cache。
- internal C API 同时识别旧 `speed_and_size` 枚举和新 `speed` 枚举，但 production profile 只选择
  `speed`。
- 正式判断沿用冻结门槛：P50/P95 几何均值 `<= 0.95`、kernel 胜率 `>= 0.60`、MAD 几何均值
  `<= 1.25`、correctness failure `0`、fallback `false`。

## 实施

1. 扩展内部 Wasmtime optimization enum 与 engine factory 映射，不改 Host ABI。
2. 升级 production compiler profile、lock/schema、sidecar identity 与合同测试。
3. 运行工具链合同、UE5.8 no-clean VM/Editor build 和聚焦 Wasmtime Automation。
4. 从 clean candidate 创建隔离 benchmark project，执行同一冻结 12-kernel 正式矩阵。
5. 只有完整门禁全绿才把 D06 标记为 `Verified`；否则记录分项收益并继续 LLVM AOT/等价 codegen 路线。

## 非目标

- 不关闭或放宽 P57-D06 阈值。
- 不把 Semantic/reflection 已有领先数据混入纯执行几何均值。
- 不在本批次关闭 Spectre mitigation，也不引入项目 API wrapper。
- 不以单次进程、部分 kernel 或 P50 单项替代正式 5-process P50/P95 结果。
