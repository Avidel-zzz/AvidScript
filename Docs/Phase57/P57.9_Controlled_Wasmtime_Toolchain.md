# P57.9 受控 Wasmtime 工具链与正式性能归因

## 阶段结论

P57.9 已完成可复现的 Wasmtime v45 性能工具链、最小 C API 扩展、统一 compiler
profile、JIT/serialized artifact 配置统一、CPU 能力校验、DLL 身份验证和 benchmark
provenance 闭环。实现本身已通过 UE 5.8 构建与 27 项聚焦 Automation。

冻结 12-kernel 正式门禁仍未通过，因此
`P57-D06-ControlledLeadership` 必须保持 `Fixing`，不得宣称 AvidScript 的纯 Wasm
执行层已经全面领先 Puerts V8。

## 已实现能力

- 上游固定为 Wasmtime `v45.0.0` commit
  `377cd917af258d932d55b201a646917ecf193639`，源码归档、补丁、Rust 版本和 Cargo
  feature 均进入 lock/schema。
- 新增扩展 `avidscript_wasmtime_config_compiler_inlining_set`，只映射
  `Inlining::No/Yes`，没有修改 Cranelift 优化器实现。
- 受控配置固定为 Cranelift、`speed_and_size`、backtracking regalloc、
  `inlining=all`、`x86-64-v3`、4 GiB 固定 wasm32 reservation、Spectre mitigation
  开启、NaN canonicalization 关闭、并行编译开启。
- 为保持既有模块兼容，工具链显式启用 `gc + gc-drc`，engine profile 与 compiler
  identity 同步记录 `wasm_gc=on;gc_collector=drc`。
- Win64 启动前通过 CPUID/XCR0 验证 x86-64-v3；缺少扩展、CPU 不满足、工具链缺失
  和 profile 无效均返回稳定错误类别。
- JIT backend 与 Editor artifact compiler 共用同一 engine factory 和完整身份字符串，
  P57.8 cache、attestation、manifest 与 runtime authorization 合同保持不变。
- Runtime resolver 会跳过旧的部署 DLL，只加载与编译期 SHA-256 完全一致的授权候选；
  UBT 通过 `ExternalDependencies` 感知 managed toolchain 更新。

## 架构判断

当前证据证明“受控 Wasmtime 配置”是必要基础设施，但不是 5% 全面领导性的充分条件。
V8 与 Cranelift 对短小纯计算循环都已生成接近本机上限的机器码，继续无目标地试探通用
flag 不会跨越剩余差距。下一轮应把主要工程预算投入更有杠杆的 Semantic/reflection
边界、跨调用融合和可证明的编译期特化；纯执行层若继续冲击 0.95，只接受 LLVM AOT
或等价新 codegen 后端的冻结协议结果，不接受修改 kernel 或降低门槛。
