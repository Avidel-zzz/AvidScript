# P57.12C16 数组 Foreach Await 完成报告

## 结论

P57.12C16 已完成。受控 C# `async void` 现在可以在同步一维数组的 value `foreach` 循环体中
直接 await，并正确保留集合单次求值、元素赋值、`break`、`continue`、`return` 和循环后继语义。

该能力将 foreach 编译为现有 continuation CFG、数组 region 操作与普通分支。它没有把 CLR
enumerator 带入 Runtime，没有新增 Host import、逐 API wrapper、Runtime AST interpreter，也不会在
每次暂停时复制整个数组。

## 编译与状态模型

### Semantic

- Semantic contract 升级为 schema `16` / version `1.18`。
- `SemanticAsyncMethod.CompilerLocals` 显式发布编译器生成的数组引用和索引；源 foreach item 仍是
  独立的 `SemanticSymbol`，不能被隐藏局部替代。
- 集合表达式只求值一次，随后展开为数组保存、索引归零、Length 条件、元素读取、循环体和索引递增。
- `continue` 指向递增块，`break` 指向循环后继；循环体 await 使用既有 resume target。
- 固定点活跃性只把后继真正使用的数组引用、索引和元素写入每个 await 状态帧。
- 非数组 enumerator、元素转换、解构、ref/ref readonly foreach、await foreach 与集合表达式内 await
  使用 `ASCS5419` 失败关闭。

### Guest/WASM

- Guest 数组引用是 `i32`、4 bytes、align 4；状态帧保存引用值，不复制数组内容。
- 正数引用属于当前 WASM activation 的编译器托管 region，负数引用属于当前 Session 的 UE 数组
  capability；两者分别受 activation 和 Session/reload/teardown 栅栏约束。
- foreach 使用既有 `array_length`、`array_region_load` 与 branch，不引入新的 Host ABI。
- 只有顶层数组引用可进入状态帧，带动态数组字段的 USTRUCT 继续拒绝。
- tampered compiler-local 类型、ID 冲突、越界和未来 schema 均在 Guest lowering 前拒绝。

## 可运行样例

`Samples/CSharp/AsyncArrayForeach` 提供完整 C# profile。Actor 在 `BeginPlay` 中遍历三个缩放百分比，
每个元素等待一个安全 Tick，再调用生成式 `UE.Self.SetActorScale3D`：

```csharp
int[] scalePercent = new[] { 100, 110, 125 };
foreach (int percent in scalePercent)
{
    await AvidContinuations.NextTickAsync();
    float scale = (float)percent / 100.0f;
    UE.Self.SetActorScale3D(new FVector(scale, scale, scale));
}
```

## 保留边界

- 首批只支持同步一维数组、普通 value foreach 和精确元素类型。
- 通用 `IEnumerable<T>`、自定义 enumerator、元素转换、解构、ref foreach 与 await foreach 未开放。
- string element、nested array、`TSet`、`TMap`、async helper 调用链与 `try/finally` 未开放。
- Cook、Shipping、Android 与 iOS 仍未完成正式验收。

## 性能说明

C16 没有新增竞品 benchmark。循环本体完全运行在 Guest 内，await 状态帧也不复制数组 referent，
但不能据此声称新的 Puerts/AngelScript 领先结果。`P57-D06-ControlledLeadership` 继续保持 `Fixing`，
性能表仍引用 P57.11D、P57.11B1 与 P56 的冻结正式证据。
