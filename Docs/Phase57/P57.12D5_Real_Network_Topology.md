# P57.12D5 Dedicated、Listen 与多客户端真实网络拓扑完成报告

## 结论

P57.12D5 已完成。AvidScript 不再只用单进程 fixture 证明 RPC/RepNotify hook，而是用 UE5.8
Development Editor 的独立进程跑通两种真实 NetDriver 拓扑：

- dedicated server + 2 remote clients；
- listen server + 1 remote client。

两种拓扑都执行同一个 production-built C# + WASM 产物。客户端脚本从 `BeginPlay` 安排下一 Tick
continuation，恢复后调用生成式 Server RPC；服务器进入 C# `before` handler、写入 replicated property，
随后执行原生 RPC；UE 把属性复制回 owning client，原生 RepNotify 与 C# `after` handler 依次执行，最后
由客户端发送确认 RPC。整个链路没有项目 API 名称分支，也没有用单进程直接调用冒充网络传输。

## 实现范围

### Runtime fixture 与 Harness

- `AAvidScriptNetworkTopologyTestActor` 是 owner-only replicated Actor，拥有默认
  `UAvidScriptComponent`、Server RPC、确认 RPC、RepNotify 和链路计数。
- `FGameModeEvents::OnGameModePostLoginEvent()` 为每个远端 PlayerController 生成并设置 owner，满足 UE
  client-to-server RPC ownership contract。
- Harness 仅在 `WITH_DEV_AUTOMATION_TESTS` 且命令行带
  `-AvidScriptNetworkTopologyRole=` 时启用，普通 Editor、PIE、Game 与 Shipping 路径不注册测试逻辑。
- 每个进程原子写自己的 JSON，记录 topology、role、PID、NetMode、Runtime 生命周期、计数、值和稳定
  错误类别。

### C# 与生成式绑定

- Profile schema 10 同时选择 `/Script/Engine.Actor::HasAuthority`、项目 Actor 的四个普通/RPC
  UFUNCTION、`ReplicatedScore` writable property、`ServerSubmitValue` before handler 与 RepNotify after
  handler。
- C# `BeginPlay` 使用零堆 `AvidContinuation` 下一 Tick回调；server 与 client 在回调处重新获取
  `UE.Self`，不把宿主对象句柄无意义地携带进 async 状态帧。
- 同一 `ServerSubmitValue` 同时存在于 outbound facade 和 inbound handler。客户端 Remote-only
  ProcessEvent 由 UE callspace/NetDriver 转发；服务器 Local 入站才被 C# hook 接收。
- `ReplicatedScore` 继续使用 D2 authority setter 与 Push Model dirty；RepNotify 继续由 UE 复制系统触发。

### 多进程编排

- `RunAvidScriptNetworkTopology.ps1` 为每种拓扑分配独立端口和证据目录，等待 NetDriver listen 后再启动
  clients。
- 所有进程由 `Start-Process -PassThru -WindowStyle Hidden` 创建；编排器只保存和停止自己创建的精确
  PID，不按进程名清理用户 Editor。
- 进程提前退出、监听超时、结果缺失、schema/role/PID 不匹配、任一 `succeeded=false` 或计数不精确都
  会使拓扑失败。
- 成功结果汇总命令、PID、角色结果、日志 SHA-256 与 JSON SHA-256 到 `aggregate.json`。

## 本轮纠正

1. 测试 Actor 的 C# 可调用函数必须满足通用 Reflection 策略，补齐 `BlueprintCallable` 后生成式 facade
   才包含 RPC 与 recorder 方法。
2. `UAvidScriptComponent` production sample 必须提供完整生命周期 ABI，即使 Tick 为空也要导出
   `avid_on_tick`；缺失时 Runtime 按设计 fail closed。
3. 单次延迟 RPC 不需要 async 状态图，改用已有 Session-owned continuation，避免无意义的宿主对象状态
   捕获。
4. architecture checker 只在实现提交后的 clean candidate 上形成正式证据；dirty 或日志捕获失败的运行
   不计入验收。

这些纠正及防复发规则已写入 `AGENTS.md`。

## 未完成边界

- 仍未覆盖跨机器、Internet、packet loss/lag、断线重连、travel、Iris replication graph、FastArray、
  custom delta、动态 replicated subobject、网络预测和回滚。
- D5 是 Development Editor 多进程验收，不代表 Cook、Shipping 或移动端网络已完成。
- return/ref/out/latent inbound handler 与 Blueprint 图中新声明函数的通用发现仍未完成。
- 本阶段没有新增性能 benchmark。`P57-D06-ControlledLeadership` 继续保持 `Fixing`，不能把真实网络功能
  闭环表述为纯执行性能门禁已经关闭。
