# P57.11B3 通用数组 Value Capability 阶段报告

## 当前状态

P57.11B3 已完成。AvidScript 现在可以把 UE Reflection 中满足安全约束的一维 `TArray<T>`
自动投影为 C# `T[]`，覆盖 UFUNCTION 的 value、const-ref、ref、out、return 与 UPROPERTY
get/set。用户自定义 API 只要通过同一 descriptor/type policy，就会进入相同路径，不需要修改
VM switch 或手写 wrapper。

真实 C# fixture 已通过 Roslyn semantic frontend、Guest IR、Wasm backend 与 Runtime Session，
并在 WAMR 和 Wasmtime 上执行 Tick 游戏逻辑。最终 UE5.8 no-clean target 通过，工具链测试
`35/35 + 15/15 + 81/81` 通过，完整 AvidScript Automation `345/345` Success，clean
architecture Gate 通过。

## C# 使用方式

生成 facade 直接暴露数组：

```csharp
[UnmanagedCallersOnly(EntryPoint = "avid_on_tick")]
public static void Tick(float deltaSeconds)
{
    AMyGameplayActor self = UE.Self;
    int[] input = new int[] { 1, 2 };
    int[] inOut = new int[] { 10 };

    int[] result = self.IntArrayRoundTrip(input, ref inOut, out int[] output);
    if (result.Length == 3)
    {
        result[0] += 1;
    }

    self.ReadableIntArray = result;
    AvidScriptValue.Release(inOut);
    AvidScriptValue.Release(output);
    AvidScriptValue.Release(result);
}
```

这段代码实际执行了数组构造、value/ref/out/return、Length、element load/store、property set
与 capability release。UE 侧最终读取到 `[11, 1, 2]`，两个 backend 完成调用后 live array
capability 都为 0。

## 类型与 API 覆盖

descriptor schema 升级为 v10。array type 使用 `element_type_id` 指向统一 type graph，ABI
仍是单个 `i32` value reference，不为每种 `TArray<T>` 发明新的 host ABI。

当前支持的一维数组元素：

| 元素类别 | 示例 | 状态 |
|---|---|---|
| scalar | bool、各宽度整数、float、double | 已支持 |
| enum | UENUM/byte enum | 已支持 |
| UE fixed value | FVector、FRotator、FTransform | 已支持 |
| object handle | UObject、Actor、Component 派生类型 | 已支持 |
| fixed struct-wire | 已通过递归安全检查的自定义 USTRUCT | 已支持 |
| string/name/text | FName、FString、FText | 暂不支持作为元素 |
| nested/container | TArray、TSet、TMap | 暂不支持作为元素 |

函数方向覆盖 value、const-ref、ref、out 与 return，属性覆盖 get/set。数组元素中的 UObject
仍使用 generational handle 和类型检查，payload 不包含裸 UObject 指针。

EngineGameplay profile 当前生成 `371` 个 reflection binding；manifest 再加入 object/owner 与
四个 value capability，共 `377` 个授权 import。profile 数量是当前默认 surface，不等于完整
UE API 总量；项目自定义 UCLASS/UFUNCTION 仍由 profile 与类型能力共同决定是否自动进入。

## Capability 与生命周期

数组和 UTF-8 heap 现在共享同一个进程唯一 capability ID 空间。token 的 high bit 区分宿主
能力与 linear reference，剩余 31 bit 单调分配且不复用，因此数组 token 不会与字符串 token、
另一 Runtime 或 reload 前 token 撞权。

每个 Runtime Session 拥有独立 array heap：

- 单数组最多 `4096` elements；
- canonical payload 最大 `1 MiB`；
- 最多 `65535` live/reserved values；
- resolve 同时检查 session token 和 expected element/type identity；
- read/write 检查 index、stride、buffer size 与溢出；
- `AvidScriptValue.Release` 立即回收，重复 release 和后续访问 fail closed；
- unload、replacement load 与析构 reset，作为异常路径兜底。

heap 记录 live、reserved、live bytes、peak bytes、published 和 released 统计，后续可以直接建立
长时间游戏 session 的内存预算门禁。

## 原子调用边界

Bindings 在 `ProcessEvent` 前完成 array input decode、输出地址与 overlap 检查、对象借用以及
全部数组输出 reservation。调用结束后先把 ref/out/return/property get 编码到 staging bytes，
全部成功才发布 token 和 guest 写回。任一输出失败会回滚 reservation、新 capability 与对象
borrow，不留下半写 guest memory 或不可达 live value。

array element codec 复用现有 immutable codec program，生产路径不按函数名、class path、
ordinal 或 fixture identity 分派。Runtime 只管理 heap、host dispatch 和 session 生命周期；
WAMR/Wasmtime 不认识 `TArray` 或具体 UE API。

## Manifest 与授权

以下四个 shared capability 被视为原子集合：

- `avid_value_array_length (i)i`；
- `avid_value_array_load (iiii)i`；
- `avid_value_array_store (iiii)i`；
- `avid_value_release (i)i`。

生成器、Binding Slice、PowerShell package parser、prepared semantic、Runtime manifest loader、
WAMR registration、Wasmtime static host catalog 与 architecture gate 使用相同身份。包只声明
其中一部分、重复声明、修改 stable id/name/signature 或伪造 ordinal 都会在加载阶段拒绝。

## 性能结论

本阶段没有新增 array/Puerts 正式 benchmark，因此不宣称数组吞吐已经领先。Phase57 已冻结的
scalar、property、FVector、UObject prepared reflection 比率仍分别为 Puerts Reflection 的
`0.51409`、`0.66144`、`0.05573`、`0.53167`；这些数据只说明既有 prepared shape，不可外推
到数组。

当前数组 `Length`、每次 element load 和每次 element store 都经过一次 host crossing。这个
模型先提供稳定、安全、可用的闭环；下一性能批次应引入批量 view/copy 或受控借用 ABI，再以
冻结数组 workload 对比 Puerts 的实际数组路径。纯 Wasmtime/V8 controlled suite 的 P95 债务
也仍保持 `Fixing`，没有被本阶段掩盖。

## 当前边界

- 只支持一维、固定元素 codec 的 `TArray<T>`，不支持 nested array；
- FName/FString/FText 尚不能作为数组元素；
- TSet、TMap、delegate、latent、RPC 与 interface dispatch 尚未完成；
- 当前 C# array 是受控语言子集，不等于完整 .NET Array/BCL/GC；
- 热循环逐元素 host call 尚未优化，长数组不应据此宣称性能领先；
- Cook、Shipping、Android/iOS AOT 与移动端内存预算尚未正式验收。

## 下一批次建议

P57.11C 应先建立数组专用性能协议和批量访问 ABI：冻结 scalar/vector/struct/object 数组的
Length、bulk read/write、UFUNCTION roundtrip、property get/set 与 release workload，并同口径
对比 Puerts。功能侧随后扩展 string element、nested container、TSet/TMap；delegate、latent、
RPC 和 interface dispatch 继续独立推进，避免把容器 ABI 与调用语义耦合成新的大模块。
