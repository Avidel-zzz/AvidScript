# P57.11 通用反射 Codec Program 架构设计

## 1. 背景

P57.10 已让 scalar、property i32、FVector 和 UObject roundtrip 通过不可变 invocation
cell 进入 prepared native 路径，并在冻结 Micro formal 中全部领先 Puerts Reflection。
但完整 UE API 覆盖仍由通用 dynamic dispatcher 承担：VM 先按 ordinal 调回 Runtime，
Runtime 再进入 package plan array，Bindings 在每次调用时遍历参数并按 value kind 分支。

现有通用路径其实已经支持 bool、全部整数/浮点、enum、FName 输入、UObject handle、
FVector、FRotator、FTransform 和 ref/out。主要问题不是“没有这些类型”，而是：

- `AvidScriptBindingInvocation.cpp` 已超过 4400 行，同时拥有 descriptor 校验、value
  codec、对象生命周期、host effect、prepared fast path 和通用 ProcessEvent executor；
- C# renderer 再次按 canonical type/kind 重复类型分支；
- generic call 每次仍有 ordinal lookup、package dispatch、参数循环和动态类型判断；
- 新增 FString、用户 UStruct 或容器时，没有单一的递归类型图与 wire contract 可扩展。

P57.11 的目标是把现有能力收敛为“递归 value codec + 不可变参数程序 + 可选生成特化”
的分层体系，自动覆盖用户 UFUNCTION，不增加逐 API wrapper。

## 2. 方案比较

### 方案 A：继续增加 typed host shape

短期最快，单个 shape 的调用成本最低。但 bool/enum/string/struct/ref/out 的组合会产生
指数级 shape，VM、Runtime、Bindings 和测试都要同步增加 switch，最终只是把逐 API
wrapper 换成逐签名 wrapper。

### 方案 B：立即切换 Wasm Component Model / WIT

Component Model 的 canonical ABI 和资源类型适合长期方向，但当前 Wasmtime C API、C#
toolchain、预编译 artifact、热重载证明和 Puerts benchmark 都建立在 Core Wasm import
上。一次切换会把 ABI、工具链、缓存、调试和性能归因同时置于变化中，无法在一个批次
内得到可信结果。

### 方案 C：递归 codec program + tiered specialization

在 descriptor load 时把类型图编译为不可变操作程序。通用层执行预绑定的 decode、
ProcessEvent/native、encode 指令；高频且可证明的调用再提升到 P57.10 typed cell 或
generated S1。该方案保持现有 Core Wasm ABI 兼容，同时提供可递归扩展的类型系统，
因此采用方案 C。

## 3. 分层模型

### Tier 0：strict universal reflection

- 支持任意由已注册 codec 组成的 UFUNCTION 参数图；
- 走 ProcessEvent，保持 Blueprint override、RPC/event/interface 等 UE 语义；
- package load 时完成 UFunction/FProperty/type graph 验证，调用时不做名称查找；
- 用于完整覆盖与安全 fallback，不承担最低延迟承诺。

### Tier 1：prepared codec program

- VM dynamic import 直接持有 opaque prepared target，成功路径不再通过 ordinal 和
  package plan array；
- 每个参数编译为 decode/encode op，op 已绑定 FProperty、frame offset、direction、
  guest wire layout 和 capability requirement；
- executor 只遍历紧凑 op tape，不按 canonical string 或 Property class 动态选择 codec；
- frame alignment、InitializeStruct/DestroyStruct、out/ref chain 和 host effect policy 都
  固化在 invocation cell。

### Tier 2：typed/generated specialization

- P57.10 typed cells 与 Generated S1 保持不变；
- profiler/生成器可以把高频参数图提升为固定 C++ thunk；
- 提升规则按参数图 hash 和安全证明工作，不按 UE API 名称工作。

## 4. 模块边界

### AvidScriptBindings

新增私有目录 `Private/Invocation`：

- `AvidScriptBindingValueCodec`：value kind、direction、wire layout 与
  decode/encode 函数表；
- `AvidScriptBindingCodecProgram`：不可变 op tape、frame contract、参数图 hash；
- `AvidScriptBindingPreparedInvocation`：receiver、host effect、frame lifecycle 和
  ProcessEvent/native executor；
- `AvidScriptBindingInvocation.cpp` 只保留 package load、plan ownership 和公共 facade。

Bindings 不访问 Wasmtime，不持有 runtime session，也不拥有 UObject registry。

### AvidScriptRuntime

- package 加载后为 dynamic import 绑定 prepared target context；
- 解析 self/object capability、guest memory、write policy、host effect journal、reload
  epoch 与 package owner；
- 在调用产生 host side effect 前完成所有可预检的 guest range/capability 校验；
- reload/unload 先撤销 VM prepared target，再释放 codec program owner。

### AvidScriptVM

- `FAvidScriptVmDynamicImport` 增加可选 opaque prepared dynamic target；
- Wasmtime dynamic callback 完成固定 ABI cell 解码后优先调用 prepared target；
- 未绑定 target 的旧 artifact 继续使用 `IAvidScriptHostDispatcher`；
- VM 不包含 UE type、FProperty、codec policy 或 UObject 逻辑。

### AvidScriptEditor

- ReflectedTypePolicy 输出递归 wire type graph，不再让 renderer 自行猜测类型；
- C# renderer 根据 wire codec model 生成 public type、storage type 和 marshal steps；
- descriptor schema 对新增 type node/field/element contract 做 canonical hash；
- 代码生成仍由选择 profile 自动驱动，不要求用户手写 glue。

## 5. Codec Program

每个 value node 编译为以下信息：

- kind、direction、native size/alignment、wire size/alignment；
- FProperty 与 frame offset；
- argument cell offset/width；
- guest read/write requirement；
- object expected class 或 child codec index；
- `DecodeCells`、`DecodeGuest`、`EncodeGuest` 函数指针；
- construct/destroy requirement。

函数 cell 持有连续的 input op、output op 和 return op。调用顺序固定为：

1. 校验 argument count、guest memory availability、receiver capability 和 write policy；
2. 对所有 guest address、长度、容量和 object handle 做无副作用预检；
3. 对齐并初始化 frame；
4. 执行 input op tape；
5. 准备 host effect journal；
6. ProcessEvent，或在 native proof 成立时调用 prepared native thunk；
7. 执行 ref/out/return output tape；
8. 销毁 frame，并返回稳定错误类别。

任何 decode/preflight 失败都发生在 UE side effect 前。output buffer 不足不得重放有副
作用的 UFUNCTION；可变长输出必须使用一次调用即可安全发布的 host-owned blob handle，
不能通过“执行一次拿长度、再执行一次拿数据”的方式实现。

## 6. Wire 类型图

P57.11 保留 schema v6 artifact 兼容，并为递归 codec 引入新 schema revision。type node
至少包含：

- scalar/enum：Wasm `i32/i64/f32/f64`；
- object：`slot + generation` capability；
- fixed struct：descriptor field list 与递归 child type；
- UTF-8 view：guest address、byte length、严格 UTF-8；
- host blob：slot、generation、byte length，用于 FString/容器等可变长输出；
- sequence：element type、count 和 wire stride。

首轮不把 UE native memory layout暴露给 C#。UStruct 使用稳定 wire field layout，Bindings
根据 field codec 写入 UE frame；因此 LWC、平台 alignment 或 UE 内部 padding 变化不会
破坏 guest ABI。

## 7. P57.11 分组

### P57.11A：prepared generic bridge 与代码拆分

- 把现有 scalar/enum/name/object/vector/rotator/transform codec 移出大文件；
- 为所有现有 dynamic UFUNCTION 生成 prepared dynamic target；
- 保持 descriptor schema、C# API 和 import signature 不变；
- 证明成功路径没有 ordinal/package Dispatch lookup。

### P57.11B：递归类型图第一批

- 增加 FString value/const-ref 输入和安全的 FString return/ref/out blob；
- 增加 FName return/ref/out；
- 增加只由已支持 codec 组成的用户 USTRUCT value/const-ref/return/ref/out；
- C# 生成 public struct/string API 与内部 marshal steps。

### P57.11C：性能与迁移

- 为通用 primitive、mixed numeric、name/string、user struct 建立冻结 workload；
- Tier 1 必须相对旧 dynamic dispatcher 明显降低固定成本；
- P57.10 四项正式比例不得回退；
- 记录下一阶段 sequence/container、delegate 和 soft reference 债务。

## 8. 安全与兼容

- schema v6 继续加载；新字段只由新 schema 使用，hash/identity 包含完整类型图；
- 旧 VM backend 或未绑定 prepared target 时 fail-safe 回到 dispatcher；
- object/blob handle 都有 slot + generation，不把裸 UObject/FString/TArray 地址暴露给 guest；
- guest address 使用 64 位中间算术防溢出，长度和递归深度有硬上限；
- arbitrary UStruct 只允许显式字段白名单，不序列化 transient/editor-only/delegate/
  instanced-reference 等危险字段；
- Blueprint/event/RPC/interface 调用保持 ProcessEvent，不因 codec program 自动升级 native；
- Runtime/Bindings/VM 的 ownership 与 reload 顺序沿用 P57.10。

## 9. 验收

- 用户自定义 UFUNCTION 不需要手写 wrapper 即可进入 codec program；
- 已支持类型的 C# 公共调用方式不变；
- P57.11A 所有 eligible dynamic import 均绑定 prepared target，dispatcher fallback 仅发生
  在旧 artifact 或显式不支持的 invocation kind；
- schema/renderer/runtime 对同一参数图产生相同 canonical hash；
- guest range、invalid UTF-8、forged object/blob handle、recursive depth、output capacity 和
  reload stale target 均 fail closed；
- focused Automation、完整 AvidScript Automation、UE 5.8 no-clean build、architecture
  contracts 与 frozen benchmark 在阶段末集中执行；
- 不新增按 UFunction 名称、fixture 名或 benchmark commit 的分支。

## 10. 非目标

- P57.11 不切换 Component Model/WIT；
- 不在同一批次实现 TMap/TSet、delegate、latent action、soft reference 和任意 UObject
  graph 序列化；
- 不为每个 UE API 生成手写 wrapper；
- 不用 Semantic 结果关闭 P57-D06 纯 Wasm execution debt；
- 不 clean Editor target。
