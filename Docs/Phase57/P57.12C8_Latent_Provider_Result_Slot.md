# P57.12C8 Latent Provider 与 Result Slot

## 目标

P57.12C8 实现 C6D 冻结的宿主侧 completion payload 基础：只有显式注册的
`IAvidScriptLatentCompletionProvider` 可以为一个准确的 latent UFUNCTION 发布 typed payload；结果先复制到
Session-owned result slot，再随既有五参数 continuation callback 传递 slot/generation capability。

本阶段没有增加按 UFUNCTION 名称判断的 Runtime switch，也没有保留 `ProcessEvent` 的 `ref/out` 指针。

## 显式 Provider 注册

provider 必须同时声明三个稳定身份：

- `provider_id`：插件级唯一 provider 名称；
- `function_path`：唯一的完整 UFunction path；
- `payload_type_id`：已经存在于 descriptor type graph 的类型稳定 ID。

`FAvidScriptLatentCompletionProviderRegistry` 同时按 provider ID 和函数路径建索引，重复注册任一身份都会失败。
Editor generator 只根据这个显式注册表生成 payload binding；Runtime 加载 descriptor 时再次校验 provider、
当前 UFunction 和 payload TypeId 三方一致。没有注册、注册已撤销或任一身份漂移时均 fail closed。

## Descriptor schema v13

含 provider payload 的 package 升级到 schema v13。每个 latent binding 都写入：

```json
{
  "completion": {
    "mode": "provider",
    "provider_id": "avidscript.test.score.v1",
    "payload_type_id": "<sha256-type-id>",
    "status_policy": "abandon_on_cancel",
    "cancellable": true
  }
}
```

同一 v13 package 中没有 payload 的 latent binding 使用 `mode = none`，provider/type identity 必须为空。
schema v12 保持原 completion-only 语义；v12 出现 completion block、v13 未知 mode、缺失 payload type、
非 latent binding 携带 completion block 都会被拒绝。selection hash、package hash 和 provider binding 的
canonical identity 都纳入 completion 合同，不能通过只改 JSON 绕过验证。

## Session result slot

每个 Runtime Session 最多持有 1024 个 result slot，每个 C8 payload 最多包含 64 个规范化 ABI cell。
slot 使用独立的 slot/generation capability，并冻结 lane、activation serial、continuation token 和 TypeId。

- provider 成功发布且 result slot 分配成功后，continuation 才进入 Ready；
- provider 缺失结果、TypeId 不符、cell 为空或超过上限时发布 `Failed`，不暴露半成品；
- 只有准确 lane、activation、slot、generation 和预期 TypeId 可以消费；
- 消费是 move-and-release，只能成功一次；
- cancel、prepared discard、active replacement、dispatch 未消费回滚和 teardown 都会回收 slot；
- prepared result slot 与 continuation 一起提升到 active lane，旧 lane 不能消费。

provider 还必须实现 `AbandonPayload`。取消在 payload 被 Session 消费前获胜时，Session 会通知 provider
清理自己的待发布状态；一旦已经复制进 result slot，后续生命周期只由 Session 管理。

## C8 与 C9 边界

C8 没有公开 Guest 读取 ABI。生成器遇到 `mode = provider` 时会以稳定错误
`latent_completion_payload_guest_unsupported` 停止生成 C# facade，避免脚本看到无法消费的伪 API。

P57.12C9 才会实现一次性 bulk read/release、compiler-owned resume route 与 `AvidOutcome<T>`，并扩展对象、
固定结构体、UTF-8 和数组所有权。当前 C# 游戏脚本仍只能使用 completion-only latent await 与 C7 显式取消；
不能宣称已经能读取 latent payload。
