# P57.11B2 变长 UTF-8 Value Heap 阶段报告

## 当前状态

P57.11B2 已完成。AvidScript 现在可以把普通反射 `UFUNCTION` 和 `UPROPERTY` 中的
`FName`、`FString` 自动投影为 C# `string`，覆盖 value、`const ref`、`ref`、`out`、
return、property get 和 property set。实现不依赖函数名、ordinal 或逐 API wrapper，符合
类型合同的用户自定义 UFUNCTION 会自动进入相同路径。

真实 C# fixture 已经通过 Roslyn frontend、Semantic、Guest IR、Wasm backend 和运行时
绑定闭环，并分别在 WAMR 与 Wasmtime 上执行 BeginPlay/Tick。最终 UE 5.8 no-clean 构建
通过，完整 `AvidScript` Automation 为 `341/341` Success，clean architecture Gate 通过。

## 已实现能力

### C# 字符串调用面

生成 facade 将 `FName` 和 `FString` 都公开为 C# `string`。用户可以直接写属性、读取属性，
也可以使用 ref/out/return：

```csharp
[UnmanagedCallersOnly(EntryPoint = "avid_on_begin_play")]
public static void BeginPlay()
{
    AAvidScriptCSharpNameStringTestActor self = UE.Self;
    self.ReadableFName = "Input_Name_\u540d";
    self.ReadableFString = "Input_String_\u503c";
}

[UnmanagedCallersOnly(EntryPoint = "avid_on_tick")]
public static void Tick(float deltaSeconds)
{
    AAvidScriptCSharpNameStringTestActor self = UE.Self;

    string name = self.ReadableFName;
    string text = self.ReadableFString;
    self.RefFName(ref name);
    self.RefFString(ref text);

    self.OutFName(out string outName);
    self.OutFString(out string outText);
    self.ReadableFName = self.ReturnFName();
    self.ReadableFString = self.ReturnFString();
}
```

这段能力不是测试类专属。Editor 根据反射类型生成 descriptor 和 facade；项目自己的 Actor、
Component 或 UObject 只要 UFUNCTION 形状满足通用安全规则，就会使用相同 codec。

### Descriptor 与 API 覆盖

类型合同保持单一 Wasm `i32` value reference：

| UE 类型 | canonical type | descriptor kind | Wasm ABI | C# 类型 |
|---|---|---|---|---|
| `FName` | `name:fname` | `name_utf8` | `i32` | `string` |
| `FString` | `string:fstring` | `string_utf8` | `i32` | `string` |

schema 版本仍为 9，不需要为字符串单独提高格式版本。renderer 会严格检查 canonical type、
kind、C++ type、ABI、size/alignment 和 direction，描述符被篡改后 fail closed。

EngineGameplay profile 因通用 FName return 支持自动新增三个 UE API：

- `Actor.GetAttachParentSocketName`；
- `SceneComponent.GetAttachSocketName`；
- `PrimitiveComponent.GetCollisionProfileName`。

accepted function 从 349 增至 352；连同两个 property，生成 binding 从 351 增至 354，
再加 object-type 与 owner-handle 两项共享 capability，授权 import 总数为 356。旧 binding
集合没有删除成员。

### Session-owned UTF-8 capability heap

guest 中的字符串仍只占一个 `i32`。最高位为 0 时，它是 linear UTF-8 地址，格式为
`[u32 length][payload][NUL]`；最高位为 1 时，它是 runtime session 签发的 heap token。
guest 看不到 UE 的 `FString` 内存，也不能把任意宿主地址伪装成字符串。

token 使用 `1-bit tag + 31-bit process-unique capability id`。ID 在进程内单调分配且永不
复用，因此不同 runtime、reset 前后和 reload 前后的 token 不会偶然重新获得权限。每个
session 最多保有 65,535 个 live value，单值最大 1 MiB；达到 live 上限或全进程 ID 空间
耗尽时均 fail closed。

heap 按 UTF-8 bytes 做 hash lookup，再 exact compare。相同值返回已有 token，不复制第二份
payload；empty 与 Unicode 合法，非 canonical UTF-8、FName 内嵌 NUL 和超长 Name 均拒绝。

### 原子输出与副作用边界

prepared dynamic executor 在调用 UFUNCTION 前完成以下工作：

1. 验证所有 guest 输出地址、alignment 和范围；
2. 拒绝完全或部分重叠的 ref/out/return 存储；
3. 借用所有 mutable output range；
4. 为全部 FName/FString 输出预留 heap 容量。

只有预检全部成功才允许 `ProcessEvent`。调用结束后，所有输出先编码到 staging storage；
所有编码都成功后才一次性发布 token 和 guest bytes。任一阶段失败都会回滚 reservation、
本次新 token 与对象 borrow，不会留下半写 guest memory 或不可达 heap value。生产输出路径
不再降级到逐项 `WriteBytes`。

Runtime 实例拥有自己的 heap，并在 unload、replacement load 与析构时 reset。Runtime 只
负责生命周期和 Bindings context 注入；VM、WAMR、Wasmtime 不包含 FName/FString 分支。

## 双后端闭环指标

同一个由 C# 编译产生的 Wasm fixture 在 WAMR 和 Wasmtime 上得到一致结果：

| 阶段 | live values | reservations |
|---|---:|---:|
| BeginPlay 后 | 0 | 0 |
| property get 后 | 2 | 0 |
| ref output 后 | 4 | 0 |
| out output 后 | 5 | 0 |
| return output 后 | 5 | 0 |

一次完整 oracle 包含 2 个 literal input、8 次 output publication、5 个 unique live value、
3 次 intern hit 和 2 个 ref round-trip。每个可观察边界的 reservation 都归零，证明没有
泄漏未提交容量。返回 token 会继续作为后续调用输入，验证了跨 invocation 复用。

## 性能约束

B2 没有修改 P57.10/P57.11B1 的四个 typed prepared shape，静态路由 Gate 已确认 workload、
backend、计时源与 validation 合同不变。本阶段沿用最近一次冻结正式数据：scalar、property、
vector、object 分别为 Puerts Reflection 的 `0.51409`、`0.66144`、`0.05573`、`0.53167`，
四项仍全部领先。

这些数据不能被解释为新字符串路径的吞吐 benchmark。B2 首要目标是正确性、权限隔离和
原子提交；下一轮如优化字符串 hot path，应新增冻结字符串 workload，并分别测量 linear
decode、intern hit、unique output 和 UE ProcessEvent 边界，不能混用整数 benchmark 得出结论。

## 明确不支持的边界

- `FText` 的本地化 identity、namespace/key 和 history 语义尚未支持；
- `TArray`、`TSet`、`TMap` 及字符串数组尚未进入通用 container codec；
- 固定宽度 `struct_wire` 内仍不允许 FName/FString child；
- delegate、multicast delegate、latent、RPC 和 interface dispatch 仍是独立能力；
- heap 当前是 session 生命周期 ownership，不提供 guest 主动 release 或长期 GC；
- 移动端 backend、AOT artifact 与平台内存预算仍需后续适配。

这些是类型与生命周期边界，不要求逐个手写 UE API。后续应继续扩展 descriptor-driven codec
和调用语义，使符合规则的 API 批量自动获得覆盖。
