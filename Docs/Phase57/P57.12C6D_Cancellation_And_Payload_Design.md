# P57.12C6D 显式取消与 Completion Payload 设计

## 状态

设计已冻结，行为实现安排在 P57.12C7 与 P57.12C8。当前 C6 代码继续 fail closed：生成式 latent
await 尚未暴露脚本取消 token，也不把 UE latent `ref/out` 当作完成 payload。

## 现有基础

当前 continuation 由 Session 分配 64 位 generational token，绑定 Active/Prepared lane、activation serial、
World、owner generation 与 producer。`Pending -> Ready -> Dispatching -> Terminal` 只在 Game Thread
推进，reload discard、EndPlay、World teardown 与 owner 失效会取消整条 lane。

低层 `AvidContinuation.Cancel()` 已能取消显式 callback API，但受控 `await FooAsync()` 的 producer token
只存在于编译器生成的调度 segment 中，脚本拿不到它。因此直接把现有类型改名为 `CancellationToken`
既不能取消 await，也无法覆盖完成竞态。

## 决策一：Cancellation scope 与 continuation token 分离

脚本使用独立的 `AvidCancellationSource`。一个 source 可以绑定多个 continuation，符合游戏中“取消这一组
加载/移动/过场”的常见需求；脚本永远不能看到 UE latent UUID 或内部 continuation token。

```csharp
AvidCancellationSource source = AvidCancellationSource.Create();
await UKismetSystemLibrary.DelayAsync(0.25f)
    .WithCancellation(source.Token);
```

`.WithCancellation(...)` 是编译器识别的零 CLR Task 标记，不执行普通 C# 方法体。producer 调度顺序固定：

1. 校验 cancellation token 属于当前 Session、lane 与 activation serial；
2. 调用 descriptor 授权的 producer，获得 continuation token；
3. 在同一 Game Thread 调度段调用 `continuation_bind_cancel`；
4. 绑定失败时立即取消刚创建的 producer，调度段 fail closed，不留下孤儿 action；
5. 绑定成功后才允许调度段返回。

冻结的 host ABI：

```text
continuation_cancel_source_create() -> i64
continuation_cancel_source_cancel(i64 source_token) -> i32
continuation_cancel_source_release(i64 source_token) -> i32
continuation_bind_cancel(i64 source_token, i64 continuation_token) -> i32
```

source token 与 continuation token 使用不同的 token kind，不能互换。每个 Session 最多存在 1024 个
source、4096 条 continuation binding；超过上限拒绝分配，不回退到无取消调度。

## 取消状态机

Cancellation source 状态只有 `Open`、`Cancelled`、`Released`。continuation 状态维持：

```text
Pending -> Ready -> Dispatching -> Terminal
    |         |
    +---------+-> Cancelled -> Terminal
```

- `Cancel()` 只对 `Pending/Ready` 赢得竞态；它取消 producer、移除 ready completion，并释放 slot；
- 已进入 `Dispatching` 的 completion 胜出，取消返回 false，不中断 Guest；
- 重复取消或释放没有副作用，返回 false；
- source 先取消、后绑定时，bind 会同步取消新 continuation 并返回“已处理”；
- Prepared token 不能绑定或取消 Active continuation，反向同理；
- reload 后旧 generation token 永久失效，不迁移到 candidate；
- latent proxy 可以被 UE 延迟删除，但 disarm 后的迟到 callback 不能重新排队。

受控 async router 后续增加 `Cancelled = 3`。取消获胜时不执行 await 后续 segment；Failed 仍按编译器策略
trap，Completed 才进入下一段。这样取消不会伪装成正常完成，也不要求当前受限 C# 支持异常。

## 决策二：Payload 必须来自显式 provider

UE latent UFUNCTION 的 `ProcessEvent` frame 在调度调用返回后即结束。普通 `ref/out` 只描述调度帧，
Reflection 无法证明哪个对象会在 action 完成时写回数据。因此禁止：

- 把 latent `ref/out` 指针保留到完成时；
- 根据函数名、参数名或 Blueprint pin 猜测 payload；
- 在 callback proxy 中读取已经销毁的 ProcessEvent frame；
- 为每个 UE API 增加 VM switch。

有 payload 的 producer 必须注册 `IAvidScriptLatentCompletionProvider`，并由 descriptor 记录稳定 provider
identity。provider 在 completion 排队前把结果复制到 Session-owned result slot；结果类型仍使用现有
descriptor type graph、object capability、fixed struct、UTF-8 与 array codec。

## Descriptor schema v13

schema v13 为 latent binding 增加显式 completion 块：

```json
{
  "completion": {
    "mode": "none",
    "provider_id": "",
    "payload_type_id": "",
    "status_policy": "abandon_on_cancel",
    "cancellable": true
  }
}
```

允许值：

- `mode = none`：当前 completion-only 行为；`provider_id/payload_type_id` 必须为空；
- `mode = provider`：两项 identity 必须存在，provider 注册表、UFunction identity 与 payload type 必须
  三方一致；
- `status_policy = abandon_on_cancel`：取消不进入后续 segment；
- 后续只有在编译器支持显式 outcome 后才允许 `resume_outcome`。

旧 schema v12 读取语义等价于 `mode=none`、不可脚本显式取消，保持兼容。未知 mode、provider、类型、
状态策略一律拒绝加载。

## Session result slot

result slot 也是 slot/generation capability，最多 1024 个。现有 continuation callback 的五参数 ABI
保持不变：

```text
avid_on_continuation_v2(
    i32 callback_id,
    i64 continuation_token,
    i32 status,
    i32 payload_slot,
    i32 payload_generation)
```

对 `payload_kind=object`，两个 payload cell 保持现有对象 capability；对通用 provider payload，它们解释为
result slot capability，具体类型由编译期 resume route 冻结，而不是由 Guest 传入。Guest 通过 descriptor
生成的批量 result codec 读取并原子 release，避免按字段跨 Host 边界。

result slot 所有权规则：

- provider 写入成功后才能发布 Ready；失败发布 Failed 且不暴露半成品；
- object/string/array capability 在 slot release、取消、reload 或 teardown 时统一回收；
- Guest 只能读取当前 callback 携带且 TypeId 匹配的 slot；
- 一个 slot 只能消费一次，重复读、错类型、旧 generation 都 fail closed；
- callback dispatch 失败时由 Session 回滚 result slot，不把所有权遗留给 Guest。

## C# typed surface

completion-only API 保持现有零分配表面：

```csharp
await UKismetSystemLibrary.DelayAsync(0.25f);
```

provider payload 使用显式 outcome，避免在受限 C# 子集中伪造异常：

```csharp
AvidOutcome<UObject> outcome = await ProjectAsync.LoadActorAsync(...)
    .WithCancellation(source.Token);

if (outcome.Succeeded)
{
    UObject actor = outcome.Value;
}
```

`AvidOutcome<T>` 只包含 `Status` 与 typed value，不保存 host 指针。compiler-owned resume route 负责 result
slot read/release；用户代码不能自行构造有效 outcome capability。

## 性能与安全门禁

- completion-only 且未使用取消时不增加 Host crossing；
- 使用取消时只增加一次 `continuation_bind_cancel`，不在 Tick 轮询；
- result payload 使用一次批量 read/release，不按字段调用；
- token lookup、source fan-out 与 result slot lookup 都是 O(1) 或与被取消绑定数线性；
- 所有计数有硬上限，provider 不得持有 Guest memory 指针；
- benchmark 必须分别报告无取消 fast path、bind path、cancel fan-out 与 payload bulk read。

`P57-D06-ControlledLeadership` 继续保持 `Fixing`。C6D 没有修改冻结性能阈值，也没有用设计结论替代
正式 benchmark。
