# P57.5 Shape-Specialized Prepared Export

## 1. 问题与目标

Phase 56 的 prepared export 已缓存导出 slot，但正式比值仅为 `0.995238`，未达到
冻结门禁：

```text
prepared_export_ratio <= 0.95
```

P57.5 基线 diagnostic 仍为 `0.997041`：generic export `34.0 ns/op`，prepared
export `33.9 ns/op`，只节省 `0.1 ns/op`。归因显示两条路径最终都使用 Wasmtime
unchecked raw call；prepared 省掉的 handle 查找，被公共校验、函数指针 thunk、
backend 转发和通用 cell marshalling 抵消。

本批次不修改 physical ladder 的 kernel、seed、stage、oracle、样本数或阈值。

## 2. 设计

### 2.1 解析期 ABI shape 分类

Wasmtime 导出解析后保存语言无关的 prepared call shape。目前首个专用 shape 为：

```text
(i32, i32) -> i32
```

分类依据只包含参数与返回值类型，不读取函数名、fixture 名、UE API 名或候选 commit。
未命中专用 shape 的导出继续使用通用 prepared cell 路径。

### 2.2 Raw-value 专用 thunk

`PrepareExportCall` 在计时窗口前选择固定 thunk。专用 thunk 直接构造两个
`wasmtime_val_raw_t` 参数并读取一个 `i32` 结果，消除通用路径中的：

- parameter/result kind 循环；
- cell index 推进；
- result capacity 与动态 result count plumbing；
- 最大结果数组的清零与复制。

这是一种有限 ABI shape specialization，不是逐 API wrapper。后续可按真实 profile
扩展 `() -> ()`、`(f32) -> ()` 等生命周期 shape，而不污染 Runtime 与绑定层。

### 2.3 共享失败收尾

通用与专用调用都进入同一个 `CompleteResolvedExportCall`：

- trap 与本地调用失败生成相同错误类别和 stack frame；
- host import failure 仍优先传播；
- active call depth 与 deferred unload 顺序不变；
- reentrant unload 仍返回 `reentrant_unload`；
- result cell count 仍与解析期 ABI 比较；
- unload 会清空 tombstone 的 function 并推进 generation，旧 prepared call 继续拒绝。

专用 C 函数以 `unchecked` 命名，表示它只能由完成 shape 与生命周期证明的 prepared
cell 调用；它不是公共脚本 ABI。

## 5. 结论

P57.5 关闭 `prepared_export_ratio` 性能债务。prepared export 不再只是缓存 handle，
而是解析期编译出的 ABI-shape call cell；在保持完整错误与生命周期语义的同时，正式
配对 P50 相对 generic export 减少约 `9.48%`。

Phase 57 仍剩 controlled-runtime 的两项领导性门禁：

- `wasmtime_v8_geo_ratio <= 0.95`；
- `kernel_win_rate >= 0.60`。

下一批将对 hashing、predictable branch、SIMD128 与 P95 抖动做代码生成和 runtime
配置归因，不修改冻结的 12 个 kernel 字节。
