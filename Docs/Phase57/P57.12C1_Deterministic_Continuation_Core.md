# P57.12C1 确定性 Continuation 核心

状态：实现与运行验收通过，clean candidate 架构证据待提交后回填

## 本阶段完成的能力

P57.12C1 建立了 AvidScript 第一条由真实 UE deferred producer 驱动的 C# continuation 闭环：

```text
C# AvidContinuations.Delay / NextTick
  -> env.continuation_delay
  -> Session prepared/active continuation owner
  -> UE5.8 FTimerManager
  -> Session ready queue
  -> avid_on_continuation
  -> 编译器生成 callback-id dispatcher
  -> C# public static handler
```

它与旧 `UE.SetTimer` 不同：旧 Timer 由单个 WASM Runtime 的逻辑时钟推进，并要求用户手写
`avid_on_timer`；新 continuation 由 UE TimerManager 完成、由 Runtime Session 统一拥有，Guest export
与 handler 分发均由编译器生成。

## C# 使用方式

```csharp
private const int ResumeSpawn = 1;

[AvidTransient]
private static AvidContinuation PendingSpawn;

public static void BeginPlay()
{
    PendingSpawn = AvidContinuations.Delay(0.25f, ResumeSpawn);
}

[AvidContinuation(ResumeSpawn)]
public static void ResumeSpawnHandler()
{
    UE.Self.SetActorScale3D(new FVector(1.05f, 1.0f, 1.0f));
}
```

`AvidContinuation` 是不透明 64 位 token，只提供 `IsValid` 与 `Cancel()`。保存 token 的静态字段
必须标记 `[AvidTransient]`，因为 token 绑定当前 Session activation，不能跨热重载迁移。

当前 handler 必须满足以下约束：

- `public static void`；
- 无参数、非泛型、有具体方法体；
- callback id 是正整数，并在脚本内唯一；
- `Delay`/`NextTick` 调用使用编译期常量 callback id，且必须对应一个 handler；
- lambda、closure、普通 `Task`、`ValueTask` 和 C# `async/await` 继续 fail-closed。

## ABI 与编译器合同

Host import：

```text
env.continuation_delay(f32 delay_seconds, i32 callback_id) -> i64 token
env.continuation_cancel(i64 token) -> i32
```

Guest export：

```text
avid_on_continuation(i32 callback_id, i64 token, i32 status) -> void
```

C1 dispatcher 只用 callback id 调用零参数 handler；token 与 status 已进入稳定 ABI，供后续异步资源
结果、失败/取消状态和受控 C# 状态机使用。WAMR 使用显式 native thunk，Wasmtime 继续复用统一
static-import catalog，没有复制后端业务逻辑。

## Session 所有权

continuation owner 位于独立 `Continuation` 模块，不放进 Runtime 的 Timer 容器，也不让 Session
直接管理 FTimerManager 细节。

- token 采用 slot/generation 编码，slot 重用会更换 generation，旧 token 不能命中新任务；
- endpoint 显式携带 active/prepared lane 与 activation serial，不依赖全局 `bPreparing` 猜测身份；
- candidate `BeginPlay` 只写 prepared lane；完成可以进入 prepared ready 状态，但不能恢复 Guest；
- host-effect commit 前验证 prepared World；失败只取消 prepared timer 并保留旧 active；
- 成功提交会先关闭旧 active endpoint、取消旧 producer，再把 prepared endpoint 原位提升为 active；
- candidate token 在成功提升后保持不变；旧 active token、重复 token 和伪造 token 返回失败；
- Timer lambda 只捕获 continuation owner 的弱引用，不捕获裸 Session 指针。

## 调度与 teardown

FTimerManager 回调只把完成项放入 ready queue，不直接进入 Guest。Session 在正常 Tick 完成后按
`registration_serial` 恢复最早的一项：

- 同一调用栈内不会同步重入；
- 每个 Session Tick 最多恢复一个 continuation；
- 回调产生的新 continuation 最早在后续 timer pump 与 Session Tick 中恢复；
- producer 已完成但 Guest 尚未恢复时，token 仍可取消并抑制该回调；
- handler 开始前 token 已失效，回调内取消自身返回 `false`；
- HostContext owner/registry/world 变化、`ClearHostContext`、`EndPlay`、Unload 与 Session 析构都会
  关闭 endpoint、清理 ready queue 并取消对应 FTimerHandle；
- retired endpoint 会保留到旧 Runtime 完成 EndPlay/Unload 或 HostContext 切换，避免 Runtime 中的
  裸 host interface 指针悬空。

## 顺带修复

delegate subscription 的 `Prepare(nullptr, non_empty_events)` 失败路径现在会退出 prepared 模式。
此前该路径可能让后续 live subscribe/cancel 错误进入 prepared lane；新增回归覆盖会验证旧 active
广播和显式订阅在失败后仍可工作。

## 已知边界

- `NextTick` 表示当前调用栈返回后的下一次 UE TimerManager pump，不承诺跨越完整渲染帧；
- C1 producer 只有 Delay/NextTick，不包含 `StreamableManager::RequestAsyncLoad`；
- C1 不支持 C# `async/await` 状态机、局部变量 spill、异常传播或泛型 `AvidTask<T>`；
- UE latent UFunction 仍由反射策略拒绝，后续通过通用 producer adapter 接入；
- 每 Tick 一个恢复项优先保证 teardown 边界；可配置批量预算要等 Session stop fence 完成后再开放；
- 本阶段没有改变反射调用热路径，不新增性能结论，P57-D06-ControlledLeadership 继续保持开放。
