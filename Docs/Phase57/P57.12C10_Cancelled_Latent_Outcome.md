# P57.12C10 可观察的 Latent 取消终态

## 目标

P57.12C10 补齐 provider 型 latent await 的第三种终态：脚本主动取消后，不再只能依赖“后续代码没有执行”
来推断结果，而是可以从同一个 `AvidOutcome<T>` 中读取 `Cancelled`。成功、失败与取消现在共享一条生成式
callback、result-read 与 Guest lowering 路径，没有增加按 UFUNCTION 名称手写的 Runtime API。

```csharp
AvidOutcome<int> outcome = await UKismetSystemLibrary
    .WaitForScoreAsync(42)
    .WithCancellation(lifetime.Token);

if (outcome.Cancelled)
{
    return;
}

if (outcome.Failed)
{
    return;
}

int completedScore = outcome.Value;
```

## Descriptor schema v14

provider 型 latent binding 升级到 descriptor schema v14，并冻结：

```json
{
  "mode": "provider",
  "status_policy": "resume_outcome_on_cancel",
  "cancellable": true
}
```

schema v13 的 `abandon_on_cancel` 继续可加载并保持原语义；completion-only latent 也继续静默取消。v14 只允许
provider result 使用 `resume_outcome_on_cancel`，防止普通 `DelayAsync` 或对象加载 await 在没有 status/result
存储的情况下错误执行后续 segment。C# binding package resolver 与 Runtime reload manifest 同时保留 v2-v14
兼容范围。

## Session 取消竞争

`FAvidScriptSessionContinuations` 只在以下条件同时成立时排队 `Cancelled`：

- token 属于当前 Session、lane 与 activation；
- continuation 尚未进入 dispatch；
- binding 是显式 provider completion；
- status policy 为 `resume_outcome_on_cancel`。

取消获胜后，Session 停止 timer、async load 或 `FLatentActionManager` producer，回收尚未消费的 result slot，
解除 cancellation-source binding，并按原 registration serial 排队一次终态 callback。重复取消会失败，旧 token
不能再次产生 callback。无效 cancellation source/token 仍按 fail-closed 路径直接释放 continuation，不会伪装成
合法的取消结果；World 失效、reload discard 和 Session teardown 也不会向已失效 VM 投递回调。

provider payload 只有在尚未形成 Ready 结果时才调用 `AbandonPayload`。这避免失败结果已经完成后又被取消所
造成的重复 abandon，同时保留 pending producer 的确定性清理。

## Runtime 与 Guest

取消没有新增 host import。`avid_on_continuation_v2` 继续传递 status、slot 与 generation；对于 `Failed` 和
`Cancelled`，`continuation_result_read` 要求 slot/generation 都为零，一次性把预定 payload 布局清零并标记
已消费。`Completed` 仍必须携带准确的 result capability 并通过 TypeId/ordinal 校验。

生成的 `AvidOutcome<T>` 新增：

- `Succeeded`：status 为 `Completed`；
- `Failed`：status 为 `Failed`；
- `Cancelled`：status 为 `Cancelled`。

Guest 编译器把三个属性统一 lower 为 status enum 比较。取消结果仍只执行一次 bulk result read，不进行字段名
查找，也不引入新的 VM binding ID、WAMR wrapper 或 Wasmtime adapter。

## 后续边界

C10 完成的是 provider latent 的成功、失败、取消三终态闭环。下一批应转向结构化 async 上层能力：限定的
continuation 组合器、异常到 `Failed` 的稳定映射、可诊断错误码，以及真实游戏脚本中的多 await 生命周期。
成功热路径没有增加 host crossing，但本阶段未重跑冻结 Wasmtime/V8 性能套件；
`P57-D06-ControlledLeadership` 继续保持 `Fixing`，不能宣称性能门禁已经关闭。
