# P57.12C3 受控 C# async/await 闭环

状态：完成

## 本阶段完成的能力

P57.12C3 在 C2 的 Session-owned Continuation ABI 上实现了第一版原生 C# `async/await`。脚本可在
`BeginPlay` 等 UE 生命周期入口中直接等待下一 Tick、延时或异步对象加载，再继续执行 UE 游戏逻辑：

```csharp
[UnmanagedCallersOnly(EntryPoint = "avid_on_begin_play")]
public static async void BeginPlay()
{
    UE.Self.SetActorLocation(new FVector(100.0f, 200.0f, 300.0f));
    await AvidContinuations.NextTickAsync();

    AvidLoadedObject loaded = await AvidAssets.LoadObjectAsync(
        "/Engine/EngineMeshes/Cube.Cube");
    UObject mesh = UObject.TryCast(loaded);
    UE.Self.AddActorWorldOffset(new FVector(0.0f, 0.0f, 10.0f));
}
```

这不是把 CLR `Task` Runtime 搬进 WASM。Roslyn Semantic 将受控 async 方法切成同步 segment，Guest
lowerer 生成直接 continuation-passing style（CPS）WASM 函数。当前子集不生成 CLR 状态机对象、GC
依赖或每次 await 的 Guest 堆分配。

## 编译链路

```text
C# async export
  -> Roslyn SemanticAsyncMethod / SemanticAsyncSegment
  -> 受控 await shape 与跨暂停数据流验证
  -> segment 0 保留原 export/function id
  -> segment 1..N 生成 async_resume 内部函数
  -> continuation_delay / continuation_load_object
  -> Session token、ready queue 与安全 Tick 分发
  -> avid_on_continuation_v2 callback router
  -> 直接调用下一 resume segment
```

Semantic contract 升级为 `12 / 1.12`，新增 `SemanticAsyncMethod`、`SemanticAsyncSegment` 与
`SemanticAsyncAwaitSite`。每个 await site 具有稳定 callback id、producer/payload shape、源码位置和
后续 segment。prepared semantic、semantic cache、publication contract、debug map 与架构检查已同步
升级；schema 11/10 continuation Guest 继续兼容。

## 受控语法子集

- async owner 必须是零参数、非泛型、block-bodied 的 `public static async void` 导出；
- 支持任意顺序的多个直接 `DelayAsync(float)`、`NextTickAsync()` 与
  `LoadObjectAsync(const string)`，每方法最多 16 个、每模块最多 64 个；
- await 只能是顶层独立语句，或单变量声明的 initializer；
- 普通 segment 支持表达式语句与带 initializer 的单变量声明；
- 对象结果可以在紧随其后的 segment 使用，但普通 local、参数与对象结果不能跨越下一 await；
- 需要跨暂停保存的简单状态必须显式放入静态字段；
- loop/if/switch/try/using/lock 内 await、assignment RHS await、async helper 调用链、`Task`、
  `ValueTask`、异常传播、lambda/closure 与泛型 async 返回均 fail-closed。

## 调度与生命周期

编译器 callback id 使用 `[0x40000000, 0x7fffffff]`，用户 `[AvidContinuation]` 使用
`[1, 0x3fffffff]`，两者不会碰撞。callback id 标识静态 await site；Session token 标识一次具体调用。
当前无 spill frame，因此同一 async export 可并发重入而不共享局部状态。

- producer 返回零 token 时，当前源码 segment 立即 trap，避免异步流程永久悬挂；
- completion 不直接重入 Guest，而是在 Session 安全 Tick 边界恢复；
- cancel、prepared discard、热重载回滚、HostContext 切换、`EndPlay` 与 teardown 抑制未分发回调；
- 对象结果沿用 C2 的 generational capability、强引用与 callback trap 回滚规则；
- 取消发生在调度接纳后时当前为静默终止，不伪造异常，也不执行尚未支持的 `finally`。

## 生成式 facade 与样例

Editor binding renderer 生成 `AvidDelayAwaitable`、`AvidObjectAwaitable` 及其
`INotifyCompletion` awaiter。它们只为 Roslyn 提供类型与 await pattern；实际调度由 Semantic/Guest
lowering 直接生成，不会在运行时调用空的 `OnCompleted(Action)` scaffold。

`ActorLifecycle` 与项目工作区模板均已改为真实 `async void BeginPlay`，连续等待 NextTick 与对象加载。
真实样例产物包含两个 compiler callback site、两个 resume function、两个 schedule rejection trap、
对应 debug mapping，以及 `continuation_delay`、`continuation_load_object` 和
`avid_on_continuation_v2`。

## 已知边界与下一步

- C3 当前是零 spill 子集；C3B 将增加 compiler-owned bounded spill frame，支持 scalar、enum 与固定
  struct local 跨 await；
- C3C 将增加显式 single-flight/reentrancy policy、可取消 async scope 与结构化并发；
- 批量资产、进度、优先级、bundle、Cook 依赖与细粒度 lease/release 仍属于资源层后续工作；
- 不支持 CLR `Task`、异常传播、`try/finally`、任意 awaiter 或 async helper 调用链；
- PC Editor/Development 已闭环，Cook、Shipping、Android 与 iOS 尚未正式验收；
- 本阶段没有新增竞品 benchmark。零堆 CPS 是已实现的架构属性，不等于已经证明性能领先；
  `P57-D06-ControlledLeadership` 继续开放。

受保护的阶段外 dirty path 不进入本阶段提交：Phase42 架构文档、
`AvidScriptWasmReloadTypes.h` 与 `Docs/AvidScript_Technical_Status.md`。
