# P57.10 Prepared Reflection Invocation Cell 架构设计

## 1. 背景与目标

P57.4 已使 `scalar_add_int32` 的 Adaptive Semantic 正式结果达到
`64.26 ns/op`，相对同轮 Puerts Reflection 的比例为 `0.60657`，标量门禁已经
通过。但当前 prepared reflection 热路径仍在每次调用时执行 package ordinal
回查、plan identity 比较、policy 重判、完整 native guard 和通用 guest memory
返回值写入。更重要的是，prepared reflection 只覆盖
`int32, int32 -> int32`，`FVector`、`UObject*`、property 等常见 UE 形态仍退回
通用反射分派。

本批次目标是把反射描述在 package load 时编译为不可变 invocation cell，并按
参数布局自动选择 typed shape。实现不得按 UE API 名称生成特例，不改变 C# 公共
调用方式，也不修改正式 Puerts 分母、workload、seed、oracle 或 operation count。

## 2. 方案比较

### 方案 A：只删除 scalar ordinal 回查

改动最小，能降低少量固定开销，但无法改善 vector、object 与 property 覆盖，也
无法形成可持续扩展的调用架构。

### 方案 B：继续优化通用 dynamic dispatcher

所有形态共享一条路径，但每次仍需构造动态参数、遍历 value plan、初始化 frame
和执行多层分派。它适合作为完整语义 fallback，不适合作为高频主路径。

### 方案 C：不可变 invocation cell + shape compiler

在 package load 时根据 UFunction/FProperty 元数据生成结构化 shape plan，Runtime
只负责 UObject capability、guest memory 与 reload 生命周期，Bindings 负责 UE
反射 frame 与 native/ProcessEvent 语义，VM 只负责固定签名 callback。该方案同时
改善性能、模块解耦和后续类型扩展，因此采用方案 C。

## 3. 模块边界

### Bindings

- 根据参数 kind、direction、offset、frame flags 和 UFunction flags 识别 shape；
- 生成不可变 invocation cell，缓存 `UFunction*`、native thunk、frame offset、
  expected class 和形态专用入口；
- 提供 native guard 与 native/ProcessEvent 双路径调用；
- 不持有 VM、guest memory、runtime session 或 UObject handle registry。

### Runtime

- 持有 package 的 `TSharedPtr`，保证 invocation cell 生命周期；
- 解析 self/object handle，维护 callback frame 与 reload/registry proof；
- 第一次 eligible 调用执行 native guard，同 callback、同 expected exact class 的
  后续调用复用 proof；
- 解码/编码 guest memory，并把 shape 专用值交给 Bindings cell；
- guard 失败时执行 strict ProcessEvent fallback，身份不兼容时拒绝调用。

### VM

- 保留当前 guest import 签名，不能要求现有 C# artifact 改 ABI；
- 为既有 `StableObjectRoundtrip`、property guest-address、legacy scalar guest-result
  形态接入 prepared target，并为 semantic vector 的现有 expanded-f32 ABI 增加固定
  typed shape；
- prepared target 完整时直接调用，未准备的旧形态继续走 dispatcher fallback；
- 不包含 UE 反射、UObject 或 binding policy 逻辑。

## 4. Invocation Cell

`FAvidScriptPreparedReflectionBinding` 从“ordinal + opaque identity”升级为真正的调用
单元，包含：

- 不可变 cell context；
- expected receiver class 与 adaptive native eligibility；
- shape 枚举；
- shape 专用函数指针；
- native guard 函数指针；
- typed host import identity。

热路径不再通过 ordinal 回到 `FImpl::Plans`。ordinal 只保留为 provenance、错误
定位和 VM import identity，不参与成功调用分派。package unload/reload 会先销毁 VM
prepared callback，再释放 package，因此 cell pointer 不会越过 owner 生命周期。

## 5. Shape 覆盖

P57.10 分组覆盖以下通用结构，不按函数名或 fixture 名匹配：

| Shape | Guest ABI | Prepared 行为 |
| --- | --- | --- |
| `I32PairToI32` | legacy `(iiiii)i` | native/ProcessEvent + i32 写回 |
| `PropertyI32Get` | legacy `(iii)i` | 直接读取已验证 FProperty + guest 写回 |
| `PropertyI32Set` | `(iii)i` | write policy/effect proof 后直接写入 |
| `VectorValue` | `(iifffi)i` | expanded f32 输入、guest result、UE FVector frame 转换，并支持 by-value 或严格限定的 `const FVector&` 输入 |
| `ObjectRoundtrip` | `(iiiii)i` | stable handle resolve/register + UObject frame |

UE 5.8 会把 `const FVector&` 输入标记为
`CPF_Parm | CPF_OutParm | CPF_ReferenceParm | CPF_ConstParm`。P57.10 仅在结构恰为
trivial `FVector`、方向为 const-ref 输入且完整 frame 布局已验证时，为 native thunk
建立指向冻结输入 frame 的 `FOutParmRec`。其他 `ref/out`、非平凡结构、Blueprint
event、RPC、interface、script UFunction、static、write/reload effect 不可证明的调用
继续使用通用 dispatcher。本批次不扩大支持面来掩盖 fallback，也不手写某个
Actor/FVector API wrapper。

## 6. Native Guard 与安全不变量

native fast path 只允许 native、final、public、非 event/net/interface/script、无
super override，且参数标志、字段链和 frame 可证明为支持布局的 UFunction。每个 callback
第一次调用验证：

- Game Thread；
- receiver exact class；
- 非 GC、PostLoad 与 intra-frame debugging；
- handle slot/generation、registry revision 与 reload epoch；
- invocation cell 仍由当前 package owner 持有。

后续调用只在相同 callback frame、reload epoch、registry revision 和 expected class
下复用 proof。任何条件失效都进入 strict fallback 或拒绝，不允许继续执行缓存的
native thunk。

## 7. 性能与验收

阶段 Gate 仍使用冻结的 Phase56 Micro formal profile。P57.10 额外发布不替代原门禁
的 shape coverage 表，至少报告 scalar、property、vector 和 object 的 AvidScript
Adaptive / Puerts Reflection 同轮比例。

验收要求：

- 原 `semantic_vs_puerts_reflection <= 0.80` 保持通过；
- scalar prepared call 不发生 ordinal/plan array lookup；
- eligible workload 的 native hit 等于 logical operation count；
- fallback、guard reject、host crossing 和 checksum 与 oracle 一致；
- Blueprint/event/RPC/interface/script 与 runtime guard failure 仍走 strict fallback；
- UE 5.8 no-clean 构建、Automation、架构检查和正式 benchmark 在阶段末统一执行；
- P57 纯执行 leadership 债务仍按 P57.9 受控结果独立记录，不用 Semantic 结果冒充。

## 8. 非目标

- 不修改 `.avid` 语法或 C# 用户代码；
- 不切换 Puerts/V8 版本或测试脚本；
- 不修改 controlled-runtime 12 kernel；
- 不为单个 UE API 生成手写 wrapper；
- 不在本批次引入 LLVM AOT；
- 不因为 Semantic 轴领先就提前关闭仍失败的 Phase 57 全部六项 Gate。

generated `VectorValue (iii)i` 与 semantic `VectorValue (iifffi)i` 是两个不同 ABI；
前者使用 packed guest-address，后者展开三个 f32 输入并另带返回地址。P57.10 只为
后者增加通用 typed callback，不改 renderer 或现有 artifact 字节。
