# P57.11D 编译器托管数组访问区与正式性能证据

## 状态

P57.11D 已完成。普通 C# `T[]` 的 `Length`、索引读取和索引写入现在可以由编译器自动
投影为有界数组访问区。脚本不再需要为常规循环手写 `AvidScriptArray.Snapshot/Flush`；
同一 export 内首次访问会 materialize 一次，写操作标记 dirty，函数调用、capability
切换或 return barrier 再按需写回。

## 使用方式

```csharp
[AvidExport("phase57_array_run")]
public static void Run(int[] values, int logicalCalls)
{
    int size = values.Length;
    for (int call = 0; call < logicalCalls; ++call)
    {
        for (int index = 0; index < size; ++index)
        {
            values[index] = Transform(values[index], index);
        }
    }
}
```

`AvidExport` 是 AvidScript facade 提供的普通 C# export 属性。Semantic frontend 将其解析为
稳定 Wasm export；同一方法不能同时使用 `AvidExport` 与 `UnmanagedCallersOnly`。生命周期
入口继续兼容既有写法，项目脚本可用更简洁的属性导出自定义 benchmark、工具或游戏入口。

## 编译与运行模型

### Guest IR 与 lowering

- 新增 `array_region_load`、`array_region_store`，保持基础 array op 的类型和操作数 shape；
- C# 数组索引统一降低为 region op，不按 UFUNCTION 名称、fixture 或 API 写特判；
- 正地址 Guest 本地数组继续直接访问线性内存，负 `i32` capability 才进入托管 region；
- 显式 `Snapshot/Flush` 与旧六项数组 ABI 保持兼容。

### Wasm bounded region

- 每个函数最多一个 active region，上限 `4096` 元素、`1 MiB` payload；
- materialize 复用 `avid_value_array_length/read_range`，dirty flush 复用
  `avid_value_array_write_range`，没有新增 host ABI；
- 长度、stride、alignment、payload、地址和 `memory.grow` 使用有界检查，失败立即 trap；
- 普通 call、不同 capability 和 return 前 flush/invalidate，frame restore 回收 region；
- 同 token alias 复用 active region，WAMR 与 Wasmtime 消费同一 Wasm artifact。

真实 compiler artifact 只导入 `length/read_range/write_range`，包含一对 region load/store，
并导出 `phase57_array_run`。运行时计数器观测到每次 export 固定 `3` 次 host crossing：一次
长度、一次完整读取、一次 dirty 写回。

## 正式性能

正式协议使用 UE5.8 Win64 Development、Wasmtime 45 JIT 与同机 Puerts V8：

- 5 个独立 UE 进程，四条 lane 轮转；
- 每进程每个 size/lane 为 8 次 warmup、21 次 timed sample；
- `N=1/4/16/64/256/1024`，共 `2520` 个 timed sample；
- 所有 lane、size、process 与 sample 的完整 FNV-1a 输出 hash 一致；
- compiler-region lane 来自真实 C# -> Semantic -> Guest IR -> Wasm 流水线，不接受外部
  预制 Wasm 冒充编译器产物。

| N | Puerts Reflection TArray P50 | AvidScript compiler region P50 | 比率 | AvidScript 加速 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | `914.172 ns` | `10.034 ns` | `0.01098x` | `91.11x` |
| 4 | `1119.629 ns` | `20.068 ns` | `0.01792x` | `55.79x` |
| 16 | `1833.887 ns` | `61.864 ns` | `0.03373x` | `29.64x` |
| 64 | `4913.280 ns` | `245.120 ns` | `0.04989x` | `20.04x` |
| 256 | `16532.023 ns` | `946.078 ns` | `0.05723x` | `17.47x` |
| 1024 | `65368.717 ns` | `3718.771 ns` | `0.05689x` | `17.58x` |

`N>=64` 的 compiler-region/element diagnostic gate 要求 `<=0.80x`，正式结果为
`0.01198x / 0.01161x / 0.01138x`，全部通过。

### 解释边界

这组 headline 衡量“脚本已持有 capability 后，在一次 export 内执行多次普通 C# 数组循环”。
AvidScript 将 region 建立和销毁放在 export 内，并把多次逻辑变换聚合为一次 read/write；Puerts
lane 每个逻辑调用都通过 Reflection 传入并返回真实 `TArray<int32>`，计时内包含参数/返回值
分配和 wrapper 访问。它证明编译器托管数据驻留路径的优势，但不能外推为所有 UFUNCTION、
字符串、容器或纯 Wasm kernel 都领先 `17-91x`。普通 UE 调用仍由 Prepared Reflection 与
Phase 56 gameplay benchmark 的独立数据负责。

## 当前边界与下一步

- region 当前只覆盖一维固定宽度数组，并且每个 Wasm 函数最多一个 active capability；
- string element、nested array、`TSet`、`TMap` 尚未接入；
- delegate、latent、RPC、interface dispatch 与 `FText` 仍是后续 UE 语义重点；
- Cook、Shipping、Android 和 iOS 尚未完成正式验收；
- Wasmtime/V8 纯执行 P95 债务 `P57-D06` 仍为 `Fixing`。

下一批应转回功能成熟度：实现 delegate/event subscription、latent continuation 与 RPC/
Blueprint/interface 语义的自动投影，并让真实小型游戏 Demo 只写 C# gameplay 代码即可闭环。
