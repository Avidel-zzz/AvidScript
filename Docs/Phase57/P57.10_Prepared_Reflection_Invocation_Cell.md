# P57.10 Prepared Reflection Invocation Cell 阶段报告

## 阶段结论

P57.10 已完成。Adaptive Semantic 反射调用不再把高频请求送回 ordinal/plan 数组做
二次查找，而是在 binding package 加载时把 UE 元数据编译为不可变 invocation cell。
Runtime 只处理 capability、guest memory、reload epoch 和 callback proof，Bindings
拥有 UE frame/native thunk，VM 只执行固定签名 prepared callback。

这不是按函数名为 benchmark 手写 API。shape compiler 只读取 `UFunction/FProperty`
的类型、方向、标志、offset、owner class 和 frame 布局；不支持的签名仍保留严格的
ProcessEvent/dispatcher 语义。

## 已实现能力

- `I32PairToI32`：两个 `int32` 输入和一个 `int32` 返回值。
- `PropertyI32Get/Set`：验证过 owner、offset、policy 和 effect proof 后直接读写属性。
- `VectorValue`：支持按值输入以及 UE 5.8 真实生成的 `const FVector&` 输入，并返回
  `FVector`；native const-ref 调用会构造正确的 `FOutParmRec`。
- `ObjectRoundtrip`：解析 stable object capability，验证 expected class，并返回稳定句柄。
- VM prepared target：scalar、property、expanded-f32 vector 和 stable-object 都有固定
  Wasmtime C bridge；旧 dispatcher 只作为兼容 fallback。
- 生命周期：VM callback 先撤销，随后释放 package owner，旧 invocation cell 不会越过
  reload/unload 边界。

对象往返热路径还增加了通用 capability alias 优化：输入句柄与 self 相同时复用已经
验证的 receiver；返回对象与输入或 receiver 同一对象时复用现有稳定句柄。只有出现新
对象时才进入 registry/ownership borrow。该规则按对象身份和类型证明工作，不依赖
UFunction 名称。

## 正式性能

协议固定为 `phase56.micro-formal-v1`：1 个校准进程、5 个独立计时进程、每进程 5 次
warmup、每个 cell 30 个 timed sample。统计量为“每进程 nearest-rank P50，再对 5 个
进程取 nearest-rank P50”。同轮比较结果如下：

| 工作负载 | AvidScript Adaptive | Puerts Reflection | 比例 | AvidScript 领先 |
|---|---:|---:|---:|---:|
| `scalar_add_int32` | 55.1211 ns | 107.0734 ns | 0.51480 | 48.52% |
| `property_get_set` | 71.5586 ns | 103.1297 ns | 0.69387 | 30.61% |
| `vector_value` | 66.7570 ns | 1222.5875 ns | 0.05460 | 94.54% |
| `object_roundtrip` | 68.7133 ns | 131.4828 ns | 0.52260 | 47.74% |

四个 P57.10 语义 shape 均在同轮正式结果中领先 Puerts Reflection。对象优化前的候选
结果为 `129.7500 ns` 对 `127.9938 ns`，比例 `1.01372`；capability alias 复用后降至
`68.7133 ns`，完成了本批次最后一项红门禁。

该结论只适用于这里冻结的 UE 反射边界 shape，不等同于“AvidScript 所有工作负载都
领先 Puerts”。`P57-D06-ControlledLeadership` 的纯 Wasm 12-kernel P95 债务仍保持
`Fixing`，不能用本批次的 Semantic 成绩替代。

## 剩余边界

- 当前 prepared coverage 仍是结构化 shape 集合，不是任意 `UFunction` 参数图的全覆盖。
- `bool/enum/int64/float/double/FName/FString`、更多 UStruct、容器、delegate 与复杂
  ref/out 尚未进入通用 cell compiler。
- Blueprint event、RPC、interface、script/static 和无法证明 frame/effect 的调用继续
  fallback，这是安全边界，不应为追求 benchmark 数字而放宽。
- 纯 Wasm 执行层 P95 leadership 仍需 LLVM AOT 或等价 codegen 方案单独处理。
