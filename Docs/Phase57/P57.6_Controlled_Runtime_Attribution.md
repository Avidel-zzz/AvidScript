# P57.6 Controlled Runtime 正式归因

## 结论

Phase 57 已在冻结的 12-kernel、同轮 Puerts V8 denominator、5 个独立进程和 CPU0
亲和环境中完成正式测量。候选 `d144d6e/e5e6f0c` 的 p50 几何均值为
`0.982169`，p95 几何均值为 `1.043073`，p50/p95 kernel 胜率分别为
`66.67%/58.33%`。正确性失败为 `0`，没有 fallback，但领导性门禁仍为红色。

因此 Phase 57 不能发布“Controlled Runtime 全面领先 V8”的结论，
`P57-D06-ControlledLeadership` 保持 `Fixing`。

机器可读证据位于
`Docs/Phase57/P57.6_Controlled_Runtime_Formal_Evidence.json`，原始 suite aggregate
SHA-256 为
`2fdebb2a51399f41ea3813182ba6a96ab439e9e1572c93af376b164149cbf31f`。

尾部调度噪声和约 `2.4%` 的真实执行缺口，不能只靠提高 benchmark 优先级宣称通过。

## 已保留改进

- Wasm32 线性内存预留固定为完整 4 GiB，`memory_may_move=false`，消除内存基址迁移。
- Cranelift 使用 `speed_and_size`；当前机器上它的正式综合表现优于此前基线，继续保留。
- 正式 benchmark 进程固定 `ProcessorAffinityMask=1`，attempt 元数据记录并验证该值。
- Wasmtime build identity 同时绑定版本、优化级别、稳定内存策略和 DLL SHA-256。

## 被拒绝的实验

### 统一循环旋转

将所有循环从 top-test 攨写为 bottom-test 后，正式结果为 p50 `0.982928`、p95
`1.006172`，没有通过。`serial_integer` 可改善到约 `0.93/0.94`，但
`mixed_gameplay` 回退到约 `1.02/1.07`，说明该变换必须由编译器按 CFG 和依赖特征
选择，不能无条件应用。

这次实验还修改了冻结 kernel 字节，违反 Phase 57 正式合同。相关两个提交已经完整
revert，结果只能作为未来前端/编译器 pass 的研究证据，不能计入正式 Gate。

### SSE-only 与函数对齐

关闭 AVX/AVX2/FMA 对串行和浮点有小幅收益，但 predictable branch 明显回退；
32-byte function alignment 也没有形成稳定综合收益。两项均已 revert。

### Binaryen `-O4`

Binaryen version 131 对真实 C# guest 将 `normal.wasm` 从 `9221` 字节缩小到 `6998`
字节，适合作为后续构建体积优化候选；但 12-kernel 离线 ABBA 探针的近似执行几何
均值为 `1.012x`，总体约慢 `1.2%`，不能作为本 Gate 的默认执行优化。

### Cranelift single-pass regalloc

single-pass 只让 hashing、small_struct 局部获益，mixed、float、SIMD 等负载回退
`2-3x`，近似综合几何均值为 `1.318x`。继续使用默认 backtracking regalloc。

### Wasmtime inlining

Wasmtime v45 的 compiler inlining 默认关闭，CLI 探针确认 internal-call 类负载存在收益；
但官方 C API 没有暴露该开关，且冻结 suite 只有一个直接 call kernel。它是实际游戏脚本
值得实现的优化轴，但单独不足以把 12-kernel 综合值压到 `0.95`。

## 架构决策

继续在官方 C API 的少量 flag 上试探，已经不能提供目标所需的 3-5% 全面提升。
下一实现轴改为分层优化编译：

1. `WasmBytecode + JIT` 保留为快速迭代和调试路径。
2. PC 构建新增 `WasmtimeSerialized` 预编译制品，来源同时绑定 canonical WASM、
   Wasmtime/Cranelift identity、target triple 和优化策略。
3. 预编译器允许启用 compiler inlining，并为后续选择性 loop rotation/IR pass 提供
   统一入口；运行时只接受可信、同版本、同 target 的序列化制品。
4. Release 性能领导性继续评估 LLVM AOT lane；移动端必须使用无运行时 JIT 的 AOT
   方案，不能把 Windows JIT 假设扩散到移动平台。
5. 正式 Gate 保持冻结，任何内部优化都必须继续执行同一 canonical kernel、seed、
   oracle 和 observation 合同，并发布实际 execution artifact identity。

## 下一步
