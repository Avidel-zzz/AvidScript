# P57.12D3 入站 RPC 与 RepNotify C# Handler 计划

## 目标

让 Binding Profile 显式授权的 native Actor/ActorComponent RPC 与 RepNotify UFunction 在对应 UObject
收到 UE 调用时进入当前 Runtime Session 的生成式 C# handler。NetDriver、RPC callspace、属性复制条件与
RepNotify 触发时机继续由 UE 管理；AvidScript 只接管被明确选择的 UFunction 本地实现入口。

## D3A：生成式 callback 合同

- C# profile schema 9 增加 class-level `include_handlers`，不自动 hook 整个类。
- binding descriptor schema 17 复用通用 callback 参数模型，并以 `delegate_kind` 区分
  `multicast`、`network_rpc` 与 `rep_notify`。
- RPC handler 固化 network mode/reliability；RepNotify handler 固化关联 property；两者均进入
  canonical identity、selection hash 与 package hash。
- 生成的 `AvidEvents.<Name>` 常量继续使用 `[AvidEvent(...)]` 语义前端和既有 callback ABI，避免新增
  Host import、Runtime AST 或按 API 名称分支。
- `AvidSubscriptions` 只为真实 multicast delegate 生成订阅函数，function handler 不暴露伪订阅 API。

## D3B：Session 所有的 UFunction hook

1. Runtime 私有全局 hook registry 对每个 UFunction 只保存一次原 native thunk，并安装同一个静态入口。
2. 路由键为 `(UFunction, UObject)`；多个 Session 可共享同一 UFunction，但不能争用同一对象。
3. candidate 只准备 descriptor、codec 与 VM export，不安装 route；commit 在游戏线程切换 active route。
4. C# export 缺失时不安装 route，原 native/Blueprint 实现保持原样。
5. active route 成功命中时使用 `FFrame::Locals` 和加载期不可变 codec 调用 prepared VM export；脚本
   trap 会 fault 当前 Runtime，但不会在部分副作用后再执行原实现。
6. EndPlay、reload、Session teardown 会先移除对象 route；最后一个 route 消失且 thunk 身份仍属于
   AvidScript 时恢复原 native pointer，绝不覆盖其他插件后装的 hook。

## 首批替换语义

- 显式 handler 采用 `replace`：C# export 存在并激活后不再调用原 UFunction 实现。
- 未激活、缺少 export、对象不匹配或 route 已移除时调用保存的原实现。
- 运行中的同 Session 重入首批失败关闭且不回退原实现，避免双重业务副作用；有所有权的参数深拷贝
  deferred queue 留给 D4。
- 只接受 native、非 static、无 return/ref/out/latent 的 Actor/ActorComponent UFunction；参数沿用现有
  delegate callback 的 value/const-ref 固定宽度、UObject capability 与固定 USTRUCT codec。

## RepNotify 约束

- handler UFunction 必须被同 owner 的一个 `CPF_RepNotify` property 引用；零参数与 UE 支持的单个 old-value
  参数均按活动 Reflection 验证。
- D3 不轮询 replicated property，也不在 authority 本地 setter 中伪造 OnRep。
- hook 只在 UE 真正调用 RepNotify UFunction 时进入 C#，因此触发顺序与连接语义仍由 UE 决定。

## 验收

- schema 17 确定性生成/解析，handler kind、network contract 或 RepNotify property 篡改失败关闭。
- profile 生成 C# callback constant，示例源码可编译为对应 WASM export。
- 同一 UFunction 的两个 UObject 可路由到不同 sink；未注册对象执行原 thunk。
- commit/reload/unload 恢复 route 与原 thunk，不留下全局悬挂指针。
- RPC 与 RepNotify 参数从真实 `ProcessEvent` frame 编码；脚本 handler 替换原 fixture 实现。
- 阶段末统一执行固定 .NET、PowerShell、UE5.8 no-clean build、完整 Automation 与 clean architecture。

## 后续边界

- D4：有所有权的重入 deferred queue、Blueprint bytecode handler、可配置 before/after/replace 链式策略。
- D5：dedicated/listen server 与多客户端独立进程真实复制验收、动态 subobject 与 Iris 扩展。
- FastArray/custom delta、网络预测与回滚不在 D3 范围内。
