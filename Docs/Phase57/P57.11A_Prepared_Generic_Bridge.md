# P57.11A Prepared Generic Bridge 阶段报告

## 阶段结论

P57.11A 已完成。本批次把 generic reflected function/property 的成功路径从
`ordinal -> package plan lookup -> dispatcher` 改为加载期编译和绑定的 prepared
dynamic target。VM 只认识 opaque callback，Runtime 负责精确身份关联和生命周期，
Bindings 负责不可变 codec program、UE frame 与属性访问。

该实现按 descriptor、反射元数据、ABI shape 和 owner capability 工作，不按 API 名称、
fixture 名称或 ordinal 值选择行为，也没有新增逐 API wrapper。窄 shape 已存在的 typed
host import 仍保持更高优先级；prepared dynamic bridge 服务于无法由窄 typed import
覆盖的通用反射调用。

## 架构落地

- **VM**：公开 `FAvidScriptVmPreparedDynamicHostTarget`，只保存 opaque context 与
  VM public type callback；Wasmtime 完成 ABI 解码和 active caller 建立后调用 target。
- **Bindings**：把 descriptor 验证后的参数计划编译为不可变 codec program，并由 binding
  package 独占 prepared cell；通用 executor 不再按 ordinal 回查 package plan。
- **Runtime**：复制 canonical VM binding package，按 stable id、module、import、signature
  和 ordinal 的完整身份一次性关联 prepared cell；任一字段不匹配即 fail closed。
- **生命周期**：load/reload/unload 先撤销 VM package 与 stable context，再释放 Bindings
  package owner，避免 callback 穿越 package 生命周期。
- **兼容边界**：旧 artifact、未绑定 target、专用 lifecycle/factory invocation 和 WAMR
  继续使用原 dispatcher；prepared target 一旦接管后若拒绝调用，不会 fallback 重放副作用。

## 已实现能力

- 通用 reflected `UFunction` 的参数 frame 初始化、`ProcessEvent`、返回值和 ref/out 回写。
- reflected property 的直接 get/set，并保留 owner、policy、effect proof 和 capability 检查。
- guest memory 地址解析、对象 registry/ownership、host effect journal 与调用 scratch 复用。
- package 加载期预计算 argument count、scratch requirement、expected receiver class 和
  immutable invocation cell，热路径不再分配 plan 或执行 package lookup。
- `PreparedDynamicHitCount`、`PreparedDynamicFallbackCount`、
  `PreparedDynamicRejectCount` 三个互斥路由计数。
- Runtime 真 target fixture 会实际进入 Bindings prepared executor，而不是只验证函数指针
  非空或静态 token。

## 路由语义

Wasmtime 的链接规则会优先给更窄的 typed host import 精确身份，同一身份的 dynamic import
不会再重复绑定。因此 `ScalarAddInt32`、property、vector value、object、batch 和 gameplay
typed shape 的 prepared-dynamic hit 预期为 `0`，它们继续走 P57.10 的 typed prepared path。

当前 generic benchmark workload 中，`scalar_noop` 和 `vector_ref_out` 会命中 prepared
dynamic target，hit 数必须精确等于 workload iteration 数。correctness oracle 已按 ABI
shape 推导预期，不再把所有 Semantic 调用错误地等同为 prepared-dynamic 调用。

Runtime 集成 fixture 的成功调用证据为：hit `1`、fallback `0`、reject `0`；随后使用非法
argument frame 调用，reject 精确增加到 `1`，fallback 仍为 `0`，证明拒绝后不会重放旧
dispatcher。

## 剩余边界

- 当前 codec program 仍以已经物化的 scalar、object、vector 和 property 计划为基础；嵌套
  `UStruct`、容器、delegate、更多 primitive/name/string 和复杂参数拓扑尚未完整编译。
- 专用 lifecycle/factory/scene attachment invocation 仍由 facade dispatcher 管理，不应
  为了表面覆盖率伪装为通用 `UFunction` codec。
- 不直接调用 unload 后的裸 context 指针做测试，因为该行为本身是无效内存访问；当前由
  VM-first 撤销顺序、stable context reset 和 package ownership 合同保证生命周期边界。
- `P57-D06-ControlledLeadership` 仍为 `Fixing`：冻结的 Wasmtime/V8 12-kernel P95 纯执行
  门禁没有被本批次改变，也不能用反射桥接结果替代。
