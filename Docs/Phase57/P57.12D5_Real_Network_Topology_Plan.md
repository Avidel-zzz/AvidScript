# P57.12D5 Dedicated、Listen 与多客户端真实网络拓扑计划

## 目标

用 UE5.8 源码版的独立进程证明一条完整 C# + WASM 网络链路，而不是继续增加单进程 hook 模拟：

```text
client C# BeginPlay
  -> generated Server RPC
  -> UE NetDriver
  -> server C# before handler
  -> authority replicated property setter + Push Model dirty
  -> original server RPC implementation
  -> UE property replication
  -> client native/Blueprint RepNotify original
  -> client C# after handler
  -> generated confirmation Server RPC
```

同一协议分别在 dedicated server + 2 clients、listen server + 1 remote client 上执行。每个 client、
server/listen host 都是独立 `UnrealEditor-Cmd` 进程，拥有独立 World、NetDriver、Runtime Session 与 WASM
instance。

## D5A：插件内网络 Fixture

- Runtime 测试 Actor 是 owner-only replicated Actor，服务器在 `GameModePostLogin` 为每个 PlayerController
  生成一份并设置 owner，从而满足 client -> server RPC 的 UE ownership contract。
- Actor 的 default `UAvidScriptComponent` 加载 D5 production-built C# manifest；server/client 都运行同一
  WASM 产物，但按 `HasAuthority()` 选择逻辑。
- `ServerSubmitValue` 同时存在于 generated outbound facade 与 `before_handlers`。客户端 Remote-only
  ProcessEvent 必须由 UE callspace 在 native thunk 前转发，不能被本地 hook 误截获；服务器 Local 入站
  才进入 C# handler。
- `ReplicatedScore` 通过 D2 authority setter 写入并标记 Push Model dirty；客户端 `OnRep_ReplicatedScore`
  先执行原实现，再进入 D4 `after` C# handler。
- C++ fixture 只记录通用网络链路计数和值，不实现或替代 C# 游戏逻辑。

## D5B：命令行 Harness

- Harness 仅在 `WITH_DEV_AUTOMATION_TESTS` 且存在 `-AvidScriptNetworkTopologyRole=` 时注册，不改变普通
  Editor、PIE、Game、Cook 或 Shipping 行为。
- server/listen 监听 `FGameModeEvents::OnGameModePostLoginEvent()` 生成 fixture；CoreTicker 按当前 World
  检查链路完成条件。
- server 结果要求每个远端连接的 script/native Server RPC、replicated value、client confirmation 都精确
  到达；client 结果要求 native RepNotify、C# RepNotify、value 与 AvidScriptComponent Runtime 生命周期
  全部通过。
- 每个进程只原子写入自己的 JSON result，不自行杀死其他进程。编排器持有精确 Process handle，在所有
  结果通过或 timeout 后统一回收。

## D5C：PowerShell 编排与证据

1. 运行 Editor Automation 构建 D5 C# Profile，确保 descriptor、generated facade、WASM、manifest 与
   binding package 来自 production pipeline。
2. 为每种 topology 分配独立端口和证据目录，隐藏启动 server/listen 与 clients；先等待 NetDriver listen
   信号，再启动 clients。
3. 等待所有预期 JSON result；同时监控精确进程句柄，进程提前退出、timeout、缺失结果或任一
   `succeeded=false` 都失败关闭。
4. 汇总进程命令、PID、role、计数、值、日志 SHA-256 与 result SHA-256，生成一个 aggregate JSON。
5. finally 只停止本次编排器启动且仍存活的 PID，不按进程名清理用户 Editor。

## 验收

- dedicated server + 2 clients：两个独立 owner actor 均完成 RPC -> property -> RepNotify -> ack。
- listen server + 1 remote client：listen host 的本地 PlayerController 不冒充远端成功，远端链路完整。
- server 每个 actor：script/native Server RPC 各 1、ack 1、value 41；client：native/script RepNotify 各
  1、value 41，Runtime loaded、BeginPlay called。
- outbound Remote-only RPC 不触发客户端本地 inbound handler；server original `before` 精确一次；client
  original `after` 精确一次。
- timeout、端口未监听、进程提前退出、manifest/Runtime 失败、结果 schema/身份不一致全部有稳定错误。
- 阶段末集中运行 UE5.8 no-clean build、D5 real topology、完整 AvidScript Automation、固定 .NET、
  PowerShell 与 clean architecture。

## 边界

- D5 不把 Internet、packet loss/lag 仿真、跨机器、Iris replication graph、FastArray/custom delta、动态
  replicated subobject、网络预测或回滚标记为完成。
- D5 使用 Development Editor 独立进程；Cook/Shipping 与移动端网络属于 P62/P63。
- 性能债务 `P57-D06-ControlledLeadership` 继续保持 `Fixing`，网络功能闭环不改变其判定。
