# P57.12C11 结构化 Async Guard 闭环

## 目标

P57.12C11 让受控 C# async 游戏脚本可以根据异步结果安全早退。P57.12C10 已经让
`AvidOutcome<T>` 暴露成功、失败和取消三种终态，但此前 async segment 只接受表达式语句和局部变量声明，
无法直接编译最常见的结果保护逻辑。本阶段补齐以下可用写法：

```csharp
AvidOutcome<int> outcome = await UKismetSystemLibrary.WaitForScoreAsync(42);
if (outcome.Cancelled)
{
    return;
}
if (outcome.Failed)
{
    return;
}

UE.Self.SetActorTickEnabled(true);
await AvidContinuations.NextTickAsync();
```

对象加载结果同样可以作为 guard。项目自带的 ActorLifecycle 与工作区模板现在会在异步对象恢复后先检查
`if (!loadedObject.IsValid) return;`，只有有效结果才继续执行 UE API。

## Semantic 14 合同

Semantic 合同升级为 schema `14` / semantic `1.14`。顶层无 `else` 的 `if (condition) return;`
被投影为 `async_early_return_guard` operation，唯一 child 是受支持的 `bool` condition。operation 明确要求：

- `type_id` 为 `type:void`，不能携带 symbol、constant、conversion、capture 或 type argument；
- condition 必须是 canonical `type:bool`，源码 span 必须包含 condition span；
- guard 不能包含 await、分支副作用、返回值或 `else`；
- schema 13 / semantic 1.13 继续可读，但携带 guard operation 会 fail closed。

普通 if/else、分支内调用、循环、try/finally、lambda、Task 与任意 awaiter 仍不属于当前受控 async 子集。

## Guest 分支图

Guest lowerer 按源码顺序把 guard 切成确定性的 `branch_if` 基本块：true 分支进入 segment 共享的
`guard_return`，false 分支继续执行普通语句并可调度当前 segment 的下一次 await。这个过程不生成 CLR
状态机、不分配 Guest heap，也没有新增 host import、VM binding ID、WAMR wrapper 或 Wasmtime adapter。

本阶段同时修正 provider result 的接纳顺序。`continuation_result_read` 现在先进入独立
`result_accepted/result_rejected` 门禁：读取失败立即 trap，只有 capability、generation、binding ordinal
与 payload shape 全部验证成功后，Guest 才能执行 guard 或任何业务副作用。调度 token 与取消绑定仍在
segment 尾部独立验收，两个事务边界不再混在一个延迟检查中。

## 真实游戏脚本

`Samples/CSharp/ActorLifecycle/ActorLifecycleScript.cs` 与新建项目模板已使用真实 guard：

```csharp
AvidLoadedObject loadedObject = await AvidAssets.LoadObjectAsync(
    "/Engine/EngineMeshes/Cube.Cube");
if (!loadedObject.IsValid)
{
    return;
}

HasAwaitedDefaultMesh = loadedObject.IsValid;
UE.Self.AddActorWorldOffset(new FVector(0.0f, 0.0f, 10.0f));
```

这条链路经过 Roslyn Semantic、Guest IR、WASM backend 与构建发布清单，不是仅供测试调用的手写 API。

## 后续边界

C11 解决了异步终态后的结构化早退，但普通 local 仍不能跨 await。下一批应实现 Session-owned bounded
async state frame，优先覆盖 scalar、enum、固定 struct 和受控对象 capability，并保证并发重入、取消、
reload 与 teardown 下的确定性回收。timeout/race 等组合器应建立在该 frame 上，不应先堆叠一个无法保存
调用状态的表面 Task API。

本阶段没有新增 host crossing，也没有重跑冻结 Wasmtime/V8 纯执行 benchmark；
`P57-D06-ControlledLeadership` 继续保持 `Fixing`。
