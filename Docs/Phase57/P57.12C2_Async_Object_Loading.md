# P57.12C2 异步对象加载闭环

状态：完成

## 本阶段完成的能力

P57.12C2 在 Session-owned Continuation 核心上接入了第一个带 UObject 结果的真实 UE 异步生产者：

```text
C# AvidAssets.LoadObjectAsync
  -> env.continuation_load_object
  -> Runtime UTF-8 与 FSoftObjectPath 校验
  -> Session active/prepared continuation owner
  -> FStreamableManager::RequestAsyncLoad
  -> Session ready queue
  -> 对象 registry slot/generation capability
  -> avid_on_continuation_v2
  -> 编译器生成 callback-id dispatcher
  -> C# public static handler
```

脚本现在可以在 `BeginPlay` 等 UE 生命周期入口发起 soft object path 加载，并在后续 Session 安全
Tick 中获得完成状态与通用对象句柄。它不是为某个资产类型添加的手写 VM API：具体 UObject 类型仍由
Reflection profile 生成代理，并复用已有的 `IsA` / checked cast 能力。

## C# 使用方式

```csharp
private const int DefaultMeshLoaded = 2;

[AvidTransient]
private static AvidContinuation PendingMesh;

public static void BeginPlay()
{
    PendingMesh = AvidAssets.LoadObjectAsync(
        "/Engine/EngineMeshes/Cube.Cube",
        DefaultMeshLoaded);
}

[AvidContinuation(DefaultMeshLoaded)]
public static void OnDefaultMeshLoaded(
    AvidContinuationStatus status,
    AvidLoadedObject loadedObject)
{
    if (status == AvidContinuationStatus.Completed && loadedObject.IsValid)
    {
        UObject loaded = UObject.TryCast(loadedObject);
    }
}
```

`AvidContinuation` 继续是绑定当前 Session activation 的不透明 token。脚本可调用 `Cancel()`；保存
token 的静态字段必须使用 `[AvidTransient]`，不能跨热重载迁移。

加载 callback 必须满足以下约束：

- `public static void`，参数严格为 `(AvidContinuationStatus, AvidLoadedObject)`；
- callback id 是正整数编译期常量，在脚本内唯一，并有对应 `[AvidContinuation]` handler；
- asset path 是非空、无 NUL、UTF-8 不超过 1024 字节的编译期常量；
- Runtime 继续用 `FSoftObjectPath` 与长包名规则验证路径，非法输入 fail-closed；
- `Completed = 1`，`Failed = 2`；显式取消与 teardown 抑制 callback，不伪造取消完成事件；
- `Delay` / `NextTick` handler 仍是零参数，Semantic 会拒绝 producer 与 handler shape 不匹配。

## ABI 与兼容性

新增 Host import：

```text
env.continuation_load_object(i32 utf8_value_ref, i32 callback_id) -> i64 token
WAMR signature: (ii)I
```

Semantic contract 升级为 `11 / 1.11`。带结果的 Guest 使用版本化 export：

```text
avid_on_continuation_v2(
    i32 callback_id,
    i64 token,
    i32 status,
    i32 object_slot,
    i32 object_generation) -> void
```

旧 schema `10 / 1.10` 的 `avid_on_continuation(i32, i64, i32)` 仍可加载和执行。C2 没有原地修改
旧 export 签名，Wasmtime 与 WAMR 继续共享同一个静态 Host dispatcher 语义。

## 架构边界

异步加载实现位于独立 `Continuation/AvidScriptAsyncObjectLoader` adapter。它封装
`FStreamableManager`，让 continuation owner 不依赖全局 AssetManager 细节，也允许自动化使用同一
接口的可控 producer。

- VM 层只登记 import id、签名和 WAMR thunk，不保存资产业务状态；
- Runtime 层负责 UTF-8 capability、路径验证和 Host import 分派；
- Session continuation owner 统一管理 producer、ready queue、token、active/prepared lane 与分发顺序；
- Semantic 层拥有路径常量、callback id、handler shape 与 schema 合同；
- Guest lowerer 只消费已验证 payload，并生成 `avid_on_continuation_v2` dispatcher；
- Editor renderer 生成 `AvidAssets`、`AvidLoadedObject` 与每个对象代理的 `TryCast`，不新增项目专用 wrapper。

## 所有权与生命周期

`FStreamableManager` completion 不直接重入 Guest，只保存结果并排入 ready queue。Session 正常 Tick
结束后仍按 registration serial 每 Tick 最多恢复一个 continuation。

- active completion 在即将分发时才借用 slot/generation 对象 capability；prepared lane 不提前发布；
- handler 返回成功后，结果 UObject 由 Session 强持有到 teardown，避免句柄在后续脚本逻辑中失效；
- 相同 UObject 去重，单 Session 最多保留 1024 个异步结果对象；
- handler trap 会回滚本次新借出的 handle，不保留对应强引用，并进入既有 fault/teardown 路径；
- callback 开始前 token 已 finalise，handler 内取消自身返回 `false`；
- cancel、prepared discard、HostContext 改变、`EndPlay`、Unload 与析构会取消未完成 handle、清空 ready 项与强引用；
- 成功热重载保留当前 Session 已交付的资产，候选失败不会泄漏 registry capability。

## 已知边界

- 当前是单对象加载；批量、进度、优先级、asset bundle 与细粒度 lease/release 尚未实现；
- soft object path 不会自动加入 Cook 依赖，packaged build 必须由项目显式纳入资产；
- C2 不实现 C# `async/await` 状态机、局部变量 spill、异常传播或泛型 `AvidTask<T>`；
- UE latent UFunction、RPC、interface dispatch 与 `FText` 仍在后续路线图；
- PC Editor/Development 已闭环，Cook、Shipping、Android 与 iOS 仍未正式验收；
- 本阶段没有改变反射调用性能热路径，也没有新增竞品 benchmark；
  `P57-D06-ControlledLeadership` 继续开放，不能把功能闭环表述成性能领先已完成。

受保护的阶段外 dirty path 不进入本阶段提交：Phase42 架构文档、
