# P57.12C13 结构化 async 控制流完成报告

## 结论

P57.12C13 已完成。受控 C# `async void` 导出现在可以在 await 之间使用局部变量声明与重赋值、
`if/else`、`while`、`do/while`、`for`、`break`、`continue` 和 `return`。这些控制流在编译期
lowering 为 WASM 基本块，不由 Runtime 解释 C# AST，也没有新增 Host import 或按 UE API 名称分支。

本阶段实现候选为 `dad046f771877356a97c6c2549c372eb2d502bd1`，源码树为
`8e0936fc1cce50cd385152084efb3df776861105`。UE5.8 no-clean Editor 构建、完整 Automation、
固定 .NET/PowerShell 合同与 clean architecture gate 均已通过。

`P57-D06-ControlledLeadership` 仍保持 `Fixing`。C13 没有运行新的性能矩阵，也不把功能完成
表述为性能门禁已经关闭。

## 已实现能力

### Semantic 投影

- Semantic schema 保持 `15`，semantic version 升级到 `1.16`，并继续接受旧的 `15 / 1.15` 产物。
- 在既有 `SemanticOperation` 树中加入 `async_block`、`async_local_declaration`、`async_if`、
  `async_while`、`async_do_while`、`async_for`、`async_break`、`async_continue` 与 `async_return`。
- 每个 async 方法最多允许 256 个结构化节点，最大嵌套深度为 8；Semantic 与 validator 使用
  相同限制，超限输入 fail closed。

### 精确活跃性

- 新的逆向数据流分析按 segment 入口计算真正需要跨 await 保存的 local。
- 简单赋值会 kill 旧值；复合赋值与自增、自减同时读取并写入旧值。
- `if/else` 合流取可达分支并集，循环在有界 local 集合上求确定性不动点。
- `break`、`continue`、`return` 分别连接循环出口、继续点和方法出口，不把不可达尾语句
  错误计入状态帧。
- await 的结果在恢复点定义，不从前一个状态帧重复读取。
- 状态帧继续复用 C12 的整帧 store/read ABI、64 槽与 4096 字节上限，以及 continuation token
  的 Session 隔离和回收语义。

### Guest / WASM lowering

- 结构化语句被一次性 lowering 为确定性 Guest 基本块和 `branch` / `branch_if` terminator。
- 分支合流和循环回边完全位于 WASM 内，不增加 Host 往返、Guest 堆状态机或逐 local import。
- `return` 路径不会继续调度后续 producer；`break` 与 `continue` 只接受有效循环上下文。
- block ID 由 method、segment 与单调 flow ordinal 构成，相同输入生成相同 Guest IR/WASM。

## 可编写的脚本

```csharp
[UnmanagedCallersOnly(EntryPoint = "avid_on_begin_play")]
public static async void BeginPlay()
{
    int movementCount;
    if (UE.Self.IsActorTickEnabled())
    {
        movementCount = 2;
    }
    else
    {
        movementCount = 1;
    }

    await AvidContinuations.NextTickAsync();

    FVector step = new FVector(10.0f, 0.0f, 0.0f);
    for (int index = 0; index < movementCount; ++index)
    {
        UE.Self.AddActorWorldOffset(step);
    }
}
```

其中 `movementCount` 跨越 await，因此进入状态帧；`step` 与 `index` 只在恢复后的 segment 内使用，
不会占用跨暂停状态。`for` 的回边在 WASM 内执行。

语句重置而不是按方法累计；architecture checker 仍只识别 C12 的旧 liveness token。修正后重新运行
受影响合同，并在最终候选上完成全量验证。

## 明确边界

- await 仍只能位于方法体顶层表达式语句或顶层 local 初始化器。
- 分支或循环内部 await、`switch`、`foreach`、动态布局 local、异常传播、`try/finally`、
  任意 awaiter 和 async helper 调用链尚未支持。
- C14 将优先设计和实现分支/循环内部 await 的 CFG 分裂与恢复控制状态；异常与资源释放必须先冻结
  跨暂停展开、取消和 teardown 语义。
