# P57.12C16 数组 Foreach Await 方案

## 状态

- 阶段组：`P57.12C16`
- 状态：已完成并通过集中验收
- 目标：让一维 C# 数组可以在受控 `foreach` 循环体中直接 await
- 性能债：`P57-D06-ControlledLeadership` 继续保持 `Fixing`

## 冻结语义

1. Semantic 升级为 schema `16` / version `1.18`，`SemanticAsyncMethod.CompilerLocals` 显式发布
   编译器生成的数组引用与索引，禁止借用不可见 Host enumerator 状态。
2. 首批只接受同步求值的一维数组、普通值迭代和精确元素类型；集合表达式只求值一次。
3. foreach 展开为 `array = expression`、`index = 0`、`index < array.Length`、
   `item = array[index]`、body、`++index` 六段普通 continuation CFG。
4. `continue` 指向 increment，`break` 指向循环后继；循环体内直接 await 沿用 C14 的 resume target。
5. 编译器局部 ID 绑定 method 与 foreach 源码位置，按 ID 排序并接受数量、类型、span 和冲突校验。
6. 非数组 enumerator、元素转换、解构、ref foreach、await foreach 和集合表达式内 await 使用
   `ASCS5419` 失败关闭。

## 状态与所有权

- Guest 数组类型固定为 `i32 / 4 bytes / align 4`，状态帧只复制引用值，不复制 referent。
- 正数引用属于当前 WASM activation 的线性内存数组区域；continuation activation 栅栏保证恢复不跨
  已替换模块。
- 负数引用属于当前 Session 的 UE 数组 capability；reload、prepared rollback、teardown 和显式
  Release 继续使用既有 generational ownership。
- 只允许顶层数组引用进入状态帧；含动态数组字段的 USTRUCT 仍不因 C16 被顺带放开。

## 性能边界

- foreach body 在 Guest 内使用既有 `array_length`、`array_region_load` 和普通 branch，不新增 Host import。
- 编译器托管数组继续使用 region 和 call/return barrier；UE capability 数组继续使用现有批量通道。
- 每次 await 只 bulk store/read 一份精确活跃状态，不按元素生成 wrapper，也不使用 CLR enumerator。
- C16 不新增竞品 benchmark，不能以功能完成替代 `P57-D06` 的正式性能领先证据。

## 实现分组

1. C16A：Semantic compiler-local 合同、foreach CFG 和 exact liveness。
2. C16B：Guest 数组引用布局、状态帧、WASM 确定性与 tamper fail-closed。
3. C16C：C# 游戏样例、README、集中 .NET/PowerShell/UE/Automation/clean architecture Gate。

## 明确非目标

- 通用 `IEnumerable<T>` / 自定义 enumerator；
- `await foreach`、异步流、`ref`、`ref readonly`、解构与元素转换；
- string element、nested array、`TSet`、`TMap`；
- `try/catch/finally`、异常传播、CLR `Task` 与 async helper 调用链；
- Cook、Shipping、Android 和 iOS 验收。
