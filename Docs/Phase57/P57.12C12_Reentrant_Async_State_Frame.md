# P57.12C12 可重入 async 状态帧完成报告

## 结论

P57.12C12 已完成。C# 游戏脚本中的固定布局 local 现在可以跨越多个受控 await，
包括 `FVector`、enum、固定 `USTRUCT` 与对象 capability wrapper。编译器按每个 await 的
精确活跃集合生成独立状态帧，Session continuation entry 负责保存、恢复和回收；没有为
FVector、Actor 或项目 UFUNCTION 增加专用 VM wrapper。

## 已实现能力

### 编译器

- Roslyn Semantic projector 对每个 await 计算 declaration segment 与 last-use segment。
- 仅将暂停后仍会使用的 local 放入当前帧，避免方法级 union frame。
- 状态槽按 symbol id 确定性排序，每个 await 最多 64 个槽。
- Guest Type Lowerer 合成固定布局 frame type，单帧上限 4096 字节。
- resume function 内部接收 continuation token，先恢复 frame，再读取结果并执行 guard。
- suspend 端先整帧 store，再提交 producer；store 或 schedule 失败都会 cancel 后 trap。
- `memory_copy` 获得通用 Guest IR 校验与 WASM lowering，固定结构体 local 无需类型特例。

### Runtime 与 VM

- WAMR、Wasmtime static host catalog 和 Editor binding schema 统一登记新 import。
- Session entry 以 `TArray<uint8, TInlineAllocator<128>>` 保存常见小帧。
- store 只允许同一 continuation entry 成功一次。
- read 只允许在匹配 active token 的 dispatch 内成功一次，长度必须完全相同。
- cancel、reload rollback、owner/World 失效、teardown 与 callback finalization 都回收 frame。
- 两个并发 continuation token 的 frame 相互隔离；超 4096 字节与重复读取 fail closed。

### 真实 C# 示例

ActorLifecycle 与项目 workspace 模板都已经使用跨 await local：

```csharp
FVector loadedMeshOffset = new FVector(0.0f, 0.0f, 25.0f);
await AvidContinuations.NextTickAsync();

AvidLoadedObject loadedObject = await AvidAssets.LoadObjectAsync(
    "/Engine/EngineMeshes/Cube.Cube");
await AvidContinuations.NextTickAsync();

if (!loadedObject.IsValid)
{
    return;
}
UE.Self.AddActorWorldOffset(loadedMeshOffset);
```

最终产物包含 4 个 segment、3 个 compiler-owned await、3 个 resume function，frame 槽数
依次为 `1 / 1 / 2`。每个边界只使用一次 bulk store 和一次 bulk read，不按字段跨 Host。

## 兼容与失败语义

- Semantic schema 15 为当前写入版本；schema 14 继续可读，但禁止携带状态帧。
- 旧 callback handler 与 `avid_on_continuation_v2` ABI 没有破坏性变更。
- 明确不支持的动态布局值不会降级为不安全字节复制，而是在 Guest 编译阶段拒绝。
- state store 成功但 producer 调度失败时，`continuation_cancel` 是必要的编译器依赖，
  用于释放已创建 token；它不能再按用户源码可达性裁剪。
- state read 失败时不会继续执行 guard 或 UE 游戏副作用。
