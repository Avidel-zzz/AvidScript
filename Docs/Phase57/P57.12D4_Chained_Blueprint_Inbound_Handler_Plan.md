# P57.12D4 链式、Blueprint 与重入安全的入站 Handler 计划

## 目标

在 D3 的 `(UFunction, UObject)` Session 路由基础上补齐三项游戏逻辑能力：Profile 可显式选择
`before`、`after` 或 `replace` 链式语义；Blueprint bytecode RPC/RepNotify 可作为原实现参与链路；guest
调用期间再次到达的入站事件按有界 FIFO 深拷贝并延迟到下一次 Session tick 分发。

UE 继续拥有 NetDriver、callspace、复制发送和 RepNotify 时机。AvidScript 不新增项目 API wrapper，
不通过函数名推断策略，也不在 hook 内递归进入 WASM VM。

## D4A：Profile 与 descriptor 合同

- C# Profile schema 10 在 class rule 增加 `before_handlers` 与 `after_handlers`；`include_handlers` 默认
  `replace`，三组成员名必须互斥。
- selection 为每个 function handler 固化 `handler_mode`，合法值仅为 `replace`、`before`、`after`。
- descriptor schema 18 把 `handler_mode` 纳入 callback canonical identity、selection hash 与 package
  hash；multicast callback 固定为 `replace`，不暴露伪链式策略。
- 自动 binding slice 必须保留 handler mode，不能在 reload/profile 重建时退化为 replace。

## D4B：原实现链路与 Blueprint bytecode

1. hook route 同时保存 handler ordinal 与冻结 chain mode。
2. `replace`：active C# handler 成功后不执行原实现。
3. `before`：C# 成功后执行保存的原 thunk；C# trap/failure 后不继续，避免部分脚本副作用后追加原逻辑。
4. `after`：先执行保存的原 thunk，再调用 C#；脚本失败不会伪装回滚已完成的原逻辑。
5. 非 native、拥有 bytecode 的 Blueprint RPC/RepNotify 允许进入 descriptor；保存的
   `UObject::ProcessInternal` 仍是原实现 owner，hook 不复制或解释 Blueprint bytecode。
6. 没有 native thunk 且没有 bytecode、static/delegate/latent、return/ref/out 继续失败关闭。

## D4C：有界重入 FIFO

- 当 Session 正在执行 guest call 时，hook 不递归调用 VM；它按 UFunction `CPF_Parm` 图把参数复制进
  `FStructOnScope`，从而正确持有 FString、容器、结构体和 UObject 引用的生命周期。
- 队列固定上限 64 项；溢出会 fault 当前 Session 并记录稳定错误类别，不覆盖旧事件、不回退原实现。
- 队列项保存弱 UObject、UFunction、handler ordinal、chain mode 与参数快照。reload、EndPlay、Session
  teardown、route replacement 会整体清空，旧 activation 不得进入新 Runtime。
- 下一次 Session tick 在 outer guest guard 退出后 FIFO drain；每帧最多 64 项，新重入事件留到下一帧，
  防止单帧无限自激。
- deferred `before` 在 C# 成功后通过 registry 验证 route 所有权并调用保存的原 thunk；deferred
  `after` 的原实现已在事件到达时执行，不重复调用。

## 验收

- schema 18 确定性生成/解析，handler mode 篡改、重复分组与 slice 丢失模式均失败。
- native route 覆盖 replace/before/after 精确顺序、脚本失败语义与原 thunk 恢复。
- Blueprint UFunction 保存并调用 `ProcessInternal`，不要求 `FUNC_Native`，但必须存在 bytecode。
- 重入参数快照验证深拷贝、FIFO、64 项边界、每帧预算、reload/teardown 丢弃和 deferred before 原实现。
- 阶段末集中执行固定 .NET、PowerShell、UE5.8 no-clean build、完整 Automation 与 clean architecture。

## 后续边界

- D4 不宣称真实网络拓扑已验收；dedicated/listen server 与多客户端独立进程留给 D5。
- D4 仍禁止 return/ref/out/latent handler；delegate ref/out 属于 P58/P60 类型与调用语义工作。
- Blueprint 图中新声明函数的通用发现与完整调用属于 P59/P60；D4 只允许 Profile 精确选中的网络或
  RepNotify UFunction。
