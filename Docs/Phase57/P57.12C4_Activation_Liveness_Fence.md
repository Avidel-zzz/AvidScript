# P57.12C4 Activation Liveness Fence 实现报告

## 状态

实现与集中验收完成。

P57.12C4 关闭的是 Continuation activation 与 UE 生命周期之间的安全缺口：Timer 或异步对象加载完成时，不能只相信旧 endpoint 和 token，还必须确认所属 World、owner handle generation 与当前 active/prepared lane 仍然有效。

## 本组目标

- active 与 prepared activation 保存各自的 owner handle；
- 在调度、生产者完成、prepared commit、Guest dispatch 四个位置执行同一套 liveness 检查；
- owner generation 失效、World 销毁或 HostContext 重绑后，整条 lane 立即失效；
- 精确取消仍在等待的异步生产者，清除 ready completion，并抑制强制触发的迟到回调；
- 保持 active/prepared 热重载事务隔离，不让失败候选污染当前运行实例。

## 实现

### 1. Activation 身份

`FAvidScriptSessionContinuations` 现在分别保存 `ActiveOwnerHandle` 与 `PreparedOwnerHandle`。`FAvidScriptRuntimeSession` 在 `ResetActive` 和 `BeginPrepared` 时传入当前 `HostContext.OwnerHandle`，因此 Continuation 层不再依赖上层恰好先调用 `EndPlay` 才能知道宿主已经失效。

### 2. 统一存活性合同

`IsLaneContextLive` 要求：

- lane 的 `UWorld` 仍有效；
- `World->bIsTearingDown == false`；
- 若 activation 携带 owner handle，则对应 registry 仍存在；
- handle 必须以相同 generation 解析到有效 UObject；
- 对有 World 的 owner，其 World 必须与 lane World 一致。

没有 owner handle 的底层宿主仍可使用 Continuation，但 World 围栏始终生效。普通无 World UObject 可以作为宿主 capability，由 generation 负责其生命周期身份。

### 3. 四点围栏

| 时机 | 行为 |
| --- | --- |
| Schedule | 上下文失效时拒绝创建 token，并关闭旧 endpoint |
| Producer completion | Timer/对象加载完成时重新验证 endpoint、owner 与 World |
| Prepared commit | 候选宿主失效时返回 `continuation_prepared_context_unavailable` |
| DrainReady | Guest 分发前做最后一次验证，防止 ready 与 dispatch 之间发生 teardown |

任一点失败都会执行 `InvalidateLane`：endpoint 失效、同 activation 的 producer 取消、ready token 清除。异步对象 completion 自身先标记为 ready，再统一回收，避免在 producer 的回调栈内重复取消同一个 handle。

active/prepared lane 还维护 O(1) entry 计数。帧级 `DrainReady` 只在当前 active activation 确实持有 continuation entry 时执行 liveness 检查，不会为无异步工作的普通 Tick 扫描最多 4096 个 slot；没有 entry 的 headless/纯 VM Session 也不会被错误提升为必须拥有 World。

## 生命周期验证矩阵

新增 `AvidScript.Runtime.Continuation.ActivationLiveness`，覆盖：

| 场景 | 预期 |
| --- | --- |
| ready Timer 后 owner generation 失效 | 不分发，active entry 清零 |
| 同 lane 仍有 pending object load | producer 精确取消一次 |
| owner 失效后的旧 endpoint | 后续调度返回零 |
| 取消后强制完成旧 object load | 不产生 Guest completion |
| HostContext/owner 重绑 | 旧 producer 取消一次，旧 endpoint 退休 |
| prepared owner 在 commit 前失效 | commit fail closed，active lane 不被替换 |
| World 进入 teardown | 不分发、取消 producer、拒绝新调度 |
| teardown 后强制触发旧回调 | 不产生 Guest completion |

原有 `ActiveLifecycle`、`AsyncObjectProducer`、`HostBoundary`、`PreparedTransaction` 同时作为回归合同。

## 剩余边界

- 当前 C3 为 zero-spill CPS，因此宿主取消不会遗留编译器 frame；后续 bounded spill 必须生成 `avid_reset_async_frames()` 一类 reset 握手，并由 HostContext 重绑与 liveness cancellation 调用；
- UE latent action 的生成式 await bridge 尚未实现，顺延为 P57.12C5；
- async `EndPlay` 的语义尚未冻结，在 teardown 顺序明确前不应扩大支持；
- P57-D06 ControlledLeadership 性能债务继续保持打开，本组不发布新的性能领先结论。

## 下一组

P57.12C5 将先冻结生成式 latent await 的 descriptor 与 callback-target/UUID 所有权，再实现可取消的 `FLatentActionManager` bridge；随后进入 P57.12C3B bounded spill frame 与 reset handshake，避免把只支持零 spill 的 async 表面误写成完整 C# async 状态机。
