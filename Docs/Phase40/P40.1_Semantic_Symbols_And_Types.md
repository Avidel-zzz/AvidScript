# P40.1 Compilation、语义诊断、符号与类型

状态：完成
日期：2026-07-13

## 本组实现

新增独立 .NET 8 工具 AvidScript.CSharpSemantic，不把语义逻辑塞回 Phase 39 syntax frontend。工具使用 SDK 内置 Roslyn 和当前 .NET 8 Trusted Platform Assemblies 建立离线 CSharpCompilation，再投影为 AvidScript 自有模型：

- SemanticSource：source id、当前源码 SHA-256、frontend SHA-256 与 UTF-16 长度。
- SemanticType：稳定 type id、canonical name、显示名、类型类别、值类型与 nullable 属性。
- SemanticSymbol：稳定 symbol id、kind、containing symbol、type id、signature、static/accessibility 与声明 span。
- SemanticDiagnostic：稳定 code、invariant-culture message 与完整 UTF-16 span。

公开 JSON 不包含 Roslyn 数字枚举、对象 identity、程序集路径或 SDK 路径。

## 稳定 ID

基础类型使用与 Guest ABI 对齐的 canonical identity，例如：

- type:float32
- type:int32
- type:void

用户类型使用 fully-qualified identity，例如 type:global::AvidScript.FVector。字段和方法 ID 包含 containing type 与完整类型签名，重载不再依赖文本方法名猜测。

## CLI 与失败策略

CLI 参数：

~~~text
--source <path>
--source-id <id>
--frontend <frontend.json>
--output <semantic.json>
~~~

退出码约定：

- 0：语义成功并原子写入 artifact。
- 1：C# 语义错误，但仍写入 diagnostic artifact。
- 2：参数、IO 或 frontend artifact 结构错误，不产生 semantic artifact。

semantic analyzer 会重新计算源码 SHA-256，并与 frontend artifact 比较；不一致写 ASCS1001，不生成符号或类型表。
