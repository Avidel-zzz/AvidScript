# P40.4 实例状态与语义支持策略

状态：完成
日期：2026-07-13

## 本组目标

P40.4 完成两项进入 Guest IR 前必须明确的契约：

1. 构造器、实例字段、显式/隐式 `this`、实例 property 与普通 helper method 共享完整 containing type identity。
2. lambda/closure、dynamic、unsafe 等当前未支持语义由集中式 policy 诊断，并阻止任何 CFG 进入 Phase 41。

本组不决定实例字段在线性内存中的 offset，也不生成 UE API。对象布局属于 Phase 41；UE facade/reference assembly、proxy 与 host stub 仍由 Phase 42 Reflection Binding Generator 生成。

## 实例 Identity

`SemanticSymbol` 已有的 `containing_symbol_id`、`is_static` 与完整 signature 现在形成可验证的实例图：

- instance field 指向 containing type symbol；
- constructor 使用完整 `.ctor(...)` method ID，kind 为 `constructor`；
- 普通 instance method 指向同一 containing type symbol；
- parameter 指向完整 containing method ID；
- field/property/invocation operation 继续绑定 Roslyn 选中的完整 member ID；
- `IInstanceReferenceOperation` 的 `symbol_id` 绑定 containing type symbol，`type_id` 绑定同一类型。

显式 `this.Value`、隐式 `Value` receiver 和 `this.Read()` 不再只有 operation kind/type，而是能回到同一个稳定 type symbol。Phase 41 因而可以根据 symbol graph 设计实例布局，不需要从 C# 文本猜测 owner。

## 集中式 Support Policy

新增 `SemanticSupportPolicy`，把“是否允许进入当前 AvidScript 语义配置”与 operation 数据投影分开：

- `SemanticOperationProjector` 负责稳定 kind、type、symbol、conversion、span 与 children，并说明当前节点是否已有完整投影。
- `SemanticSupportPolicy` 负责 language-profile allow/deny、稳定诊断 code/message/span。
- document policy 使用 Roslyn syntax 与 SemanticModel 识别 lambda/local function、dynamic type、pointer/function pointer、stackalloc 和 unsafe declaration；它不执行绑定或控制流重建。

当前新增诊断：

| 诊断 | 不支持语义 |
| --- | --- |
| `ASCS4001` | lambda、closure、delegate 与 local function |
| `ASCS4002` | dynamic type、member、indexer、invocation 与 object creation |
| `ASCS4003` | unsafe declaration/block、pointer、function pointer 与 stackalloc |

已有 `ASCS2001` 继续表示具有 Roslyn operation、但尚无完整稳定投影的通用节点；`ASCS3001-ASCS3004` 继续负责异常、async、yield 与 CFG 失败。

## 全文档 Fail-Closed

operation tree、symbol/type table 和 diagnostics 在失败时仍保留，便于 Editor 展示准确原因；但只要 document policy 或 operation policy 产生 error，`control_flow_graphs` 就整体清空。即使同一文件中还有完全安全的方法，也不会发布“部分可用”CFG。

Phase 41 必须同时要求：

- semantic artifact `succeeded=true`；
- `control_flow_graphs` 中存在目标 method；
- source/frontend hash 与当前输入一致。

这样既保留诊断能力，又不会让后端误消费不完整程序。

## Semantic Version

JSON 字段结构仍是 schema v3；支持边界与 `instance_reference.symbol_id` 语义发生变化，因此 semantic version 从 1.2 提升到 1.3。仓库继续用 `global.json` 精确锁定 .NET SDK 8.0.416 与 SDK 内置 Roslyn。

## TDD 记录

首个 RED 准确失败于 `instance_reference.symbol_id` 为空。绑定 containing type 后，后续 RED 依次暴露并关闭：

- closure 缺少 `ASCS4001`；
- dynamic 缺少 `ASCS4002`；
- unsafe 缺少 `ASCS4003`；
- 只有 document-level dynamic field 时，安全方法 CFG 仍被发布；
- semantic version 尚未升级到 1.3。

永久测试使用真实 instance class 覆盖 field、constructor、`this`、implicit receiver、helper invocation 与三张 CFG，并要求所有 ASCS4xxx 诊断具有非空 UTF-16 span。
