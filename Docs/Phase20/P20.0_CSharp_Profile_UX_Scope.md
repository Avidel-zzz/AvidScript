# P20.0 C# Profile UX 范围

## 目标

Phase 20 将 Phase 19 的 C# build profile 底座接成一个 Editor 可用的最小 UX: 用户可以通过一个默认 profile JSON 指向自己的 C# 源文件, 然后从 Editor module 走“读取 profile -> 构建 direct ABI WASM -> 绑定到选中 Actor”的完整链路。

这一阶段优先解决“我怎样不用改代码, 就让自己的 `.cs` 文件进入 C# WASM binding 流程”。

## 交付内容

- 新增 C# profile 文件服务, 负责读取和校验 profile JSON。
- profile JSON 映射到 `FAvidScriptEditorCSharpBuildConfig`。
- 支持默认 profile 路径, 便于后续菜单入口和文档稳定引用。
- 新增 Editor module API, 从 profile path 构建并绑定到当前选中 Actor。
- 新增菜单入口的注册配置, 为后续真实 UI 留稳定 entry name。
- 自动化覆盖自定义 C# source/profile 的 build-and-bind 流程。

## Profile JSON 初版字段

```json
{
  "schema_version": 1,
  "language": "csharp",
  "source_path": ".../CustomMoverScript.cs",
  "project_path": ".../AvidScript.ActorLifecycle.csproj",
  "module_id": "csharp_custom_mover",
  "artifact_stem": "custom_mover",
  "output_root": "Saved/AvidScriptCSharpGuest/CustomMover",
  "report_path": "Saved/AvidScriptCSharpGuest/CustomMover/custom_mover.csharp.report.json",
  "manifest_path": "Saved/AvidScriptCSharpGuest/CustomMover/custom_mover.avidscript.json",
  "configuration": "Release"
}
```

## 本阶段边界

- 不做 Slate 文件选择器。
- 不做 Project Settings profile 列表持久化。
- 不扩大 C# source adapter 语法子集。
- 不做 packaging/mobile 验证。
- 不替换现有 ActorLifecycle 默认菜单; 现有入口继续保留。

## 验收标准

- profile service 能读取 profile JSON 并生成可用 `FAvidScriptEditorCSharpBuildConfig`。
- 缺失 profile、无效 JSON、非 C# profile 能 fail closed 并给出下一步建议。
- Editor module 能从指定 profile path 执行 build-and-bind。
- 自定义 C# source/profile 能生成独立 report、manifest、WASM artifact, 并绑定到测试 Actor。
- `AvidScriptEditor` module build、相关 Editor 自动化和完整 `AvidScript` 自动化通过。
