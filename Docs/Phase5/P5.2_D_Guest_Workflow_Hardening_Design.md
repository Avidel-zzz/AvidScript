# P5.2 D Guest Workflow Hardening Design

日期: 2026-07-05
状态: Implementation In Progress

## 1. 背景

P5.1 已经完成关键可行性验证: 使用官方 LDC 1.42.0 Windows x64 便携包生成真实 D WASM artifact, 并通过 `AvidScript.Guest.D.ExternalActorSetLocationSmoke` 证明 D guest 可以经 WAMR 调用 UE Actor Host ABI。

这意味着 D-first 路线可以从“能不能做”进入“怎么稳定做”。P5.2 是 Phase 6 正式语言前端/绑定生成器实现前的最后工程化关口。

## 2. 目标

P5.2 目标是把 P5.1 的手工链路固化为可重复、可诊断、可热重载验证的 D guest 工作流:

```text
D source -> configured LDC toolchain -> .wasm + manifest -> manifest validation -> reload staging -> UE Actor Host ABI smoke
```

完成 P5.2 后, Phase 6 可以正式开始实现 AvidScript 语言前端和绑定生成器, 而不再把时间花在工具链路径、artifact 识别、manifest 校验和 reload 接线这些基础问题上。

## 3. 非目标

- 不实现完整 AvidScript 语言 parser/typechecker/codegen。
- 不扩展 UE Host API 面, 继续使用 `actor_set_location` 和已有 lifecycle exports。
- 不实现 Editor UI、文件 watcher UI 或 IDE 插件。
- 不做 Android/iOS device smoke。
- 不恢复 packaging/cook/stage/pak。
- 不移除 `env` 兼容别名; 除非先证明 D artifact 可以稳定直接导入 `avidscript.*`。

## 4. 范围拆分

| 小组 | 目标 | Done 标准 |
| --- | --- | --- |
| P5.2a | Toolchain config | D build script 不再依赖手工 PATH, 可通过参数或环境变量定位 LDC。 |
| P5.2b | D artifact manifest | D build script 同时输出 `.wasm` 和 `.avidscript.json`, manifest 包含 module id、ABI、wasm sha256、required exports/imports、toolchain 信息。 |
| P5.2c | Runtime manifest loader | UE 侧可以读取 manifest, 校验 wasm 路径和 sha256, 转换为 reload/runtime 可用结构化输入。 |
| P5.2d | D reload smoke | 真实 D artifact 走 reload staging, 成功 artifact 可激活, 坏 manifest/坏 hash/缺 export 可 fail closed 并保留 live runtime。 |
| P5.2e | Closeout | 文档、tracker、验证矩阵和 commit 收口, 明确 Phase 6 入口条件。 |

## 5. Toolchain Config 设计

`BuildDGuestActorSetLocation.ps1` 增加工具链定位顺序:

1. `-Ldc2Path` 参数, 指向具体 `ldc2.exe`。
2. `-ToolchainRoot` 参数, 自动拼接 `bin\ldc2.exe`。
3. `AVIDSCRIPT_LDC2` 环境变量。
4. `AVIDSCRIPT_D_TOOLCHAIN_ROOT` 环境变量。
5. 当前 PATH 中的 `ldc2`。

诊断输出必须结构化:

```text
[AvidScript][DGuest][Toolchain] ldc2=FOUND source=parameter path=...
[AvidScript][DGuest][Toolchain] ldc2=MISSING checked=...
```

`wasm-ld` 保持可选诊断项。P5.1 已证明 LDC internal LLD 可用, 因此 `wasm-ld` 不作为硬依赖。

## 6. Manifest 设计

生成文件建议命名:

```text
Saved/AvidScriptDGuest/actor_set_location_guest.wasm
Saved/AvidScriptDGuest/actor_set_location_guest.avidscript.json
```

最小 schema:

```json
{
  "schema_version": 1,
  "module_id": "d_guest_actor_set_location",
  "abi_version": 1,
  "language": "d",
  "source": {
    "file": "Saved/AvidScriptDGuest/Generated/actor_set_location_guest.generated.d"
  },
  "wasm": {
    "file": "Saved/AvidScriptDGuest/actor_set_location_guest.wasm",
    "sha256": "<hex>"
  },
  "required_exports": [
    "avid_on_begin_play",
    "avid_on_tick"
  ],
  "required_imports": [
    {
      "module": "env",
      "name": "actor_set_location"
    }
  ],
  "toolchain": {
    "compiler": "ldc2",
    "version": "1.42.0",
    "target": "wasm32-unknown-unknown-wasm",
    "linker": "ldc2-internal-lld"
  }
}
```

文件写入规则:

- 先完整写 `.wasm`。
- 计算 `.wasm` sha256。
- 最后写 manifest。
- 后续 watcher/reload 可把 manifest 视为 reload signal。

## 7. Runtime Manifest Loader 设计

新增轻量 runtime-side manifest loader, 只负责:

- 从 `.avidscript.json` 读取 JSON。
- 校验 `schema_version`、`module_id`、`abi_version`。
- 解析相对 wasm 路径。
- 读取 wasm bytes。
- 计算并比对 sha256。
- 提供 `FAvidScriptWasmReloadManifest` 和 wasm bytes 给现有 reload/runtime 流程。

不在 P5.2 里实现完整 asset pipeline。manifest loader 仍是 PC Editor smoke 级能力。

## 8. Reload Smoke 设计

P5.2d 复用现有 `FAvidScriptWasmReloadSession`, 但需要补齐 host context 接线, 让 reload candidate 的 `BeginPlay` 能调用 Actor Host ABI。

建议验证路径:

1. 构建 D artifact v1: `actor_set_location(1, 1, 123, 456, 789)`。
2. 从 manifest load v1, 创建 live runtime, 验证 Actor 移动到 v1 坐标。
3. 构建 D artifact v2: `actor_set_location(1, 1, 321, 654, 987)`。
4. 通过 reload staging 激活 v2, 验证 Actor 移动到 v2 坐标。
5. 构造坏 manifest 或坏 sha256, reload 应失败, live runtime 保持 v2。

## 9. 错误处理

所有失败都必须 fail closed:

- 找不到 LDC: `missing_toolchain`。
- 编译失败: `compiler_failed`。
- manifest 缺字段: `manifest_invalid`。
- wasm 文件缺失: `module_file_missing`。
- sha256 不匹配: `module_hash_mismatch`。
- ABI 不匹配: `abi_mismatch`。
- import/export 缺失: 沿用现有 WAMR structured diagnostics。

错误信息必须带 next action, 便于后续 Editor UI 或命令行输出复用。

## 10. 验证矩阵

P5.2 完成时必须通过:

```text
BuildDGuestActorSetLocation.ps1 with configured LDC -> result=built + manifest
AvidScript.Guest.D -> Success
AvidScript.Reload -> Success
AvidScript -> 30+ tests performed, Success
Markdown control-character scan -> OK
Plugin git diff --check -> OK
```

如果测试数量增加, 以实际输出为准。

## 11. Phase 6 入口条件

满足以下条件后, 可以正式进入 Phase 6:

- D artifact 构建不依赖手工 PATH。
- D artifact manifest 可被 UE 读取和校验。
- 真实 D artifact 可进入 reload staging。
- 失败 artifact/manifest 不会替换 live runtime。
- P5.2 文档和 commit 已完成。

Phase 6 的第一组应开始实现语言/绑定生成的最小纵切, 例如:

```text
AvidScript DSL or D-friendly binding declaration -> generated D import declarations -> generated wasm -> manifest -> reload
```

### P5.2c Runtime Manifest Loader

状态: Done。

已实现 runtime-side manifest loader:

```text
FAvidScriptWasmRequiredImport
FAvidScriptWasmReloadManifestLoadResult
FAvidScriptWasmReloadManifestLoader::LoadFromFile
```

loader 现在会读取 `.avidscript.json`, 校验 schema/ABI/language/required exports/imports, 解析 wasm 路径, 读取 wasm bytes, 使用 OpenSSL SHA256 校验 manifest hash, 并输出结构化错误分类与 next action。

路径解析策略:

```text
absolute path -> 直接规范化
Saved/Content/Plugins/... -> 优先按 ProjectDir 解析
其他相对路径 -> 优先按 manifest 所在目录解析, 再回退 ProjectDir
```
