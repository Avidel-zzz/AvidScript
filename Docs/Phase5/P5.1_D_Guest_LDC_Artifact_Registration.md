## 3. RED 1: Build Script Over-required wasm-ld

命令只把 LDC bin 放入 PATH:

```powershell
$env:PATH = 'C:\tmp\AvidScriptToolchains\ldc2-1.42.0-windows-x64\ldc2-1.42.0-windows-x64\bin;' + $env:PATH
& '<PluginRoot>\Build\BuildDGuestActorSetLocation.ps1' -Slot 1 -Generation 1 -X 123 -Y 456 -Z 789
```

旧脚本结果:

```text
[AvidScript][DGuest][Build] result=missing_toolchain missing=wasm-ld output=...\Saved\AvidScriptDGuest\actor_set_location_guest.wasm
```

结论: `wasm-ld` 不能再作为硬依赖。真实硬门槛是 `ldc2`; `wasm-ld` 只能作为诊断信息, 因为 LDC 1.42.0 可直接调用内置 LLD。

## 4. Build Script Change

`BuildDGuestActorSetLocation.ps1` 调整为:

- `ldc2` missing 时仍 `result=missing_toolchain`。
- `wasm-ld` missing 时继续编译, 并输出 `linker=ldc2-internal-lld`。
- 保持输出路径 `Saved/AvidScriptDGuest/actor_set_location_guest.wasm`。

## 5. RED 2: LDC Default Import Module

真实 artifact 进入 automation 后, WAMR load 失败:

```text
AvidScript WAMR error | backend=WAMR | module=d_guest_actor_set_location | export=<import> | import=env.actor_set_location | category=missing_import | details=Required host import 'env.actor_set_location' was not registered | next=reject this script module and keep the previous live runtime
```

自动化失败点:

```text
Runtime loads D guest artifact = false
D guest BeginPlay calls actor import = false
Actor stayed at X=10 Y=20 Z=30 instead of X=123 Y=456 Z=789
```

结论: 当前 D source 的 `extern(C)` undefined function 会被 LDC/LLD 编码为 `env.actor_set_location`, 而 Phase 4 Host ABI canonical module 是 `avidscript.actor_set_location`。

## 6. Runtime Change

`FAvidScriptWasmRuntimeInstance` 的 WAMR native symbol 注册保留 canonical ABI:

```text
avidscript.actor_get_location
avidscript.actor_set_location
```

同时新增 LDC freestanding compatibility alias:

```text
env.actor_get_location
env.actor_set_location
```

实现细节:

- 同一组 `GAvidScriptNativeSymbols` 同时注册到 `avidscript` 和 `env`。
- 任一模块注册失败时回滚已注册模块。
- runtime release 时同时 unregister `env` 与 `avidscript`。
- `avidscript` 仍是正式 ABI 名称; `env` 是 LDC 当前默认 import module 的兼容入口, 不是长期公开 ABI 承诺。
