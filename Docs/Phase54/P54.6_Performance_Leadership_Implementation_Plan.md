# P54.6 性能领先 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立 Generated S1、Data-Oriented Fast Lane 与 Semantic Fallback 三层执行架构，使 AvidScript 在首批常用 UE shape 和真实 gameplay frame 上形成经正式统计证明的性能领先。

**Architecture:** `AvidScriptEditor` 从 profile/UHT/descriptor 生成 backend-neutral IR、专用 guest import 与项目 C++ call site；`AvidScriptVM` 用 typed Wasmtime trampoline 绕过通用 value-array 转换；`AvidScriptBindings` 负责生成注册表与 receiver policy；`AvidScriptRuntime` 负责 callback epoch、Self capability 和事务式 command buffer。现有 dynamic dispatcher 与 `ProcessEvent` 路径永久保留为完整语义 fallback。

**Tech Stack:** Unreal Engine 5.8 source build、C++20、C11 Wasmtime 45 C API、Cranelift JIT、C#/.NET 8、Roslyn、WASM、UHT/Reflection、PowerShell benchmark sidecar、Puerts V8。

## Global Constraints

- 引擎固定为 `C:\UnrealEngine` 的 UE5.8 源码版。
- PC/Win64 Development Editor 优先；移动端与 WAMR AOT 不进入 P54.6 headline。
- 不清理 Editor target，不使用全局 `-DisableUnity`。
- 不按 workload、类名、函数名、stable id 或 benchmark fixture 特判。
- 不逐 API 手写 wrapper；所有 S1 call site 来自统一 IR 与 source emitter。
- Runtime 默认保持 semantic；只有 descriptor、generated registry、receiver 与 runtime identity 全部通过时进入 fast lane。
- 测试代码随功能编写，但 UE build、Automation、正式 benchmark 和集中审查只在阶段末执行一次。
- 只有 ABI/Schema、安全、对象生命周期、线程或 packaged target 风险允许中途最小探针。
- 所有给人阅读的设计、进度和收尾文档使用中文。
- 并行写任务必须使用独立 Git worktree/branch；提交前精确核对 staged path。
- 领先结论必须同时满足 P50、跨进程 P95、`2 x MAD`、正确性与实际路径计数门槛。

`TypedHostDispatcher` and `TypedHostImports` in `FAvidScriptVmLoadConfig`; no

object validity. Registry/name/type lookup is absent.

- [x] **Step 4: 实现 StableBorrow receiver**

expected class and policy; object pointer is not cached across callback epochs.

- [x] **Step 5: 实现 typed dispatcher methods**

Each dispatcher method selects the immutable plan by ordinal, validates the
shape-specific capability, and invokes the generated function pointer. On any
qualification failure return `FallbackRequired` or `Rejected` according to
descriptor policy; do not execute both paths. `DispatchI32PairToI32` is the
receiver-free cost/control shape and must never resolve a `UObject`.
