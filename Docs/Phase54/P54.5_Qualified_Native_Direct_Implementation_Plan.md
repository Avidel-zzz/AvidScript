# P54.5 Qualified Native Direct Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为严格合格且由 descriptor 显式授权的 native UFUNCTION 建立可选的 `UFunction::Invoke` direct lane，并在同一正式 PC 矩阵中与 ProcessEvent 和同层 Puerts Reflection fast 对比。

**Architecture:** 扩展现有 `AvidScriptBindingFastPath` immutable plan，不创建第二套 cache。Runtime policy 默认保留 `ProcessEvent`；显式请求 direct 时，仅 qualified plan 使用 UHT native exec thunk，其余 plan 确定性回退。正式 benchmark 使用两个独立 Wasmtime session 表示两个语义层。

**Tech Stack:** Unreal Engine 5.8 source build、C++20、UFunction/FFrame、Wasmtime 45 Cranelift JIT、Puerts V8、UE Automation、PowerShell benchmark sidecar。

## Global Constraints

- 引擎固定为 `C:\UnrealEngine` 的 UE5.8 源码版。
- 不按类名、函数名、stable id 或 benchmark workload 特判。
- 不手写 FVector、Actor 或其他 UE API wrapper。
- 默认调用策略必须保持 `SemanticProcessEvent`。
- Native direct 是显式语义层，不宣称保留自定义 ProcessEvent、RPC 或 Blueprint event 行为。
- function flags 只负责资格校验；descriptor `dispatch_mode=qualified_native_direct`
  才是逐 binding 的语义授权。
- 任一资格条件不满足必须确定性回退，不得运行时猜测。
- 保持 Guest WASM、oracle、operation count、host count 和 workload body 不变。
- WAMR 继续作为移动/受限平台后端，但不进入 P54.5 PC headline。
- 构建和 Automation 在实现批次完成后集中执行，不做碎片化全量构建。
- 所有给人阅读的阶段文档使用中文。

### Task 3: Qualified Native Classifier 与 Direct Thunk

**Files:**
- Modify: `Source/AvidScriptBindings/Private/AvidScriptBindingFastPath.h`
- Modify: `Source/AvidScriptBindings/Private/AvidScriptBindingFastPath.cpp`
- Modify: `Source/AvidScriptBindings/Private/AvidScriptBindingInvocation.cpp`

**Interfaces:**
- Consumes: Task 1 的 policy/mode 和 Task 2 的 descriptor authorization。
- Produces:

```cpp
struct FFastPathPlan
{
	EAvidScriptBindingFastPathKind Kind;
	// HighestInvocationMode is introduced by Task 1.
	FFastPathThunk SemanticThunk;
	FFastPathThunk NativeDirectThunk;
	// Existing immutable frame offsets and sizes remain.
};

bool IsQualifiedNativeDirectFunction(const UFunction& Function);
```

- [ ] **Step 1: 实现加载期资格证明**

先要求 `dispatch_mode=qualified_native_direct`，再要求
`FUNC_Native | FUNC_Final | FUNC_Public`，native pointer 非空，owner 为 native
非 interface/非 Blueprint class，`GetSuperFunction()==nullptr`、`Script.Num()==0`。
拒绝 network、NetValidate、event、BlueprintEvent、delegate、Ubergraph、DLLImport、
exec、static、authority-only、cosmetic、editor-only、out/default/local property。
要求 `NumParms==3`、`ParmsSize==PropertiesSize==12`、UFunction offset 为
`0/4/8`、property chain 顺序精确且 init/post-construct/destructor link 为空。

- [ ] **Step 2: 拆分共享 frame codec**

ProcessEvent 和 NativeInvoke 两个 thunk 共享：

```cpp
bool PrepareScalarI32PairFrame(...);
bool WriteScalarI32Return(...);
```

两个 helper 只操作缓存 offset 和现有 scratch，不做 property walk。

- [ ] **Step 3: 实现 NativeInvoke thunk**

在 Game Thread 构造 compiled-in frame：

```cpp
FFrame Stack(&Target, Plan.Function, Frame, nullptr, Plan.Function->ChildProperties);
Stack.Code = nullptr;
Plan.Function->Invoke(
	&Target,
	Stack,
	Frame + Plan.ReturnFrameOffset);
```

调用后检查 abort state，再通过共享 return writer 写回 Guest Memory。不得直接调用
裸 `FNativeFuncPtr`，保留 `UFunction::Invoke` 的 `CurrentNativeFunction` guard。
direct frame offset 必须来自 `GetOffset_ForUFunction()`，不能复用
`GetOffset_ForInternal()` 的证明。

- [ ] **Step 4: 在 dispatcher 按 policy 选择**

请求 direct 且 plan qualified 时调用 `NativeDirectThunk`；其他情况调用
`SemanticThunk`。ordinal、handle generation、`IsA`、write/reload 和 Guest Memory
guard 仍位于公共 dispatcher。

进入 direct 前还要求 Game Thread、target exact class、非 GC、非 PostLoad、非
intra-frame debugging。上述运行时状态失败时返回结构化错误，不在错误线程或危险
状态下 fallback 调用 `ProcessEvent`。

- [ ] **Step 5: 更新静态 plan instrumentation**

每个 plan 在 load 时只计入一个最高 mode；warm call 不增加原子计数或日志。

- [ ] **Step 6: 提交**

只提交 FastPath 与 BindingInvocation 三个实现文件。
