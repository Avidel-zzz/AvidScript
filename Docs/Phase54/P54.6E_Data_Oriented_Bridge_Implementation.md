# P54.6E Data-Oriented Bridge 实施说明

## 1. 本批目标

P54.6E 把多次 C# 属性写从“每次写都跨越 WASM/Native 边界”改为“WASM 内构造连续命令，一批提交”。公开 C# API 仍是普通属性语法，用户不需要调用 benchmark 专用接口。

第一版只融合满足全部证明条件的 generated S1 `int32` 直接属性写：

- 同一 basic block；
- 同一个 receiver SSA identity；
- 连续区域内只有常量、纯计算和无副作用的 operand preparation；
- 至少三个 setter；
- getter、未知调用、store、receiver 变化或任何不确定副作用都会终止融合；
- profile 必须显式授权该属性进入 `generated_native_properties`，编译器不会扩大写权限。

## 2. C# 与 GuestIR 合同

生成的 C# facade 在合格 setter accessor 上写入：

```csharp
[AvidScriptDataLane("buffered_write", bindingOrdinal)]
set
{
    _ = AvidScriptNative.BindingN(this.Slot, this.Generation, value);
}
```

Semantic artifact schema 8 / 1.8 保存 `OptimizationClass` 与真实 `BindingOrdinal`。旧 schema 4 到 7 仍可读取，但携带 optimization metadata 会 fail closed。

GuestIR fusion pass 删除合格区域中的 accessor call，在组尾生成：

1. `avid_data_lane_epoch() -> i64`；
2. 栈上固定布局 command buffer；
3. 小端字段写入；
4. `avid_data_lane_submit(address, byteCount) -> i32`。

两个 setter 不融合，避免一次 epoch 加一次 submit 比原调用更贵。合成 type、local、import ID 都由确定性 allocator 产生，相同输入必须得到相同 GuestIR checksum。

## 3. Command Buffer ABI

所有字段均为小端，header 为 24 字节：

| Offset | 类型 | 字段 | 值 |
| ---: | --- | --- | --- |
| 0 | `u32` | Magic | `0x41564342`，即 `AVCB` |
| 4 | `u16` | SchemaVersion | `1` |
| 6 | `u16` | CommandCount | 本批命令数 |
| 8 | `u32` | ByteCount | `24 + 32 * CommandCount` |
| 12 | `u32` | Reserved | `0` |
| 16 | `u64` | CallbackEpoch | 当前 callback token |

schema 1 的每条命令固定 32 字节：

| Offset | 类型 | 字段 |
| ---: | --- | --- |
| 0 | `u16` | Opcode，`SetI32 = 1` |
| 2 | `u16` | Flags，必须为 `0` |
| 4 | `u32` | RecordBytes，必须为 `32` |
| 8 | `u32` | BindingOrdinal |
| 12 | `i32` | SelfSlot |
| 16 | `i32` | SelfGeneration |
| 20 | `i32` | Value |
| 24 | `i32` | Arg1，必须为 `0` |
| 28 | `u32` | Reserved，必须为 `0` |

`SetVector`、`InvokeI32Pair` 和 `AssignObject` 已保留 opcode，但 schema 1 parser 明确拒绝，避免尚未完成语义证明时悄悄执行。

## 4. 生命周期与安全

BeginPlay、Tick、事件、EndPlay 和 timer callback 各自进入独立 callback epoch。嵌套或重入 callback 得到新 token；callback 结束、reload、world/HostContext 切换都会让旧 token 失效。

Native submit 依次执行：

1. 校验 header、checked byte count、alignment、command/byte/object 预算和 callback epoch；
2. 把 guest bytes 完整解析到 Native-owned command 数组，不在应用 UE 调用时继续读取 WASM view；
3. 校验每个 ordinal 的 generated lease、shape、receiver mode、`FIntProperty`、写策略、Self generation、world 和 Game Thread；
4. 抓取全部旧值，并为 candidate reload 预备 host-effect journal；
5. 按源码顺序调用 generated setter；
6. 任一调用失败或超过 apply CPU 预算时，按逆序直接恢复旧属性值。

默认预算：4096 条命令、256 KiB、2048 个对象、2 ms apply 时间。未知 opcode、非零 reserved 字段、过期 epoch 或不匹配 binding 都是整批拒绝。

常见热路径对 32 条以内的解析命令、prepared write 和对象去重使用 inline
storage，不产生 parser/目标表堆分配。连续的同 ordinal、同 receiver 命令只执行
一次 lease、类型、Self capability、旧值与 host-effect 资格准备；generated setter
仍逐条按源码顺序调用。apply 时间预算每 32 条或批尾检查一次，避免在四命令批次
中为每条写入读取高精度计时器，同时仍对长批次保持有界中止。

## 5. Backend 取舍

schema 1 编译器产物使用 `avidscript` 静态 import：

- `avid_data_lane_epoch`：`()I`；
- `avid_data_lane_submit`：`(ii)i`。

submit 通过 VM guest-memory adapter 借用只读范围，parser 在任何 UObject 调用前完成读取。这样 Wasmtime 与 WAMR 共享同一授权和 ABI，不需要把框架内部命令伪装成项目 binding。

P54.6A/P54.6C 已保留 raw typed `CommandBufferSubmit` trampoline，本批 Runtime dispatcher 也能从 backend guest memory 读取并执行同一 parser。是否让编译器默认切到 raw typed submit，必须由 phase-end crossing cost ladder 证明收益，不能只凭理论判断。

## 6. 可观测性

`FAvidScriptWasmSmokeResult` 公开：

- `DataBridgeMetrics.SubmittedBuffers`；
- `BoundaryCrossings`（epoch 与 submit 的真实边界次数）；
- `SubmittedCommands`；
- `AppliedCommands`；
- `RejectedBuffers`；
- `SubmittedBytes`；
- 完整 `BindingInstrumentation`，包括 semantic、generated S1 hit/fallback/reject。

正式 benchmark 必须同时校验 logical operation、command、crossing、generated hit/fallback 和 checksum。路径计数不匹配时，耗时样本无效。

## 7. 验证状态

当前已编写 parser 负例、真实 generated `FIntProperty` 三命令应用、中途拒绝回滚和 stale epoch replay 用例。按照阶段流程，本批未单独运行 UE build/Automation；它们将在 P54.6 集中 Gate 中与 Semantic、GuestIR、CSharpGuest、WasmBackend 和 gameplay benchmark 一次性验证。
