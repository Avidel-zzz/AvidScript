# P54.6 性能领先架构

> 状态：设计已冻结，等待书面规格复核
> 决策：采用方案 C，Generated S1、Data-Oriented Fast Lane 与 Semantic Fallback
> 三层混合架构
> 平台：先完成 UE5.8 Win64 Development Editor，移动端与 Shipping AOT 后续独立验收

## 1. 目标

P54.6 不以“追平 Puerts”作为终点。Puerts Reflection、Puerts Static 与
UnrealEngine-Angelscript 只是竞争基线；AvidScript 的优化目标是：

1. 纯 WASM 稳态执行接近 Native 上限；
2. 常用细粒度 UE 调用在同语义层领先成熟框架；
3. 通过生成式 ABI、连续内存、融合调用和批处理，在真实 gameplay frame 吞吐上
   建立结构性优势；
4. 不牺牲对象生命周期、热重载、线程、权限和 Guest Memory 安全边界；
5. 不按函数名手写 API，不为 benchmark 建立产品特判。

“性能领先”必须按具体语义层和 workload 类别声明。某一 shape 领先不能扩写为
全部 UE API 领先；完整语义 fallback 的结果也不能冒充 generated-native 结果。

## 2. 当前基线

### 2.1 纯执行

同一 WASM kernel 的正式跨进程 P50：

| Lane | ns/iteration |
| --- | ---: |
| Native C++ | 1.1682 |
| Puerts V8 WebAssembly JIT | 1.1780 |
| AvidScript Wasmtime Cranelift JIT | 1.1777 |

Wasmtime 已接近 Native 上限。P54.6 不再通过单一整数 kernel 追求不现实的数量级
提升，而是扩展到分支、连续/随机内存、函数调用、SIMD、结构体和混合 gameplay
kernel，使用几何平均与最差 P95 判断执行层。

### 2.2 UE crossing

P54.5 `scalar_add_int32`：

| Lane | P50 ns/op |
| --- | ---: |
| AvidScript Semantic | 682.35 |
| AvidScript Qualified Native Direct | 218.84 |
| Puerts Reflection | 113.82 |
| Puerts Static | 28.67 |

Qualified direct 已移除约 463 ns 的 `ProcessEvent` 相关成本，但相对 Puerts
Reflection 仍多约 105 ns，相对 Puerts Static 仍多约 190 ns。该剩余成本尚未被
分段实测，P54.6 禁止在成本阶梯完成前把它归因于单一组件。

当前 Wasmtime host callback 还会把 `wasmtime_val_t` 数组逐项转换为
`AvidScriptWasmtimeValue`，进入统一 callback 后再经过动态 shape、binding ordinal、
receiver、对象 generation、权限、Guest Memory、frame codec 与 invocation。
这条通用路径是正确 fallback，但不能继续承担性能领先 lane。

## 3. 方案评估

### 3.1 方案 A：只优化通用 Reflection

优点是覆盖面大、产品变化小。上限受 host import、动态 ABI、对象解析与 `FFrame`
约束，可能领先 Reflection，但难以稳定领先 Static。

### 3.2 方案 B：全部转为 Generated Native

单调用上限最高，但 Blueprint、RPC、event、interface、动态加载和热重载无法统一
安全静态化；生成代码体积、项目模块依赖与编译时间也会迅速扩大。

### 3.3 方案 C：三层混合架构

采用：

- `Generated S1` 负责可静态证明的常用 C++ UFUNCTION；
- `Data-Oriented Fast Lane` 负责高频 gameplay 数据交换和融合执行；
- `Semantic Fallback` 保留完整 UE 语义与 API 覆盖。

该方案允许普通 C# 写法保持自然，由编译器和 descriptor 自动选择 lane；开发者
不需要手工选择某个 benchmark API，也不需要为每个 UE 类型维护 wrapper。

## 4. 性能宪章

### 4.1 领先判定

正式领先结论同时要求：

- 5 个独立 timed process；
- 每进程至少 5 次 warmup、30 次 timed sample；
- P50 与 process-P50 的跨进程 P95 均达到门槛；
- 两 lane 差值大于 `2 x max(MAD_a, MAD_b)`；
- checksum、operation count、host crossing count 与可见副作用一致；
- 候选 commit/tree、UE、CPU、runtime、WASM、descriptor 与 generated source
  身份完整且 clean；
- 不使用 workload、类名、函数名或 stable id 特判。

### 4.2 P54.6 硬指标

| 类别 | 阶段 Gate |
| --- | --- |
| 多 kernel 纯执行 | 固定至少 12 个同 WASM kernel；Wasmtime/V8 几何平均不高于 `0.95x`，至少 60% kernel 获胜；相对 Native 单独报告，不伪造“领先 Native” |
| Qualified S2 | 首批支持 shape 的 P50/P95 至少领先 Puerts Reflection 20% |
| Generated S1 标量 | P50 目标 `<25 ns/op`，并至少领先 Puerts Static 10% |
| Generated 属性 | get/set 合计 P50 目标 `<50 ns/op` |
| Tick/事件派发 | P50/P95 至少领先 Puerts 对应 lane 15%，P50 目标 `<150 ns` |
| POD/`FVector` | 保持现有领先，并把 P50 再降低 15% |
| Gameplay frame | Small/Dense 两档的脚本 CPU P50/P95 至少领先 Puerts 30% |
| 稳定性 | 7500 条以上正式 observation 全部正确，无 backend fallback、错误 direct hit 或权限绕过 |

这些是架构 Gate，不是预先宣布已经达到的结果。任一 Gate 未通过时报告真实成本和
下一条架构路径，禁止降低统计门槛换取“领先”措辞。

纯执行固定 suite 至少覆盖：串行整数依赖、可并行整数、可预测分支、数据相关分支、
连续内存、随机内存、标量浮点、SIMD、内部函数调用、小结构体、哈希/位运算和混合
gameplay kernel。V8 WebAssembly 与 Wasmtime 必须加载同一 WASM 字节，不能用
JavaScript 与 WASM 的语言差异替代 runtime 对比。

### 4.3 物理下限止损

P54.6 首先测量最小 typed empty host import。若其正式 P95 已不低于当前 Puerts
Static 标量 P50 的 70%，则单次细粒度调用缺少足够预算，不能继续靠局部 dispatcher
优化追逐 `<25 ns`。该情况下：

1. 保留 Generated S1 作为低延迟普通调用；
2. 将性能领先 headline 切换到 fused import、command buffer 和 gameplay frame；
3. 单调用结果继续公开，不用批处理数字冒充单调用领先。

## 5. 三层执行架构

### 5.1 Generated S1

Editor 根据 Project Binding Profile、UHT 元数据与 canonical descriptor 生成
backend-neutral Binding IR。只有满足以下条件的函数进入 S1：

- C++ native owner 与方法在构建期可见；
- 非 Blueprint override、RPC、event、interface 和 custom thunk；
- 参数、返回值、引用方向、对象所有权与异常边界具有已登记 shape；
- descriptor 明确授权 generated-native；
- 项目接受该调用跳过 `ProcessEvent` 语义。

生成产物包括：

- guest import 声明；
- signature-specific Wasmtime host trampoline；
- C++ typed call site；
- stable binding id 到生成函数的注册表；
- owner module、header、signature、descriptor 与 source hash；
- semantic fallback ordinal。

生成器按签名族共享模板，不为每个 API 手写实现。函数级生成代码只包含 owner、
成员调用和常量布局；对象、权限和错误合同来自统一运行时组件。

#### 项目集成

Engine 与插件 owner 进入项目级 `AvidScriptGeneratedBindings` 模块。项目自定义
C++ owner 由同一生成器输出到项目拥有的 generated binding module，并显式声明
owner module 依赖。Blueprint-only owner 不生成 S1。

生成模块由固定 bootstrap 注册，不能把 benchmark Harness 作为产品注册入口。
Profile 或 owner ABI 改变时只重新生成受影响 translation unit；生成内容必须
deterministic，并以 source hash 参与 Runtime package identity。

### 5.2 Typed Wasmtime Host Trampoline

现有通用 `avidscript_wasmtime_host_trampoline` 永久保留。S1 新增独立的 typed
trampoline SPI：

- 实例化时按 import 绑定 immutable call-site environment；
- environment 预绑定 binding identity、typed function pointer、receiver policy、
  参数布局和错误映射；
- 标量直接读取 Wasmtime native value，不复制到通用 value 数组；
- POD 使用固定 linear-memory layout 和一次 bounds proof；
- 不在 warm call 做字符串、哈希、reflection lookup 或 shape switch；
- 只有加载期证明、descriptor、generated registry 与 runtime identity 全部一致时
  才安装 typed trampoline。

若 Wasmtime C API 的公开安全接口不能达到预算，先用成本证据判断是否引入受控
unchecked/raw API。未经版本锁、ABI 静态断言、负例和 sanitizer 证明，不得仅为
benchmark 绕过 Wasmtime 安全合同。

### 5.3 Receiver 与对象快路径

对象调用分为：

- `SelfBound`：生命周期 session 在 BeginPlay/Tick/Event 入口预绑定 Self capability；
- `StableBorrow`：调用传入带 generation 的稳定 handle；
- `DynamicObject`：走完整 registry 与类型检查。

`SelfBound` 允许移除每次 hash/registry lookup，但不能移除 session generation、
world、Game Thread 和 reload epoch 检查。检查结果可按 callback epoch 缓存，不可
跨 Tick、GC、reload 或 world transition 复用。

### 5.4 Data-Oriented Fast Lane

编译器识别同一 callback 中可证明无中间可见副作用的一组访问，将其降低为：

- snapshot read view；
- write command buffer；
- generated fused operation；
- 批量 UObject handle/POD 数组。

典型数据流：

```text
Begin callback epoch
→ 发布只读 snapshot 与 Self capability
→ WASM 连续内存中执行游戏逻辑
→ 提交 typed command buffer
→ Native 批量验证
→ 按稳定顺序执行 generated S1 或 semantic fallback
→ 提交 effect journal
```

该 lane 不要求开发者改写成专用 benchmark API。C# facade 保持普通属性、方法和
集合语义，只有满足 alias、顺序、异常和 side-effect 证明时才融合；否则保留原调用。

Command buffer 必须有最大长度、字节预算、对象数量、操作白名单和每帧 CPU 预算，
并保持首错停止、确定性错误位置与事务式 effect journal。

### 5.5 Semantic Fallback

以下情况永久进入 semantic：

- Blueprint override、RPC、event、interface；
- custom thunk 或未知参数 shape；
- 动态函数发现；
- generated source/descriptor/runtime identity 不一致；
- receiver、thread、world、reload epoch 或权限证明失败。

Fallback 是产品能力，不是失败；但 benchmark 必须记录实际 S1、data lane 与
semantic hit count，禁止请求 fast 后静默回退并仍计入 fast 结果。

## 6. 模块边界

| 模块 | P54.6 职责 |
| --- | --- |
| `AvidScriptCore` | Generated Binding IR 的纯数据 schema、stable identity 与版本 |
| `AvidScriptEditor` | UHT/profile 解析、资格证明、确定性 source/import emitter |
| `AvidScriptVM` | backend-neutral typed trampoline SPI 与 Wasmtime 实现 |
| `AvidScriptBindings` | generated registry、receiver policy、semantic fallback、instrumentation |
| `AvidScriptRuntime` | callback epoch、Self capability、snapshot/command 生命周期与 effect journal |
| `AvidScriptGeneratedBindings` | 项目生成的 typed C++ call sites，不拥有通用策略 |
| Perf Harness | 成本阶梯、竞争矩阵和统计，不提供产品实现 |

禁止把 codegen、VM ABI、UObject 生命周期、benchmark orchestration 重新集中到单一
文件或模块。跨模块只传递稳定 IR、capability 和 typed call-site contract。

## 7. 成本阶梯

同一进程、同一固定种子依次测量：

1. Native C++ no-op；
2. WASM cached export；
3. Wasmtime typed empty import；
4. 当前通用 value conversion trampoline；
5. immutable environment dispatch；
6. Self capability validation；
7. StableBorrow handle validation；
8. scalar/POD codec；
9. `UFunction::Invoke`；
10. generated C++ member call；
11. fused import；
12. command buffer 每 operation 摊销成本。

每一级报告增量而不是只报告总数。生产代码不保留逐调用计时；成本阶梯由独立
benchmark binary/harness 编排，避免 telemetry 改写被测热路径。

## 8. Gameplay Benchmark

### 8.1 Small Frame

单 Actor 执行 BeginPlay/Tick/Event；每个 timed frame 固定包含 64 次标量/属性
操作、8 次 `FVector` 操作、4 次对象引用和 2 次事件派发，并包含确定性分支。比较：

- C++ oracle；
- Puerts Reflection；
- Puerts Static；
- AvidScript Semantic；
- AvidScript Generated S1；
- AvidScript Data-Oriented。

### 8.2 Dense Frame

固定 1024 个逻辑实体，每个实体执行 8 次标量/属性操作、2 次 `FVector` 操作和
1 次对象引用或事件队列更新。所有 lane 使用相同对象集合、更新顺序、可见副作用和
checksum。报告：

- frame CPU P50/P95/MAD；
- 每帧 crossing 数；
- 每 operation 摊销；
- 临时分配与峰值内存；
- generated code size；
- cold load 与 warm steady-state。

Puerts 和其他竞争框架继续作为计分板，但 Native oracle、正确性和真实帧预算才是
设计中心。

## 9. 错误与安全

- Generated registry 与 descriptor/source hash 不一致：加载失败，不降级成伪 S1；
- 某一 binding 不合格：该 binding 显式 semantic，其他 binding 不受影响；
- command buffer 越界或含非法对象：整批拒绝，effect journal 不提交；
- callback epoch 过期：Self capability 与 snapshot 全部失效；
- Game Thread、world、GC/reload generation 不一致：稳定类别失败；
- typed trampoline trap：映射到统一 AvidScript diagnostic，保留 binding identity，
  不暴露原始指针；
- 性能 Gate 未通过：保留正确实现与数据，禁止通过关闭安全检查伪造通过。

## 11. 非目标

P54.6 不包含：

- 为全部 UE API 生成 S1；
- Blueprint/RPC/event 的静态直调；
- 移动设备 WAMR AOT 正式数据；
- Shipping 平台完整发布 Gate；
- 为追求单个数字关闭对象 generation、Guest Memory、线程或 reload 检查；
- 按 benchmark fixture 手写 API 或专用运行时分支。

## 12. 完成定义

P54.6 完成必须同时具备：

1. 成本阶梯给出剩余 host crossing 的可复现归因；
2. 至少标量、属性、`FVector` 和一种 UObject receiver 具有 generated S1；
3. Data-Oriented lane 完成一个真实 Small/Dense gameplay 闭环；
4. Semantic fallback 与实际路径计数完整；
5. 正式竞争矩阵满足或诚实否决各项领先 Gate；
6. UE5.8 no-clean build、目标 Automation、正式 benchmark 与中文报告完成；
7. 代码、生成产物、文档和 compact evidence 已提交并推送。
