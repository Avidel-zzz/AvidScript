## 已实现架构

### Generated S1

- 新增 backend-neutral generated binding IR，按 binding canonical identity 生成稳定
  import 名、C# facade 元数据和项目 C++ call site。
- 新增 immutable generated binding registry 与 package lease；注册、撤销、shape、
  receiver mode 和 descriptor identity 均 fail-closed。
- Runtime 在 VM load 前从已验证 binding plan 生成 typed host import；Wasmtime 以
  shape-specific C trampoline 直接读取、写入 `wasmtime_val_t`，成功路径不经过通用
  value-array 转换。
- 首批支持 `int32 + int32 -> int32`、`int32` property、`FVector` value 与稳定
  `UObject` roundtrip；不满足资格时保留 semantic fallback。

### Receiver 与生命周期

- `SelfBound` capability 绑定 callback epoch、reload epoch、Game Thread 与 weak object
  有效性。
- `StableBorrow` 保留 slot、generation、type 与 ownership 校验，不跨 callback epoch
  缓存对象指针。
- generated package 卸载先撤销共享状态，已有 lease 不再暴露可调用函数指针。

### Data-Oriented Fast Lane

- 新增 schema 1 command buffer：24 字节 header、32 字节 command record。
- 首批只开放事务式 `SetI32`；`SetVector`、独立调用与对象赋值仍为保留 opcode，
  parser 明确拒绝，不能计入已实现能力。
- 完整 buffer、epoch、预算、binding、receiver 和 host effect 在第一次写入前完成
  验证；失败时不提交部分效果，apply 中途失败会按 journal 回滚。
- C# fusion 只处理可证明 alias、receiver、异常顺序和可见副作用安全的连续 setter；
  读后写、动态 receiver、潜在异常计算和未知调用保持原始 import 顺序。

### Benchmark 与证据

- Gameplay benchmark 使用六条真实 lane：Native C++、Puerts Reflection、Puerts
  Static、AvidScript Semantic、Generated S1、Data-Oriented。
- `gameplay_frame_small` 与 `gameplay_frame_dense` 共用事件步进、初始状态、逻辑操作
  数、checksum 和可见副作用合同。
- 每条 AvidScript lane 发布 semantic、generated 和 data-lane 实际路径计数，禁止从
  workload 名称推算命中。
- 正式 profile 固定 5 个独立进程、5 次 warmup、30 次 timed sample；统计单位为每个
  logical operation 的纳秒。
- 领先 Gate 同时要求 P50、进程内 P95 的跨进程中位数、`2 x MAD` 分离、正确性与真实路径计数；每个
  类别独立报告，不允许用综合分数掩盖失败项。
- 12-kernel PC headline 同时约束 P50/P95 几何均值、kernel win rate 和 MAD 几何
  均值；MAD 不再只是展示字段。
- 十项补充 Gate 不接收手写数值文件。Evaluator 直接读取并校验 suite aggregate、
  5 个 micro 原始进程结果、physical-cost aggregate 与仓库内冻结的 Phase54 vector
  基线，再自行计算 Gate 输入和源文件 SHA-256。

## 正式性能结论

### 执行层

12 个相同 WASM kernel 上，Wasmtime/V8 的 P50 几何均值比为 `0.9772`，即 Wasmtime
约快 `2.3%`，并赢得 `9/12` 个 P50 kernel。P95 几何均值比为 `1.0159`，只赢得
`4/12` 个 P95 kernel。阶段门槛要求比值不高于 `0.95` 且 win rate 不低于 `0.60`，
因此执行层“绝对领先”失败。结果说明 Wasmtime 选择成立，但尾延迟仍需继续优化，
不能宣称它天然大幅领先 V8。

### UE 交互层

六通道 gameplay 的组合热路径已经领先 Puerts：

| Workload | AvidScript 路径 | P50 ns/op | 最快 Puerts P50 | P50 比值 | 进程内 P95 比值 | 结果 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| Small frame | Generated S1 | 83.77 | Static 140.96 | 0.5943 | 0.4758 | 通过 |
| Dense frame | Data-Oriented | 126.19 | Static 229.93 | 0.5488 | 0.3212 | 通过 |

两项均满足 P50、进程内 P95 和 `2 x MAD` 分离。正式路径计数中，Generated S1 的
small/dense 分别有 `11,980,800`/`13,516,800` 次真实 hit，fallback 与 reject 均为
零；Data-Oriented 分别执行 `4,915,200`/`2,457,600` 条 command 和
`2,457,600`/`1,228,800` 次 data crossing，拒绝 buffer 为零。

单次 crossing 仍未领先：Generated S1 标量为 `54.12 ns`，Puerts Static 为
`27.70 ns`；属性为 `197.09 ns` 对 `60.42 ns`；空 callback 为 `385.86 ns` 对最快
Puerts 的 `134.92 ns`。`FVector` value 已降到 `199.97 ns`，相对 P54 历史基线比值
`0.2716`，并快于本次 Puerts Static 的 `1053.81 ns`。物理 typed import 只有约
`4.58 ns`，因此主要差距不在 Wasmtime host ABI 本身，而在 callback、receiver、
generated binding 与 UE 语义工作组合。

### Gate 总结

集中 Gate 共 `12` 项：通过 `3` 项，失败 `9` 项，无未测项。通过项为 `FVector`
基线改善、Small gameplay、Dense gameplay。P54.6 的实现、正式六通道 benchmark 与
证据闭环已经完成，但 AvidScript 尚未达到“所有性能类别绝对领先 Puerts”的产品目标。
下一阶段应直接处理 generated scalar/property 的固定开销、callback dispatch 与
执行层 P95，不再扩充低价值的手写 API 或重复 benchmark 外壳。

## 当前限制

- P54.6 只封板 PC/Win64 Wasmtime JIT；移动端 WAMR AOT 与平台 SIMD 策略后续单独验收。
- Data-Oriented schema 1 只正式支持 `SetI32`，不能把保留 opcode 当成完整 UE API
  批处理能力。
- Generated S1 是已生成的常用 shape 快路径；完整普通 `UFunction` 覆盖仍由 semantic
  reflection fallback 提供。
- 当前 9 项 formal Gate 失败，尤其是单次 scalar/property/callback crossing 与执行层
  P95；不能用 gameplay 的组合胜利替代这些失败类别。
- Gameplay 结果证明批量化与生成路径能够领先，但收益依赖 workload 可聚合性；普通
  一次一调用的 C# 游戏逻辑仍需要下一阶段继续压缩。
