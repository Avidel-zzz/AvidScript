# P54.5 Qualified Native Direct 实施与正式基准报告

## 1. 阶段结论

P54.5 已完成首个由 descriptor 授权、加载期证明、运行时确定性选择的
`qualified_native_direct` 调用层。它不是 benchmark 专用分支，也没有手写某个
UE API；首批通用 shape 为：

`instance + 2 x value int32 -> int32`

正式结果证明该架构方向有效：

- `scalar_add_int32` 从 P54.4 的 713.14 ns/op 降至 218.84 ns/op，
  P50 改善 69.31%；
- 同一次正式矩阵内，direct 相对 semantic 的 P50 改善 67.93%；
- direct P50 已低于 500 ns/op 目标，跨进程 P95 为 220.27 ns/op；
- 150 个 direct 标量样本共记录 4,800,000 次真实 direct hit、零回退；
- `batch_scalar` 另记录 4,800,000 次真实 direct hit、零回退；
- operation count、host crossing count 与既有 workload oracle 一致；
- 7,500 条正式 observation 全部正确。

但 AvidScript 目前仍未在标量调用上领先 Puerts。`scalar_add_int32` direct P50
为 218.84 ns/op，Puerts Reflection 为 113.82 ns/op，AvidScript 延迟仍为
1.92 倍；Puerts Static 为 28.67 ns/op，AvidScript 延迟为 7.63 倍。因此本阶段
只证明 direct 层显著降低了 AvidScript 自身 crossing 成本，不宣称整体性能已经
领先 Puerts，也不把 S2 direct 描述成 S1 static binding。

## 2. 已实现内容

### 2.1 显式调用策略

Runtime host context 与 binding invocation context 增加：

- `SemanticProcessEvent`：默认策略，保留现有完整语义；
- `QualifiedNativeDirect`：调用方显式请求；未获授权或未通过资格证明时确定性
  回退 semantic。

默认值保持 `SemanticProcessEvent`，现有 session、脚本和 API 行为不变。

### 2.2 Descriptor 授权与 canonical identity

Project Binding Profile 可按函数声明 `qualified_native_direct`。授权进入 canonical
descriptor、哈希身份、切片闭包与 C# profile 再生成链路。Resolver 仍先执行通用
类型和函数策略，不能通过函数名、类名、stable id 或 workload 名放行。

加载期只接受满足以下约束的计划：

- native、非网络、非 event、非 interface；
- owner 与函数元数据能够形成稳定 immutable plan；
- 参数帧布局、偏移、大小和返回槽位与首批 shape 完全匹配；
- descriptor 显式授权；
- UE5.8 Editor-only 元数据访问受编译宏保护。

任一条件不满足都保持 semantic-only。

### 2.3 共享 immutable plan 与 direct thunk

P54.5 复用 `AvidScriptBindingFastPath` 的 immutable plan 和 frame codec，没有创建
第二套缓存。Qualified thunk 构造 `FFrame` 后调用缓存 `UFunction` 的 `Invoke`
终点，由其进入 UHT native exec thunk；该路径绕过 `ProcessEvent` 的第二层虚拟
frame 与参数复制，同时保留公共 dispatcher 的：

- ordinal 与 descriptor 身份校验；
- UObject generation、类型和写策略校验；
- Guest Memory 与 scratch 边界检查；
- reload effect journal；
- Game Thread guard；
- 稳定错误分类与 semantic fallback。

Binding package 新增通用 `UClass + FName -> ordinal` 查询，不再从 stable id 文本
猜测计划身份。

### 2.4 真实路径证据

Benchmark 的 `direct_hit_count` 与 `requested_direct_fallback_count` 由 dispatcher
实际执行路径写入，不再按 workload 或迭代数推算。正式 direct lane 的累计计数为：

| Workload | Direct hit | Requested-direct fallback |
| --- | ---: | ---: |
| `scalar_add_int32` | 4,800,000 | 0 |
| `batch_scalar` | 4,800,000 | 0 |
| `scalar_noop` | 0 | 2,400,000 |
| `property_get_set` | 0 | 9,600,000 |
| `object_roundtrip` | 0 | 600,000 |
| `vector_ref_out` | 0 | 1,200,000 |
| `vector_value` | 0 | 1,200,000 |

这证明当前只对已授权标量 shape 直调。向量、对象、属性和 noop 在 direct lane
中的计时仍是 semantic fallback，不能被引用为 native-direct 优势。

## 5. 数据边界

正式矩阵还观测到 AvidScript semantic fallback 在 `vector_ref_out` 和
`vector_value` 上分别低于 Puerts Reflection，但这些 workload 没有 direct hit。
它们可作为当前通用 ABI 的后续研究线索，不能用来证明 P54.5 direct shape 覆盖或
整体领先。回调、属性与对象路径也没有纳入本阶段 direct 资格范围。

## 6. 下一阶段

P54.6 应把优化重心从 `UFunction::Invoke` S2 层移到生成式 S1 binding 与更低成本的
Wasmtime host trampoline：

1. 由 descriptor 和 UHT 元数据生成 C++ typed binding，不逐 API 手写 wrapper；
2. 首批覆盖标量、bool、float、枚举、`FVector` POD 与 UObject handle shape；
3. 将 receiver、ordinal、参数布局和写回策略预绑定，继续压缩每次 host import；
4. 同时保留 semantic fallback，并用真实路径计数证明每个 shape 的命中与回退；
5. 在同一五 lane 协议下以 Puerts Static 作为 S1 上界，以 Puerts Reflection 和
   UnrealEngine-Angelscript 作为成熟度与性能对照。

在生成式 S1 lane 和更广 shape 覆盖完成前，AvidScript 仍处于性能架构验证期，
还不能定义为已经达到 Puerts/UnLua/Angelscript 的完整成熟闭环。
