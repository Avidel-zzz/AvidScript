# P54.0 执行分层与性能领先架构

> 状态：已批准，进入实施
>
> 日期：2026-07-27
>
> 平台：UE5.8 源码版，Win64 优先，Android/iOS 约束前置
>
> 基线：Phase 53 正式四 lane benchmark

## 1. 阶段目标

Phase 54 将 AvidScript 从“固定 WAMR 解释器的 UE binding”升级为“后端可替换、制品可验证、执行模式可选择的 C# / WASM 游戏脚本运行时”，并在不改变同一份 Guest 语义和 Host ABI 的前提下建立执行层竞争。

“领先 Puerts 与 UnrealEngine-Angelscript”是工程目标，不是预设结论。只有同机、同引擎语义、同 workload、同正确性 oracle 的 P50 和 P95 均稳定领先超过 5%，且差异大于两倍 MAD，才允许标记为“已领先”。

## 2. Phase 53 暴露的问题

Phase 53 的 AvidScript lane 使用 `interpreter + fast interpreter, aot=0, jit=0, fast_jit=0`。正式结果表明：

- `pure_integer` 相对 Puerts V8 static 慢约 64.14 倍，主要受执行层限制；
- callback 相对 Puerts static 慢约 2.37 到 4.06 倍，包含 Guest 入口和生命周期分发成本；
- scalar/property/object/batch 相对 Puerts static 慢约 14.91 到 50.43 倍，主要成本不能只归因于 VM，还包括 Host crossing、动态调用计划、封送和对象句柄路径；
- `vector_value` 已经比 Puerts reflection 快约 5.2%，说明通用 ABI 和零分配结构体路径具备竞争力。

因此 Phase 54 必须同时推进执行后端和跨边界热路径，不能把所有差距都押在更换 VM 上。

## 3. 架构原则

1. `AvidScriptCore`、`AvidScriptBindings` 和 `AvidScriptRuntime` 不得依赖 WAMR、Wasmtime 或其他后端头文件。
2. 后端公共契约只表达稳定身份、执行模式、制品格式、能力位、加载、调用、Guest Memory 与 trap。
3. `.wasm`、WAMR `.aot` 和未来 Wasmtime serialized module 都是显式制品；禁止根据扩展名静默猜测。
4. Editor 可以使用 JIT 或解释器以换取迭代速度；Shipping 优先使用构建期 AOT 制品。
5. 移动端不假设允许运行时生成可执行代码。Android/iOS 的发布策略必须能只携带 AOT loader。
6. WAMR 保留为正式后端。是否成为 PC 默认由 AOT/JIT 与 Wasmtime 的同 ABI 实测决定。
7. benchmark fixture 不得拥有专用 VM 快路径或专用 UFunction 名称分支。
8. 失败诊断、ownership、reload、capability、Guest Memory 边界不能为跑分关闭。

## 4. 公共执行契约

`AvidScriptVM/Public/AvidScriptVmBackend.h` 增加以下概念：

```cpp
enum class EAvidScriptVmBackendKind : uint8
{
	Wamr,
	Wasmtime
};

enum class EAvidScriptVmExecutionMode : uint8
{
	Auto,
	Interpreter,
	Aot,
	Jit
};

enum class EAvidScriptVmArtifactFormat : uint8
{
	WasmBytecode,
	WamrAot,
	WasmtimeSerialized
};

enum class EAvidScriptVmCapability : uint32
{
	None = 0,
	GuestMemory = 1 << 0,
	Interpreter = 1 << 1,
	Aot = 1 << 2,
	Jit = 1 << 3,
	PrecompiledArtifact = 1 << 4,
	StructuredStack = 1 << 5
};
```

`FAvidScriptVmBackendInfo` 是不可变运行身份，至少包含：

- backend kind；
- execution mode；
- artifact format；
- capability mask；
- stable backend id；
- runtime version；
- target triple。

`FAvidScriptVmBackendSelection` 表达请求：

- backend kind；
- execution mode；
- artifact format；
- 是否允许 fallback。

工厂 `CreateAvidScriptVmBackend(Selection, OutError)` 负责能力检查和实例创建。现有 `CreateAvidScriptWamrBackend()` 暂时保留为兼容入口，但 Runtime 生产路径改用通用工厂。

`FAvidScriptVmArtifactView` 显式携带：

- execution bytes；
- artifact format；
- canonical WASM bytes；
- execution artifact identity；
- canonical WASM identity；
- target triple。

解释器的 execution bytes 与 canonical WASM 相同。WAMR AOT 和 Wasmtime serialized module 的 execution bytes 是派生制品，但 import/export layout、binding package 和 Guest ABI 授权继续从对应 canonical WASM 验证。不得把 AOT 文件交给标准 WASM parser，也不得因为 AOT 文件不可解析而跳过授权。

`FAvidScriptVmExportHandle` 增加实例归属身份，使来自另一个 backend 实例或 reload generation 的 handle 必须失败关闭，不能只依赖 slot/generation 恰好不冲突。

## 5. 制品模型

构建管线以 canonical `.wasm` 为源制品，并生成带 provenance 的派生制品：

```text
canonical.wasm
  sha256
  guest ABI version
  binding package hash
  source manifest hash

canonical.win64-x86_64.wamr.aot
  source wasm sha256
  wamrc version and sha256
  target triple
  CPU feature policy
  opt level
  artifact sha256
```

加载前必须验证派生制品与 canonical WASM、binding package、目标平台和 compiler identity 一致。热重载比较的是逻辑模块身份与 provenance，不以本机绝对路径作为身份。

WAMR runtime library 同样生成 build-config identity，至少覆盖 WAMR commit、`INTERP/FAST_INTERP/AOT/JIT/FAST_JIT`、target、configuration 与 library SHA-256。`WAMR.Build.cs` 不能继续仅凭任意候选 `.lib` 存在就假设执行能力。

## 6. PC 执行策略

第一轮只建立可审计的 WAMR 对决：

| 目标 | 默认候选 | 允许 fallback |
| --- | --- | --- |
| Win64 Editor Development | WAMR AOT | WAMR fast interpreter |
| Win64 Shipping | WAMR AOT | 无静默 fallback |
| benchmark | 显式 lane 指定 | 禁止 |

第二轮引入 Wasmtime/Cranelift PC 候选：

| 目标 | 候选 | 目的 |
| --- | --- | --- |
| Win64 Editor Development | Wasmtime JIT | 纯脚本与 callback 性能 |
| Win64 Shipping | Wasmtime precompiled | 去除运行时编译成本 |

Wasmtime 不能在未完成依赖锁、许可证、包体、trap、Guest Memory、动态 import 和 reload 验证前替换默认后端。

## 7. 移动端策略

- Android 首选 WAMR AOT，保留 WasmEdge/Wasmtime AOT 作为后续挑战者；
- iOS 只设计构建期 AOT，不把 JIT 作为发布前提；
- AOT manifest 必须包含架构、目标三元组和 CPU feature policy；
- 任何 PC 专用后端能力都通过 capability mask 暴露，Runtime 不做平台字符串分支。

## 8. Host crossing 优化

执行层优化和 Host crossing 优化分开计量：

1. 同一 descriptor 生成静态 typed thunk；
2. ordinal 在模块加载时解析为稳定 invocation entry；
3. blittable 标量和结构体使用固定布局 frame；
4. 对象句柄只执行 generation/ownership 所需检查，成功路径不构造字符串；
5. reflection fallback 保留完整 UE API 覆盖；
6. 高频调用支持 batch，但 benchmark 同时报告单次 crossing 和 batch 摊销成本。

禁止为 benchmark fixture 手写 thunk。生成器必须能从任意满足策略的 UFUNCTION descriptor 产生同类代码。

## 9. Benchmark 矩阵

Phase 54 延续 Phase 53 的 fixture、oracle、独立校准、5 个 fresh process、每进程 5 次 warmup 和 30 次 sample，并增加执行层维度：

1. Native C++；
2. Puerts V8 reflection；
3. Puerts V8 static；
4. AvidScript WAMR fast interpreter；
5. AvidScript WAMR AOT；
6. AvidScript Wasmtime JIT/AOT，依赖就绪后启用；
7. UnrealEngine-Angelscript interpreter/precompiled，仅在官方引擎候选和相同 fixture 可复现后启用。

每条 AvidScript lane 必须使用相同 canonical Guest、binding package、输入、checksum 与 Host ABI。结果记录 backend id、mode、artifact format、runtime/compiler hash、artifact hash、target triple 和 fallback 状态。

Phase 53 的历史 `avidscript_wamr` 永久表示 interpreter + fast interpreter，不能把 AOT 偷换到同名 lane。Phase 54 schema v2 使用 profile 锁定的 `lane_catalog`；每个 lane 的 runtime、tier、adapter、source WASM、execution artifact、compiler flags、runtime build config、target、CPU feature policy 共同形成 `lane_identity_sha256`。Calibration、request、raw result 和 aggregate 的 catalog/hash 必须完全一致。

五 lane 正式矩阵使用五个 timed process，使每条 lane 各占一次顺序位置，总样本为 `10 workloads x 5 lanes x 5 processes x 30 samples = 7500`。增加 Wasmtime 成为六 lane 后使用六个 timed process，总样本为 10800。cold start、稳定 RSS 与峰值 RSS 使用 lane-exclusive process，不能从组合 Editor 进程包络归因。

UnrealEngine-Angelscript 依赖引擎源码修改，不能把独立 AngelScript SDK 或不同 UE fork 的数字混入当前 `C:\UnrealEngine` 排名。依赖未就绪时状态只能是“不可比较”。

## 10. 性能 Gate

Phase 54 的目标 Gate：

- 纯脚本：AvidScript 最优正式 PC lane 的 warm P50 和 P95 均优于 Puerts V8 static；
- callback：`callback_empty` 与 `callback_tick` 均优于 Puerts V8 static；
- UE crossing：scalar、property、struct、object、batch 的几何平均 P50 和 P95 均优于 Puerts static；
- 任一单项不得稳定落后 Puerts static 超过 5%；
- AngelScript lane 可比较后，使用同一规则判定；
- 任何 correctness、identity、fallback 或 provenance 不满足的 sample 不参与排名；
- 未满足时阶段报告必须列出成本归属和下一批次，不得写“绝对领先”。

## 12. 完成定义

- Runtime 生产路径不再硬编码 WAMR 工厂；
- backend/mode/artifact 能力不匹配时失败关闭，并有稳定诊断；
- WAMR interpreter 与 AOT 能加载同一逻辑 Guest 并得到相同 oracle；
- AOT 制品拥有可重放的 compiler、source、target 和 hash 证据；
- benchmark 不允许 AOT 静默回退解释器；
- 至少完成一次 WAMR AOT 正式复测和一次通用 crossing 优化复测；
- Wasmtime 只有通过完整语义与性能 Gate 后才可成为 PC 默认；
- AngelScript 依赖未就绪时明确标记不可比较，不发布伪排名；
- 完整 UE5.8 构建、Automation、架构、隐私与 Phase Gate 通过；
- 中文 closeout 明确列出领先、持平、落后与未验证项。
