# Phase 54 Task 3A Wasmtime Cranelift JIT Core 实现报告

## 结论

Task 3A 已实现 Win64 Wasmtime `v45.0.0` Cranelift JIT core，并保持 WAMR interpreter 行为。实现包含：

- 明确的 `Wasmtime/Jit/WasmBytecode` factory 选择；
- config、engine、module、store、linker、instance 生命周期；
- canonical WASM layout/import contract 先验验证；
- event export 类型检查、缓存、调用与 stale/foreign handle 语义；
- guest memory read/write 与同步 borrow；
- 完整静态 host import catalog、host failure trap 和结构化 frame；
- active call 中 reentrant unload 延迟；
- WAMR 与 Wasmtime 标准 wasm-c-api 的可靠链接边界。

本任务没有实现 Task 3B dynamic binding package adapter、serialized artifact、benchmark、Runtime 改动或 Editor target 清理。

## 关键设计

### Cranelift 与生命周期

Wasmtime C shim 创建 fresh config，固定：

- `WASMTIME_STRATEGY_CRANELIFT`
- `WASMTIME_OPT_LEVEL_SPEED`
- component model 显式关闭
- 不注册 WASI

metric 映射如下：

- `RuntimeInitMs`：一次性 DLL 可用性确认、config 与 engine；
- `ModuleLoadMs`：`wasmtime_module_new` 的 Cranelift compile；
- `ExecEnvCreateMs`：store/context；
- `ModuleInstantiateMs`：linker、静态 imports 与 instantiate。

卸载顺序为 export wrapper、instance wrapper、module、linker/host bridge、store、engine。重复 unload 与析构均幂等；active guest call 中的 unload 延迟到调用展开后执行。

### C API 编译与链接边界

WAMR `libiwasm.lib` 原产物包含 `wasm_c_api.c.obj`，导出 `wasm_config_*`、`wasm_engine_*`、`wasm_functype_*`、`wasm_trap_*`，与 Wasmtime import library 冲突。仅禁 Unity 或改变链接顺序不能保证正确实现被选中。

本任务采用两层边界：

1. WAMR CMake 增加 `WAMR_BUILD_WASM_C_API` 开关，Win64 构建固定传 `0`，从 source glob 移除 `wasm_c_api.c` 并重建 tracked `libiwasm.lib`。
2. Wasmtime 头只出现在独立 C 编译单元 `AvidScriptWasmtimeApi.c`，向 C++ backend 暴露 `avidscript_wasmtime_*` 唯一前缀 opaque API，解决 Unity 聚合时 WAMR/Wasmtime 类型名冲突。

shim 直接调用官方 import library，不使用 `GetProcAddress` 或动态 symbol table。开发运行时通过插件路径一次加载并缓存 DLL handle；打包 RuntimeDependency 发布到 `$(PluginDir)/Binaries/Win64/wasmtime.dll`。

`BuildWAMRWin64.cmd` 的 `dumpbin /linkermember:1` gate 要求：

- `wasm_runtime_init`、`wasm_runtime_load` 存在；
- `wasm_config_*`、`wasm_engine_*`、`wasm_functype_*`、`wasm_trap_*` 不存在。

### Wasmtime 依赖布局修正

Task 2 锁定 archive 身份正确，但选择了 `min/` 子布局；其 `wasmtime/conf.h` 未启用 compiler/Cranelift，不能提供 Task 3A 所需 API。

本任务保持同一 v45 archive URL、size 与 SHA-256，只把 lock layout 改为 archive 的 `include/` 和 `lib/` 完整 C API 布局。安装器新增 `WASMTIME_FEATURE_CRANELIFT` gate，仍只发布 headers、DLL、import library 与 LICENSE，不安装或链接静态 `wasmtime.lib`。

最终受管安装：

- content SHA-256：`4399f843601d637308bd85fff7a59245afdf3546fae327996d2504c7635528e5`
- file count：`115`
- `wasmtime.dll`：`21353984` bytes
- `wasmtime.dll.lib`：`203258` bytes

### ABI 与静态 imports

compact ABI parser 已从 WAMR dynamic registry 提升为 backend-independent contract：

- `i/I/f/F` 对应 `i32/i64/f32/f64`
- 最多 64 个参数
- 零或一个结果

静态名称、签名、binding id 与 `env` compatibility 只保存在一个 ASCII catalog。Wasmtime linker 和 WAMR `NativeSymbol` 注册表都从该 catalog 构造；WAMR callback 也按 dense binding id O(1) 取名称，避免第二份字符串表漂移。

Wasmtime host callback 使用 inline value storage，成功 warm call 不构造字符串。dispatcher/memory failure 保留 import name/details，并转换成 Wasmtime trap。

### Guest memory borrow

`IAvidScriptVmGuestMemory` 新增同步、受控 borrow：

- `BorrowReadOnlyBytes`
- `BorrowMutableBytes`

默认实现 fail closed，保证现有非 VM provider 兼容。WAMR 与 Wasmtime 均验证 size、power-of-two alignment、guest address alignment 和 bounds，并在每次操作重新获取 native pointer。

borrowed view 只在当前同步 host dispatch 内有效，不跨 guest call 保留。transform batch 直接将 guest spans 映射为 `InputCells`/`OutputFloats`，删除每次调用的 `TArray<uint32>`、`TArray<float>` 分配、输入复制与输出回写，也没有全局 scratch。

未修改 `Source/AvidScriptRuntime`、benchmark 或 Editor target。

## 限制与关注项

- dynamic binding package 在 Wasmtime backend 中以 `dynamic_import_unavailable` fail closed，留给 Task 3B；
- event export 当前只接受 `() -> void` 与 `(f32) -> void`；
- 只暴露名为 `memory` 的默认线性内存；
- 不接受 Wasmtime serialized artifact，也不启用 unchecked call；
- `StackSize`/`HeapSize` 目前执行非零 contract 校验，但没有映射为 Wasmtime store limiter；
- DLL handle 按进程缓存，不在 VM backend unload 时释放，避免 delay-import 生命周期悬空；
- 本批遵循阶段集中验证，没有运行全量 AvidScript Automation 或 benchmark。
