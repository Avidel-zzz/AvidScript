# P54.3 真实 C# frontend 五通道正式基准报告

## 1. 范围与边界

本报告发布 Phase 54 Task 4B 的真实 `AvidScriptPerfWorkload.cs` 五通道正式矩阵。数据边界固定为 `csharp_frontend_output`：

- AvidScript 两条 lane 使用同一份正式 C# frontend 生成的 WASM、binding package、debug map 与 workload adapter。
- 数据包含 C# frontend 输出、生成 binding ABI、host crossing、fixture 语义与 runtime 执行的共同影响。
- 本矩阵没有运行固定等价 kernel，不把差异全部归因于 runtime，也不宣称 runtime-only 性能优势。
- 原始 sample 与本机路径只保存在 Git 外部 attempt；仓库只发布去路径、无 raw sample 的 compact evidence。

## 4. Wasmtime P50 比率

比率定义为 `Wasmtime P50 / comparator P50`。大于 1 表示本矩阵中的 Wasmtime lane 更慢，小于 1 表示更快；它描述完整 lane 输出，不是 runtime-only 归因。

| Workload | Wasmtime / Native | Wasmtime / Puerts Reflection | Wasmtime / Puerts Static | Wasmtime / WAMR |
| --- | ---: | ---: | ---: | ---: |
| `callback_empty` | 362.69x | 2.11x | 2.12x | 0.50x |
| `callback_tick` | 349.56x | 1.76x | 1.77x | 0.58x |
| `pure_integer` | 1.02x | 1.02x | 1.02x | 0.02x |
| `scalar_noop` | 679.38x | 7.28x | 24.09x | 0.72x |
| `scalar_add_int32` | 771.52x | 7.19x | 25.39x | 0.76x |
| `property_get_set` | 317.32x | 3.02x | 4.91x | 0.39x |
| `vector_value` | 667.89x | 0.59x | 0.73x | 0.63x |
| `vector_ref_out` | 494.13x | 0.82x | 1.05x | 0.70x |
| `object_roundtrip` | 857.11x | 6.33x | 17.78x | 0.62x |
| `batch_scalar` | 96.79x | 6.85x | 23.71x | 0.75x |

`pure_integer` 的正式 headline 为：Wasmtime P50 `1.00 ns/op`，相对 Puerts Reflection、Puerts Static 与 Native 均为约 `1.02x`，相对 WAMR 为 `0.02x`。这只能说明当前 `csharp_frontend_output` 完整 lane 在该 workload 上的观测结果，不能单独证明 runtime-only 优势。

## 5. 结论与剩余边界

- Wasmtime lane 在 `vector_value` 相对 Puerts Reflection/Static 为 `0.59x/0.73x`，在 `vector_ref_out` 相对 Reflection 为 `0.82x`、相对 Static 为 `1.05x`。
- callback、scalar、property、object 与 batch workload 中，Wasmtime lane 仍慢于两条 Puerts lane；这些结果包含不同语言 frontend、binding ABI 与 host crossing，不能归结为 V8 与 Cranelift 的纯 runtime 差异。
- Wasmtime 相对 WAMR 的 P50 比率为 `0.39x` 到 `0.76x`，`pure_integer` 为 `0.02x`；这仍是同一 C# frontend output 下完整 backend lane 的端到端差异。
- 本批次没有修改 workload、canonical profile 或候选源码，也没有依据诊断矩阵发布性能结论。

机器可读证据见 `P54_CSharp_Five_Lane_Benchmark_Evidence.json`。
