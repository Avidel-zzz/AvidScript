# P54.2 Wasmtime v45 C API 依赖锁实现报告

## 状态

初始实现、独立审查 C1/I1 与复审 I2-R1/I2-R2 修复完成，等待第三修复提交上的 clean-HEAD architecture 复验。

本组只建立 Wasmtime v45 minimal C API 的依赖锁、安装闭环与 UBT External Module，不包含 Wasmtime backend，也未修改 VM/Runtime C++。

## 实现范围

- 新增 JSON lock/schema，固定官方发布 URL、archive 身份、minimal layout 与安装路径。
- 新增 `ValidateLock`、`Install`、`Verify`、`Remove` 四模式安装器。
- 下载使用唯一 partial 文件，大小和 SHA-256 通过后才发布到版本隔离 cache。
- ZIP 解压拒绝路径逃逸、额外顶层 root、重复 entry、reparse/link entry 与 NTFS alternate data stream。
- 安装只复制 `min/include`、DLL、import library 与 archive 根许可证。
- marker 只记录固定身份与 canonical 内容摘要，不记录路径、用户或时间戳。
- 从受信 RepositoryRoot 到 version install path 的每级现存祖先都执行 reparse 拒绝与物理 containment 检查，Install 发布前和 Remove 删除前重新取路径并比对。
- `Verify` 拒绝缺失、多余、修改文件、marker/lock 身份漂移，以及受管树内任意文件或 marker 的非默认 NTFS ADS。
- `Remove` 只删除完整验证通过的版本目录，删除前再次检查祖先边界、reparse tree 与 ADS；空父目录清理不越过 `installed/`。
- 新增 `Wasmtime` External Module；仅 Win64 受管布局完整时定义 `AVIDSCRIPT_WITH_WASMTIME=1`。
- `AvidScriptVM` 仅通过 Private dependency 引入 `Wasmtime`，Public 不暴露 Wasmtime header。
- architecture checker 先以等长 mask 移除 C# 注释、string/raw/verbatim string 与 char 内容，再枚举每个代码级 `PrivateDependencyModuleNames`/`PublicDependencyModuleNames` occurrence；只有该 occurrence 自身属于 literal-only `Add`/`AddRange` 才被接受，unresolved 参数与 Insert、索引器、alias、赋值、未知 mutator 全部 fail closed，Wasmtime 只允许位于 Private。

## 自审

- tracked/untracked 路径与 brief ownership 一致。
- `installed/` 位于最终 `!Source/` 规则之后并已由 `git check-ignore` 确认。
- tracked 文件未包含 archive、header、`.lib`、`.dll`、cache、绝对本机路径、用户名、时间戳或凭据。
- UBT 未引用或链接 static `wasmtime.lib`。
- 安装 marker 未记录绝对路径。
- synthetic ZIP 合同不联网，也不读取真实用户目录。
- ancestor junction fixture 的外部目标与 sentinel 在 Verify/Remove 拒绝后保持不变。
- DLL ADS、marker ADS 都在内容摘要和删除前被稳定错误 `ASP54W1606` 拒绝。
- 把 `PrivateDependencyModuleNames.AddRange` mutation 为 Public 后，结构化合同同时观察到 Private 缺失与 Public 泄漏。
- 移除真实 Private Wasmtime 并加入伪调用字符串后，Private 依赖仍被观察为缺失；Public 使用变量表达式时记录 unresolved 并拒绝。
- Public 使用 `Insert` 时记录 unsupported mutator；把 dependency list 赋给 alias 时，原始 occurrence 也记录 unsupported，后续 alias 调用无法绕过 gate。

## 剩余风险

- 当前任务只提供依赖与构建开关；Wasmtime backend、运行时选择、调用 ABI 与行为一致性属于后续任务。
- `Wasmtime.Build.cs` 只做受管布局存在性检查；内容完整性仍必须由安装器 `Verify` 提供。
- Windows 本地并发目录替换仍存在最终复查与文件系统 syscall 之间的窄 TOCTOU 边界；脚本已逐级拒绝 reparse、检查物理 containment、使用唯一 staging，并在发布/删除前复查，但未持有目录句柄锁。
