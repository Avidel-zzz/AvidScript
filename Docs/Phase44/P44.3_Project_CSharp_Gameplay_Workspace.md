# Phase 44.3：项目 C# Gameplay Workspace 使用说明

## 1. 本阶段已经打通的闭环

P44.3 已经验证以下正式链路，而不是测试专用旁路：

1. Editor 创建项目级 C# workspace；
2. 从 workspace profile 启动正式 Roslyn Frontend、Semantic、Guest IR 与 WASM Backend；
3. 从 115 项 gameplay 授权包中自动切出脚本实际可达的 3 项 runtime binding；
4. `ComponentBindingService` 把 build report 应用到目标 Actor；
5. `UAvidScriptComponent` 在 UE 世界生命周期中加载 WAMR；
6. C# `BeginPlay` 修改 Actor 缩放；
7. C# `Tick` 读取 `FRotator`、计算新 yaw，并写回 Actor；
8. 同一份脚本分别通过 cold build 与 semantic-cache warm build 验收。

当前已经可以用 C# 编写一个最小但真实可运行的 Actor 游戏逻辑脚本。

## 2. 默认目录

首次执行创建命令后，项目文件位于：

```text
<Project>/Scripts/AvidScript/
├── GameplayScript.cs
├── AvidScript.Gameplay.csproj
├── default.csharp-profile.json
└── global.json
```

生成内容与用户源码分开：

```text
<Project>/Intermediate/AvidScript/CSharpWorkspace/
├── AvidScript.Bindings.generated.cs
└── BindingPackages/

<Project>/Saved/AvidScriptCSharpGuest/ProjectGameplay/
├── project_gameplay.csharp.report.json
├── project_gameplay.avidscript.json
├── project_gameplay.wasm
└── runtime binding package
```

所有 `Scripts/AvidScript` 文件默认采用 create-only 规则。再次刷新 workspace 不会覆盖已经修改的游戏脚本、项目文件或 profile；generated facade 可以安全刷新。

## 3. Editor 使用流程

1. 在 UE Editor 主菜单打开 `Tools > AvidScript`。
2. 执行 `Create Project C# Gameplay Workspace`。
3. 在 IDE 中打开 `<Project>/Scripts/AvidScript/AvidScript.Gameplay.csproj`。
4. 编辑 `GameplayScript.cs`。
5. 在关卡中选择一个带可移动 RootComponent 的 Actor。
6. 执行 `Build And Bind Project C# Gameplay Script`。
7. 启动或保持游戏世界运行，观察 Actor 的 `BeginPlay` 与 `Tick` 行为。

Build/Bind 命令会先以 create-only 方式刷新 workspace，再复用正式 profile Build/Bind pipeline，不会在菜单层复制编译或绑定逻辑。

## 4. 完整 starter 脚本

```csharp
using System.Runtime.InteropServices;

namespace AvidScript;

public static class GameplayScript
{
    private const float RotationSpeedDegreesPerSecond = 90.0f;

    public static int Main() => 0;

    [UnmanagedCallersOnly(EntryPoint = "avid_on_begin_play")]
    public static void BeginPlay()
    {
        UE.Self.SetActorScale3D(new FVector(1.0f, 1.0f, 1.0f));
    }

    [UnmanagedCallersOnly(EntryPoint = "avid_on_tick")]
    public static void Tick(float deltaSeconds)
    {
        FRotator rotation = UE.Self.GetActorRotation();
        UE.Self.SetActorRotation(
            new FRotator(
                rotation.Pitch,
                rotation.Yaw + RotationSpeedDegreesPerSecond * deltaSeconds,
                rotation.Roll),
            false);
    }

    [UnmanagedCallersOnly(EntryPoint = "avid_on_timer")]
    public static void OnTimer(int callbackId, int timerHandle)
    {
    }

    [UnmanagedCallersOnly(EntryPoint = "avid_on_event")]
    public static void OnEvent(int eventId, float value)
    {
    }

    [UnmanagedCallersOnly(EntryPoint = "avid_on_gameplay_event")]
    public static void OnGameplayEvent(
        int eventType,
        int primaryId,
        int secondaryId,
        int objectSlot,
        int objectGeneration,
        float x,
        float y,
        float z)
    {
    }

    [UnmanagedCallersOnly(EntryPoint = "avid_on_end_play")]
    public static void EndPlay()
    {
    }
}
```

这里的 `UE.Self` 是当前 `UAvidScriptComponent` 所属 Actor 的 typed handle facade。`FVector`、`FRotator`、`AActor.GetActorRotation`、`AActor.SetActorRotation` 和 `AActor.SetActorScale3D` 都来自 reflection binding generator，并非手写测试 API。

| Guest IR | 2 | 2 |

行为断言：

- Actor 初始缩放为 `(2,2,2)`，C# `BeginPlay` 后为 `(1,1,1)`；

- warm 产物重新经过 Guest IR、WASM、runtime slice 和 WAMR 验收。

## 6. 本阶段修复的通用问题

### 6.1 运行中 Build/Bind 的注册顺序

运行中的 world 会在 `RegisterComponent()` 时立即触发组件 `BeginPlay`。绑定服务现在保证：

```text
创建 Component -> 写入 manifest path -> 注册 Component
```

因此新组件第一次 `BeginPlay` 就加载目标 C# WASM，不会误加载默认 embedded smoke。

### 6.2 C# const 字段 lowering

Roslyn semantic artifact 已经为 `const` 字段引用提供 typed constant。Guest IR 现在直接内联该常量，不再从零初始化的 mutable global 读取。starter 中的 `90.0f` 因此能正确参与 Tick 计算。

## 7. 常见问题

### 没有生成 workspace

检查插件 `Templates/CSharp/ProjectWorkspace` 是否完整，然后重新执行创建命令。已有用户文件会被保留。

### Build/Bind 提示没有目标 Actor

在关卡中选择一个 Actor 后重试。命令只绑定当前选中的 Actor。

### 构建失败

先查看 ResultPresenter 中的 `Category`、`Message`、`Next action`、source、profile、report 和 pipeline invocation counts。不要直接编辑 generated facade 或 runtime package。

### 修改脚本后运行中的旧 Component 没有切换

P44.3 保证新绑定 Component 的正确首次加载。对已经运行的 Component 执行事务式 reload、失败保留旧实例和成功后切换新实例属于 P44.4。

## 8. 当前限制

- 当前正式验证目标是 UE5.8 Win64 Editor/PC；
- C# 由 Roslyn 解析并编译到 AvidScript Guest IR/WASM，不在游戏中托管 CoreCLR；
- gameplay profile 当前自动发现并接受 115 项 UE reflection binding，还不是完整 UE API；
- Android/iOS、Shipping packaging、调试器、断点与完整 IDE 诊断仍在后续阶段；
- `.avid` 语言前端暂不在当前交付路径中，现阶段以 C#+WASM 为主。

下一阶段 P44.4 将补齐已运行 Component 的事务式 Live Reload，使编辑、构建、切换与失败回滚形成更接近 Puerts/UnLua 的持续开发循环。
