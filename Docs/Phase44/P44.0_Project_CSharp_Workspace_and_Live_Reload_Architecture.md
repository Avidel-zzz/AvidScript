# P44.0 项目 C# Workspace 与事务式 Live Reload 架构

> 状态：已批准进入实施。批准依据为用户对本十小时窗口的自主规划与持续执行授权。

## 1. 背景

P43.5 已完成 C# source 到 Roslyn Frontend、Semantic、Guest IR、WASM、最小 runtime binding package、`UAvidScriptComponent` 生命周期和内容寻址缓存的完整闭环。当前主要障碍不再是“能否运行”，而是项目作者仍需自己拼出 source、`.csproj`、profile 和 generated facade 的关系，默认 profile 还指向插件样例而不是项目代码。

成熟脚本框架需要让游戏代码属于游戏项目，让生成文件属于 Intermediate，让最终 artifact 属于 Saved；三者不能混在插件源码或同一个目录里。构建成功后，运行中的组件还应能事务式接纳新模块，失败时继续运行旧模块。

## 2. 本阶段目标

P44 交付一个可直接使用的项目 C# 游戏脚本工作流：

1. 在 `<Project>/Scripts/AvidScript` 创建项目拥有的 C# source、`.csproj`、`global.json` 和 profile。
2. 在 `<Project>/Intermediate/AvidScript/CSharpWorkspace` 刷新 IDE 使用的完整 generated UE facade。
3. 在 `<Project>/Saved/AvidScriptCSharpGuest/ProjectGameplay` 发布 report、manifest 和 WASM。
4. Editor 菜单可一键创建 workspace，再对选中 Actor 执行 Build And Bind。
5. 默认 `GameplayScript.cs` 实现真实 `BeginPlay/Tick/EndPlay`，使用 generated `AActor`、`FRotator` 和 `FVector` API。
6. 已运行的 `UAvidScriptComponent` 可从同一 manifest path 事务式 reload；候选失败时旧 runtime、旧 manifest binding 和 Tick 保持有效。

## 3. 方案比较

### 方案 A：项目 Workspace + Component Reload

新增小型 Editor workspace service，复用 BindingEmitter、ProfileService、BuildService 和 ComponentBindingService。优点是能在当前 ABI 上直接交付游戏代码，文件所有权清楚，风险集中；缺点是生命周期方法仍需要显式 export attribute。

### 方案 B：UE DataAsset 与 Slate 面板优先

把 profile 做成 `UDataAsset`，提供文件选择器、详情面板和最近使用记录。优点是 UE 原生体验更好；缺点是会提前引入 UHT、资产迁移和 Cook 语义，而底层项目代码/IDE/reload 闭环仍未解决。

### 方案 C：编译器合成生命周期

允许用户继承 `AvidScriptBehaviour` 或使用 attribute，由编译器生成 ABI exports。优点是 C# 表面最现代；缺点是同时改变语义入口、符号映射、Guest IR 和调试契约，不适合作为 P43.5 后的第一个可用性阶段。

本阶段采用方案 A。方案 B 在 workspace/profile contract 稳定后接入；方案 C 在调试信息与多脚本模块模型明确后单独设计。

## 4. 文件所有权

| 根目录 | 所有者 | 内容 | Git 建议 |
| --- | --- | --- | --- |
| `Scripts/AvidScript` | 游戏项目 | `GameplayScript.cs`、`.csproj`、profile、`global.json` | 应纳入项目版本管理 |
| `Intermediate/AvidScript/CSharpWorkspace` | AvidScript Editor | generated facade | 禁止提交 |
| `Saved/AvidScriptCSharpGuest/ProjectGameplay` | Build pipeline | WASM、report、manifest | 禁止提交 |
| `Saved/AvidScript/CSharpSemanticCache/v1` | Semantic Cache | immutable semantic entries | 禁止提交 |
| `Plugins/AvidScript/Templates/CSharp/ProjectWorkspace` | 插件 | 默认 workspace 模板 | 纳入插件 Git |

Editor 不把 generated facade 写进项目 source，也不把用户脚本写进插件。用户文件默认 create-only；除非显式 `bOverwriteUserFiles=true`，重复创建只刷新 Intermediate facade，不覆盖 source、project、profile 或 `global.json`。

## 5. Workspace Service

新增 `FAvidScriptEditorCSharpWorkspaceService`，只负责 workspace 物化，不拥有构建或绑定：

```cpp
struct FAvidScriptEditorCSharpWorkspaceConfig
{
    FString WorkspaceRoot;
    bool bOverwriteUserFiles = false;
};

struct FAvidScriptEditorCSharpWorkspaceResult
{
    bool bSucceeded = false;
    bool bCreatedSource = false;
    bool bCreatedProject = false;
    bool bCreatedProfile = false;
    bool bCreatedGlobalJson = false;
    bool bRefreshedGeneratedFacade = false;
    FString WorkspaceRoot;
    FString SourcePath;
    FString ProjectPath;
    FString ProfilePath;
    FString GeneratedFacadePath;
    FString ErrorCategory;
    FString ErrorMessage;
    FString NextAction;
};
```

核心接口：

```cpp
static FString GetDefaultWorkspaceRoot();
static FString GetDefaultProfilePath();
static bool CreateOrRefresh(
    const FAvidScriptEditorCSharpWorkspaceConfig& Config,
    FAvidScriptEditorCSharpWorkspaceResult& OutResult);
```

Service 调用 `FAvidScriptEditorCSharpBindingEmitter::PublishEngineGameplay` 获取经过验证的完整 facade，只复制 emitter 返回的 immutable reference source。Service 不解析 reflection descriptor，不重新生成 bindings，也不调用 BuildProfile。

## 6. Workspace 内容

### GameplayScript.cs

默认脚本是可运行的旋转 Actor 行为：

```csharp
using System.Runtime.InteropServices;

namespace AvidScript;

public static class GameplayScript
{
    private static float YawDegreesPerSecond = 90.0f;

    [UnmanagedCallersOnly(EntryPoint = "avid_on_begin_play")]
    public static void BeginPlay()
    {
        UE.Self.SetActorScale3D(new FVector(1.0f, 1.0f, 1.0f));
    }

    [UnmanagedCallersOnly(EntryPoint = "avid_on_tick")]
    public static void Tick(float deltaSeconds)
    {
        FRotator rotation = UE.Self.GetActorRotation();
        UE.Self.SetActorRotation(
            rotation + new FRotator(0.0f, YawDegreesPerSecond * deltaSeconds, 0.0f),
            false);
    }
}
```

正式模板还包含必需的 `EndPlay/OnTimer/OnEvent/OnGameplayEvent` exports。空 callback 不产生 generated UE imports。

### AvidScript.Gameplay.csproj

项目使用 `net8.0`、`Library`、nullable 和禁用 implicit usings。它通过相对路径把 Intermediate facade 链接为 `Generated/AvidScript.Bindings.generated.cs`，使 Rider/Visual Studio 的类型检查与正式构建使用同一份 generated API 表面。

### Profile

profile 继续使用 schema 1，避免无必要迁移。字段只引用项目相对 source/project 和 Saved output；authorization package 留空，由 BuildService 自动发布完整 gameplay ceiling 并在 final 生成最小 runtime slice。

## 7. Editor 入口

增加两个 Tools 菜单命令：

- `Create Project C# Gameplay Workspace`：create-only 写用户文件并刷新 facade。
- `Build And Bind Project C# Gameplay Script`：加载 workspace profile，执行 BuildProfile，将 report 绑定到选中 Actor。

保留既有 `Create Default C# Profile` 和 `Build And Bind C# Profile Script`，不破坏已有 Saved profile。新入口使用 project workspace profile，是推荐路径。

ResultPresenter 显示 source、profile、manifest、cache lookup 和五类工具调用次数。错误继续使用稳定 `ErrorCategory/ErrorMessage/NextAction`，不在菜单 handler 重建错误语义。

## 8. 事务式 Component Reload

`UAvidScriptComponent` 新增 C++ rich result API 与 Blueprint 简化入口：

```cpp
bool ReloadConfiguredScript(FAvidScriptWasmReloadResult& OutResult);

UFUNCTION(BlueprintCallable, Category = "AvidScript|Runtime")
bool ReloadScript();
```

运行中 reload 流程：

1. 重新读取并验证当前 manifest、WASM 和 runtime binding package。
2. 使用现有 `FAvidScriptRuntimeSession::ReloadModule` 构造候选 runtime。
3. 候选完成 load、required export/import 验证和 `BeginPlay` 后才替换旧 runtime。
4. 失败时保留旧 runtime、scheduler、timer/event router 和 Tick enable 状态。
5. 成功时更新 module、metrics、reload counts 和错误状态。

ComponentBindingService 在 live component 上应用新 manifest 时保存旧 path。reload 失败则恢复旧 path，并返回 `reload_rejected`；非 live component 仍只更新绑定，等待下一次 BeginPlay。

本阶段 reload 重置 guest 静态状态，并重新调用候选 `BeginPlay`。状态迁移、managed heap snapshot 和 coroutine continuation 不在本阶段伪装实现。

## 9. 失败语义

Workspace 稳定类别：

- `workspace_root_invalid`
- `workspace_template_missing`
- `workspace_directory_failed`
- `workspace_file_write_failed`
- `workspace_binding_publish_failed`
- `workspace_facade_refresh_failed`

Live reload 稳定类别复用 manifest/runtime 诊断，并由 binding service 增加 `reload_rejected`。任何失败都不得删除或改写用户已有 source；live reload 失败不得卸载旧 runtime。

## 10. 验证标准

完成条件：

- workspace create-only 和显式 overwrite 行为可重复验证；
- generated facade 来自完整 gameplay package，IDE project 可解析 starter 使用的类型和方法；
- workspace profile 通过正式 BuildProfile 冷/热构建；
- starter WASM 绑定到 Actor 后，BeginPlay 设置 scale，Tick 改变 yaw；
- 成功 reload 切换行为，失败 reload 保持旧模块继续 Tick；
- Runtime manifest 不依赖 Intermediate facade；
- UE5.8 增量编译、focused automation 与完整 AvidScript automation 全绿；
- 不清理 Editor Target，面向团队的文档使用中文。
