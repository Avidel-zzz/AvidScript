# P66.B：异步闭包的作用域与执行

## 要解决的行为

受支持的静态异步入口现在可以直接创建捕获闭包。下面的片段说明循环与等待如何组合；完整可执行测试见下文：

```csharp
for (int i = 0; i < 3; ++i)
{
    int copy = i;
    Func<int> read = () => i + copy;
    await AvidContinuations.NextTickAsync();
    copy += 10;
}
```

`i` 在整个 for 循环中使用同一个捕获位置；`copy` 每次进入循环体都会获得新位置。等待结束后，`read` 和当前方法必须继续访问本轮的同一个 `copy`，不能重新分配，也不能把一份旧值覆盖回共享位置。离开循环体后，仍被其他委托引用的旧环境应继续存活，没有引用的环境才能回收。

## 实现

Semantic 升级为 **27/1.31**，保留 **26/1.30** 等既有读取路径。`SemanticAsyncMethod.LexicalScopes` 记录作用域身份、源码位置、实际所属 segment 和进入边：

| 种类 | 新环境的创建时机 |
| --- | --- |
| activation | 首次进入方法 |
| for_entry | 首次进入该 for 语句，包括初始化之前 |
| block_entry | 每次从外部进入该代码块 |
| foreach_iteration | 条件通过后、给本轮迭代变量赋值之前 |

[控制流投影](../../Tools/AvidScript.CSharpSemantic/Analysis/SemanticAsyncControlFlowProjector.cs)在构建 segment 时记录成员集合。它不依赖“源码范围相近”或连续编号猜测作用域：foreach 的条件、递增、取元素可能共享头部源码位置，但只有本轮变量绑定与循环体属于 iteration 环境。不可达 segment 在发布前剔除；不可达作用域保留空成员、空进入边和原有身份，避免悬空的捕获分析引用。

含 lambda 或局部函数的 async 统一进入可恢复 CFG。`null` 来源的进入边只表示初次调用；从 await segment 到后继 segment 的边仍然存在，只有跨越作用域边界才构成新进入。同一作用域内的恢复不会再次分配。同步闭包仍使用已有 Roslyn lifetime region；async 环境不复用同步 block ordinal。

[验证器](../../Tools/AvidScript.CSharpSemantic/Validation/SemanticAsyncScopeValidator.cs)检查版本、身份、数量上限、成员排序与唯一性、有效目标、唯一完整 activation，以及从实际 CFG 重新算出的精确进入边。异步捕获环境必须对应同身份、同源码位置的作用域；空、重复、越界、丢失或旧版本夹带的新元数据均拒绝。Guest 在生成代码前消费这项验证；具有完整可恢复作用域合同的环境才能执行，旧版缺少此合同的异步捕获仍拒绝执行。

## 环境分配与状态恢复

例如，在生命周期脚本的静态 `BeginPlay` 内编写以下代码，最终 `Result` 为 **1616**：

```csharp
int value = 5;
Func<int> increment = () => ++value;
Func<int> read = () => value;
await AvidContinuations.DelayAsync(0.01f);
value += 10;
increment();
await AvidContinuations.NextTickAsync();
Result = read() * 100 + value;
```

两个委托和当前方法读写的是同一个 `value`。第一次恢复后它从 5 变成 16，第二次恢复不会把它还原成挂起前的旧副本。片段沿用生命周期脚本的 `using System`、入口特性和静态 `Result` 字段，不能单独作为完整脚本文件。

[作用域分配](../../Tools/AvidScript.CSharpGuest/Lowering/CSharpAsyncClosureAllocations.cs)在首次调用及同步控制流的进入边创建环境，离开边清除当前局部引用。跨 await 的作用域转换由恢复入口处理，同一作用域内恢复不重新分配；委托仍可保活已离开的旧环境。

[执行状态布局](../../Tools/AvidScript.CSharpGuest/Lowering/CSharpAsyncClosureState.cs)在已验证的 Semantic 文档上推导实际挂起布局，不修改原始文档。捕获变量的值槽替换为当前活动环境的引用，非捕获局部值沿用原有存储。即使值活跃性分析没有留下局部槽，活动环境仍需保留，保证恢复后的捕获赋值有合法位置。恢复先接回环境，再处理作用域转换，最后将被捕获的 await 结果写入共享位置。

生成委托适配函数的步骤移到异步函数生成之后，确保异步体内创建的委托目标也进入模块；值布局与闭包字段使用的引用类型同时纳入类型依赖，避免未调用辅助方法的布局引用缺失。复用 Semantic **27/1.31**、Guest IR **11/1.10** 和已有状态 ABI，没有引入新版本或裸引用入口。
