# P66.B：异步闭包的作用域合同

## 要解决的行为

下面是本组为后续执行接入准备的语义，**当前仍不能把这段捕获闭包直接编译运行**：

```csharp
for (int i = 0; i < 3; ++i)
{
    int copy = i;
    Func<int> read = () => i + copy;
    await AvidContinuations.NextTickAsync();
    copy += 10;
}
```

`i` 在整个 for 循环中使用同一个捕获位置；`copy` 每次进入循环体都会获得新位置。等待结束后，`read` 和当前方法必须继续访问本轮的同一个 `copy`，不能重新分配，也不能把一份旧值覆盖回共享位置。离开循环体后，仍被其他委托引用的旧环境应继续存活，没有引用的环境才能回收。

## 实现

Semantic 升级为 **27/1.31**，保留 **26/1.30** 等既有读取路径。`SemanticAsyncMethod.LexicalScopes` 记录作用域身份、源码位置、实际所属 segment 和进入边：

| 种类 | 新环境的创建时机 |
| --- | --- |
| activation | 首次进入方法 |
| for_entry | 首次进入该 for 语句，包括初始化之前 |
| block_entry | 每次从外部进入该代码块 |
| foreach_iteration | 条件通过后、给本轮迭代变量赋值之前 |

[控制流投影](../../Tools/AvidScript.CSharpSemantic/Analysis/SemanticAsyncControlFlowProjector.cs)在构建 segment 时记录成员集合。它不依赖“源码范围相近”或连续编号猜测作用域：foreach 的条件、递增、取元素可能共享头部源码位置，但只有本轮变量绑定与循环体属于 iteration 环境。不可达 segment 在发布前剔除；不可达作用域保留空成员、空进入边和原有身份，避免悬空的捕获分析引用。

含 lambda 或局部函数的 async 统一进入可恢复 CFG。`null` 来源的进入边只表示初次调用；从 await segment 到后继 segment 的边仍然存在，只有跨越作用域边界才构成新进入。同一作用域内的恢复不会再次分配。同步闭包仍使用已有 Roslyn lifetime region；async 环境不复用同步 block ordinal。

[验证器](../../Tools/AvidScript.CSharpSemantic/Validation/SemanticAsyncScopeValidator.cs)检查版本、身份、数量上限、成员排序与唯一性、有效目标、唯一完整 activation，以及从实际 CFG 重新算出的精确进入边。异步捕获环境必须对应同身份、同源码位置的作用域；空、重复、越界、丢失或旧版本夹带的新元数据均拒绝。Guest 在生成代码前消费这项验证，尚未移除 async-owned closure 的执行拒绝。

## 验证范围

[语义测试](../../Tools/AvidScript.CSharpSemantic.Tests/SemanticAsyncScopeTests.cs)使用真实 C# 源码，按投影后的整数控制流执行分支、循环、continue、break 和 await 边，检查进入次数：activation 一次、for 初始化一次、循环体每轮一次，等待后不重复进入；另覆盖 do-while、foreach 迭代绑定、顶层捕获、确定性、序列化及畸形数据拒绝。这是作用域分配时机的合同证据，不是闭包在 WASM 中执行的证据。

Guest 回归同时检查上一版 26/1.30 的托管异步状态仍可编译，新版缺少作用域时在产物验证阶段拒绝，旧版 async 捕获分析可读取但继续拒绝执行。正式构建入口需通过真实编译器构建及版本/来源篡改测试后交付。

本组最终验证：固定 SDK 8.0.416，Semantic **338/338**（其中作用域 **30/30**）、Guest **429/429**；正式构建合同 **5/5**，结果为工程 `Saved/AvidScript/GuestBuildContracts/b4fdfffdb2e74542828ccb5a6e0d3250/results.json`。Harness audit、文档本地链接及写集 diff 检查通过。架构检查唯一报告为当前写集与既有受保护 header 不同于 Git tree，不作为干净发布 Gate。本组没有修改 UE 原生实现，没有把上一组运行测试作为新闭包执行证据。

## 后续执行接入

1. 为每个作用域进入边生成环境分配，离开边清除当前局部 owner；已逃逸的委托自行保活旧环境。
2. 挂起状态持有当前环境引用；恢复先接回环境，再恢复非捕获局部变量，避免把捕获值快照写回共享 cell。
3. 覆盖多委托共享读写、跨多次 await、循环不同迭代、ref/out、取消及 teardown 的双后端真实执行。

实例 async、持久事件、对象图热重载与托管暂停帧仍为后续工作，P66.B 不标记完成。
