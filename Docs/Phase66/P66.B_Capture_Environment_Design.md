# P66.B：捕获环境与委托设计

## 实现顺序与边界

最新执行进展见 [C# 共享与逃逸闭包执行](P66.B_CSharp_Closure_Execution.md)。下文按合同演进记录历史设计：原先的 Guest 拒绝边界已对受支持的同步闭包开放，持久回调、跨 await、实例和完整引用语义仍需后续实现。

P66.B 的完整目标仍包括捕获局部函数、lambda、方法组、可逃逸委托、共享环境、event，以及 reload/teardown 后有效性。本批次尚未完成。先实现直接调用的同步局部函数捕获，后续在同一语义基础上引入堆环境和委托生命周期，不能用直接调用替代逃逸闭包目标。

## 直接调用的捕获规范化

Roslyn 仍负责绑定、作用域、确定赋值与非法 ref/struct 捕获诊断。Semantic 在原始方法/CFG 投影后、可达性分析前做一次词法捕获规范化：

1. 记录局部函数直接引用的外层局部变量、参数与实例接收者；常量无需捕获。
2. 对局部函数调用图求固定点，补充只通过被调用函数使用的传递捕获。每个调用帧自己声明的变量不成为该函数的外部捕获。
3. 变量按稳定身份排序，变为显式隐藏 `ref` 参数；实例接收者按值传递身份。局部函数改为无隐式接收者的 callable。
4. 重写函数体和 CFG 的捕获读写与调用实参，保留 Roslyn 选出的调用目标及源位置。同一变量始终取同一存储地址，不做 copy-in/copy-out，不产生新的 Host import。
5. 受控 async 的语句、条件、await 实参和取消参数执行同样的重写，然后重新计算存活变量与 state frame。跨 await 保存值，禁止保存已退出调用帧的栈地址。

规范化后的产物仍是现有 callable、parameter-reference、argument、CFG 与 ref 参数合同；不增加 opcode、Runtime ABI 或 serialized schema 字段。工具源码指纹必须使缓存失效。未来逃逸委托引入环境对象或新 IR 时须显式版本化。

## 验证

真实 WASM 执行验证：两个局部函数共享读写、递归/嵌套传递捕获、捕获外层参数、显式 ref 参数与捕获别名、调用中再进入兄弟函数、循环与分支作用域。静态函数和不捕获的非静态局部函数不生成环境参数。

async 要验证捕获仅在 await 后间接使用时仍被保存，不能只做语法通过检查；非法捕获、委托逃逸等未实现路径继续明确拒绝。UE 生命周期、热重载、堆环境和完整调试仍是后续集成验收，不能由独立 WASM 测试替代。

## 共享与逃逸环境合同（Semantic 22/1.26）

Semantic 已增加 `closure_environments` 与 `closure_bindings`。这些是后续环境 lowering 的输入，不代表堆或逃逸执行已经可用。由方法引用确定潜在逃逸目标，不尝试证明一个立即调用的 lambda 不会逃逸；只被直接调用的局部函数保留现有 `ref` 路径，不生成堆环境。

捕获图固定点计算之后，对潜在逃逸目标需要的变量取并集。原始变量身份对应唯一 cell；同一变量的直接局部函数读写、多个委托和传递捕获必须绑定同一个 cell。绑定记录保留哪些 callable 作为委托目标，哪些只是访问共享 cell 的直接被调函数。

环境按变量的分配作用域合并：

| ScopeKind | 创建时机 | 语义 |
| --- | --- | --- |
| `activation` | 每次调用 owner | 参数、接收者和函数顶层局部变量共享该次激活的环境 |
| `block_entry` | 每次进入声明块 | 循环体内的局部变量每次重新进入块时获得新 cell |
| `for_entry` | 每次进入整个 for | 初始化器变量在该循环的各次迭代间共享 |
| `foreach_iteration` | 每次 foreach 迭代 | 迭代变量每次获得新 cell |

环境 ID 使用词法 owner、作用域种类和同类节点序号。同名兄弟块不合并。cell 沿用现有符号 ID（局部变量 ID 仍包含源码位置），因此这些 ID 不承诺结构热重载或存档稳定性。out/pattern designation、catch 等未实现的逃逸分配作用域返回 `ASCS4004`，不输出部分环境计划。常量不产生 cell，非法 ref 捕获由 Roslyn 拒绝。

Validator 校验 owner、cell 类型与身份、绑定覆盖、隐藏捕获参数及旧 Schema 边界。Guest 当前明确拒绝需要环境分配的产物，不能忽略计划并退回栈地址。21/1.24 静态方法组与 21/1.25 无捕获 lambda 的既有读取能力保留。

## 控制流分配合同（Semantic 23/1.27）

同步环境已新增 `allocation`：包含 Roslyn local lifetime region 的 inclusive block 范围与完整的外部进入边；activation 使用 source=null 的函数入口。必须在进入边上创建环境，不能在区域内部循环回边重复初始化。变量的首次赋值和 delegate 创建都不替代作用域入口。旧 22/1.26 产物不能携带该新字段内容。

同步捕获 lambda 已保留正常 CFG，Guest 仍拒绝未连接的环境执行。async owner 的分配合同暂为空；同步 foreach 迭代范围已有分析，但异常清理 CFG 仍使其不可执行。详见 [作用域分配结果](P66.B_Closure_Allocation_Results.md)。

## 后续堆与生命周期必须遵守的约束

1. owner 对被提升变量的读写、直接局部函数的 `ref` 别名及委托调用都访问同一 cell。初始化仅在对应作用域进入时发生；创建第二个委托不能再次复制或初始化捕获值。嵌套环境引用外层已有环境，不能扁平复制外层变量。
2. 环境和委托是可形成环的对象图，例如 `self = () => self()`。下一组采用可追踪根与对象边的回收模型，不能以纯引用计数或永久保留至 Session 结束代替长期运行所需的回收。对象数、总字节、追踪工作量必须有界；分配失败要有明确诊断。
3. 根集合包含活动调用帧、实参与返回暂存、持久化状态、挂起 continuation、排队回调与已注册事件。回调重入时旧帧仍是根；trap/取消必须由 invocation owner 清理帧根。跨 await 保存环境身份，不能序列化原始栈地址或重新复制共享 cell。
4. 所有环境归属 Session 和模块代际。无效 token、错误环境类型、过时代际和错误目标签名均拒绝；UObject 接收者继续通过 ObjectHandle 的有效性检查访问。不能把 WASM 函数表槽当成跨模块稳定 callback 身份。
5. teardown 先阻止新回调进入，再幂等取消订阅/continuation、释放根及环境。reload 候选失败保留旧环境；提交成功后才原子切换代际并清理旧根。当前不承诺活动闭包结构迁移，后续必须明确选择取消旧闭包或验证可迁移布局。

上述运行时行为仍需实现及真实执行、回收压力、重入、reload 回滚、World/Object teardown 验收。本次环境分析与合同测试只提供其编译器输入，P66.B 不标记完成。
