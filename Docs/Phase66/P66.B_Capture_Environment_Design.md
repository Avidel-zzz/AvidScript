# P66.B：捕获环境与委托设计

## 实现顺序与边界

P66.B 的完整目标仍包括捕获局部函数、lambda、方法组、可逃逸委托、共享环境、event，以及 reload/teardown 后有效性。本批次尚未完成。先实现直接调用的同步局部函数捕获，后续在同一语义基础上引入堆环境和委托生命周期，不能用直接调用替代逃逸闭包目标。

## 直接调用的捕获规范化

Roslyn 仍负责绑定、作用域、确定赋值与非法 ref/struct 捕获诊断。Semantic 在原始方法/CFG 投影后、可达性分析前做一次词法捕获规范化：

1. 记录局部函数直接引用的外层局部变量、参数与实例接收者；常量无需捕获。
2. 对局部函数调用图求固定点，补充只通过被调用函数使用的传递捕获。每个调用帧自己声明的变量不成为该函数的外部捕获。
3. 变量按稳定身份排序，变为显式隐藏 `ref` 参数；实例接收者按值传递身份。局部函数改为无隐式接收者的 callable。
4. 重写函数体和 CFG 的捕获读写与调用实参，保留 Roslyn 选出的调用目标及源位置。同一变量始终取同一存储地址，不做 copy-in/copy-out，不产生新的 Host import。
5. 受控 async 的语句、条件、await 实参和取消参数执行同样的重写，然后重新计算存活变量与 state frame。跨 await 保存值，禁止保存已退出调用帧的栈地址。

规范化后的产物仍是现有 callable、parameter-reference、argument、CFG 与 ref 参数合同；不增加 opcode、Runtime ABI 或 serialized schema 字段。工具源码指纹必须使缓存失效。未来逃逸委托引入环境对象或新 IR 时须显式版本化。

## 验证

真实 WASM 执行验证：两个局部函数共享读写、递归/嵌套传递捕获、捕获外层参数、显式 ref 参数与捕获别名、调用中再进入兄弟函数、循环与分支作用域。静态函数和不捕获的非静态局部函数不生成环境参数。

async 要验证捕获仅在 await 后间接使用时仍被保存，不能只做语法通过检查；非法捕获、委托逃逸等未实现路径继续明确拒绝。UE 生命周期、热重载、堆环境和完整调试仍是后续集成验收，不能由独立 WASM 测试替代。
