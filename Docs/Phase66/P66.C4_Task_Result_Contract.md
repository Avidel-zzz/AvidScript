# P66.C4：可等待的任务结果

这段代码现在可以编译为可执行 WASM。[CSharpAsyncCfgLowerer](../../Tools/AvidScript.CSharpGuest/Lowering/CSharpAsyncCfgLowerer.cs)为 `Task<int>` 方法创建任务并返回受控 token；[CSharpTaskAwaitLowerer](../../Tools/AvidScript.CSharpGuest/Lowering/CSharpTaskAwaitLowerer.cs)处理立即读取、挂起、保存 token 和恢复后的结果读取。它只覆盖上述受限直接调用，尚未实现本合同的所有终态。

## 身份与状态

每次调用 `async Task` / `async Task<T>` 创建独立任务。任务身份由执行域、owner Session、Session 代次、任务槽、槽代次与代码代次共同约束；Guest 只持有受控句柄或托管引用，不持有 Runtime 指针。同步前缀在调用时执行；无等待的方法可以在返回任务句柄前完成。一个任务只能终结一次：`Running` → `Succeeded(value)`、`Faulted(language error)` 或 `Cancelled`。重复完成、晚到完成和代次不匹配都拒绝，不改变已发布结果。

`Task<T>` 的值使用当前封闭 `T` 的 Guest 类型与数据布局；有托管引用的值和语言错误对象在任务终态可被读取期间保持根。读取结果不得消费任务本身：两个等待者应观察同一个终态和值，但各自持有自己的 continuation。没有活动句柄或等待者后释放结果和根。现有 [Session continuation result slot](../../Source/AvidScriptRuntime/Private/Continuation/AvidScriptSessionContinuations.h)归属于单个 continuation token，读取后消费，不可直接充当可多次等待的 `Task<T>` 存储。

## 等待与所有权

- `await task` 若已成功，按 `T` 的类型读取结果并继续当前段；若仍运行，登记当前调用的等待者并挂起。完成时按确定顺序排入 owner dispatcher，恢复前重新验证等待者 Session、World、代码代次和对象句柄。
- 被等待任务属于创建它的目标 Session；等待者属于发起 `await` 的 Session。跨对象调用不得把目标任务转移到调用者。任一方退出时只退休其拥有的任务或等待者；有效的另一方不能重入已失效 Session。
- `Faulted` 携带 P66.C3 的语言错误类型、源码令牌与对象根。`await` 在等待者方法内重新进入该语言错误通道，并执行应有的 `catch` / `finally`。Host import 拒绝、VM trap、fuel 或越界仍是不可由脚本捕获的故障。
- 显式取消、Object/World teardown 和模块关闭令该 owner 的待完成任务进入 `Cancelled`，注销生产者与等待者并释放根；完成与取消竞态只有一个终态。成功 reload 退休旧代码任务和旧等待者；候选失败回滚保留旧任务及其身份。不得把旧任务句柄接到新代码的恢复地址。

## 版本与实现边界

Roslyn 只提供 `Task` 语法、类型与控制流。Semantic 必须发布返回结果类型、任务创建点、每个 `await` 的目标身份与恢复边；验证器从 callable 和源码派生的类型关系重算这些字段。Guest IR 承载版本化任务结果与挂起/恢复合同；WASM Host ABI 只传受控 token、状态及规范化值/错误，不传 CLR 对象。任何新字段或导入都要升相应版本，并拒绝旧版产物夹带新任务语义。

首批接收源码定义的非虚直接调用与 `Task` / `Task<T>` 的受支持封闭结果类型；接口、委托和虚调用须先能静态确定目标或通过版本化间接调用合同进入，不以“碰巧只有一个实现”放行。自定义 awaiter、`ValueTask`、`Task.Run`、线程池与任意 BCL Task API 继续在源码位置拒绝。`async void` 的现有入口及 continuation ABI 保持兼容。

## 前一切片：Task 局部声明的直线初始化窗口

上文 Semantic 36/39 的“方法开头连续声明”是最初实现的限制。现在，首次 `await` 前的直线控制流可以穿插普通同步语句：

```csharp
int adjustment = 1;
Task<int> left = LoadScoreAsync(7);
adjustment = adjustment + 1;
Task<int> alias = left;
await AvidContinuations.NextTickAsync();
int score = await alias;
```

这个切片要求全部任务局部变量沿同一无分支路径完成初始化，且每个 owner 至少通向一次 `await`；当时首次挂起后声明与分支绕过初始化仍会被拒绝。独立验证器从入口逐段重算任务声明顺序和生产者/别名来源，允许不改变任务所有权的同步段穿插；状态帧及每条挂起/退出边仍由现有 Guest IR 19/1.18 合同处理。没有新增字段或 Host ABI。

[组合样例](../../Fixtures/Phase66/TaskIntIntegrated.cs)在这个切片把局部计算穿插在三个任务 owner 的声明间，并在跨帧后使用该值。.NET 参考结果为 `253`、清理 `2` 次；固定 SDK Semantic **397/397**、Guest **544/544**、fixture **11/11** 通过。Win64 `AvidScript.Runtime.Continuation.CompiledTaskInt` Automation **1/1** 通过；Wasmtime JIT 与 WAMR Interpreter 各得到 `253`、清理 `2` 次、恢复 `7` 次，测试还覆盖取消/teardown 和最终引用释放。日志：`Saved/Logs/AvidScript_TaskInterleaved_20260925T011559295Z.log`。本切片未改原生代码，因此未重跑 no-clean UBT。

## 当前切片：按控制流跟踪 Task 局部所有权

任务可在前一次 `await` 恢复后创建；分支在创建别名前直接退出也可通过。每个可达段都有入口与出口的任务 owner 集：声明或别名创建增加 owner，挂起时只转移当时已有的 owner，恢复时只重新持有已转移的 owner，退出时只释放实际持有的 owner。`await task` 必须在所有可达路径上已有该 owner；若两条路径以不同的 owner 集汇合，验证器拒绝该源码，不猜测缺失的 token。

await AvidContinuations.NextTickAsync();
