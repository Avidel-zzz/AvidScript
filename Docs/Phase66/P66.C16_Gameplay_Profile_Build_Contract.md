# P66.C16：Gameplay 配置进入正式构建

本节冻结普通构建入口的显式 `-LanguageProfile gameplay-v1`：Semantic / Guest 缓存键、prepared 输入与 worker 请求使用 C# owner 的同一份配置身份。旧入口保持兼容；默认 Editor 流程的切换另行验收。

从插件根调用，替换为自己的源码及 Editor 实际生成的 `package.json` 路径：

```powershell
./Build/BuildCSharpActorLifecycle.ps1 `
  -SourcePath ../../Scripts/Gameplay.cs `
  -BindingPackagePath ../../Saved/Bindings/MyProject/package.json `
  -LanguageProfile gameplay-v1
```

无需另传八个分析开关，缓存和 worker 默认可用。配置与显式参数冲突时拒绝构建。未使用新能力的普通源码保留原字节；使用静态字段时，新配置会启用静态初始化合同，不能要求它与旧模式的全局变量布局相同。

构建脚本不扩展版本号白名单。C# Guest 编译器提供只读 admission：读取实际 Semantic bytes，使用与公开 CLI 相同的完整 lowering 和 validator，返回配置身份、源 / Semantic 哈希、实际 Guest 合同及预期 Guest bytes 哈希。最终构建必须与这些 bytes 一致。Semantic 的 preview 诊断及 `succeeded=false` 保持原样；admission 表示可编译，不能作为运行时验收。

缓存和 prepared 读取重新执行 admission，拒绝缺失、修改或不匹配的配置身份。Semantic cache 只保存 Frontend / Semantic，不保存可执行模块。Guest cache 仍验证所有产物哈希，最终构建继续检查 binding、WASM、debug map 与 state schema。缓存命中省去 Roslyn 和 WASM backend，但仍承担一次 Guest lowering 的验证成本；后续优化必须保留 bytes 一致性。

验证覆盖 cold / warm、源码修改、prepared 重用及配置不匹配、worker 与 CLI fallback 的同源输出；旧入口回归及工具链环境安全检查串行执行。测试使用唯一目录和可证明归属的进程，保留日志，按文件清单清理生成物，不改持久环境变量，不启动 UE / Android / Mac 验收。

在 C16 验证时，生产 facade 只声明 `AvidCancellationToken`，标准 token 的编译器 / 双 VM 证据使用专门的测试 facade；缺少转换声明的真实包会保留 Roslyn 诊断并拒绝发布。[C17](P66.C17_Generated_Cancellation_Token_Contract.md)补齐公开生成器的转换与 await overload，并使用重新生成的真实包验证正式入口。旧包的缺口测试继续保留，默认 Editor 入口切换仍需单独验收。

worker pipe 身份增加可选 project 维度，构建入口按项目隔离。IPC 的同一超时覆盖异步写入和读取，不响应的 peer 不能阻塞同步 flush。初始化失败只回收该次启动的 worker；已存在的其他进程不由此 owner 结束。构建使用单节点和 BelowNormal，不修改持久环境变量。
