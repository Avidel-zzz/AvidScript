# P66.C10：取消异常的 token 身份

## 目标与当前状态

目标是在 C# 捕获取消异常后，通过 `OperationCanceledException.CancellationToken` 得到实际触发取消的 token，
并与调用方原先持有的 token 比较。取消经过 Task 传播、重复 await 和重新抛出后仍须保持身份。
[原始 29 案例](P66.C10_Await_Member_Assignment_Contract.md#同源基准矩阵)的业务源码、.NET 参考行为和完成条件保持不变。

Session 已保存实际取消来源，Task 错误记录和两个 VM 的版本化导入已支持保存、传播和读取身份。
Guest IR 工具与编译器已接入显式 IR 32 传输升级入口；默认编译入口保持原行为。
异步 catch 变量已由 Semantic 52 接入 IR 33 的异常对象绑定，可保存对象别名并进入后续异步状态帧。
v2 取消 writer 已把只读身份快照存入异常对象；原 Task 和 source 释放后，快照随对象继续存活。
标准 token 的 Semantic 53 投影与独立校验已接入显式分析选项。
**标准 C# 取消异常属性尚未接通 WASM 执行，C10 仍在实现中。**
原生 ABI 测试与编译产物测试各自记录，不能算作标准 C# 异常属性验收。

## Session 保存取消来源

`FEntry.CancellationSourceToken` 是等待与 source 之间的可变反向绑定。取消时必须解除绑定，因此它不能同时承担异常身份。
新增的 `CancellationCauseSourceToken` 只记录首次获胜的直接取消，随等待项一起释放，不持有 source 的所有权。

| 触发方式 | 保存的身份 |
| --- | --- |
| 已绑定的 source 调用 Cancel | 该 source 的完整 64 位 token |
| 绑定一个已经取消的 source | 该 source 的完整 64 位 token |
| 直接取消 continuation | `0`，即没有 source 的取消；不能把当时绑定的 source 当作原因 |
| 正常完成、Task 结果传播 | 不生成新的直接取消来源 |
| 已排队取消之后再次取消或绑定 | 拒绝，保留首次结果 |

source 在回调派发前 Release，或槽位被另一个 source 复用，都不改变已记录的身份。
读取旧身份不会复活 source，不增加 source 引用，也不授权访问复用后的槽位。

`IAvidScriptContinuationHost::ReadCancellationCause(ContinuationToken, OutSourceToken)` 的合同：

- 只在 Game Thread、当前 activation、正确 Session/lane、对象和 World 仍有效时读取。
- continuation 必须通过 token 类型、槽位和 generation 检查，并处于直接取消回调的派发期间。
- 成功返回 `true`。`OutSourceToken == 0` 表示无 source 的取消，与读取失败不同。
- 失败返回 `false`，同时把输出清零。普通等待、尚未派发、正常派发和已经结束的等待均不可读取。
- 重复读取不消费保存状态，不改变完成顺序，也不增加对象、source 或 Task 的所有权。
- Prepared 回滚只清理候选；成功发布保留候选的身份并使旧 activation 失效。teardown 后不能继续读取。
- 未实现该方法的旧原生 Host 默认返回失败。既有 Guest Schema、WASM ABI 和 v1 取消 import 保持原行为。

World 有效性同时排除 `HasEverBeenInitialized() && !IsInitialized()`：UE 的 `DestroyWorld`
经 `CleanupWorld` 清除初始化状态，但不一定设置 `bIsTearingDown` 或立刻执行 GC。
已初始化 World 的这个清理间隙也必须拒绝查询、创建等待和派发回调，因此修复共享 lane 检查。
初次 World 初始化之前的原生 Task 建立仍遵守既有合同；不能把“尚未初始化”与“已经清理”混为一类。

实现位于 [Session continuations](../../Source/AvidScriptRuntime/Private/Continuation/AvidScriptSessionContinuations.cpp)
与 [Host 接口](../../Source/AvidScriptRuntime/Public/AvidScriptContinuation.h)。

## 取消身份的数据与 C# 接入

### 1. 版本化错误数据

为语言错误增加显式取消身份，不复用现在表示源码位置的 `SourceToken`。源码位置和取消 source 是不同合同。
新数据必须由 Semantic、Guest IR、独立 validator、WASM emitter、Runtime 和两个 VM backend 共同识别；旧版本保持原行为，
不能通过放宽旧版本检查来接收新增字段。

- 挂起后取消：从当前直接取消派发读取已经记录的 cause，不重新执行 `.WithCancellation(...)` 的 token 表达式。
- 预取消即时路径：使用已经求值的 token，并验证它确实来自当前可访问的已取消 source。
- 不能让 Guest 任意提交一个整数来冒充取消来源；新增 import/验证必须关联当前派发或经过检查的即时 source。
- Task 保存并传播带身份的错误，重复 await 与 rethrow 复用原身份，不生成新 source。
- 同步错误、普通失败、取消和 owner teardown 保持各自结果，不能把 Cancelled 改成 Faulted 来绕过传播。

#### 原生传输 ABI

原生错误记录增加 `TOptional<int64> CancellationSourceToken`：未设置表示旧接口没有记录来源，
设置为 `0` 表示经过检查的无 source 取消，负数保存完整 source token。该值不持有 source；
错误根仍由 Task 的共享租约持有。普通 Faulted 结果不得带此字段，Task 传播不得丢弃或重算它。

新增导入只接受目录与 provenance 一致的 **Guest IR 32/1.31**。该 envelope 使用 `guest_ir_base`
指定 `24/1.23`、`25/1.24`、`26/1.25`、`29/1.28` 或 `30/1.29`；具有 Task lifetime 的 base
必须使用 `cancellation` 异常模型。它保留直接 await readiness 的 base 规则，并增加取消身份能力。
Runtime 与 Guest IR 工具已支持该版本；编译器通过下述显式升级入口生成，保留原有 Semantic 来源记录。

| 导入 | 签名 | 行为 |
| --- | --- | --- |
| `avid_task_cancel_language_error_v2` | `(task:i64, type:i32, sourceSpan:i32, root:i64, sourceProof:i64) -> i32` | 校验来源后把语言错误存为 Cancelled；成功返回 `1`，失败触发 Host error |
| `avid_task_cancellation_token_v1` | `(task:i64) -> i64` | 返回已记录的完整身份；未知来源、普通失败或无错误 payload 均拒绝，不能以 `0` 冒充成功 |

`sourceProof == 0` 只允许读取当前 Runtime 的直接取消派发，实际 cause 从 Session 取得；
其他值必须是当前 Session/activation 中仍可访问且已经取消的 source。输入既不是要保存的任意整数，
也不是 Guest 自选的 continuation。源码位置、错误类型、Task 类型和当前调用帧的对象根仍按原合同校验。

旧 v1 导入和旧版本不补填身份；其 Task 传播仍保留“未知”。身份读取不新增对象根、不恢复 source，
重复调用无副作用。v2 完成失败不得改变 Task、唤醒 waiter 或泄漏持久根。上述签名必须在两个 VM 中一致。

#### Guest IR 与编译产物

[CSharpCancellationIdentityCompiler](../../Tools/AvidScript.CSharpGuest/Lowering/CSharpCancellationIdentityCompiler.cs)
提供 `TryUpgrade(input, out module, out error)`。输入必须是已通过独立校验的 C# 取消模块：
原始执行版本为 24、25、26、29、30，或以其中一个版本为 base 的 IR 31。
它先验证输入，再替换 v1 writer、添加身份 reader，最后独立验证 IR 32；失败时不返回部分产物。
对已经有效的 IR 32 重复调用不改变内容。

- `cancellation_identity` 显式记录原始执行版本；字段缺失、未知字段、不匹配或未来版本均拒绝。
- 预取消 producer 使用 readiness query 已经求值的 token 寄存器，不重新调用 token 表达式。
- 挂起取消 producer 只在已校验的直接取消 resume 路径提交常量 `0`，由 Runtime 取得真实 cause。
- `ASIR1039` 拒绝未登记的 producer、伪造来源、旧版本冒充、新旧 writer 混用、reader 别名或错误签名。
- 错误根、目录中的类型与源码位置、Task owner、readiness 分支和传播仍执行原有校验；新增参数不放宽这些条件。
- JSON 往返与 WASM 生成保持确定性；WASM provenance 和语言错误目录共同声明 32/1.31 及原始 base。
- 升级不修改输入；旧模块的 JSON 与 WASM 字节保持不变。该入口不增加 C# 语法，也不改变默认构建输出。

同一组编译检查覆盖五种 base，包括 Task 局部所有权、直接 throw、同步异常与静态初始化组合。
求值顺序测试可显式生成 IR 32，再由现有双 VM 执行器执行：

```powershell
pwsh -NoProfile -File Build/TestAvidScriptAwaitReadiness.ps1 -CancellationIdentity
```

此命令使用与 IR 31 相同的 18 份业务源码和 .NET 参考观察值，每个 VM 分别执行正常完成、
初始挂起时 teardown、首次恢复后 teardown，并在挂起与恢复之间执行 GC。
它验证编译生成的 writer 及原控制流；标准异常属性读取仍属于下一节的工作。

### 2. 异步 catch 变量与 token 值

#### 已实现：前端绑定与独立校验

`SemanticAnalyzer.Analyze(..., enableAsyncCatchVariables: true)` 显式启用 **Semantic 52/1.61**。
它要求同步异步异常分析已启用；与静态初始化的组合仍拒绝。没有命名 catch 变量时保留既有版本，
未启用时继续诊断不支持的异步控制流，不改变默认源码接受范围。

Roslyn 的 catch 局部符号对应一个 `async_caught_exception` 定义。类型匹配成功后先初始化变量，
再进入 handler；该定义属于 catch 区域，位于花括号块作用域之前。
状态流分析可识别保存到其他局部变量的异常别名，并将跨后续 await 使用的别名放入状态帧。
这描述的是所需状态，不证明异常对象已经在 Runtime 中保活。

[独立校验器](../../Tools/AvidScript.CSharpSemantic/Validation/SemanticAsyncCatchVariableValidator.cs)
检查变量 owner、类型、源码范围、唯一初始化和 catch 匹配边。绕过初始化、handler 回跳初始化、
匹配失败进入 handler、越界引用变量、缺失/重复绑定以及错误版本都拒绝。
既有异步调用、异常区域和词法作用域校验继续执行，不以新版本绕过它们。

源码合同测试包含未使用变量、兄弟 handler 同名变量、嵌套 protected try/rethrow、
保存别名后再次 await，以及确定性序列化。handler 内 await、过滤器和静态初始化组合仍需后续合同。
前端合同交付时，普通 Guest 编译入口以 `ASCG1027` 拒绝发布，直接语言错误编译入口也不返回部分产物。
后续 IR 33 仅开放完整的语言错误编译路径；普通 lowering 仍不能绕过组合验证，默认编译参数未开放。

#### 异常对象的编译与所有权

`CSharpLanguageErrorCompiler` 将经过校验的 Semantic 52/1.61 编译为 IR 33/1.32，
其中 `exception_values.bindings` 记录所属方法、实际函数、初始化块、错误 Task owner、变量和引用类型。
绑定执行四步：读取 owner → 读取原始托管错误根 → 转为异常引用 → 写入 catch 局部变量。
不构造第二个异常，也不把 Task token 当成异常对象。后续局部别名和状态帧沿用托管引用的保活机制。

IR 33 组合 IR 32 的取消身份传输和 IR 29 的同步/异步异常执行规则。编译器仅在内部校验视图中使用
既有执行合同；最终 IR 保留 Semantic 52 来源，WASM 写入 `guest_ir=33/1.32`、`guest_ir_base=29/1.28`
和 `semantic=52/1.61`。原生加载器检查完整字段与版本对，不接受旧目录冒充或错误 base。

独立校验检查唯一绑定、原始错误根、匹配成功的入口边及保留寄存器；缺失、重复、空字段、错误 owner、
反向匹配边、版本降级和未知序列化成员均被拒绝。同步命名 catch 与异步命名 catch 可以在同一编译单元组合。
这仍不支持 handler 内 await、过滤器、静态初始化组合或标准异常成员读取。

#### 下一步：标准 token 属性

通过 Roslyn 确认标准取消异常属性符号，把异常保存的取消来源转换为编译器定义的 token 逻辑值，用于身份比较。
不拷贝 CLR `CancellationToken` 的物理布局，也不把 Runtime token 当成裸指针。

编译器与生成 facade 必须明确标准类型和 AvidScript source/token 的对应关系。
身份相等不等于重新获得已经 Release 的 source；完整 BCL 注册、Dispose 和取消状态查询语义仍需各自合同与测试，
不能由身份比较通过推导出全部兼容。

handler 退出会释放其 Task owner，而异常对象的其他别名可能继续存活。token 快照已归异常值持有，
不依赖原 Task 或取消 source 仍然存在；标准属性接入时仍须验证释放/复用 source、离开 catch、跨 await/GC 后的源码读取。

#### 对象快照的原生所有权合同

标准属性读取依赖以下对象存储规则；此处不开放新的 Guest import 或改变 Semantic / IR 版本：

- 托管对象可拥有一份 native-only、带类型标识的只读数据。普通对象槽只增加一个指针；
  有快照的对象才分配记录。快照不在 WASM 可写字节中，不保存裸 UObject 指针，不创建 GC root。
- 数据由对象自身释放。GC、代际复用、执行域关闭和未发布回滚均释放记录；
  数据大小计入 `LiveBytes`、`MaxLiveBytes` 和每对象字节上限，另报 native 数据对象数及字节数。
- 准备记录时预留预算，但查询尚不可见。Task 完成成功后原地发布；失败由 move-only guard 回滚。
  guard 不保活对象；调用者在整个发布期间持有原调用帧及 Task 的根租约。
  Session 完成只排队 waiter，不在发布中重入 Guest。
- v2 取消 writer 保存已验证的异常类型 token 与完整 64 位取消源身份。
  再次使用同一异常对象只允许相同类型与相同身份；不能换用另一个已取消 source 覆盖对象。
  Task 传播共享原对象和根租约，不复制快照。已经释放的 source 不会因读取快照而复活。
- 旧 writer 与普通 Faulted Task 仍保留既有 Task 元数据语义：未知取消身份不补为零。
  它们不新建或改写对象的取消快照；同一异常对象已有的身份也不会因被另一个 Task 引用而消失。
- 堆仅提供有界的原生数据所有权，不认识 C# 类型或 Task。取消记录及准入检查属于 Runtime 的 continuation 模块。
  标准 `CancellationToken` 的逻辑表示、属性符号识别、相等运算和新 ABI 由后续版本合同接入，
  不把本批原生所有权测试当作 C# 属性已可用的证据。

#### 标准 token 值合同（Semantic 53 / IR 34）

本节定义完整执行接口。当前已实现语义投影、IR 值合同及 WASM 生成，完整 C# 到 UE 执行尚未通过验收。与异步命名 catch 的目标组合示例：

```csharp
var source = AvidCancellationSource.Create();
CancellationToken token = source.Token;
try
{
    await AvidContinuations.NextTickAsync().WithCancellation(token);
}
catch (OperationCanceledException error)
{
    bool fromSource = error.CancellationToken == token;
}
```

- 新源码采用 Semantic **53/1.62**，仅在显式启用取消 token 值、异步命名 catch 与同步异常组合时发布。
  源码本身不必包含命名 catch 或异步方法；同步 token 参数、返回和比较同样属于该合同。
  后续执行产物采用 Guest IR **34/1.33**，保留 Semantic 53 来源；旧版本不能携带新操作或调用新 reader。
  `cancellation_tokens` 记录精确执行基础：普通值使用 **14/1.13**，同步错误使用 **17/1.16**，
  异步错误使用 **29/1.28**。这是对原先统一 IR 29 方案的修正：纯 token 比较和同步 helper 不应被迫伪造 Task、catch 或异常来源。
  异步路径仍保留原始取消 owner、v2 writer 和 catch 根验证，不以较低版本回避这些要求。
- Roslyn 必须解析到框架中的 `System.Threading.CancellationToken` 和 `System.OperationCanceledException.CancellationToken`。
  同名项目类型、重写/隐藏属性和伪造 facade 转换均不当作内建操作处理。
- 支持标准属性读取、局部赋值/参数/返回、跨 await 保存、`default` / `None` / 无参构造、`==` / `!=` 和 typed `Equals`。
  标准 token 在 Guest 中是独立名义类型，采用编译器规定的 8 字节身份布局，不读取 CLR 私有字段。
- 现有 `AvidCancellationToken` 保持兼容。生成 facade 提供到标准 token 的隐式转换和接收标准 token 的等待重载，
  按原求值顺序复制完整身份；不把任意整数转换为 token，不重新执行 source/token 表达式。
- 属性 reader 从异常对象的 native-only 快照读取身份，不查原 Task 或 source。
  空 receiver 通过正常语言异常路径产生 `NullReferenceException`；失效对象或缺少已证明身份的旧异常拒绝读取，不能返回伪造的 `None`。
- token 身份相等只表示来源相同，不授予访问已释放 source 的权利。
  `Register`、状态查询、带参数的 BCL 构造、任意 .NET 库兼容和静态初始化组合不由此版本推导为已实现。
- 前端投影、独立 Semantic / IR 校验、WASM 版本门禁、两个 VM reader、同源 .NET 对照及原始业务矩阵必须分层留证；
  默认编译入口在这些组合验证完成之前继续关闭。

IR 34 使用唯一标准 token 类型和固定 8 字节 `int64` 身份字段。异常 reader 为
`avidscript.avid_exception_cancellation_token_v1(language_error_root) -> int64`，只允许同步/异步错误基础；
纯值基础不能导入 reader。旧 IR、错误签名、假来源、可疑 reader 别名和错误类型布局均须被独立校验拒绝。
异步基础中的取消 writer 必须使用已有 v2 身份发布合同。`cancellation_tokens` 不替代既有的异常目录、
Task 生命周期、readiness、取消身份或 catch 绑定元数据，各项继续独立检查。

#### Semantic 53 实现与验证

`SemanticAnalyzer.Analyze(..., enableCancellationTokens: true)` 开启新投影，要求同时开启已有的
`enableAsyncCatchVariables`、`enableAsyncSynchronousExceptions` 和取消分析选项。
未开启时保留旧投影；没有标准 token 类型时不升级版本。正式 CLI 与生成 facade 尚未开放该选项。

投影器验证 Roslyn 的框架程序集和真实类型身份，将操作规范化为：

| 操作 | 输入与结果 |
| --- | --- |
| `cancellation_token_none` | 无输入，产生标准 token 零值 |
| `cancellation_token_read` | 取消异常引用 → 标准 token；保留空引用语言异常路由 |
| `cancellation_token_from_avid` | 可信可执行引用中声明的 extern 隐式转换；保留单次操作数求值 |
| `cancellation_token_compare` | 两个标准 token → `bool`，只允许相等与不等 |

独立校验器遍历方法树、普通 CFG、同步异常块及异步 segment，包括 await 的取消参数。
它检查版本配对、名义类型、转换声明、异常继承关系、操作数数量和附加元数据，并拒绝重复类型身份、
伪造 CLR 布局和旧版本中的新操作。普通值流仍使用已有局部变量、参数、返回和异步状态槽表示。
同名源码类型、隐藏属性不采用内建投影；`CanBeCanceled`、`IsCancellationRequested`、带参数构造、
`Equals(object)` 以及继承的 `ToString` / `GetType` 等未支持 API 产生 `ASCS5430`。

新增的异步调用参数用例使用 `int result = await Use(token); return result;`；直接 `return await Use(token)`
