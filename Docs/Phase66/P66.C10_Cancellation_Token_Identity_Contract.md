# P66.C10：取消异常的 token 身份

## 目标与当前状态

目标是在 C# 捕获取消异常后，通过 `OperationCanceledException.CancellationToken` 得到实际触发取消的 token，
并与调用方原先持有的 token 比较。取消经过 Task 传播、重复 await 和重新抛出后仍须保持身份。
[原始 29 案例](P66.C10_Await_Member_Assignment_Contract.md#同源基准矩阵)的业务源码、.NET 参考行为和完成条件保持不变。

当前实现先在 Session 中保留实际取消来源，并提供原生读取接口。**C# 异常属性、异步 catch 变量、Guest payload
和对应版本化 ABI 尚未接入，C10 仍在实现中。** 原生读取接口没有暴露为 WASM import，不能算作 C# API 验收。

## Session 保存取消来源

`FEntry.CancellationSourceToken` 是等待与 source 之间的可变反向绑定。取消时必须解除绑定，因此它不能同时承担异常身份。
新增的 `CancellationCauseSourceToken` 只记录首次获胜的直接取消，随等待项一起释放，不持有 source 的所有权。

| 触发方式 | 保存的身份 |
| --- | --- |
| 已绑定的 source 调用 Cancel | 该 source 的完整 64 位 token |
| 绑定一个已经取消的 source | 该 source 的完整 64 位 token |
| 直接取消 continuation | `0`，即没有 source 的取消；不能把当时绑定的 source 当作原因 |
| 正常完成、Task 结果传播 | 不生成新的直接取消来源 |
| 已排队取消之后再次取消或绑定 | 拒绝，保留首次结果 |

source 在回调派发前 Release，或槽位被另一个 source 复用，都不改变已记录的身份。
读取旧身份不会复活 source，不增加 source 引用，也不授权访问复用后的槽位。

`IAvidScriptContinuationHost::ReadCancellationCause(ContinuationToken, OutSourceToken)` 的合同：

- 只在 Game Thread、当前 activation、正确 Session/lane、对象和 World 仍有效时读取。
- continuation 必须通过 token 类型、槽位和 generation 检查，并处于直接取消回调的派发期间。
- 成功返回 `true`。`OutSourceToken == 0` 表示无 source 的取消，与读取失败不同。
- 失败返回 `false`，同时把输出清零。普通等待、尚未派发、正常派发和已经结束的等待均不可读取。
- 重复读取不消费保存状态，不改变完成顺序，也不增加对象、source 或 Task 的所有权。
- Prepared 回滚只清理候选；成功发布保留候选的身份并使旧 activation 失效。teardown 后不能继续读取。
- 未实现该方法的旧原生 Host 默认返回失败。既有 Guest Schema、WASM ABI 和取消 import 不变。

World 有效性同时排除 `HasEverBeenInitialized() && !IsInitialized()`：UE 的 `DestroyWorld`
经 `CleanupWorld` 清除初始化状态，但不一定设置 `bIsTearingDown` 或立刻执行 GC。
已初始化 World 的这个清理间隙也必须拒绝查询、创建等待和派发回调，因此修复共享 lane 检查。
初次 World 初始化之前的原生 Task 建立仍遵守既有合同；不能把“尚未初始化”与“已经清理”混为一类。

实现位于 [Session continuations](../../Source/AvidScriptRuntime/Private/Continuation/AvidScriptSessionContinuations.cpp)
与 [Host 接口](../../Source/AvidScriptRuntime/Public/AvidScriptContinuation.h)。

## Guest 与 C# 的后续接入

### 1. 版本化错误数据

为语言错误增加显式取消身份，不复用现在表示源码位置的 `SourceToken`。源码位置和取消 source 是不同合同。
新数据必须由 Semantic、Guest IR、独立 validator、WASM emitter、Runtime 和两个 VM backend 共同识别；旧版本保持原行为，
不能通过放宽旧版本检查来接收新增字段。

- 挂起后取消：从当前直接取消派发读取已经记录的 cause，不重新执行 `.WithCancellation(...)` 的 token 表达式。
- 预取消即时路径：使用已经求值的 token，并验证它确实来自当前可访问的已取消 source。
- 不能让 Guest 任意提交一个整数来冒充取消来源；新增 import/验证必须关联当前派发或经过检查的即时 source。
- Task 保存并传播带身份的错误，重复 await 与 rethrow 复用原身份，不生成新 source。
- 同步错误、普通失败、取消和 owner teardown 保持各自结果，不能把 Cancelled 改成 Faulted 来绕过传播。

### 2. 异步 catch 变量与 token 值

通过 Roslyn 确认 catch 变量及属性访问符号，扩展异步异常计划、变量作用域、liveness 与根管理。
支持读取标准取消异常属性，并把结果转换为编译器定义的 token 逻辑值，用于身份比较。
不拷贝 CLR `CancellationToken` 的物理布局，也不把 Runtime token 当成裸指针。

编译器与生成 facade 必须明确标准类型和 AvidScript source/token 的对应关系。
身份相等不等于重新获得已经 Release 的 source；完整 BCL 注册、Dispose 和取消状态查询语义仍需各自合同与测试，
不能由身份比较通过推导出全部兼容。

### 3. 执行与默认入口

保留原始 29 案例，增加 token 专项源码，并对同源 .NET 和 Wasmtime / WAMR 的观察值作比较：

- 挂起取消、预取消、两个 source、token 表达式有副作用、等待期间原 token 变量被改写。
- source Release、槽位复用、重复 await、Task 间传播、嵌套 catch 和 rethrow。
- 挂起时 GC；完成、错误、取消、teardown 后的根、Task owner、waiter 和状态帧归零。
- 真实 Actor/World 销毁、候选回滚、成功 reload，以及同域另一个实例的隔离。
- 缺失或伪造身份、旧 Schema 冒充、错误 token 类型、失效 activation、错误线程等负例。

之后接入正式构建命令，补齐诊断和可运行示例。单独的 Session 测试不替代这组 C# 与双后端验收。
