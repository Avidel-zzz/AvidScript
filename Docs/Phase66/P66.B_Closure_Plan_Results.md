# P66.B 进展：共享与逃逸捕获环境分析

## 实现

新增 `SemanticClosurePlanner`，在原始变量身份尚未被隐藏参数替换前读取词法捕获固定点结果，生成按激活/块/循环分配的环境与 callable 绑定。Semantic Schema 升至 22，Version 升至 1.26；Guest IR 与 WASM ABI 未变化。数据模型、验证器、Guest 输入读取、prepared/cache、脚本类型入口同步版本。

测试证明多个委托与直接局部函数引用同一 cell；`for` 初始化变量、循环体局部变量与 `foreach` 迭代变量分配范围不同；嵌套 lambda、接收者、setter 隐式参数、同名兄弟块和自引用委托保留所需身份。直接调用专用捕获不会产生堆计划。计划序列化往返与重复分析确定性均已检查。

`SemanticClosureContractValidator` 拒绝缺失/重复环境、伪造 owner/type/ID、缺失或不匹配绑定、被删掉的环境元数据及旧版携带新合同。Guest 对合法但需要堆环境的计划返回 `ASCG1024`；当前仍未支持捕获 lambda 的实际运行。未知逃逸分配作用域返回 `ASCS4004`，不猜测 lifetime。具体语义与待实现生命周期约束见 [捕获环境设计](P66.B_Capture_Environment_Design.md)。

## 验证

固定 .NET SDK 8.0.416，Release 自执行测试：

| 检查 | 结果 |
| --- | --- |
| Semantic（含 35 项环境分析与合同检查） | 152/152 |
| CSharpGuest（含 6 项环境边界检查） | 198/198 |
| UeTypeGenerator | 5/5 |
| PreparedSemanticContracts | 13/13 |
| SemanticCacheEntryContracts | 25/25 |
| 无捕获 lambda / 方法组 WASM 回归 | 1050/1050、1890/1890 |
| 直接捕获 / 异步直接与 CFG 捕获 WASM 回归 | 900/900、各 80/80 |

Guest 回归包含 21/1.24 静态方法组、21/1.25 无捕获 lambda 和既有 async 合同兼容；新环境合同不能伪装成旧 Schema。Prepared 测试的备份清理告警来自预期故障注入。

复现：使用固定 SDK 执行 `dotnet run --project Tools/AvidScript.CSharpSemantic.Tests --configuration Release`、`Tools/AvidScript.CSharpGuest.Tests` 与 `Tools/AvidScript.UeTypeGenerator.Tests`；两个 PowerShell 合同脚本位于 `Tools/AvidScript.CSharpFrontend.Tests`。

本组没有新增闭包 WASM 执行、回收器、UE 构建、Automation 或生命周期验收。下一步是环境堆、精确根集合、共享 cell lowering 和含环境的间接调用，再接入 continuation、Session、reload 与 teardown。不能把环境计划的测试通过解释为逃逸闭包完成。
