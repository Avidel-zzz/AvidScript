# P66：语言一致性与下一代开发体验路线

## 决策与范围

用户已授权从发布收尾转向开发体验设计并自动推进实现。Windows 为当前验收平台；Android/iOS 真机验收继续延期。P65 的性能、发布与移动端债务保持原状态，不以新路线覆盖其未完成事实；D40 未提交草稿保持原样。

总目标是让开发者在运行中的游戏内安全修改、理解和验证玩法。验收同时关注语言、UE 编辑循环、调试、生命周期和真实玩法效率，不用单项微基准或测试数量代替成熟度。

| 顺序 | 交付目标 | 必须具备的证据 |
| --- | --- | --- |
| P66 语言一致性 | 明确支持契约；局部函数、闭包/委托、泛型与集合、错误处理及异步组合 | 普通 C# 源码到真实 WASM 执行；正反例、语义差异与版本兼容；不能靠样例绕开限制 |
| P67 结构热重载 | 新增/修改反射成员的编辑循环；Blueprint 子类与实例状态迁移 | 属性/函数/组件变更、GC、默认对象、网络复制、Cook 的原型结果；量化需要退出 PIE 或重启的边界 |
| P68 完整调试 | 内部函数、返回值函数、异步链与 IDE 调试 | 真实断点、调用栈、变量、步进、reload 后源码映射；明确暂停对 World 的影响 |
| P69 生命周期与玩法验证 | 有归属的并发任务、取消和诊断；技能/UI/存档/网络完整切片 | 开发耗时、保存到生效 P50/P95、重启次数、手写桥接量、故障定位时间及长时间运行 |

以上顺序不是缩减总目标。结构重载和调试需要的共享状态模型应在语言实现时预留，后续阶段须各自冻结实现方案。成熟度与“领先”只有经过同语义、同工作流的竞品对测和真实项目使用后才能声明。

## 保留与需要验证的架构

- 保留 Roslyn -> Semantic -> Guest IR -> WASM 的单向边界；Roslyn/CLR 不进入 UE Runtime。
- 保留 ObjectHandle 代际校验、Session 生命周期、受控 Host effect、候选重载与可回滚状态。
- 编译器为词法函数、捕获环境、异常与挂起状态提供明确合同，不能把所有能力做成 Runtime 特例。
- 结构热重载先比较动态反射类型/实例重建与原生外壳方案。不得未经 UE 反射、Blueprint、GC、复制及 Cook 原型验证就承诺纯插件支持任意结构热更。
- 调试需要可重建的执行帧与异步因果关系；仅增加 Slate 面板不足以消除当前暂停范围限制。
- 确定性回放、任意外部副作用回滚、完整 .NET/NuGet 兼容均不是既有能力，也不由 WASM 自动提供。

## P66 模块与合同

Semantic 层负责语言能力契约、词法符号、函数体、CFG 与诊断；Guest 层负责函数/环境/值的显式 lowering；Guest IR 和 WASM backend 负责验证及执行语义；Runtime 只接受版本化产物和 Session 所有权。

第一组实现从静态同步、非泛型局部函数开始：独立词法身份、独立 CFG、直接调用、嵌套与递归、跨函数可达性。不得将局部函数错误投影为包含它的外层方法。静态限制由 C# 编译器保证无捕获；未实现的捕获、泛型局部函数与异步局部函数保留明确诊断。这是闭包工作的第一步，不是整个 P66 的完成定义。

局部函数身份包含词法 owner 和同名作用域序号，不使用裸类型+方法名；身份不对外导出，不充当存档字段身份。引用源与主源采用相同规则。局部函数声明不会作为外层函数的可执行操作重复 lowering。

首组不增加 Guest opcode、Host import 或 Runtime ABI。局部函数沿用现有 callable/CFG 编码；新增语言接受能力由独立语言 profile 合同描述。若后续捕获环境或错误处理改变产物含义，必须同步升级 schema/version、所有读取者、缓存和拒绝测试。

## 验证要求

正例覆盖词法同名隔离、嵌套调用、递归、分支、ref/out、默认参数及引用源；反例覆盖捕获、泛型、异步、非法导出和不能安全表示的签名。执行证据须包含实际结果，不仅是生成成功。保持现有源码诊断、确定性、可达性与旧产物读取测试。

阶段 Gate 统一执行受影响的托管测试、WASM 执行、架构检查及适用 UE 验证。第一组纯编译器变更不把未运行的 UE/PIE 宣称为通过。真实开发切片和 IDE 人工体验另行验收。
