# P66.C24：经过准入的构建视图

## 冻结范围

C23 的热构建仍完整物化约 36.83 MiB Semantic，PowerShell 峰值 working set 约 1.1 GiB。普通 Actor/Component 样例中，`methods` 占约 17 MiB、`control_flow_graphs` 占约 16 MiB；构建器不读取前者，对后者只读取可达 callable 的图。降低这条路径的成本，不改玩法源码或执行语义。

C# 的 `--validate-language-profile` 增加可选 `--include-build-metadata`。请求该选项时，仍读取完整原始文件、执行同一 Semantic reader 和 C#→Guest IR 编译准入；随后返回 `build_metadata` Schema 1。它保留构建器实际读取的完整根字段，控制流图保留原顺序的可达子集。原始文件、哈希、编译器结果和产物不改写。没有该选项的 CLI/API 输出保持原合同。

视图的根字段由 C# owner 固定：schema/version、成功状态、source、diagnostics、reachability、symbols、callables、UE 类型与方法目录、async methods、exception flows、delegate callbacks 和 event subscriptions。保留字段内的对象结构、数组顺序、null、数值与字符串。所有被跳过的数据仍经过完整编译准入，并扫描空属性名及大小写冲突，保持原 PowerShell reader 的拒绝边界；不能借裁剪忽略非法 JSON。

prepared 与 semantic cache reader 增加显式构建视图选项，默认仍返回完整模型。正式 gameplay 构建与 profile cache publisher 请求视图；legacy 和无 profile 的 reader 保留原路径。源文件、逻辑 SourceId、绑定授权、类型清单、Semantic 原始哈希与 Guest IR 字节关联继续独立验证，准入响应还必须匹配读入前已核对的 Semantic 哈希。不能信任调用者提供的摘要或复用可变 Profile 对象。

原子发布 helper 增加可选的两个预期 SHA-256；prepared reader 传入已验证的哈希。临时文件同时匹配该哈希和当前来源后，才替换目的文件。验证之后、复制之前来源变化时必须拒绝并保留旧目的，不能仅比较两个已经同时改变的文件。未提供预期哈希的其他调用者保持原合同。

## 写集与验证

写集：C# admission CLI 与 metadata owner、profile helper、prepared/cache reader、正式构建器、必要测试及最小文档。两层指纹纳入 profile helper 源码；C# metadata owner 由现有 Guest 源码指纹覆盖。规则变化产生新缓存键。

- C# 同源正例比较原准入与带视图准入的 SourceId、源码/原始 Semantic/Guest IR 哈希；保留字段与原始 JSON 一致，可达图与现有构建过滤一致。
- legacy/default reader 仍返回完整模型；malformed JSON、未知合同、错误 source/identity、大小写冲突及空属性名在发布前拒绝，旧目的文件保持不变。
- 正式 Actor/Component 的冷构建、prepared 与双缓存复用；六份原始产物与 C20 一致，热构建四工具为零、无 worker 启动或 fallback。
- 受影响 C# runner 与缓存合同串行验证，再复用 C22/C23 的三样本计时入口。计时边界一致，峰值 working set 仅指 PowerShell 进程，不与子进程总和混用。

固定已安装 SDK 8.0.416、BelowNormal、单并发；复用单一大型输出，不安装 SDK、不修改持久 PATH，不重试旧目录的清理。P66.C/D、真实玩法、结构热重载、完整调试、跨语言与 Windows 发布仍未完成。
