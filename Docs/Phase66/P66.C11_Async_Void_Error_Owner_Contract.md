# P66.C11：`async void` 错误归属与候选回滚

状态：源码、Guest IR 36 与 WASM 编译候选已实现，2026-10-04；生产 Host 与默认构建尚未接入，P66.C 仍未完成。本文只处理受控 C# `async void` 方法的语言错误。Host import 拒绝、WASM trap、越界和预算耗尽仍是不可由脚本 `catch` 捕获的故障。

## 当前实现与验证

- `SemanticAnalyzer.Analyze(..., enableAsyncVoidErrorOwner: true)` 产生 Semantic 55 / 1.64；方法记录私有错误 owner、`report_to_session` 策略及唯一未处理出口。同步调用、Task await、直接 await 的取消与异常区域共用受检 CFG。
- 源码测试覆盖无 catch、局部 catch、命名异常变量、跨 await、rethrow、finally 替换错误与 Task await；旧版伪装、缺 owner、错误策略、越界出口及缺失集合均拒绝。SDK 8.0.416，Semantic 全量 **1557/1557**、同步异步异常专项 **485/485**；构建 0 警告、0 错误。
- 这是显式开启的源码候选，暂不与静态初始化或标准 `CancellationToken` 值组合。普通 Guest 入口仍以 `ASCG1030` 拒绝；`CSharpLanguageErrorCompiler.TryLower` 仅从完整 Semantic 55 建立私有执行上下文，输出经独立验证的 IR 36 / 1.35。伪造版本或 owner 不得进入该上下文，调用完成后普通入口也不获得准入。
- IR 36 的 `async_void_error_owners` 列出源方法、owner/type 局部槽、唯一未处理出口及其初始/恢复函数中的报告位置。manifest 必须声明 `error.async_void_owner@1`、精确 base 29 / 1.28 和实际携带的其他计划；不分配无用的结果 Task，不要求填入未使用的静态或 token 计划。IR 35 的既有五项异步组合合同保留。

## 为什么先做这项

当前 Semantic 54 / IR 35 能把同步语言错误交给 `Task<int>` 的异常 owner，也能在 `async void` 等待子 Task 失败时调用 `avid_language_error_report_v1`。但是导出的 `async void BeginPlay` **自身**直接调用可能返回语言错误的同步方法时，`SemanticAsyncProjector` 不建立异常 owner，`SemanticAsyncSynchronousExceptionValidator` 禁止其 `synchronous_exception_target`，Guest lowering 以 `ASCG1026` 拒绝。这是明确的编译失败，不能通过删除 outcome 检查或把调用藏进测试适配层放行。

仍待生产执行验证的原始用法是：

```csharp
[UnmanagedCallersOnly(EntryPoint = "avid_on_begin_play")]
public static async void BeginPlay()
{
    try
    {
        AvidCancellationSource source = AvidCancellationSource.Create();
        await AvidContinuations.NextTickAsync();
        source.Cancel();
    }
    catch (Exception)
    {
        UE.Self.SetActorScale3D(new FVector(1.0f, 1.0f, 1.0f));
    }
}
```

同一入口还要覆盖无 `catch`、`catch` 后重新抛出以及 `finally` 清理失败。示例中的 `Create()` 是现有失败路径探针，不代表它在正常条件下一定抛错；执行测试应使用确定性的语言错误生产者，并保留同一业务源码的 .NET 参考结果。

## 版本与所有权

- 候选使用 **Semantic 55 / 1.64** 和 **Guest IR 36 / 1.35**；只有所有读写端、provenance 与原生准入一起升版才能进入生产构建。当前原生 language-error catalog 读端仍拒绝 IR 36；不能只放大版本上限来开启运行。旧 Semantic 54 / IR 35 不解释新字段，不接受伪造的 `async void` 出口或降版产物。
- Semantic 为每个受控 `async void` 记录明确的未处理策略 `report_to_session`，连同源方法、导出/接收者身份、异常区域和 CFG 出口。同步 outcome、await 失败、显式 throw 与取消必须进入同一受检区域图；无处理区域时进入唯一未处理出口。不能按相同源码 span 推断复制的 `finally` 的身份。
- 当前方法的异常 owner 是**私有 carrier**，可复用已有 Task fault 的对象根和引用计数，但不向 C# 返回 `Task<int>`，也不作为业务结果。进入 catch、跨 await、rethrow、清理替换及退出时，owner 的 retain、转交和 release 各有唯一边；帧或 Session 退休后为零。普通返回不得携带未报告的错误。
- 未处理出口从仍受 owner 保护的对象读取类型 token、源码 token 和根，调用现有 `avid_language_error_report_v1`。报告保留实际错误身份和 Session/Actor/代码代次；只在报告及根转交完成后释放 carrier。报告失败或 owner 无效时 fail-closed，不以空错误继续执行。Guest IR 逐站点记录调用、status 分支、owner、目标和报告位置；读端核对每个生产者与每个消费出口。
- 已有 `async void` 子 Task 失败报告路径与新同步 outcome 路径只能共同到达一次未处理出口。Host 不能把语言错误误记为普通成功，也不能把 VM 故障伪装为可捕获异常。成功路径的额外成本要单独测量，不能只测异常慢路径。

## 候选 `BeginPlay` 的两个时间点

| 发生时点 | 应有行为 |
| --- | --- |
| 候选调用返回前，语言错误使准备失败 | 拒绝发布候选；回滚 journal 覆盖的可逆 Host 副作用；旧 Session、VM、挂起 Task 与代码身份保持不变。测试必须由**原始 C# 错误**触发，不能只用测试钩子卸载 VM。 |
| 候选已发布，随后 await 恢复时出错 | 错误归属已发布代次和当前 Session；按运行期策略隔离/退休故障实例或执行域。旧版本已经不再是可回滚的运行状态，不能声称恢复旧 VM。其他 World 与未受影响的 owner 不应被牵连。 |

准备期间的 RPC、存档和外部服务写入等不可撤销操作须拒绝或延至提交；Actor Transform 的 journal 恢复不证明任意 Host 副作用均可回滚。现有 [第十三切片](../Architecture/AvidScript_Composable_Capability_Contract.md)只验证执行后**注入失效**及受检 Transform 回滚，是前一行的事务底座。

## 实施顺序和停止条件

1. **源码合同。** 在 Semantic 投射与验证中加入版本化 `async void` owner/出口；固定 `.NET` 参考程序和明确的旧版拒绝测试。缺区域、伪造出口、缺 owner、重复未处理出口以及混用旧版本均拒绝。
2. **Guest IR 与 WASM。** 同步 outcome 与 Task await 共用 owner 和未处理出口；为局部 catch、跨 await、rethrow、`finally` 替换错误、取消各保留源码 token 和根。验证器独立核对控制流、引用计数和报告导入，不能只信任编译器生成的计划。旧 fixture 的规范字节不变。
3. **生产 Host。** 用同一 C# 源码经正常构建入口生成 WASM/manifest，在 WAMR Interpreter 与 Wasmtime JIT 上分别运行立即失败、挂起后失败、捕获恢复、候选准备失败及 Actor/World teardown。检查结果、错误位置、旧任务延续、journal 恢复和 Task/等待者/continuation/帧/根归零。然后接入默认 `Build And Bind`；不依赖测试开关或手写 WASM。

任何一步若只能靠静默返回、跨代复用旧 owner、跳过 Guest 验证、重跑旧代码或修改业务源码绕开错误，就保持 P66.C 未完成并修合同。通过这些专项仍不等于真实 Editor Play、Windows Shipping 或竞品性能领先；这些门槛仍由 [后续迭代路线图](../Architecture/AvidScript_Iteration_Roadmap.md)和 [跨语言交付合同](../Architecture/AvidScript_Cross_Language_Delivery_Contract.md)管理。
