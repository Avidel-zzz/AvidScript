# P66.C14：静态状态与异步值组合

2026-10-04。补齐统一 Gameplay 配置探针发现的两处合法源码组合缺口：

| 实际源码 | 旧合同的失败原因 | 新合同的源基础 |
| --- | --- | --- |
| `Task<int>` + 静态状态 + `catch (ArgumentException error)`，不使用 token | Semantic 51 的固定 base 50 不接受命名异常值 | 52 / 1.61 |
| `Task<int>` + 静态状态 + token，只使用 `catch (OperationCanceledException)` | 旧组合要求实际命名异常绑定，不能接收未声明 `error` 的源码 | 53 / 1.62 |

例如，第一种组合可以保留异常变量：

```csharp
public static async Task<int> Run()
{
    try { return Cache.Value + await Read(7); }
    catch (ArgumentException error) { return error == null ? 99 : 3; }
}
```

第二种组合可以只捕获异常类型：

```csharp
try { await AvidContinuations.NextTickAsync().WithCancellation(token); }
catch (OperationCanceledException) { return 3; }
```

编译器不能为了套用旧版本，给第一种源码补 token 计划，或给第二种源码补空异常绑定。
