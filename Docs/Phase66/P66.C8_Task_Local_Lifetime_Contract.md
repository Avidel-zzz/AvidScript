# P66.C8：Task 局部变量的赋值与作用域

状态：控制流所有权求解器已支持退出边上的引用退休，并接入现有条件 Task 分析。源码重赋值、循环局部 Task 与 Guest 清理代码尚未接通；现有入口继续拒绝这些源码，不能将本项记为语言支持完成。P66.C 继续实现。

## 要解决的源码

```csharp
Task<int> pending = LoadAsync(1);
Task<int> saved = pending;
pending = LoadAsync(2);
int first = await saved;
int second = await pending;

for (int i = 0; i < 3; ++i)
{
    Task<int> iteration = LoadAsync(i);
    int value = await iteration;
    if (value == 0) continue;
    if (value == 2) break;
}
```

替换 `pending` 只释放该变量原先持有的一份引用，`saved` 仍指向第一个任务。循环每次进入声明都会取得新的任务引用；正常离开、`continue`、`break`、`return`、语言异常和取消都必须释放离开的作用域所持有的引用。生产者任务、await 等待者、源码变量和别名分别拥有自己的引用，不能用“释放变量”代替“取消任务”。

## Semantic 合同

后续接入采用新的 **Semantic 45 / 1.54** 合同，以下字段是待实现设计，当前构建仍输出既有版本：

- `SemanticAsyncMethod.TaskLocalLifetimes` 记录 Task 局部变量与其词法 scope ID 的关系；scope 的成员 segment 和进出边继续由 Roslyn 控制流构建产生。投影器直接从声明的 Roslyn local 与语法作用域建立关系，不能在 Guest 根据名称或行号猜测。
- 新合同的 `TaskLocalSymbolIds` 总是列出完整 owner 集，不再把“是否存在别名”当成启用条件。未初始化声明需单独表示声明事实，不能伪造一次返回零任务的调用。
- Task 赋值保留普通 `assignment` operation 的目标和值；`TargetSymbolId` 继续表示声明，不能把重赋值伪装成第二次声明。
- 局部 Task await 只要求变量在当前路径已初始化且类型匹配，不再固定到初始生产方法。新合同的 `task_local` 不携带单一 `TaskCallableId`；`task_call` 仍携带实际被调用方法。每个赋值中的调用各自核对静态 async 方法、返回类型和参数，允许不同合法生产方法写入同一个变量。
- 每个局部变量的写入、别名读取、await 读取和 scope 退出都进入验证。可能持有的集合用于清理；所有路径都已初始化的集合才允许读取。赋值需要按 statement 顺序检查，不能只用 block 末尾的事实授权较早的读取。
- 不扩展 CLR、任意 `Task<T>`、Task 字段存储、跨 Session 传递、捕获或空 Task await。未实现形态继续在源码位置拒绝，并保留清晰的诊断。

新字段须同步模型、序列化、schema、Semantic/Guest 读端、CLI、构建器和缓存身份。给新计划改成旧版本、遗漏变量、伪造 scope、隐藏赋值或省略退出清理必须拒绝。Guest IR 及 Host ABI 是否需要升级，按最终发射合同决定；不能仅修改 provenance 标签让旧读端接受新语义。

## 引用取得与释放顺序

1. **初始化和替换。** 先求值右侧；别名来源先 retain，再释放目标的旧引用，最后存入新 token。`pending = pending` 与两个变量指向同一 Task 时仍遵循此顺序。右侧调用失败时旧变量保留到相应的清理路径，不能提前清空。
2. **作用域退出。** 从真实 CFG 边计算离开的作用域及 owner 集。对可能存在的引用执行受检 release 并清零；未进入声明的分支保留零值。非零 token 操作失败继续 trap，不能静默吞掉非法引用。
3. **挂起和恢复。** 同一作用域内的 await 不退休变量；槽值及其引用交给 continuation，恢复后重新取得调用所需的引用。跨 scope 的正常、失败和取消后继分别执行应有的清理。
4. **异常与 finally。** 根据已经构建的清理 CFG 安排退出，不绕过 finally，不提前释放外层仍可访问的别名。新的 finally 错误按语言错误合同替换原错误。
5. **失效 owner。** Session、World、Object teardown 和退休代码仍由 Runtime 回收，不重新进入 Guest。旧任务与候选任务保持各自的 lane、代次和 VM 所有权。

最终 Guest 生成应使用同一份已验证的派生流分析结果生成替换与退出清理。不要再维护一份序列化的 may/must 集，或由 lowerer 独立猜测哪条路径创建过 Task。

## 已实现：退出边数据流基础

[`SemanticAsyncTaskOwnerFlowSolver`](../../Tools/AvidScript.CSharpSemantic/Validation/SemanticAsyncTaskOwnerFlowSolver.cs) 接受由源适配层产生的 block 写入集合、控制流边及边上的退休集合，输出：

- 每段入口和出口可能持有、确定持有的变量集合。
- 每条可达边上确实可能需要释放的变量集合。
- 不让不可达生产者影响活跃路径；循环返回入口也保留最初空状态这条路径。

集合使用有限不动点求解：可能集合取并集，确定集合取交集；传播到后继前移除该边退休的变量。退出一个分支不会影响另一个后继，离开内层 scope 不会移除外层别名。未知变量、非法边、重复事实、缺失入口与超预算 CFG 都拒绝。

现有 [`SemanticAsyncTaskOwnership`](../../Tools/AvidScript.CSharpSemantic/Validation/SemanticAsyncTaskOwnership.cs) 已复用该求解器；旧合同传入空退休集合，继续保留原来的单次声明、初始化和别名校验。新求解器本身不是源码验证器，不负责证明传入的退休集合与 Roslyn scope 一致。新源适配层和对应拒绝检查完成前，不允许开放循环声明或重赋值。

专项测试包含循环重入、continue/break/异常边、分支条件初始化、外层别名、入口自环、不可达分支和输入拒绝。另外对 256 个分支/循环图枚举所有可达的具体 owner 位集，将其并集、交集及退出集合与求解器比较；这个对照使用有限状态路径枚举，不复制求解器的不动点算法。它验证编译器数据流，不是 .NET/UE 运行结果。

固定 SDK `8.0.416` 下，专项 **34/34**（包含上述 256 图对照）、Semantic 全量 **479/479**、Guest 全量 **589/589** 通过。使用 C7 生命周期验证的两份原源码重新执行正式构建，Semantic、Guest IR、WASM 共 **6/6** 逐字节一致；没有改写旧产物。本切片未改 Runtime，也未重跑 UBT/Automation，不把产物相同称为新的 UE 验收。
