# P66.B：分离实例执行状态与 VM 生命周期

## 问题与实现

上下文回调已能在同一 Runtime 内切换 owner，但原有 BeginPlay/EndPlay 标志、Tick 计数和旧 Timer 队列仍属于整台 Runtime。直接共享 Session 的 Runtime 指针会导致一个实例推进其他实例的 Timer，或结束其他实例仍在使用的 VM。

本组将这些状态及事件/Host 调用观察计数提取为 `FAvidScriptWasmInstanceExecutionState`。VM、线性内存、代码、预备出口、托管堆、绑定和值堆仍属于 Runtime；性能时长仍是 Runtime 级采样，不宣称新增实例级 Profiler。

| 所有权 | 当前行为 |
| --- | --- |
| Runtime | 持有 VM/堆/代码及旧入口使用的默认实例状态；卸载整台 VM 时使所有显式实例状态退休 |
| 显式实例状态 | 私有构造、不可复制；绑定代码身份、ObjectHandle、registry、World；保存生命周期、Timer 时钟/队列和计数 |
| 上下文调用 | 在完整同步调用期间保留状态引用和活动计数；按指针切换状态，返回后恢复，不复制 VM 内存或堆对象 |
| 调用者 | 仍须保留 Runtime、实例服务和对象注册表的有效生命周期；状态引用不是 Session/执行域的所有权租约 |

新增受检原生入口：`CreateInstanceExecutionState`、`BeginPlayInContext`、`TickInContext`、`EndPlayInContext`、`RetireInstanceExecutionState`。创建要求空输出和新 owner 上下文，拒绝覆盖已有状态及重复 owner；上下文入口核对身份，普通出口要求实例 Running。生命周期入口拒绝对同一活动实例再次 Tick/EndPlay；允许 A Tick 同步进入空闲 B Tick。

旧 Timer 在显式实例状态下使用各自的时钟、句柄空间和队列；没有显式实例状态的上下文仍不能使用模块 Timer。EndPlay 清除本实例待处理 Timer，重复 EndPlay 不重复执行 Guest；显式 retirement 不卸载 VM。整台 VM 卸载清除所有队列，旧状态不能进入替换代码。状态本身不持有 UObject 强引用。

Tick 与 Timer 回调退出时检查整链失败，原生回调忽略内层失败也不能继续派发后续到期 Timer。旧入口使用默认状态保持兼容。`SetHostContext` 只设置基准上下文，不接受显式实例状态；状态选择必须经过受检上下文入口。

## 接入生产 Host 的下一组合同

1. 以包、World 和对象注册表作为执行域边界，共享 VM/堆/静态状态；每个 Session 持有自己的执行状态、owner 权限、订阅、continuation 和调试服务。
2. 生成实例的普通成员、Tick、event、continuation、BeginPlay/EndPlay 全部使用同一状态入口。Scheduler 不得借用其他实例的基准上下文；模块初始化与生成 shell 的实例生命周期分别处理。
3. 实例退出先禁用派发并取消资源，在没有活动调用时释放自身状态。最后的执行域 owner 才卸载 VM；活动调用中销毁应有受控延迟或明确拒绝，不能释放外层栈仍在使用的对象。
4. 新实例激活失败与共享 VM trap 可能已改变共享状态，不能宣称仅隔离单个 Session 就恢复整个执行域。需要执行域级故障传播和一致停止；不能用丢弃一个状态对象代替回滚共享堆。
5. 包级 reload 先准备完整新代码、实例状态和路由，再一次提交；旧版本在提交/回滚完成前保持存活。不能沿用逐实例重新创建独立 VM 的方式，破坏静态状态、对象身份和引用别名。
6. 接入后以真实 Host 的多实例测试证明共享与最后 owner 释放，再连接完整方法签名、C# 跨对象派发和持久根。P66.B 不因本组通过而完成。
