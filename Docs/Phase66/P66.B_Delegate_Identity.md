# P66.B：委托身份与相等

## 合同

同步单目标委托的相等必须比较调用目标及捕获环境身份，不能比较每次构造分配的 binding 对象 token，也不能比较捕获值的当前内容。两个独立激活即使捕获值相同，仍具有不同环境；同一方法组在同一环境重新构造，不因新分配 binding 而不等。

普通 C# `==`、`!=` 保持左右表达式各求值一次。null 只与 null 相等，非 null 静态目标以方法身份比较，捕获目标在方法一致后逐项比较实际需要的环境引用。不同方法不因共享环境而相等；对匿名函数采用同一 callable、同一捕获环境可相等的策略，不合并不同源码 lambda。

此选择符合 [C# 委托相等规则](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/expressions#12159-delegate-equality-operators)：相等依赖运行时类型和有序调用项；规范允许但不要求语义相同且捕获实例相同的匿名函数相等。比较测试区分必须保证的语义与编译器允许选择的匿名函数缓存/身份策略。

## 实现边界与后续

使用现有 function_ref/managed_ref 的相等指令及受检 managed_cast，不增加 Host 命令或 IR Schema。包含闭包的模块按实际调用生成名义签名对应的比较函数，在目标匹配后恢复具体 binding，读取捕获环境引用；不把 binding 的值相等当作对象相等。没有闭包环境的委托沿用函数引用表示。

后续组合与移除必须复用调用项相等规则，同时保留不可变调用序列、顺序、重复项、最后一次连续匹配移除、最后返回值及 ref/out 的共享位置。该组不提前声明组合、event、绑定实例委托、跨 await 或持久订阅完成。P66.B 保持进行中。

当前比较函数按该签名已生成的捕获目标展开分支，方法匹配后再读取对应环境。它不分配新的闭包对象，但分支数及保守根插桩成本会随候选目标增长；本组没有性能领先结论，组合集成时需要对目标规模和调用列表长度分别度量。`Delegate.Equals`、跨名义类型转换和反射 API 不在本组支持声明中。
