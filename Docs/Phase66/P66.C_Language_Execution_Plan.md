## 跨层合同

1. **类型实例。** Semantic 以方法定义身份和有序、封闭的类型实参身份构成专门化键，限制实例数量与递归展开；Guest 的函数签名、局部、返回、调用目标和闭包布局必须使用同一替换。不同封闭实例不能意外共享状态。未封闭、不可表示或超预算的实例在源码位置失败。新增合同要升级 Semantic/Guest 版本，旧产物不得冒充专门化产物。
2. **迭代与清理。** 集合表达式只求值一次。数组可用经语义确认的索引快路径；普通枚举器必须按 `GetEnumerator` → `MoveNext` → `Current` 执行，并在正常结束、`break`、`return`、语言异常及取消时按 C# 规则至多一次 `Dispose`。不能把数组快路径误用于带自定义枚举器的集合，也不能丢弃 Roslyn 的 `finally` 区域来制造通过用例。
3. **错误传播。** 区分可由脚本处理的语言错误与致命的 Host/VM 拒绝。前者需要带源码位置的传播结果和显式清理边；后者仍 fail-closed，由 Session/执行域 owner 回收资源，不假装被任意 `catch` 捕获。`finally` 必须在已支持的退出路径运行，清理动作自身失败时不得吞掉原错误或留下根。先固定该语义和双后端可执行表示，再公开 `try/catch/finally`。
4. **异步结果。** `Task`/`Task<T>` 若公开，必须是 Runtime 可拥有的结果对象：创建者、等待者、取消源、代码代次和完成/失败状态可追溯；等待中的值、闭包和 UE handle 维持既有根与代际校验。owner 销毁、World teardown、失败候选和成功 reload 分别保留或终止正确的任务，不能让子任务在失效 owner 上继续写入。CLR 不进入游戏 Runtime，当前 `async void` 合同继续兼容。

### C3 下一切片：语言错误通道

逐次调用结果槽的 Win64 双 VM 探针与后续版本化合同见 [P66.C3 语言错误通道](P66.C3_Language_Error_Channel_Contract.md)。探针尚未开放 C# 异常语法。

当前 Guest 函数只有正常返回值（复合值可走现有 SRet），终结指令只有 `return`、分支和 VM `trap`；WASM 的 `trap` 无法运行 C# `finally`，也不应被脚本 `catch` 捕获。因此语言错误需要独立的版本化结果通道，不能把异常临时写入一个模块全局变量（递归、重入和并发会覆盖它）。下一切片按以下合同实现：

1. Semantic 为 `throw`、`catch`、重抛和跨调用传播保留源码位置、异常类型与确定的清理顺序；未支持的异常对象类型在源码位置拒绝，不把 `throw` 降为 `trap`。
2. Guest IR 明确区分正常值、语言错误和致命 VM/Host 故障。可传播的函数使用逐调用结果槽；调用者检查状态后才读取正常返回值，并按内层到外层执行 `finally`。清理再次抛错时采用 C# 的替换规则，不能误用原返回值。
3. WASM 导出保持现有 UE 回调签名，边界适配器把未捕获的语言错误交给 Session/Runtime 报告并终止该次脚本调用。Host import 校验失败、越界和燃料耗尽仍走不可捕获的失败路径，保留现有 owner 回收策略。
4. 先用同源 .NET/WASM 验证本地捕获、跨方法传播、嵌套 `finally`、清理抛错和重抛，再在 Wasmtime JIT/WAMR Interpreter 中检查错误分类、源码位置、清理次数和遗留根；完成这些证据前继续拒绝 `catch`/`throw`。
