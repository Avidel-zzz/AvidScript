# P66.C：泛型、集合、错误清理与异步组合的执行计划

## 目标与当前红线

本批次沿用 [Phase 66 冻结范围](P66.1_Implementation_Plan.md)：普通 C# 玩法代码需要在类型专门化、集合遍历、错误传播/清理和挂起后继续保持语义。Roslyn 接受源码不等于 Guest 能执行；P66.B 已完成的闭包与事件根必须在这些组合中继续正确。P66.C 尚未完成，以下是实施入口与验收合同，不是新能力声明。

在产品提交 `e285a14b`，使用固定 SDK 8.0.416 对四份最小普通 C# 源码依次运行 Frontend、Semantic 与 Guest CLI，得到：

| 普通 C# 源码及预期值 | 当前 AvidScript 结果 | 需要补齐的层 |
| --- | --- | --- |
| `foreach (int value in new[] { 3, 5, 8 }) sum += value` 得到 `16` | Frontend 成功；Semantic `ASCS3001` | 同步迭代计划、CFG 清理与 Guest 执行 |
| `static T Identity<T>(T value)` 的 `Identity<int>(7)` 得到 `7` | Semantic 成功；Guest `ASCG1002`、`ASCG1004`，类型参数无可执行表示 | 封闭实例身份、类型替换、函数体与调用专门化 |
| `try { value += 2; } finally { value += 4; }` 从 `1` 得到 `7` | Semantic `ASCS3001`、`ASCS2001` | 结构化退出、清理边与可传播的语言错误 |
| `async Task<int>` 等待后返回 `12` | Semantic `ASCS3002`、`ASCS5401` | 结果任务、父子所有权、完成/失败/取消及恢复 |

这些是工程 `Saved/AvidScript/P66CProbe/` 下的临时源码与 CLI 产物，未纳入正式回归或 Gate。它们证明当前拒绝位置，不能证明完成修复。数组 `foreach` 的 Roslyn CFG 实际包含 `GetEnumerator`、`MoveNext`、`Current`、`Dispose` 和 `TryAndFinally`；单纯删除 `ASCS3001` 检查会留下错误执行路径。受控 async 数组 `foreach` 已有以索引/长度执行的计划，但不能据此宣称同步 `foreach` 已支持。

## 跨层合同

1. **类型实例。** Semantic 以方法定义身份和有序、封闭的类型实参身份构成专门化键，限制实例数量与递归展开；Guest 的函数签名、局部、返回、调用目标和闭包布局必须使用同一替换。不同封闭实例不能意外共享状态。未封闭、不可表示或超预算的实例在源码位置失败。新增合同要升级 Semantic/Guest 版本，旧产物不得冒充专门化产物。
2. **迭代与清理。** 集合表达式只求值一次。数组可用经语义确认的索引快路径；普通枚举器必须按 `GetEnumerator` → `MoveNext` → `Current` 执行，并在正常结束、`break`、`return`、语言异常及取消时按 C# 规则至多一次 `Dispose`。不能把数组快路径误用于带自定义枚举器的集合，也不能丢弃 Roslyn 的 `finally` 区域来制造通过用例。
3. **错误传播。** 区分可由脚本处理的语言错误与致命的 Host/VM 拒绝。前者需要带源码位置的传播结果和显式清理边；后者仍 fail-closed，由 Session/执行域 owner 回收资源，不假装被任意 `catch` 捕获。`finally` 必须在已支持的退出路径运行，清理动作自身失败时不得吞掉原错误或留下根。先固定该语义和双后端可执行表示，再公开 `try/catch/finally`。
4. **异步结果。** `Task`/`Task<T>` 若公开，必须是 Runtime 可拥有的结果对象：创建者、等待者、取消源、代码代次和完成/失败状态可追溯；等待中的值、闭包和 UE handle 维持既有根与代际校验。owner 销毁、World teardown、失败候选和成功 reload 分别保留或终止正确的任务，不能让子任务在失效 owner 上继续写入。CLR 不进入游戏 Runtime，当前 `async void` 合同继续兼容。

## 实施顺序与验收

### C1 当前增量（尚未完成 P66.C）

同步方法中的一维数组 `foreach` 已复用受控 async 的索引/长度计划，输出普通 Semantic CFG 和 Guest IR；集合表达式求值一次，`break`、`continue` 与方法返回走显式控制流。可执行引用源码也能投射遍历局部变量。Semantic 合同保持 schema 30，语义版本升为 1.35；不含新编译器局部变量的 1.34 产物仍可读取，给含新计划的产物改写成 1.34 会被拒绝。普通枚举器和捕获迭代变量的闭包继续拒绝，避免丢失 `Dispose` 或逐次捕获语义。

固定 SDK 的 Semantic 回归 `373/373`、Guest 回归 `480/480` 通过；预处理语义合同 `13/13`、发布合同 `14/14`、语义缓存集成 `8/8`、构建集成 `15/15` 通过。运行 Guest 测试时设置 `AVIDSCRIPT_ARRAY_FOREACH_WASM_DIR=Saved/AvidScript/P66CArrayRuntime`，然后执行 `node Tools/AvidScript.CSharpGuest.Tests/RunArrayForeachWasm.js Saved/AvidScript/P66CArrayRuntime`，四份 WASM 实际得到 `16`、`107`、`117`、`6`（`4/4`）。它们分别覆盖基本求和、`break`/`continue` 与数组表达式只求值一次、嵌套遍历和提前返回、可执行引用源码；同源 .NET 对照也得到相同结果。显式 `finally` 与普通枚举器仍是拒绝负例。该执行证据使用 Node 的 WASM 引擎与本地数组，不等于 UE 内 Wasmtime/WAMR 的 Host capability、Editor Play 或长期运行验收；这些仍属后续 C1/P66.D 范围。

- **C1：共享迭代计划。** 从已验证的 async 数组迭代抽取可用于同步方法的语义计划，先让普通源码的单维数组 `foreach` 与同源 .NET 结果一致；同时设计枚举器资源/清理图。完整枚举器支持前保留精确诊断，不能把数组成功称为集合完成。
- **C2：封闭类型专门化。** 按[封闭泛型执行合同](P66.C2_Closed_Generic_Execution_Contract.md)推进。可达的同步静态泛型方法已生成封闭 callable、符号、方法体和 CFG，Guest/WASM 形成独立函数；`Identity<int>`/`Identity<float>`、二级调用、同实例递归、有序双类型参数、`ref/out T` 与 `T[]` 已实际执行，并与同一源码的 .NET 结果一致。Semantic 版本为 1.36，旧版冒充封闭实例会被拒绝。命名泛型与多维数组的布局、闭包/委托、实例泛型、async 泛型和 Win64 Editor 组合验收仍未完成，不能将此切片称为 C2 完成。
- **C3：语言错误与清理。** 在 Semantic/Guest IR/WASM 两后端连接结构化退出和传播；用 `try/finally`、枚举器 `Dispose`、嵌套调用与失败清理检查执行次数、原错误、资源和根。
- **C4：值结果异步组合。** 在 Session 所有权上接 `Task<T>` 等待与结果/错误/取消，和集合、事件闭包及重载一起测试。P66.D 再用完整自然玩法源码做集成审查与 Gate。

每组都要有同一份普通 C# 源码的 .NET 参考值、Semantic 正反例、Guest IR/Schema 验证、真实 WASM 执行；生命周期组合须在 Wasmtime JIT 与 WAMR Interpreter 检查结果、对象身份、清理次数及遗留根。Win64 no-clean Editor 构建与受影响 Automation 按风险运行。最终 P66.C 完成判定要求上述能力能组合，不以四个孤立演示或错误诊断改善代替；实际 Editor Play、Shipping 长跑和独立开发体验仍由 P66.D/P69 验收。Android/Mac 真机暂缓。
