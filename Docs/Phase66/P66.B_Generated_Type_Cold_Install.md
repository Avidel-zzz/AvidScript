# P66.B Windows 生成类型冷启动安装

## 结果

五类型 `ScriptDefinedTypes.cs` 样例通过正式 `BuildCSharpScriptTypes.ps1 -HeadlessRelease` 生成 Win64 包并安装到插件当前包指针。no-clean Editor 构建后，冷启动 `AvidScript.GeneratedTypes` Automation 8/8 通过：Cook 包加载、继承派发、Actor/Component/Subsystem 生命周期、RPC、属性、RepNotify、启动身份和 UE 反射。`AvidScript.Runtime.GeneratedTypes.ReceiverAuthority` 1/1 通过，包含 World teardown 等越权负例。当前产物的原生结构与已有壳相同，因此本组没有证明**改变原生结构后的 UHT 冷编译**。

## 修复

- 生产包加载先读取并校验规范 WASM，再用受检类型注册表准备精确的 receiver、属性、方法帧和动态派发 Host import 授权；加载后复核 WASM 哈希，避免预检和执行使用不同字节。
- 调试映射的 `defined_function_count` 计入 WASM 后端为 framed export 额外生成的函数，保持 Guest IR、调试偏移、构建合同与运行时校验一致。
- UE 将 World 标记为 teardown 后仍会调用 Actor/Component `EndPlay` 与 WorldSubsystem `Deinitialize`。仅这些原生终止回调可在其所属 Session 中完成同步 C# 逻辑；普通入口、异步恢复和失效 receiver 仍受原有 World 栅栏限制。owner 已失效时，Session 清理跳过无法安全执行的通用 `EndPlay` 导出。
