## 编译和运行所有权

原始源码文档先验证完整组合。静态准备只能在编译器内部生成去除静态 owner 并替换存储符号的执行视图；带 token 的视图保持 Semantic 56，重新投射实际剩余能力。不带 token 的静态视图可使用已验证的 Semantic 55 普通源码合同。原始源码版本和 hash 始终保留在最终产物中；私有上下文不能让公开普通 lowerer 获得准入。

静态构造或字段初始化错误进入当前 `async void` 的同步 outcome 路由；静态错误缓存、`TypeInitializationException`、命名 catch 值与 finally 使用既有类型/对象根合同。标准取消令牌的来源、身份和取消错误也进入同一个私有 carrier。未处理错误向 Session 报告一次，Guest 释放完成后才向调用方交付失败。Host 拒绝和 VM trap 不转成可捕获的 C# 异常。

中间的 static/token/readiness 包装只能在已验证的编译器上下文内延迟验证；最终 IR 37 发布前必须运行全部独立验证器。对于已知的静态 wrapper，允许把经过验证的 IR 30 包装 base 归并到其真实 IR 29 执行 base；不接受任意版本降级或未声明的计划。
