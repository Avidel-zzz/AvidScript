## 源码语义

```csharp
SelectTarget().Value = await Produce();
```

1. 先且仅执行一次 `SelectTarget()`，再执行 `Produce()`。接收对象求值抛错时，不能启动 producer。
2. producer 可以修改原先用于取对象的变量。成功恢复后仍向之前选中的对象写入，不能重新求值左侧。
3. 接收对象为空时也要先执行 producer。若 producer 成功，写回时才发生 `NullReferenceException`；
   不能提前报错而吞掉右侧的副作用。producer 自身失败或取消时，不执行写回。
4. 属性 setter 只在成功取得结果后调用一次；允许 setter 自己抛错，其错误继续经过源代码的清理/传播路径。
5. 没有其他引用的临时接收对象必须跨等待存活。正常完成、错误、取消和 owner 退出都要释放其等待状态中的根。
6. 已完成 Task 和挂起后恢复必须具有相同的求值与写回语义；循环每轮、并行调用每次各有自己的捕获对象。
7. `Task<int> pending = Produce(); target.Value = await pending;` 中 producer 已在前一条语句启动。
   捕获对象仍发生在赋值语句处，不能移到创建 Task 之前；Task 别名的所有权继续遵守 C8。

本次延续当前 `Task<int>` 结果范围，目标成员为精确 `int` 类型。覆盖普通 C# class 字段/属性、接口属性、
隐式 `this`，以及生成 UE 类型的可写属性。索引器、复合赋值、ref return 和需要保留可变 struct
存储位置的目标需要独立的地址生命周期合同，不借本节把值复制伪装成对原位置的修改。

## 实现边界与顺序

### Semantic：接收对象与写回计划

已新增 Semantic 47/1.56 的 `SemanticAsyncMemberAssignment`。计划保留源赋值位置、目标 operation、
接收对象临时槽、结果临时槽和写回 segment；旧版及不匹配版本继续拒绝新计划。

- 在调用 producer / 读取 Task 局部之前，用普通 operation 求值接收对象并写入编译器临时槽。
- 等待成功时先接收结果，再进入专属写回 segment；失败/取消边直接进入原有错误/清理路径。
- 写回复用普通字段或属性赋值，不新增按成员名查找或 UE 类型专用的异步 setter。
- 接收对象槽进入现有 liveness 与 state-frame 计算；不得借用栈地址，也不得借用 `foreach` 临时槽身份绕过验证。
- 读者独立核对源 method operation、临时槽身份/类型、捕获在前、成功写回入口和异常区域归属。
  删除捕获、改对象、提前写回、错误边接到写回块、旧版冒充和省略根均须有篡改负例。

普通 async 投射与 `try/finally` 的异常投射已共享该计划。新合同要求整个模块中的 Task 局部遵守 C8
生命周期规则，包含原来只需旧别名计划的简单方法。闭包规范化与封闭泛型专门化同步重写目标；
读者根据专门化 callable 的定义及类型实参核对源码身份。不可达赋值的临时槽会随 CFG 裁剪。

独立验证器检查捕获次数、源目标身份、写回块唯一成功入口、精确状态槽和临时符号归属。
JSON 中的目标、接收槽及写回 ordinal 均为必填，防止缺失字段被反序列化为看似有效的默认值。

### Guest / IR：值、错误与所有权一起执行

先将捕获/写回映射到已有局部变量、托管根和普通赋值指令，再处理语言错误路径。
接收对象求值错误、空对象写回和 setter 错误都必须进入 async 的清理与 Task 终止路径。
不得把 VM/Host 拒绝当成脚本 `NullReferenceException`，也不得让写回失败绕过 `finally`。

若新增写回或隐式错误的 IR metadata / opcode，使用新 Guest IR 版本，补齐独立验证器、
序列化、WASM emitter 和兼容性测试后再开放 Semantic 47 的执行。仅复用现有可执行表示时，
仍必须证明旧 IR 验证器已覆盖相同错误与资源合同，不能用“不加指令”为理由省略审查。
不改 UE binding descriptor 的成员身份，不引入 CLR 或新的 UObject 裸指针通道。

### Runtime：普通对象与生成 UE 类型

同源测试先在 Wasmtime JIT / WAMR Interpreter 上运行；暂停时主动触发托管堆收集。
临时对象场景必须确认没有源码静态字段或调用者持有接收对象，避免额外根掩盖 liveness 缺陷。

生成 Actor 测试使用真实生成壳、`ProcessEvent` 与 `World::Tick`，覆盖隐式 `this` 和显式对象属性。
在等待前后分别检查 Actor/World 销毁、失败候选回滚、成功 body-only reload；同域另一个实例应保持
自身等待与对象身份。对象根、Task owner、waiter、continuation frame 最终归零。
不得用 .NET 取消测试替代 UE teardown 或 reload 验收。

## 同源基准矩阵

`Trace` 的十进制数字依次表示：`1` 接收对象求值、`2` producer 开始、`3` producer 恢复、
`4` setter 调用、`8` consumer 的 finally。数值、异常类型、Task 终态和每个对象的 setter 次数分别断言。

| 场景 | 数量 | 必须满足 |
| --- | ---: | --- |
| 字段/属性 × 挂起成功、立即成功 | 4 | 写回原对象，替换对象不变 |
| 字段/属性 × 挂起后失败、挂起前失败 | 4 | 不写回；清理一次 |
| 字段/属性 × 等待中取消、预先取消 | 4 | Task 为 Canceled，保留 token 身份，不写回 |
| 字段/属性 × 空对象、接收对象求值抛错 | 4 | 分别验证右侧执行后失败、右侧根本不启动 |
| 隐式 this 的字段/属性 | 2 | 保存本次调用的对象 |
| 两轮循环中的字段/属性 | 2 | 第一轮写原对象，第二轮写替换对象 |
| 同时挂起两次的字段/属性 | 2 | 两个 invocation 不共用捕获槽 |
| Task 局部别名 × 字段/属性 × ready/pending | 4 | Task 先启动，赋值时再捕获当前对象 |
| setter 抛错 | 1 | setter 一次、值不变、finally 一次 |
| 无外部引用的临时对象 × 成功/取消 | 2 | 等待时 GC；成功保留身份，取消不调用 setter |
| **合计** | **29** | 不能只比较最终数值 |

基准通过仅证明 .NET 参考行为。C10 的完成条件是同源 WASM 结果、Schema/IR 负例、双后端资源
验收和生成 Actor 生命周期均通过；PIE 实际玩法、Shipping 长跑仍由 P66.D/P69 验收。
Android/Mac 真机继续暂缓，P66.C 保持实现中。
