# P66.C10：预取消 await 的同步完成

## 问题与验收目标

原始 [AwaitMemberAssignment.cs](../../Fixtures/Phase66/AwaitMemberAssignment.cs) 中：

```csharp
await AvidContinuations.NextTickAsync().WithCancellation(Lifetime.Token);
```

若调用前已取消 `Lifetime`，同源 .NET awaiter 的 `IsCompleted` 为真，`GetResult()` 立即抛出取消异常。
producer 返回的 Task 此时已取消；调用者取得它后，应在当前调用内执行相应的 `catch` / `finally`。
不能先安排 Timer，再等取消回调完成这些操作。

原始 29 场景的首次双后端执行暴露了该差异：`field-mode-5` 和 `property-mode-5` 在普通完成模式中，
`InitialCleanup` 期望 `1`、实际 `0`，`InitialTrace` 期望 `128`、实际 `12`。
最终结果相同不能掩盖同步副作用时机不同。原始业务源码、.NET awaiter 和这两项断言均保持不变。
证据：工程 `Saved/AvidScriptStaticAsync/20260926T213449459Z/automation.log`。

## 取消状态 ABI

新增 `avidscript.avid_continuation_cancel_status_v1(i64 source) -> i32`。
[原生合同](../../Source/AvidScriptVM/Public/AvidScriptContinuationCancellationAbi.h)定义：

| 返回值 | 含义 | 编译器行为 |
| --- | --- | --- |
| `0` | token 或执行域无效；Host 不支持查询 | 拒绝执行，不当作未取消 |
| `1` | 当前执行域中的有效、未取消 source | 安排等待并绑定 source |
| `2` | 当前执行域中的有效、已取消 source | 在当前调用中执行取消路径 |

查询只读，不创建 Timer、Task、状态帧或绑定，不消费完成队列，也不释放 source。
校验顺序为 Game Thread、endpoint 有效性、Session activation、World / owner 存活、token kind、slot generation、lane。
跨 active / prepared 域、过期代际、已释放 source、失效 owner 和 teardown 均返回 `0`。
未实现查询的旧原生 Host 默认返回 `0`；旧 WASM import 的签名和数值绑定 ID 不变。
新 import 只接受 `avidscript` 模块和精确 v1 签名，没有 `env` 别名。

## 编译器接入要求

1. 先按源码顺序求值 producer 参数和取消 token，均只求值一次，再查询状态。
2. 状态为 `1` 时，沿既有 Timer、取消绑定、状态保存和 Task producer 所有权路径执行。
3. 状态为 `2` 时，不安排 Timer、不保存 continuation frame；创建既有类型化取消错误 owner，
   进入当前源码的异常分派或隐式 Task 取消传播，并在当前调用内完成 `finally`。
4. 同步路径保留 Task 的 Cancelled 状态，不改成普通 Faulted；错误所有权、源位置、接收对象根与 Task 局部释放都要验证。
5. 从另一个 await 恢复后遇到预取消 source，仍执行相同分支，不能只修首次方法入口。
6. 继续保留已挂起后取消、Session teardown、Actor / World 退出和 reload 的既有合同；查询不是取消操作的替代品。

若增加 IR readiness metadata，使用独立版本，并记录已有执行合同的精确 base version。
独立 IR 读者必须验证查询到 schedule / cancellation / invalid 三条边、查询和绑定使用同一 token、
取消分支中的错误 owner、所有资源释放，以及每个实际函数副本中的控制流。
删除查询、改 token、绕过状态判断、把取消边接到成功写回、移除清理、旧版本携带新 metadata 均须拒绝。
不得仅凭 block 名称白名单放行新增的类型化取消 producer。
