# P66.C19：Editor 的 Gameplay 语言配置

## 冻结范围

C16–C18 已通过正式命令行构建，但 Editor 的 BuildConfig 尚未传递语言配置。新建 workspace、Build And Bind 和自动重载需要走同一份配置与回执合同，不能让源码在两个入口得到不同的能力。

本节实现三项相互依赖的能力：

1. **配置与兼容。** 新创建的 workspace / profile 使用 profile Schema 11，显式保存 `language_profile: "gameplay-v1"`。Schema 1–10 沿用原行为；Schema 11 的空字符串显式选择 legacy。旧 Schema 不得声明新字段，Schema 11 不得缺少或提供非字符串字段。已有 workspace 和 profile 保持既有的非覆盖规则。Schema 11 使用明确的 Schema 10 binding 能力映射，不改变项目 API 的授权范围。
2. **构建与回执。** BuildConfig 把名称传到 bootstrap、final、prepared 和异步 job / 自动重载；配置内容及哈希仍由 C# owner 定义。Editor 不复制八个分析开关，不扩大 Semantic / Guest 版本白名单。回执保留配置名称与合同哈希；成功结果必须对应请求的名称，bootstrap / final 必须使用同一份身份。缺失、类型错误、名称不匹配或阶段间哈希不一致时拒绝发布，保留既有 artifact 事务回滚。
3. **正式流程验证。** 使用实际 workspace 创建服务、实际生成的绑定声明和正式编译器，核对正常源码、标准 token / 对象等待 / 清理组合的构建及缓存重用。验证异步构建 / 重载沿用 profile，失败回执不替换旧产物。配置与回执的正反例使用聚焦 Editor Automation，实际输出模块按 manifest 校验；源代码不改写为较窄的业务逻辑。

新配置仍遵守 C# owner 当前支持范围，未知名称及选项冲突由该 owner 给出诊断。旧 JSON 不自动升级，既有用户文件不被覆盖。公开配置名称不是 binding 授权，也不是 Runtime 执行许可；实际模块仍经过既有 ABI、元数据、字节与生命周期校验。

## 写集与边界

Editor BuildConfig / Invoker / Pipeline、FrontendReport DTO / Reader、ProfileService、workspace profile 模板及相应测试拥有本节主要写集。普通命令行入口的默认模式不变，已有 `-LanguageProfile gameplay-v1` 入口继续由 C16 合同负责。

默认模板验证暴露了两个编译器阻塞。静态状态使同步 callback 进入 outcome 编译，而自动生成的 gameplay / continuation 分派函数没有 C# 源码方法，不能加入源码 effect closure。修复由 `CSharpLanguageErrorCompiler` 和私有 `CSharpGeneratedLanguageErrorAdapter` 负责：只暂存明确注册的编译器 Host router 与其唯一 export，在源码 outcome 编译后恢复路由；受影响的 void callback 经过与直接 UE export 相同的错误报告适配器。原 callback 参数与公开 export 保持不变；私有适配函数不成为新 export，也不生成虚构的 C# source span。其他调用者仍须满足原 effect closure 检查，委托适配限制不因此放宽。当前回归源码输出 gameplay 与 continuation v2 两个 router；它不同时输出旧 continuation ABI。

第二个阻塞是 `[AvidPersist]` 字段的状态表仍按原源码字段查找，而静态初始化已按封闭类型生成专用存储。`CSharpStaticSourcePreparation` 提供同一份存储身份映射，状态表仅根据已验证的静态初始化计划解析实际 global / slot，并核对类型。面向迁移的稳定字段名、旧名 alias 和 Schema 2 保持原合同；缺失或类型不符的存储仍拒绝，transient 字段不进入快照。默认模板及其 callback、异步逻辑和持久化标记均不改写。

对应写集增加 Guest 编译器、公共入口适配器的内部 helper、静态存储身份解析、状态表和语言配置回归。正式 CLI / worker / IR / WASM / debug map 都需要覆盖该修复；托管产品已发生变化，因此本节重跑完整 Guest runner。

本节不关闭 P66.C/D，不将 API 驱动的 Editor Automation 当作人工 Play 验收。共享生成类型域的自然语言失败回滚、直接向其他辅助类静态字段赋 await 结果、捕获委托与静态异常组合、完整调试、Shipping 和移动平台仍需后续交付。

工作区测试使用正式 StreamableManager 加载引擎资源，并手动推进测试 World、CoreTicker、无 World 的全局 Tickable 和帧计数。文件变更通知由受控 watch 提供，后续构建、缓存、artifact 校验、component 绑定和重载均走生产服务。它覆盖编译失败后保留旧模块，不替代共享生成类型域中候选执行产生 C# 语言错误后的回滚，也不证明人工 Editor Play 或文件监视器的完整体验。

## 验证与环境

先完成配置、回执和入口实现，再冻结候选，集中检查 Diff、解析与架构，执行单并发 no-clean Win64 构建及受影响 Editor Automation。托管产品未改变时复用 C18 的托管验证，只有实现影响面变化才增加对应 runner。正式构建与 EditorCmd 串行、BelowNormal，复用安装 SDK；不修改用户 / 机器 PATH，不启动或结束用户的 Editor，不安装临时 SDK。

唯一测试工作区记录文件哈希及进程归属，只回收本节创建的生成文件，保留日志和报告。已有七个 protected 路径保持基线；此前被拒绝的清理目标不重试。验证通过后同步 README 的简短边界说明，按白名单提交并推送。
