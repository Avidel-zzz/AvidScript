# P66.B 进展：C# 方法组与委托调用

## 可执行范围

普通 C# 源码中的静态方法组现在可以构造委托，在 Guest 内作为局部变量、参数和返回值传递，再通过既有受检 `call_indirect` 执行。覆盖封闭泛型 `Func`/`Action` 和用户声明的委托；目标必须是参数与返回类型精确匹配、可达且有函数体的 Guest 方法。无捕获局部函数也可作为目标。这个范围内的值不需要堆环境。

已执行验证：运行时选择多个目标、循环内重复调用、重新赋值、ref/out 写回、void/Int32/Int64 返回、空值分支、委托递归。命名参数按源码顺序求值，再按绑定参数 ordinal 排列；默认参数继续使用 Roslyn 投影的实参。Invoke 参数身份保留封闭泛型信息，避免不同泛型实例混用原始泛型参数身份。

Semantic Schema 保持 21，Semantic Version 升至 1.24。新增稳定的 `delegate_creation` 操作；Guest 继续读取 21/1.23 的已有功能，但拒绝把新委托执行操作伪装成旧版。当前缓存、prepared semantic、脚本类型生成入口同步到 21/1.24。Guest IR 保持 3/1.2。

## 集成边界

- 可达性分析原本递归处理方法引用；本次执行测试证明仅通过方法组引用的目标也能保留。最终函数引用合同由实际生成的 `function_ref` 指令汇总，类型与目标排序确定。
- 调试恢复候选排除被 `function_ref` 引用的目标，避免将同步被调函数替换为不兼容的恢复入口。此项验证是插桩后的编译与合同有效性，不是完整委托调用栈调试验收。
- 数据通道合并已有的副作用白名单会在间接调用处结束分组；WASM 后端在调用前刷新 array region。没有允许优化跨未知调用移动副作用。
- 静态状态（包括嵌套结构/数组）、Host import 和入口签名不得携带模块内函数引用。该限制防止原始槽跨 Session/reload 迁移；不是最终的委托持久化或回调所有权方案。

捕获环境、绑定实例、lambda、泛型方法专门化、协变适配、返回引用、多播/event 与跨 await 委托状态仍未完成。非法绑定、伪造实参身份/类型及当前不支持的环境返回明确诊断，不以栈地址模拟逃逸闭包。
