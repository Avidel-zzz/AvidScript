# P66.C2：封闭泛型类型与方法的执行合同

## 当前缺口与目标

在提交 `259b3ff5` 上，用固定 .NET SDK 8.0.416 重新分析普通 C# 源码 `static T Identity<T>(T value) => value`，再从导出入口调用 `Identity<int>(7)`。Frontend 和 Semantic 成功；Semantic 的调用保留定义方法 ID ``symbol:method:global::Script.Identity`1(T):T`` 与有序实参 `type:int32`，方法签名、形参和函数体仍使用 `type:T`。Guest 失败：`ASCG1004` 指出形参 `type:T` 与调用返回没有可执行表示，同时出现导出函数缺失的 `ASCG1002`。这证明源码绑定信息已存在，但没有封闭函数实例，不能把诊断改成放行。

本组目标是让同一份普通 C# 源码在 .NET 与真实 WASM 上得到相同结果；同一个泛型定义的不同封闭实参必须形成不同函数，递归调用同一实参则回到同一函数。首个实现面限定静态方法和已能表示的参数/返回布局；泛型类型的实例状态、开放委托、异步泛型方法与任意 .NET 泛型库不因本组自动获得支持。

## 版本化身份与投射

1. **定义身份与实参。** 保留现有 `SemanticOperation.SymbolId` 的方法定义身份和 `TypeArgumentIds` 的声明顺序；Semantic 另输出方法定义的有序类型形参身份，不能从方法名、`T` 字符串或参数签名猜测顺序。封闭实例键是 `(definition method ID, ordered concrete type IDs)`，稳定实例 ID 由该元组编码；`Identity<int>` 与 `Identity<float>` 必须不同，重复的 `Identity<int>` 必须相同。
2. **实例内容。** 在 Roslyn 投射、闭包归一化之后且 reachability 计算之前，按调用图建立封闭实例。每个实例有替换后的 callable、形参和局部 symbol、方法体与 CFG；返回值、局部/临时值、操作类型、调用目标以及调用实参合同使用同一替换映射。原定义仍保留为源码事实，但不能作为带 `type_parameter` 的可执行函数降低。源码 span 保持原声明与调用位置，供诊断和调试映射使用。
3. **组合类型。** `SemanticTypeRegistry` 的数组形状记录元素类型；schema 31 又为命名泛型记录定义身份和有序类型实参。单维 `T[]` 与具备定义字段布局的 `Pair<T,U>` 等值类型按结构事实寻找已登记的封闭类型。不能通过对子串 `T` 做文本替换；缺少定义布局或仍为开放类型时明确拒绝。
4. **闭包与派发。** 初版只封闭同步静态方法。含捕获的局部函数、方法组、虚/接口派发、实例泛型类型或跨 await 状态一律保留精确拒绝；后续支持时，环境布局与派发槽必须按同一实例键投射，不能共享定义方法的开放 `T` 布局。

## 有界展开与校验

- 模块最多 128 个封闭实例，展开链最多 16 层。相同键递归是固定点，不重复生成；实参不断变化的递归在预算用尽前以源码位置诊断失败。输出按实例 ID 排序，构建不依赖发现顺序。
- 新 Semantic 合同必须升级语义版本；若增加实例集合或结构化类型节点，则同步升级 Schema。Guest 只接受版本匹配、定义存在、实参数量正确且全部封闭、实例 ID 与元组一致、形参/返回/CFG 无剩余开放类型的产物。旧产物可按原合同读取，但不得靠改写版本号冒充新实例。
- reachability 从导出、UE 函数和回调根走封闭调用目标；未被调用的开放定义不得被当作 Guest 函数，也不得因兼容性 `all_callables` 模式被意外执行。未知调用目标、重复键、冲突的实例布局和超限实例均 fail-closed。
- Guest IR 为每个封闭实例生成独立函数与类型化调用；WASM 函数索引、调试映射和状态 Schema 使用实例身份。函数的参数/返回 ABI 与既有 Guest 布局一致，不引入 CLR 或运行时泛型字典。

## 同源验收样例

| 源码行为 | 必须检查 |
| --- | --- |
| `Identity<int>(7)` 与 `Identity<float>(2.5f)` | 两个实例键、不同函数、.NET/WASM 结果分别相等 |
| `Pair<T,U>` 分别传入 `<int,float>` 和 `<float,int>` | 形参顺序、两个不同布局、无 ID 碰撞 |
| `Forward<T>` 调用 `Identity<T>` | 闭包替换后的二级调用仍指向正确封闭实例 |
| `Bounce<T>(n, value)` 以原实参递归 | 只生成一个实例，有限调用正确返回 |
| `ref T` / `out T` 与受支持结构体/引用 | 地址、别名、返回和布局与同源 .NET 一致 |
| 开放类型、未支持布局、变化实参递归、预算超限 | Semantic/Guest 在源码位置拒绝，不发布部分模块 |
| 篡改实例 ID、实参顺序、类型映射或版本 | 输入校验拒绝，不让旧产物冒充新执行计划 |

每个正例同时检查 Semantic 正反合同、Guest IR 函数和调用、实际 WASM 返回值；跨对象引用与生命周期再用 Wasmtime JIT、WAMR Interpreter 及 Win64 Editor 组合验证。

## 首个实现切片

首个切片采用 schema 30 / semantic 1.36：方法定义输出有序类型形参，可达的同步静态封闭调用输出由定义 ID 和实参 ID 哈希构成的实例 ID，并克隆替换 callable、形参/局部符号、方法体和 CFG。Guest 验证实例身份、实参顺序、布局和可达图，再生成独立函数。未调用的开放定义不进入可执行 reachability；直接递归复用同一实例。单模块最多 128 个实例，展开链最多 16 层。单维 `T[]` 通过元素类型形状寻找已由 Roslyn 登记的封闭数组类型；多维数组及当时尚无结构化布局的命名泛型在源码位置拒绝。

固定 SDK 8.0.416 的 Semantic 回归 `373/373`、Guest 回归 `483/483`、预处理语义合同 `13/13`、发布合同 `14/14`、语义缓存集成 `8/8`、构建集成 `15/15` 通过。运行 `pwsh -NoProfile -File Tools/AvidScript.CSharpGuest.Tests/RunGenericMethodsComparison.ps1 -DotNetPath <固定SDK的dotnet.exe>`，同一份 [C# 源码](../../Fixtures/Phase66/GenericMethods.cs) 在 .NET 和真实 WASM 的七个导出结果逐项相同：`7`、`2.5`、`3`、`4`、`12`、`57`、`5`。后两项覆盖 `ref/out T` 与单维 `T[]`；篡改实例实参、数组返回布局或降版为 1.35 的产物被拒绝。

## 第二增量：命名泛型值类型

schema 31 / semantic 1.37 为命名泛型类型增加 `generic_definition_type_id` 与有序的 `generic_argument_type_ids`。Roslyn 投射原定义和封闭实例；Guest 以原定义字段和实参映射构造封闭 `struct` 布局，字段写入沿值类型左值链写回。输入校验拒绝缺失实参、重复的结构化身份、类型形状循环和把新字段降版为旧合同。schema 30 / semantic 1.36 的旧封闭方法产物保持可读；旧产物不携带 schema 31 的形状字段。

同一份 [C# 源码](../../Fixtures/Phase66/GenericMethods.cs) 新增 `Pair<int,float>`、反序 `Pair<float,int>` 和嵌套 `Pair<Pair<int,float>,int>`；它们在 .NET 和实际 WASM 的返回值分别为 `7`、`9`、`7`。固定 SDK 8.0.416 下，同源对照 **10/10**，Semantic **373/373**、Guest **484/484**、预处理语义合同 **13/13**、发布合同 **14/14**、语义缓存集成 **8/8**、构建集成 **15/15** 通过。

在第二增量结束时，泛型引用对象的实例状态、闭包/委托、异步泛型方法、无定义布局的命名类型、多维数组及 Win64 Editor/双 VM 组合验收仍未完成；C3/C4 按 [P66.C 计划](P66.C_Language_Execution_Plan.md)推进。Android/Mac 真机暂缓。

## 第三增量：泛型引用对象的字段状态

保留 schema 31 / semantic 1.37 的结构化类型形状。Guest 对源码声明、直接继承 `object`、没有初始化器或虚成员的封闭泛型类，以原定义的字段和有序实参生成独立的托管对象布局。隐式无参构造可按原定义的构造器身份创建封闭对象；带方法体的构造器仍在专门化前拒绝。开放定义不生成对象布局，缺少封闭字段类型的产物也不发布。

[同源样例](../../Fixtures/Phase66/GenericMethods.cs) 新增 `Box<int>` 的两个独立实例和 `Box<Pair<int,float>>` 的嵌套字段写回；.NET 与实际 WASM 返回 `94`、`8`，全部 **12/12** 匹配。Node 测试 Host 按 `avid_managed_heap_v1` 的 packet 合同提供对象字段读写，并断言每次导出后 frame/root 清空；Guest 回归 **485/485** 通过。此对照验证 Guest/WASM 执行，不替代 UE 内 Wasmtime/WAMR 对生产 Host 的验收。

第三增量结束时，C2 仍缺泛型类自定义构造器与实例方法、闭包/委托、async 泛型、多维数组和 Win64 Editor 双 VM 组合。C3/C4 的错误清理和结果任务也尚未完成；Android/Mac 真机继续暂缓。

## 第四增量：泛型类构造器与同步实例方法

保留 schema 31，语义版本升为 1.38。源码泛型类的类型形参和成员方法的类型形参按声明顺序组成实例键；调用点同时记录封闭的类实参与方法实参，构造表达式也记录类实参。Semantic 把可达的同步、非虚类成员投射为独立 callable、符号、方法体与 CFG，并把接收者的 `ContainingTypeId` 替换成封闭类。原定义不进入可执行 reachability。泛型结构体成员保持旧路径，尚不按类对象布局专门化。

[同源样例](../../Fixtures/Phase66/GenericMethods.cs) 增加 `MemberBox<T>(T value)`、`Read()`、`Store(T)` 与类内部调用 `Relay() => Read()`。`MemberBox<int>` 的两个对象和 `MemberBox<Pair<int,float>>` 的嵌套值在 .NET 与实际 WASM 分别返回 `94`、`8`；全套导出 **14/14** 相同，聚焦 Guest 测试 **5/5**。校验会拒绝篡改封闭接收者布局、把新产物降版为 1.37，以及类/方法同名类型形参造成的身份碰撞。schema 30 / 1.36 的静态泛型方法与 schema 31 / 1.37 的静态方法产物保持读取支持。

固定 SDK 8.0.416 的工作树验证：Semantic **373/373**、Guest **485/485**、预处理语义合同 **13/13**、发布合同 **14/14**、语义缓存集成 **8/8**、构建集成 **15/15**。WASM 对照使用 Node 测试 Host；Win64 Editor 的生产 Host、Wasmtime/WAMR 双 VM 与实际 Play 仍待独立验收。C2 的闭包/委托、async 泛型、多维数组及组合覆盖仍未完成，不能据此宣告 P66.C 完成。
