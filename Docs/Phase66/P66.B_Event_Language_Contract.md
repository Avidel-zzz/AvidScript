# P66.B：C# UE 事件 `+=` / `-=` 合同

本文件保留分步实施时的验证记录；其中“P66.B 仍进行中”指当时状态。当前批次裁定与后续验收边界见[批次验收记录](P66.B_Batch_Completion.md)。

## 开发者写法与完成条件

选中 UE 事件并生成绑定后，脚本可以直接写：

```csharp
AvidEventHandlers.OnScriptSignal handler = (actor, amount, scale) => Score += amount;
UE.Self.OnScriptSignal += handler;
UE.Self.OnScriptSignal -= handler;
```

这是已生成 UE 事件的可执行语法。普通 C# 源码经 Roslyn、Semantic、Guest IR 和 WASM，在 Windows 两后端的真实 UE 事件上验证了重复和组合移除、捕获变量、绑定实例方法、回调内增删、空处理函数、`ref/out` 写回、单播返回，以及事件源和处理函数各求值一次。同一 World 内两个有能力授权的 Actor 可分别订阅同一事件；各自保留回调根，移除其一不影响另一个。显式 `AvidSubscriptions.SubscribeOnScriptSignal(source, handler)` 可与同一多播事件的语言桥接并存，双方独立取消；单播的显式与语言绑定互相拒绝第二个占用，保留原桥接。无效默认代理、跨 World 源和已释放句柄都被拒绝而不发布桥接；跨 World 测试先授予对象能力，单独验证 World 边界。活动桥接在 Session 停止、World 清理及源 Actor 销毁后的 GC 中解绑并释放回调根。无效重载候选保留旧桥接；成功提交新模块后，旧桥接解绑，新 Runtime 可重新订阅。复杂对象图迁移、更多多源/多事件组合和真实游戏长时间运行仍待验证，不能把当前局部闭环称为 P66.B 全部完成。

当前进度：生成器已输出强类型事件；Semantic 30/1.34 已验证 `+=`、`-=` 的事件身份、owner 和处理函数类型，并拒绝伪造或非生成事件。Guest helper 复用具体状态盒和委托列表。生成的 C# 事件 fixture 1/1、完整 Guest 回归 468/468、no-clean Editor 构建和真实 UE 聚焦 Automation 1/1 通过；后者在 Wasmtime JIT 与 WAMR Interpreter 上覆盖上述委托行为、同 World 双源独立订阅/取消、跨 World 与失效代际拒绝、取消及源 Actor 销毁后的 GC 回收、重载候选的拒绝/提交路径。Session 停止在 Wasmtime、World 清理在 WAMR 路径验证；其他语义组合仍以本文完成条件为门槛。

嵌套广播增量：已生成的 C# 语言事件桥接允许有界的、无返回值的 UE 多播回调在当前 Guest 调用内再次进入同一 Session。例如外层 `OnScriptSignal` 收到 `2`，处理函数再次广播 `3`，两个回调都会执行；外层为 `ref/out` 事件时，内层无返回值广播不会覆盖外层写回事务。独立 Session 的 Wasmtime JIT / WAMR Interpreter 真实事件测试及 DelegateSubscription Automation 14/14 通过；共享 Runtime 回调、Session prepared 派发各 1/1 回归通过。显式 token 订阅、生成类型入站函数和带输出值的嵌套事件仍保持原有重入限制；深层递归只受入口深度上限保护，业务代码仍需终止条件。共享 Runtime 上下文的更多嵌套组合及长时间运行尚未验收。

## 事件回调跨 await

生成的事件可以接收 `async void` 处理函数。下面的 `amount` 在回调返回后仍保留到下一帧；收到 `2` 时最终共加 `22`：

```csharp
using System;
using AvidScript;

public static class ScoreScript
{
    public static int Score;

    static async void OnSignalAsync(AActor actor, int amount, float scale)
    {
        int bonus = amount;
        Func<int> readBonus = () => bonus;
        Score += readBonus();
        await AvidContinuations.NextTickAsync();
        Score += readBonus() * 10;
    }

    public static void Start() => UE.Self.OnScriptSignal += OnSignalAsync;
    public static void Stop()  => UE.Self.OnScriptSignal -= OnSignalAsync;
}
```

此组合以生产生成 facade 编译的 C# WASM 和真实 UE 多播事件，在独立 Session 的 Wasmtime JIT、WAMR Interpreter 路径验证：挂起期间强制 GC 保留闭包，恢复并退订后释放根；无效重载候选保留旧订阅与等待，成功重载退休两者，Session 停止取消剩余等待。

生成类型生产 Host 的共享 Runtime 路径现在也从 C# `[UClass] EventReceiver` 的 `[UFunction] StartEventAwait()` 进入：编译器给出类型 ID、方法 ID、ordinal 与 WASM 导出，注册表用这些元数据核对已有的原生测试壳；方法体通过 `UE.Self.OnScriptSignal += Script.OnSignalAsync` 订阅。两个同 World Actor 分别挂起后，脚本静态分数先累计 `2 + 3 = 5`。结束第一个实例会释放它的事件桥接和等待根，第二个实例继续恢复自己的 `3 × 10`，分数成为 `35`。Wasmtime JIT 与 WAMR Interpreter 都通过了这条生产 Host 调用路径。独立 Session fixture 与 `[UClass]` fixture 分别编译：前者没有生成类型 receiver import，后者只在具备生成类型授权的 Host 中加载。

对象销毁/GC 增量：同域两个 Actor 的事件回调都已挂起时，销毁其中一个并运行 GC，生产 Host 在下一次 Game Thread CoreTicker 扫描中退休它的 Session、回调和等待根，不对失效 owner 调用 Guest `EndPlay`；另一个 Actor 继续恢复，最终分数仍为 `35`，强制 Guest GC 后只留幸存事件的一个根。修复前 Host 遗留销毁实例；直接调用失效 owner 的 Guest `EndPlay` 又会把共享域一起隔离。

共享域包级重载增量：两个 C# `[UClass]` Actor 的事件回调同时停在 `await` 时，注入“已准备一个实例后失败”的候选，Host 逆序丢弃候选；旧共享 Runtime、两个事件桥接及等待继续工作，peer 再次广播也能增加分数。随后发布同结构包，两个旧等待和桥接一并退休，旧 VM 租约失效；推进旧 Timer 不改变新域静态状态，新域 GC 无遗留事件根，两个 Actor 可重新订阅并各自恢复。此路径用生产 Host、真实 UE 多播和编译后的 C# WASM 在 Wasmtime JIT / WAMR Interpreter 上通过，Win64 no-clean Editor 构建与聚焦 Automation **1/1** 通过。当前测试仍使用预先存在的原生测试壳；从 C# 自动生成、编译并安装该壳的完整 Editor 流程、其他迁移形状及真实玩法长时间运行尚未在此组合中验收。

后续已打通正式生成壳组合：[五类型 C# 样例](../../Samples/CSharp/ScriptDefinedTypes/README.md)中的 `Projectile.StartOverlapAwait()` 从 C# 自动生成 UHT 壳、编译 WASM 并发布 Win64 包，订阅真实 `AActor::OnActorBeginOverlap`。回调先把 `OverlapScore` 写成 `2`，跨 `NextTickAsync()` 恢复后成为 `22`；同域两个 Actor 同时等待，销毁其一后只有另一个恢复。编译器为无源码的订阅桥接保留 WASM 索引而不伪造 source map；发布器只接受与绑定包事件 ID/ordinal 一致的回调导出，并逐一验证编译器桥接导入的身份和签名。Guest 回归 472/472、生成类型 Automation 10/10、typed owner 权限 1/1、no-clean Win64 Editor 构建通过。

正式生成壳的包级重载现也有聚焦 Automation 1/1：两个 `Projectile` 事件回调同时等待时，准备一个候选后注入失败，回滚保留两边的旧订阅与等待；随后以同反射形状的正式包成功重载，旧桥接和续执行均退休。再次广播不触发旧处理函数，两个 Actor 重新订阅后只运行新回调，销毁其中一个不会恢复到失效对象。早期包级重载 fixture 仍提供双后端更广的根和候选事务检查。

不同代码版本也已用正式 C# 生成入口在 Win64 Editor 自动化中验证：候选源码仅把 `OnOverlapAsync` 恢复后的 `bonus * 10` 改为 `bonus * 20`，原生反射结构哈希不变，包 ID 不同且分类为 `body_only`。注入失败后，旧包的两个等待仍在；成功切换后，旧等待与桥接均取消，重新订阅后幸存 Actor 的分数从即时 `4` 变为 `44`，证明实际运行的是新方法体。复现入口是 `Build/Contracts/TestGeneratedCSharpEventVersionReload.ps1 -BindingPackageManifestPath <已生成的绑定包 package.json>`：它在工程 `Saved/AvidScript/GeneratedEventVersionReload/` 下先构建基线，再构建候选，核对当前安装包、结构哈希、前后包 ID 与分类，分别在 `Game` 和 `PIE` 类型的测试 World 中运行聚焦 Editor 自动化，保留两份唯一日志；本次 **2/2** 通过。需预先完成 no-clean Editor 构建和样例绑定包生成。该 Editor 候选使用正式生成链的 Wasmtime JIT 模式；跨进程预编译产物在非发布包加载路径会因会话证明失效而被拒绝，不应为测试关闭证明检查。测试创建 PIE 类型 World，不等于人在 Editor 点击 Play 并操作关卡；后者、Cook/Shipping 版本切换和长时间运行仍待后续集成验收。P66.B 冻结范围的最终裁定见[批次验收记录](P66.B_Batch_Completion.md)。

## 语义和所有权

- `+=`、`-=` 都只求值一次事件源和右侧处理函数。空处理函数不改变订阅。错误源、跨 World、错误代际或错误签名必须拒绝，不能绑定别的 Actor。
- 同一 Session、执行域、源和事件 ordinal 最多有一个**语言事件**桥接项。它持有具体类型的状态盒；状态盒中是当前组合委托和取消 token。`+=` 按顺序追加，`-=` 使用现有 C# 委托相等与“移除最后一个匹配子序列”的规则。重复方法组、绑定接收者、同一闭包实例和组合列表必须与这些规则一致。
- UE 单播事件也只占一个桥接项；组合委托依次运行，非 `void` 时最后一个处理函数的结果写回 UE。原有单播绑定占用同一源和事件时，新语言事件添加应明确失败；不静默替换已有订阅。
- 原有显式 token 订阅与语言事件桥接分开标记。查找语言状态不能选中显式订阅，更不能移除它。不同源、事件、World 或执行域互不共享处理函数列表。
- 事件派发先取当前委托快照。处理函数在回调内添加或移除处理函数，只改变下一次派发；当前调用和被取消的状态保持根租约到回调退出。取消最后一个处理函数时解除桥接并释放根。对象 GC、Session/World teardown、候选丢弃和重载提交沿现有 owner 路径释放。
- UE 多播上各 C# 处理函数的顺序必须稳定。一个桥接项不承诺它们与其他系统独立绑定到同一 UE 多播事件的处理函数交错顺序；该边界需在用户文档明确。

## 分层实现

1. **生成接口。** 为被选中的 UE 事件在其对象代理上生成强类型 C# `event`，保留现有显式订阅接口。事件声明携带稳定事件 ID、ordinal、签名和 owner 类型合同；成员名碰撞或不支持的参数方向在生成时失败。
2. **Semantic。** 识别 Roslyn `IEventAssignmentOperation`，区分 add/remove，绑定到生成的事件合同。源表达式和处理函数表达式只投影一次。伪造事件、静态/实例不符、签名不符、非选中事件或不支持的 accessor 都给定位诊断。新增合同须升级 Semantic Schema，并保留 29/1.33 读取；旧文档不能携带新事件赋值。
3. **Guest。** 复用现有委托组合、精确身份比较与最后子序列移除逻辑。编译器生成每事件 add/remove helper，使用具体状态盒，不让用户管理堆 token。既有显式订阅的 `_state_v1` 回调 ABI 继续兼容。
4. **Guest IR / Host。** 增加版本化的语言事件状态查找及语言模式订阅操作，按 `(Runtime, Session, source handle, ordinal, concrete box type)` 校验。查找仅返回同域、同源的语言桥接状态；没有桥接时返回空。Host 必须把返回的对象保活到 Guest 帧根建立，旧 IR 不得使用新操作。首次 `+=` 创建状态盒和桥接，后续 `+=` / `-=` 原地更新其不可变委托值；最后一次 `-=` 解除桥接。订阅发布和失败回滚不能留下半绑定状态。
5. **验证。** 先固定生成源码与 Semantic/IR 正反例，再用生产生成 facade 编译 C#，最后在 Wasmtime JIT 和 WAMR Interpreter 上由真实 UE 单播/多播事件检查结果。覆盖重复添加与最后一次移除、组合列表子序列、静态/实例/捕获处理函数、回调内移除、`ref/out` 和返回值、错误源、GC、取消、重载候选及 teardown。记录自动化和真实玩法验收的不同范围。

先验证上述状态查找能安全保活到 Guest 帧，再公开生成的事件成员；不能把仅能 `+=`、`-=` 删除全部处理函数或重订阅后改变处理函数身份的捷径称为完成。
