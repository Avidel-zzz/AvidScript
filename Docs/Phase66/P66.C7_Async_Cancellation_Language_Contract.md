# P66.C7：异步取消的语言语义

状态：Semantic **44/1.53** 内部预览、Runtime 取消异常接口，以及 Guest IR **24/1.23** 的 ABI 校验与 WASM 生成已实现。C# 到 Guest/WASM 的取消分派仍未接通。P66.C 继续实现，Windows 优先。

## 问题与目标

Semantic 42/43 把取消直接送到清理入口，跳过所有 `catch`。这足以执行 `finally`，但不符合以下 C# 代码的预期：

```csharp
try
{
    int result = await LoadAsync();
}
catch (OperationCanceledException)
{
    // 取消已处理，方法可以继续执行或返回结果。
}
finally
{
    Cleanup();
}
```

本项的完成目标包括：直接 Timer await 与 Task await 的类型匹配、取消的重新抛出、`finally` 顺序、捕获后的继续执行、未捕获取消的语言诊断，以及 Task/取消对象/状态帧的生命周期回收。实现必须通过同源码 .NET 对照和 Win64 双后端执行，不能用 Semantic 测试代替运行结果。

## 取消对象与所有权

- Timer 的显式取消采用 `TaskCanceledException`；其继承关系为 `TaskCanceledException → OperationCanceledException → SystemException → Exception`。这与本仓库 .NET `Task.WaitAsync(token)` 适配器的实际结果一致。
- Task 传播取消时保留取消异常的类型、来源和对象身份；同一 Task 被重复等待不能生成不同的异常对象。Task 终态仍为 `Cancelled`，不得为了进入 `catch` 改成 `Faulted`。
- 有匹配的 `catch` 时，源顺序中的第一个匹配分支执行。正常离开 `catch` 消费当前异常 owner，允许后续再次 `await`；`return` 经过必要清理后完成 Task。
- `throw;` 保留当前异常，离开当前 handler，执行当前层 `finally`，再进入外层分派。不得重新进入同级 handler。
- `finally` 抛出的新语言异常替换原取消；该情况仍需接入新合同。现有 43/23 的清理抛错回归继续保留。
- Host 错误、VM trap、非法 completion 状态不可被语言 `catch` 捕获。World/Object teardown 与退休实例不恢复 Guest，由 Session owner 回收。

Guest 侧接续实现必须使用下述独立接口；不能复用仅接受 `Faulted` 的读取接口，也不能用一个类型编号代替实际拥有的异常对象。

## Runtime 与 Host ABI

Runtime 的 language-error catalog 已为 **Guest IR 24/1.23** 接入取消合同。Guest IR validator、规范化序列化和正式 WASM backend 现已接受该版本的 ABI 模块；C# lowerer 仍以 **ASCG1004** 拒绝 Semantic 44，尚未生成取消处理控制流。

| 新导入 | WASM 签名 | 行为 |
| --- | --- | --- |
| `avid_task_cancel_language_error_v1` | `(i64, i32, i32, i64) -> i32` | Task、类型 token、源码 token、对象 token；成功后 Task 为 `Cancelled` |
| `avid_task_terminal_error_meta_v1` | `(i64) -> i64` | 读取 `Faulted` 或 `Cancelled` 的异常元数据，高 32 位类型、低 32 位源码；不新增根 |
| `avid_task_terminal_error_root_v1` | `(i64) -> i64` | 返回原异常对象，并在当前 VM 调用帧中持有它，直到该帧退出 |

这三个接口仅接受具有配对 catalog/provenance 的 IR 24/1.23 模块，且只注册在 `avidscript` 模块。旧 IR 17、20–23 调用时返回 `task_language_error_version`；旧的 fault 接口与仅限 `Faulted` 的读取接口在 IR 24 中仍保持原语义。

取消提交依次验证 Session、Task 类型、catalog token、取消异常类型和当前调用帧的根。支持的取消类型为 `TaskCanceledException` 与 `OperationCanceledException`；普通 `Exception` 不能冒充取消。提交成功后 Task 持有 persistent root，重复完成失败时释放本次尝试的临时租约。`avid_task_propagate_failure_v1` 在两个 Task 间共享该租约，保留 `Cancelled`、原类型、源码位置和对象身份。旧的无载荷取消仍可传播，新读取接口不会为它凭空生成异常。

最后一个 Task/等待者释放后回收异常对象；读取方已取得的调用帧根可继续存活至帧退出。prepared 丢弃只释放候选，提交会退休旧代次，teardown 清除排队的取消等待者且不重新进入 Guest。

## Guest IR 与 WASM 接口校验

[`GuestTaskCancellationErrorValidator`](../../Tools/AvidScript.GuestIr/Validation/GuestTaskCancellationErrorValidator.cs) 是 IR 24 的版本与取消接口 owner，诊断码为 `ASIR1032`。新版本必须配对 Semantic 44/1.53、非空异常 catalog、三个新接口，以及原有完整 Task 和 fault 接口。旧的 fault-only 读取接口仍可成对声明，语义不变。

取消生产者必须传入 catalog 中的 `TaskCanceledException` 或 `OperationCanceledException` 类型常量和源码常量。两者均须在调用前于同一基本块定义，且不可被重复定义、赋值或取地址。异常对象必须刚在当前调用帧中分配，`field:code` 与提交类型相同。普通异常、名称相似的用户类型、未知 token、未持有的对象、`env` 别名、缺失/重复接口及降版产物均被拒绝。托管引用只能通过规定的取消与终态读取接口跨边界，不能借新版本导入任意对象指针。

ABI 夹具由 [GuestTaskCancellationFixture.cs](../../Tools/AvidScript.GuestIr.Tests/GuestTaskCancellationFixture.cs) 构造，供 IR 与 WASM backend 测试共同使用。它包含取消、故障和重复读取函数；正式 backend 保留类型目录、源码位置和 `guest_ir=24/1.23` 身份，规范化序列化前后产生相同 WASM。该夹具不是 C# 编译产物，也没有实现 handler 路由。现有 IR 22/23 的路由元数据不能直接改版本后冒充新取消分派。

## 已实现的 Semantic 合同

仅内部 `SemanticAnalyzer.Analyze` API 的 `enableAsyncCancellationFlow: true` 启用本预览，同时要求 `enableAsyncExceptionFlow: true`；直接 Timer await 还需 `enableDirectAwaitCleanup: true`。正式 CLI 尚未开放新开关。

`SemanticAsyncExceptionPlan` 新增：

| 字段 | 用途 |
| --- | --- |
| `cancellation_type_id` | 取消的默认异常类型，由 Roslyn 注册完整父类链 |
| `exception_scopes` | 每个 try 的 Roslyn 区域、handler 顺序、父区域、分派入口与向外清理入口 |

新增三种控制转移：

| 转移 | 行为 |
| --- | --- |
| `end_catch` | 消费已处理的异常 owner，然后进入正常后继 |
| `rethrow` | 将已处理状态恢复为未处理状态，保留故障/取消种类并向外转移 |
| `propagate_exception` | 在方法边界传播未处理异常，保留 Task 的故障/取消终态 |

Task 的故障和取消进入同一个有序分派入口；直接 Timer await 只有正常和取消出口，仍不声明语言故障出口。reader 根据独立 scope 元数据核对入口、handler 类型、清理顺序和父区域，并检查所有权状态：未处理取消不能进入正常返回，已处理异常不能带着 owner 进入下一次 await。空 catch 也有明确的消费节点。

旧 42/43 合同、默认编译路径和已有 WASM 行为保持原定义。旧版本夹带新字段或转移、新版本缺失 scope/类型、伪造成功入口、跳过 handler、绕过 finally、错误 rethrow 均拒绝。Guest 编译入口对 Semantic 44 返回 **ASCG1004**，普通模式与 bounded 模式均不产生 Guest module。
