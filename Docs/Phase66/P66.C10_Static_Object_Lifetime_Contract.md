# C10 前置：静态对象初始化与生命周期

原始 [AwaitMemberAssignment.cs](../../Fixtures/Phase66/AwaitMemberAssignment.cs) 通过
`Original`、`Replacement`、`Current` 静态字段保存对象。同步源码已通过专用编译 API 接通静态初始化，
但普通构建及原始 C10 所需的异常、异步组合仍未开放；完整支持须满足以下合同。
本项属于 P66.C10，不改变 P66.C/P66.D 的完成条件，Windows 优先。

## 所有权与存储

- 静态对象由执行域的 `FHeap` 保活。独立 Session 持有独立堆；生成类型沿用包/World/registry 共享执行域。
- 函数返回、异常展开、单个共享实例退出不能清空域静态字段。最后实例退出或整个域失效时，由堆关闭统一释放。
- 静态槽保存经 owner、代际和类型检查的对象 token。槽编号是声明顺序对应的 1-based ID，不是 root token 或内存地址。
- 槽本身是 GC 根，独立于函数帧和普通 root token 表。Guest 的 `SetRoot`、`ReleaseRoot`、`Allocate` 不能取得或删除槽的根。
- 静态槽与局部/原生租约共同占用 `MaxRoots`。每个槽即使为 null 也占一个根预算，初始化失败不得部分占用预算。
- 替换槽值后，旧对象只有在其他根仍引用它时才存活。清空最后引用后，下一次 GC 回收整张不可达对象图，包括环。

## Heap v1 扩展

保留已有 1–13 命令及包头；新增命令由旧 Runtime 按 unknown command 拒绝，不改变旧包的解释。

| 命令 | 编号 | Header 后的请求 | 响应 |
| --- | ---: | --- | --- |
| `ConfigureStaticSlots` | 14 | u32 count，随后 count 个 u32 target type | 无 |
| `ReadStaticSlot` | 15 | u32 slot，u32 expected type | u64 object token |
| `WriteStaticSlot` | 16 | u32 slot，u32 expected type，u64 object token | 无 |

每个堆只能成功配置一次，配置必须在 heap layout 配置后执行。数量为 1–4096，并受剩余根预算约束。
类型必须在本堆 layout 中存在，0 表示 erased reference。读写的 expected type 必须精确等于该槽声明，
写入对象还必须满足声明的目标类型；null 可以写入任何槽。未知槽、外域或过期对象、错误类型、截断包、
多余字节及错误输出长度均拒绝，失败写入保留旧值。

嵌套导出可以读写相同执行域的静态槽，仍不能操作调用者帧根。WASM start function 继续禁止访问 heap ABI。
堆关闭幂等，静态槽计数、总根数、对象数和帧数归零；旧 token 不能用于同地址重建的新堆。

## 编译器接入顺序

1. 实现原生静态槽、协议和所有权负例测试。本步骤不开放 C# 静态对象字段。
2. 增加版本化 IR 静态槽描述及 typed get/set，校验、序列化、WASM emitter 同步支持。槽不进入可复制的线性内存 state slots，禁止通过普通 global/地址别名绕过根维护。
3. 从 Roslyn 投影静态字段初始化和显式静态构造函数，保留声明顺序、依赖调用和 `NotStarted / Initializing / Ready / Faulted` 状态。重入可观察尚未赋值的默认值；初始化错误不得在下一次调用中被静默重试。
4. 同源 .NET/WASM 验证初始化顺序、跨调用替换、别名、循环依赖和失败路径；再用 Wasmtime/WAMR 及共享生成 Actor 验证 GC、最后实例退出、World teardown 与重载。

成功重载使用新执行域，辅助类静态对象不作为原始 token 迁移；失败候选销毁自身堆，旧域继续保存原对象身份。

### IR 27 静态存储合同

`schema_version=27`、`ir_version=1.26` 增加必需的 `static_storage`：
`base_schema_version`、`base_ir_version` 指明已有执行合同，`slots` 为有序的 `{ id, type_id }` 声明。
当前基础版本只接受已支持的 IR 4–26 及其精确版本对，不允许自身嵌套或未来版本。
Task、异常、取消等仍完整执行基础版本的校验和 Semantic provenance 配对；静态槽不能作为绕过这些检查的开关。
旧 IR 省略本字段并保持既有序列化字节；缺失声明、在旧版本偷带声明、非法基础版本均拒绝。

槽数量为 1–4096，ID 与顶层标识符不得重复，类型必须是已声明的 `managed_ref`。
槽顺序决定 native 1-based ordinal，不进入 `globals`、`data_segments` 或 `state_slots`。
`managed_static_get` 无操作数、返回槽的精确类型；`managed_static_set` 无返回值、接受一个相同类型操作数。
两者的 `target_id` 必须指向槽；不支持原始地址、数字转换或不经过类型检查的别名。

WASM 首次进入需要托管堆的函数时，先配置 layout，再配置静态槽，最后标记 heap 已初始化。
读出引用后立即更新函数帧根，避免清空静态槽或后续 GC 丢失局部引用。普通函数退出仅释放帧根。
配置包与函数 scratch/栈布局统一分配，旧模块不新增静态配置包。

WASM provenance 保存外层 `guest_ir=27/1.26` 和精确 `guest_ir_base`；语言错误 catalog 仍记录真实外层版本。
Runtime 必须核对基础版本与 catalog/provenance 的对应关系，再启用原有 Task 错误和取消能力。
未知或缺失的基础版本、与旧外层版本混用的基础声明，以及必需 catalog 缺失均拒绝。

## C# 源码投影合同

Semantic 49/1.58 记录静态存储、初始化计划及字段访问的类型归属，并保留分析得到的基础 Semantic 版本。
该步骤由分析 API 的 `enableStaticInitialization` 显式开启，旧调用与旧序列化结果不变。
前序 Semantic 48/1.57 缺少封闭泛型字段归属，不能作为完整静态存储合同读取。
普通 `CSharpGuestLowerer.Lower` 入口继续拒绝这些源码计划。同步预览通过
`CSharpStaticInitializationCompiler.TryLower` 校验并组合初始化状态、逐调用错误结果和静态读写；
不能通过改回旧版本号发布一个忽略初始化的 WASM。

计划按类型记录所有非 const 静态字段，字段按编译输入中的源码声明顺序排列。
每个字段保留来源、源码摘要、位置，以及可空的初始化操作树与 Roslyn CFG；无显式初始化时取默认值。
多声明字段、partial 文件、条件表达式、方法调用及其他类型的字段引用不能被按名称排序或折叠掉。
显式静态构造函数通过原有 callable/body/CFG 或异常流合同引用，位于全部字段初始化之后。
没有显式静态构造函数的类型保留 `beforefieldinit` 标记，不把它与精确初始化触发时机混淆。
只有默认值、没有 Roslyn `.cctor` 的类型也记录静态存储计划；纯 const 类型仍不需要此合同。

每个非 const 静态字段访问都记录 `static_field_owner_type_id`。字段的 `symbol_id` 继续指向源码声明，
但 `Cache<int>.Value` 与 `Cache<long>.Value` 分别引用各自的类型，而不是只记录同一个 `Cache<T>.Value`。
继承访问使用字段真正的声明类型。泛型方法实例化时通过 Roslyn 构造并注册封闭类型；
例如 `Read<T>() => Cache<T>.Value` 的两个实例分别保留 `Cache<int>` 和 `Cache<long>`，不靠替换类型名字生成标识。

校验覆盖方法树、CFG、异步语句与 await 参数/接收者、异常流以及静态初始化体。
字段类型必须与所属类型的泛型实参代换结果一致；缺失、未知、错误归属和实例字段冒充静态字段均拒绝。
普通旧版本输入不允许携带此元数据，移除外层计划并修改版本号也不能发布被合并的静态存储。

源码投影只提供初始化内容和依赖，不把声明顺序当作跨类型初始化顺序。同步 lowering 按封闭泛型类型
分配独立状态，在静态字段读写、取地址、精确初始化类型的方法/构造调用处触发。
底层 guard 可把初始化错误保存为不可重试的 `Faulted` 状态；C# 抛错初始化体尚未接入该路径。
完整运行时验收仍以本合同前述 .NET/WASM 同源结果为准。
