# P66.C23：路径检查的 IO 成本

## 冻结范围

[C22](P66.C22_Cached_Build_Latency_Contract.md) 的两个源码指纹函数合计约 1.2 秒；每个源码文件都逐级检查路径是否经过 reparse point。现有实现每一级先调用 PowerShell `Test-Path`，再读取 .NET 文件属性。改用一次直接的 .NET 属性查询，并以 `Path.Combine` 组合已经规范化的路径片段，减少 provider 和 cmdlet 开销。

保持大小写比较、绝对路径规范化、根目录前缀、逐级 reparse 拒绝和合法未来输出路径的既有行为。Windows 盘符根拼接保留尾部路径分隔符，防止 `C:` 被当作盘符相对路径。不缓存文件属性或路径准入结果；每次调用重新读取所有已有层级。仅 FileNotFound/DirectoryNotFound 允许继续验证后续片段；访问拒绝及其他 IO 错误必须拒绝。新增明确拒绝已有文件被用作中间目录的非法路径。此 helper 不是整个文件系统的事务快照，不扩大原有并发保证。

写集为 binding package 路径 helper、两层工具链指纹 owner、路径合同测试、必要的缓存夹具与本节文档。两层指纹新增 binding package helper 的源码身份，规则改变会生成新键。不改变 C# 源码、语言 Schema、生成类型、UE Runtime 或执行字节。

## 验证

- 路径正反例：实际文件、大小写、缺失输出、根自身、同名前缀、父目录逃逸、文件充当目录、junction 与缺失的 junction 子路径；拒绝后原目标文件保持不变。
- 持有真实文件的独占句柄验证错误行为；能以元数据查询安全读取时仍允许，不能把文件打不开误作路径逃逸。
- 同一正式 Actor/Component 源码重新填充失效的缓存，再复用单一输出目录测双缓存命中；四工具为零、不启动 worker、无 fallback，六份执行产物必须与 C20 一致。
- 复用 C22 三样本入口及计时边界，分别记录冷构建与热样本；统计只用于构建成本诊断。受影响缓存合同核对 owner 改变使键失效。

串行 BelowNormal，固定已安装 SDK，不修改持久 PATH，不清理旧证据目录或用户/引擎产物。P66.C/D、真实 Editor Play、完整调试、跨语言 SDK、Windows 发布与竞品对测仍未完成。

## 实现结果

逐级检查现在直接使用 `File.GetAttributes`；没有共享路径缓存，每次仍检查已有层级。合法的缺失输出继续允许，junction、盘符根下的 junction、文件被用作父目录和无效路径片段均拒绝。补充盘符根用例时修正了 `Path.Combine` 的盘符相对路径边界，然后重新填充缓存并执行最终样本。

| 验证 | 最终结果 |
| --- | --- |
| 路径与两层 owner 身份合同 | 28/28；包含断开 junction |
| 原有 semantic cache key 合同 | 21/21 |
| 原有 semantic cache entry 合同 | 25/25 |
| 新键填充 | 成功；required worker 三阶段，无 fallback |
| 正式热构建 | 8/8；双缓存命中、四工具为零、未启动 worker |
| C20 六份原始产物 | frontend、Semantic、IR、debug、state、WASM 均一致 |

最终冷填充约 20.73 秒，与热样本分开记录。worker PID 在 idle timeout 后自然退出；没有结束用户进程。路径测试的私有 Scratch 已回收，最终测量复用 C22 的单一输出目录，没有按轮复制大型 Semantic。用户与机器 PATH 未变。

同样的 349 个实际工具链文件，隔离的路径检查三轮中位数从 772.89 ms 降至 76.25 ms。该实验只比较路径检查，不包含哈希、语义准入或构建发布，不能作为整个构建的加速比例。

| 无函数观测的正式热构建 | 三样本中位数 | nearest-rank P95 |
| --- | ---: | ---: |
| C22 基线 | 5,993.54 ms | 6,033.23 ms |
| C23 最终代码 | 5,370.17 ms | 5,386.33 ms |

这个固定玩法的诊断中位数减少约 10.4%，P95 减少约 10.7%；三样本 P95 是最大值，尚不是大规模性能验收。C23 有观测组中位数为 6,356.52 ms、P95 为 7,618.27 ms，慢样本全部保留，不能据此宣称所有路径和尾延迟都改善。

有观测组中，semantic 与 compilation 两个指纹函数的平均 inclusive 时间分别为 213.53 ms、242.79 ms，低于 C22 的 475.22 ms、728.76 ms。Semantic import 仍约 3.45 秒，其中准入约 1.63 秒；嵌套时间不能相加。PowerShell 峰值 working set 为 1,102.50 MiB，当前优化没有解决完整 JSON 对象物化的内存成本。

最终路径合同、隔离成本和冷填充记录位于 `%LOCALAPPDATA%/AvidScript/Verification/PathContainment/20261004T120334533Z-77213a24dd13428abaea197855e01c75/`；热构建原始报告位于 `%LOCALAPPDATA%/AvidScript/Verification/CachedBuildLatency/20261004T115541952Z-b6dd3d75/`。开发工作树仍有七个受保护修改，Harness 基线满足；本节是实现期反馈，未执行新 VM 或 Editor 验收，也不是 clean Gate。

下一步保留当前路径校验，继续处理完整 Semantic 读取与工具准备的成本；同时沿 P66.C 的语言合同补齐集合、泛型结果与清理组合。结构热重载、IDE 调试、第二语言和真实 Windows 玩法仍按长期路线推进。
