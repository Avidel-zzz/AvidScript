# P66.B：C# 实例方法参数帧

## 交付与边界

在[间接方法 ABI](P66.B_Indirect_Method_ABI.md)之上，真实 C# 方法调用现在由已验证的 UE 方法目录生成参数帧适配器。直接调用、属性访问器产生的调用、局部函数和绑定方法组 thunk 中对这些方法体的调用使用同一条 `call_framed` 路径。私有方法保持私有，不升级为 UFUNCTION。

**本组连接 C# 编译与当前 owner 的执行，不代表生产跨对象路由完成。** 目标仍是同模块的已选定方法体；不同 Session 的目标选择、virtual/interface、Host 返回前强制 GC 和根贷款授权仍待接入。原有虚/接口派发与引用返回拒绝保持，P66.B 继续进行。

## 参数与接收者

- 适配器从方法的稳定符号身份生成名称，核对目录与方法体的参数、返回值和传递方式。只为实际被 Guest 调用的同步方法生成；旧 Semantic 25/1.29 没有目录时保留原路径。
- 隐藏 receiver 统一为 `uint64` 弱句柄，适配器内部恢复声明类型后进入原方法体。原方法体的类型、owner、registry 与生命周期校验继续执行。统一表示不授予跨对象访问权限。
- 基类/派生类上具有相同参数与返回类型的方法得到相同帧签名；具体方法与代码身份仍独立。未来虚槽路由不能只凭这个签名选择目标。
- 值参数和含引用结构返回沿既有类型化帧布局处理；`ref/out/in` 使用 borrowed descriptor，保留即时别名写入。`ref readonly` 使用只读传递模式；不将引用返回变成值返回。
- 处理发生在闭包 thunk 和访问器生成之后、调试插桩之前。当前已支持的同步 void 入口仍可调试；未调用的引用参数方法不会触发不必要的根管理。闭包和持久帧调试限制保持。

## 无分配对象的引用根

原先仅有 erased owner 的 borrowed descriptor 无法单独配置堆，导致只用整数 ref/out 的方法需要额外闭包才能进入受追踪引用路径。本组新增真实的 roots-only 配置，不添加占位对象或虚假对象布局。

- Guest IR 升级到 **8/1.7**，保留 1–7 的读取能力。旧版仍拒绝没有具体对象布局的 erased 引用；新能力降级、未来版本和 erased 对象分配均拒绝。
- `avid_managed_heap_v1` 增加命令 **13 / ConfigureRootsOnly**，请求仅含八字节 magic/command，响应为空。旧 Configure 命令对零布局的拒绝不变；旧 Runtime 不认识命令 13 时失败关闭。
- roots-only 状态仅允许帧和空对象根，不包含任何对象分配类型。它不能再次配置来扩充权限，也不能接受其他堆的对象。帧/根数量限制、调用边界、错误展开和关闭状态沿用同一实现。
- Backend 配置、根插桩与原生协议共享相同命令值，受原有 wire contract 对照检查。新版本及编译器源码进入现有产物/工具链身份，不复用旧缓存冒充兼容。

实现：[IR 验证](../../Tools/AvidScript.GuestIr/Validation/GuestManagedHeapValidator.cs)、[配置生成](../../Tools/AvidScript.WasmBackend/Codegen/WasmManagedHeapPlan.cs)、[原生 wire contract](../../Source/AvidScriptCore/Public/AvidScriptManagedHeapAbi.h)、[堆协议](../../Source/AvidScriptRuntime/Private/Memory/AvidScriptManagedHeapProtocol.cpp)。
