# P66.C9：异步取消中的显式抛错

状态：Semantic、Guest IR、WASM 和正式脚本构建入口已实现；Win64 Wasmtime / WAMR 的同源对照与 Session teardown 测试通过。生成 UE 类型、Actor/World 自动 teardown、reload/rollback 的新组合仍待验收。此项承接 [C8](P66.C8_Task_Local_Lifetime_Contract.md)，P66.C/D 尚未完成。

## 源码与语义

```csharp
try
{
    try { await WaitAsync(); }
    catch (OperationCanceledException) { throw new ArgumentException(); }
    finally { CleanupCount++; }
}
catch (ArgumentException) { return 90; }
```

显式 `throw` 必须进入所属区域的异常出口：try 进入本层有序 catch；catch 经过本层 finally 后进入外层；finally 抛错直接进入外层，不能重入自身或同级 catch。新异常替换正在传播或已捕获的旧异常，旧 owner 释放一次。正常返回、取消、重新抛出及清理抛错均保持 C# 的清理顺序。

## 合同与写集

- Semantic 46 / 1.55 新增 `raise_exception` 控制转移。它携带既有受检异常构造表达式与异常后继，仍由 `ErrorPlan.Throws` 记录类型、构造器和源码位置。旧 `throw` 保持终结 Task 的原语义，旧版本拒绝新转移。
- Roslyn 结构化 CFG 产生区域成员和后继；读端从区域/父作用域独立核对路由。新的异常边进入状态存活、Task 作用域释放和异常 owner 分析。异常替换将 owner 状态变为 Fault，不把旧 Cancellation 带入新 handler。
- Guest IR 26 / 1.25 记录异常创建/替换到分派出口的路由，并由独立读端验证。复用现有 Task 异常对象 ABI；不新增裸指针或绕过 catalog 的接口。
- Guest lowering 在新异常建立成功后替换当前异常 owner，再沿受检边执行 finally/catch。Host 失败继续 trap，不能进入语言 catch。
- 源码仍使用现有预览开关与 bounded language-error 模式。当前支持的零参数框架异常构造器保持原范围。catch/finally 内 await、catch 变量/filter、handler 内嵌套 try 是后续工作，不随本项自动放开。

实现归属依次为 `Tools/AvidScript.CSharpSemantic`、`Tools/AvidScript.CSharpGuest`、`Tools/AvidScript.GuestIr` 与其测试；正式构建入口和 Runtime 只增加新版本识别及执行验收。类型系统、同步异常及旧取消合同不另建旁路。

## 已实现：Guest IR 26 与 Win64 执行

每个 `raise_exception` 转移携带异常类型和源码 token。WASM 先创建新的 faulted Task 并持有异常对象，确认成功后释放旧异常 owner、清零旧类型，再发布新 owner 并进入目标分支。分配或建立异常失败会 trap；失败时创建的 Task 也会释放。IR 校验分别检查新对象、catalog、旧 owner 释放、清零、发布和后继。Task 作用域退出桥仍由生命周期校验器独立验证。

两个新组合修复了读端与 lowering 的旧假设：

- 一个方法可以先执行 `try/catch`，再执行未被该处理器保护的 `await`。后一次等待失败应终结返回的 Task，不能跳回已经离开的 catch。IR 26 对这种终结分支检查 source/producer，仍拒绝遗漏受保护等待的路由。
- `finally` 无条件抛错时，先前求值的返回值不会被读取。只有新合同中不存在正常 return 后继的情况才允许保留这个写入；普通孤立的返回槽仍被拒绝。

27 组业务源码在 .NET 执行，并编译为同源 WASM。覆盖 try/catch/finally 抛错、异常替换、rethrow、无条件 finally 覆盖返回、跨 Task 传播、重复等待故障 Task、Task 别名、循环作用域，以及子 Task/直接等待取消后改抛新异常。清理顺序用十进制 Trace 记录，例如 `1234` 表示四段清理按顺序各执行一次。
