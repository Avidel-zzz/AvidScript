# P66.B：Runtime 持有生成绑定

## 本组结果

生成 receiver 与标量属性 import 的预备上下文现在归 Runtime 所有，解析目标时使用当前 HostContext 的实例权限。原 Session 注销后，仍存活的 Runtime 不再借用已释放的 Session 绑定数组。该改动进入现有 Session 的候选加载与重载路径；生产 Host 仍为每个实例创建独立 Session/VM。

## 所有权与执行边界

- `AvidScriptGeneratedTypeHostBindings.cpp` 持有不可变 Registry、receiver 校验上下文与属性 codec；候选 Runtime 拥有自己的绑定状态，旧 Runtime 不借用候选的数据。
- `IAvidScriptGeneratedTypeAuthority` 是实例权限端点，HostContext 只保存弱引用。Session 的注册清理使已保存的上下文失效；停止、故障、对象代际变化及 World teardown 继续拒绝访问。
- receiver 和属性读写均检查当前 owner，并通过权限端点核对**同一 Registry snapshot**、Game Thread、注册状态、类型、World 和 ObjectRegistry。相同类及 ordinal 不能授权另一个包快照。
- scalar codec 仍在冷路径按反射类型准备；热路径不重复发现 FProperty，也不永久捕获首个 UObject。
- 原生 `InvokeInContext` 的调用方仍须在整个调用期间保留 Runtime 和实例服务。该接口不是 Guest 任意选择 owner 的权限。

## WAMR 能力补齐

新增真实 C# 属性用例暴露了 WAMR supplemental import 仅支持 `(I)i` 的限制。本组补齐 packed receiver 的 i32/i64/f32/f64 getter 与 void setter，按位传递标量并严格匹配 shape、签名及预备目标。现有 typed-property 合同使用 `d` 表示 f64；WAMR 注册表及 generic ABI parser 使用 `F`，适配仅发生在 backend 内部，不改写对外 import 身份。

进程级注册表只复用 ABI stub；上下文及权限仍归各 VM。普通 dynamic binding package 的整数返回值约束保持原样，没有因 supplemental 扩展而放宽。拒绝的 getter/setter 产生 VM 失败，未授权 VM 不能借用已经注册的全局符号。

```powershell
pwsh -NoProfile -File Build/TestAvidScriptUeReceivers.ps1
pwsh -NoProfile -File Build/TestAvidScriptSupplementalImports.ps1
pwsh -NoProfile -File Build/InvokeAgentHarness.ps1 audit
pwsh -NoProfile -File Build/CheckAvidScriptArchitecture.ps1
```

- GeneratedTypes Automation 10/10。新增 `CSharpSharedBindings` 在 Wasmtime/WAMR、正常/每分配强制 GC 下，均通过 Runtime A 执行 A/B/A：共享静态计数，各自属性分别为 14 和 22。原 A 注册清理后 B 仍执行得到 2626；旧权限、停止的 Session、错误 self 及不同 Registry 快照拒绝；捕获帧、根及脱离对象全部释放。
- WAMR raw registry Automation 4/4，含 i32/i64/f32/f64 原始位模式、void setter、目标拒绝、错签名、双 VM 上下文隔离及原 VM 卸载后 peer 存活，并回归旧注册冲突、权限及重入卸载行为。
- Harness audit 通过。架构检查已将 codec 与热路径检查迁移到新 owner 文件；工作树仍有受保护的 `AvidScriptWasmReloadTypes.h` 改动，不能把结构检查无新增问题描述为 clean-tree Gate 通过。
