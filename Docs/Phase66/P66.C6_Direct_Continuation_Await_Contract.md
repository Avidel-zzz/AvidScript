# P66.C6：直接 `await` 的状态与取消合同

状态：Semantic 43 / Guest IR 23 显式预览已接通直接 Timer await 与 Task await 的 `try/catch/finally` 组合。Win64 双后端已验证正常、语言错误、主动取消和状态拒绝路径；默认构建仍拒绝，P66.C 未完成。Windows 优先，Android/iOS 验收暂缓。

## 起点

[`DirectAwaitInTry.cs`](../../Fixtures/Phase66/DirectAwaitInTry.cs) 把 `await AvidContinuations.NextTickAsync()` 直接放进 `try/catch/finally`。仅启用 `-LanguageErrors bounded -AsyncExceptionFlow` 的构建返回 `ASCS3002`，退出码 1，且不生成 WASM。本切片开始前，`SemanticAsyncControlFlowProjector` 只给 Task await 创建故障与取消后继，`SemanticAsyncExceptionPlanValidator` 也只允许 Task await 位于受保护区域。

原生完成消息已经带 `Completed`、`Failed`、`Cancelled` 状态，`avid_on_continuation_v2` 也接收状态；但编译器生成的无载荷 resume 函数只接收 token，路由器原先丢弃状态。`FAvidScriptSessionContinuations::CancelEntry` 对普通 Timer 取消直接释放回调并终结绑定的生产者 Task，不派发 `Cancelled`。因此只删除 Semantic 的拒绝条件会让脚本在意外失败后继续执行，也无法在有效 Session 的主动取消路径运行 `finally`。

本切片先让编译器生成的无载荷路由只在 `Completed` 时调用 resume；其他状态在进入脚本前 trap，保持 fail-closed。显式声明的无载荷回调沿用原合同。这个保护只收紧现有路由的执行，不改变当前 Semantic/IR 数据格式；它不等于直接 `await` 的取消清理已实现。固定 SDK 8.0.416 的 Guest 自执行回归 **553/553** 通过；正式构建后 Win64 Automation **1/1** 通过，Wasmtime JIT/WAMR Interpreter 正常组合路径 **6/6**，伪造 `Failed` 状态的 Guest 拒绝 **2/2**，结果和清理字段保持未写入。两后端分别报告 `guest_trap`、`trap`，continuation owner teardown 后 continuation 和 Task 归零。日志：`Saved/Logs/AvidScript_CompiledIntegratedLanguageFlow_20260925T201046210Z.log`。

Session owner 现提供独立的 `ScheduleDelayWithCancelResume`，在分配 Timer entry 时记录 opt-in。有效 Session 的主动取消派发一次 `Cancelled`，并在清理回调终结后才取消绑定的生产者 Task；已取消 source 的后绑定也走同一终态。普通 `ScheduleDelay` 不变，teardown 不派发 Guest 清理。Win64 no-clean Editor 构建与 `AvidScript.Runtime.Continuation.CancelResume` Automation **1/1** 通过，核对了状态帧、Task 延迟终结、重复取消和 teardown；日志：`Saved/Logs/AvidScript_CancelResume_20260925T202443152Z.log`。

## 目标合同

1. 受保护的直接 await 使用状态可见的 compiler resume。沿用 `avid_on_continuation_v2` 的状态参数，不改 UE 导出签名。`Completed` 进入正常后继；仍有效的 Session 主动取消时，`Cancelled` 进入独立清理后继，跳过 `catch` 并由内到外执行 `finally`；`Failed` 和非法状态走 Host/VM 故障隔离，不得进入 C# `catch`。
2. 调度需要显式 opt-in 的“取消终态可恢复”合同，保存在 continuation entry 上；旧模块和普通无载荷回调的取消行为不变。opt-in 必须在取消源绑定前原子生效，不能在 `BindCancellationSource` 可能同步取消之后补设标志。Object/World teardown、reload 后的失效 Session 不派发 Guest 清理，只由 owner 回收资源。
3. Semantic **43/1.52** 与 Guest IR **23/1.22** 已建立受控编译链，Win64 的 `try/catch/finally` Timer 正常与主动取消路径已运行验证。状态可见 await 记录正常/取消目标及生产者类型；不伪造语言故障目标或源 Task 错误租约。验证器重算受保护区域、取消清理顺序、状态帧及目标可达性，旧版本夹带新路由必须拒绝。Task await 的语言故障路线继续使用现有 Task 租约和 `catch_match`。
4. 生产者 Task 在主动取消后须等 Guest 清理完成，再传播取消并释放最后一个 owner；清理若抛出语言错误，按 C# 规则替换取消终态。任何调度、状态存取、Host import 或 VM trap 失败都不可被脚本 `catch` 捕获。

## 验收

| 场景 | 预期 |
| --- | --- |
| `NextTickAsync` / `DelayAsync` 正常恢复 | 与同源码 .NET 值和 `finally` 次数一致 |
| 有效 Session 主动取消 | 不进入 `catch`；`finally` 一次；生产者 Task 为 `Cancelled` |
| World/Object teardown、成功或失败 reload | 不重新进入失效 Guest；continuation、Task、托管根归零 |
| Host 故障、VM trap、无效状态 | fail-closed，不伪报语言异常，也不执行等待后的用户代码 |
| 伪造 Semantic/IR 路由或旧版产物 | 读端拒绝，不生成可执行 WASM |

剩余验收包括完整 Session reload 事务与故障注入，以及对外层未捕获取消的语言级传播。下文的 owner 队列生命周期测试不替代 Session prepare/commit/rollback 的完整调用链。当前取消始终绕过语言 `catch`，不能把 `InvalidOperationException` handler 未执行的 .NET 对照推广为 `catch (Exception)` 或 `catch (OperationCanceledException)` 已符合完整 C# 取消语义。`await` 位于 `catch/finally`、异常变量与 filter 仍不支持，P66.C 未完成。

## 直接 await 与 Task await 的组合

Semantic 43 的显式预览现允许 Timer await 出现在 `try/catch/finally` 中。直接 await 只有正常和取消出口；子 Task await 仍保留独立的语言错误出口和错误对象租约。只有直接 Timer await 的方法没有语言错误生产者时，源码 catch 元数据保留，可执行 handler 被可达性裁剪；读端核对这一条件，不能通过清空 handler 绕过 Task 错误分派。

Guest 按 Roslyn 的 `ClassTypes.BaseTypeId` 链计算匹配类型，本预览支持父类 handler 和没有可匹配 throw 的 handler，不再要求每个 catch 类型都必须有一个对应 throw token。类型链缺失或循环会拒绝编译。正式构建仅在预览版本、异常计划和 `ASCS5422` 诊断均符合约定时接受带 bounded throw 的 Semantic 43，不屏蔽其他语义错误。不含直接 await、也没有任何 throw 的 Task handler 仍受旧 IR 22 的非空 catalog 约束，需在后续统一异常版本时补齐。

组合夹具同时执行直接 Timer await、子 Task await、数组 foreach、泛型调用、不匹配 handler、父类 handler 与 finally。同源 .NET **4/4**、Win64 双后端 **8/8** 和无效状态保护 **2/2** 通过；日志：`Saved/Logs/AvidScript_CompiledIntegratedLanguageFlow_20260926T033751813Z.log`。固定 SDK 8.0.416 的 Semantic **408/408**、Guest **558/558** 通过，包含无 throw、不同 throw 类型及父类 catch 的编译用例。`TestBoundedLanguageErrorBuild.ps1` 的默认拒绝、受限错误构建、非法构造器和模块身份合同 **5/5** 通过，结果位于 `Saved/AvidScript/BoundedLanguageErrorBuildContracts/17375856fb98442899e20d15e2b42f8d/results.json`。

[`DirectAwaitCleanup.cs`](../../Fixtures/Phase66/DirectAwaitCleanup.cs) 的同源 [.NET 参考](../../Fixtures/Phase66/DirectAwaitCleanup.Reference.cs)现覆盖正常/主动取消与清理抛错的四种组合，**4/4** 通过。Win64 双后端 **8/8** 通过，均验证 `cleanup=1, catch=0`，Task、continuation 和根被回收。日志：`Saved/Logs/AvidScript_DirectAwaitCleanup_20260926T035535464Z.log`。

| 等待结果 | finally 行为 | 生产者 Task / 外层观察结果 |
| --- | --- | --- |
| 正常 | 计数一次 | 成功，返回 `16` |
| 主动取消 | 计数一次 | Cancelled；未处理的外层 `async void` await 仍为 VM trap |
| 正常 | 计数后抛 `InvalidOperationException` | Faulted，外层报告 `language_error_uncaught` |
| 主动取消 | 计数后抛 `InvalidOperationException` | Faulted，清理异常替代取消，外层报告 `language_error_uncaught` |

同级 catch 的类型也为 `InvalidOperationException`，用于核对 finally 抛错不会错误地返回该 catch。Semantic 读端现在按 throw 所属的受保护区域判断 handler 是否必须可达；finally 自身的 throw 不使同级 catch 变为可达。把该 throw 伪造为 try 内的生产者仍被拒绝。Session 的 Task 终态只写入一次，取消完成回调释放 owner 时不会覆盖 Guest 已发布的清理异常；该行为由真实编译 WASM 验证，不依赖测试替身手动写入故障结果。

该切片回归：Semantic **409/409**、Guest **559/559**；Win64 no-clean Editor 构建和聚焦 Automation **1/1** 通过。

## 取消排队后的生命周期

[`DirectAwaitCleanup.cs`](../../Fixtures/Phase66/DirectAwaitCleanup.cs) 现在在等待前创建 `AwaitValue`，恢复后读取它的字段。测试先确认挂起和取消排队时都有存活对象及根，再核对清理后根与调用帧归零，执行 GC 并确认对象回收，避免空堆检查制造通过结果。

正式构建曾以 `ASBI4203` 拒绝这份源码：普通 C# 对象使用的 `import:$closure:heap` 只在生成 UE 类型路径获得授权，托管 continuation 的读写接口也未纳入编译器接口校验。构建入口现在统一验证这三个编译器生成接口的完整身份、模块、调度类别、优化类别、ordinal、参数与返回类型；同名用户 `DllImport` 不获得豁免。既有异常专用接口仍受原预览条件约束。[导入校验回归](../../Build/Contracts/TestCompilerManagedImportContracts.ps1)使用正式生成的 IR，分别在异常预览关闭和开启时测试原接口及八种错误修改，**54/54** 通过。默认受保护 await 仍以 `ASCS3002` 拒绝；既有 bounded 构建合同 **5/5** 通过。

[`CompiledDirectAwaitCleanupLifecycle`](../../Source/AvidScriptRuntime/Private/Tests/AvidScriptDirectAwaitCleanupLifecycleTests.cpp) 对每种 VM 使用独立 Runtime 和真实编译 WASM，在取消消息已入队、Guest 尚未恢复时执行以下操作：

| 操作 | 旧实例 / 丢弃候选 | 保留 / 提交实例 |
| --- | --- | --- |
| continuation owner `Teardown` | 不恢复，`cleanup=0` | 无 |
| World `BeginTearingDown` | 不恢复，`cleanup=0` | 无 |
| `DestroyActor` 销毁 owner | handle 无法解析，不恢复，`cleanup=0` | 无 |
| 丢弃已排队取消的 prepared 候选 | 候选 `cleanup=0` | 旧实例正常返回 `16`，`cleanup=1` |
| 提交正常 prepared 候选 | 旧实例 `cleanup=0` | 候选正常返回 `16`，`cleanup=1` |
| 提交也已排队取消的 prepared 候选 | 旧实例 `cleanup=0` | 候选只执行一次清理，取消继续传到外层 |

所有场景在最终兜底 teardown 前核对 Task、waiter、状态帧、取消绑定和托管根；失效 owner 的取消源此时也必须已释放。有效实例保留自己的取消源直到 teardown。重复 teardown 后，两条队列和取消源均为空。候选提交/丢弃通过 continuation owner 的正式 lane API 驱动，尚未覆盖完整 Session reload 事务、Editor Play 或长时间运行。

固定 SDK 的同源 .NET **4/4**、Win64 no-clean Editor 构建、Automation **2/2** 通过。Wasmtime JIT / WAMR Interpreter 的正常、取消、清理抛错回归 **8/8**，新增生命周期组合 **12/12** 通过；日志：`Saved/Logs/AvidScript_DirectAwaitCleanup_20260926T042011467Z.log`。本次没有更改 Runtime 的取消状态机；修复位于正式构建的接口授权。下一步将相同脚本接入完整 Session reload 事务，继续补故障注入和取消的语言级传播。
