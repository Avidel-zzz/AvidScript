# P66.C13：默认语言构建链

状态：公共 CLI 接入已验证，默认 Editor 构建尚未接入，2026-10-04。目标是让普通项目构建按源码实际能力选择合同，保留增量缓存和 worker，并贯通正式 Session 生命周期；不要求用户为业务代码手动组合编译器开关。CLI 接入是其中一部分，不能据此宣称默认 Build And Bind 已完成。

## 本批实现

- Semantic CLI 和 `InvokeCSharpSemantic.ps1` 增加同步/异步错误、静态初始化、命名 catch、标准 token 与 async void owner 分析选项；缺少依赖、重复参数和未知模式会拒绝。
- Guest CLI 在 `--language-errors bounded` 下按完整源合同选择 static/token/error 编译器。30 个同源用例覆盖单项与组合；CLI/API 的 Semantic、Guest IR 和 WASM 字节一致。所有用例同时生成状态布局和调试映射。完整 facade 中未使用的 token 声明不再污染 Guest 类型表。
- 静态字段初始化与显式静态构造函数保留各自源码位置；内部 guard 只接受经源计划重建的精确 ID，伪造前缀会拒绝。调试 sidecar 仍为单源文档；可执行引用中的初始化位置不能假装映射到主文件，目前拒绝生成该 sidecar，后续需要多源映射合同。

复现公共 CLI 的同源 Windows 执行验证：

```powershell
pwsh -NoProfile -File Build/TestAvidScriptAsyncVoidErrorOwners.ps1 -PublicCli -SkipBuild
```

`-SkipBuild` 要求已有兼容的 Win64 Editor 产物。本次只修改 C# 工具与构建脚本，复用上一批已构建的 Native 模块：CLI 专项 **351/351**，聚焦 Automation **9/9**，24 份 CLI WASM 在两个 VM、四种生命周期模式下 **192/192**。异常类型和执行顺序同时对照相同业务源码的 .NET 参考。运行报告、日志和哈希保存在项目 `Saved/AvidScriptAsyncVoidOwners/<run>`；成功后已回收本次 97 个生成文件，共 34,812,491 字节。失败产物不自动删除。

受影响的完整回归：`CSharpSemantic.Tests` **1557/1557**，`CSharpGuest.Tests` **5409/5409**，包含现有 CLI、状态布局、调试映射和组合执行测试。构建零警告、零错误。环境安全 **128/128**，覆盖 35 个隔离入口，首次运行 PATH 未变，探针已回收。Harness `Auto` 选择 Managed，`audit` 通过；本批不改 Native 模块，不重复 UE 构建，也不计作整个 P66.C 的最终 Gate。

## 当前缺口

- CLI 与 worker 已支持 [P66.C15 的统一 Gameplay 配置](P66.C15_Gameplay_Profile_Contract.md)，调用方不必拼分析开关；尚未成为普通项目默认配置。
- `BuildCSharpActorLifecycle` 的 bounded 模式禁用缓存和 worker；prepared 读端只准入 Semantic 31 / 45。新增能力若绕开这些检查，会破坏缓存与来源身份合同。
- 普通 Task 的静态状态、命名异常值与 token 有无组合已由 [P66.C14](P66.C14_Static_Catch_Composition_Contract.md)补齐，并核对全部分析选项的 8 种组合；闭包/事件/泛型/集合的组合覆盖仍需继续，不能据此假定完整语言配置已经交付。

## 实施顺序与边界

1. **公共编译入口**：Semantic CLI 转发完整分析选项，独立验证依赖与 enabled/disabled 值；Guest 端只从精确版本与完整源计划选择编译器。static 优先完成源码准备，再组合 token/异常值/owner。普通 lowerer 的拒绝边界保留，未知版本、半版本、缺计划和伪造来源不得得到路由权限。CLI 产物须与相同源码、相同选项的 API 编译产物规范字节一致。
2. **统一 Gameplay profile 与能力覆盖**：用户侧只有项目语言 profile；内部按实际源码投射能力，不能用正则猜语法，也不能给未使用的能力补空计划。核对普通 Task、async void、静态初始化、命名异常值、token 有无、纯同步与现有闭包/事件/泛型/集合组合。若现有版本合同限制合法组合，先补独立能力合同与同源执行证明，再进入默认 profile。
3. **缓存与 worker**：prepared、Semantic cache、Guest cache 和 worker 共用版本化 profile 身份。键必须包含所有分析/执行选项、源码/引用/生成 facade、工具身份、Semantic 合同、实际能力、目标 ABI 和优化策略。hit、miss、损坏、旧版 entry、选项切换、引用变化与源码变化均验证实际 bytes；prepared/worker 不通过字符串改标签取得新合同准入。默认 profile 不以禁用缓存/worker作为交付方案。
4. **Editor 与 Runtime**：Build And Bind、live reload、脚本定义类型构建使用同一份 profile 决策与报告；正式实例加载和生成类型共享域仍重新验证能力。组合初始化失败、async void 报告和候选错误必须遵守域隔离/回滚边界；Actor/World 销毁、重载和同域多实例清理要走正式组件路径。

## 交付验证

- CLI 同源矩阵：静态、token、owner、catch 值的已支持单项与组合；无新选项时旧产物字节保持稳定。非法 CLI 依赖、未知模式、伪造输入、禁用语言错误、debug/fusion 不相容和预存失败产物不得发布成功结果。
- 完整 profile 同源覆盖：以 .NET 参考为对照，两个 Windows VM 核对结果、顺序、取消身份、错误报告次数和 owner 释放；无静态计划时资源清零，有静态计划时只保留精确域根/缓存对象，域退休释放全部资源。
- 正式项目链：冷构建、同源码命中、改源码、改引用、改选项、worker 重启/故障回退、候选失败、双实例以及 Actor/World teardown；生产报告、WASM、manifest、调试映射和状态布局身份一致。改变反射 shape 返回 native rebuild required。
- 性能分别测冷构建、缓存命中、单文件增量、worker 常驻内存，以及 Tick、纯 WASM、crossing、取消/continuation 的分配与延迟。与既有 profile 的成本先比较；竞品优劣必须另用冻结 workload 的 Puerts/AngelScript 对照证明。
