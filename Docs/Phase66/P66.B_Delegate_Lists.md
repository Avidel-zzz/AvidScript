# P66.B：不可变委托调用列表

## 冻结合同

普通同步 C# 委托支持 `+`、`-`、`+=`、`-=`，保持名义签名、null 恒等规则、左右各求值一次和不可变调用列表。组合按左后右调用，保留重复项；参数按原签名传递，ref/out 在所有项之间共享同一位置，非 void 取最后返回值。调用开始后修改原委托变量，不改变当前调用快照。

移除最后一段连续匹配序列；不存在匹配时返回原列表，移除全部时返回 null。列表相等比较有序调用项，复用方法与环境身份合同，不比较树形或新分配节点身份。遵循 [C# delegate 规范](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/delegates)；`new D(existingDelegate)` 的嵌套构造、Delegate 反射 API、绑定实例、语言 event、跨 await 和持久订阅不是本组支持声明。

## 表示与生命周期

沿用 IR 6/1.5 的函数引用、类型化堆引用与内部借用。组合产生不可变二叉节点，保存左右委托、左项数和总项数；单项保留原目标与环境。生成按签名区分的调用包装函数，按序取叶子并调用，列表遍历不递归增长 WASM 栈。计数超过有符号 32 位上限或非法内部索引会 trap，不允许溢出。

包含组合运算的模块即使没有捕获变量，也使用受追踪委托表示和内部借用；单纯静态单目标模块保持原表示。根由现有调用帧管理，返回、trap 和回收沿用既有 owner；调试暂停与持久存储仍明确拒绝未接通的根合同。

本组先保证语义：组合分配一个节点，索引遍历与树深度相关，调用成本为项数乘树深度；移除按逆序查找并重建剩余序列。长列表可能产生较高 Host crossing 和保守根成本，不能据此宣称性能领先。后续应在保持语义与身份的前提下量化并优化列表表示。

## 执行用例与边界

同一 C# 源码的 .NET 参考结果，对照正常与每次分配后强制回收的实际 WASM；覆盖静态模块提升、捕获环境、关联顺序、重复项、最后返回、ref/out 别名、调用期间修改、最后连续匹配移除和无匹配。双后端运行后检查根/帧清理及对象图回收；本组完成不等于 P66.B 完成。

完整 Guest 回归发现格式错误的 Semantic 产物在拒绝前进入委托计划分析；现已调整入口次序，输入校验失败时不分析委托。既有伪造/缺失签名反例随完整 runner 重新通过。最初的 fixture 也暴露普通对象初始化器仍被 Semantic 拒绝；结构体返回验证使用已支持的构造函数，并明确保留对象初始化器为语言缺口，不把构造函数用例当作初始化器支持证据。

本组的 .NET 对照预期值：捕获/混合签名 fixture 为 65535，静态模块为 7；各有正常与强制回收版本。遍历实现采用循环，32 项左结合列表执行通过，未进行大型列表性能门禁。完整异常传播、嵌套 delegate 构造、持久根及新列表自身的故障中断专项仍需后续覆盖。
