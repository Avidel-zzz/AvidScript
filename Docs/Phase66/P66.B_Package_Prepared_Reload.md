# P66.B：全包准备后发布，失败保留原 VM

## 问题

原包级 body-only reload 逐个替换 Session。后续实例失败时，它再次加载旧 WASM 来回滚已经替换的实例；即使函数返回值恢复，也已经丢失原 VM 的 global、堆对象身份和未声明迁移的状态。这不能作为共享执行域的回滚基础。

## 实现

Session 将候选激活拆为准备、复核、发布与丢弃。待发布对象持有候选 Runtime、上下文/实例状态、预备成员与回调、BeginPlay 结果、manifest、Host effect journal 和借用句柄检查点；journal 地址在整个事务中保持稳定。旧 Runtime、实例状态和路由直到发布才替换。

Host 在第一个候选执行前为全包 Session 设置进入屏障。候选准备期间，原 Session 的成员、Tick、事件、卸载和独立重载不能进入；Host 实例表变更仍受原事务保护。所有候选成功准备并复核 owner、continuation、inbound handler 与 journal 状态后，才逐个执行不运行 Guest 的发布步骤，最后更新包描述并解除屏障。脚本不能观察到一部分旧代次、一部分新代次。

准备失败时，按逆序丢弃所有已准备候选、还原 Host effects 与候选借用句柄，保留原 VM、global、实例状态和代码代次。不得重新加载旧代码冒充恢复。任何还原失败都使全包停止；发布期间若原生生命周期变化导致参与者失效，也停止全包，不能留下混合代次。

结果新增 `PreparedInstanceCount`。`ReloadedInstanceCount` 仅统计实际发布；`RolledBackInstanceCount` 统计已成功丢弃并还原的候选。准备拒绝时发布数为零。普通单 Session 加载/重载仍立即准备并发布，使用相同实现。

## 验证

`PackagePreparedReload` 在 Wasmtime/WAMR 上使用真实 Host、两个生成对象和带可变 global 的 WASM：

- 原 VM 先执行多次，分别在第 1、第 2 个候选准备后注入失败；断言原 Runtime 指针、实例状态、generation 和 global 全部保持。
- 候选回调试图进入两个原 Session 及卸载 peer，均被包屏障拒绝。
- 两个候选 journal 依次修改同一 UE 属性；失败逆序还原为事务前值，成功发布保留候选修改。
- 成功发布后，两份旧状态退休，generation 各自只增加一次。
- 对象在候选准备期间销毁导致 journal 无法还原时，不宣称包仍完整；所有 Session 和注册句柄被清理。
- 原 Session 已因 trap 隔离时，候选按自身身份重新验证；有效替换能恢复执行，不被旧代次的 quarantine 状态误拒绝。

## 仍需推进

这是共享执行域前必需的包事务改造，生产 Host **仍为每实例创建独立 VM**。尚未交付共享 VM/堆/静态所有权、最后 owner 卸载、域级 trap 传播、完整跨对象调用或持久 event/await 根。

Host effect journal 在准备期间暂时应用 UE 修改，屏障阻止本包脚本进入，但不宣称 UE 原生观察者看不到暂态。成功重载继续遵守已有显式状态迁移合同；本测试只证明失败保留原 VM，不证明成功重载能自动迁移所有 Guest 对象或闭包。下一组把 Runtime 所有权提升到包/World/registry 执行域，并复用本次准备/发布边界，P66.B 保持进行中。
