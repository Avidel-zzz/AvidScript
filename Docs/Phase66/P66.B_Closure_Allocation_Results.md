# P66.B：闭包作用域的控制流分配合同

## 已实现

Semantic **23 / 1.27** 在已有共享 cell 和词法作用域合同上，为同步闭包环境增加 `allocation`：包含 Roslyn 生命周期区域的起止 block ordinal，以及进入该区域的完整 CFG 边集合。函数调用环境使用 source 为 null 的函数入口。

过去的环境计划只有词法范围和源码 span，不能据此可靠地决定循环中的分配时机。本组从 Roslyn 的 local lifetime region 获取范围，再计算从区域外进入区域内的边；不能用首次变量赋值、首次构造委托或循环头执行次数替代作用域进入次数。

- `activation`：每次函数调用创建一次，参数与顶层局部共享该次调用环境。
- `for_entry`：进入整个 for 时创建；循环内部回边不重新创建初始化变量的环境。
- `block_entry`：每次进入声明块时创建，包含 continue 后下一次进入；离开块和 break 不构成新的分配。
- `foreach_iteration`：保留 Roslyn 迭代变量生命周期分析，但当前同步 foreach CFG 包含未实现的异常清理区域，仍返回 `ASCS3001`，不输出可执行 CFG。该缺口须在 P66.C 集合/控制流工作中处理；既有受控 async 的数组 foreach 使用另一条规范化路径，不受本结论否定。
- async owner 的 allocation 保持 null，不能借用同步 CFG 伪造挂起/恢复的分配位置；后续须连接 continuation frame 与根所有权。

同步捕获 lambda 现在保留正常的 callable、CFG 和环境分析结果，不再因“尚未接 Guest 执行”抹去整个 CFG。Guest 仍明确返回 `ASCG1024`；这一步没有开放 C# 捕获 lambda、逃逸闭包、绑定实例或 event 的运行。

## 兼容与验证边界

23/1.27 校验分配区间、唯一且有序的入口、完整 CFG 入边、函数入口和循环内部回边区别。缺失、重复、null 或与 CFG 不一致的 allocation 拒绝。编译失败并隐藏 CFG 时仍检查分配 metadata 的基本形状，不把分析数据当作执行授权。

22/1.26 环境分析继续可读，但不能携带新 allocation 字段内容；此前静态方法组和无捕获 lambda 的执行读取保留。未来版本拒绝。新的 Semantic 内容与版本进入既有产物及缓存身份，不改变 Guest IR 或 Runtime ABI。

## 本组验证

固定 SDK 8.0.416，Semantic runner **174/174**。新增的有界整数 CFG 轨迹测试覆盖 `for`、`continue`、`break`：函数环境 1 次、for 初始化变量环境 1 次、循环体环境实际进入 4 次。另覆盖同名兄弟作用域、foreach 明确拒绝、确定性、序列化回读、旧版本与非法 metadata。

Guest runner **203/203**；由当前编译器生成并在 Node WebAssembly 实际执行的既有能力回归：直接捕获 **900/900**、静态方法组 **1890/1890**、无捕获 lambda **1050/1050**。这三组不需要 Host，不能作为 UE 闭包回调证据。

整数轨迹测试中的委托表达式为惰性占位，只验证分配位置与控制流，不是闭包执行证据。本组不重复运行未受影响的 UE native 构建，也不登记正式 Phase Gate。架构检查已同步版本 owner；受保护 `AvidScriptWasmReloadTypes.h` 与提交树不一致仍使 clean evidence 门槛未通过，未覆盖该本地修改。

## 接下来的执行工作

将 allocation 入口转成受追踪环境分配；owner、直接局部函数和委托必须访问同一 cell。需同时处理进入边拆分、环境传递、委托目标签名、返回值保活，以及捕获变量作为 ref 实参时的别名一致性，不能使用复制后回写掩盖重入差异。

后续仍包括作用域退出时释放当前激活的根、嵌套委托、循环回收、持久回调/continuation 根与 reload/teardown。P66.B 和完整路线保持未完成。
