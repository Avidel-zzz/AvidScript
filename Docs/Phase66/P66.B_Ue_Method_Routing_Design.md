# P66.B：跨实例方法路由与执行边界

## 基线与目标

实现基线为 `cb5f95ab`。当前 owner 的直接实例委托与同步 this 捕获已交付；本文件记录下一组的设计和必须取得的证据，不宣称跨实例或虚派发已经可用，不改变 P66.A 的完成状态和 P66.B/C/D 的范围。

用户目标是普通玩法能够自然表达，并为运行中修改、完整调试和有归属的异步提供共同基础。下一组必须让调用根据真实 receiver 和语言派发规则进入正确实现；不能通过移除当前 owner 校验、复制引用对象或把同步调用改成排队事件来通过测试。

## 源码复核发现

| 已有机制 | 真实边界 | 对下一组的影响 |
| --- | --- | --- |

| Runtime 故障与重载 | trap 会触发隔离；替换/卸载受活动调用限制 | 不能在内层失败时释放仍由外层栈引用的 VM、根或路由 |

## 必须保持的语义

### 方法身份与目标选择

- 编译期描述声明方法、签名、派发种类、虚槽及 base 事实；运行期描述接收实例、包身份、实现版本及目标入口。二者不混用。
- 类型与方法使用稳定身份，ordinal 仅是一个已验证包内的索引。冷路径将稳定身份解析为 prepared route，热路径不按字符串重新查找反射。
- `direct` 与 `base` 保持声明处选定的函数体；`virtual` 选择真实接收类型对槽的实现；`interface` 需要完整接口映射。不能只凭同名或相同签名猜测覆写。
- 方法组绑定须保存语言要求的方法身份与 receiver；后续调用不得错误切回调用者的实例。Blueprint event 路由与普通 C# 虚方法分别处理，避免 `ProcessEvent` 与生成 thunk 互相回调。
- 私有或非 UFUNCTION 的脚本方法需要独立的 Guest 方法目录，不应为了可调用而全部注册成公开 UFUNCTION。反射 registry 继续描述 UE 可见成员。
- 完整目录同时服务直接调用和委托 thunk，不能维护两套不一致的目标选择规则。

### 值、引用与隔离域

| 数据 | 要求 |
| --- | --- |
| 标量、无引用值结构 | 由版本化签名布局传递，校验大小、对齐与返回值 |
| UObject 身份 | 通过源 registry 解析并在目标访问域重新验证；不能假设不同 registry 中相同 packed handle 指同一对象 |
| 普通引用对象、闭包、委托 | 同一语言执行域内保持身份和共享修改；跨隔离域必须有明确 API，不静默深复制或开放原始 token |
| ref/out 与包含引用的结构 | 同一位置多次传参仍是同一位置，写入顺序和异常前已发生的写入保持 C# 语义；简单 copy-in/copy-out 不足以证明别名正确 |
| 静态状态 | 明确语言执行域的共享范围；不能把每个 Actor 的 VM globals 自动解释为整个脚本模块共享的 C# static |

以上是完成要求。目前尚未决定通过共享执行域，还是由保留来源的受检引用适配满足跨实例引用语义。实现前用两个实例交换同一对象、同一 ref 位置及静态状态的探针比较候选；不把仅支持标量的桥接作为最终替代。

### 调用租约与生命周期

每次跨实例调用需要在 Runtime 层关联源实例、目标实例、目标代码版本、调用父节点和活动根。租约至少保证：

1. 进入时检查目标注册序号、对象代际、线程、World、暂停、隔离及版本；不能复用退休 Session 的地址。
2. 整条同步调用链使用有界深度和预算，不因切换 Session 重置成无限预算。
3. A→B→A 保持同步返回与别名语义。只有经过两后端验证的受控调用链可重入；重载、卸载、配置变更等 mutation 继续禁止重入。
4. 内层失败标记故障并传播；释放 VM/根等操作等待相关活动调用退出。调用期间对象失效不得再次进入。
5. 队列回调、event、await 与调试暂停引用同一套 owner/代码版本身份；持久根仍由 P66.B 后续实现，不通过永久保留全部环境绕过回收。
6. 错误包含稳定类别、源位置、方法、receiver 和代码版本；调试器可以使用调用父节点恢复异步/跨实例因果关系。

### 版本与重载

新增方法目录和调用签名要独立版本化，随后同步更新生产者、读取者、缓存、兼容性和拒绝测试。不能只修改当前 Semantic 版本号就默认旧 Runtime 已有执行能力。

prepared route 绑定到已验证包和代码版本。body reload 需在安全边界替换整套路由，旧活动调用使用被保留的旧版本，或明确拒绝此次重载；不得半途混用新函数体与旧环境布局。结构迁移不能把当前位置相关的 closure cell ID 当作稳定存档字段 ID。

## 三组实现与判定

本分组细化 P66.B 后续责任，不增删冻结的 Phase 批次。

| 组 | 责任与主要 owner | 可验证交付 |
| --- | --- | --- |
| 方法目录与参数合同 | CSharpSemantic、CSharpGuest、GuestIR、UeTypeGenerator；Runtime Registry 只消费版本化产物 | 私有/公开、direct/base/virtual/interface 身份；完整签名、ref/out 和引用类别；确定性目录、旧版拒绝、错槽/错包反例 |
| 目标执行与生命周期 | Runtime Session/Router、VM backend、Memory；编译器接入同一目录 | 双实例状态隔离、普通引用身份与 ref 别名、A→B→A、预算、错误展开；Wasmtime/WAMR 实际执行，根和路由不泄漏 |
| 语言、UE 与持久能力集成 | CSharpGuest、Runtime 事件/continuation、生成类型与 Blueprint 测试 | 直接调用、实例委托、覆写、接口、Blueprint 组合一致；后续接 event/await/reload/teardown，再进入 P66.C |

首个探针使用两个实例共享同一个普通对象和 ref 参数；B 改值并同步回调 A，A 读取修改后状态，再测试故障和 owner 销毁。以同源 .NET 结果作为纯语言部分的参照，UE 生命周期使用实际 UObject/Session 测试。源码编译成功、原生路由 stub 成功和真实 WASM 执行分别记证据。

在确认数据所有权和可重入边界前，不开放跨实例调用作为可用产品功能。这里的拒绝是过渡保护，不能作为该组的完成条件。

| 探针 | 操作与验收 | 结果将决定什么 |
| --- | --- | --- |
| 反射结构修改 | 两个实例和 Blueprint 子类运行后新增字段/函数；检查默认值、旧状态、GC、复制与 Cook；分别记录继续 PIE、退出 PIE、重启 Editor 的需要 | 动态类型重建或稳定原生外壳是否满足目标，是否需要有边界的引擎集成 |
