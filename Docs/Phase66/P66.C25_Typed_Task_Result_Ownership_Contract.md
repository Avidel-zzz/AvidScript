# P66.C25：通用任务结果的引用所有权

## 要解决的代码

```csharp
static async Task<float> CalculateDamageAsync(float damage)
{
    await AvidContinuations.NextTickAsync();
    return damage * 1.5f;
}

static async Task<PlayerState> LoadPlayerAsync()
{
    await AvidContinuations.NextTickAsync();
    return new PlayerState { Name = "Player", Health = 100 };
}
```

这两种结果目前都未接通；可执行的结果任务仍限定为 `Task<int>`。目标是按封闭 `T` 的统一类型、布局与生命周期处理结果，覆盖日常玩法用到的标量、结构体和引用值。不是为每个 `T` 增加一套 Host import，也不引入 CLR、任意 BCL Task 调度器或自定义 awaiter。

## 实现顺序

1. **成功值 owner。** 结果任务声明值是否需要租约；成功值的根属于任务，多个等待者各持有任务引用。结果在最后一个任务/等待者引用释放时回收。取消、fault、candidate rollback、成功发布和 World teardown 继续进入现有 Session dispatcher。先交付本组 Native 合同。
2. **类型与载荷。** 从 canonical Guest 类型生成有界的值计划，固定类型身份、size/alignment、字段和引用位置；完成/读取时核对同一计划。标量保留精确位模式，结构体递归验证，托管对象/数组/委托等通过各自已有 owner 获取租约；UE handle 继续验证 registry、代次和 World。新增 Semantic 能力与 Guest ABI 在其实现组冻结版本，再接 Roslyn 投射、独立验证器、lowering、codegen 和 Runtime 准入。旧产物不能夹带新载荷。
3. **普通源码与集成。** 同源 .NET/WASM 对照覆盖立即/跨帧返回、混合结果类型、别名和多等待者、取消/错误清理、GC、生成 Actor/Component 及重载。接正式 gameplay、缓存/worker/prepared 和两种 Win64 VM；真实 Editor Play 与长期运行继续由 P66.D/P69 验收。

上述三组共同推进通用 `Task<T>`。第一组完成不能称为新结果类型已经能从 C# 执行，P66.C/D 不因此完成。完整枚举器、泛型组合、`catch/finally` 内 await、结构热重载和完整调试仍在原范围内。

## 第二组的值计划与准入

先实现共用冷路径 owner，再接可执行合同。`GuestTaskValuePlan` 从原始、已经 canonical 的 Guest 类型生成结果计划；反算后发现字段 offset、size/alignment 不同即拒绝，不能重算并悄悄接受调用者提供的错误布局。计划包含结果的 nominal type、可达类型声明的 SHA-256、size/alignment 和嵌套 leaf。可达对象 payload 和数组元素属于身份，循环对象图允许；借用调用帧的 ref，包括藏在对象 payload 中的 ref，不能成为跨帧结果。

独立 `TPV1` 值计划格式版本 1：LE u32 magic、version、size、alignment、leaf count；u32 UTF-8 字节长度 + result type；32 字节 shape hash；每个 leaf 为 offset、size、alignment、kind 四个 u32，再加 nominal type 和可选 target type 的长度前缀 UTF-8。上限为结果 4096 字节、256 leaf、identity 1024 UTF-8 字节、plan 1 MiB、类型依赖深度 128。leaf 严格按 offset 排序且不重叠，padding 不能成为隐藏资源；未知版本、kind、越界、错位、截断和额外数据均拒绝。

这是元数据格式，不是新 Guest import，不提高 Semantic/IR 版本或授权旧 WASM 执行新能力。编译准入必须从原始类型重建并逐字节匹配；Native parser 只能确认结构，不能凭 Guest 提交的 type/hash 自行赋予权限。后续加载器必须把计划与已验证、实际执行的模块 bytes 关联。

资源 leaf 分别标记托管引用、线性字符串/数组、UE handle、class/factory/object type/composite/function reference，不能按宽度退化为普通整数。Native capture 先实现标量/枚举、嵌套结构体和托管引用：精确保留标量位模式、要求 padding 为零、用受信已加载 heap catalog 解析引用类型，并验证每个非空对象在当前调用帧有根，再原子取得持久根与复制结果。别名只取得一份根；失败保留原 capture 的全部根和字节。其他资源在 owner adapter 接通前明确拒绝，空资源也不能借零值绕过能力校验。读取结果时的 frame-root 接管、错误跨结果类型传播、可执行 ABI、Roslyn/validator/lowering/codegen 和真实 gameplay 集成继续按第二、三组推进。

本小节写集为 Core wire header、Guest IR 的共用值计划 owner、Runtime 冷路径 parser/capture、两侧有风险的必要测试和最小文档。用真实 managed heap 检查跨帧 GC、类型/owner/frame 权限、原子失败、根预算、null/alias 与释放；编译端发出的原始计划必须由 Native reader 逐项读取。没有把 parser 或 Native capture 单独通过记为通用 `Task<T>` 已可执行。

## 第二组：读取与类型化失败合同

结果 owner 保存原始值计划、不可变字节和直接持有的对象根。Native reader 必须逐项核对完整计划，包括 nominal type、shape hash、size/alignment 和全部 leaf；不能只检查 hash 或字节长度。引用读取要求同一个仍存活的 heap、调用边界之上的当前帧和未移交的持久租约，空引用结果也绑定 heap。先证明全部对象属于该租约，再一次取得当前帧根，最后复制字节。预算不足或任一校验失败时，输出与调用帧保持原样；重复读取和别名不重复增加根。读取成功后才可释放最后任务引用。snapshot 和 `GetBytes()` 均不授予引用权限。

新增 Native `PropagateTypedTaskFailure(source, expectedSourceType, target, expectedTargetType, waiters)`，分别检查源、目标的确切结果身份、同 Session/lane/activation、源已 fault/cancel、目标仍 running。失败没有成功值，因此显式类型化路径允许不同结果类型与值租约声明；保留原错误对象、错误来源、取消身份和错误根，目标原结果声明不改变。旧 `PropagateTaskFailure` 继续要求同结果类型与租约声明，不改变旧 Guest ABI。未来可执行 import 必须从已加载且与实际执行 bytes 关联的目录取得两侧类型，不能由 Guest 字符串自授权限。

写集限定于 heap 的 Native 批量 frame-root 接管、值 owner/reader、Session Task Native 接口与端点、必要测试及本报告。不增加 Guest import，不改变 Semantic/IR 版本；模块准入、其他资源 adapter、前端/codegen 与双 VM 的新结果端到端执行仍待下一组。

## 第二组：模块目录与执行升级

值计划需成为加载模块的一部分。可选 `TaskValueCatalog` 元数据由原始 canonical Guest 类型生成，结果 ordinal 连续、类型唯一；validator 重建并比较每份 TPV1 的全部 bytes。WASM emitter 写入 `avidscript.task_values` 的 TVC1 目录，包含 module ID、源码 SHA-256、结果计划及与实际 managed heap 相同的 nominal reference/ordinal/payload layout 表。整个目录最多 2 MiB、128 个结果类型、1024 个 managed reference 类型；类型计划和 payload 的单项预算沿用现有 owner。

Native reader 核对同一个 canonical WASM 的来源字段与目录身份，重复/截断/错版本/不一致的目录均拒绝。Runtime 只在 VM 加载与生命周期准入成功后发布该目录，失败及 unload 清除；目录不暴露 Guest 可变根。引用捕获必须先核对堆的完整布局与目录，包括 payload size、引用 offset 和 target ordinal；相同数字的类型 ordinal 不能冒充其他 payload。目录缺省时保持旧产物的序列化与执行行为。

目录是独立版本化元数据，不能授予新 Guest import。执行升级采用下一空闲 Guest IR 40/1.39 与 Semantic 59/1.68，仍需同时实现 validator、lowering、emitter、Runtime/两个 VM 和正式构建准入后才能启用。拟定的统一值 import 为 `(iIiii)I`：command、task token、目录 type ordinal、payload address/await callback、payload byte length；标量、结构体和引用均走同一个有界载荷路径。跨 Task 错误传播另传源/目标的目录 ordinal，绑定生产者及 continuation 也检查任务类型。旧整数 import 的参数、版本与类型检查保持原合同；错误/取消 reader 必须同步扩展，不能只开放成功路径。此处冻结的是实现边界，新增执行版本尚未准入。

## 第一组冻结合同

Native 的 `IAvidScriptTaskHost` 增加 `CreateRootedTaskResult(TypeId)` 和 `SucceedRootedTaskResult(Token, Value, Lease, OutWaiters)`。`IAvidScriptTaskValueLease` 是只由受信 Runtime 代码创建的 RAII owner；它可组合持久根与其他经过校验的值资源，不是 Guest 提供的证明。普通创建/成功方法保持原语义，原 `Task<int>` import、Semantic、Guest IR 和 WASM 字节合同均不改变。C++ 模块需一起重建，新接口不供旧二进制混用。

任务创建时固定 `bValueRequiresLease`。成功状态下，该声明与租约必须严格匹配；有根的值必须有非空、有界字节载荷，无根任务不能接收值租约。错误对象的根与成功值的根分开，不允许同时发布两个结果变体。缺失租约、错误完成方法、过大/空载荷、重复完成、失效/跨 lane token 均先拒绝，不改旧终态、不清空既有等待者。

Snapshot 只复制不可变字节和 `bValueRequiresLease`，不复制拥有根的租约，也不授权解引用。未来的 Guest reader 必须在仍持有任务引用时验证类型并取得自己的调用帧根，之后才能释放任务。多个 reader 重复读取同一值；最后一个等待者完成前仍保活，snapshot 本身不能阻止回收。

Session endpoint 复用当前 owner、Game Thread、World、lane/activation 校验和有序队列。普通取消/fault 不携带成功值根；Rooted 与普通值的同名类型也不得在 failure propagation 中混用。回滚只退休 candidate，发布退休旧 active 并提升 candidate；teardown 幂等释放所有任务和等待者。

本组写集：Task Native 接口、结果存储、Session endpoint、真实端点 observer、聚焦 Automation 及最小文档。验证使用小型真实 managed heap，覆盖 GC、两等待者、snapshot 非 owning、调用帧接管、缺失/多余租约、空/过大值、失败完成释放 incoming 租约、零引用生产者完成、取消/fault、候选回滚/提交和 teardown。Win64 no-clean UBT 与受影响 Automation 串行、BelowNormal、最大构建并发 1；不安装 SDK、不改持久 PATH、不清理引擎产物或结束用户进程。
