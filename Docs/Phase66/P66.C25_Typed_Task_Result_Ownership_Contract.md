# P66.C25：通用任务结果的引用所有权

## 要解决的代码

```csharp
static async Task<float> CalculateDamageAsync(float damage)
{
    await AvidContinuations.NextTickAsync();
    return damage * 1.5f;
}

static async Task<PlayerState> LoadPlayerAsync()
{
    await AvidContinuations.NextTickAsync();
    return new PlayerState { Name = "Player", Health = 100 };
}
```

这两种结果目前都未接通；可执行的结果任务仍限定为 `Task<int>`。目标是按封闭 `T` 的统一类型、布局与生命周期处理结果，覆盖日常玩法用到的标量、结构体和引用值。不是为每个 `T` 增加一套 Host import，也不引入 CLR、任意 BCL Task 调度器或自定义 awaiter。

## 实现顺序

1. **成功值 owner。** 结果任务声明值是否需要租约；成功值的根属于任务，多个等待者各持有任务引用。结果在最后一个任务/等待者引用释放时回收。取消、fault、candidate rollback、成功发布和 World teardown 继续进入现有 Session dispatcher。先交付本组 Native 合同。
2. **类型与载荷。** 从 canonical Guest 类型生成有界的值计划，固定类型身份、size/alignment、字段和引用位置；完成/读取时核对同一计划。标量保留精确位模式，结构体递归验证，托管对象/数组/委托等通过各自已有 owner 获取租约；UE handle 继续验证 registry、代次和 World。新增 Semantic 能力与 Guest ABI 在其实现组冻结版本，再接 Roslyn 投射、独立验证器、lowering、codegen 和 Runtime 准入。旧产物不能夹带新载荷。
3. **普通源码与集成。** 同源 .NET/WASM 对照覆盖立即/跨帧返回、混合结果类型、别名和多等待者、取消/错误清理、GC、生成 Actor/Component 及重载。接正式 gameplay、缓存/worker/prepared 和两种 Win64 VM；真实 Editor Play 与长期运行继续由 P66.D/P69 验收。

上述三组共同推进通用 `Task<T>`。第一组完成不能称为新结果类型已经能从 C# 执行，P66.C/D 不因此完成。完整枚举器、泛型组合、`catch/finally` 内 await、结构热重载和完整调试仍在原范围内。

## 第一组冻结合同

Native 的 `IAvidScriptTaskHost` 增加 `CreateRootedTaskResult(TypeId)` 和 `SucceedRootedTaskResult(Token, Value, Lease, OutWaiters)`。`IAvidScriptTaskValueLease` 是只由受信 Runtime 代码创建的 RAII owner；它可组合持久根与其他经过校验的值资源，不是 Guest 提供的证明。普通创建/成功方法保持原语义，原 `Task<int>` import、Semantic、Guest IR 和 WASM 字节合同均不改变。C++ 模块需一起重建，新接口不供旧二进制混用。

任务创建时固定 `bValueRequiresLease`。成功状态下，该声明与租约必须严格匹配；有根的值必须有非空、有界字节载荷，无根任务不能接收值租约。错误对象的根与成功值的根分开，不允许同时发布两个结果变体。缺失租约、错误完成方法、过大/空载荷、重复完成、失效/跨 lane token 均先拒绝，不改旧终态、不清空既有等待者。

Snapshot 只复制不可变字节和 `bValueRequiresLease`，不复制拥有根的租约，也不授权解引用。未来的 Guest reader 必须在仍持有任务引用时验证类型并取得自己的调用帧根，之后才能释放任务。多个 reader 重复读取同一值；最后一个等待者完成前仍保活，snapshot 本身不能阻止回收。

Session endpoint 复用当前 owner、Game Thread、World、lane/activation 校验和有序队列。普通取消/fault 不携带成功值根；Rooted 与普通值的同名类型也不得在 failure propagation 中混用。回滚只退休 candidate，发布退休旧 active 并提升 candidate；teardown 幂等释放所有任务和等待者。

本组写集：Task Native 接口、结果存储、Session endpoint、真实端点 observer、聚焦 Automation 及最小文档。验证使用小型真实 managed heap，覆盖 GC、两等待者、snapshot 非 owning、调用帧接管、缺失/多余租约、空/过大值、失败完成释放 incoming 租约、零引用生产者完成、取消/fault、候选回滚/提交和 teardown。Win64 no-clean UBT 与受影响 Automation 串行、BelowNormal、最大构建并发 1；不安装 SDK、不改持久 PATH、不清理引擎产物或结束用户进程。

- `Results`：两个有序等待者逐次进入 dispatcher；同一结果中共享对象身份保持，修改输入不改已发布字节；父对象和嵌套引用跨生产帧退出与 GC 存活；读者先获得自己的调用帧根再释放最后任务引用；调用帧退出后对象及根归零，copied snapshot 不延长生命周期。
