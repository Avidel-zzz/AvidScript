# C10：同步错误进入 Task

状态：同步方法显式抛错进入异步 Task 的 C# → WASM 预览入口已在 Win64 的 Wasmtime/WAMR 中执行验证。
成员 await 写回、静态初始化组合及原始 C10 的 29 个案例仍未完成；P66.C/D 保持实现中。

## 语义目标

同步接收者求值、属性 setter 或静态初始化抛错时，异步方法必须停止后续求值，将原异常交给当前
异常出口，按 C# 次序执行 catch/finally。失败对象不能为了满足旧校验而重新构造；静态缓存异常与
Task 持有同一对象，但各自拥有独立 GC 根。释放 Task 不删除静态缓存，卸载执行域统一释放两者。
原始 `Fixtures/Phase66/AwaitMemberAssignment.cs` 不修改；成员接收者只能求值一次，并在 await 前保活。

## 分层实现

1. IR 28/1.27：建立同步 outcome 到 Task 的受检转交合同，支持既有执行配置与可选静态存储。
   先以 IR/WASM 与 Host 所有权测试验证对象身份和释放行为，不将此步骤记为 C# 异步源码已支持。
2. Semantic 与 C# lowering：记录可能抛错的同步调用及其源区域出口，保持实参/接收者/赋值求值次序，
   接入既有异常 owner、Task 局部变量和 continuation 生命周期。新源码信息使用新的 Semantic 版本，
   不改写旧产物语义。具体源合同在实现前单独冻结。
3. 同源 .NET/Wasmtime/WAMR：原始 29 案例、静态失败跨 await 传播、GC、共享 Actor/World teardown。
   接入普通构建前保持显式预览入口，并保留真实游戏验收。

## Semantic 50 源码合同

`50/1.59` 为同步求值的异常出口增加显式 API 预览选项 `enableAsyncSynchronousExceptions`，
要求同时启用异步异常与取消分析。每个 `Task<int>` 方法的同步调用、属性/字段访问和对象创建等
求值段记录 `synchronous_exception_target`；纯跳转、常量和异常分派段不得夹带该字段。
旧版本不写入新字段，也不接受夹带或降版的新产物。

- 出口在 CFG 构造时捕获：try 内进入当前 catch 分派，catch 内进入本层 finally，finally 内
  离开本层进入外层分派；无处理区域时进入方法级异常传播出口。复制的 finally 使用各自段身份。
- 接收者捕获与成功后的成员写回分别记录异常出口；await 生产者失败不经过写回。
- 读端按既有 Roslyn 区域成员和 scope 合同独立核对每条出口，不通过相同源码位置猜测复制段归属。
- liveness 保留失败赋值前、处理器仍会读取的旧值。同步求值失败边上的 Task 所有权取提交前状态，
  不把未完成的 Task 赋值当成已取得所有权；正常边才提交新 owner。
- 无 try/catch/finally 的 Task 方法仍有方法级异常传播语义；其异常区域和 scope 列表可为空。

源码合同最初只接入验证器与数据流。现由 `CSharpLanguageErrorCompiler` 组合同步 outcome、共享
异常 catalog 和受检 Task 转交后发布 IR 29；普通 `CSharpGuestLowerer` 仍拒绝直接发布未组合产物。
IR 28 的旧 Semantic provenance 配对不放宽。静态初始化
49 与新合同的组合另行版本化，禁止把 base 50 偷放进旧 49 包装。此步骤不代表原始 29 案例已执行。

## IR 28 合同

### IR 29 源码执行组合（API 预览）

IR `29/1.28` 精确对应 Semantic `50/1.59`，复用 IR 26 的 Task、取消、异常出口和局部 owner 协议；
不修改 IR 28 的 provenance 配对，也不伪造 Semantic 46。顶层 `async_synchronous_exceptions.sites`
逐项记录源方法、实际函数、outcome 调用 block/指令、异常目标、异常 Task owner 与类型局部变量。
此版本不组合静态存储；静态初始化仍需后续独立版本合同。

调用后立即读取并分支检查 outcome status。错误分支创建 Task、检查创建成功，从同一 outcome 读取
类型/来源/对象并提交；只有提交成功才能释放旧异常 owner、发布新 owner，再进入源码指定的异常目标。
失败分支不得进入正常取值或后续实参/赋值；创建或提交失败仍为 Host failure。读端逐条核对字段来源、
控制流、唯一写入、owner 替换顺序及最终目标，未列出的非 fresh fault 调用不得发布。

编译组合上下文只由已验证源码在编译器内部创建。同步函数转换为 outcome，异步函数保留 Task 返回值，
保留原 Semantic provenance，并在全部组合及校验完成后才返回可发布模块。同步失败边释放赋值提交前的
局部 owner；正常边使用提交后的 owner。旧 artifact 不序列化新字段，降版或字段缺失必须拒绝。

### IR 28 既有转交协议

顶层增加必需的 `task_error_transfers`，包含 `base_schema_version`、`base_ir_version` 和非空 `sites`。
基础配置仅接受已有 Task/error IR 20–26 及其精确版本对；旧版本不能夹带该字段。
基础配置原有的 Semantic provenance、Task 生命周期、取消与异常出口检查完整保留。
可选 `static_storage` 必须使用相同基础配置，仍按 IR 27 的静态槽规则验证，不形成递归包装。

每个 site 记录函数、同步调用所在 block/指令、错误 block 和 Task fault 指令位置。读端独立核对：

- 调用是返回已声明 outcome 的直接函数调用，结果及 status 临时值各有唯一写入。
- status 来自该结果的 `field:status`；调用后立即检查，真分支进入错误 block。
- 错误 block 只有这个入口；Task fault 的类型、来源和对象分别来自同一 outcome 的三个字段。
- 不允许结果被覆写、别名化或在转交前修改。未列出的非 fresh fault 提交仍拒绝。
- 重复 site、缺失 site、错配三元组、分支绕过、错误指令位置和降版均拒绝。

WASM provenance 保留外层 IR 28 及精确基础配置；Runtime 核对 catalog、版本和来源摘要后，
复用 `avid_task_fault_language_error_v1`。不增加裸对象导入，不改变旧 Host ABI。
Host 仍要求正确 Task 类型与 Session、有效 catalog token、当前 VM 调用帧中的对象根；
新 Task 根建立成功后才允许释放旧 owner，转交失败走 Host failure/trap。

## 下一步

### 同步与异步编译组合约束

接入 WASM 前，编译器先从同一份源码合同计算异常类型、来源和同步调用影响范围：

- Semantic `50/1.59` 同时携带同步 `exception_flows` 和异步异常出口时，两份合同必须都通过校验。
  不能因为存在同步异常而绕过异步段、区域和 Task 所有权校验。
- 同步调用链改写为 outcome 返回值；传播到 `async` 方法时停止。该方法仍返回 Task，其同步调用失败
  交给已绑定的异常出口。调用该 Task 方法的同步工厂或其他异步方法不能仅因此被改成同步 outcome。
- 编译器统一排序同步 throw、异步 throw、取消与静态初始化的类型和源码位点；每个类型和位点只有一个
  token。同步 producer、异步 catch 分派和最终 catalog 必须消费同一编号。旧版本保持原有编号与输出。
- 此组合分析不允许普通 Guest 入口发布 Semantic 50。新的执行合同、outcome 转交及 owner 清理完整接通
  并验证之后才解除 `ASCG1026`，不伪造旧版本 provenance。

上述组合分析已接入编译器。`SemanticLanguageErrorEffectPlanner` 分开返回同步 outcome 方法与
`AsyncBoundaryMethodIds`；原始 C10 源码的同步调用影响范围不再越过 Task 方法。共享异常表由
`CSharpLanguageErrorCatalogBuilder` 生成，同步 producer、异步 throw、取消和发布端使用同一套编号。
发布端按各源码单元的实际长度校验位置，拒绝来源缺失、同名来源长度冲突与越界位置；旧执行版本仍
