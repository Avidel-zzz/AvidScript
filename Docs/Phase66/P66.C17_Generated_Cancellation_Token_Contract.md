# P66.C17：正式生成 API 的标准取消 token

本节补齐 C16 发现的生产 facade 缺口。公开生成器声明 `AvidCancellationToken` 到 `System.Threading.CancellationToken` 的隐式转换，并为 delay、object load 与 generic outcome awaitable 生成标准 token 的 `WithCancellation` overload。保留原有 token API。

转换声明由现有 C# projector / Guest lowerer 识别，运行时仍使用 Session 管理的取消源身份；UE 不执行 CLR。Editor facade emitter 更新为 49.5.0，不改变 descriptor Schema、Guest IR、WASM import 或 Runtime ABI。旧包不会因版本更新而改写；使用新 API 的源码需要重新生成绑定包。

真实包回归发现普通脚本在 profile 下多出四个未使用的异常类型，导致 Semantic、IR 和 WASM 的哈希变化。原因是 reference facade 出现标准 token 类型时就注册了隐式空接收者异常；修复后仅当源码实际使用 token 值时才注册，保持普通脚本的原始字节。该回归先在未修复版本上失败，再运行完整 C# 检查与真实包构建。

```csharp
using AvidScript;
using System.Threading;
using System.Threading.Tasks;

public static async Task<int> Wait()
{
    var source = AvidCancellationSource.Create();
    CancellationToken token = source.Token;
    try
    {
        await AvidContinuations.NextTickAsync().WithCancellation(token);
        return 1;
    }
    finally
    {
        source.Release();
    }
}
```

Windows 验证使用真实 publish commandlet 的唯一输出目录，不修改生成的 C#。先检查生成确定性与 manifest，再编译真实 facade 的三种标准 / legacy overload，随后从正式 `-LanguageProfile gameplay-v1` 入口验证标准 token 配合 Timer 的 cold / warm、worker 与 prepared。运行绑定包合同测试时传入 `-StandardCancellationTokens`；旧生成器包不传此开关，继续检查缺少转换声明时的拒绝。

实际测试还发现：将相同 Task 中的 Timer 替换成 object load，与静态初始化及 catch/finally 一起使用时，当前 source execution 没有可接受的组合计划。正式入口保留 `ASBI4701 / ASCG1004` 并拒绝发布 WASM。本节没有扩展该执行合同；object / generic outcome 的 overload 已有真实声明编译证据，不能据此宣称这两类异步的完整错误与静态组合已可运行。下一节优先补齐该组合能力，再继续 Editor 默认接入。

构建与 EditorCmd 串行、BelowNormal、单任务并发；复用已安装 SDK 和固定 CLI HOME。记录用户 / 机器 PATH 前后快照。仅回收本轮唯一目录内的生成物，保留日志与文件哈希，不清理已有 UE 输出或此前被拒绝的路径。Editor 默认接入、共享类型域回滚和 teardown 仍属于后续工作。
