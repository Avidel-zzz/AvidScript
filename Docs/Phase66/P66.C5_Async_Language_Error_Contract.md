# P66.C5：`Task<int>` 的语言错误与跨 `await` 清理

状态：实现合同；本文不是功能已可用的声明。目标平台先固定为 Win64，Android/iOS 验收暂缓。

## 要跑通的源码

```csharp
static async Task<int> LoadAsync()
{
    await AvidContinuations.NextTickAsync();
    throw new InvalidOperationException();
}

static async Task<int> ReadAsync()
{
    try
    {
        int value = await LoadAsync();
        return value;
    }
    catch (InvalidOperationException)
    {
        return 7;
    }
    finally
    {
        CleanupCount++;
    }
}
```

`LoadAsync` 的错误必须成为其任务的 `Faulted(language error)` 终态；`ReadAsync` 恢复时按类型进入 `catch`，执行一次 `finally`，最终以值 `7` 成功。不同类型的 `catch` 不得吞掉错误。成功任务走正常返回；取消不是 C# 语言异常；Host import 拒绝、VM trap、fuel 和越界都不得被脚本 `catch` 捕获。

## 现有边界

- [Async CFG](../../Tools/AvidScript.CSharpSemantic/Analysis/SemanticAsyncControlFlowProjector.cs) 只有 goto、branch、await、return；带 `catch` 的 `try` 和 `try/finally` 中的 `await` 被 `ASCS5420` 拒绝。[异常流程验证器](../../Tools/AvidScript.CSharpSemantic/Validation/SemanticExceptionFlowContractValidator.cs) 不允许同一方法同时拥有 async 与异常计划。
- [Task await lowering](../../Tools/AvidScript.CSharpGuest/Lowering/CSharpTaskAwaitLowerer.cs) 将成功以外的终态统一传播或 trap；它没有异常处理目标。[组合编译器](../../Tools/AvidScript.CSharpGuest/Lowering/CSharpLanguageErrorCompiler.cs) 只接受互不调用的同步异常方法和 Task 方法。
- 原生结果槽已能保有语言错误载荷，并在 `avid_task_propagate_failure_v1` 时共享根租约。Guest IR 20/1.19 和 Runtime 已提供 `avid_task_fault_language_error_v1`、`avid_task_language_error_meta_v1`、`avid_task_language_error_root_v1`；当前 C# 生成函数没有调用这些 import。

## 版本化表示

1. Semantic 新合同使用 schema **41** / semantic **1.50**。`SemanticAsyncMethod` 增加可空的异步错误计划，其中每个抛出点和失败的 `await` 均绑定到本方法的 segment ordinal、源码 span、Roslyn 异常区域、按内到外的清理区域及候选 `catch`。抛出点记录实际异常类型、零参构造器身份和源码令牌；`await` 的正常目标、错误目标和取消目标必须分别可达。异常变量及跨挂起存活的错误对象进入现有状态帧，不能借用调用栈地址。
2. 同步 [SemanticExceptionFlow](../../Tools/AvidScript.CSharpSemantic/Model/SemanticExceptionFlow.cs) 继续服务同步方法。新 async 计划与其共享异常类型和源码令牌规则，但不把 Roslyn 的同步 CFG 冒充 async 执行图。schema 40/1.49 继续只允许互不重叠的方法；旧版本夹带 async 错误字段须拒绝。验证器重算 segment/region 归属、handler 优先级、清理顺序、局部类型和来源，拒绝伪造跳边与悬空 segment。
3. Guest IR 新合同使用 schema **21** / IR **1.20**，provenance 只接受配对的 Semantic 41/1.50。已有 Task 和语言错误 Host import 保持 v1 签名；新增的是编译后的异常控制流与根所有权要求，不向旧 IR 20 偷加语义。旧 IR 20/1.19 继续读取和执行原有的互不重叠组合产物。

## 执行规则

| 位置 | 必须执行的动作 |
| --- | --- |
| `async Task<int>` 中 `throw new` | 仅接受当前同步语言错误子集中的零参框架异常。创建有当前 VM 调用帧根的错误对象，按模块目录取类型/源码令牌，调用 `avid_task_fault_language_error_v1` 终结当前生产者任务。检查 Host 接受结果，然后按任务 owner 释放本次调用的 token 与局部根；拒绝时走不可捕获的失败路径。 |
| `await` 读到 `Succeeded=1` | 读取值并继续正常目标；不访问错误 import。 |
| `await` 读到 `Faulted=2`，且存在脚本处理区域 | 在释放被等待任务引用之前调用 `avid_task_language_error_meta_v1` 和 `avid_task_language_error_root_v1`。两者验证任务身份、故障载荷和当前调用帧根；普通 Host/VM 故障在这里被 Host 拒绝，不能进入 `catch`。按类型与源码计划选择第一个匹配 handler，先运行应执行的内层 `finally`。未匹配时把原错误及根租约传播给生产者任务。 |
| `await` 读到 `Faulted=2`，且无脚本处理区域 | 沿现有 `avid_task_propagate_failure_v1` 传播，保留语言错误载荷；普通故障仍为普通故障。 |
| `await` 读到 `Cancelled=3` | 不读取语言错误 import，不进入 `catch`。仍有效的 Session 可以沿明确的取消清理边运行 `finally`，然后传播取消；Object/World teardown 不重新进入已经失效的脚本。 |

错误对象从任务租约转入当前调用帧根后，才可释放最后一个被等待任务引用。若 handler 在另一个 `await` 后继续，状态帧必须持有该对象的受管根；恢复、取消、reload 和 teardown 各只能由一个 owner 释放它。`finally` 自身抛错按 C# 规则替换在途语言错误；普通 Host/VM 失败不执行脚本 `catch`，由 Session 负责回收。`async void` 边界不得把未捕获语言错误静默改为成功返回，须交给现有 Session 错误报告路径。

## 实现次序与证据

1. Semantic 先发布并验证同方法的 `throw`、`await`、`catch`、`finally` 区域图；旧版本、错误目标、错误类型和不受支持的构造器须在源码位置失败。序列化往返必须字节确定。
2. Guest 将终态分支接到真实 handler/cleanup block，并生成 fault、meta、root 调用。立即完成和跨帧完成共用同一错误路由；生产者、等待者与错误根的 release 路径逐边检查。
3. 同一份源码先与 .NET 对照正常值、匹配/不匹配 `catch`、嵌套 `finally`、清理再次抛错、重抛和取消；再在 Win64 Wasmtime JIT 与 WAMR Interpreter 中跑真实 C# → Semantic → IR → WASM，核对状态、源码令牌、清理次数、任务引用与受管根归零。独立负例验证普通故障不被 `catch` 捕获、teardown 不重入、旧产物不能冒充新合同。

以上三步和双 VM 执行证据齐备之前，README 继续声明异步抛错和 `await` 后捕获未支持，P66.C 不标记完成。
