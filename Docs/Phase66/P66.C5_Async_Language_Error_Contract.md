# P66.C5：`Task<int>` 的语言错误与跨 `await` 清理

状态：实现中。受限的 `async Task<int>` 生产者 `throw new` 已能在 Win64 生成并执行；同方法 `await` 后捕获和异步 `finally` 尚未实现。Android/iOS 验收暂缓。

## 要跑通的源码

```csharp
static async Task<int> LoadAsync()
{
    await AvidContinuations.NextTickAsync();
    throw new InvalidOperationException();
}

static async Task<int> ReadAsync()
{
    try
    {
        int value = await LoadAsync();
        return value;
    }
    catch (InvalidOperationException)
    {
        return 7;
    }
    finally
    {
        CleanupCount++;
    }
}
```

`LoadAsync` 的错误必须成为其任务的 `Faulted(language error)` 终态；`ReadAsync` 恢复时按类型进入 `catch`，执行一次 `finally`，最终以值 `7` 成功。不同类型的 `catch` 不得吞掉错误。成功任务走正常返回；取消不是 C# 语言异常；Host import 拒绝、VM trap、fuel 和越界都不得被脚本 `catch` 捕获。

## 现有边界

- [Async CFG](../../Tools/AvidScript.CSharpSemantic/Analysis/SemanticAsyncControlFlowProjector.cs) 只有 goto、branch、await、return；带 `catch` 的 `try` 和 `try/finally` 中的 `await` 被 `ASCS5420` 拒绝。[异常流程验证器](../../Tools/AvidScript.CSharpSemantic/Validation/SemanticExceptionFlowContractValidator.cs) 不允许同一方法同时拥有 async 与异常计划。
- Semantic 41 的 `ASCS5422` 诊断计划保留同文件同步方法的 control-flow graph；正式样例同时导出 `BeginPlay` 和 `Tick`。其他支持错误仍阻止这条受限构建路径，不能借此放行无效 C# 源码。
- [Task await lowering](../../Tools/AvidScript.CSharpGuest/Lowering/CSharpTaskAwaitLowerer.cs) 将成功以外的终态统一传播或 trap；它没有异常处理目标。[组合编译器](../../Tools/AvidScript.CSharpGuest/Lowering/CSharpLanguageErrorCompiler.cs) 仍只接受互不调用的同步异常方法和 Task 方法。
- 原生结果槽能保有语言错误载荷，并在 `avid_task_propagate_failure_v1` 时共享根租约。IR 21 的受控 C# 路径现会调用 `avid_task_fault_language_error_v1`；`avid_task_language_error_meta_v1` 和 `avid_task_language_error_root_v1` 仍待接入脚本 `catch` 路由。

## 版本化表示

1. 首个 Semantic 合同使用 schema **41** / semantic **1.50**：记录 `async Task<int>` 中受支持的 `throw new`，将 segment ordinal、源码 span、实际异常类型和零参构造器身份绑定在 `SemanticAsyncMethod.ErrorPlan`。投影继续发出源码位置的 `ASCS5422`；默认编译拒绝该诊断产物，只有显式的 `-LanguageErrors bounded` 路径验证计划后降级为可执行 IR。旧版本夹带错误计划或 `throw` 转移必须拒绝。
2. 后续 `await` 失败路由、`catch` 和跨挂起 `finally` 必须再升 Semantic 版本，记录 Roslyn 异常区域、正常/错误/取消目标、由内到外的清理顺序与异常变量的状态帧所有权。验证器须重算 segment/region 归属、handler 优先级、局部类型和来源，拒绝伪造跳边与悬空 segment。同步 [SemanticExceptionFlow](../../Tools/AvidScript.CSharpSemantic/Model/SemanticExceptionFlow.cs) 继续服务同步方法，不把其 CFG 冒充 async 执行图。
3. 首个 Guest 执行合同使用 schema **21** / IR **1.20**，provenance 只接受配对的 Semantic 41/1.50；当前仅覆盖 `async Task<int>` 生产者的 `throw` fault lowering。`catch/finally` 路由再升 IR 版本。已有 Task 和语言错误 Host import 保持 v1 签名；旧 IR 20/1.19 继续读取和执行原有的互不重叠组合产物。

## 执行规则

| 位置 | 必须执行的动作 |
| --- | --- |
| `async Task<int>` 中 `throw new` | 仅接受当前同步语言错误子集中的零参框架异常。创建有当前 VM 调用帧根的错误对象，按模块目录取类型/源码令牌，调用 `avid_task_fault_language_error_v1` 终结当前生产者任务。检查 Host 接受结果，然后按任务 owner 释放本次调用的 token 与局部根；拒绝时走不可捕获的失败路径。 |
| `await` 读到 `Succeeded=1` | 读取值并继续正常目标；不访问错误 import。 |
| `await` 读到 `Faulted=2`，且存在脚本处理区域 | 在释放被等待任务引用之前调用 `avid_task_language_error_meta_v1` 和 `avid_task_language_error_root_v1`。两者验证任务身份、故障载荷和当前调用帧根；普通 Host/VM 故障在这里被 Host 拒绝，不能进入 `catch`。按类型与源码计划选择第一个匹配 handler，先运行应执行的内层 `finally`。未匹配时把原错误及根租约传播给生产者任务。 |
| `await` 读到 `Faulted=2`，且无脚本处理区域 | 沿现有 `avid_task_propagate_failure_v1` 传播，保留语言错误载荷；普通故障仍为普通故障。 |
| `await` 读到 `Cancelled=3` | 不读取语言错误 import，不进入 `catch`。仍有效的 Session 可以沿明确的取消清理边运行 `finally`，然后传播取消；Object/World teardown 不重新进入已经失效的脚本。 |

错误对象从任务租约转入当前调用帧根后，才可释放最后一个被等待任务引用。若 handler 在另一个 `await` 后继续，状态帧必须持有该对象的受管根；恢复、取消、reload 和 teardown 各只能由一个 owner 释放它。`finally` 自身抛错按 C# 规则替换在途语言错误；普通 Host/VM 失败不执行脚本 `catch`，由 Session 负责回收。`async void` 边界不得把未捕获语言错误静默改为成功返回，须交给现有 Session 错误报告路径。

1. Semantic 已发布并验证 `async Task<int>` 的 `throw` 诊断计划，旧版本、错误类型和不受支持的构造器在源码位置失败，序列化往返保持字节确定。同文件的普通 `Tick` 控制流图保留，其他支持错误仍被拒绝；固定 SDK 回归 **398/398** 通过。
2. 首个 Guest 执行切片将 `throw` 转为受管错误对象、目录令牌和 `avid_task_fault_language_error_v1` 调用，显式检查 Host 接受并释放任务本地引用。聚焦编译测试 **2/2**、完整 Guest 回归 **553/553** 通过；旧 IR 版本拒绝伪造的 Semantic 41 产物。可重复入口：[`TestAvidScriptAsyncLanguageError.ps1`](../../Build/TestAvidScriptAsyncLanguageError.ps1)；传入当前生成的 `avidscript.engine.core` package 后还会构建并执行[正式高层样例](../../Fixtures/Phase66/TaskLanguageError.cs)。
3. 正式 `BuildCSharpActorLifecycle.ps1 -LanguageErrors bounded` 发布 `direct_abi_built`、Semantic 41/1.50、IR 21/1.20、WASM、调试映射和 manifest，默认模式拒绝同一源码。Win64 no-clean Editor 构建与 `AvidScript.Runtime.Continuation.CompiledTaskLanguageError` Automation **1/1** 通过；正式构建产物在 Wasmtime JIT、WAMR Interpreter 各执行一次同步 `Tick`，随后完成异步生产者故障与等待者唤醒，任务引用与 teardown 根归零，显式 GC 回收错误对象。日志：`Saved/Logs/AvidScript_CompiledTaskLanguageError_20260925T105848545Z.log`。这验证生产者故障链，不证明 `catch/finally` 或无处理者错误的最终诊断质量。
4. 下一切片需补同方法 `await`、`catch`、`finally` 区域图，生成 fault、meta、root 与 handler/cleanup 路由。再用同一源码与 .NET 对照正常值、匹配/不匹配 `catch`、嵌套 `finally`、清理再次抛错、重抛和取消；独立负例验证普通故障不被 `catch` 捕获、teardown 不重入、旧产物不能冒充新合同。
