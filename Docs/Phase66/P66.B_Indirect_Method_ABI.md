# P66.B：间接方法参数帧的执行基础

## 范围与当前边界

在[生产实例上下文入口](P66.B_Production_Method_Entry.md)之上准备完整方法 ABI。本组交付语言无关的 IR 合同、调用方编码和可执行 WASM 适配器，保留原生 VM 帧上限；适配器只需要两个 i32 参数：线性内存地址与字节数。参数自身存放在受检的间接帧中。

**尚未连接 C# 方法目录和生产跨对象路由。** 当前 `call_framed` 在同一模块内调用已声明的适配器；本组真实 VM 证据来自编译器生成的 Guest IR 夹具。它不证明普通 C# 跨对象调用、virtual/interface、持久 event/await 或 P66.B 已完成。既有生成 UFUNCTION 参数入口的三类形状仍保留。

## 合同

- Guest IR 升级为 **7/1.6**，新增 `framed_exports` 和 `call_framed`；兼容读取 1/1.0 至 6/1.5。旧版本携带新能力、未来版本、重复/未知目标、错误参数或返回类型均拒绝。
- `GuestFramedExport` 绑定函数、导出名和有序的 value/ref/out/in 传递方式。非值参数必须使用现有 borrowed descriptor；引用返回继续拒绝，不把别名静默转换成值。
- `GuestCallFrameLayout` 是布局与签名的 owner。小端、16 字节对齐、64 字节头，单帧至多 64 KiB、256 参数；模块至多 4096 个适配器。头包含 magic、版本、总长度、SHA-256 签名与必须为零的保留字段。
- SHA-256 绑定参数顺序、传递方式、返回类型、可达类型图、字段布局和函数引用签名；能处理递归托管类型，不依赖类型发现顺序。实际代码身份与目标对象授权由后续 Runtime 路由另行验证，签名本身不是执行许可。
- 每个调用 activation 保留独立帧空间，递归不会复用全局参数缓冲。适配器先用 64-bit 运算核对范围、当前保留栈区、内存长度和头，再读取参数。
- 值结构复制到参数区；托管引用保持同一 token；ref/out/in 复制 borrowed descriptor，保留原 owner、地址和偏移。ref/out 没有独立值回拷，多个参数可指向同一位置。readonly 表达式规则仍由语言前端负责。
- 返回值及 borrowed pointee 的托管叶子对应调用者已有的 root。适配器在返回前更新这些 root；堆内字段由 owner 保活，栈引用通过原位置读取。适配器不创建持久 root，也不延长借用至 await。
- 普通导入导出、原始指针和 borrowed descriptor 的原有防逃逸校验保持。生成适配器不能被当作任意原生调用接口；生产消费者必须要求同域活动来源、当前代码身份和合法目标。

WASM 增加版本化 `avidscript.call_frames` custom section，记录适配器名、规范签名和帧长度。函数和调试索引保持原顺序，适配器追加在原函数之后。取消检查的调用图把 `call_framed` 还原为实际 Guest 目标，递归不会因适配器而漏检。

相关实现：[布局](../../Tools/AvidScript.GuestIr/Layout/GuestCallFrameLayout.cs)、[验证器](../../Tools/AvidScript.GuestIr/Validation/GuestFramedCallValidator.cs)、[调用方](../../Tools/AvidScript.WasmBackend/Codegen/WasmFramedCallEmitter.cs)、[适配器](../../Tools/AvidScript.WasmBackend/Codegen/WasmFramedExportCompiler.cs)。现有编译缓存和 Worker 的工具链 fingerprint 递归包含 Guest IR/backend 源码；新模型、布局和 emitter 会改变工具链身份，序列化产物与 WASM 哈希亦改变。

- 编译器验证 malformed contract、原始导出逃逸、旧版/未来版、名冲突、参数失配、规范 roundtrip、稳定签名及递归取消证明。

本组未新增 Shipping、性能、完整 C# 跨对象或人工玩法验收。未单独验证 Host 在适配器返回与调用方恢复之间触发 GC 的重入桥接场景，也未完成恶意帧头/根贷款的生产入口故障矩阵；这些属于下一组生产消费者接入的必须验证项。

架构检查只报告工作树输入与 Git tree 不一致（包括受保护的 `AvidScriptWasmReloadTypes.h`），未报告其他结构违规；不声明 clean architecture Gate。最初 backend runner 使用旧的“7/1.6 是未来版本”拒绝夹具失败，已改为拒绝 8/1.7；该失败不算通过证据。
