# P66.B：环境堆 Host ABI 与调用根清理

## 本组交付

环境堆现可通过真实 WASM 调用；Wasmtime 与 WAMR 共用协议解释器和错误合同。Runtime 实例是堆与调用根的 owner，VM 负责在每次导出执行前后通知 owner。该工作连接了已有环境堆与 WASM，但没有放开 C# 捕获 lambda 的诊断，也不代表逃逸闭包的编译器 lowering 已完成。

固定接口为 `avidscript.avid_managed_heap_v1(i32 input, i32 inputBytes, i32 output, i32 outputBytes) -> i32`，不接受 `env` 别名。成功返回 `1`；范围、协议或堆操作失败形成带分类的 Host trap。已有 import 编号保持不变，新编号追加到目录末尾。

线协议常量和操作编号由 `Source/AvidScriptCore/Public/AvidScriptManagedHeapAbi.h` 管理。Runtime 的协议解释器不依赖 UE 或 VM，可直接由独立 MSVC runner 编译。VM 层只验证并借用内存，不依赖 Runtime 堆实现。

## 线协议

所有整数均为 little-endian，不要求自然对齐。请求开头为 `u32 0x3150484d`（字节 `MHP1`）与 `u32 command`。下表列出其后的完整 payload；不能有尾部多余字节。`token` 为不透明 `u64`，不得由 Guest 解释 owner、代际或槽位编码。表中输出长度是精确值，不是容量下限。

| command | payload | output |
| --- | --- | --- |
| 1 Configure | `u32 count`，随后逐布局 `u32 type, u32 size, u32 refCount` 与 `refCount` 个 `(u32 offset, u32 targetType)` | 0 |
| 2 PushFrame | 无 | frame token，8 bytes |
| 3 PopFrame | frame token | 0 |
| 4 CreateRoot | frame token、初始 object token | root token，8 bytes |
| 5 SetRoot | root token、object token | 0 |
| 6 ReleaseRoot | root token | 0 |
| 7 Allocate | `u32 type`、root token | object token，8 bytes |
| 8 ReadBytes | object token、`u32 type, u32 offset, u32 count` | count bytes |
| 9 WriteBytes | object token、`u32 type, u32 offset, u32 count`、count bytes | 0 |
| 10 ReadReference | object token、`u32 type, u32 offset` | object token，8 bytes |
| 11 WriteReference | object token、`u32 type, u32 offset`、object token | 0 |
| 12 Collect | 无 | 0 |

frame `0` 表示模块持久根，object `0` 表示空引用。Configure 仅能成功一次；type 与 reference 的合法性仍由堆验证。调用者须显式释放持久根，或由对应 continuation/订阅 owner 在后续集成时释放；模块卸载最终释放全部资源。

请求最多 1 MiB，响应最多 64 KiB；最多 1024 个布局、每布局 256 个引用字段、全部布局 65536 个引用字段。布局大小不超过 64 KiB，并继续受堆实例的更小限额约束。解析器先检查完整布局及总引用量，再分配描述数据。

input 地址非零。无输出时必须传 `(0, 0)`；有输出时地址非零。地址按无符号 wasm32 解释，长度按非负 i32 验证，计算区间使用 64-bit，拒绝溢出和输入/输出重叠。两个范围都通过实际 VM 内存检查后才能调用 Runtime；Runtime 再检查协议、精确响应长度和令牌。分配响应区不足时不能先分配；失败不写响应。分配自身遇到限额时可能收集不可达对象，沿用已有堆合同。

协议同步执行，不重入 Guest、不增长 Guest memory、不保留借用视图。普通 byte 写入不能绕过引用字段的类型化写屏障。

## 调用与失败清理

只有实际导入该 ABI 的模块启用 `IAvidScriptVmInvocationObserver`，缺少 observer 的加载请求以 `managed_heap_scope_required` 拒绝。普通模块不调用 observer；本组未测量新增分支的性能影响，不作零成本或性能领先声明。

覆盖入口包括 WAMR 通用调用，以及 Wasmtime 通用、预备通用、`i32,i32 -> i32` 和 `i32,f32 -> void` 预备快路径。每次进入保存当前 frame depth；正常返回和 trap 都在 VM 延迟卸载之前回退到该深度。内层调用不能通过 PopFrame 弹出调用者的帧；持久根与进入前已有帧保留。清理移除根，未被引用的对象由 Collect 或后续分配压力回收，不保证每次返回即执行 GC。

堆在 backend 加载前创建，加载失败释放。该 ABI 只允许在受控导出调用内使用；WASM start 阶段不支持调用环境堆。布局初始化应在显式初始化/BeginPlay 导出内完成。

错误分类：`managed_heap_range`（地址、长度或重叠），`managed_heap_protocol`（版本、包形状、配额或调用帧边界），`managed_heap_rejected`（堆类型、令牌、引用字段或资源限制），`managed_heap_invocation`（缺少活动导出调用）。堆错误细节使用符号名，避免依赖 C++ enum 序号。

## 验证

- `Build/TestAvidScriptManagedHeap.ps1`：13/13，通过真实产品核心与协议源码。包含全部 12 类命令、共享/持久根、自引用回收、截断布局、尾部字节、未知版本/操作、精确输出长度、引用总预算和 wasm32 范围检查；保留原有 4000 步图 oracle 与完整根代际耗尽测试。
- UE5.8 canonical Editor no-clean UBT：通过。首轮读取函数名与 UE 编译上下文冲突，改为明确的 `ReadToken/ReadUint32` 后恢复。
- `Build/TestAvidScriptManagedHeap.ps1 -RuntimeAutomation`：2/2，通过并正常退出。Ownership 保留模块/Session 重载回滚；HostAbi 对 Wasmtime JIT 和 WAMR Interpreter 分别执行真实 WASM 的布局注册、分配、写入、读回、trap、范围/重叠/短输出/版本拒绝及跨堆令牌拒绝。另验证两种 Wasmtime 预备快路径的返回与 trap 清理、错误 import module/签名和缺失 observer。
- `AvidScript.Architecture.VM`：24/24，逐项唯一测试数、零失败、队列完成与正常退出均核验。覆盖原有静态/动态 import、内存借用、WAMR 执行与新目录合同。
- 首轮 HostAbi 未通过：测试错误地统一了两个 backend 既有 trap 分类，并把 WAMR 扩展实例内存内的地址当成越界。已改用真正越界地址及各自既有 trap 合同；签名拒绝 fixture 也改为合法 WASM 的不兼容返回类型。重新执行完整聚焦集合通过。
- 架构内容检查已纳入新 canonical-only import；工作树与 Git tree 的证据身份检查仍受既有 protected header 改动影响，不声明 clean-tree Gate。

## 下一步与保留范围

下一组由 Semantic 环境计划生成布局、Guest IR 与 ABI 调用，完成自动根插桩、共享 cell 读写和带环境的间接调用。随后接入返回值暂存、跨 await、订阅与 World/Object teardown 的持久根 owner。活动闭包迁移、完整 delegate/event 语义仍待实现。

当前协议建立正确性与生命周期边界，尚未对细粒度 heap crossing 做性能验收。后续需要结合实际闭包 workload 评估批量访问、编译器消除重复访问与根操作成本；不能以有界内存或独立测试通过代替游戏帧内回收延迟证明。P66.B 保持进行中。
