# P66.C21：源码身份与构建缓存

## 冻结范围

C20 的正式 Actor/Component 源码使用逻辑 `SourceId`，但 semantic cache 和 prepared reader 仍将它与物理文件路径混为一值，因而拒绝复用。本节修复正式构建链，不改玩法源码、Guest 字节、Runtime 或反射结构，也不关闭缓存来绕过准入。

构建报告 Schema 1 增加 `source.source_id`；`source.file` 仍用于定位实际输入文件，原始文件 SHA-256 继续独立核对。逻辑身份区分大小写，不能解析为文件路径。frontend、semantic、debug map 和 Runtime manifest 必须保持同一身份。

semantic cache 的 canonical input 同时包含物理输入身份和逻辑 `source_id`；工具链指纹新增 prepared reader、缓存 owner 和正式构建脚本，规则变化使旧条目失效。默认身份与显式指定同一默认值应产生同一缓存键，不同逻辑身份必须产生不同键。compilation cache 已包含 frontend/semantic 原始字节哈希，复用现有合同。

prepared reader 先核对物理路径与源码哈希，再独立核对调用方身份、报告身份和两个语义产物。旧报告缺少新字段时仅以原 `source.file` 为身份，不能从产物推断逻辑别名。非法类型、空身份、身份不匹配和伪造产物在任何复制前拒绝。cache reader 对调用方与 context 的身份冲突在隔离缓存条目前拒绝，不能把有效条目当作损坏产物搬走。

## 验证要求

- 使用 C20 未改写的普通 C# Actor/Component 源码、真实生成 facade 和已验证类型清单，验证冷构建、双缓存命中与 prepared 复用；比较 frontend、semantic、IR、debug、state、WASM 六份原始字节。
- 第二个逻辑身份必须独立冷构建并命中自己的缓存；debug map 保留正确身份。默认身份、显式默认身份及旧默认报告继续可读。
- 核对身份冲突、缺少字段的逻辑别名、非法字段和重算哈希的产物伪造均拒绝；既有目标文件和有效缓存条目不变。
- 受影响合同串行执行，复用 SDK 8.0.416；BelowNormal、单并发、无持久环境变量写入。缓存留在项目 `Saved/AvidScript` 内，日志和工具链 CLI state 留在仓库外，不清理用户或引擎产物。

本节不代表 P66.C/D 或 Windows 发布闭环完成。结构热重载、完整调试和真实玩法的默认开发流程仍按原计划推进。

## 实现与验证

例如，本节的实际文件是 `Plugins/AvidScript/Fixtures/Phase66/GeneratedNaturalReload.cs`，编译身份是 `Fixtures/Phase66/GeneratedNaturalReload.cs`。报告分别保存 `source.file` 和 `source.source_id`。改成 `Scripts/Skills/GeneratedFlow.cs` 时，原始文件和哈希不变，但缓存键与源码映射必须变化；不能命中旧映射。

正式构建入口将当前身份传到缓存 factory、reader、publisher 和 prepared reader。缓存 context 冲突在获取条目和隔离损坏内容之前拒绝。原有文件位置、原始哈希、绑定授权、语言配置、产物路径限制和原子发布检查保持独立。

专项入口为 `Build/Contracts/TestCSharpSourceIdentityCache.ps1`，输入真实生成绑定包的 `BindingPackagePath` 和同源类型清单的 `GeneratedTypeManifestPath`。可选 `BaselineBuildReportPath` 比较六个已执行的 C20 产物。过程复用安装 SDK，不安装工具链，也不修改原生生成目标。

最终专项记录位于 `%LOCALAPPDATA%/AvidScript/Verification/SourceIdentityCache/20261004T103640033Z-146aa52a/results.json`；固定 SDK 8.0.416、BelowNormal、持久 PATH 未变。`worker-cache-results.json` 保存两个正常 worker 模式的热缓存核对。正式工具计数在命中与 prepared 时为零；不同别名独立构建并命中自己的条目。旧默认报告可复用，缺少身份字段的逻辑别名及重算哈希的身份伪造均拒绝，既有目标文件和有效缓存条目保留。

缓存回归夹具补齐当前 compiler worker 文件，并使用现有 Semantic 31/1.40 成功合同。测试清理前验证绝对命名空间和 reparse point；仓库外输出使用独立 LocalAppData 目录，共享 transaction 目录只清理本次 PID 新建的对象，不扫描清除其他任务的事务。

本节没有修改 C# 编译实现或 UE Runtime，六份正式产物与 C20 实际执行字节一致，因此保留 C20 的原生执行证据，不重复启动 Editor。Harness Auto 仍保守建议 Runtime 检查；本次架构检查只发现开发工作树与 Git tree 不同，包括受保护的原有 header 修改，没有结构违规。本节不作为 clean Gate 或新的原生验收。

## 下一步

单次探针中，冷构建约 35 秒，命中构建约 9 秒，prepared 约 8 秒。这不是多样本性能基准，也不能据此宣称领先。下一节先拆分语义准入、产物校验、工具进程和发布耗时，确认命中后仍消耗时间的路径，再沿同一正式源码及授权合同优化日常修改循环。
