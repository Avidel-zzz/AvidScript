# P66.B：事件与异步状态的持久根

## 生命周期合同

continuation 的原生状态入口现可同时持有复制的状态字节与唯一根租约；旧 Guest 状态 ABI 仍仅保存原始字节，不能以此证明 C# 跨 await 引用已保活。事件订阅、挂起任务、暂停帧应由各自 owner 持有原生根租约。恢复读取不立即释放根，必须保持到本次回调完成或显式移交下一 owner；取消、准备候选丢弃、实例/World teardown 都释放租约。需要恢复取消结果的 Latent 回调保留租约直到终态回调结束。

第一步提供堆原生 `FPersistentRoots`：一次获取全部非空对象的持久根，失败回收已获取部分且保留输出旧租约。移动转移唯一所有权，析构及 Reset 幂等释放。堆 Close/析构先失效化生命周期哨兵，因此租约晚于 Runtime 销毁时不会访问悬挂指针，也不能在同地址新堆上复活。旧租约替换要求新旧根能够短暂同时满足配额，不能先释放旧值来掩盖失败。

该租约不暴露 root token，不为 Guest 新增 frame-zero 根创建权限；现有 Host ABI 保持不变。使用与释放遵守堆所属执行线程，不把 weak/shared 指针解释为堆可并发操作。

## 后续接入要求

Runtime 根据经过验证的状态布局提取托管引用，在复制字节与发布 continuation 状态之前原子持有根；不能信任任意 Guest 提交的偏移列表。订阅与恢复必须验证执行域和代码代次。读取状态后，生成代码重建当前调用帧根，原租约仍保持到 dispatch finalize，避免 Host 返回与 Guest 根建立之间的 GC 空窗。

先接 continuation 和取消，再接事件、跨 await 闭包以及实例异步入口；不能仅移除编译器的拒绝分支。引用恢复还需要处理共享捕获环境和方法组身份，不能把函数索引或旧堆 token 当作可跨版本迁移的状态。

当前已完成原生根租约、continuation 状态所有权、具体堆类型的 WASM 存取 ABI、类型化 Guest IR 与后端生成，并接通受支持的 C# 静态异步入口状态对象及 [async 内创建的共享捕获环境](P66.B_Async_Closure_Scopes.md#环境分配与状态恢复)。实例异步入口及持久事件仍需连接，P66.B 保持 implementing。下文各验证小节保留其交付时点的范围。

## continuation 原生状态接入

`FAvidScriptWasmRuntimeInstance::CreateContinuationStateLease` 将已校验对象列表转换为不暴露根 token 的原生租约。获取失败保留原输出，租约不延长 Runtime/堆寿命；有效性由当前 Runtime 的堆生命周期哨兵判断，卸载、重载或同地址重用都不能恢复旧租约。

`StoreManagedState` 在 endpoint、activation、token、字节大小和 Runtime 校验通过后才转移唯一所有权。失败时调用者仍持有租约，已发布状态不可替换。`ReadManagedState` 校验当前 Runtime 并消费一次字节；租约继续保留到 `FinalizeDispatched`，避免读取后、Guest 帧根建立前的回收空窗。旧 `ReadState` 拒绝携带租约的状态，托管读取也拒绝旧字节状态。

状态仍由原有 continuation slot 管理：Timer 取消直接回收；需要恢复取消结果的 Latent 先保留状态，终态回调完成后回收；候选丢弃、旧 activation 退休、World 失效和 teardown 均走同一释放路径。该接入没有新增 Guest import，不允许 Guest 自报任意引用偏移；后续版本化状态布局必须由编译器生成并由 Runtime 验证，之后才能连接 C# await。

## 具体状态对象的 WASM ABI

后续接入复用已有托管堆的类型布局和引用图，不另外接受 Guest 提交的引用偏移表。编译器将挂起时的局部值写入新分配的具体状态对象；该对象的字段可引用共享捕获环境、委托和普通对象。continuation 持有状态对象的根，GC 沿已经验证的布局追踪整个图。状态对象应由编译器独立创建，不能把保存值的语义误写为对原可变状态盒的无条件共享；字段中的语言引用则保留其原身份，不深拷贝对象图。

本组新增 [Core ABI](../../Source/AvidScriptCore/Public/AvidScriptContinuationStateAbi.h)，导入仅使用 `avidscript` 模块，不提供 `env` 别名：

| 导入 | 签名 | 运行时合同 |
| --- | --- | --- |
| `avid_continuation_state_store_v1` | `(IiI)i` | continuation token、具体堆 type id、对象 token；成功返回 1，状态重复/取消等发布拒绝返回 0；无效对象/类型/上下文终止调用 |
| `avid_continuation_state_read_v1` | `(Ii)I` | 当前 continuation token、预期具体 type id；返回仍由 continuation 保活的对象 token；禁止在其他回调、普通入口或重复读取中消费 |

原生 slot 保存 LE `u32 type + u64 object` 的 12 字节身份及唯一租约。它不保存原生指针，也不把此身份用作跨 Runtime 或跨重载的迁移格式。读取成功后，租约一直保留到外部 dispatcher finalize；类型不匹配的恶意恢复会消费该次状态并终止调用，由 owner 清理，不能重试成另一个类型。旧字节状态 ABI 保持原行为，不能借旧读取绕过租约校验。

Wasmtime/WAMR 静态导入目录追加两个 binding id，保持已有编号。即使模块仅导入状态 API、没有导入堆操作，也必须安装 invocation observer；WASM start 函数及缺少 continuation owner 的调用无法获取状态权限。状态对象受现有堆对象/字节/根配额约束，不开放无界保活。

[真实 WASM 用例](../../Source/AvidScriptRuntime/Private/Tests/AvidScriptContinuationStateAbiTests.cpp)通过生产 Runtime 进入存储和 continuation 恢复，验证原对象身份、循环引用、返回后 Guest GC、重复存储无泄漏、错误类型、空/外来/失效对象、错误 token、重复读取和普通入口读取拒绝；两套后端均包含仅导入状态 API 的场景。另覆盖 `env` 别名和错误签名拒绝。对象由原生 fixture 构造，测试 WASM 直接调用 ABI；这不是编译器生成 C# await 的证据。

## C# 异步状态对象

受支持的静态异步入口现在可以在等待后继续使用局部对象。例如下面的片段中，`counter` 与 `alias` 始终指向同一个对象，等待结束后 `Result` 为 7：

```csharp
public class Counter
{
    public int Value;
    public Counter(int value) { Value = value; }
}

// 放在脚本静态类中；沿用生命周期样例的 using、Tick 等声明。
public static int Result;

[UnmanagedCallersOnly(EntryPoint = "avid_on_begin_play")]
public static async void BeginPlay()
{
    Counter counter = new Counter(5);
    Counter alias = counter;
    await AvidContinuations.NextTickAsync();
    alias.Value += 2;
    Result = counter.Value;
}
```

[状态生成器](../../Tools/AvidScript.CSharpGuest/Lowering/CSharpAsyncManagedState.cs)为每次挂起创建独立状态对象。普通值复制到字段，托管对象与委托保留引用身份；恢复后重新建立当前帧根。读取局部变量的实际存储位置，因此 `ref/out` 替换局部引用后，下一次挂起保存的是新值。无托管引用的原有状态仍使用字节保存路径。

[编译测试](../../Tools/AvidScript.CSharpGuest.Tests/CSharpGuestManagedAsyncTests.cs)在状态对象首组交付时包含五组真实源码：对象别名与循环图、循环内多次等待、同步辅助函数返回的捕获委托、含引用结构体、空引用。当时另保留 async 方法内部直接创建捕获闭包的拒绝测试；后续执行接入已将具备完整作用域合同的用例转为成功路径，并继续拒绝缺少分配合同的输入。

原生 `AvidScript.Runtime.Continuation.CSharpManagedAsync` 使用这些 C# 编译出的 WASM，在 Wasmtime JIT 与 WAMR Interpreter 上分别验证正常恢复、C# 主动取消及 owner teardown，共 30 个组合。在挂起与每个恢复段之间强制 GC，检查结果、恢复次数、对象身份以及最终对象/根/活动帧全部清空。测试按编译布局回执读取结果，并像正式加载流程一样先验证 `avid_on_continuation_v2` 导出。
