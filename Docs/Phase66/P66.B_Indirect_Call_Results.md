# P66.B 进展：函数引用与受检间接调用

## 合同与实现

Guest IR 升级为 Schema 3 / IR 1.2，继续读取 1/1.0、2/1.1。新增 `function_ref` 类型（i32，4 字节对齐）与 `function_references` 合同表：每种名义类型声明参数类型、返回类型及允许引用的 Guest 函数集合。集合可以为空，表示无法调用的引用类型。每个目标必须与签名精确匹配，Host import 不能直接作为目标；后续由 Guest 适配函数显式调用已有 import。

`function_ref` 指令以目标函数 ID 产生类型化引用。`call_indirect` 以引用类型 ID 为合同，首个操作数为引用，其余为实参。支持普通值、显式地址参数、void、浮点和通过 sret 返回的结构体。该层只负责函数引用，闭包的接收者/环境将作为适配函数的显式参数，不把栈地址升级为逃逸环境。

WASM backend 生成单个私有、定长函数表，零号槽保留为空。每种名义签名拥有独立的连续槽范围，即使两个签名被 WASM 擦除为相同机器类型，也不能互相使用引用。调用前计算无符号 `token - start` 并与槽数量比较；空引用、下溢、越界、其他签名及空目标集合均 trap。随后执行 WASM `call_indirect` 的机器签名检查。函数表不导入、不导出，没有表写入指令；目标和槽顺序确定。

间接调用先刷新现有 array region 写缓冲。递归分析将每个间接调用连接到其合同允许的全部目标，保守覆盖直接/间接混合递归；原有 cooperative safepoint 的递归入口轮询因而不会被委托调用绕开。

## 验证

固定 .NET SDK 8.0.416，测试使用 Release 自执行 runner：

| 检查 | 结果 |
| --- | --- |
| GuestIr | 35/35 |
| WasmBackend | 50/50 |
| CSharpGuest | 161/161 |
| PreparedSemanticContractTests.ps1 | 13/13 |
| 新函数引用真实 WASM 执行 | 3051/3051 |

合同测试包括缺失/重复/空签名、非法类型/目标、错误参数/返回类型、旧版本夹带新功能、伪造整数引用、非法布局、确定性序列化与编译。递归轮询验证覆盖间接自递归以及直接/间接混合互递归。PreparedSemantic 的备份清理失败告警来自预期故障注入。

WASM 执行使用 Node 宿主，分别测试普通和 cooperative 模块，覆盖动态目标选择、引用传参/返回、重复调用、同机器签名的名义隔离、ref 写回、void/浮点/结构体返回、空引用、空目标集合与取消轮询。复现：

1. 将 `AVIDSCRIPT_FUNCTION_REFERENCE_WASM_DIR` 指向仓库外输出目录。
2. `dotnet run --project Tools/AvidScript.WasmBackend.Tests --configuration Release`。
3. `node Tools/AvidScript.WasmBackend.Tests/RunFunctionReferenceWasm.mjs <输出目录>`。

此处没有新增 UE Runtime import，也未执行新的 UE no-clean 构建、Automation 或 PIE；这些仍属于 P66 集成 Gate。不能将 Node 执行结果当作 UE Session 生命周期或 Wasmtime/WAMR 集成验收。

## 后续和限制

P66.B 未完成：C# 方法组/lambda 尚未生成这些指令，捕获堆环境、event、回收、Session/reload/teardown 有效性仍需实现。本节是它们共用的实际调用底座，不是完整委托对象或闭包实现。

槽 token 仅对当前模块实例有效，不能作为稳定身份跨 reload、存档或 Host 回调持久化。后续公开委托值必须携带受控的环境与生命周期身份，并在迁移时重绑定；不得原样复制旧槽。C# 可达性、调试恢复与数据通道优化接入间接调用时也必须同步处理间接目标和调用副作用，不能仅修改表达式 lowering。
