# P66.B：共享执行域的 VM 重入探针与预算修复

## 结果

Wasmtime JIT 与 WAMR Interpreter 均通过同一 VM 内的 Host→Guest 同步嵌套调用探针。调用链模拟逻辑接收者 A→B→A，嵌套调用看见同一线性内存位置和可变 WASM global；外层返回时可看见内层写入。普通调用与 prepared call 均覆盖成功、预算耗尽、内层 trap、活动期间请求卸载四种场景。

这证明共享 VM 候选具有所需的部分底层条件；没有将 Runtime Session 的重入限制移除，也没有启用真实 UObject 跨实例路由。探针使用手工构造的小型 WASM，不是 C# 语言或完整 ref/out 验收。它尚不证明跨包执行、普通托管对象共享、GC、Blueprint、网络、await 或调试暂停正确。

## 修复

`AvidScriptWamrBackend.cpp` 的 `Call` 原先无条件清零 Host 调用计数，嵌套进入 Guest 会得到新预算。现在只在 `ActiveCallDepth == 0` 时重置预算与入口错误状态。内层调用消耗同一最外层预算，下一次独立入口仍获得新预算。Wasmtime 已有不在活动调用中重置预算的判断，本组未改变其实现。

预算为 1 时，A 写入后调用 B；B 的下一次 Host 调用在进入 dispatcher 前拒绝。A/B 已发生的写入保留，最外层收到 `host_call_budget_exhausted`。这不等于 Runtime 已具备跨多个 VM 的统一预算，后者仍需调用链 owner。

## 对执行域接入的约束

本组使共享 VM 成为可以继续验证的候选，而不是最终完成的实例执行模型。源码显示生成类型 Host 目前仍为每个 receiver 创建独立 Session；属性 import 上下文固定在单一 receiver，生命周期、回调、continuation 与重载也由各 Session 拥有，不能仅共享一个 VM 指针。

下一步要区分执行域与实例：执行域拥有已验证代码版本、VM、线性内存、普通托管堆和模块静态状态；实例仍拥有 receiver 身份、生命周期与资源归属。活动调用栈必须恢复目标上下文，检查源/目标 World 与代际，并限制深度和整链预算。域的划分（World、脚本包、显式隔离）需要与 UE Subsystem 生命周期一起确定，不能意外跨 World 共享状态。

决定接入前，仍需真实 C# 双对象探针：两个 receiver 交换同一个普通对象和同一 ref 位置，B 改值后同步回调 A，验证静态共享、强制 GC、内层失败及目标销毁；并与独立 VM 的受检引用适配成本比较。不能用当前线性内存的成功代替这条完成要求。P66.B 保持进行中。
