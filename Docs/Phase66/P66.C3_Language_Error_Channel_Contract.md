# P66.C3：语言错误通道

状态：底层结果槽和新版 IR 的结果类型布局已验证。Semantic 可以生成版本化的异常流诊断记录；工具层已能把同一份源码中的多个受限 `throw new System.Exception()` 方法、直接调用者、跨方法 `catch`，以及同方法的直接 `throw`/`catch` 组成 IR 17/WASM。普通方法中直调错误跨越受限的线性或前向分支同步 `finally` 时，已能按内层到外层执行清理；异常方法中的单个本地 `throw` 能经过有界的嵌套线性同步 `finally`。同一 `try` 的纯条件分支可以让多个本地抛错和正常返回共用线性或有界前向分支 `finally`；返回值在清理前求值。返回表达式中的受影响直调若产生语言错误，同一清理路径执行后再传播原错误。单层 `try/catch/finally` 的两个返回叶及 `catch` 内调用再次出错也已按此规则执行。单层清理中的有界前向分支已能执行；单层清理或嵌套线性清理的任一层若再直接抛出一个受限错误，会用新错误替换旧错误；嵌套情形仍会执行剩余外层清理。无清理的 `catch` 可通过 `throw;` 把原错误传给调用者或同方法的外层 `catch`；`catch (System.Exception e)` 可判断对象是否为空。每个新抛出点有独立源码令牌；重抛沿用原令牌和对象根。UE Runtime 已在加载 canonical WASM 时校验并保存目录；受影响的 `void` 导出在未捕获时报告错误。命令行发布入口仍拒绝异常产物；异常对象成员、超出有界前向图的清理或嵌套处理器清理、复杂清理图中的再次抛出、带清理的重抛及跨 `await` 清理尚未执行。本文不把专用入口算作已开放的语言功能。

Semantic **34/1.43** 仍只用于含异常语法的失败诊断产物。记录按方法保存 Roslyn 的 `try`、`catch`、`finally` 区域、分支的离开/进入/清理区域、带源码 span 的 `throw`/`throw;` 和 catch 类型，以及按序的异常基本块、块所属区域、块内运算及分支值。每个 catch 处理器指向对应的 Roslyn catch 区域。一个源码单元同时含普通方法和异常方法时，普通方法的 CFG 现在保留在产物中，异常方法仍只发布上述诊断记录；两者的方法身份不能重叠。它目前**不发布异常方法的可执行 CFG**。新版本校验序号、区域归属、类型、源码 span 和运算预算；旧版 32/1.41、33/1.42 不能冒充新版。原有成功产物仍为 31/1.40，序列化时省略 `exception_flows`。C# Guest 即使收到伪造成功标志或降版的异常记录，也会拒绝输入。固定 SDK 下 Semantic 测试 **387/387** 通过；过滤器保留在记录中并给出源码位置诊断，尚未实现。

`SemanticExceptionDispatchPlanner` 可从上述区域树为每个基本块推导语言错误路由：内层 `finally` 先于外层 `catch`，未匹配处理器后才继续外层清理；`throw;` 跳过当前 catch，`finally` 自身的新错误不会再次进入同一个 `finally`。同一规划器也给 `try` 内的调用块生成 catch 候选。`SemanticExceptionDispatchResolver` 在通过异常流和类继承合同校验后，用已注册的异常类型沿路由选择第一个匹配的处理器，并返回其前需要执行的 `finally` 区域；基类 catch、同类型内外层 catch、catch-all、未匹配传播和重抛均有源码级回归。未注册类型、非异常类型和伪造继承环拒绝解析。固定 SDK 下 Semantic 测试 **387/387** 通过。专用编译入口现消费无清理及单层线性或有界前向分支外层清理的处理器决策；另由普通方法 CFG 规划器执行受限有界前向同步 `finally`。异常方法内的单条清理路径、直接与嵌套 catch 重抛，以及受限变量绑定已能执行；嵌套处理器的多路径清理、异常对象成员和带清理的重抛仍只是编译期规划。含过滤器的处理器不能生成路由。

`SemanticLanguageErrorEffectPlanner` 从含异常语法的方法向直接调用者做传递闭包，列出需要结果通道签名的方法；无关方法不进入闭包。属性访问器和显式转换等潜在调用一并保守计入。尚不能完整枚举目标的虚调用、接口调用和委托调用会使规划失败，不能据此输出部分结果。专用 `CSharpLanguageErrorCompiler` 已消费该闭包改写受限同源直接调用、无清理 catch 和受影响的 `void` UE 导出；其他异常方法与导出签名仍不能使用。

## 待落地的版本化合同

1. **Semantic。** 已有 34/1.43 的异常区域、分支、基本块运算及同源普通方法 CFG；多个受限抛出方法、跨方法 catch、同方法直接 catch、直接与嵌套 catch 重抛、`System.Exception` catch 变量引用判断、普通方法的有界前向同步 `finally`，以及本地 throw 的嵌套线性清理、纯条件分支中正常返回与多个直接抛出共用单层清理、返回表达式受影响直调、单层与嵌套线性清理中任一层的直接抛错替换、单个本地抛出经过有界前向分支清理能经专用工具层入口执行。下一步要让一般副作用决策条件、其他多块或嵌套处理器清理及其他异常退出路径执行，并让不支持的异常对象、过滤器、异步清理或动态分派在源码位置失败；旧版本产物不能冒充新图。
2. **Guest IR。** 16/1.15 已约束结果生产者、direct/indirect 调用后的状态分支和字段读取路径；17/1.16 增加有界、可校验的错误令牌目录。受限同源 C# 直接调用已使用这些规则；一般异常方法仍需结果槽、清理和对象根所有权合同。正常值只在正常状态可读，异常类型、源码位置及异常对象根只在错误状态可读。实际字段布局由版本化类型和 `GuestDataLayout` 计算，不能把早期探针中的常数 7/9、31/44 或 20 字节写成产品 ABI。受限 `void` UE adapter 已检查结果状态，其余入口继续拒绝异常语法。
3. **清理。** 普通方法中的受影响直调已能在错误返回时按内外顺序执行有界前向同步 `finally`；异常方法的本地 throw 已能执行嵌套线性同步 `finally`，纯条件决策树中的多个直接抛出与正常返回可共用单层线性或有界前向分支清理，单层或嵌套线性清理中任一层直接抛出的第二个受限错误会替换第一个，嵌套情形继续执行外层清理。仍需覆盖嵌套处理器清理、复杂清理图中的再次抛出、枚举器 `Dispose`、循环控制流及清理中的受影响调用；普通返回值在错误路径失效。异常对象及其捕获环境在传播、重抛和清理期间必须有明确的 managed-heap 根，调用结束不留根。
4. **UE 边界。** 受限 `void` 导出已有入口适配器，保持现有 `avid_on_*` 签名；生成的 UFunction 回调和其他签名仍需逐类接入。未捕获语言错误以类型和源码位置交给 Runtime/Session 报告并终止本次调用。Host import 拒绝、WASM trap、fuel/超时和越界仍走致命故障路径，脚本 `catch` 不得捕获它们；不能用模块全局错误变量传递语言错误。
