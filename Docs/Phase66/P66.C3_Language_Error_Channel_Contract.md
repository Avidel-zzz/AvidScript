# P66.C3：语言错误通道

状态：底层结果槽和新版 IR 的结果类型布局已验证。Semantic 可以生成版本化的异常流诊断记录；C# `throw`、`catch`、重抛和跨方法异常传播仍不能执行。本文固定后续跨层实现的边界，不把布局或诊断记录算作语言功能。

## 可执行底座

Guest IR 已有结构体返回的 SRet 路径：调用者为每次 `call` 提供独立的线性内存结果槽，WASM 函数把结构体写回该槽。[WasmOutcomeSlotTests.cs](../../Tools/AvidScript.WasmBackend.Tests/WasmOutcomeSlotTests.cs) 用两个连续的嵌套调用模拟正常值、错误传播和 `finally` 抛出新错误覆盖旧错误。探针结构体为五个 `int32` 字段：`status`、`error_type`、`source`、`value`、`cleanup`；它只是测试布局，`cleanup` 是可观察计数，不属于拟定的生产 ABI。

固定 SDK 8.0.416 下 WasmBackend 测试 **323/323** 通过；[RunOutcomeSlotWasm.cjs](../../Tools/AvidScript.WasmBackend.Tests/RunOutcomeSlotWasm.cjs) 在 Node WASM 上检查五组结果，**5/5** 通过。Win64 no-clean Editor 构建通过；[TestAvidScriptLanguageOutcomeSlot.ps1](../../Build/TestAvidScriptLanguageOutcomeSlot.ps1) 把同一 WASM 放进 Editor，在 Wasmtime JIT 和 WAMR Interpreter 上检查五组结果，Automation **1/1** 通过。该证据说明现有 SRet 能承载逐次调用结果，不证明 Roslyn 异常已经可执行。

Guest IR **15/1.14** 可选地声明 `language_outcome_types`，但不能用这些类型作为函数返回值。每个结果结构按规范顺序包含 `status`、`error_type`、`source`、`error_root` 和可选的 `value`；前三项为 `i32`，错误根为带 payload 的 `managed_ref`，偏移和大小由 `GuestDataLayout` 计算。`source` 是留给后续源码位置表的令牌，不直接充当源码 span。验证器拒绝字段乱序、错误根形态、重复声明和降版伪装；旧产物省略该字段，原有序列化字节不变。

Guest IR **16/1.15** 允许内部函数返回上述结果结构。直接和间接调用后必须立即读取 `status` 并按其分支；`value` 只能在成功专属路径读取，错误字段只能在错误专属路径读取。生产者在每条返回路径上必须写入常量状态 `0` 或 `1`；正常状态需要 `value`，错误状态需要 `error_type` 和 `source`。状态常量必须支配写入点，不能经可变局部或地址别名伪装。调用结果与生产者结果均不能通过普通操作数或地址别名绕过检查。Host import 不能返回语言错误结果；原始结果函数不能直接导出给 UE。

固定 SDK 下 Guest IR 回归 **67/67** 通过；[GuestLanguageOutcomeFlowTests.cs](../../Tools/AvidScript.GuestIr.Tests/GuestLanguageOutcomeFlowTests.cs) 的手工模块经 WASM backend 编译后，[Node 测试](../../Tools/AvidScript.GuestIr.Tests/RunLanguageOutcomeFlowWasm.cjs)验证单次调用以及两层函数间的正常结果和错误字段，**4/4** 相符。测试中导出的标量探针只读取字段便于断言，不是 UE 错误适配器；Host heap import 也仅为无对象分配的测试桩，没有验证异常对象根或 UE Session。当前 C# Guest 仍生成 14/1.13；C# 异常来源、清理、catch 与 UE 回调适配器尚未接入。

Semantic **33/1.42** 仍只用于含异常语法的失败诊断产物。记录按方法保存 Roslyn 的 `try`、`catch`、`finally` 区域、分支的离开/进入/清理区域、带源码 span 的 `throw`/`throw;` 和 catch 类型；现在还保存按序的基本块、块所属区域、块内运算及分支值，包括抛出表达式和清理赋值。每个 catch 处理器指向对应的 Roslyn catch 区域；嵌套同类型处理器和无类型 `catch` 都有独立测试。Guest 后续可以从同一份 Roslyn 图读取实际源码运算，但目前**不发布可执行 CFG**。新版本要求这些块存在并校验序号、区域归属、类型、源码 span 和运算预算；旧版 32/1.41 不能冒充新版。原有成功产物仍为 31/1.40，序列化时省略 `exception_flows`。C# Guest 即使收到伪造成功标志或降版的异常记录，也会拒绝输入。固定 SDK 下 Semantic 测试 **383/383** 通过；过滤器保留在记录中并给出源码位置诊断，尚未实现。

## 待落地的版本化合同

1. **Semantic。** 已有 33/1.42 的区域、分支和基本块运算诊断记录，但还没有可执行异常 CFG。下一步要验证异常退出、catch 类型匹配和清理顺序，并让不支持的异常对象、过滤器、异步清理或动态分派在源码位置失败；旧版本产物不能冒充新图。
2. **Guest IR。** 16/1.15 已约束结果生产者、direct/indirect 调用后的状态分支和字段读取路径；手工 IR 的错误结果可沿检查后的分支跨函数返回。下一步要把这些规则接入 C# Guest，并为每次调用独占的结果槽建立清理和异常对象根所有权。正常值只在正常状态可读，异常类型、源码位置及异常对象根只在错误状态可读。实际字段布局由版本化类型和 `GuestDataLayout` 计算，不能把早期探针中的常数 7/9、31/44 或 20 字节写成产品 ABI。生成的 UE adapter 还未具备检查路径，继续拒绝异常语法。
3. **清理。** 调用者在错误返回时沿当前作用域从内到外执行 `finally` 和枚举器 `Dispose`。清理本身抛出的语言错误替换待传播错误；普通返回值在该路径失效。异常对象及其捕获环境在传播、重抛和清理期间有明确的 managed-heap 根，调用结束不留根。
4. **UE 边界。** 现有 `avid_on_*` 与生成的 UFunction 回调签名保持稳定，由入口适配器调用内部结果函数。未捕获语言错误以类型和源码位置交给 Runtime/Session 报告并终止本次调用。Host import 拒绝、WASM trap、fuel/超时和越界仍走致命故障路径，脚本 `catch` 不得捕获它们；不能用模块全局错误变量传递语言错误。
