# P66.B 进展：委托签名合同

## 实现与兼容

Semantic Schema 升至 21、Semantic Version 升至 1.23。新增 `delegate_types`，显式描述委托的 Invoke 身份、返回类型、返回引用方式，以及按 ordinal 排序的参数类型和 ref/out/in/ref readonly 方式。递归委托签名通过类型注册去重终止；序列化顺序确定。

委托 Invoke 使用封闭类型及实际参数/返回类型生成身份，避免将 `Func<int, int>` 与 `Func<long, long>` 统一为原始泛型定义而产生符号碰撞。Semantic 投影和签名表共用身份构造器。

Guest 输入校验要求每个委托类型恰有一条有效签名，拒绝缺失、重复、伪造身份、非法类型、参数次序和引用方式。旧 Schema 不得携带新版签名元数据。Guest 继续读取 20/1.22，包括原有 CFG async 状态流；旧版本测试显式去掉当时不存在的字段。前端缓存、prepared semantic 发布和脚本类型生成入口只接收当前 21/1.23，旧缓存需重建。

本节不更改 Guest IR、WASM ABI 或 UE Runtime，不引入运行时 CLR/Roslyn。元数据可表达的签名不等于 Guest 已能执行该签名。
