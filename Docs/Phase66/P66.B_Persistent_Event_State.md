# P66.B：持久事件回调状态

## 目标与接入顺序

让 C# 事件订阅持有真实委托和共享捕获环境。例如订阅时捕获 `score`，函数返回后事件仍能修改同一个变量；取消订阅或实例退出后释放它。最终通过生成的类型化订阅接口及语言事件连接，不能要求用户自己管理 WASM 函数索引和堆 token。

接入顺序：

1. **原生订阅所有权。** 在现有 Session 订阅项中原子保存状态和根租约；覆盖回调中取消、事件源 GC、候选丢弃/提交及停止清理。
2. **类型化 Guest ABI。** 编译器生成并验证具体回调状态布局与签名，Runtime 校验实际执行域、订阅权限和代码代次；读取仅允许当前回调，并在建立 Guest 帧根前保持租约。旧无状态回调 ABI 保持兼容。
3. **C# 与真实 UE 事件。** 生成订阅接口接收匹配签名的委托，将绑定目标、共享环境及调用列表接入；再连接 `+=` / `-=` 的事件语义。使用真实源码及两个 WASM 后端验证，不把原生租约测试当作 C# 用法已经完成。

已完成第 1、2 步，以及第 3 步中的**类型化 C# 显式订阅**：生成的接口可以接收 lambda、实例方法、静态方法和调用列表；事件触发时从持久状态盒取回委托，在当前回调中修改同一捕获环境。`ref/out`、单播返回值、自取消和 GC 清理已经过真实 UE 事件验证。`+=` / `-=` 语言事件语义仍未接入，P66.B 继续进行。当前 Semantic 为 **29 / 1.33**，Guest IR 为 **13 / 1.12**；下文早期版本号和测试数字保留为当组历史证据。

## 所有权约束

### Guest ABI 冻结

新增两个仅位于 `avidscript` 模块的版本化 import，旧 import 编号与签名不变：

- `avid_event_state_subscribe_v1(slot:i32, generation:i32, eventOrdinal:i32, type:i32, object:i64) -> i64`：使用现有事件目录和对象权限检查，原子发布订阅与状态根，返回订阅 token；权限或订阅拒绝返回 0，非法状态类型/对象产生结构化 Host 错误。
- `avid_event_state_read_v1(type:i32) -> i64`：仅当前事件 Guest 调用可读取一次，返回同一具体堆类型的对象。原生 owner 内部保存 LE `u32 type + u64 object`，不接收 Guest 自报引用偏移。

Runtime 校验活动调用、具体堆布局、对象存活与执行深度。进入嵌套实例调用时撤销外层事件读取权，返回后恢复；订阅 owner 继续检查 Runtime 身份、当前源、状态租约和一次读取限制。状态租约覆盖从读取到 Guest 建立帧根的窗口，回调内自取消仍保活至返回。事件参数签名继续使用既有准备目录；编译器将事件签名映射到具体状态盒、生成 wrapper 与 IR 操作属于下一组接入，当前 ABI 不能作为任意 C# 委托已支持的证据。

原生 ABI 组修改 Core ABI、VM 静态导入目录与两后端编组、Runtime Host/上下文与 Session 接口，并增加真实 WASM + UE 事件测试；当时不改 Semantic/IR 版本。验证覆盖两后端、错误模块/签名、对象权限、堆身份/类型、回调外与重复读取、重复派发、自取消及失败清理，并回归 VM、continuation 和生成实例上下文测试。

集成测试使用 Actor 的 `OnActorBeginOverlap` 稀疏多播事件，暴露桥接函数复制时把 `USparseDelegateFunction` 缩窄为 `UFunction` 导致的引擎断言。桥接复制保留签名的实际 UObject 类，再移除委托函数标志；稀疏存储仍由原 `FMulticastDelegateProperty` 的 Add/Remove 路径管理。这个崩溃修复纳入当前写集与同一回归，不替换测试事件回避问题。

- 每个订阅所属 Session 与准备它的 Runtime 绑定，活动与候选分别存放；只接受同一 Runtime 的有效原生根租约。Host ABI 复用既有源对象代际、能力权限与 World 检查。
- 先验证并创建完整订阅，再转移状态租约、发布桥接；失败保留调用者租约，不产生半绑定项。状态字节必须由经过验证的原生布局产生，不能接收 Guest 自报根偏移。
- 订阅持有一份共享状态容器；派发临时保留同一容器。处理函数自取消或替换订阅时，停止后续派发，当前调用仍保有根直到返回。
- 状态读取只允许当前回调、匹配 Runtime、正确长度且每次派发读取一次。拒绝时输出不变。嵌套派发恢复外层上下文；全 owner teardown 立即撤销读取权限。
- 事件源保持弱 UObject 身份。GC 清理失效源的活动与候选订阅，释放闭包根；不靠下一次事件才能回收。
- 取消、候选丢弃、提交替换、Session/World 清理复用现有解绑路径。状态不跨代码重载迁移；Runtime 卸载后晚释放租约必须安全。

## 实现

[公共租约](../../Source/AvidScriptRuntime/Public/AvidScriptManagedStateLease.h)定义不延长 Runtime 寿命的原生状态所有权；原 continuation 接口继承它并保留现有入口。`CreateManagedStateLease` 复用已经验证的根获取和失败原子性，不向 Guest 暴露持久根 token。

[Session 订阅 owner](../../Source/AvidScriptRuntime/Private/Session/AvidScriptSessionDelegateSubscriptions.cpp)增加 `SubscribeManaged` 与 `ReadCurrentManagedState`。每项最多保存 64 KiB 原生状态字节，并带有唯一根租约；派发临时持有同一状态容器，取消不造成正在执行的回调失去根。读取检查当前源、Runtime、租约、长度和本次读取标志，状态不会通过普通无状态订阅入口泄漏。

Session 在准备初始模块、设置上下文和构建重载候选时，把对应 Runtime 交给订阅目录。活动与候选身份分别保存；没有指定 Runtime 的原有原生调用仍能使用无状态订阅，但不能发布托管状态。仅在第一次订阅托管状态时注册 GC 清理监听，按弱源身份回收活动/候选项，析构移除监听。

原生接口仍只接收可信状态字节。[Guest Host 实现](../../Source/AvidScriptRuntime/Private/Delegate/AvidScriptEventStateHost.cpp)验证当前堆中的对象与具体类型，生成固定 12 字节状态并获取根租约。失败不发布订阅，临时租约自动释放。两后端共用静态导入目录中的调用作用域要求；即使模块只导入事件状态接口，也必须提供 invocation observer，保证每次调用的堆帧正确建立和退出。

Runtime 在事件进入 Guest 时记录执行深度，嵌套实例调用通过上下文 guard 撤销并恢复外层权限。当前 native owner 继续执行一次读取和源有效性检查；错误类型、重复读取或无状态订阅不会返回对象。此层不接收任意 Guest 字节，不接收 Guest 自报根图，也没有绕过编译器的委托签名验证需求。

## Guest IR 与代码生成合同

本组把 Guest IR 升至 **12 / 1.11**，保留 1–11 的成对版本读取；旧版本不能携带新指令，未来版本及错配版本拒绝。C# Semantic 保持 28 / 1.32，正式构建入口同步接受当前 IR 输出。

- `managed_event_subscribe`：操作数为三个 i32（源 slot、generation、事件 ordinal）及一个具体 `managed_ref`；结果为 i64 订阅 token，`target_id` 必须指向精确的 `avid_event_state_subscribe_v1` 导入。
- `managed_event_read`：无操作数，结果为具体 `managed_ref`；`target_id` 必须指向精确的 `avid_event_state_read_v1` 导入。

具体堆类型编号由 backend 根据规范化布局产生，不是用户指令参数。两操作均禁止常量/运算符附加数据、擦除引用和任意同签名 Host 替代。订阅前同步活跃帧根；读取后立即建立结果根，先于后续调用、分配、垃圾回收和协作式轮询。沿用统一 managed heap 的对象图与根帧协议，不引入第二套闭包内存。

本组验证序列化往返、确定性生成、旧版兼容、畸形输入拒绝；由正式 WASM backend 生成的模块在两原生后端经真实 Actor 事件读取并更新同一对象图，覆盖重复事件、自取消、错误读取类型和回调外读取。语言层的委托状态盒和事件签名映射留到下一组，不把 IR 模块生成视为 C# 事件语法已完成。

## C# 显式订阅：当前可用写法

以下片段取自生成事件名为 `OnScriptSignal` 的测试配置。`SubscribeOnScriptSignal`、参数类型和名称由项目选定的 UE 事件生成；它们不是所有项目都会有的固定 API。脚本在模块加载完成后调用一次 `Connect`，并在不再需要事件时调用 `Disconnect`：

```csharp
using AvidScript;

public static class Script
{
    [AvidTransient]
    public static AvidSubscription SignalSubscription;

    public static void Connect()
    {
        int score = 40;
        SignalSubscription = AvidSubscriptions.SubscribeOnScriptSignal(
            UE.Self,
            (actor, amount, scale) =>
            {
                score += amount;
                if (scale < 0) SignalSubscription.Cancel();
            });
    }

    public static void Disconnect() => SignalSubscription.Cancel();
}
```

这里 `score` 是回调与订阅期间共享的变量；`Connect` 返回后，事件仍能访问它。`AvidSubscription` 是取消订阅的句柄。当前可将 lambda、绑定的实例方法、静态方法或受支持的委托调用列表传给同一个类型化参数。带 `ref/out` 的事件和有返回值的单播事件会生成对应签名的委托；不能把不匹配的处理函数接上去。

生成器为每个事件发出 `AvidEventHandlers` 委托类型和 `AvidSubscriptions.Subscribe…` / `Bind…` 重载。Semantic **29 / 1.33** 将方法、稳定事件 ID、ordinal 与委托签名写入合同；Guest IR **13 / 1.12** 用具体状态盒保存委托，生成带 `_state_v1` 后缀的回调导出。Runtime 只在显式订阅后绑定这种回调，并拒绝用旧无状态订阅入口绕过状态盒。原有无状态导出与旧 IR / Semantic 文档继续可读。

当前验证范围是生成 facade → C# 编译 → WASM → 实际 UE 单播/多播事件。Wasmtime JIT 与 WAMR Interpreter 各覆盖捕获变量、实例方法、静态方法、调用列表、空委托、`ref/out`、单播返回值，共 **14 个组合**；还检查事件内自取消、回调后强制 GC、源和订阅退出后根与帧归零。额外两个后端场景验证重复调用复用栈帧时，取地址的局部变量重新初始化为 `0`，函数返回值按地址读取为 `85`。UE 5.8 Win64 Development no-clean 构建成功；聚焦 Automation **75/75**，失败 0，队列完成且进程退出 0；日志位于工程 `Saved/Logs/AvidScript_CSharpEventState_20260923T013705748Z.log`。该证据来自最终生成模块与原生测试。

.NET SDK 8.0.416 自执行测试：Semantic **371/371**、C# Guest **467/467**、WASM backend **311/311**、Guest IR **35/35**；生产生成 facade 的七份 C# 模块编译 **7/7**，正式构建合同 **5/5**。这些结果证明列出的编译与运行路径，不代替 PIE 或真实游戏长时间验收。架构检查仍因工作树中的实现文件及原有受保护 header 与旧提交 tree 不同而报告 dirty evidence，不能当作干净发布 Gate。
