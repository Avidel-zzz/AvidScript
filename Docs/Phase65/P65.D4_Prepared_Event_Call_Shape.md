# P65.D4 Prepared Event 专用调用形状

## 目标

`avid_on_event(i32, f32) -> void` 是 BeginPlay 后高频进入脚本的固定 ABI。此前它虽然已经缓存
export handle，但仍通过 generic prepared bridge 在每次调用中循环读取参数类型、组装 raw values、
再循环处理空结果。本小节把固定签名提升为 backend 内部的 prepared call shape。

## 实现

- Wasmtime C ABI 新增 `I32_F32_TO_VOID` shape，以及对应的 unchecked prepared call。
- export 首次解析时只检查一次参数与返回类型，后续 prepared call 直接填充两个 raw value。
- backend 在 `PrepareExportCall` 时选择专用 thunk，Runtime 和 Session 不感知 Wasmtime 类型。
- 通用签名继续使用 generic bridge；错误、trap、fuel、epoch watchdog、Host-call budget 和
  unload-defer 语义保持不变。

这不是 benchmark 专用旁路。任何满足相同 ABI 的生产 export 都会自动使用该路径；签名不匹配时
fail closed 到通用 prepared shape，不会误用专用函数。

## 验证

- UE5.8 `AvidTPSTemplateEditor Win64 Development` no-clean 增量构建成功。
- C API、backend thunk 和链接产物在同一构建中完成编译与链接。

本小节只确认结构与编译正确性，不单独宣称 callback 门禁改善。正式收益在后续 callback containment
批次完成后，以冻结的 Phase56 diagnostic/formal profile 统一测量。
