# P65.D35：epoch 读取与比较融合诊断

本轮隔离实验实现了预期的热循环指令融合，但配对测速整体接近持平，并出现单项回退，
因此不纳入生产运行库。正式 patchset.3、Windows 468/468 与 Shipping 证据保持原身份；
P65-D03 仍为 Fixing，正式性能 Gate 保持 16/18。

## 实验与正确性

以 D33 的隔离来源为基线，6,614 个源码文件中仅修改两个文件：

- `crates/cranelift/src/func_environ.rs`：Win64 PreserveAll epoch 检查的冷路径重新执行
  atomic load，避免热点读取被冷路径复用；热路径采用等价的 deadline <= current 比较，
  使读取位于 x64 比较指令可折叠的右操作数。原有轮询点全部保留。
- `cranelift/codegen/src/machinst/lower.rs`：在 Brif lowering 设置当前 side-effect color，
  沿用已有的单次使用、同基本块、无中间副作用约束允许读取下沉；分支完成后清空窗口。
  这是通用编译器改动，需要验证其他分支，不能仅凭 epoch 测试通过合入。

实际原生 production 配置的 `scalar_float` 在偏移 `0x4b` 生成 `cmpq (%r9), %r8`，
替代原来的独立 load 和 compare；中断与慢路径保留。24/24 个 epoch-off 控制产物
在两套运行库间字节一致。该结论只覆盖本次内核集合，不代表所有程序代码生成不变。

| 验证 | 结果与范围 |
| --- | --- |
| 原有 epoch 探针 | 17/17：中断、恢复、deadline 重载、强制慢路径与寄存器破坏 |
| 新增内存顺序探针 | 42/42：写入/调用屏障、多次使用、异常顺序、未选择分支的非法读取 |
| 既有分支执行文件 | brif、br、br_table、i128-br 共 4/4 |
| x64 编译文件 | 基线 181/181；实验 180/181，1 项汇编预期变化 |
| 浮点比较逐函数核对 | 原始 10 个函数和预期分别拆分；基线 10/10、实验 9/10；唯一差异是 brif_cond_rhs 的单次读取融合，多次使用等其余 9 个函数原预期通过 |
| 更广目录检查 | 9 个目录失败列表与基线一致；i128-load-store 在两者均以访问异常退出；未宣称完整 upstream suite 通过 |

没有更新或删除原始汇编断言。首次整目录异常退出、解析错误、分目录与基线复测记录均保留。
既有目录失败与访问异常在基线中同样出现，不能据此归因于本次改动；完整上游回归仍未通过。

## 固定配对测速

运行库使用 Rust 1.93.0、`fastest-runtime`、与生产相同的六项 Cargo features；
NativeProfileProbe 使用冻结 `8c032e9f` 的 C ABI 与 12 个 WASM 内核。
基线 DLL 是当前 patchset.3，实验 DLL 独立构建，没有替换生产安装目录。

每个内核 3 轮交替顺序、共 72 个计时进程；每进程四配置，每配置 5 次预热、30 次采样，
固定 8,192,000 次迭代和 seed 1397313。编译与回归结束后才开始计时。
72 份报告哈希、内核哈希、固定参数、288 组配置校验和与聚合指标均独立读回核对。
epoch/Spectre 关闭配置仅用于归因；下列指标使用两者均开启的 production_baseline。

实验/基线的配对比例先按每个内核的三轮取几何均值，再跨 12 个内核等权取几何均值：
P50 **0.998966x**、P95 **0.996449x**；分别为 5/12、7/12 个内核小于 1。
整体仅约 0.10%/0.36% 的改善，`internal_call` 约 3% 回退，不支持生产采用。
这不是 V8 对照，也不能乘以历史 V8 比率推算正式 Gate 通过。

逐内核、逐轮数值、来源文件哈希与外置证据哈希见
[结构化结果](P65.D35_Epoch_Load_Fusion_Diagnostic.json)。外置证据根名称为 `as35epoch`；
保留 source inventory、语义报告、编译日志、原生归档、原始计时报告和失败对照。
