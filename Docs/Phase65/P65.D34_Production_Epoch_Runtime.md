## 运行库身份与兼容边界

生产 patch 合并 D33 已通过 17/17 定向合同的 Win64 `PreserveAll` 实现。
补丁涉及原来的四个 C API 文件与三个 Cranelift epoch 文件；宿主 C ABI、公开导出、
编译配置和逐回边 epoch 检查频率保持原合同，其他目标平台保持原生成调用约定。

- toolchain：`avidscript-wasmtime-v45.0.0-patchset.3-win64-multiarch`。
- 新安装根：`Source/ThirdParty/Wasmtime/installed/Win64/v45.0.0-avidscript.3`。
- canonical patch SHA-256：`1635067d97b9af7fdc4c1cf85c5b4b0b0d9141a86ad1c1401c624484d2170b1c`。
- Wasmtime commit、Rust 1.93.0、六个 Cargo features、CPU/优化配置、安全检查均未改变。

`Wasmtime.Build.cs` 选择新的安装根，并继续将实际 DLL 哈希写入编译定义。
`ResolveAvidScriptWasmtimeRuntimeIdentity` 使用观测 DLL 哈希建立 runtime build identity，
因此新 DLL 与旧预编译产物的身份不同；不靠更改 workload 或降低校验来复用旧缓存。

新发布声明使用 patchset.3。可信发布校验器明确允许已知 `.2` 和 `.3` 两种布局，
由工具链版本决定唯一路径；Schema 的 `oneOf` 同时绑定版本与路径，禁止混装。
这使新安装器能够验证既有 `.2` 离线包，再执行替换。它没有放开任意版本或任意包内路径。
