# P65.D6 Hot Callback 可观测性惰性化

## 目标

`DispatchEventHot` 的正常成功路径原先每次都采集 wall-clock 起止时间，并在 Wasmtime 返回后构造
完整失败诊断临时对象。callback benchmark 已证明 typed Host bridge 只有数纳秒，因此这些固定成本
不应继续占据每次脚本入口。

## 实现

- 完整 `DispatchEvent` 仍逐次计时；`DispatchEventHot` 每 256 次成功入口采样一次 callback 时间。
  第一笔调用必采样，运行中持续更新观测值，不把生产热路径变成完全不可观测的黑盒。
- Wasmtime 在 call status 成功、failure 为空、没有 deferred unload 且返回形状正确时直接完成调用。
  只有 trap、Host failure、错误结果形状或重入卸载才构造字符串和 stack-frame 容器。
- pending Host failure 字符串只在确实存在上一笔 failure 时清理，正常调用不再重复 reset 四个空字符串。
- fuel、epoch、Host-call budget、prepared export lifetime 和 failure category 均未改变。

## 验证

- UE5.8 `AvidTPSTemplateEditor Win64 Development` no-clean 增量构建成功。
- `AvidScript.Runtime.Event`：发现 6 项，6/6 Success。
- `AvidScript.VM.Wasmtime`：发现 14 项，14/14 Success；覆盖 execution budget、trap、reentrant
  unload、precompiled artifact、reload lifetime 与 ABI。
