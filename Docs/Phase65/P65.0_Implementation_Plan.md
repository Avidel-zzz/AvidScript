# Phase 65 实施计划

状态：架构冻结，开始 P65.A

## 批次

### P65.A 可重复发布与原子安装

- 建立 release manifest/inventory schema 与共享校验内核。
- 实现 source developer preview 发布器，纳入受管第三方实物与许可证，排除本机产物和隐私数据。
- 实现 `Install/Upgrade/Repair/NoOp/WhatIf` 计划、项目级锁、同卷 staging、readback 和完整回滚。
- 用故障注入覆盖篡改、路径逃逸、未知文件、并发、提交前失败与提交后清理失败。

### P65.B Compatibility Doctor 与 support bundle

- 统一探测 UE5.8、.NET 8.0.416、PowerShell、VS、Wasmtime、Binding、Generated Type 和项目 Target。
- 输出稳定 JSON code/category/severity/remediation，不以终端文本作为机器合同。
- 导出 allowlist support bundle，脱敏个人路径、凭据、环境和源码，发布 inventory 与哈希。
- 提供一个只读命令完成安装验证与问题收集，不修改系统或项目配置。

### P65.C Android 与 Shipping 自动发布 Gate

- 复用并收敛现有 Android preflight、UBT、BuildCookRun、receipt 与 scenario runner。
- 在工具链可用时完成 arm64 UBT、APK/AAB 内容身份和自动设备生命周期；缺失层保持 `not_run`。
- 用同一 release manifest 绑定 Win64/Android backend、Generated Type 与模块包身份。
- 保留 Shipping UI 视觉、物理输入和设备体验的人工作业边界，不中断自动实现。

### P65.D 当前版本性能领导力与 Release Candidate

- 冻结当前 AvidScript/Puerts/AngelScript/native 的版本、语义、workload 和正确性 oracle。
- 复跑当前候选的纯执行、Reflection、生命周期、事件、容器和批量玩法矩阵。
- 对红项做分层 attribution 和产品路径优化，不添加 benchmark 专用 API。
- 完成一次集中审查、修复、完整 Gate、中文结果与 Developer Preview Release Candidate。

## 提交节奏

每个批次作为一个完整能力单元：架构/产品代码/必要合同/中文文档完成后，执行轻量静态验证，更新 README，
精确暂存、提交并推送。UE 构建、完整 Automation 与 benchmark 在受影响大批次或阶段统一 Gate 执行，
普通低风险问题集中处理，不重复碎片化复审。

## 转入边界

- `P65-D01-AndroidDevice`：Phase 64 未具备 Android SDK/ADB，必须保持真实层级状态。
- `P65-D02-ManualReleaseAcceptance`：Shipping UI、物理输入、手柄和真机体验是人工 Gate。
- `P65-D03-ControlledLeadership`：纯执行和完整跨框架矩阵尚未达到全面领先声明标准。

## 下一步

实现 P65.A 的共享 release package model、确定性 inventory 与发布/安装事务；完成后立即提交推送，再进入 P65.B。
