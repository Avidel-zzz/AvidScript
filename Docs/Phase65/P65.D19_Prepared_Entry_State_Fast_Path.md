# P65.D19 Prepared Entry State 快路径

## 本节目标

压缩每次 Guest entry 都会支付的 Runtime/VM 固定成本，让 callback 优化从 profiler 外围进入真正的
Wasmtime prepared export 包装层。所有改动必须继续保留失败诊断、嵌套调用、fuel、epoch watchdog、
Host-call budget 与延迟卸载语义。

## 已实现

- `InvokeVmExport` 不再先清空一次 `FAvidScriptVmError`，随后又由 VM backend 重复清空；Runtime 自己
  拒绝 backend 或参数时仍显式重置并填写完整错误。
- Wasmtime 在模块加载并完成首次 budget 初始化后，计算 `bResetExecutionBudgetPerEntry`。verified
  Win64 package 的 terminal epoch + unlimited Host-call + no per-entry fuel 组合可跳过整个逐 entry
  budget 重置；其他配置继续走原路径。
- 只有启用 `MaxHostCallsPerEntry` 时才清零 Host-call counter，fuel 和 epoch 的独立配置不再产生无关写入。
- export 完成态拆成 `FORCEINLINE` 成功路径与 `FORCENOINLINE` 冷诊断路径。正常调用只递减深度并写回
  可选结果；trap、Host failure、result ABI 错误和 reentrant unload 仍进入原有完整诊断流程。
- 没有按 export 名、binding 类型或 benchmark workload 添加特判。

## 正式结果

| Workload / lane | D18 P50 | D19 P50 | D19 P95 | D19 / Puerts static P50 | D19 / Puerts static P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| callback_empty / generated S1 | `121.38 ns` | **`112.99 ns`** | `139.60 ns` | `1.068x` | `1.158x` |
| callback_tick / generated S1 | `148.14 ns` | **`137.11 ns`** | `146.09 ns` | `1.061x` | `1.069x` |
| callback_empty / adaptive semantic | `120.22 ns` | **`113.09 ns`** | `136.45 ns` | `1.069x` | `1.132x` |
| callback_tick / adaptive semantic | `146.73 ns` | **`136.85 ns`** | `144.34 ns` | `1.059x` | `1.057x` |

Generated S1 相对 D18 的 callback_empty P50/P95 分别下降 `6.92% / 7.40%`，callback_tick 分别
下降 `7.44% / 6.33%`。同轮 Puerts static 的 callback_empty/tick P50 为
`105.80 ns / 129.20 ns`，因此两项 P50 仍分别慢约 `6.8% / 6.1%`，尚未关闭 callback 门禁。

十项 UE micro 的 generated S1 P50/P95 几何均值为 `0.733x / 0.737x`，P50 与 P95 各有
`6/10` 胜项；data-oriented 为 `0.735x / 0.737x`，同样各有 `6/10` 胜项。与 D18 相比，
generated S1 的整体 P95 比率也从 `0.750x` 改善到 `0.737x`。

## 当前结论

D19 证明 prepared-entry 固定状态处理是有效优化面：两种 callback 的 P50/P95 均获得约 `6%` 到
`7%` 的正式提速，同时完整安全语义回归通过。总体 UE micro 继续领先，但 callback、
object_roundtrip、pure_integer 与同口径 AngelScript 矩阵尚未全部达到领导力标准，P65-D03 不关闭。
