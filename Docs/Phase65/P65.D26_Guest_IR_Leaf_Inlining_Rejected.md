# P65.D26 Guest IR 纯叶函数内联候选归档

## 本节目标

验证 `pure_integer` 约为 Puerts static 两倍的主要差距是否来自循环内的 Guest 函数调用。候选在
非调试 C# Guest IR 管线中增加受预算约束的纯标量叶函数内联，仅接受线性控制流、无 import、无内存、
无局部写入且至少包含两个算术操作的函数；调试插桩继续保留源码调用边界。

## 诊断与正式结果

| 口径 | D22 generated P50/P95 | D26 generated P50/P95 | D26 / Puerts static P50/P95 |
| --- | ---: | ---: | ---: |
| 1 ms diagnostic | `1.932 / 2.055 ns` | **`1.034 / 1.129 ns`** | **`1.062x / 1.090x`** |
| 5 ms formal | `1.922 / 2.022 ns` | `2.300 / 2.710 ns` | `2.172x / 2.005x` |

诊断校准为 `819,200` 次 generated 迭代，候选绝对耗时下降约 `46.5%`；正式校准为
`2,048,000` 次迭代，五个独立进程的 generated P50 均约为 `2.24-2.37 ns`，相对 D22 正式
P50/P95 反而上升约 `19.7% / 34.0%`。这证明短诊断收益不能外推为稳定正式收益。

十项 generated S1 的正式几何均值为 `0.659x / 0.650x`，仍有 `7/10` 个 P50/P95 胜项；但
`callback_empty` 为 `1.030x / 1.099x`，`object_roundtrip` 为 `1.082x / 1.067x`，且本节目标
`pure_integer` 没有改善，因此不以整体几何均值掩盖关键失败。

## 结论与下一步

Guest IR 级复制消除了 call，却同时增加调用者的临时 locals 与代码体积。现有证据只能证明这种代码形态
对采样时长敏感，不能单凭结果断言具体微架构原因。D26 按正式门禁拒绝，P65-D03 继续开放。

D27 改为在 Wasm backend 做通用的单基本块表达式栈化：根据 use count 把单次使用、无副作用的 producer
直接发射到 consumer 栈上，减少 `local.set/local.get` 和活跃 locals；保持 Guest IR、源码调试合同、
分支合流、内存与 import 边界不变。先用生成字节码与短诊断筛选，再进入正式 packaged 矩阵。
