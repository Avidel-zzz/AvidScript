# P65.D13 Packed UObject Roundtrip 性能闭环

## 本节目标

把实例 `UObject* -> UObject*` UFUNCTION 从旧的五个 `i32` 参数与 Guest 输出缓冲区，迁移到
`(i64 self, i64 object) -> i64` 的版本化 packed handle ABI，并用真实 Win64 packaged host 与冻结版
Puerts 完成正式对比。实现按 generated shape 与签名识别，项目自定义的同形 UFUNCTION 可复用该路径，
不依赖 benchmark API 名称。

## 已实现

- 新增 `packed_stable_object_roundtrip`，按 `slot | generation << 32` 打包 handle；旧
  `stable_object_roundtrip (iiiii)i` 继续保留，现有 package 不被强制迁移。
- Descriptor、C# facade、生成 C++ callsite、Runtime prepared target 与 Wasmtime typed host 已贯通
  `(II)I`。新路径不再借用 Guest Memory 写回两个输出 cell。
- 旧、新 ABI 共用同一 UObject 语义核心：owner/参数解析、期望 class、world/capability、native thunk、
  alias 复用与输出注册只维护一份。
- 成功 null 使用 packed `0`；失败继续通过 typed-host status 形成 trap，不能伪装成 null。半零 handle、
  过期 generation、错误 target 或签名均失败关闭。
- 性能 runner 的 fused generated oracle 已同步 object shape；正式样本要求一次 revalidate，后续全部命中
  fast path，fallback、reject 与 Semantic 命中均为零。

## 正式结果

环境为 UE5.8 Win64 Development、Intel Core Ultra 7 265K、Wasmtime 45 Cranelift 与冻结 Puerts V8。
每个 lane/workload 在 5 个独立进程中先预热 5 次，再计时 30 次；表中 P50/P95 是先计算进程内
nearest-rank，再取 5 个进程结果的 nearest-rank P50。

| Lane | P50 | P95 | 相对 Puerts static P50 |
| --- | ---: | ---: | ---: |
| AvidScript generated S1 | **`51.88 ns`** | **`54.92 ns`** | `1.139x` |
| AvidScript data-oriented | **`51.96 ns`** | **`54.65 ns`** | `1.140x` |
| AvidScript adaptive semantic | `94.64 ns` | `98.25 ns` | `2.077x` |
| Puerts static | `45.57 ns` | `47.75 ns` | `1.000x` |
| Puerts reflection | `112.89 ns` | `120.88 ns` | `2.477x` |

D11 的 generated S1 `object_roundtrip` P50 为 `147.73 ns`。本批降低约 `64.9%`，即 `2.85x`
提速；相对 Puerts reflection 为 `0.460x`，但相对 Puerts static 仍为 `1.139x`，因此 object static
单项尚未领先。正式运行累计 `19,200,000` 次 generated 命中，fallback、reject、Semantic 命中均为 `0`。

十项 UE micro 的 generated S1 P50/P95 几何均值从 D11 的 `0.810x / 0.870x` 改善到
**`0.779x / 0.786x`**，P50/P95 胜项保持 `6/10`；data-oriented 为
**`0.783x / 0.788x`**，同样为 `6/10`。聚合值已领先本轮每项最快 Puerts lane，但 callback、
pure integer、object static 与 AngelScript 同语义矩阵仍未全部关闭，所以 P65-D03 继续保持未验证。
