# Phase 65 发布工程与性能领导力架构

状态：架构 v1，实施前冻结

## 目标

Phase 65 把 Phase 64 已通过正式 Gate 的 C# + WASM 游戏闭环收敛为可分发、可安装、可升级、
可诊断且可验证性能的开发者预览版。目标不是生成一个能解压的 ZIP，而是建立一条能回答以下问题的
Release 工程链：

- 这个包由哪个 Git tree、工具链、依赖和构建配置产生；
- 安装或升级前是否与目标 UE 项目兼容；
- 失败时是否保持旧版本和用户项目数据不变；
- Android 与 Shipping 的自动证据达到哪一层，哪些仍未实际执行；
- 当前版本在同语义玩法与 UE 交互路径上是否仍领先 Puerts，并如何纳入 AngelScript 对照。

本阶段继续坚持 WASM-first、通用 Reflection/Profile Binding 与 backend 解耦。发布工程不会把 Demo
专用 API 写进 Runtime，也不会为了通过性能门禁关闭 capability、类型、World、Session 或 ABI 校验。

## 非目标

- 不实现完整 CLR、NuGet Runtime、任意 C# 或 `.avid` 语言前端。
- 不以脚本安装器改写用户的 `.uproject`、引擎目录、系统环境变量或现有游戏资产。
- 不把 Android 交叉 AOT、SDK preflight 或模拟报告称为真机通过。
- 不以 microbenchmark 单项胜出声明整款游戏帧率领先。
- 不在没有 macOS、签名和设备的环境中声明 iOS 支持完成。

## 模块边界

```text
tracked source + dependency locks + generated release inputs
                         |
                         v
Release Publisher -> immutable release directory/archive + release manifest
                         |
                         v
Compatibility Doctor -> install plan / fail-closed diagnostic
                         |
                         v
Atomic Installer -> staged target -> verify -> commit or rollback
                         |
                         v
Project Plugins/AvidScript

Runtime/VM diagnostics -> redacted support snapshot
Android runner          -> toolchain / UBT / package / device evidence
Benchmark harness       -> correctness-bound cross-framework aggregate
```

- `Build/ReleaseEngineering` 拥有发布 manifest、inventory、安装事务和 support bundle schema。
- `Build/` 顶层脚本只负责编排和稳定 CLI，不复制发布、哈希、兼容或回滚规则。
- `AvidScriptRuntime` 只发布只读版本与运行诊断，不读取安装器状态，不执行文件升级。
- `AvidScriptVM` 继续只通过 backend interface 暴露 runtime、artifact 与 feature 身份。
- Android SDK/ADB 与 benchmark 竞争框架只存在于构建和验证侧，不进入产品 Runtime 依赖图。

## 发布包合同

发布 manifest schema v1 至少包含：

- `release_id`、语义版本、channel、Git commit/tree 与 dirty policy；
- UE 最低/最高兼容范围、目标平台与配置；
- .NET、PowerShell、Wasmtime/WAMR、Binding/ABI/Schema 身份；
- 规范化相对路径 inventory：文件长度、SHA-256、角色和可执行位语义；
- package profile、生成时间、publisher 版本与根 inventory hash；
- 可选签名 envelope 的算法、key id 和签名，不将私钥或机器路径写入包。

inventory 按 ordinal 路径排序，拒绝绝对路径、`..`、重复路径、大小写碰撞、reparse point、未声明文件、
不匹配哈希和超限文件。发布器从新 staging 根构建，完成全部验证后一次提交；不得在旧输出目录上增量覆盖。

开发者预览包使用 source profile：保留构建所需源码、Build/Tools、Samples、必要 Docs、Content、Config、
descriptor、许可证和锁定的第三方实物；排除 `.git`、Binaries/Intermediate/Saved、临时日志、私有证据、
编辑器用户状态与凭据。第三方实物必须由受管 receipt 证明版本、来源和哈希，并携带许可证。

## 安装、升级与回滚

安装器只接收经过 manifest 与 inventory 验证的目录或 archive。目标固定为调用方显式给出的
`<Project>/Plugins/AvidScript`，并执行以下事务：

1. 获取目标项目级独占锁并确认路径没有逃逸、链接或大小写歧义；
2. 读取现有安装 receipt，计算 `Install`、`Upgrade`、`Repair` 或 `NoOp` 计划；
3. 在目标父目录创建同卷 staging，复制后重新验证完整 inventory；
4. 将旧插件原子移到唯一 backup，再把 staging 原子提交为目标；
5. 对提交后的 descriptor、manifest、依赖和文件哈希做 readback；
6. 提交前任一步失败均恢复旧目录；提交后的 backup 清理失败只告警并保留可恢复材料。

安装器不删除项目 `Saved/AvidScript`、用户 C# 工程、Binding package 或游戏资产。已有目标缺少合法
install receipt 时默认拒绝覆盖，只有显式 adoption 流程且 inventory 无未知文件时才能接管。跨卷、目录锁、
目标进程占用、降级、ABI 不兼容和并发安装均 fail-closed。`-WhatIf` 输出同一份计划但不写目标。

## 兼容与诊断

Compatibility Doctor 使用只读探针输出 versioned JSON 和简短终端摘要，分层报告：

- Host：Windows、PowerShell 7、固定 .NET SDK、VS toolchain 与 UE5.8 source root；
- Plugin：descriptor、模块、第三方依赖 receipt、二进制/BuildId 与 Generated Type 完整性；
- Project：uproject、target、Binding/Profile/package identity 和 writable staging；
- Platform：Win64 JIT/AOT 与 Android SDK/NDK/JDK/ADB 可用性；
- Runtime：可选的 package、backend、Session、cache 和诊断 snapshot。

错误使用稳定 code、category、severity、message 与 remediation，不依赖本地化文本解析。Support bundle
只汇总 allowlist 诊断、manifest、receipt 和日志尾部；默认脱敏用户名、绝对用户路径、token、环境值和
源码正文，并对每个导出文件发布 SHA-256。原始日志不因导出成功被删除。

## Android 与 Shipping Gate

沿用 Phase 64 的四层模型：toolchain、arm64 UBT、APK/AAB、device。每层独立发布 `passed`、`failed`
或 `not_run`，上层不能由下层状态推导。受控工具链版本继续固定为 Android 34、Build Tools 35.0.1、
CMake 3.22.1、NDK 27.2.12479018 与兼容 JDK；脚本只设置子进程环境。

有设备时，device Gate 安装唯一 package、启动唯一 run id，验证 BeginPlay/Tick/Event/Save、后台恢复、
进程重启读回与干净退出。无设备时自动流程继续完成可执行的较低层并保留 `not_run`，不等待人工确认。
Shipping UI 视觉和物理输入仍是独立人工作业，不阻塞自动编码，但正式公开 Release 不能把它标成通过。

## 性能领导力

P65.D 使用冻结 workload、同机进程、正确性 oracle、warmup、样本数、CPU 策略与版本身份，对比：

- AvidScript Wasmtime JIT/AOT；
- 冻结 Puerts V8 static/reflection 路径；
- 可复现的 AngelScript UE 集成或明确记录无法建立同语义对照的原因；
- UE native baseline，用于定位而非竞争声明。

矩阵至少覆盖纯计算、普通 UFunction、property、FVector、UObject、容器、BeginPlay/Tick/event 与批量玩法。
发布 median、p95、吞吐、分配、Host crossing、prepared/fallback route 计数和原始 aggregate SHA。
先优化 reflection/name lookup、crossing、codec/memory copy、Session 调度，再评估 backend；不为单项数字
增加 benchmark-only fast path。只有所有声明的 headline lane 满足冻结阈值时才发布“领先”，否则保留
精确红项和成本归因。

## Gate 与完成定义

- 发布器与安装器：确定性、篡改、路径、并发、故障注入、升级/回滚与隐私合同通过。
- Doctor/support：稳定 schema、脱敏、缺失工具链和损坏安装的真实只读验证通过。
- UE5.8：clean source install、no-clean Editor UBT、完整 Automation 与 Win64 package smoke 通过。
- Android：环境允许的层全部执行，未执行层明确保留；不制造设备证据。
- 性能：同语义 correctness 先通过，受控 aggregate 可审计，领先与未领先结论逐 lane 发布。
- 人工视觉、手柄、Shipping UI 与真机物理体验继续单列，自动化不冒充人工验收。

阶段采用一次集中审查、一次集中修复和一次统一 Gate。每个完整批次更新简洁 README 后立即提交并推送，
不为普通问题重复构建和复审。
