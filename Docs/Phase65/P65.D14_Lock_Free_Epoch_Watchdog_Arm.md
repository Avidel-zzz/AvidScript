# P65.D14 Lock-Free Epoch Watchdog Arm

## 本节目标

移除每次顶层 Guest entry 在共享 epoch watchdog `Arm` 上获取的全局 critical section，同时保留
epoch timeout、fuel、Host-call budget、线性内存限制以及注册/注销安全。该优化作用于所有顶层 export，
不按 callback 名称或 benchmark workload 特判。

## 已实现

- 每个 entry 继续用 release-store 发布绝对 deadline；共享 `NextWakeCycles` 改为原子 CAS-min，只有
  发布了更早 deadline 的调用才触发 wake event。
- watchdog 后台线程在持有 entries 锁时清空并重建最早唤醒时间；与并发 `Arm` 竞争时，较早唤醒
  最多产生一次保守空醒，不会丢失 timeout。
- 注册、注销、engine epoch 递增与 entries 生命周期仍保留原锁；正常 callback 的 `Arm/Disarm`
  不再进入该锁。
- wake event 由 thread-safe shared signal 持有，并同时挂在 watchdog 与 entry 上。注销或关停释放
  watchdog 所有权后，在途 entry 仍保证 event 生命周期，不需要每次 `Arm` 增减全局引用计数。
- `Disarm` 仍只清零 entry deadline，不增加正常成功路径的内核事件通知。

## 正式结果

每个 lane/workload 使用 5 个独立进程、每进程 5 次预热和 30 次计时。P50/P95 先取进程内
nearest-rank，再取 5 个进程结果的 nearest-rank P50。

| Workload / lane | D13 P50 | D14 P50 | D14 P95 | P50 变化 |
| --- | ---: | ---: | ---: | ---: |
| callback_empty / generated S1 | `158.53 ns` | **`144.83 ns`** | `151.69 ns` | **`-8.6%`** |
| callback_empty / adaptive semantic | `156.93 ns` | **`142.78 ns`** | `151.75 ns` | **`-9.0%`** |
| callback_empty / data-oriented | `160.71 ns` | **`142.69 ns`** | `151.50 ns` | **`-11.2%`** |
| callback_tick / generated S1 | `222.60 ns` | **`206.88 ns`** | `217.40 ns` | **`-7.1%`** |
| callback_tick / adaptive semantic | `222.55 ns` | **`205.60 ns`** | `214.69 ns` | **`-7.6%`** |
| callback_tick / data-oriented | `226.85 ns` | **`207.50 ns`** | `216.80 ns` | **`-8.5%`** |

本轮 Puerts static 的 callback_empty/tick P50 为 `114.03 ns / 133.31 ns`。Generated S1 对应
比率仍为 `1.270x / 1.552x`，所以去锁优化尚未让 callback 单项领先。十项 UE micro 的 generated
S1 P50/P95 几何均值从 D13 的 `0.779x / 0.786x` 改善到 **`0.766x / 0.765x`**；data-oriented
为 **`0.767x / 0.770x`**。其余八项 generated workload 的最大 P50/P95 回退为
`2.50% / 2.22%`，低于本批 `3%` 守门线。

## 当前结论

这轮证明 watchdog 全局锁确实是 callback 固定成本之一，并且优化没有把开销转移到其他 micro。
但 callback 仍有约 `31 ns` 的 empty 差距和约 `74 ns` 的 tick 差距，P65-D03 继续保持未验证；
十项聚合领先不能扩写为所有 workload、纯执行层或 AngelScript 同语义领先。
