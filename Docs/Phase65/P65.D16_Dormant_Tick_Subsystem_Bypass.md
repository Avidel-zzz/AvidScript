# P65.D16 休眠 Tick 子系统直通

## 本节目标

让没有 continuation、deferred inbound 或 timer 工作的普通游戏 Tick 直接通过，避免为休眠子系统构造临时
容器、扫描状态或初始化错误对象。优化必须保留异步完成、递归 inbound、调试暂停、定时器与 fault
quarantine 的原有顺序和失败语义。

## 已实现

- continuation owner 新增 O(1) `NeedsTickPump()`：存在 active entry 或待回收 latent proxy 时才进入
  `DrainReady`；Guest Tick 内刚创建的 continuation 会立即反映到计数中。
- inbound handler 新增 O(1) `NeedsDeferredPump()`：pending failure 或启用状态下确有 deferred handler
  时才进入 pump；递归失败不会因队列为空而遗漏。
- Session 的 `Tick`、`TickLive` 与 `TickHot` 统一缓存 Tick 后的 debug suspended 状态。只有 continuation
  pump 实际运行并成功后才重新读取，保持 continuation callback 可进入调试暂停的语义。
- timer clock 继续每 Tick 推进；heap 为空时提前返回，due scratch 为空时不再构造和重置
  `FAvidScriptVmError`。

## 正式结果

每个 lane/workload 使用 5 个独立进程、每进程 5 次预热和 30 次计时。P50/P95 先取进程内
nearest-rank，再取 5 个进程结果的 nearest-rank P50。

| Workload / lane | D15 P50 | D16 P50 | D16 P95 | P50 变化 |
| --- | ---: | ---: | ---: | ---: |
| callback_tick / generated S1 | `174.10 ns` | **`140.19 ns`** | **`154.84 ns`** | **`-19.5%`** |
| callback_tick / adaptive semantic | `172.27 ns` | **`138.68 ns`** | **`154.66 ns`** | **`-19.5%`** |
| callback_tick / data-oriented | `172.65 ns` | **`140.10 ns`** | **`154.22 ns`** | **`-18.9%`** |

本轮 Puerts static 的 callback_tick P50/P95 为 `127.31 ns / 133.62 ns`，generated S1 对应比率由
D15 的 `1.331x / 1.360x` 收敛为 **`1.101x / 1.159x`**。5 个独立进程内的 P50 比率均位于
`1.10x–1.12x`，收益不是单进程离群值。

十项 UE micro 的 generated S1 P50/P95 几何均值为 **`0.686x / 0.732x`**，data-oriented 为
**`0.687x / 0.728x`**，两者保持 `6/10` 胜项。未修改的 callback_empty 本轮 generated S1 为
`128.82 / 138.94 ns`，其绝对值相对 D15 也下降；这项变化只能视作同机环境或二进制布局漂移对照，
不归因于 D16。其余八项相对 D15 的最大正向回退为 P50 `0.29%`、P95 `1.59%`。

## 当前结论

普通 Tick 为休眠子系统支付的固定成本已基本消除，generated Tick 与 Puerts static 的 P50 差距从约
`43.27 ns` 收窄到约 `12.88 ns`。P65-D03 仍未关闭：Tick P50/P95 尚未单项领先，pure integer 与
object static 仍是独立债务，也没有 AngelScript 同语义矩阵。

## 下一步

下一批聚焦 Session profiler scope 的禁用态和 Tick runtime 的剩余固定分支。优先把“是否采集”缓存为

语义，不允许为 benchmark 永久关闭诊断。
