# P65.D18 内联 Profiler Capture 判定

## 本节目标

消除 profiler 关闭时 `IsCaptureEnabled` 的跨模块调用开销，验证动态采集判定是否仍是 callback
成功路径的主要固定成本。本节只优化通用 profiler 入口，不按 export、绑定类型或 benchmark workload
编写特例。

## 已实现

- 在 profiler 公共头中声明 UE Trace channel，并将 `IsCaptureEnabled` 改为 `FORCEINLINE`。
- 调用点可直接完成 runtime buffer 与 UE Trace channel 判定，不再进入 out-of-line 函数。
- 保留逐次动态启停语义：运行中开启 buffer 或 Trace 后，下一次 scope 仍会立即开始采集。
- 未改变事件布局、correlation、成功状态、epoch、probe 或 `Record` 路径。

## 正式结果

| Workload / lane | D17 P50 | D18 P50 | D18 P95 | D18 / Puerts static P50 | D18 / Puerts static P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| callback_empty / generated S1 | `121.52 ns` | `121.38 ns` | `150.76 ns` | `1.147x` | `1.269x` |
| callback_tick / generated S1 | `146.70 ns` | `148.14 ns` | `155.96 ns` | `1.158x` | `1.158x` |
| callback_empty / adaptive semantic | `121.15 ns` | `120.22 ns` | `149.47 ns` | `1.136x` | `1.258x` |
| callback_tick / adaptive semantic | `147.63 ns` | `146.73 ns` | `154.48 ns` | `1.147x` | `1.147x` |

本轮 Puerts static 的 callback_empty/tick P50 为 `105.86 ns / 127.93 ns`。Generated S1 相对 D17
的 callback_empty P50/P95 变化为 `-0.11% / -0.70%`，callback_tick 为 `+0.98% / +0.07%`；
均处于当前进程与频率噪声范围，不能证明内联 predicate 带来稳定性能收益。

十项 UE micro 的 generated S1 P50/P95 几何均值为 `0.735x / 0.750x`，P50 与 P95 各有
`6/10` 胜项；data-oriented 为 `0.732x / 0.746x`，同样各有 `6/10` 胜项。总体仍领先同轮
Puerts static，但 callback_empty、callback_tick、object_roundtrip 与 pure_integer 仍未全部关闭门禁。

## 当前结论

D18 通过功能、架构与正式性能验收，但 callback 领先目标未达到。连续两轮 profiler 微调都没有产生
稳定收益，因此到此停止该方向，不再通过追加重复运行挑选结果。P65-D03 继续保持未验证。
