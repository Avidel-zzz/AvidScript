# P65.D33：保留 epoch 检查的代码生成优化实验

状态：诊断导出、原生代码检查与隔离 Win64 PreserveAll 实验已完成；生产优化尚未合入，完整性能结果仍为 D31.C11 的 16/18。
P65-D04 已按 D32.A-H 证据转为 Verified，P65-D03 进入 Fixing；Android/Mac 与人工验收继续独立保留。

## 问题与边界

历史正式候选 `7707d5c6` 的纯执行 P50/P95 几何均值为 1.1024x/1.2389x，未通过 0.95x 门槛。
最新原始明细中 `scalar_float` 的 P95 为 V8 的约 2.37x，另外 hashing 的 P95 约 1.71x。
不能把 D32 新 DLL 的包内运行通过解释为性能通过，也不能降低阈值、改变 kernel 或关闭生产安全检查。

本节仅扩展 `ControlledRuntime/NativeProbe`：可选 `ArtifactRoot` 导出四种配置实际测量的已编译模块，
序列化严格发生在全部 calibration、warmup、timed samples 与 checksum 比较之后。未传参数时保持原调用方式。
`WasmtimeInstallSource` 可显式选择中性运行库，并复用 D32 来源/内容/声明校验；编译后检查探针目录中的
实际 DLL，采样结束再次核对 DLL 与 EXE 哈希。已存在的产物根或报告拒绝覆盖。

导出只用于反汇编，不作为可加载生产包，不改变 ABI、VM profile selection 或正式 benchmark protocol。

## 新发现：热循环中的寄存器溢出

`scalar_float` 的 `wasm[0]::function[0]` 中，epoch-on 快路径回边是 `0xfc → 0x81`。
除 epoch load/compare/branch 外，每轮还有六次栈读写：

| 地址 | 指令作用 |
| --- | --- |
| `0x91` | 从 `[rsp]` 读取循环上界 |
| `0xab` | 从 `[rsp+8]` 读取整数状态 |
| `0xc8` | 从 `[rsp+0x10]` 读取浮点累积值 |
| `0xed` | 向 `[rsp]` 写回循环上界 |
| `0xf1` | 向 `[rsp+8]` 写回整数状态 |
| `0xf6` | 向 `[rsp+0x10]` 写回浮点累积值 |

epoch-off 的快路径 `0x62 → 0x1e` 没有栈访问，浮点累积值保持在 `xmm0`。
这证明启用 epoch 的生成代码还引入了循环状态的反复栈读写；尚未通过单独改变调用约定的对照，证明六次访问各自贡献的成本。

锁定 Wasmtime 源码的 `crates/cranelift/src/func_environ.rs` 已缓存 epoch 指针和 deadline，
普通的再次缓存指针不是新的优化方向。慢路径调用 `new_epoch`，返回值用于刷新缓存 deadline。
`crates/wasmtime/src/runtime/vm/libcalls.rs` 的 `new_epoch` 在正常返回前已经写入 store deadline，
因此可以研究无返回值的寄存器保留 wrapper，再在慢路径读取 deadline。

Cranelift `CallConv::PreserveAll` 明确用于减少插桩调用对周围寄存器分配的影响，但不支持返回值；
现有断点 trampoline 已演示无返回值调用、错误 sentinel 检查与 trap 转发。
下一实现必须为 epoch 定义清晰的内部调用合同，不能只在调用方标记 PreserveAll、却让被调函数继续破坏寄存器。

## 实验冻结的验证要求

1. 为 Win64 epoch 慢路径研究真实保留寄存器的无返回值 wrapper；快路径仍逐回边读取并比较 epoch。
2. 保留 deadline 更新、异常 sentinel、trap、stack limit、Spectre、原始 WASM 与第三方模块的中断边界。
3. 定向验证已过期 deadline 中断、回调继续后的新 deadline、浮点/SIMD 跨慢路径值保持及后续调用可恢复。
4. 只有中断语义和编译代码均验证后，才建立新的 runtime/patch/cache identity，再做中性构建与正式矩阵。
5. 当前诊断不能关闭 P65-D03；AngelScript 同语义矩阵仍缺失。

## D33.B：Win64 PreserveAll 实现与定向合同

实验文件位于 `Benchmarks/PuertsComparison/ControlledRuntime/NativeProbe/EpochPreserve/`。
补丁只修改锁定 Wasmtime 的三个 Cranelift 源文件，不改变主仓库生产 patch、运行库 lock 或安装目录。

`BuiltinFunctionSignatures::trampoline_signature` 为 Win64 的 `new_epoch` 提供普通指针参数、
无返回值的 `PreserveAll` 内部合同。调用方与生成的 trampoline 均使用这一入口；宿主 `host_signature`
仍返回原来的 deadline/sentinel，因此 `compile_wasm_to_builtin` 继续检查失败、转发 trap。
`epoch_check_full` 在正常返回后的冷路径读取 store deadline；其他平台保持原调用约定。
这里继续使用该 builtin 自身的内部 key，没有借用断点 trampoline 或启用 patchable 调用。

独立 Rust 探针执行 **17/17**：四个实际 kernel 分别验证已过期 deadline 中断及恢复、
Continue(100) 仅触发一次回调、Continue(0) 强制每次检查走慢路径、以及第 17 次回调失败后的错误传播和恢复；
另有纯无限回边被外部 epoch 增量中断。每个 kernel 的强制慢路径实际触发 **129 次回调**。
回调故意覆盖 Win64 宿主可改写的 GPR/XMM0-5；返回值及完整导出线性内存与 epoch-off 对照一致，
因此浮点累积值和 SIMD 存储也进入校验。探针包含 60 秒 watchdog，失去中断能力时不会无限等待。

`Invoke-EpochPreserveProbe.ps1` 在仓库外新目录复制来源、检查基线文件哈希并应用补丁；
记录完整源文件 inventory、Rust 版本、锁文件、探针、kernel 与产物哈希。离线构建只使用锁定依赖；
已存在的工作目录与被修改的基线均拒绝，两个拒绝合同 **2/2** 通过。
示例（`$BaselineSource` 是 D32 archive 加原锁定 patch 的已展开源码，`$WorkRoot` 必须不存在）：

```powershell
pwsh -NoProfile -File Benchmarks/PuertsComparison/ControlledRuntime/NativeProbe/EpochPreserve/Invoke-EpochPreserveProbe.ps1 `
    -BaselineSourceRoot $BaselineSource -WorkRoot $WorkRoot -CargoHome $CargoCache
```
