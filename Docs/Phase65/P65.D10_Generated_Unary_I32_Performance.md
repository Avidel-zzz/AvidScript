# P65.D10 Generated Unary I32 性能闭环

## 本节目标

把常见的实例 `int32 -> int32` UFUNCTION 从 Semantic/ProcessEvent 路径迁移到通用 Generated S1，
并用真实 Win64 packaged host 与冻结版 Puerts 完成同机正式对比。实现按签名识别，不包含
`ReflectNoOp` 名称特判，因此项目自定义的同形 UFUNCTION 可以复用同一生成路径。

## 已实现

- 新增 `I32ToI32` generated binding shape 与 `SelfI32ToI32` VM typed-host shape。
- 固定 ABI 为 `(iii)i`：对象 handle slot、generation、`int32` 输入，直接返回 `int32`。
- Descriptor、C# facade、生成 C++ callsite、registry、Runtime prepared target 和 Wasmtime linker
  已贯通；该 shape 只能使用验证后的 prepared generated target，缺失或身份漂移时失败关闭。
- generated S1 与 data-oriented 正式 profile 均启用 `ReflectNoOp`，不再经 semantic 或
  prepared-dynamic fallback。
- C++ runner、PowerShell Gate 与 fused evidence oracle 已同步新的 lane 计数语义。
- candidate freezer 的 artifact 准备命令显式抑制初始 Generated Type package 启动，允许新 sidecar
  在 catalog 发布前完成准备，不放宽运行包信任检查。

## 正式证据

运行环境为 UE5.8 Win64 Development、Intel Core Ultra 7 265K、Wasmtime 45 Cranelift JIT 与冻结
Puerts commit `1977328c84661024be10a9e73640a74b278a7659`。正式 profile 使用 5 个独立进程，
每进程 5 次预热、每 lane/workload 30 次计时，共 `9000/9000` 正确样本。

- Runtime evidence commit：`1003e3d3c1e436e236f50e48bf86d0aa6363c314`
- Tree：`6d07341053af59d56d4722a655e23504aae7ddd0`
- Candidate：`f12ef47c926985d555f0`
- 机器摘要：[P65.D10_Generated_Unary_I32_Performance.json](P65.D10_Generated_Unary_I32_Performance.json)

`scalar_noop` 的正式跨进程结果：

| Lane | P50 | P95 | 相对最快 Puerts P50 |
| --- | ---: | ---: | ---: |
| AvidScript generated S1 | `18.17 ns` | `20.67 ns` | **`0.829x`** |
| AvidScript data-oriented | `18.36 ns` | `21.39 ns` | **`0.838x`** |
| Puerts static | `21.92 ns` | - | `1.000x` |
| Puerts reflection | `75.06 ns` | - | `3.425x` |

旧候选的 generated S1 `scalar_noop` P50/P95 为 `587.93/609.01 ns`。新签名族将 P50 降低
约 `96.9%`，并使十项 micro 的 generated S1 P50 几何均值从 `1.440x` 改善到 `1.004x`；
P50 胜项由 `4/10` 增至 `5/10`。

## 当前结论

通用 unary i32 UE crossing 已经领先本次冻结的 Puerts static，但十项 micro 尚未全面领先：
generated S1 P50/P95 几何均值为 `1.004x/1.119x`，胜项为 `5/10`；data-oriented 为
`1.007x/1.127x`，P50 胜项同为 `5/10`。主要剩余热点是 `object_roundtrip 3.95x`、
`vector_ref_out 1.47x`、callback 和纯整数执行，因此 P65-D03 性能领导力继续保持未关闭。

## 下一步

下一批优先增加通用 FVector ref/out generated shape：使用固定 guest wire buffer 与一次 prepared
native writeback，消除当前每次调用的反射帧处理。随后优化 UObject handle roundtrip 的查找与验证边界，
最后再处理 callback entry containment 和纯执行 backend 生成质量。
