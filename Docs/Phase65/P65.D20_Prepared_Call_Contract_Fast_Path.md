# P65.D20 Prepared Call 合同快路径

## 本节目标

继续压缩每次 Guest entry 都会支付的固定成本，但不削弱公开 VM API 的输出初始化语义，也不移除
reload lifetime、trap、execution budget、Host failure 与延迟卸载保护。

## 已实现

- 公开 `FAvidScriptVmPreparedExportCall::Call` 在完成句柄和参数数量校验后统一清空错误与可选结果。
  普通 backend 调用者仍获得“每次调用都从干净输出开始”的稳定合同。
- `InvokeFunction` 被明确为内部低层 prepared 路径：Runtime 的热路径只向它传入本轮新建的临时输出，
  不再让 Wasmtime 重复清空 `FString`、stack frame 和结果 cells。
- Wasmtime 把 `ResetCallState` 收缩为按需执行的 `ResetPendingHostFailure`。无 Host failure 的正常调用只做
  一个布尔判断，不触碰四个诊断字符串。
- 三个 prepared member 路径不再重复读取 `IsLoaded`、generation 和 function。static thunk 已经先检查
  `Entry->Function`；卸载顺序仍是先删除 function 并将该指针置空，再释放 instance/store/engine，因此旧
  prepared handle 继续在接触 backend 状态前 fail closed。
- 没有按 export 名、binding 类型或 benchmark workload 添加特判。

## 正式结果

| Workload / lane | D19 P50 | D20 P50 | D20 P95 | D20 / Puerts static P50 | D20 / Puerts static P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| callback_empty / generated S1 | `112.99 ns` | **`108.38 ns`** | `132.27 ns` | `1.035x` | `1.137x` |
| callback_tick / generated S1 | `137.11 ns` | **`131.54 ns`** | `138.38 ns` | `1.018x` | `1.033x` |
| callback_empty / adaptive semantic | `113.09 ns` | **`111.23 ns`** | `130.18 ns` | `1.063x` | `1.119x` |
| callback_tick / adaptive semantic | `136.85 ns` | **`132.06 ns`** | `139.53 ns` | `1.022x` | `1.042x` |

Generated S1 相对 D19 的 callback_empty P50/P95 分别下降 `4.08% / 5.25%`，callback_tick 分别下降
`4.06% / 5.28%`。同轮 Puerts static 的 callback_empty/tick P50 为 `104.68 ns / 129.24 ns`，两项
P50 差距因此缩小到约 `3.5% / 1.8%`；callback_empty P95 仍慢约 `13.7%`，不能关闭 callback 门禁。

十项 UE micro 的 generated S1 P50/P95 几何均值为 `0.712x / 0.723x`，P50 与 P95 各有 `6/10`
胜项；相对 D19 的 `0.733x / 0.737x` 继续改善。data-oriented 为 `0.718x / 0.722x`，P50/P95
各有 `5/10` 胜项。

## 当前结论

D20 证明公开合同与内部低层调用分层可以继续减少 callback 固定成本，并且旧 prepared handle、错误输出、
budget 与 trap 语义均由真实回归覆盖。generated callback_tick 已非常接近同轮 Puerts static，
callback_empty 仍需要进一步处理成功路径中的 Wasmtime C API wrapper、watchdog 与间接调用成本。

P65-D03 继续保持未关闭；同口径 AngelScript 矩阵、pure integer 与剩余 static/object 场景也不能由本节
结果替代。
