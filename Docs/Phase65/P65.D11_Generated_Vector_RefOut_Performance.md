# P65.D11 Generated FVector Ref/Out 性能闭环

## 本节目标

把实例 `FVector ref/out` UFUNCTION 从 Semantic/ProcessEvent 路径迁移到通用 Generated S1，
并用真实 Win64 packaged host 与冻结版 Puerts 完成同机正式对比。实现按参数 shape 识别，
项目自定义的同形 UFUNCTION 可复用同一生成路径，不依赖 benchmark 函数名称。

## 已实现

- Descriptor、C# facade、生成 C++ callsite、registry、Runtime prepared target 与 Wasmtime typed host
  已贯通 `FVector ref/out` 固定 ABI。
- Guest 输入、输出使用固定 wire buffer；Runtime 每次 crossing 只借用一次 Guest Memory，并通过
  prepared native thunk 完成读取、调用与 writeback。
- Generated S1 与 data-oriented profile 均命中 generated shape；Semantic 与 prepared-dynamic
  计数保持为零，缺失 target、类型不匹配或内存越界时继续失败关闭。
- C++ runner、PowerShell Gate 与 fused evidence oracle 已同步新的 lane 计数语义。

## 正式证据

运行环境为 UE5.8 Win64 Development、Intel Core Ultra 7 265K、Wasmtime 45 Cranelift 与冻结
Puerts commit `1977328c84661024be10a9e73640a74b278a7659`。正式 profile 使用 5 个独立进程，
每进程 5 次预热、每 lane/workload 30 次计时，共 `9000/9000` 正确样本。

- Runtime evidence commit：`884443a1e1d65e116304f928451f178a56f56a7a`
- Tree：`6659b6a8dc2aaf391a553671213495e9d6bcb9a3`
- Candidate：`2a7f6ab653e64dc525ee`
- 执行宿主：验证后的 packaged game，5/5 进程身份一致
- 机器摘要：[P65.D11_Generated_Vector_RefOut_Performance.json](P65.D11_Generated_Vector_RefOut_Performance.json)

`vector_ref_out` 的正式跨进程结果：

| Lane | P50 | P95 | 相对最快 Puerts P50 |
| --- | ---: | ---: | ---: |
| AvidScript generated S1 | **`103.64 ns`** | **`111.34 ns`** | **`0.144x`** |
| AvidScript data-oriented | **`103.57 ns`** | **`117.65 ns`** | **`0.144x`** |
| Puerts static | `717.51 ns` | `845.75 ns` | `1.000x` |
| Puerts reflection | `792.00 ns` | `928.69 ns` | `1.104x` |

D10 候选的 generated S1 `vector_ref_out` P50 为 `1026.61 ns`。本批将 P50 降低约
`89.9%`，即约 `9.91x` 提速；相对本轮最快 Puerts P50 快约 `6.92x`。正式样本累计
`9,600,000` 次 generated 命中，Semantic 命中、generated fallback、reject 均为 `0`。

## 当前结论

十项 UE micro 的 generated S1 P50/P95 几何均值已从 D10 的 `1.004x/1.119x` 改善到
**`0.810x/0.870x`**，胜项从 `5/10` 增至 `6/10`；data-oriented 为
**`0.810x/0.904x`**，P50/P95 胜项均为 `6/10`。这证明当前冻结的 UE micro 聚合已经快于
Puerts 最快 lane，但不能扩写为全场景领先：`object_roundtrip`、callback 与 pure integer 仍落后，
相同 WASM 执行层门禁和 AngelScript 同语义矩阵也尚未关闭，因此 P65-D03 保持未验证。

## 下一步

下一批优先优化 UObject roundtrip：在 Session owner 身份已由当前 frame 验证时复用 fused receiver，
随后评估把 slot/generation 输出合并为 packed `i64` 直接返回，减少 Guest Memory 写回和 handle
registry 往返。callback containment 与纯执行 backend 生成质量继续作为独立欠账推进。
