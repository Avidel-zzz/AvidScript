# P65.D32 Win64 公开二进制路径脱敏

状态：D32.A 只读扫描器与 D32.B 中性重建实测已通过；现有 Wasmtime 产物扫描正确拒绝，新中性产物完整扫描通过。传递依赖许可证、新 DLL 的 UE 集成与公开离线包 Gate 尚未完成。Android 与 Mac 实机验收按用户要求暂缓。

## 问题与范围

现有 Wasmtime managed receipt 能证明文件内容一致，却不能证明 DLL 没有内嵌个人目录。
P65-D04 因此继续保持 Open；当前 `source-developer` 发布合同与外部依赖方式不变。
本小节先补齐受控中性构建和可验证的隐私证据，真实结果通过后再单独扩展离线发布 profile。

修改 owner 为 Wasmtime 工具链构建入口及 `Build/ReleaseEngineering` 的文件扫描工具；不修改 VM
执行策略、Guest ABI、编译优化、安全预算和正在采样的冻结候选。公开包不能依赖手动修改 DLL 字节。

## 构建合同

1. 使用锁定的 upstream commit、归档 SHA-256、patch、Rust 版本、Cargo features 和 CMake profile。
   中性构建在独立根中进行，不覆盖主工程或性能候选的 installed runtime。
2. 源码、Cargo cache/target、生成代码和临时目录必须有完整前缀映射。Windows 正斜杠与反斜杠
   分别处理；宽泛映射在前，具体映射在后。实际构建目录不得处于用户 home 中。
3. 使用 `CARGO_ENCODED_RUSTFLAGS` 传递独立参数，避免含空格路径被拆开；受控模式拒绝未经记录的
   外部编译参数。保留 `SOURCE_DATE_EPOCH`、现有优化 profile 和全部安全能力。
4. 环境修改限制在构建子进程或可恢复的作用域；路径映射和隐私检查失败时不发布 managed install。
   receipt 只保存稳定虚拟映射身份和内容哈希，不能把真实用户名或私有路径重新写入可分发证据。

Rust 官方说明明确指出路径映射是文本替换，且不覆盖链接器自行生成的路径；因此配置成功不能代替
最终字节扫描。见 [Rust 路径映射](https://doc.rust-lang.org/rustc/remap-source-paths.html) 和
[Cargo 环境变量](https://doc.rust-lang.org/cargo/reference/environment-variables.html)。实际参数必须由
仓库固定的 Rust 1.93 工具链验证，不依赖最新文档才有的选项。

## 隐私证据合同

- 对将要分发的完整文件集合扫描，不只检查 DLL 的可打印字符串；至少覆盖 UTF-8、UTF-16LE/BE、
  两种 Windows 分隔符、大小写变化和跨读取块的匹配。
- 必查当前用户名、home、源码/Cargo/build/temp 根，以及常见个人目录模式。相对文件名同样检查。
  未知编码或工具引入的路径不由“已配置 remap”自动豁免。
- 只读扫描拒绝空集合、路径逃逸、reparse point、ADS、读取失败及扫描期间发生的文件变化；
  验证与报告必须绑定同一组文件内容。
- 报告包含相对路径、长度、SHA-256、规则标识和命中数量，不复制命中的私有字符串。
  扫描失败保留本地诊断并以非零状态阻止发布；receipt/inventory 不得把失败重新解释为成功。
- 许可证、锁定来源、导出符号、managed receipt 与扫描结果分别验证。隐私通过不表示许可、功能、
  确定性或 UE 安装运行已经通过。

## 集中验证与后续边界

行为合同使用合成文件覆盖多种编码、路径变体、边界匹配、命中拒绝和证据内容身份；构建参数合同
覆盖带空格路径、嵌套映射及环境恢复。真实 Gate 使用新的中性目录重建锁定工具链，扫描全部交付
文件，复核许可证、导出与 receipt，再执行隔离 Win64 集成验证。已有性能样本仍属于原 runtime
身份；换用新 DLL 后不能沿用旧身份宣称性能通过。

本节完成之前不启用公开离线二进制 profile。启用该 profile 需要另一个完整写集，包含发布 schema、
包内依赖 provenance、安装器验证、篡改拒绝及全新 UE 工程安装构建；不能只放宽扩展名 allowlist。

## 实施批次与写集

实现分为两个批次；D32.A 已落地，D32.B 已完成真实重建与扫描，后续发布验收继续按以下合同执行。

| 批次 | owner 与交付 | 集中验证 |
| --- | --- | --- |
| D32.A | `Build/ReleaseEngineering` 新增只读 payload 隐私扫描器及版本化报告；`Build/Contracts` 新增行为合同 | 合成二进制、多编码、跨块、文件名、空集合、ADS、reparse、读取冲突与报告不泄漏 |
| D32.B | Wasmtime 工具链构建入口增加显式中性模式；同目录 helper 管理映射、环境与发布前扫描 | 固定 Rust 参数探针、环境恢复、独立中性根真实构建、全部安装文件扫描、导出与 managed receipt |

扫描输入为单一普通目录的完整文件集合，报告必须位于该目录外。扫描器不得接受扩展名白名单、
静默跳过不可读文件或让调用者从完整 payload 中挑选有利子集。报告记录 scanner 版本、规则身份、
文件数量及按相对路径排序的内容清单；扫描不改变输入，也不执行输入二进制。

扫描与 SHA-256 从同一受控文件流读取，Windows 打开共享模式禁止并发写入和替换；扫描前后比较
普通目录清单与文件元数据。编码窗口保留足够重叠，并覆盖 UTF-16 两种字节起点，避免只识别
文本文件起始对齐。报告不得带入实际 deny token、源目录或异常中的机器路径；文件名命中时也不能
把命中的相对路径原文写入可分发报告。失败报告只能说明规则、文件索引和内容身份。

中性模式使用独立 Cargo home、target 和 temp，在新进程中执行；外部 Rust flags、wrapper、
Cargo profile 覆写和原生编译/链接参数应在下载或构建前拒绝。`CARGO_ENCODED_RUSTFLAGS` 的
每个映射作为一个参数传递，不改变现有优化和安全配置。Cargo 调用显式使用 `--locked`，确认
上游 `Cargo.lock` 未被构建改写；中性缓存不得复用普通模式的 target 输出。

隐私报告作为独立验证证据留在 payload 外，managed receipt 继续绑定实际交付文件哈希，避免
报告包含自身哈希的循环依赖。构建失败或扫描命中时保留原有 install 与本地失败证据，不发布
新目录。许可证检查需要覆盖实际锁定依赖图，不能由 Wasmtime 顶层 LICENSE 的存在代替。

本批不修改正在执行正式矩阵的候选、共享 runtime 或性能门槛。新的中性 DLL 具有独立内容身份，
只有其后续 Win64 集成与发布 Gate 才能证明可分发，旧 DLL 的性能与运行证据不能自动转移。

## D32.A 实现与实测（2026-09-11）

入口为 `Build/InvokeAvidScriptBinaryPrivacyScan.ps1`，策略与 C# 扫描核心位于
`Build/ReleaseEngineering/AvidScriptBinaryPrivacy*`。报告 schema 为 v1，并记录实际加载的策略
与扫描核心 SHA-256。全部文件在扫描期间保持只读共享句柄，并核对实际句柄路径及前后目录清单；
任一不完整读取或集合变化均拒绝。报告中的 `matched_views` 是命中的解码窗口数，重叠窗口可能
重复计数，不表示原始字节中的独立出现次数。命中文件名时 `path` 为 null，保留索引和内容哈希。

行为合同入口 `Build/Contracts/TestAvidScriptBinaryPrivacyContracts.ps1 -OutputRoot <外部证据目录>`
覆盖多编码、奇偶字节起点、跨块、并发写入/目录变更、ADS、junction、报告不覆盖和不泄漏。
集中验证通过 157/157 项断言；CLI 的干净输入返回 0，隐私命中返回非零。

对现有 `Source/ThirdParty/Wasmtime/installed/Win64/v45.0.0-avidscript.2` 的只读扫描完整覆盖
117 个文件、36,803,705 字节；`lib/wasmtime.dll` 与 `lib/wasmtime.lib` 命中私人路径规则，
以 `ASBP1006` 拒绝。最终本地报告 `current-wasmtime-privacy-final.json` SHA-256 为
`4a9309cc844f07d7b7ad5f3809a3f85845efb222a6cfc80ab12981eec15a338a`。
该证据确认既有 P65-D04 发布阻塞，不是功能回归；没有替换运行库或启用离线二进制发布 profile。

## D32.B 中性构建入口

`Build/BuildAvidScriptWasmtimePerformanceToolchain.ps1 -Mode Build -NeutralBuild` 使用
`Build/ReleaseEngineering/AvidScriptNeutralWasmtimeBuild.ps1` 管理路径和环境。必须显式选择用户
home 外的独立 `RepositoryRoot` 与全新空 `CacheRoot`；两者不允许包含彼此。安装目标必须不存在，
扫描命中、构建失败或并发发布均不能删除原有 install。此模式不提供覆盖已有运行库的操作。

构建拒绝继承的 Rust/native 编译参数、Cargo profile/target 覆写和祖先 Cargo 配置；使用独立
Cargo home、target、temp，按前缀长度排列并以 unit separator 分隔映射。固定 Rust 1.93 探针
实际编译 `file!()` 到 metadata 并检查虚拟前缀；Windows 后缀保留的分隔符不改变路径脱敏结论。
Cargo 显式 `--locked`，构建前后比较 `Cargo.lock`。实际发布副本通过完整扫描后才移动到新 install，
报告留在外部缓存 `reports`。现有导出及 managed receipt 校验仍单独执行。

环境恢复覆盖成功与异常退出，并保留变量原本“未定义”和“空字符串”的差别。行为合同
`Build/Contracts/TestAvidScriptNeutralWasmtimeBuildContracts.ps1 -OutputRoot <中性证据目录>`
已通过 42/42 断言，包含真实 Rust 探针和真实构建入口的失败恢复；原工具链 70 项合同也通过。
这些检查不替代完整 Wasmtime 重建、传递依赖许可证收集和新 DLL 的 UE 集成验收。

## D32.C 许可证与构建来源写集

本批由 `Build/ReleaseEngineering/AvidScriptWasmtimeNotices.ps1` 生成版本化声明清单，构建入口
在中性 CMake/Cargo 构建中捕获 JSON 产物消息，并在 managed receipt 与隐私扫描之前纳入 staging。
依据实际 `compiler-artifact` 包集合收集声明，不用整个 workspace 或仅根 LICENSE 代替构建依赖。
Cargo 的产物消息及版本化 metadata 格式见 [Cargo 外部工具协议](https://doc.rust-lang.org/cargo/reference/external-tools.html)。

合同：完整成功的构建消息、固定 C API features/profile、DLL/静态库/import library 与实际消息哈希
一致；每个包通过精确 manifest 路径取得 metadata，拒绝根外文件、链接和缺失声明。Registry 包
同时记录 Cargo checksum，workspace 包绑定锁定 Wasmtime 来源；保留原始 license expression、
真实声明文件字节与 SHA-256。Rust 标准库单独收录固定工具链的 `COPYRIGHT-library.html`。
公开清单只用稳定来源和相对路径，不复制本机构建路径。声明集合与 runtime 一起执行完整隐私扫描。

本批交付声明与来源证据，不自动宣称离线发布许可检查或 UE 集成已通过。集中合同覆盖集合缺失、
错误产物身份、包重复/路径逃逸、缺失许可证、内容篡改及成功清单；随后在全新中性构建中验证实际
94 个构建包及标准库声明，再进入新 DLL 的 Win64 集成。

收集器与构建入口现已实现，行为合同通过 27/27，原工具链合同 70 项与中性构建合同 42 项保持通过。
同一 runtime 的缓存重放产生 128 项全部 fresh 的 Cargo 产物；独立 `cargo tree --edges normal,build`
确认同样的 94 个包（25 个 workspace、69 个 crates.io 包），没有集合差异。Registry 声明文件与
原始 `.crate` 归档逐文件哈希比较，含空 tar 文件的身份处理；标准库收录真实版权 HTML。
探针副本生成的声明清单 SHA-256 为 `252878b6c5b44abe838f3c0eb5bab7241826fde06eef5ba61d4676e9b71bd425`。

该探针副本第一次隐私扫描以 `ASBP1004` 拒绝，原因未获进一步证实；未修改内容的随后扫描完整通过
176 文件、37,529,852 字节、0 命中，额外前后目录比较无差异。首份拒绝报告保留为本地诊断，不能
把它改写成通过。本批仍需全新中性构建从 Cargo 消息捕获、声明收集、receipt 到隐私扫描直接通过；
探针副本沿用了旧 receipt，因此不是可安装的完整候选。
