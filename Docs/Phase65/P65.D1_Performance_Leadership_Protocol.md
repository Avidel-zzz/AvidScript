# P65.D1 性能领导力协议冻结

## 目标

P65.D 不沿用“挑一项快的数据就宣布领先”的做法。正式结论必须同时绑定候选源码、UE5.8
可执行文件、CPU/操作系统、脚本运行时、workload 字节、warmup、样本数、统计口径和正确性
oracle。协议由
`Benchmarks/PuertsComparison/Leadership/Config/Phase65LeadershipProtocol.json` 统一描述，文本输入
使用换行无关的 `normalized_utf8_lf_sha256_v1` 固定身份。

## 冻结矩阵

| 矩阵 | 目的 | 规模 | 当前状态 |
|---|---|---:|---|
| `ue_micro_six_lane` | BeginPlay/Tick、纯计算、UFunction、property、FVector、UObject、ref/out、batch 等微观 UE 路径 | 5 进程 x 5 warmup x 30 sample，10 workload，6 lane | 已冻结 |
| `ue_gameplay_six_lane` | small/dense gameplay frame，比较 reflection、static、Adaptive、generated S1 与 data-oriented | 5 进程 x 5 warmup x 30 sample，2 workload，6 lane | 已冻结 |
| `identical_wasm_execution` | 排除语言前端和绑定差异，只比较 V8 与 Wasmtime 执行同一 WASM | 5 进程 x 5 warmup x 30 sample，12 kernel | 已冻结 |
| `angelscript_same_semantics` | 与 AngelScript 建立相同 UE 语义的玩法路径比较 | 尚未冻结 | 阻断完整领先声明 |

六 lane 协议是当前正式协议；旧 5-lane sidecar 仅保留兼容用途，不进入 P65.D 正式结论。
`native_cpp` 只用于定位绝对成本，不计入脚本框架胜负。Puerts 固定在提交
`1977328c84661024be10a9e73640a74b278a7659` 与 V8 `9.4.146.24`；AvidScript 固定使用
Wasmtime `45.0.0`、Cranelift speed 和 `x86-64-v3` compiler profile。任何 runtime、profile、
workload 或阈值变化都必须升级协议版本，不能覆盖本协议。

## 门禁

- correctness failure 必须为 `0`，且正式 lane 不允许 fallback。
- 同 WASM 执行层 P50/P95 几何均值必须不高于 Puerts V8 的 `0.95x`，kernel 胜率至少
  `60%`，MAD 几何均值不高于 `1.25x`。
- AvidScript Adaptive Semantic 对 Puerts Reflection 的冻结 UE shape 比例必须不高于
  `0.80x`。
- AngelScript dependency、UE5.8 build identity 和 adapter 未冻结前，只能发布
  “AvidScript vs Puerts”分轴结果，禁止发布“AvidScript 全面领先 Puerts 与 AngelScript”。

## 下一步

P65.D1b 候选冻结器只接受 clean Git worktree，并把 artifact 准备与候选冻结收敛为一个有界事务：

1. 原子装配并验证 lock 管理的 Wasmtime 安装内容；
2. 创建隔离 benchmark project，执行一次 Editor 构建并准备 Semantic、Generated S1、Data-oriented
   三类 C# artifact；
3. Generated S1 首次生成项目绑定模块时，只允许一次增量构建握手；
4. 如果生成模块改变了共享 `Source`，自动创建第二个正式项目并重新构建；两轮后仍漂移则失败关闭；
5. 在写入不可变 candidate manifest 前重新验证 Git、Source、Config、Puerts、Wasmtime 与 UE5.8
   executable 身份，并记录构建日志、artifact manifest/report SHA。

Profile 参数始终以 UE 内嵌引号传递，避免 `data-oriented` 中的连字符被 `FParse` 截断。候选
manifest schema v2 的三项 UE/WASM 矩阵只有完成构建和 artifact 准备后才标记为 `ready`；
随后先跑快速校准，再统一执行正式矩阵。
