## 候选目标

尝试进一步压缩 specialized prepared callback 的成功返回：C shim 只在真实失败时写 failure 输出，backend
以 call status 为权威，固定 0/1 cell 结果绕过通用 failure/count 检查和 `Memcpy`。generic prepared path、
trap、Host failure、reload lifetime 与 epoch watchdog 合同保持不变。

## 诊断结果

| Workload / lane | D22 diagnostic P50 | D23 diagnostic P50 | D22 / Puerts static | D23 / Puerts static |
| --- | ---: | ---: | ---: | ---: |
| callback_empty / generated S1 | `103.47 ns` | `105.27 ns` | `1.010x` | `1.020x` |
| callback_tick / generated S1 | `106.56 ns` | `111.02 ns` | `0.932x` | `0.967x` |

两个主要 workload 的同进程 P50 比值分别退化约 `0.95` 和 `3.48` 个百分点。P95 出现明显单进程噪声，
不足以推翻 P50 的一致方向，因此没有升级到正式 5 进程矩阵，也不把本次诊断写成性能结论。
