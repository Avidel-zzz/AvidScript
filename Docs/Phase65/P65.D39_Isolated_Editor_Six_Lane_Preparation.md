# P65.D39：隔离 Editor 六路径准备与诊断

## 结果与范围

在 D38 使用的隔离 UE5.8.0 引擎中，已生成 AvidScript 的 adaptive semantic、generated S1、data-oriented 三套 C# 产物，并完成生成绑定模块的增量编译。Native、Puerts reflection/static 与 AvidScript 三条路径均实际运行成功：10 个 micro workload 的 **300 个计时样本**、small/dense gameplay 的 **60 个计时样本**全部通过校验。

这是正式对照之前的诊断验证。使用仓库原有 Phase56 diagnostic profile，每套 1 个校准进程、1 个测量进程，每个 lane/workload 预热 1 次、计时 5 次；不能替代正式的 5 进程采样，也不关闭 P65.D。生产性能门禁仍为 **16/18**，Android/Mac 验收按用户要求暂缓。

## 构建与输入

- 生产插件取自固定提交 `8c032e9fd9f0afe23c3b18a15057aa7a90d8774c` 的离线发布包；每套诊断前复核安装清单中 **2,063 个文件**的原始 SHA-256。
- AS 适配器来自固定提交 `4a747c02d892845daaab25b866596e35113b5561`。原始 fixture、C# workload、AS 脚本和原生适配器通过既有预检，未修改工作负载以适应测试。
- generated S1 首次准备返回 `generated_binding_build_required` / exit 4；这是生成器要求编译新模块的握手，保留首次日志。导出的构建计划有 **5 个动作、15 个输出或替换路径**，均位于物理隔离工程内；随后 no-clean 构建退出 0，generated/data 两条路径准备成功。
- 三份 C# 报告均为 `succeeded=true`，没有错误诊断；产物 manifest/WASM、绑定包、实际 Editor、模块清单、生成绑定 DLL、JsEnv/Wasmtime DLL 与脚本身份被记录。
- 工程新增 `AvidScriptGeneratedBindings` 模块，因此 D38 的工程身份已改变。归档了仍匹配旧采样记录的 **59 个输入**，保留旧结果；正式比较必须在最终配置下重跑 AS，不能把历史 D38 结果直接当作本次环境的同步对照。
- 压缩本任务隔离目录中的归档、二进制与工具文件，恢复构建启动空间；未删除源码、运行库或旧证据，未修改共享主引擎。

## 验证

两套诊断各有两个成功退出的进程，均存在唯一的结果发布和 commandlet 完成标记。进程前后输入哈希稳定；请求和结果经过原有 JSON Schema 校验。

独立复核覆盖完整 lane/workload/sample 元组集合、唯一性、冻结迭代数、请求及 profile 身份、正计时、校验和、fixture 调用次数、Host import 调用次数，以及 generated fallback/reject 和 data buffer reject 为零。micro 为 300/300，gameplay 为 60/60。

原有 gameplay evaluator 返回 `validity.valid=true`、空错误列表。其整体性能结果仍为 false：16 项依赖本轮未提供的 supplemental evidence，保持 `not_measured`；两个 gameplay 门槛仅得到诊断结果。本节不据此发布性能领先声明。

原有 evaluator 直接接收 micro diagnostic profile 时因缺少 `gates` 字段退出，未生成通过证据；micro 的独立校验只证明本节列出的执行与样本合同。最早的 semantic 准备包装脚本还曾错误期待仅在失败时输出的返回码日志，导致原生退出 0 后被包装脚本标记失败；原始尝试保留，独立验证器依据唯一成功标记、退出码与 C# 报告确认准备成功，没有覆盖失败记录。

结构化身份、外置证据目录名与哈希见[结果记录](P65.D39_Isolated_Editor_Six_Lane_Preparation.json)。本轮诊断包装脚本保存在外置证据环境，尚未作为通用正式入口交付。
