# P65.D27 Wasm 表达式栈化候选归档

## 本节目标

验证 Guest IR 的单次使用标量临时值是否因 `local.set/local.get` 搬运造成 Wasmtime 执行差距。候选在
Wasm backend 增加块内 use-count 计划器，只把连续、无副作用、单次使用的标量 producer 树直接发射到
consumer 栈上，不跨 call、global、memory、分支或基本块。

`08ee404e942d61869336ec3f583e9c764598cccff0ac9a116bcb7c73fa647d6b`，证明候选确实进入冻结产物。

## 诊断结果

| Workload | D22 generated P50/P95 | D27 generated P50/P95 | D22 ratio | D27 ratio |
| --- | ---: | ---: | ---: | ---: |
| pure_integer | `1.932 / 2.055 ns` | `1.942 / 2.091 ns` | `1.995x / 2.098x` | `1.986x / 1.814x` |
| callback_empty | `103.47 / 110.39 ns` | `103.94 / 106.70 ns` | `1.010x / 1.004x` | `1.033x / 0.874x` |
| callback_tick | `106.56 / 109.17 ns` | `105.98 / 120.18 ns` | `0.932x / 0.845x` | `0.927x / 0.885x` |
| object_roundtrip | `37.75 / 38.47 ns` | `48.86 / 57.79 ns` | `1.046x / 1.056x` | `1.099x / 1.115x` |

`pure_integer` 的 generated P50/P95 绝对值分别增加约 `0.52% / 1.72%`，P50 没有改善。部分 P95
比值变化来自同轮 Puerts 尾延迟波动，不能当作 AvidScript 收益。object_roundtrip 的比值也明显恶化，
所以本节在 diagnostic 阶段直接拒绝。

## 结论

生成字节码减少局部搬运却没有降低执行时间，说明 Cranelift 已能在当前函数内处理这类 SSA/local 形态；
继续扩展自研栈化只会复制后端优化器职责。D27 不保留，P65-D03 继续开放，README 仍以 D22 为最新正式
基线。

下一批不再做函数内 peephole。先审计 Wasmtime compiler profile、循环 safepoint/epoch 配置和直接函数调用
代码形态，再决定是做 codegen 级叶函数调用融合，还是调整锁定的 Cranelift 优化配置；任何候选仍须先过
真实 packaged diagnostic。
