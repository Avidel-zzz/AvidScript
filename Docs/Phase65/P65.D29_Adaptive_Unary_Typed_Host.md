# P65.D29 Adaptive Unary Typed Host

## 本节目标

消除 adaptive semantic `int32 F(int32)` 在每次调用中重复支付的动态反射准备和通用 VM Host-call
分派成本，同时继续保持通用 UFunction descriptor、对象句柄校验和 fail-closed 回退边界。本节不新增
成员专用 API，也不关闭 Wasmtime containment。

## 已实现

- Binding 层新增可复用的 `FAvidScriptPreparedReflectionI32Call`，在解析阶段冻结 owner、函数和参数布局。
- VM 层新增固定 ABI `SelfI32ToGuestI32 (iiii)i`，由 Runtime 在 linker 阶段注册 typed host thunk。
- guest result 直接写回受校验的 WASM memory，不再为命中的 unary `int32` 调用创建动态参数容器。
- adaptive semantic 首次 revalidate 后复用 typed receiver；签名、对象代次或 owner 漂移仍按原合同拒绝或回退。
- gameplay fused oracle 与离线 Gate evaluator 统一按 `logical operations - vector operations` 计算 typed
  generated 命中，并在 data lane 额外扣除 command-buffered property write。

主要实现提交为 `3290da29`、`653f9537` 和 `199fa2f9`；离线 Gate 计数同步提交为
`8fa891a1`。最终二进制候选 commit/tree 为
`199fa2f92ba004a9fdd5470f6278d31eb1c2c3ac` /
`fe96068222803d051e5ada0416de66cb2eefe9b3`。

| `scalar_add_int32` adaptive semantic / Puerts reflection | `82.919 ns` | `112.319 ns` | **`0.738x`** |
| `scalar_noop` generated S1 / Puerts static | `27.567 ns` | `32.021 ns` | **`0.861x`** |

`vector_ref_out` 使用 prepared dynamic/ProcessEvent 路径，因此不能宣称所有 semantic 签名都已 typed 化。

## 尚未通过

统一 `18` 项 Gate 当前通过 `14` 项，以下 `4` 项仍失败：

| Gate | 当前值 | 目标 |
| --- | ---: | ---: |
| Wasmtime/V8 12-kernel P95 几何均值 | `1.131x` | `<= 0.95x` |
| 12-kernel P95 胜率 | `33.3%` | `>= 60%` |
| generated scalar 上限 | `28.111 ns` | `<= 25 ns` |
| generated property 上限 | `51.837 ns` | `<= 50 ns` |

controlled suite 的主要差距集中在 `scalar_float 2.096x`、`simd128 1.334x`、
`mixed_gameplay 1.329x` 和 `data_branch 1.137x`；serial integer、random/sequential memory 与 hashing
已经接近或领先 V8。下一批不再继续堆叠 UFunction 特例，而是优先分析 Cranelift scalar-float/SIMD
代码形态，以及把 generated scalar/property 压过绝对时延门禁。

## 结论

D29 保留。它让 adaptive semantic 从 D28 packaged formal 的主要落后项转为当前 Editor formal 中相对
Puerts reflection 的稳定领先路径，并证明 typed host ABI 可以由通用 descriptor 和 signature family 驱动。
P65-D03 仍保持开放：执行层总体、generated scalar/property 绝对时延和 AngelScript 同语义矩阵尚未全部关闭。
