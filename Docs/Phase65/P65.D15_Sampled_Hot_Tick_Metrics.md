# P65.D15 热 Tick 指标采样

## 本节目标

消除 `TickHot` 成功路径中每次 Guest callback 都读取两次高精度时钟的固定成本，同时保留完整调用语义、
失败诊断与执行预算。该优化作用于所有热 Tick，不识别 benchmark workload，也不关闭 fuel、epoch timeout、
Host-call budget 或线性内存限制。

## 已实现

- `TickHot` 与现有热事件路径统一使用 `1/256` 指标采样；首次调用及之后每 256 次成功 Tick 更新一次
  `TickCallMs`。
- 非热调用继续逐次测量，公开 `Tick` 的观测语义不变。
- 热路径未命中采样时不读取 `FPlatformTime::Seconds()`，也不覆盖上一次有效的 Tick 指标。
- trap、非法生命周期和定时器失败仍通过原有 failure-only 路径物化完整错误；Wasmtime entry containment
  与 watchdog 生命周期没有变化。

## 正式结果

每个 lane/workload 使用 5 个独立进程、每进程 5 次预热和 30 次计时。P50/P95 先取进程内
nearest-rank，再取 5 个进程结果的 nearest-rank P50。

| Workload / lane | D14 P50 | D15 P50 | D15 P95 | P50 变化 |
| --- | ---: | ---: | ---: | ---: |
| callback_empty / generated S1 | `144.83 ns` | `144.29 ns` | `153.41 ns` | `-0.4%` |
| callback_empty / adaptive semantic | `142.78 ns` | `145.56 ns` | `153.31 ns` | `+1.9%` |
| callback_empty / data-oriented | `142.69 ns` | `143.11 ns` | `153.21 ns` | `+0.3%` |
| callback_tick / generated S1 | `206.88 ns` | **`174.10 ns`** | **`183.41 ns`** | **`-15.8%`** |
| callback_tick / adaptive semantic | `205.60 ns` | **`172.27 ns`** | **`180.04 ns`** | **`-16.2%`** |
| callback_tick / data-oriented | `207.50 ns` | **`172.65 ns`** | **`181.96 ns`** | **`-16.8%`** |

本轮 Puerts static 的 callback_empty/tick P50 为 `114.73 ns / 130.83 ns`。Generated S1 对应
比率从 D14 的 `1.270x / 1.552x` 收敛为 **`1.258x / 1.331x`**；callback 单项仍未领先。
十项 UE micro 的 generated S1 P50/P95 几何均值由 `0.766x / 0.765x` 改善到
**`0.751x / 0.752x`**，data-oriented 为 **`0.753x / 0.755x`**，两者均保持 `6/10` 胜项。
其余八项 generated workload 相对 D14 的最大 P50/P95 回退为 `1.05% / 1.55%`，低于 `3%`
守门线。

## 当前结论

逐次时钟读取是 Tick callback 的显著固定成本，采样后 generated S1 的 P50/P95 分别下降
`15.85% / 15.64%`，且收益没有以其他 micro 的明显回退换取。P65-D03 仍保持未验证：十项聚合领先
不能扩写为 callback、纯执行层或 AngelScript 同语义全面领先。
