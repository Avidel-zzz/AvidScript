# P65.D9 按需 Fuel 编译配置

## 目标与边界

Wasmtime 的 fuel 是确定性的指令预算，但开启 `consume_fuel` 会在生成代码中加入计数。此前即使
`FuelPerEntry == 0`，纯执行基准仍使用带 fuel 插桩的 Cranelift profile。本批把 compiler profile
选择绑定到真实执行合同，而不是绑定到 benchmark 开关：

- 原始 WASM 且 `FuelPerEntry == 0`：使用
  `cranelift-speed-x86_64-v3-fuel-free-v1`；
- 配置了 fuel 预算：继续使用 `cranelift-speed-x86_64-v3-contained-v3`；
- Wasmtime serialized 产物：无论调用配置是否设置 fuel，始终使用严格 profile，确保与生产编译器
  identity 和序列化配置一致；
- 两个 profile 都保留 epoch interruption、2 MiB WASM 栈、固定 4 GiB wasm32 reservation、
  Spectre mitigation、Host-call 与线性内存边界；fuel-free 不等于关闭全部 containment。

toolchain lock、JSON Schema、C++ runtime identity、PowerShell sidecar、Phase 65 protocol 和候选 manifest
现在共同记录两种 profile。身份不匹配会在计时前失败关闭。

workload 的热循环生成质量做反汇编与 perf-counter 归因，而不是继续删除通用安全边界。
