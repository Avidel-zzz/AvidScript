# Phase 65.D30：配置特化的 Typed Host 热路径

## 目标

在不削弱 ObjectHandle、生成绑定租约、同回调对象失效检测和执行预算语义的前提下，关闭最新正式门禁中的两个绝对性能缺口：

- `scalar_add_int32` generated S1 P50：`28.111 ns`，目标不高于 `25 ns`。
- `property_get_set` generated S1 P50：`51.837 ns`，目标不高于 `50 ns`。

当前相对性能已经领先 Puerts static，分别为 `0.796x` 和约 `0.713x`；本批次处理的是绝对时延，而不是放宽门禁。

## 热路径判断

一次 prepared generated 调用当前依次经过 Wasmtime C trampoline、VM typed callback、执行预算消费、Runtime prepared dispatch 和生成 thunk。默认配置的 `MaxHostCallsPerEntry` 为 `0`，表示不限制 host call；但每次调用仍进入预算函数并读取 Backend 配置。

## 架构冻结

1. 在 typed import 装载时根据执行预算选择回调，而不是在每次调用时解释配置。
2. 仅对已有 prepared target 且 host-call 预算无限的 `SelfI32`、`PropertyI32Get`、`PropertyI32Set` 使用无计量特化回调。
3. 预算非零、target 未 prepared 或需要 semantic fallback 的 import 保持原回调和错误分类。
4. Runtime 侧的租约校验、callback/reload epoch、registry revision、`IsValid` 和 effect policy 全部保留。
5. 不新增成员专用 API；优化单位仍是生成绑定 shape。

## 分批验收

- D30.A：实现装载期回调特化和 focused contract。
- D30.B：用短样本判断方向；有效后再进入统一正式构建与门禁。
- D30.C：若仍未达标，再评估只在无限预算配置启用的 direct bridge，失败路径仍回到 Backend 生成稳定诊断。

性能数据只有在独立进程、固定样本和完整正确性计数通过后才能更新 README。
