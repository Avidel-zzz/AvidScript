# P65.D28 已验证包 Fuel-Free Artifact

## 本节目标

让正式游戏包中的 Wasmtime AOT artifact 按真实 Session 安全合同生成机器码。此前 verified package 已使用
terminal epoch watchdog、Host-call 上限关闭和签名 package 校验，但序列化模块仍固定启用 fuel 插桩；即使
`FuelPerEntry == 0`，热循环也会持续支付 fuel 计数成本。

## 已实现

- `FAvidScriptVmArtifactCompileRequest` 显式携带 `bConsumeFuel`，artifact cache key 继续由完整 compiler
  identity 隔离 strict 与 fuel-free 产物。
- Editor package publisher 为 verified packaged artifact 请求
  `cranelift-speed-x86_64-v3-fuel-free-v1`；JIT 和默认编译请求保持 strict profile。
- 运行时不解析 identity 片段，而是分别构造受支持 profile 的完整 identity，并以精确相等选择反序列化引擎。
- 旧的 `fuel=on` serialized artifact 仍可加载；fuel-free artifact 若搭配非零 `FuelPerEntry`，以
  `artifact_budget_mismatch` fail-closed。
- epoch interruption、100 ms watchdog、固定 4 GiB wasm32 reservation、2 MiB WASM 栈、Spectre
  mitigation、Host-call 与 package trust 边界均未关闭。

实现提交为 `9c7996f4d008b84eff795c6363d0ff72adca3b9a`，benchmark published-package provenance
修正提交为 `518e03fc4042c7db1ebe058f605282bd58024f8c`。

## 结论与下一步

D28 保留。它证明 verified packaged artifact 不应为未启用的 fuel 预算支付持续机器码成本，并让 generated
与 data-oriented lane 在真实游戏包十项矩阵上形成稳定总体领先。

P65-D03 仍保持开放：`pure_integer` 和 generated `callback_empty` 尚未同时领先，adaptive semantic lane
的十项几何均值仍为 `1.472x / 1.483x`。下一批应把主要精力转向 semantic dispatch 的一次解析、多次复用
与 pure integer 的 Cranelift 循环代码形态，不再继续删除通用 containment 边界。
