# P2.0 Binding And Hot Reload Scope

日期: 2026-07-01
状态: Done
范围: Phase 2 设计切分 / P2.1-P2.5 验收口径

## 1. Phase 2 目标

Phase 2 验证 AvidScript 的 UE binding 与 editor iteration 底座, 对应白皮书中的 E2 UObject Handle ABI 与 E3 Hot Reload State Migration。

本阶段不实现完整语言、完整 binding generator、C# guest toolchain 或生产级 asset pipeline。Phase 2 的目标是把以下硬门槛变成可自动化验证的插件行为:

- guest 不接触 raw `UObject*`。
- UObject 只通过 host-owned handle registry 暴露。
- invalid / stale / generation mismatch handle fail closed。
- 最小 Actor read/write host API 有明确 authority policy。
- 最小 script component 可以承载 runtime instance 与 owner handle。
- reload 先 staging validate, 再切换 live entrypoint; 失败时 rollback。

## 3. P2.1 设计

P2.1 先实现纯 C++/UE 可测 registry, 暂不接入 WASM import。理由:

- handle ABI 是后续 host call、脚本组件、reload 安全的共同底座。
- 不先绑定 WASM 可以更快覆盖 UE object lifetime 与 generation 语义。
- P2.2 再把 registry 接进 host binding API, 避免第一步同时调试 WAMR import 和 UObject lifetime。

### Handle 格式

```text
FAvidScriptObjectHandle
  uint32 Slot
  uint32 Generation
```

`Slot == 0` 或 `Generation == 0` 视为 invalid handle。registry 不暴露 raw pointer 或 pointer-sized address 给 guest。

### Registry 规则

- `RegisterObject(UObject*)` 为有效对象分配 handle。
- `ResolveObject<T>(Handle, Result)` 只在 slot/generation 匹配且 weak object 仍有效时返回对象。
- `ReleaseHandle(Handle)` 释放 slot 并递增 generation, 阻止旧 handle 命中新对象。
- `Reset()` 清空所有 slot, 并推进 generation domain。
- 所有失败路径返回 `FAvidScriptObjectHandleResult`, 包含 `ErrorCategory`、`NextAction`、`ErrorMessage`。

## 4. 后续约束

- P2.2 的 host API 必须复用 P2.1 registry, 不单独保存 raw actor pointer。
- P2.3 的 component 只能持有 handle 和 host runtime 对象, 不把 guest 状态藏在 UObject raw pointer 中。
- P2.4 reload 必须以 manifest/ABI validation 为边界, 不做 best-effort live patch。
