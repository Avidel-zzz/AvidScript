# P2.4 Reload Manifest Staging Rollback

日期: 2026-07-02
状态: Done

## 1. 目标

P2.4 建立 AvidScript 热重载的最小安全语义: 新脚本模块不能直接替换 live runtime, 必须先进入 staging runtime 完成 manifest 与 ABI/export 校验, 通过后再原子切换 live runtime; 失败时保留旧 runtime。

本阶段不实现文件监听、Editor UI、asset pipeline、C# guest 编译器或状态迁移 schema。目标是把后续热重载系统最容易出事故的核心边界变成 automation 可验证行为:

- compatible reload 成功切换 live module。
- ABI version mismatch 拒绝切换, live runtime 不变。
- required export 缺失拒绝切换, live runtime 不变。
- rejected reload 后旧 runtime 仍可继续 tick。
- reload 计数和失败诊断可被测试和后续 tooling 读取。

## 2. 实现内容

新增 `FAvidScriptWasmReloadManifest`:

- `SupportedAbiVersion = 1`。
- `ModuleId` 标识候选模块。
- `AbiVersion` 作为 host/guest ABI 兼容边界。
- `RequiredExports` 定义激活前必须存在的 guest exports。
- `MakeSmoke()` 生成当前 smoke ABI: `avid_on_begin_play` + `avid_on_tick`。

新增 `FAvidScriptWasmReloadResult`:

- 记录 `PreviousModuleId`、`CandidateModuleId`、`ActiveModuleId`。
- 记录 `bReloadApplied`、`bRollbackPreservedLiveRuntime`。
- 复用 runtime 的 `ErrorCategory`、`ExportName`、`NextAction`、`ErrorMessage` 诊断模型。
- 保留底层 `FAvidScriptWasmSmokeResult RuntimeResult`。

新增 `FAvidScriptWasmReloadSession`:

- `LoadInitialModule()` 构建第一份 live runtime, 不计入 reload 次数。
- `ReloadModule()` 先构建 staging runtime, 再切换 `LiveRuntime`。
- `TickLive()` 只驱动当前 live runtime。
- `GetSuccessfulReloadCount()` / `GetRejectedReloadCount()` 为后续 Editor tooling 提供观测点。

`FAvidScriptWasmRuntimeInstance` 新增 `ValidateRequiredExports()`:

- 在 runtime 已 load/instantiate/exec env 创建后, 逐项通过 WAMR `wasm_runtime_lookup_function` 检查 required exports。
- 缺失 export 返回 `missing_export`, 并保持结构化错误信息。
- 后端不可用、runtime 未加载等路径继续 fail closed。

## 3. Reload 流程

```text
ReloadModule(candidate bytecode, manifest)
  1. Validate manifest
     - ModuleId non-empty
     - AbiVersion == SupportedAbiVersion
     - RequiredExports non-empty
  2. Build staging runtime
     - LoadModule(candidate)
     - ValidateRequiredExports(manifest.RequiredExports)
     - BeginPlay(staging)
  3. Success
     - LiveRuntime = staging
     - LiveManifest = manifest
     - SuccessfulReloadCount++
  4. Failure
     - Destroy staging runtime
     - ActiveModuleId remains previous live module
     - RejectedReloadCount++
     - bRollbackPreservedLiveRuntime = true when a previous live runtime exists
```

这个阶段刻意没有做 best-effort live patch。后续要做状态迁移时, 也必须在 staging validation 通过之后, 再进入显式 migration schema, 不能把部分初始化失败的候选 runtime 暴露给 live gameplay。

## 4. 测试内容

新增 `AvidScript.Reload` automation:

- `CompatibleSmoke`: 初始加载 `reload_v1`, tick 一次; compatible reload 到 `reload_v2`; 验证 active module 切换、successful reload 计数为 1, 且新 live runtime tick count 从 1 开始。
- `MissingExportRollbackSmoke`: 初始加载 `reload_v1`, reload 一个缺少 `avid_on_tick` 的 candidate; 验证返回 `missing_export`, active module 仍为 `reload_v1`, rejected reload 计数为 1, 旧 runtime tick count 继续增长。
- `AbiMismatchRollbackSmoke`: 初始加载 `reload_v1`, reload 一个 ABI version 高于 host 支持版本的 candidate; 验证返回 `abi_mismatch`, active module 仍为 `reload_v1`, rejected reload 计数为 1, 旧 runtime 仍可 tick。

## 8. 剩余风险

- 还没有状态迁移 schema, 当前 reload 会替换 runtime, 不迁移 guest state。
- 还没有文件 watcher 或 Editor reload 按钮, 只能通过 C++ session API 和 automation 触发。
- 还没有 guest module 元数据文件格式, manifest 目前由 host C++ 构造。
- 移动端未验证; 当前验证仍是 Win64 Editor PC-first 路径。
