# P2.3 AvidScript Component

日期: 2026-07-02
状态: Done

## 1. 目标

P2.3 在 P2.1 UObject handle registry 和 P2.2 Actor host binding 之上建立最小 `UAvidScriptComponent`。

本阶段目标不是把 Actor API 直接注册进 WASM import table, 而是先把脚本组件的 UE 生命周期做成可测试行为:

- component 挂到 Actor 后, `BeginPlay` 注册 Owner Actor handle。
- component 持有独立 object registry, owner handle 不暴露 raw `UObject*`。
- component 在 `BeginPlay` 加载并启动内置 smoke WASM runtime。
- component `TickComponent` 调用 `avid_on_tick`。
- component `EndPlay` unload runtime 并 release owner handle。
- component 暴露只读 runtime stats, 供 automation 与后续 editor tooling 观测。

## 2. 实现内容

新增 `UAvidScriptComponent`:

- `FAvidScriptComponentRuntimeStats` 记录 owner 注册/释放、runtime load、begin/tick/end、owner handle、owner path、错误信息和 runtime metrics。
- `ResolveOwnerActor` 通过 `FAvidScriptObjectRegistry::ResolveObject<AActor>` 验证 owner handle, 不返回裸 registry 或裸 slot。
- `BeginPlay` 先注册 owner, 再加载内置 smoke module 并调用 `BeginPlay`。
- `TickComponent` 仅在 play active 且 runtime loaded 时驱动 WASM tick。
- `EndPlay` 按 runtime unload -> owner handle release -> stats 标记的顺序清理。

`AvidScriptRuntime.Build.cs` 将 `Engine` 调整为 public dependency, 因为 public header 暴露 `UActorComponent`。

## 3. 测试内容

新增 `AvidScript.Component` automation:

- `OwnerHandleLifecycleSmoke`: 验证 BeginPlay 注册 owner handle, active 时可 resolve, EndPlay 后 handle 释放且旧 handle 不再 resolve。
- `RuntimeTickSmoke`: 验证 component BeginPlay 加载 smoke runtime, 调用 `avid_on_begin_play`, world tick 后调用 `avid_on_tick`, EndPlay 后 runtime unload。

测试夹具最终采用: 先让 synthetic PIE world `BeginPlay`, 再 `SpawnActor` 并动态注册 component。UE 源码路径显示 runtime actor spawn 会在 `World->HasBegunPlay()` 时走 `PostActorConstruction -> DispatchBeginPlay`, component 注册会走 `HandleRegisterComponentWithWorld`, 这样能触发组件真实生命周期。

## 5. 调试结论

首次 `AvidScript.Component` automation 失败不是 production component 逻辑问题, 而是测试夹具问题: synthetic PIE world 的 `World->BeginPlay()` 触发了 world subsystem, 但没有把已经手工创建的测试 actor/component 路由到 `AActor::BeginPlay()` / `UActorComponent::BeginPlay()`。因此组件 stats 保持默认值。

修正方式是让 world 先 BeginPlay, 再动态 spawn actor 并注册 component, 复用 UE runtime 中动态 actor/component 的真实生命周期路径。修正后同一组测试通过。

## 6. 流程事故记录

P2.3 实现期间曾误用:

```powershell
Build.bat ... -Clean
```

本意是让 UBT 重新扫描新增 plugin source file, 但该命令清理了整个 `AvidTPSTemplateEditor` target, 删除了 `UnrealEditor-Cmd.exe` 和项目 target receipt, 导致后续 automation 需要完整恢复构建。

防错规则已经写入 `Plugins/AvidScript/AGENTS.md`:

- 不得为了刷新新增插件 `.cpp`/`.h` 使用 `Build.bat -Clean`。
- 日常 AvidScript C++ 验证优先使用 `-Module=AvidScriptRuntime`。
- 更大范围 rebuild 必须先获得用户明确授权。
- 在 Codex managed sandbox 中, `Build.bat` 可能需要写入 `C:\UnrealEngine\Engine\Intermediate\Build`; 若非提升权限运行时出现 `UnrealBuildTool failed to check dependencies`, 不改代码, 原命令改用引擎构建权限重跑。
