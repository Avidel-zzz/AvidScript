## 1. Phase 2 结论

Phase 2 已把 AvidScript 的 UE binding 与 editor iteration 底座推进到可自动化验证的状态。当前成果不是完整脚本语言, 也不是生产级 hot reload pipeline, 但已经验证了后续语言层必须依赖的四个核心边界:

- guest-facing UObject 访问必须通过 host-owned handle, 不暴露 raw `UObject*`。
- Actor host API 可以通过 handle 做最小 read/write, 并通过 write policy fail closed。
- `UAvidScriptComponent` 可以在真实 UE 生命周期中注册 owner handle, 驱动 WAMR runtime tick, 并在 EndPlay 清理。
- reload 可以通过 manifest + staging runtime 验证后再切换 live runtime, 失败时保留旧 runtime。

Phase 2 仍保持 WASM-first、WAMR-first feasibility、C#-friendly guest tooling、PC-first/mobile-aware 的方向。

## 3. 当前可实现能力

### UObject Handle ABI 底座

- `FAvidScriptObjectHandle` 使用 `uint32 Slot + uint32 Generation`。
- invalid handle、slot 越界、generation mismatch、released slot、weak object invalidation 都会 fail closed。
- `ResolveObject<T>` 会执行 UE 类型校验, type mismatch 不返回对象。
- handle 可以转为 `uint64`, 适合后续通过 WASM ABI 传递。

### 最小 Actor Host Binding

- 可以通过 handle 读取 Actor location。
- 可以在 `EAvidScriptActorWritePolicy::AllowWrites` 下写入 Actor location。
- `ReadOnly` 下写入返回 `write_denied`。
- 所有失败路径都返回结构化 `ErrorCategory` / `NextAction` / `ErrorMessage`。

### 最小 Script Component

- `UAvidScriptComponent` 可作为 Blueprint spawnable component 加到 Actor。
- BeginPlay 注册 owner handle 并加载内置 smoke WASM module。
- TickComponent 调用 `avid_on_tick`。
- EndPlay unload runtime 并 release owner handle。
- `FAvidScriptComponentRuntimeStats` 提供 owner/runtime/tick/metrics 观测数据。

### Reload Staging And Rollback

- `FAvidScriptWasmReloadManifest` 固定当前 `SupportedAbiVersion = 1`。
- `RequiredExports` 在候选模块激活前逐项验证。
- compatible reload 会替换 live runtime。
- ABI mismatch 或 required export 缺失会拒绝切换并保留旧 runtime。
- rejected reload 后旧 runtime 可继续 tick。

## 7. 已记录的流程规则

- 不使用 `Build.bat -Clean` 刷新插件新增 `.cpp` / `.h`。
- 日常 C++ 迭代优先使用 `-NoUBTMakefiles -Module=AvidScriptRuntime`。
- Codex sandbox 下 `Build.bat` 写 `C:\UnrealEngine` 失败时, 使用同命令提升权限重跑, 不改代码。
- `apply_patch` Windows helper 失败时, 可受控 PowerShell 写入, 但必须立刻 `git diff` 和验证。
- PowerShell 写 Markdown 时, 包含反引号的内容必须使用单引号 here-string 或 line array, 避免反引号被当作转义字符。
