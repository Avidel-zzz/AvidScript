# P2.2 Actor Host Binding API

日期: 2026-07-02
状态: Done
范围: Actor handle binding / location read-write / write policy / structured errors

## 1. 目标

P2.2 的目标是在 P2.1 `FAvidScriptObjectRegistry` 之上实现第一组 UE host binding API。guest 仍然只能传入 host-owned handle, host 每次调用时通过 registry resolve `AActor`, 不缓存 raw Actor pointer。

本小组暂不接入 WASM import table, 先把 C++ host-side binding 行为固定为 automation 可测路径。后续 P2.3 的 `UAvidScriptComponent` 和 P2.4 reload 才会继续接入生命周期和热重载。

## 2. 实现内容

新增 `EAvidScriptActorWritePolicy`:

| 值 | 含义 |
| --- | --- |
| `ReadOnly` | 默认只读, 拒绝 Actor 位置写入。 |
| `AllowWrites` | host 已授权本次调用可以修改 Actor transform。 |

新增 `FAvidScriptActorBindingResult`:

| 字段 | 含义 |
| --- | --- |
| `bSucceeded` | host binding 调用是否成功。 |
| `Handle` | 输入或解析后的对象 handle。 |
| `ObjectPath` | 成功或失败路径的 UObject path。 |
| `ErrorCategory` | 结构化失败分类。 |
| `NextAction` | host/guest 后续处理建议。 |
| `ErrorMessage` | 可写入 UE log 的完整错误信息。 |
| `Location` | 成功读写后的 Actor location, 或 movement_failed 时的实际位置。 |
| `ObjectResult` | 底层 registry resolve 的结果快照。 |

新增 `FAvidScriptActorBinding`:

| API | 行为 |
| --- | --- |
| `GetActorLocation(Registry, Handle, OutLocation, OutResult)` | 通过 registry resolve `AActor`, 成功后返回 `Actor->GetActorLocation()`。 |
| `SetActorLocation(Registry, Handle, Location, WritePolicy, OutResult)` | 通过 registry resolve `AActor`; `ReadOnly` 返回 `write_denied`; `AllowWrites` 才调用 `Actor->SetActorLocation()`。 |

失败分类:

| 分类 | 触发条件 |
| --- | --- |
| `invalid_handle` | 输入 handle 无效或不属于 active registry。 |
| `type_mismatch` | handle 指向非 Actor UObject。 |
| `write_denied` | 写入请求没有显式 `AllowWrites` policy。 |
| `movement_failed` | host 尝试移动 Actor 后实际 location 未达到目标值。 |

## 3. 测试覆盖

新增 automation suite:

```text
AvidScript.Binding.ActorBinding
```

测试用例:

| 测试 | 覆盖点 |
| --- | --- |
| `LocationReadWriteSmoke` | 通过 Actor handle 读取 location; 在 `AllowWrites` policy 下写入 location; 写入后 Actor 实际位置匹配目标。 |
| `WritePolicySmoke` | 在 `ReadOnly` policy 下拒绝写入, 返回 `write_denied`, Actor location 保持不变。 |
| `InvalidHandleSmoke` | invalid handle 返回 `invalid_handle`; 非 Actor UObject handle 返回 `type_mismatch`。 |

测试类型更新:

- `UAvidScriptObjectRegistryTestObject`: 继续用于非 Actor UObject handle。
- `AAvidScriptActorBindingTestActor`: 新增带 `USceneComponent` root 的测试 Actor, 用于真实验证 location 读写。

## 4. TDD / 调试记录

### RED

先写 `AvidScript.Binding.ActorBinding` 3 个测试, 不实现 `AvidScriptActorBinding.h`。UE5.8 build 失败于预期缺失头文件:

```text
fatal error C1083: cannot open include file: 'AvidScriptActorBinding.h'
```

### GREEN

实现 `FAvidScriptActorBinding` 后, 首次普通 build 出现链接错误:

```text
LNK2019 unresolved external symbol FAvidScriptActorBinding::GetActorLocation
LNK2019 unresolved external symbol FAvidScriptActorBinding::SetActorLocation
```

根因: 新增 `AvidScriptActorBinding.cpp` 后 UBT 仍使用旧 makefile, 没把新 cpp 纳入模块编译。使用 `-NoUBTMakefiles` 强制重扫后, UBT 输出 `Invalidating makefile ... (source file added)`, 构建通过。

首次 automation 运行时测试 world fixture 调用了 `InitializeNewWorld()`, 触发重复生成 `WorldSettings` fatal:

```text
Cannot generate unique name for 'WorldSettings' in level ... AvidScriptActorBindingWorld:PersistentLevel
```

根因: `UWorld::CreateWorld()` 已经创建 persistent level/world settings, 当前测试不需要 `InitializeNewWorld()`。删除该调用后 fatal 消失。

第二次 automation 使用裸 `AActor` 验证移动, 读写结果停在 zero。根因: 裸 `AActor` 没有 root component, `SetActorLocation()` 不能验证真实位移。新增带 `USceneComponent` root 的 `AAvidScriptActorBindingTestActor` 后, ActorBinding 3 项测试全部通过。

## 6. 当前结论

P2.2 已完成最小 Actor host binding API:

1. Actor read/write 只通过 P2.1 handle registry resolve, 不暴露 raw Actor pointer。
2. `ReadOnly` 默认拒绝写入, `AllowWrites` 才允许修改 location。
3. invalid handle、wrong UObject type、denied write 都返回结构化错误分类。
4. P2.1 ObjectRegistry 回归和 Phase 1 Runtime 回归均通过。

## 7. 未覆盖项与下一步

P2.2 不覆盖以下内容:

- WASM import table 中的 Actor binding ABI。
- 网络 authority、server/client ownership 和 replication policy。
- Blueprint-exposed binding generator。
- 多 world registry ownership。
- `UAvidScriptComponent` 生命周期接入。

下一步进入 P2.3: 最小 `UAvidScriptComponent`, 在 BeginPlay 注册 owner handle, Tick 调用 runtime, EndPlay 清理。
