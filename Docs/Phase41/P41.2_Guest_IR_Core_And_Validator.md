# P41.2 Guest IR Core、Serializer 与 Validator

## 完成内容

P41.2 建立了独立的 `AvidScript.GuestIr` 模块，固定首版 `schema_version=1`、`ir_version=1.0`。该模块不引用 Roslyn、C# semantic 实现、UE、WAMR 或 PowerShell，只描述所有语言前端都可以生成、所有 WASM backend 都可以消费的语言无关中间表示。

当前模块提供：

- immutable record 数据模型；
- typed register CFG 与显式 terminator；
- type、value、block、call、import/export 与 provenance 校验；
- UTF-8、snake_case、LF 结尾的确定性 JSON；
- 反序列化 round-trip；
- 校验成功后才执行的同目录临时文件写入与原子替换。

## IR v1 契约

`GuestModule` 顶层保存 schema/IR 版本、module/language、三段输入 hash、semantic schema/version、成功状态，以及 type/import/global/function/export/diagnostic 集合。

函数使用以下稳定形态：

- 参数和 local 都是带 `type_id` 的 register；
- basic block 按 ID 建图；
- instruction 只引用已声明 value；
- control flow 只由 `branch`、`branch_if`、`return`、`trap` terminator 表示；
- `call` 目标只能是已声明 import 或 function，并逐参数验证签名；
- 非 void 返回值必须有类型匹配的 result register；
- void 语义来自 type 的 `kind=void`，不依赖某个前端约定的 type ID。

首批 instruction 为 `constant`、`copy`、`binary`、`convert` 和 `call`。未知 opcode 不会被静默跳过，而是以稳定诊断失败关闭。后续 lowering/backend 扩展 opcode 时，必须同步扩展模型、validator 与测试。

## Validator 诊断

| 诊断码 | 含义 |
| --- | --- |
| `ASIR1001` | header、provenance 或必需对象图无效 |
| `ASIR1002` | type/import/global/function/register/block/field ID 为空或重复 |
| `ASIR1003` | 引用了未知 type |
| `ASIR1004` | 引用了未知 value |
| `ASIR1005` | entry 或 branch 引用了未知 block |
| `ASIR1006` | terminator 形态无效或不支持 |
| `ASIR1007` | export name 重复、为空或目标 function 不存在 |
| `ASIR1008` | instruction、constant、return 或基础 shape 类型不正确 |
| `ASIR1009` | import/call 元数据或签名不匹配 |
| `ASIR1010` | `succeeded` 与模块自身 diagnostics 不一致 |
| `ASIR1011` | opcode 不受当前 IR 版本支持 |

validator 会稳定排序诊断。空集合、非法常量文本和损坏引用都会返回诊断，不把 `NullReferenceException`、解析异常或后端错误当作正常控制流。

## 确定性与产物安全

`GuestIrSerializer` 固定属性顺序、snake_case 命名、UTF-8 编码、显式 null 和单个 LF 文件结尾。同一模块连续序列化、反序列化后再序列化必须得到逐字节相同的结果。

`GuestIrArtifactWriter` 在接触目标文件前运行完整 validator。成功后先在目标目录写入唯一临时文件并 flush 到磁盘，再替换正式产物；验证或写入失败时保留旧产物并清理临时文件。WASM backend 不应直接消费未经 validator 通过的对象。

## 验证结果

- Guest IR validation：13/13；
- serializer/writer：2/2；
- 合计：15/15；
- production 与 tests 项目分别通过 `dotnet format`；
- 确定性双序列化与 round-trip 字节比较通过；
- 非法 constant、类型错配、空集合、未知 type/value/block、错误 terminator、错误 call 与 export 均经过 RED/GREEN；
- 项目引用检查确认 Guest IR core 不依赖 Roslyn、UE 或 WAMR。

## 给 P41.3 的边界

P41.2 只检查 size、alignment、field offset 的基础合法性，不计算最终线性内存布局。P41.3 将在独立 `Layout` 子系统中实现 struct/enum/array/string/state/data/heap 的确定性布局、checked arithmetic、递归值类型拒绝和 bounds 规则，再把布局结果接回 validator。
