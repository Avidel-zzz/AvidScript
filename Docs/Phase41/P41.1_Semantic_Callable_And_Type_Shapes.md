# P41.1 Semantic Callable 与 Type Shape

## 完成内容

P41.1 将 semantic contract 从 schema v3 / semantic 1.3 升级为 schema v4 / semantic 1.4，新增两个供 Guest IR lowering 直接消费的稳定集合：

- `callables`：方法身份、containing type、返回类型、有序参数、`ref/out/in`、static/constructor/body、关联 property、import 与 export；
- `type_shapes`：array element type 与 enum underlying type。

这些数据都来自 Roslyn symbol/attribute API。后续 lowering 不需要解析 `SemanticSymbol.Signature` 字符串，也不需要重新读取 C# 源码判断 `DllImport` 或 `UnmanagedCallersOnly`。

## Callable 契约

每个 primary source callable 形成一个 `SemanticCallable`：

- `method_symbol_id` 使用 Phase 40 的 stable method identity；
- `containing_type_id`、`return_type_id` 和 parameter `type_id` 进入统一 type table；
- parameter 按 ordinal 排序，ref kind 映射为 `none/ref/out/in`；
- `has_body` 与 `SemanticExecutableBodyResolver` 共享事实来源；
- property/indexer accessor 通过 `associated_symbol_id` 关联原 symbol；
- `DllImport` 投影为 module/name import；
- `UnmanagedCallersOnly.EntryPoint` 投影为 export name。

ABI attribute 不按语法文本解析。空 import module/name 产生 `ASCS5001`，export 缺少非空 EntryPoint 产生 `ASCS5002`，重复 export name 产生 `ASCS5003`。这些错误会令 `succeeded=false` 并清空全部 CFG，避免 backend 消费半有效模块。

## Type shape

array canonical identity 现在递归使用 element canonical name，例如 `int[]` 稳定表示为 `type:int32[]`。array shape 保存 `element_type_id`；enum shape 保存 `enum_underlying_type_id`。P41.3 将仅依赖这些字段计算 element stride 与 enum storage，不猜测 display name。

## 真实样例结果

ActorLifecycle schema v4 / semantic 1.4 artifact：

| 指标 | 数量 |
| --- | ---: |
| types | 15 |
| symbols | 186 |
| callables | 52 |
| executable bodies / CFG | 38 / 38 |
| host imports | 14 |
| direct exports | 5 |
| diagnostics | 0 |

五个 direct export 是 BeginPlay、Tick、EndPlay、Timer 和 generic event；十四个 import 与现有 direct host ABI 一致。typed gameplay event dispatcher 仍由过渡 emitter 生成，P41.4/P41.6 必须通过稳定事件 descriptor 解决，不能按方法名硬编码。

## 给 P41.2 的输入

Guest IR core 可以把 callable 当作唯一函数签名与 ABI 来源，把 type shape 当作 array/enum layout 来源。P41.2 不依赖 Roslyn；它只定义语言无关模型与 validator，P41.4 再执行 C# lowering。
