# P41.5 确定性 WASM 后端

## 目标

P41.5 将已经通过 `GuestModuleValidator` 的 Guest IR v1 编译为可由 WAMR 2.4.4 加载和执行的 WASM 1.0 二进制。后端只依赖语言无关 Guest IR，不读取 C# 源码、Roslyn 模型或 UE Reflection，也不维护逐个 UE API 的手写映射。

本阶段完成的是正式编译后端，不是默认构建链切换。ActorLifecycle 从源码到 Guest IR 再到 WASM 的默认发布、manifest/report 四级 provenance 和完整 BeginPlay/Tick/EndPlay 回归属于 P41.6。

## 模块边界

- `Tools/AvidScript.WasmBackend/Encoding`：WASM 二进制 writer 与 canonical LEB128。
- `Tools/AvidScript.WasmBackend/Codegen`：module layout、函数 frame、通用 CFG dispatcher、内存访问与指令生成。
- `Tools/AvidScript.WasmBackend/Validation`：独立解析生成物，检查 section、import/export、code/data 和边界检查序列。
- `Tools/AvidScript.WasmBackend.Tests`：后端行为、确定性、失败关闭和内存安全测试。
- `Tests/Fixtures/WasmBackend`：由 Guest IR 生成并由 UE/WAMR 共同消费的可追踪 smoke fixture。

后端入口在编译前再次调用 Guest IR validator。无效 IR 返回 `ASWB1001`；当前不支持或无法生成的语义返回 `ASWB1002`，且不发布部分 WASM。

## WASM 生成能力

当前后端生成标准 WASM 1.0 magic/version，并支持：

- canonical unsigned/signed LEB32/LEB64；
- type signature 去重，以及稳定的 import/function index；
- type、import、function、memory、global、export、code、data section；
- 携带 Guest IR provenance 的确定性 custom section；
- `i32`、`i64`、`f32`、`f64` 类型映射；
- scalar 常量、copy、算术、比较、conversion、import call 与内部 call；
- `pc + loop` 通用 block dispatcher，覆盖 branch、branch_if、回边、return 与 trap；
- state/global initializer、data segment 与线性内存地址；
- struct field、address-of、stack allocation、local/indirect load/store 和结构体复制；
- memory struct 返回值的 caller-owned hidden `sret`；
- 显式 stack pointer、frame 上界检查和正常返回时恢复；存在 frame 的模块额外预留一个 WASM page 作为运行时栈余量；
- array load/store 的无符号 `index < length` 检查，地址计算前失败进入 `unreachable`。

初版 dispatcher 有意保持通用和可验证。后续结构化控制流、AOT 与更激进优化由 Phase 53 承担，不改变 Guest IR 契约。

## 数组安全规则

Guest IR 新增 `array_load` 与 `array_store`。validator 要求目标为 array，索引为 32 位 scalar/enum，元素类型与数组声明一致。后端必须先加载长度并完成无符号范围检查，再计算 payload 地址；越界不会绕回、截断或读取相邻线性内存。

独立 WAMR 验证结果：

- `guest_at(1)` 返回 `20`；
- `guest_at(2)` 触发 `Exception: unreachable`，进程退出码为 1。

## 验证结果

### .NET 测试

- `AvidScript.CSharpGuest.Tests`：14/14；
- `AvidScript.GuestIr.Tests`：31/31；
- `AvidScript.WasmBackend.Tests`：10/10。

测试覆盖 magic/version、canonical LEB、section 与 index、CFG/backedge、state/data、struct/pointer/sret、数组 bounds trap、malformed IR 拒绝和双编译确定性。

### 真实 ActorLifecycle

同一份 P41.4 ActorLifecycle Guest IR 连续编译两次：

- 每份 WASM 大小：8,849 字节；
- SHA-256：`a76cef5c06cbdcc4eb06020fe0cfed4ce29d3a7f69f38f8f89adbc0ef49ec75d`；
- 逐字节差异：0。

### WAMR 与 UE5.8

使用仓库内 vendored WAMR 2.4.4 构建的 `iwasm` interpreter 直接执行生成物：最小 `guest_value` 返回 `7`，数组正常访问和越界 trap 均符合预期。

UE5.8 源码版完成 `AvidScriptVM` 模块增量编译，未清理 Editor target。自动化测试 `AvidScript.Architecture.VM.GeneratedWasmBackendArtifactSmoke` 从插件 fixture 路径读取生成物，经正式 WAMR backend 完成 load、resolve、call 和 unload，结果为 Success。

## 当前边界

- P41.5 已证明正式后端能够生成和执行 WASM，但默认 ActorLifecycle 构建脚本仍未切换，属于 P41.6。
- 完整 ActorLifecycle 的 UE BeginPlay/Tick/EndPlay 端到端执行将在 P41.6 通过新构建链验证。
- Guest IR 当前整数类型主要按存储宽度表达；更细的 signedness 与数值类别元数据应继续集中演进，不能在 backend 中按类型名猜测。
- UE 类型和 API 的规模化 C# facade、proxy、descriptor 与 host stub 由 Phase 42 Reflection Binding Generator 生成，不在后端逐项硬编码。

## 下一步

P41.6 将把默认 ActorLifecycle 构建入口切换为 frontend -> semantic -> Guest IR -> WASM backend，发布四级 hash/provenance，删除失败构建的陈旧 manifest/WASM，并执行完整 Runtime、Editor 与 AvidScript automation 回归。
