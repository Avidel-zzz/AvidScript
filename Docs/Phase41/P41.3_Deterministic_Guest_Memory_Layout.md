# P41.3 确定性 Guest 线性内存布局

## 完成内容

P41.3 在 `AvidScript.GuestIr` 内增加了独立 Layout 子系统，并把最终布局写回正式 Guest IR artifact。`GuestModule` schema v1 现在包含 `memory_layout` 与 `data_segments`；WASM backend 不需要重新猜测 state offset、string/array header 或 heap 起点。

实现按职责拆分为：

- `GuestTypeLayoutResolver`：scalar、enum、struct、string、array、handle 的 canonical layout；
- `GuestConstantCodec`：常量的严格类型检查与 little-endian 编码；
- `GuestDataLayout`：UTF-8 string 与 constant array data segment；
- `GuestLayoutBuilder`：state、immutable data、heap 的确定性地址排布；
- `GuestCanonicalTypeValidator`：重算 type layout，拒绝被篡改的 size/alignment/field offset；
- `GuestMemoryLayoutValidator`：交叉核对 global/state slot、segment、region 与 header。

这些模块仍然不依赖 Roslyn、UE 或 WAMR。

## Type Layout

线性内存固定 little-endian，最大 alignment 为 16 字节：

- `i32/f32` 使用最多 4 字节存储，`i64/f64` 使用 8 字节；
- bool 与小整数可以使用 1/2 字节 memory size，同时 register storage 仍为 `i32`；
- enum 继承 underlying integer 的 storage、size 与 alignment；
- struct 按字段声明顺序逐字段对齐，最终 size 补齐到 struct alignment；
- string 与 array 的 Guest 值是 4 字节 header address；
- UObject handle 保持 slot/generation 语义，canonical memory size 为 8 字节；
- 递归值类型、未知 field/element/underlying type 和非法 alignment 失败关闭。

最终 artifact 不能自行声明 offset。validator 会调用同一 resolver 重算 canonical type，并逐字段比较 identity、type、offset、size 与 alignment。

## Memory Region

模块线性内存按以下区域排列：

1. `[0, 16)`：保留 null guard，不放置可寻址对象；
2. state：global 按稳定 `global_id` ordinal 排序并逐项对齐；
3. immutable data：整体从 16 字节边界开始，segment 按稳定 `segment_id` 排序；
4. heap：从 data end 向上对齐到 16 字节后开始，供后续模块私有 bump allocator 使用。

所有 address、size、stride、header 和 alignment 运算使用 checked arithmetic。任何 32 位地址溢出都会产生 `ASIR2001`，不会环绕到低地址。

struct state 可以使用 `GuestConstant(kind=zero, value=null)` 做确定性全零初始化。非零字段初始化由 P41.4 lowering 生成的构造逻辑写入，避免在常量模型中复制一套聚合表达式语义。

## String 与 Array

string data 固定为：

```text
[byte_length:i32][utf8 bytes][0]
```

`byte_length` 是 UTF-8 字节数，不是 UTF-16 code unit 或 Unicode scalar 数。validator 使用严格 UTF-8 解码并检查 header、总长度与零终止符。

array data 固定为：

```text
[element_count:i32][optional alignment padding][element payload]
```

element stride 为 `AlignUp(element_size, element_alignment)`。当 element alignment 大于 4 时，payload offset 同样向上对齐；例如 `i64[]` 的 payload 从 header address + 8 开始。空数组只包含 4 字节零 count header。

当前 compile-time constant array 支持 scalar、enum 与 handle element。struct array 的运行时分配和逐字段写入由后续 lowering/backend 完成。每个运行时 array get/set 必须先验证 `0 <= index < length`，再计算 element address；P41.5 backend 不得把 bounds check 当作可选优化。

## 诊断

| 诊断码 | 含义 |
| --- | --- |
| `ASIR2001` | size、stride 或 address 超出 32 位线性内存 |
| `ASIR2002` | 重复/未知 type 或递归值类型 |
| `ASIR2003` | type kind、storage、size、alignment 或 shape 不支持 |
| `ASIR2004` | string/array data declaration 或 constant element 不匹配 |
| `ASIR2005` | 最终 type/state/data/heap layout 非 canonical 或被篡改 |

## 验证结果

- Guest IR 总测试：28/28；
- P41.3 layout：13/13；
- mixed struct offset 与 tail padding；
- enum underlying layout；
- 递归值类型拒绝；
- UTF-8 byte length 与终止符；
- 2/8 字节 element stride、payload alignment 与 little-endian；
- 空数组；
- state/data/heap 确定性排序；
- struct zero initialization；
- address overflow；
- 最终 region、type offset 与 string header 防篡改；
- production 与 tests 项目分别通过 `dotnet format`。

## 给 P41.4 的输入

C# semantic lowering 必须先生成 raw Guest type/global/data declaration，再依次调用 `ComputeTypes`、data encoder 与 `GuestLayoutBuilder`，最后构造带完整 `memory_layout` 的 GuestModule 并运行 `GuestModuleValidator`。lowering 不得自行计算第二套 field offset 或 array stride。
