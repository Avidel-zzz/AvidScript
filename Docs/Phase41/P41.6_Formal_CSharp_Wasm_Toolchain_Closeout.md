# P41.6 正式 C# 到 WASM 工具链收尾

## 阶段结论

P41.6 已完成 Phase 41 收尾。默认 ActorLifecycle 不再由 PowerShell 读取 C# AST、猜测语义或直接拼装 WASM，而是严格经过以下正式链路：

```text
C# source
  -> AvidScript.CSharpFrontend
  -> AvidScript.CSharpSemantic
  -> AvidScript.CSharpGuest
  -> Guest IR v1
  -> AvidScript.WasmBackend
  -> WASM 1.0
  -> manifest/report
  -> UE5.8 WAMR runtime
```

PowerShell 现在只负责工具定位、进程编排、失败清理、artifact 发布和报告聚合。C# 语法、控制流、类型布局、Guest IR lowering 与 WASM opcode 生成均由各自的 C# 模块负责。

## 构建入口

- `Build/BuildCSharpActorLifecycle.ps1`：正式默认构建入口。
- `Build/InvokeCSharpGuestCompiler.ps1`：依次调用 CSharpGuest、WasmBackend 和实际 WASM inspection，失败时不发布部分 WASM。
- `Samples/CSharp/ActorLifecycle/ActorLifecycleScript.cs`：可执行的 C# 游戏逻辑样例。

默认构建命令：

```powershell
& .\Plugins\AvidScript\Build\BuildCSharpActorLifecycle.ps1 `
  -DotNetPath <UserProfile>\.dotnet\dotnet.exe
```

默认产物位于：

```text
Saved/AvidScriptCSharpGuest/ActorLifecycle/
  actor_lifecycle.csharp.frontend.json
  actor_lifecycle.csharp.semantic.json
  actor_lifecycle.guestir.json
  actor_lifecycle.wasm
  actor_lifecycle.wasm.inspect.json
  actor_lifecycle.avidscript.json
  actor_lifecycle.csharp.report.json
```

每次构建会先删除同 stem 的旧 report、manifest、Guest IR、WASM、WASM inspection 和旧适配器产物。语法、语义、Guest IR、后端、ABI 或 report/manifest 发布任一阶段失败时，都会移除 manifest/WASM，不会留下可被 Editor 误绑定的半发布产物。

## Provenance 与失败诊断

report 与 manifest 记录 source、frontend、semantic、Guest IR 和 WASM 的 artifact 路径、schema/version 与 SHA-256。Guest IR 自身携带 source/frontend/semantic provenance，WASM custom section 继续携带后端 provenance。

Editor 的 `FAvidScriptFrontendReportReader` 已能读取 Guest IR metadata 与根级 `result`。`FAvidScriptEditorCSharpBuildService` 在编译进程非零退出时优先读取结构化报告，并把具体错误类别和首个 error diagnostic 返回 UI；进程退出 0 时也会重新解析 report，验证 `succeeded/result/schema`、error diagnostic、manifest 和最终 WASM，损坏或不完整的成功结果不会进入绑定。

自定义源码 C# profile 当前明确失败关闭：

- result：`phase42_binding_required`；
- diagnostic：`ASBI4201`；
- 不生成 Guest IR、manifest 或 WASM；
- Editor 不执行绑定，也不会给 Actor 留下旧组件。

这是 Phase 42 Reflection Binding Generator 接入前的主动安全门，不是恢复旧 AST 适配器的兼容入口。

## UE 生命周期与类型交互

ActorLifecycle 样例已通过正式 WASM 在 UE5.8 中执行：

- `avid_on_begin_play`：初始化状态、Actor transform 和 Timer；
- `avid_on_tick`：累积脚本状态并驱动位置、旋转、缩放；
- `avid_on_timer`：接收 timer callback id/handle；
- `avid_on_event`：处理通用事件 id/value；
- `avid_on_gameplay_event`：接收固定 POD envelope，并路由 BeginOverlap、EndOverlap、Hit、Input；
- `avid_on_end_play`：执行脚本清理逻辑。

运行时交互覆盖 `AActor`、`USceneComponent`、`FVector`、`FRotator`、`FTransform`、对象 slot/generation handle、Timer、碰撞事件、输入事件与热重载。typed gameplay dispatcher 是脚本显式 ABI export，不是编译器按 C# 方法名硬编码。

## 本阶段修复的真实问题

1. Roslyn 的合法 `void` fallthrough 会沿 regular edge 进入 exit block。旧 lowering 把所有无后继 exit block 都生成 `trap`，导致 BeginPlay 进入 `unreachable`。现在 `void` exit 生成无值 `return`，非 void 非法退出仍 trap，并有聚焦回归测试。
2. UE 启动的 Windows PowerShell 环境不保证自动加载 `Get-FileHash`。构建报告哈希已改为纯 .NET 流式 SHA-256，不依赖 cmdlet/module 自动加载。
3. 旧 Editor profile 自动化忽略构建失败后解引用空组件，曾触发访问冲突。命令测试现在验证失败即停止绑定，并断言 Actor 保持未绑定。
4. 旧 runtime 测试检查 AST 适配器 manifest 文本。现在改为结构化验证 Guest IR/report/manifest provenance，再由 manifest loader 和真实 WAMR 生命周期执行验证行为。
5. 构建报告曾把 Guest IR 声明直接当作 `observed_exports`。现在由 WasmBackend 的 `WasmArtifactInspector` 读取最终 WASM，发布带 SHA-256 的 inspection，并分别校验声明导出和实际函数导出。
6. manifest 与 report 发布曾缺少事务清理。现在 JSON 原子写入拒绝目录目标、清理临时文件，report/manifest 任一发布失败都会删除 manifest/WASM 并返回非零。
7. Editor 曾把“进程退出 0 且 report 存在”直接当作成功。现在损坏 JSON、结构化失败、缺 manifest、缺 WASM 都有独立失败类别和自动化覆盖。
8. 子 PowerShell 写 stderr 时，`ErrorActionPreference=Stop` 曾在父脚本形成 `NativeCommandError` 并绕过结构化分类。现在三个子阶段统一通过受控进程捕获器保存 stdout/stderr 和真实退出码。

## Phase 41 完成后的能力边界

已经完成：

- 稳定、可验证、语言无关的 Guest IR；
- 正式 C# semantic 到 Guest IR lowering；
- 确定性 WASM 1.0 backend；
- C# BeginPlay/Tick/EndPlay、Timer、事件、碰撞、输入与热重载闭环；
- handle-backed UE 对象与基础数学/变换类型交互；
- artifact provenance、失败清理和 Editor 结构化诊断。

尚未完成：

- 从 UE Reflection 自动生成大规模 C# facade/reference assembly；
- 自动生成 binding descriptors、host stubs 和类型 marshalling；
- 任意用户 C# profile 在不手写 facade 的情况下直接使用 UE API；
- Android/iOS 工具链、AOT、调试器与生产级性能优化。
