# P8.4 Phase 8 Closeout

日期: 2026-07-05
状态: Done

## 1. 结论

Phase 8 已完成 CLI/report-first 的开发者工作流入口。当前 `.avid` source 可以通过 `InvokeAvidScriptFrontend.ps1` 生成机器可读 JSON report, 并保持与 P7 typed binding declaration、diagnostics 和 D/LDC WASM artifact pipeline 的兼容。

本阶段没有引入重 Editor UI 或新的 Editor module, 而是先稳定后续 Editor command、watcher、IDE 和 CI 共同需要的 report contract。

## 2. 已完成内容

- `Build/InvokeAvidScriptFrontend.ps1` 包装 `BuildAvidScriptActor.ps1`, 捕获 stdout/stderr 和 exit code。
- JSON report schema v1 覆盖 `source`, `bindings`, `output_root`, `exit_code`, `succeeded`, `diagnostics`, `build_events`, `raw_output`。
- wrapper 可解析 structured diagnostics, 包括 unknown binding 这类 frontend failure。
- wrapper 可解析 frontend build result, 包括 `generated` 和 `built` 结果。
- 真实 LDC build report 已验证, manifest hash/import 仍可被 runtime reload path 使用。
- Editor handoff contract 已文档化: report succeeded 后交给 manifest loader 和 reload staging; report failure 时不触发 reload。

## 4. 当前可实现能力

现阶段可以把 `.avid` 文件作为开发输入, 通过稳定 wrapper 获得:

```text
.avid source
-> generated D source
-> optional LDC WASM artifact
-> .avidscript.json manifest
-> JSON report with diagnostics/build events
```

对后续 Editor 接入来说, 这意味着 Editor command 不需要解析临时 stdout, 只要读取 report:

- report success: 展示 output/manifest 并触发 reload staging。
- report failure: 展示 `ASLxxxx` 诊断, 保持当前 live runtime 不变。
- toolchain failure: 展示 `ASL130x` 诊断, 引导配置 LDC 路径。

## 5. 剩余风险

- 目前仍是 Windows PowerShell wrapper, PC-first; 跨平台 CLI 或移动端工具链入口未完成。
- 尚未实现真正 Editor command、watcher 或 UI 面板。
- report 中 `bindings` 字段在未显式传参时保留调用参数视角; 后续 Editor command 可补充 effective bindings path。
- frontend parser/type checker 仍是最小纵切, 尚未覆盖变量、控制流、模块系统或完整类型系统。

## 6. 下一阶段建议

Phase 9 应进入轻量 Editor command integration:

- 增加 Editor-facing 入口, 但继续避免重 UI。
- 从 Editor/automation 触发 frontend wrapper 或等价 C++ service。
- 读取 JSON report 并建立成功/失败的 UE 侧消费测试。
- 成功路径衔接现有 manifest loader/reload staging。
