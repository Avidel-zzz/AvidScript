# P8.1 Frontend Workflow Wrapper

日期: 2026-07-05
状态: Done

## 1. 目标

`Build/InvokeAvidScriptFrontend.ps1` 是 Phase 8 的 CLI/report entry。它调用 P7 的 `BuildAvidScriptActor.ps1`, 捕获 stdout/stderr 和 exit code, 并写出机器可读 JSON report。

## 2. Report Schema

```text
schema_version: 1
source: wrapper input source path
bindings: wrapper input bindings path
output_root: wrapper input output root
exit_code: child frontend process exit code
succeeded: true only when exit_code == 0, no error diagnostics, and final result is generated or built
diagnostics: parsed frontend diagnostics
build_events: parsed frontend build result lines
raw_output: complete captured child output
```

## 3. 验证计划

P8.1 验证 wrapper 的两个最小路径:

```text
success: sample .avid + -SkipCompile -> report.succeeded=true, final result=generated
failure: unknown binding .avid + -SkipCompile -> report.succeeded=false, diagnostic code=ASL1202 with line/column
```

P8.2 再验证真实 LDC build report。
## 4. 验证结果

```text
ps_parse=ok
success_succeeded=True
success_diag_count=0
success_result=generated
p8_1_unknown_report=passed line=6 column=5
```

## 5. 剩余风险

- wrapper 当前解析 stdout, 因此依赖 P7 frontend 输出格式保持稳定。
- `bindings` 字段记录 wrapper 输入参数; 如果未显式传入 `-BindingsPath`, report 中该字段为空, 真实默认 binding path 仍可从 raw output 的 `bindings=` 行获得。
- 真实 LDC build 的 `built` report 已在 P8.2 验证; 后续风险转为 Editor integration 如何消费 report。
## 6. P8.2 LDC Report 验证

验证命令:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Plugins/AvidScript/Build/InvokeAvidScriptFrontend.ps1 -SourcePath Plugins/AvidScript/Samples/AvidScript/ActorSetLocation/actor_set_location.avid -ReportPath Saved/AvidScriptReports/p8_2_ldc_build.report.json -Ldc2Path C:\tmp\AvidScriptToolchains\ldc2-1.42.0-windows-x64\ldc2-1.42.0-windows-x64\bin\ldc2.exe
```

结果:

```text
p8_2_report_succeeded=True
p8_2_result=built
p8_2_bytes=486
p8_2_manifest_frontend=p7.2
p8_2_import=env.actor_set_location
p8_2_sha_ok=True
```

结论:

- wrapper 能覆盖真实 LDC build path。
- `build_events[-1].fields.output` 能正确保留包含空格的 Windows path。
- report 与 manifest 可以共同作为后续 Editor integration handoff 输入。
