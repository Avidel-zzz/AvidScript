# Phase 50 Typed Object Benchmark

## 目的

本基准为 Phase 50 的 typed object / checked cast 建立项目内性能采样面，固定比较三条同一 fixture、同一 warmup/sample 规则下的路径：

1. Native `UObject::IsA(UActorComponent::StaticClass())`；
2. `FAvidScriptBindingPackage::Dispatch` 的 `avidscript.avid_object_type_is_a` ordinal capability；
3. 已加载 WAMR runtime 中、由 `avid_on_tick` 触发一次真实 checked cast import 的路径。

另行保留现有 typed binding `GetActorLocation` 指标，供集中 Gate 与 Phase 49 同机基线比较。该指标不混入上述三条 checked-cast 的计时结果。

自动化入口：

```text
AvidScript.Performance.TypedObjectBenchmarkSmoke
```

## 测量设计

默认配置与 Phase 49 一致：warmup `3` 轮、sample `20` 轮、每个 sample `1000` 次操作；统计使用 nearest-rank P50/P95。每轮按正反交替顺序执行 Native、binding、既有 typed binding 与 WAMR，降低固定执行先后导致的 cache 或调度偏差。

fixture 是同一 benchmark world 中的 `USceneComponent`，目标类型为已缓存的 `UActorComponent` ordinal。descriptor v6 在计时前完成解析，WAMR module 也在计时前完成 load/instantiate 和 `BeginPlay`。因此计时区只包含 warm dispatch 或 warm guest-to-host checked cast，不含 world 创建、对象注册、descriptor JSON 构建、class load、module load 或数组首次扩容。

WAMR 模块的 `avid_on_tick(float)` 固定调用一次：

```text
avidscript.avid_object_type_is_a(slot, generation, actor_component_ordinal)
```

返回值会被 guest 丢弃，但 runtime 必须观察到一次 successful dynamic host dispatch。该路径不是 C++ 直接调用的替代品，而是实际 WAMR guest crossing。

## 结构预算

| 项目 | 预算 | 采样/断言方式 |
| --- | ---: | --- |
| warm typed dispatch class load | 0 | package instrumentation delta |
| warm typed dispatch reflected-name lookup | 0 | package instrumentation delta |
| typed upcast host import | 0 | typed ABI 固定为两个 `i32` copy |
| checked cast host crossing | 1 / WAMR operation | runtime `HostImportCallCount` |
| existing typed binding regression | <= 5% | 仅对同机、同 harness、已记录的 Phase 49 median 计算 |

package load 的 class-load / reflected-name lookup 会单独记录，不能与 warm loop 混淆。当前 schema sentinel 的 reflected function lookup 发生于 load，属于预热成本，不进入 checked cast dispatch 的预算。

## 解释边界

- 这是 PC Editor/NullRHI 的项目内微基准，不代表 Shipping、Cook、Android 或 iOS；
- WAMR crossing 路径验证真实 checked cast import，不用于推导完整 C# authoring、build 或首次 module load 延迟；
- 对象类型 ordinal 与 cached `UClass` 是当前 descriptor 的 immutable plan，不测量 reflection discovery；
- 未在同机、同项目、同 harness 下测试 Puerts、UnLua 或 AngelScript，因此本报告不宣称 AvidScript 在外部框架间领先或更快；
- Phase 50 集中 Gate 需运行本自动化、保留原始日志与机器信息，再决定是否满足 Phase 49 existing typed binding 的 `<= 5%` 预算。
