## 1. Phase 4 结论

Phase 4 已完成 AvidScript 的第一个真实外部 WASM 与 UE Actor 交互闭环。

- Runtime 可以从磁盘读取真实 `.wasm` 文件。

- 缺失文件、空文件、missing import、host import failure 继续返回结构化 diagnostics, Editor 不崩溃。

## 3. Final ABI

Host import module:

```text
avidscript
```

Actor imports:

```text
actor_get_location(slot:i32, generation:i32, out_xyz_ptr:i32) -> i32
actor_set_location(slot:i32, generation:i32, x:f32, y:f32, z:f32) -> i32
```

约定:

- 返回 `1` 表示成功。
- 返回 `0` 表示失败, runtime 记录 host import failure。
- `slot` / `generation` 对应 `FAvidScriptObjectHandle`。
- `actor_get_location` 的 `out_xyz_ptr` 指向 guest linear memory 中连续 3 个 `f32`。
- `actor_set_location` 只有在 host context 使用 `EAvidScriptActorWritePolicy::AllowWrites` 时才允许写 Actor。
- Guest 不接触 raw `UObject*` 或 raw host pointer。

## 6. 下一阶段建议

进入 Phase 5 MVP Decision / Guest Toolchain Spike。

推荐顺序:

1. 先用 D 做一个最小 guest module 模板, 输出与 P4.3 fixture 等价的 `.wasm`。
2. 用同一条 P4.3 automation path 验证 D 产物可以调用 `actor_set_location`。
3. 保留 C# 作为第二条可接受路径, 重点评估 WASM 体积、启动成本、AOT/toolchain 成熟度与移动端可行性。
4. 在 D/C# 二选一前, 不扩展大面积 UE API; 继续围绕 Actor transform、property get/set、event/tick 做小 ABI。

判断标准:

- 产物可稳定输出 WASM32。
- 可链接 AvidScript host imports。
- PC Editor automation 可复用 P4.3 测试闭环。
- 工具链在移动端不制造不可接受的运行时或包体风险。
