# P4.3 External WASM Actor Automation

日期: 2026-07-04
状态: Done

## 1. 目标

P4.3 完成 Phase 4 的核心闭环: automation 在磁盘写入真实 `.wasm` fixture, 通过 `FAvidScriptWasmModuleLoader::LoadFromFile` 读取 bytes, 再由 `FAvidScriptWasmRuntimeInstance` 加载并执行。Guest WASM 在 `avid_on_begin_play` 中调用 host import `avidscript.actor_set_location`, 最终验证 UE `AActor` location 被 WASM 改变。

这一步证明当前 AvidScript runtime 已具备真实外部 WASM 文件与 UE Actor host binding 交互的最小能力。

## 2. 实现内容

新增 automation:

- `AvidScript.Runtime.WasmActor.ExternalFileSetLocationSmoke`

测试流程:

1. 创建 automation world 和测试 Actor。
2. 将 Actor 注册进 `FAvidScriptObjectRegistry`, 获取 `FAvidScriptObjectHandle`。
3. 生成一个最小 WASM module bytes。
4. 将 bytes 写入 `Saved/AvidScriptTests/Phase4/actor_set_location_external.wasm`。
5. 使用 `FAvidScriptWasmModuleLoader::LoadFromFile` 从磁盘读回。
6. 设置 runtime host context: registry + `EAvidScriptActorWritePolicy::AllowWrites`。
7. 调用 `LoadModule` 和 `BeginPlay`。
8. 验证 Actor location 变为 `(123, 456, 789)`。

## 3. Fixture ABI

Fixture import:

```text
module: avidscript
name: actor_set_location
signature: (slot:i32, generation:i32, x:f32, y:f32, z:f32) -> i32
```

Fixture exports:

```text
avid_on_begin_play() -> void
avid_on_tick(delta_seconds:f32) -> void
```

`avid_on_begin_play` 指令流:

```text
i32.const slot
i32.const generation
f32.const 123.0
f32.const 456.0
f32.const 789.0
call actor_set_location
drop
end
```

当前 fixture 由 C++ test helper 直接生成 WASM bytes, 不依赖 `wat2wasm`、D 编译器或 C# toolchain。这样 P4.3 只验证 runtime/ABI/file path, 不把 guest toolchain 引入变量。
