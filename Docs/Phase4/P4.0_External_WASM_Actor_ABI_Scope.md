# P4.0 External WASM Actor ABI Scope

日期: 2026-07-03
状态: Done

## 1. 目标

Phase 4 从 Phase 3 的 minimal WASM import bridge 继续向前推进, 目标是在 PC Editor automation 中加载外部 `.wasm` 文件, 让 guest WASM 通过 AvidScript host imports 调用 UE Actor binding, 并验证真实 `AActor` 状态被改变。

这是 AvidScript 从 “embedded byte array smoke” 进入 “真实脚本产物文件与 UE 对象交互” 的第一阶段。

## 2. 范围

本阶段包含:

- 外部 `.wasm` 文件读取。
- `FAvidScriptWasmRuntimeInstance` host context。
- handle-based Actor host ABI。
- WAMR native imports:
  - `avidscript.actor_get_location(slot, generation, out_ptr) -> i32`
  - `avidscript.actor_set_location(slot, generation, x, y, z) -> i32`
- automation 写入 `.wasm` fixture 文件, 再通过 loader 读回并执行。
- 结构化失败诊断和 fail-closed 行为。

本阶段不包含:

- D/C# guest toolchain 模板。
- 自研语言编译器。
- JSON manifest parser。
- Editor watcher/UI。
- Android device smoke。
- packaging/cook/stage/pak。
- 状态迁移。

## 4. 决策

Phase 4 先采用 handle-based ABI, 不采用 owner-only shortcut。原因:

- 复用 P2.1 的 UObject handle registry。
- 对未来 D/C# 标准库更自然, 可以包装成 `ActorHandle`。
- 避免把 API 绑定死在 `UAvidScriptComponent` owner 上。
