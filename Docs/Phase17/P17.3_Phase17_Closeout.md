## 当前可用能力

到 Phase 17 结束，PC Editor 内已经可以完成 C# gameplay authoring 的最小闭环：

1. C# 样例用 `BeginPlay()` 和 `Tick(float deltaSeconds)` 表达游戏逻辑。
2. `BuildCSharpActorLifecycle.ps1` 将受支持子集生成 direct ABI WASM 和 manifest。
3. UE Editor 菜单入口把该 C# report 绑定到选中 Actor。
4. Actor 的 `UAvidScriptComponent` 在 BeginPlay/Tick 中加载 C# WASM 并驱动 Actor。

这意味着现在已经能在 C# 中接入 UE 的 BeginPlay/Tick 事件流程，并通过当前 host binding 调用 `Actor.SetLocation(...)`。

## 剩余风险

- 目前 C# source adapter 仍是受限子集，不是完整 C# 编译器。
- Editor 入口只绑定固定 ActorLifecycle report，尚未支持任意 C# 文件选择。
- 仍需要手动或外部命令运行 `BuildCSharpActorLifecycle.ps1`，菜单暂不负责构建 C#。
- 当前只绑定第一个选中 Actor，批量绑定留待后续阶段。
- packaging/mobile 仍未验证。

## 下一阶段建议

Phase 18 建议把 C# 构建也纳入 Editor 工作流，形成 `Build C# ActorLifecycle` 或 `Build And Bind C# ActorLifecycle` 的一键入口。这样用户无需离开 Editor 即可从 C# 源码更新到 Actor 组件绑定。
