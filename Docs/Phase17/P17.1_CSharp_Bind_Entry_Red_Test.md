# P17.1 Editor C# 绑定入口 RED 测试

## 测试意图

Phase 17 先用 automation 描述目标行为，再补实现：

- `AvidScript.Editor.Module.SampleCommandConfigSmoke` 扩展为同时检查 C# 绑定菜单配置。
- 新增 `AvidScript.Editor.Module.CSharpBindSelectedActorSmoke`，创建临时 world/actor，选中该 Actor 后通过 module 执行 C# report 绑定。

## RED 失败证据

RED 构建命令：

```powershell
& 'C:\UnrealEngine\Engine\Build\BatchFiles\Build.bat' AvidTPSTemplateEditor Win64 Development '-Project=<ProjectRoot>\AvidTPSTemplate.uproject' -WaitMutex -NoHotReloadFromIDE -Module=AvidScriptEditor
```

预期失败点：

- `GetCSharpActorLifecycleReportPath` 不是 `FAvidScriptEditorModule` 成员。
- `MakeCSharpActorLifecycleBindMenuEntryConfig` 不是 `FAvidScriptEditorModule` 成员。
- `ExecuteCSharpActorLifecycleBinding` 不是 `FAvidScriptEditorModule` 成员。

这说明测试确实先要求了 Phase 17 的新行为，而不是复用已有实现直接通过。

## 测试覆盖

`CSharpBindSelectedActorSmoke` 覆盖以下行为：

1. 最新 C# report 路径来自 module 固定约定。
2. 若 report 缺失，测试给出 warning 并不误报实现失败。
3. 若 report 存在，测试创建临时 Actor 并设置 Editor selection。
4. 调用 `ExecuteCSharpActorLifecycleBinding` 后，Actor 获得 `UAvidScriptComponent`。
5. 返回结果中的 report path 和组件指针与实际绑定一致。

## 设计取舍

本阶段仍使用固定的 ActorLifecycle C# sample/report，这是为了让 PC Editor C# MVP 先形成可用闭环。任意 C# 脚本、项目设置选择、批量绑定和更完整 UI 放到后续阶段。
