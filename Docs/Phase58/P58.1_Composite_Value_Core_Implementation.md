# P58.1 复合值核心实现报告

## 结论

P58.A 已实现并验证统一复合值 capability 的第一批真实 UE 类型：`FText`、
`TSoftObjectPtr<T>` 与 `TWeakObjectPtr<T>`。三者在 WASM 边界均使用一个 `i32`
token，不暴露 UE 内存布局；Host 端通过原始 `FProperty` 完成初始化、完整复制与析构。

## 已实现能力

- descriptor schema v19 增加递归 `type_arguments` 与 `capability_kind`，并对类型图执行
  节点上限、深度、循环、子类型存在性及 kind/canonical/capability 一致性检查；
- 新增 `FAvidScriptCompositeValueHeap`，提供有界 reservation、publish、commit、rollback、
  generation-safe token、引用计数子节点、精确属性类型校验及 Session reset；
- `FText` 支持通用 UFUNCTION/UPROPERTY 的 value、const-ref、ref、out、return codec 规划，
  并提供 `avid_value_text_to_string` 作为显式展示转换；
- `TSoftObjectPtr<T>` 保留软路径与惰性加载身份，`TWeakObjectPtr<T>` 保留弱引用失效语义，
  两者不会退化为强 `UObject` handle；
- 生成 C# `FAvidText`、`FAvidSoftObject<T>`、`FAvidWeakObject<T>` 名义值类型，统一通过
  `AvidScriptValue.Release(...)` 释放；
- C# Guest 编译器将上述名义值严格降级为 `composite_ref` / `i32`，并拒绝字段类型、
  readonly、可见性或构造函数不符合生成合同的伪造包装；
- `avid_value_release` 已统一探测 flat array、UTF-8 与 composite 三类 Session 值堆。

## 生命周期与安全边界

- 复合值内存仅由对应 `FProperty` 的 `InitializeValue`、`CopyCompleteValue` 与
  `DestroyValue` 管理；
- token 同时校验 generation、stable type id 与 `FProperty::SameType`，释放后的 token
  不能再次解析；
- Runtime unload 在反射 package 和 UObject roots 释放前清空值堆，避免属性析构晚于类型根；
- 旧 flat-array 路径暂不接收 FText、soft/weak object 等子 capability。P58.B 建立容器 DAG
  引用计数后再开放，避免容器释放时遗留子 token。

## 当前限制

- 尚未支持递归 `TArray`、`TSet`、`TMap` 的复合子值；
- soft object 只完成身份往返，显式同步解析与异步加载 API 留给后续易用层；
- weak object 只完成身份往返，脚本侧显式 `TryResolve` 留给后续易用层；
- delegate handler 的 ref/out 写回仍由 P58.C 完成；
- 完整 AvidScript Automation、clean architecture gate 与性能统计在 P58.D 集中执行。

## 下一批

P58.B 将复用本批的 heap slot、child token 和 transaction，不另建容器专用生命周期系统。
目标是递归 `TArray`、`TSet<T>`、`TMap<K,V>` 的 canonical snapshot/mutation，同时保留旧
flat-array bulk path 作为标量数组热路径。
