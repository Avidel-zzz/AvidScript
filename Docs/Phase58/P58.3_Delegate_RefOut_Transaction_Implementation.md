# P58.3 Delegate ref/out 事务实现报告

## 结论

P58.C 已完成动态委托 `ref/out` 从 UE Reflection 到 C#、Guest IR、WASM、VM Host
import 和 UE 参数帧写回的完整链路。脚本不直接持有 UE 参数内存，也不能按地址任意写入；
每次回调由 Runtime 创建短生命周期事务，Guest 只提交被 descriptor 授权的输出序号，全部
输出成功暂存且回调正常返回后才一次性提交。

真实 C# 样例 `Samples/CSharp/DelegateRefOut` 已通过正式 Editor profile 构建，能够只声明
`[AvidEvent]` 处理器而不额外伪造 `BeginPlay` 或其他生命周期导出。

## 跨层实现

- Reflection descriptor schema v19 为 delegate 参数保留 `in`、`ref`、`out` 方向，并把
  `handler_mode` 纳入 canonical identity、stable id 和导出名计算；
- 生成的 C# facade 按 descriptor 直接输出 `ref T` / `out T` handler 签名，不按具体
  UClass、委托名或游戏 API 手写 wrapper；
- Semantic artifact 保存参数方向，delegate callback 进入统一
  `Reachability.RootCallableIds`；纯事件脚本可由入口根确定唯一 state owner；
- Guest lowering 为有输出的回调增加一个 transaction token，并在 handler 返回后使用
  `avid_delegate_output_write(transaction, ordinal, address)` 逐项暂存；
- VM 将 `avid_delegate_output_write` 注册为 `avidscript` 模块的静态 Host import，旧 ABI
  ordinal 保持不变，新 import 只追加在冻结区之后；
- Runtime 同一时刻只允许一个活动输出事务，校验 token、输出 ordinal、Guest 地址、类型
  codec 和完整性；重复写、越权写、漏写、重入、trap 或 unload 都不会产生部分提交；
- 构建授权器把该 import 识别为具有固定 ID 和固定签名的编译器注入 ABI，不要求每个
  Reflection package 重复声明；最终 manifest 仍明确记录实际 WASM required import。

## 事务语义

一次委托调用按以下顺序执行：

1. 根据已激活 package 中缓存的 prepared delegate codec 创建原生输出候选；
2. 为本次回调分配不可复用的 transaction token，并把 `ref` 初值编码进 Guest ABI；
3. 调用生成的 `avid_on_delegate_<stable-id-prefix>` WASM export；
4. Guest handler 正常返回前，输出写入仅进入 Host 事务候选，不修改 UE 参数帧；
5. Runtime 检查每个授权输出恰好完成一次，再通过 prepared codec 统一 commit；
6. 任一步失败都销毁候选并保持调用前原生参数值。

当前真实 fixture 覆盖两个 `int32` 参数：一个 `ref` 和一个 `out`。prepared codec 使用
同一类型图和 value capability 基础设施，因此后续值类型不需要新增按 API 名分支；但复杂
复合值的完整端到端矩阵仍在 P58.D 集中门禁中确认，未验证前不宣称全部组合已发布。

## C# 用法

```csharp
namespace AvidScript;

[AvidStateContract(AvidStateMode.Explicit)]
public static class DelegateRefOutScript
{
    [AvidEvent(AvidEvents.OnRefOutSignal)]
    public static void HandleRefOutSignal(ref int value, out int doubled)
    {
        value += 3;
        doubled = value * 2;
    }
}
```

项目只需在 profile 中选择自己的 `BlueprintAssignable` 委托。descriptor、C# 事件常量、
handler contract、WASM export 和 Runtime subscription 都由现有生成链路建立。

## 已修复的集成缺口

- 保留冻结 VM ordinal：P58 imports 从旧 ABI 尾部追加，避免现有 WASM/Host contract 漂移；
- schema v19 delegate identity 在最终 schema 确定后统一重算，避免 `handler_mode` 序列化
  与 stable id 不一致；
- state schema owner 改为从语义入口根推导，并为旧 schema 保留 Export 回退路径；
- 编译器注入事务 import 采用精确 ID/模块/名称/dispatch/signature 白名单，不放宽普通
  动态 binding package 的授权边界。
