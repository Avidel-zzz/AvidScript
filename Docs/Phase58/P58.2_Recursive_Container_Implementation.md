# P58.2 递归容器实现报告

## 结论

P58.B 已完成递归 `TArray`、`TSet`、`TMap` 的跨层实现。容器不暴露 UE
内存布局，仍以统一 `i32` capability token 穿过 WASM 边界；反射 descriptor、Host
codec、Session 值堆、静态 import、C# 生成 facade 与 Guest lowering 使用同一递归类型图。

本报告记录实现完成状态。由于验证时 Unreal Editor 正在占用已加载 DLL，UE focused
Automation 与最终链接仍属于待执行门禁，不能用本轮 `-NoLink` 编译代替。

## 已实现能力

- descriptor schema v19 的 stable identity 纳入有序 `type_arguments` stable id，
  `TSet<T>` 与 `TMap<K,V>` 不再只按外层类型生成身份；
- `TArray<T>` 支持字符串元素和递归容器元素，旧 flat-array bulk path 保留为标量热路径；
- `TSet<T>` 支持 count、canonical read、find、add 与 remove；
- `TMap<K,V>` 支持 count、canonical key/value read、find、insert/update 与 remove；
- C# 生成 `FAvidArray<T>`、`FAvidSet<T>`、`FAvidMap<K,V>` 名义 capability facade，
  容器 API 从 descriptor 类型图生成，不为具体 UE API 手写 wrapper；
- 新增统一静态 Host imports：`avid_value_container_count/read/write/resize/clear/find/upsert/remove`；
- manifest import 数量与实际写入统一从 capability catalog 生成，避免计数和条目漂移；
- string `in/ref/out` Guest frame 获得真实可寻址 i32 slot，修复零逻辑大小导致的
  `address_of` 失效；
- 容器 Host 调用统一要求 GameThread，并由类型图、lane、property identity 与 token
  generation 多重校验后才可访问。

## 规范顺序与性能

`TSet` 和 `TMap` 的脚本可见顺序不依赖 UE 内部 hash bucket。首次读取时，Host 对 key
执行确定性字节编码并排序，生成 canonical index snapshot；后续读取直接复用 Session
slot 内的只读 view，不再复制整个索引数组。

- snapshot 首次建立：`O(n log n)`；
- canonical index 读取：`O(1)`；
- `find`：UE hash lookup 后通过反向索引得到 canonical index，平均 `O(1)`，不再线性扫描；
- 任意成功变更使 snapshot 失效，下一次读取惰性重建；
- reflected access plan 在 package activation 时建立并缓存，不在每次调用时递归解析 descriptor。

规范 key 当前覆盖字符串、FName、枚举及固定宽度整数。没有确定性 wire encoding 的 key
类型 fail-closed，不回退到地址、进程 hash 或 UE 内部迭代顺序。

## 原子修改与资源上限

容器写入采用 `复制候选值 -> 修改候选值 -> 完整测量 -> 一次性替换`。Guest 解码失败、
反射复制失败或预算超限时，原 capability 中的值保持不变。

当前硬上限：

- 单个递归值图最多 1 MiB；
- Session 活跃递归值合计最多 16 MiB；
- 单个容器最多 4096 个元素或条目；
- 递归深度最多 8 层；
- 单图最多 8193 个测量节点，可容纳 4096 个 map key/value 对；
- 字符串、FText 展示文本和 soft object path 的动态存储计入预算；
- 包含强 `UObject` leaf 的复合图在没有显式 GC anchor 前 fail-closed；soft/weak object
  保持各自生命周期语义。
