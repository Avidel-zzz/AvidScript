# P56.3 生命周期热结果实现

## 目标

P56.3 将高频 `Tick`、普通 Event 与 typed GameplayEvent 从“每次成功都构造完整
`FAvidScriptWasmSmokeResult`”改为“成功零结果物化、失败完整诊断”。原有 `Tick`、
`TickLive`、`DispatchEvent` 和 `DispatchGameplayEvent` 行为保持兼容，新入口只用于
生产热路径和可控 benchmark。

## 公共合同

`FAvidScriptWasmRuntimeInstance` 与 `FAvidScriptRuntimeSession` 增加：

- `TickHot`
- `DispatchEventHot`
- `DispatchGameplayEventHot`

三者共同遵守：

1. 成功时不读写 `OutFailure`，调用方可以复用一个长期存活的结果对象；
2. 失败时重建完整 Runtime 快照，并填充 module、export、category、message、
   import 与 diagnostic frames；
3. operation guard、生命周期检查、typed callback epoch、trap 后 fault、timer
   callback 和 optional typed export 语义不变；
4. `FailureOnly` 保留原有兼容语义，新的 `HotFailureOnly` 不冒充旧入口。

## 执行核心

VM export 调用被拆为两层：

- `InvokeVmExport` 只接收固定 cell frame 并返回 `FAvidScriptVmError`，成功时不接触
  `FAvidScriptWasmSmokeResult`；
- `CallVmExport` 是兼容包装层，失败时调用 `SetFailureFromVmError`。

热路径直接进入 `InvokeVmExport`。Tick 中的 timer callback 也使用相同错误返回
合同，避免 timer 成功时隐式依赖结果对象；任何 timer trap 仍标记 Runtime faulted，
并报告 `avid_on_timer`。

## 观测分层

新增两种显式观测：

- `FAvidScriptWasmHotSnapshot`：不含 `FString`、`TArray` 和 binding 大对象，只携带
  Runtime 状态、Tick/timer/event 计数及 timing metrics；
- `CaptureSnapshot` / `CaptureLiveSnapshot`：在非计时区间按需生成完整结果。

`UAvidScriptComponent::TickComponent` 使用标量生命周期查询、`TickHot` 与 POD
snapshot，不再在每帧成功路径复制 Session module string 和完整 smoke result。

benchmark 的 `callback_empty` 与 `callback_tick` 在计时区间内只调用 Session 热入口；
计时结束后由 `CollectCallbackWorkload` 采集一次完整快照，以维持 checksum、host
import、binding instrumentation 和 data bridge 的真实性。

## 失败与兼容性

- 无 Runtime、非 Running、非法 payload、缺失必需 export、host import failure 与
  trap 都会物化完整失败结果；
- 非法 event payload 不会把健康 Runtime 标记为 faulted；
- VM trap 仍会将 Runtime 标记为 `Faulted`；
- typed GameplayEvent 缺失 optional export 时仍是成功 no-op，且热结果保持不变；
- WAMR 继续走 normal backend call fallback，Wasmtime 使用 P56.2 prepared export。

## 测试与门禁

新增自动化覆盖：

- WAMR/Wasmtime Tick 与 Event 热成功不改写哨兵；
- POD snapshot 的 Tick/Event 计数；
- typed GameplayEvent 热成功；
- 非法 payload 的完整诊断与健康生命周期；
- trap 的 category、export、生命周期快照与 fault；
- Session 热 Tick、完整 snapshot、reload 后热 Tick 和 unload 后失败诊断。

现有 Component Tick/reload 自动化会直接覆盖新的生产入口。架构脚本新增合同，禁止
组件退出热 Tick/POD snapshot 路径；benchmark 静态合同要求计时内使用热入口并在
计时后采集完整结果。

UE5.8 UBT、Automation 和正式 benchmark 按阶段工作流留到 P56.5 统一执行。
