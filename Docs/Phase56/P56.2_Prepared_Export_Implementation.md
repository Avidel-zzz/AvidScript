# P56.2 Prepared Export 实现记录

> 状态：实现完成，等待 Phase 56 阶段末统一 UBT、Automation 与 benchmark 验收。

## 1. 目标

P56.2 消除 lifecycle callback 每次进入 VM 前重复执行的 backend identity、slot、
generation、export table 查找和 ABI 元数据读取。公共合同保持后端中立，不向 Runtime
暴露 Wasmtime 或 WAMR 私有类型。

## 2. 公共合同

`AvidScriptVM` 新增 `FAvidScriptVmPreparedExportCall`：

- `Owner`：后端实例；
- `Target`：后端拥有的稳定 export entry；
- `InvokeFunction`：后端中立函数指针；
- `ParameterCellCount` 与 `ResultCellCount`：resolve 时冻结的 ABI 元数据；
- `Call`：面向诊断和测试的安全调用入口，检查初始化状态与参数 cell 数。

`IAvidScriptVmBackend::PrepareExportCall` 在 export resolve 后执行一次。Runtime 使用
`FAvidScriptCachedVmExport` 同时保存原始 handle 与 prepared call：prepared 可用时走
直接入口，不可用时继续使用原有 `Call`。

## 3. Wasmtime 实现

Wasmtime export entry 改为 `TUniquePtr` 稳定分配。容器扩容不会改变 `Target` 地址；
unload 时只释放当前 generation 的 Wasmtime function，并保留无 function 的轻量
tombstone，使旧 prepared target 在 reload 后可以安全返回 `stale_export`，不会访问
已释放 entry。

普通 `Call` 和 prepared call 最终进入同一个 `InvokeResolvedExport`：

- 保留 `ActiveCallDepth` 与 deferred unload；
- 保留 host import failure 的 module/name/details；
- 保留 trap、structured stack frame 与 result cell 校验；
- prepared 路径只保留 loaded、generation 和 function-active 三项生命周期检查；
- Runtime 的可信热路径直接调用冻结函数指针，不重复 handle 与 slot 校验。

历史 tombstone 不参与 unload 扫描；卸载只遍历当前 `ExportNameToIndex`，避免 reload
次数增加后放大卸载成本。tombstone 随 backend 对象析构统一释放。

## 4. WAMR 与移动端

WAMR 返回稳定类别 `prepared_export_unsupported`，并保证 `OutCall` 为空。Runtime
只在 resolve 时尝试一次 prepare，后续直接回退 generic `Call`，不会在每帧重复探测。
因此 PC Wasmtime 可以先获得优化，同时移动端/WAMR 行为保持兼容。

## 5. 测试代码

已增加以下测试合同，统一在 P56.5 执行：

- Wasmtime void、Tick 与 i32 result prepared 调用；
- prepared 参数 shape 错误返回 `invalid_arguments`；
- unload 后旧 prepared target 返回 `stale_export`；
- prepared trap 保留结构化 stack frame；
- prepared callback 内 reentrant unload 保留 `reentrant_unload`；
- WAMR 明确 unsupported，generic `Call` 继续成功。
