# Phase 56 融合调用帧架构

> 状态：已冻结

## 1. 阶段目标

Phase 56 承接 `P55-D01` 与 `P55-D02`，在不缩减普通 `UFUNCTION` 反射覆盖、
对象生命周期、热重载和事务回滚语义的前提下，继续压缩 Generated S1 与 lifecycle
callback 的完整固定成本。

本阶段不增加手写 UE API 表，也不通过只对 benchmark fixture 特化的入口换取数字。
所有优化必须作用于 descriptor 生成的通用 shape。

## 3. 已排除方案

### 3.1 Guest memory call-frame ABI

让 C# guest 把参数帧地址传给一个统一 import，可以减少 typed import shape 数量，但会
同时修改 C# backend、WASM ABI、生成器、VM memory borrow 和所有兼容 fixture。
Phase 56 的主要剩余成本位于 Host 证明链，不需要先承担 ABI 迁移风险，因此不采用。

### 3.2 全量 command buffer

Data-Oriented lane 已证明批量写入有效，但自然游戏逻辑仍需要同步返回值、错误传播和
普通方法调用。command buffer 保持可选吞吐 lane，不替代 Generated S1。

### 3.3 Wasmtime 盲目调参

当前 Wasmtime 45 已固定 Cranelift `speed`，component model 关闭，fuel 与 epoch
interruption 未启用。P50 已接近 V8，不能在没有消融证据时引入非默认 flag 或降低
安全边界。

## 4. 选定架构

### 4.1 Callback-epoch fused host cell

`FAvidScriptPreparedGeneratedHostCall` 从“binding 指针容器”升级为 callback-epoch
调用单元。它保存：

- Runtime 与 prepared binding 身份；
- 已冻结的 typed target 与 effect policy；
- 最近一次有效 callback epoch；
- 已证明的 Self handle；
- callback 内借用的 receiver；
- fast-hit、revalidate 和 journal-slow-path 计数。

每次 guest callback 都有唯一非零 epoch。某个 call cell 在该 callback 第一次命中时
执行完整证明：

1. Game Thread、Runtime 与 binding package 有效；
2. generated lease 仍 active，shape 与 typed target 一致；
3. Self slot/generation 等于 owner capability；
4. receiver 有效，class 与 world 匹配；
5. 写策略允许当前 effect；
6. 无 journal 的 read/write 可进入 Direct，带 journal 的写入标为 Journaled。

同一 callback 的后续调用只检查 epoch、Self handle 与 `IsValid(receiver)`，然后直接
调用 frozen typed target。class、world、lease 和静态策略不再重复判断。

callback 结束后不需要遍历清理所有 cell；下一次 callback 的 epoch 不匹配会自然
触发重新证明。Runtime unload、reload 或 package replacement 会先释放整个 cell
集合，因此旧 receiver 不会跨实例使用。

### 4.2 Effect policy

冻结四种 effect mode：

- `Rejected`：加载期或首次证明不满足策略；
- `DirectRead`：不要求写权限，不需要 journal；
- `DirectWrite`：要求写权限，Host 允许写且没有 journal；
- `Journaled`：每次 effect 仍调用现有 `PrepareGeneratedHostEffect`，保持事务快照顺序。

不能把 Journaled 写入的 prepare 缓存为一次，因为一次 callback 内可能有多次具有
不同旧值和回滚顺序的写入。

### 4.3 Prepared VM export

在 `AvidScriptVM` 公共合同新增后端无关的 `FAvidScriptVmPreparedExportCall`：

```cpp
using FAvidScriptVmPreparedExportInvoke = bool (*)(
    void* Owner,
    void* Target,
    const FAvidScriptVmCallFrame& Frame,
    FAvidScriptVmError& OutError,
    FAvidScriptVmCallResult* OutResult);

struct FAvidScriptVmPreparedExportCall
{
    void* Owner = nullptr;
    void* Target = nullptr;
    FAvidScriptVmPreparedExportInvoke Invoke = nullptr;
    uint32 ParameterCellCount = 0;
    uint32 ResultCellCount = 0;
};
```

Wasmtime 在 export resolve 后返回稳定 entry 作为 `Target`。entry 改为稳定分配，避免
`TArray` 扩容使 target 失效。prepared invoke 跳过 backend identity、slot、generation
和重复 frame shape 检查，但保留 active-call depth、deferred unload、host failure、
trap 和 stack frame 诊断。

WAMR 和其他 backend 可以返回 unsupported，Runtime 自动回退现有 `Call`。这保持
PC-first，同时不破坏移动端路径。

### 4.4 Lifecycle hot result

现有 `Tick` 与 `TickLive` 的成功可观测合同保持兼容。新增生产专用
`TickHot` 路径：

- 成功时只返回布尔状态并更新 Runtime 内部计数；
- 不复制 `FString`、backend identity、metrics 和诊断数组；
- 失败时物化完整 `FAvidScriptWasmSmokeResult`；
- `UAvidScriptComponent` 使用 `TickHot`；
- benchmark callback lane 使用同一生产入口。

公共诊断调用仍可使用 `Tick` 获取完整成功快照。

## 5. 失效与安全

- callback 外禁止使用 fused receiver；
- nested callback 使用栈顶 epoch，外层再次调用时会重新证明；
- `IsValid(receiver)` 每次 fast hit 保留，防止 callback 内 Destroy 后继续调用；
- active guest call 期间 Session mutation 与 unload 仍由现有 guard 拒绝或延迟；
- package unregister 会使 lease inactive，下一 callback 首次调用拒绝；
- reload replacement 创建新的 Runtime/cell 集合，不复用旧 target；
- Journaled effect、对象 ownership 与 semantic reflection fallback 不改变。

## 6. 模块边界

| 模块 | 职责 |
| --- | --- |
| AvidScriptCore | 只保存跨模块枚举或 POD，不依赖 UE Runtime |
| AvidScriptBindings | prepared binding 与 effect mode 推导，不持有 VM |
| AvidScriptVM | prepared export 合同与 backend 实现，不感知 UObject |
| AvidScriptRuntime | callback epoch、receiver 证明、host cell 与 lifecycle 编排 |
| AvidScriptEditor | 只在 descriptor/shape 变化时调整生成器 |
| Benchmark Harness | 分段计数、消融 profile 和正式 competitor Gate |

不得把 Wasmtime 类型暴露到 Runtime，也不得把 UObject 类型引入 VM 公共合同。

## 7. 性能测量顺序

1. 静态检查确认生产路径不含逐调用字符串构造和 descriptor 查找；
2. physical ladder 分离 generic export、prepared export、typed empty、首次 cell prove、
   fused fast hit、journal slow path；
3. diagnostic profile 运行 `1 process x 5 samples`，确认总时长和计数；
4. micro 正式矩阵；
5. gameplay 正式矩阵；
6. 相同 WASM controlled-runtime P50/P95；
7. 集中 evaluator 同时执行绝对 ns、Puerts ratio、防回退和 provenance Gate。
