# P56.4 分段 Profiling 与消融实现记录

> 状态：实现完成，等待 P56.5 集中执行 UE5.8 构建、Automation 和正式 benchmark。

## 1. 目标

P56.4 为 Phase 56 的融合调用帧建立可审计的性能证据，回答以下问题：

- prepared export 相比通用 export 实际消除了多少 VM 调用固定成本；
- typed host import、动态 host import 和带参数 import 分别增加多少成本；
- generated S1 与 data-oriented lane 是否真正命中 fused fast path；
- callback 内是否只发生一次 receiver 重新证明；
- benchmark 是否意外进入 Journaled 慢路径；
- hot lifecycle result 相比完整结果物化减少多少固定成本。

这些指标用于定位瓶颈，不替代 AvidScript 与 Puerts 的同机六通道正式对比。

## 2. Physical Cost Ladder v2

物理成本阶梯升级为 schema v2，共七个 rung：

1. `native_no_op`
2. `guest_loop_baseline`
3. `generic_export`
4. `prepared_export`
5. `typed_empty_import`
6. `generic_empty_import`
7. `typed_i32_pair_import`

`generic_export` 与 `prepared_export` 使用同一 Wasmtime backend、同一模块、同一
`run_cached` export、同一进程和同一 seed。prepared target 在计时前解析一次，
计时窗口只包含重复调用。runner 同时发布真实 `export_call_count` 和
`host_import_count`，原生 rung 的 export 数为 0。

每个进程按相同 `sample_index + seed` 做配对子减法，再跨进程聚合配对增量：

- generic export - prepared export；
- typed empty import - guest loop；
- generic empty import - typed empty import；
- typed i32 pair import - typed empty import。

报告同时发布 `baseline + paired delta` 对 observed P50 的重建误差。Phase 55 中把
AvidScript P95 与 Puerts P50 混合计算的 `typed_empty_explained_ratio` 不再用于
Phase 56；内部归因和跨框架比较保持为两条独立证据链。

## 3. Fused Path 真实性计数

process result 新增六项累计增量：

- `generated_fused_fast_hit_count`
- `generated_fused_revalidate_count`
- `generated_fused_call_site_prepare_count`
- `generated_direct_read_prepare_count`
- `generated_direct_write_prepare_count`
- `generated_journal_slow_path_count`

generated S1 与 data-oriented lane 必须满足：

- 一个 observation 只重新证明 receiver 一次；
- 其余调用全部为 fused fast hit；
- direct read/write prepare 总数等于 call-site prepare 总数；
- Journaled 慢路径计数为 0。

semantic、native 和 Puerts lane 的以上计数必须全部为 0。runner 与 evaluator
分别复验同一合同，防止只依赖 benchmark 内部的单点判断。

## 4. Lifecycle Result 消融

六通道 request 新增 `callback_result_mode`：

- `hot_failure_only`：正式档使用，成功时只更新 POD hot snapshot；
- `full_snapshot`：诊断消融档使用，保留每次调用后的完整结果物化。

P56 正式 micro/gameplay profile 默认锁定 `hot_failure_only`，另提交
`Phase56Micro.full-result.diagnostic.json`。结果采集和 instrumentation snapshot
均位于计时窗口外。

## 5. Phase 56 Gate

Phase 56 在原有跨框架绝对值、ratio 和 gameplay 防回退 Gate 之外新增：

- `prepared_export_ratio`
- `physical_reconstruction_error_ratio`
- `typed_empty_net_ns`
- `fused_fast_hit_ratio`
- `fused_revalidate_per_callback`
- `direct_effect_prepare_count`
- `journal_slow_path_count`

`fused_fast_hit_ratio` 的分母由实测 `fast + revalidate` 重建，不复用 data lane
中语义不同的 S1 总命中数。P56 evaluator 对空 fused 测量直接失败，不生成 NaN
或伪造通过结果。
