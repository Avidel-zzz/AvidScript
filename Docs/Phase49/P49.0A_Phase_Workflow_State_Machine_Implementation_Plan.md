# P49.0A 阶段状态机与关闭门禁实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立不依赖聊天上下文的 Phase 状态、债务、Gate evidence 和 Close 门禁，使 Phase 49 后续批次能够自举执行新流程。

**Architecture:** tracked state 只记录可提交的阶段事实，昂贵 Gate 先验证冻结提交并生成不可变外部证据；随后只允许一个文档/evidence attestation commit。Close 校验冻结提交、Gate report 和 attestation diff，任何源码变化都会使 Gate 失效。

**Tech Stack:** PowerShell 7/Windows PowerShell 5 compatible subset、JSON Schema 2020-12、Git、SHA-256、现有 AvidScript PowerShell contract harness。

```powershell
./Build/InvokePhaseWorkflow.ps1 start -Phase 49 -Goal <text> -ArchitecturePath <path> -PlanPath <path> -CloseoutPath <path> -BatchId P49.1,P49.2,P49.3,P49.4

./Build/InvokePhaseWorkflow.ps1 debt-update -Phase 49 -DebtId P49-D001 -Status Verified -Evidence <text>

./Build/InvokePhaseWorkflow.ps1 freeze -Phase 49 -ReviewEvidence <text>
./Build/InvokePhaseWorkflow.ps1 attest -Phase 49 -GateReportPath <path>
./Build/InvokePhaseWorkflow.ps1 close -Phase 49
./Build/InvokePhaseWorkflow.ps1 reopen -Phase 49 -Reason <text>
```

### 状态

Tracked stage：

```text
absent -> implementing -> gate_ready -> gate_attested
                    ^             |
                    +--- reopen --+
```

Effective stage 由 tracked state 与外部 evidence 推导：

```text
gate_ready + passing gate report = gate_passed
gate_attested + passing close validation = closed
```

## Task 3：Gate Evidence、Attestation 与 Close

**Files:**
- Create: `Build/PhaseWorkflow/AvidScriptPhaseEvidence.ps1`
- Modify: `Build/InvokePhaseWorkflow.ps1`
- Modify: `Docs/Workflow/Phase_Gate_Evidence.schema.json`
- Test: `Tools/AvidScript.CSharpFrontend.Tests/PhaseWorkflowContractTests.ps1`

**Interfaces:**
- Produces: `Test-AvidScriptGateEvidence`、`Test-AvidScriptAttestationDiff`、`Test-AvidScriptPhasePrivacy`、`Invoke-AvidScriptPhaseClose`。
- Gate input: immutable JSON with producer/version、phase/run、verified commit/tree、state hash、checks、counts、logs/artifact hashes、budgets、completion marker。

- [x] **Step 1: 建立敌对 evidence fixtures**

覆盖错误 commit/tree、篡改 state hash、缺失 completion marker、非零 exit、zero-test Automation、found/completed/succeeded 不一致、Queue Empty/TestExit/request exit 缺失、超预算无风险理由和日志 hash 错配。

- [x] **Step 2: 实现 Gate report 验证**

每个 required check 必须完整、passed、exit 0。Automation 额外要求：

```text
found = completed = succeeded > 0
failed = not_run = 0
queue_empty = true
test_exit = true
request_exit_status = 0
process_exit_code = 0
```

- [x] **Step 3: 实现 attestation commit 模型**

`freeze` 记录执行状态转换前已经提交的源码 commit/tree；提交 `gate_ready` state 后形成 Gate verified candidate。Gate 后 `attest` 只允许更新：

- 当前 Phase state；
- 当前 Phase closeout；
- 当前 Phase 的归一化 Gate summary。

State 保存可提前确定的 `attestation_parent`，真实 attestation commit 由 Close 从 `HEAD` 推导并写入外部证据，避免 commit 自引用。Close 证明 attestation commit 的父提交等于 Gate verified commit，且 diff 不包含 Source、Build、Tools、Tests、Config 或插件描述文件。任何代码变化要求重新 Gate。

- [x] **Step 4: 实现隐私、dirty 和 commit-range 检查**

- 使用 `start_commit..HEAD` 扫描，不读取整个历史；
- 拒绝私钥、token、credential 扩展、本机账户绝对路径和 tracked 生成目录；
- 只运行 commit-range/path-scoped whitespace gate；
- 当前两份 protected dirty 必须未暂存、未进入 Phase commit range、内容与 start baseline 一致；
- index 必须为空。

- [x] **Step 5: 实现 Close**

Close 验证没有开放 Blocker/Critical/Important；Normal 只能 Verified 或带 target phase/reason 的 Transferred。成功在外部 Gate 目录写 immutable close evidence，不修改已验证 tracked tree。
