# P49.2 缓存类引用实现结果

## 结论

P49.2 已完成。项目 profile 中的 `class_references` 现在会进入 descriptor schema v5、内容寻址身份、生成式 C# facade、Guest IR 和 Runtime immutable package plan。Runtime 在加载 package 时一次性解析并校验 UClass，之后可按 ordinal 进行 O(1) 查询，不在 Tick 或调用热路径执行字符串查找、JSON 解析或反射遍历。

本批次完成的是“类值与缓存类计划”，还没有提供 `SpawnActor`、`DestroyActor` 或 `IsA`。这些 World/object lifecycle API 属于 P49.3。

## Descriptor Schema v5

schema v5 新增 `class_references`：

```json
{
  "stable_id": "<sha256>",
  "ordinal": 0,
  "script_name": "ProjectileClass",
  "class_path": "/Game/Blueprints/BP_Projectile.BP_Projectile_C",
  "base_class_path": "/Script/Engine.Actor",
  "load_policy": "EditorLoad"
}
```

类引用按 stable ID 排序并分配连续 ordinal。stable ID 由 class path、base class path 和 load policy 生成；脚本别名不改变类身份，但会进入 selection/package hash，因此重命名不会被内容寻址缓存静默忽略。

v5 package hash 覆盖完整类型、binding、默认值、ABI 和 class table。旧 schema v2-v4 的 hash 算法保持兼容。v5 还允许“零 reflected binding + 非空 class table”的独立 package，使只使用 `ProjectClasses` 的脚本不必为了通过 slice 人为引入一个 UFunction。

## Runtime Immutable Plan

package load 现在会：

- 规范化加载 class path 与 base class path，并校验加载结果的真实 path；
- 验证目标类与基类均继承自 `AActor`，且目标类满足 base constraint；
- 拒绝 abstract、not-placeable、deprecated 和 superseded class；
- 在非 Editor target 拒绝 `EditorLoad`；
- 对缺失的 `CookRequired` class 返回稳定的 `binding_class_cook_missing`；
- 用强 UObject anchor 保持已验证 UClass 生命周期；
- 生成与 descriptor ordinal 对齐的只读数组。

成功加载后，`TryResolveClassReference(ordinal)` 只执行数组边界检查和直接索引。class ordinal 与动态 UFunction import ordinal 是两个独立命名空间，不增加 WAMR host import，也不占用 UObject slot/generation。

## 生成式 C# API

存在 class table 时，facade 会生成：

```csharp
[StructLayout(LayoutKind.Sequential)]
public readonly struct TSubclassOfAActor
{
    private readonly int Ordinal;
    internal int AvidScriptOrdinal => Ordinal;
}

public static class ProjectClasses
{
    public static TSubclassOfAActor ProjectileClass => new(0);
}
```

`ProjectClasses.ProjectileClass` 完全在 Guest 内构造，不发生 host crossing。它不是 `AActor` handle，也没有从任意 `int` 或 UObject handle 的隐式转换。

`ProjectClasses` 被保留为生成容器名；profile 若把类别名声明为该名称，descriptor generator 会以稳定的 `class_reference_invalid` 在发布前失败，避免把错误产物推迟到 Roslyn 编译阶段。

## Guest IR 与 WASM

`TSubclassOfAActor` 被 lower 为 nominal `class_ref`，底层存储仍是一格 i32。该设计保留 WASM 的紧凑 ABI，同时让 validator 能区分普通整数、对象 handle 和 class ordinal。

- 只接受生成结构的单个 private readonly `Ordinal` 字段布局；
- 只接受生成构造器中的非负整数字面量；
- 同类型 Roslyn conversion 降为 `copy`，不会伪装成跨类型 cast；
- 唯一允许的投影是 `class_ref_ordinal`；
- 普通 `int -> class_ref`、`class_ref -> int` 和 `class_ref -> object handle` conversion 均失败关闭；
- WasmBackend 继续复用 i32 constant 路径，不增加专用运行时调用。

## 生成与发布闭环

class table 已贯穿以下链路：

```text
C# profile
  -> ProjectBindingProfile resolver
  -> CSharpBuildRequest
  -> authorization descriptor/facade
  -> Roslyn semantic + Guest IR
  -> used-import binding slice
  -> runtime descriptor
  -> immutable UClass plan
```

binding slice 会保留完整 class table，即使 bootstrap 没有产生普通 reflected imports。canonical regeneration、内容寻址 package 复用和 manifest 的 `class_reference_count` 使用同一份 descriptor model。

## 验收结果

| 项目 | 结果 |
| --- | --- |
| Architecture gate | 通过 |
| 固定 .NET SDK | 8.0.416 |
| Guest IR tests | 32/32 |
| C# Guest tests | 45/45 |
| .NET format verification | 通过 |
| UE5.8 no-clean target build | Bindings、Runtime、Editor 编译与链接通过 |

| Queue Empty / TestExit / 进程退出码 | 均确认，退出码 0 |

首轮三个非成功项不是 class plan 执行错误：一个是 schema v5 identity 导致的共享 FName fixture 哈希更新，两个是旧 metadata tamper 测试被更外层 package hash 提前拒绝。fixture 更新后，防御纵深测试会重算合法 hash，继续证明内层 reflection contract 独立拒绝伪造 metadata。

## 当前可用边界

现在脚本可以引用生成的项目类值，并让它通过 C# semantic、Guest IR、WASM 与 runtime package load。Runtime 已具备安全、缓存的 UClass ordinal 查询基础。

脚本还不能用该值创建或销毁 UE Actor。P49.3 将注入 World context，并在 class plan 之上实现 `SpawnActor`、`DestroyActor`、`IsA`、handle 注册/失效和 candidate reload 副作用拒绝。
