# P49.3 World 与对象生命周期实现结果

## 结论

P49.3 已完成从生成式 C# facade 到 UE5.8 `UWorld` 的对象生命周期闭环。脚本现在可以使用 P49.2 的缓存 class reference 动态创建 Actor、按缓存类计划执行 `IsA`、销毁 Actor，并继续把返回的 `AActor` 句柄传给普通生成式 reflected API。

这三个能力是共享的 capability family，不是三个项目 API 特例。普通 `UFunction` 仍由 profile、descriptor、C# facade 和缓存 `ProcessEvent` plan 自动覆盖；Runtime 与 WAMR private backend 没有新增逐函数 wrapper。

## C# 使用方式

当 profile 声明至少一个 `class_reference` 时，生成 facade 会提供：

```csharp
public static class UE
{
    public static AActor SpawnActor(TSubclassOfAActor actorClass, FTransform transform);
    public static bool DestroyActor(AActor actor);
    public static bool IsA(AActor actor, TSubclassOfAActor actorClass);
}
```

脚本可以直接写：

```csharp
FTransform spawnTransform = new(
    new FVector(200.0f, 0.0f, 120.0f),
    FRotator.Zero,
    new FVector(1.0f, 1.0f, 1.0f));

AActor projectile = UE.SpawnActor(ProjectClasses.ProjectileClass, spawnTransform);
bool isProjectile = UE.IsA(projectile, ProjectClasses.ProjectileClass);

projectile.SetActorLocation(new FVector(500.0f, 0.0f, 120.0f));
bool destroyed = UE.DestroyActor(projectile);
```

`ProjectClasses.ProjectileClass` 是一格 class ordinal；`AActor` 是 slot/generation 两格对象句柄。两者在类型系统和 ABI 中保持分离，没有 `int`、raw pointer 或 `IntPtr` 的隐式转换。

## 共享生命周期 ABI

`AvidScriptBindings` 现在拥有唯一的生命周期规格表：

| 能力 | import | ABI | crossing |
| --- | --- | --- | --- |
| Spawn | `avidscript.avid_object_spawn_actor` | class ordinal、36-byte transform 地址、handle 输出地址 | 1 |
| Destroy | `avidscript.avid_object_destroy_actor` | slot、generation | 1 |
| IsA | `avidscript.avid_object_is_a` | slot、generation、class ordinal | 1 |

stable ID、module、import name、signature 和顺序由同一规格同时驱动 Runtime package、C# emitter、manifest 与授权切片。生命周期 ordinal 连续追加在 reflected binding ordinal 之后；没有 class table 的 package 不发布这些能力。

## Runtime 设计

### World 注入

`UAvidScriptComponent` 从 owner 注入 weak `UWorld`。`RuntimeSession` 还会在调用方只提供 owner handle 时从 registry 中恢复 World，并把它转交给动态 binding invocation context。

每次生命周期调用都先验证 World 存活且未进入 teardown。脚本不能传入 World 指针，也不能跨 World 销毁 Actor。

### SpawnActor

Spawn 热路径执行以下固定步骤：

1. O(1) 读取 immutable class plan；
2. 从 Guest Memory 读取固定 9 个 `float`，重建 UE `FTransform`；
3. 在注入的 World 中使用 `AlwaysSpawn` 创建 Actor；
4. 注册 generational object handle；
5. 将 slot/generation 写回 Guest。

class load、JSON 解析、字符串类名查找都不在调用热路径。句柄注册或 Guest 输出失败时会销毁新 Actor 并释放句柄，不留下半完成对象。

### DestroyActor 与 IsA

Destroy 先通过 registry 校验 slot/generation，再验证 Actor 属于当前 World。只有 `AActor::Destroy` 成功后才释放 handle，因此重复调用和旧 generation 不会访问复用 slot 中的新对象。

当前 runtime owner 的销毁以 `binding_destroy_owner_unsupported` 拒绝，因为它需要组件停机和事件路由的延迟关闭协议。普通 spawned Actor 不受影响。

`IsA` 只执行句柄解析和缓存 `UClass` 检查，不读取 Guest Memory。Spawn 直接返回 `AActor` proxy，因此可零 crossing 使用生成的 Actor facade。任意派生 UObject proxy 的通用静态向上转换仍需要 descriptor 提供可信继承链；本批次明确不根据类名或 class-reference base 猜测关系。

## 热重载安全

候选 runtime 带有 host-effect journal 时：

- Spawn 和 Destroy 以 `binding_reload_effect_unsupported` 失败关闭；
- `IsA` 保持只读可用；
- 旧 runtime、旧 Actor 和 registry 均不被候选脚本改写。

这样避免在没有完整补偿日志之前承诺不可恢复的 World 副作用。

## 授权与生成链路

class-reference package 的授权 import 数现在等于 reflected imports 加三个生命周期 imports。binding slice 会：

- 精确验证 lifecycle stable ID、ordinal、module、name 与 signature；
- 拒绝伪造 ordinal 或 ABI；
- 拒绝没有 class table 的 package 声明生命周期能力；
- 保留完整 class table，并在最小 runtime package 中重新发布共享能力。

C# emitter version 已升级为 `49.3.0`，descriptor 仍为 schema v5，因为生命周期能力是 package capability，不改变 class table 的数据格式。

首轮 Runtime focused 测试在进入生命周期派发前失败，原因是测试手写 descriptor 的 `source` 字段没有遵守共享 `ue_reflection` 合同。修正夹具并记录预防规则后，同一测试通过；生产 parser 未被放宽。

批次状态更新还发现 PowerShell 7 会把 ISO 时间字符串自动转成 `DateTime`，从而改写历史 state 时间字节。PhaseWorkflow 现已按 host 能力使用 `ConvertFrom-Json -DateKind String`，Windows PowerShell 5 保持原有字符串行为；跨 shell 夹具确认后续 batch 更新不会改变先前时间戳。
