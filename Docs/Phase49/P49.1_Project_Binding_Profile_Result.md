# P49.1 项目级 Binding Profile 实现结果

## 结论

P49.1 已完成。C# profile schema v2 现在可以声明项目所需的 UE 模块、显式反射类和 Actor class reference。解析结果会经过既有函数/属性选择策略，再通过窄化的 BuildRequest 进入 descriptor 与 C# facade 生成链路。

本批次没有把 class reference 写入 descriptor，也没有实现 SpawnActor。它只建立项目 API 授权与稳定身份；class table、Runtime immutable plan 和生成式 `ProjectClasses` 属于 P49.2。

## Profile 格式

```json
{
  "schema_version": 2,
  "language": "csharp",
  "source_path": "Plugins/AvidScript/Samples/CSharp/MyGame/MyScript.cs",
  "binding_profile": {
    "package_name": "avidscript.project.mygame",
    "module_paths": [
      "/Script/MyGame"
    ],
    "classes": [
      {
        "class_path": "/Script/Engine.Actor",
        "include_functions": [
          "K2_GetActorLocation",
          "SetActorScale3D"
        ],
        "exclude_functions": [
          "K2_SetActorLocation"
        ],
        "include_properties": [
          "CustomTimeDilation"
        ]
      }
    ],
    "class_references": [
      {
        "script_name": "ProjectileClass",
        "class_path": "/Game/Blueprints/BP_Projectile.BP_Projectile_C",
        "base_class_path": "/Script/Engine.Actor",
        "load_policy": "EditorLoad"
      }
    ]
  }
}
```

schema v1 保持兼容并默认使用 `EngineGameplay`。schema v1 如果声明 `binding_profile` 会失败关闭，避免字段被静默忽略。模板写入使用项目相对路径，不持久化开发者本机绝对路径。

## 实现内容

- 新增 `FAvidScriptProjectBindingProfileSpec`、`FAvidScriptProjectBindingClassSpec` 和 `FAvidScriptEditorProjectBindingProfile::Resolve`。
- `/Script/<Module>` 发现只扫描当前已加载的 UClass；显式 class path 通过 UE object loader 解析并规范化。
- include/exclude 列表、class rules、module paths 和 class references 均执行稳定排序、重复检查与冲突检查。
- class reference 在 Editor 侧验证标识符、load policy、继承关系、Actor 基类约束和抽象类限制。
- `load_policy` 缺失时默认 `EditorLoad`；字段存在但不是非空字符串时失败关闭。
- 函数与属性资格继续复用已有 BindingSelection/descriptor generator，没有复制 editor-only、类型 ABI 或属性策略。
- selection hash 包含 resolver version、当前 `UnrealEditor.modules` BuildId、规范化 profile、descriptor selection/package identity 和 class reference declaration。
- modules manifest 缺失时使用 `engine_build_id_unavailable` 失败关闭，不使用 engine version 猜测二进制兼容性。
- 新增 `FAvidScriptEditorCSharpBuildRequest`，把 JSON/schema 解析与 BuildPipeline 解耦；同步构建、异步热重载和旧执行器均使用同一请求合同。
- Emitter 新增通用 `EmitProfile`/`PublishProfile`，相同内容复用既有内容寻址目录，不重写 descriptor、facade 或 manifest。

合并 filter 覆盖 `AvidScript.Editor.ProjectBindingProfile`、`AvidScript.Editor.CSharpProfileService` 和 `AvidScript.Editor.BindingSelection`。其中包括：

- module path 自动发现；
- 显式 class include/exclude 与稳定排序；
- class path、class reference、重复 ScriptName 和稳定 identity 的失败关闭；
- editor-only member 继续由共享策略拒绝；
- 不同声明顺序得到相同 selection hash；
- schema v1/v2 兼容边界和严格 JSON 类型；
- Profile 结果实际进入 BuildPipeline；
- 相同输入复用同一内容寻址包，三个生成文件的冻结时间戳保持不变。

## 架构边界

```text
C# Profile JSON
    -> CSharpProfileService
    -> CSharpBuildRequest
    -> CSharpBuildPipeline
    -> CSharpBindingEmitter
    -> descriptor + generated C# facade + package manifest
```

BuildPipeline 不认识 profile schema、JSON 或 class reference 解析细节；BindingSliceService 仍只根据 bootstrap `used_imports` 从授权包裁剪 Runtime package。

## 下一批次

P49.2 将消费已经解析的 class references，扩展 descriptor schema，建立 package-load UClass immutable plan，并生成 C# `TSubclassOfAActor` 与 `ProjectClasses`。在 P49.2 完成前，class reference 只能被验证和参与稳定身份，脚本还不能使用它执行 SpawnActor。

因此，P49.1 中只修改 `class_references` 会改变 profile selection hash，但不会改变当前只包含 reflected members 的授权包内容；P49.2 必须在扩展 descriptor 的同一提交中把 class table 纳入 package hash 和 BuildRequest attestation。
