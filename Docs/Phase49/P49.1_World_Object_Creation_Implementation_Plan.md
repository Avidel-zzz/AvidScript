# Phase 49 世界与对象创建闭环实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让项目 C# 脚本通过生成式 class reference 和通用对象生命周期 ABI，在 UE5.8 World 中动态 Spawn、调用并 Destroy Actor，同时建立可重复性能基线。

**Architecture:** 普通项目 UFunction 继续复用 reflection descriptor 和 cached ProcessEvent plan；class reference 在 package load 时解析为不可变 ordinal plan；World 由 Runtime Session 注入；Spawn/Destroy/IsA 是三个按能力族生成的动态 binding kind，不新增逐 API WAMR wrapper。

**Tech Stack:** UE5.8 C++、UObject Reflection、C# Roslyn Semantic、Guest IR、WASM、WAMR、JSON descriptor、PowerShell build pipeline、UE Automation benchmark。

## Global Constraints

- 引擎固定为 `C:/UnrealEngine` 源码版 UE5.8，PC Win64 Editor 优先。
- 不执行 Editor Target clean；中途不重复完整 UE Automation。
- Phase 49 使用 3-5 个实现批次，普通失败记入债务，只有 Blocker/Critical 立即打断。
- 普通 UE API 必须由 profile/descriptor/facade 自动生成，不新增函数级 enum、native symbol 或 Runtime switch。
- WAMR API 和 native symbol 继续只存在于 `AvidScriptVM/Private`。
- VM public contract 不包含 UObject/UClass/UWorld 类型。
- Runtime 不重新解析 C#；Editor 不拥有 Runtime invocation 规则。
- 成功热路径不做名称查找、class load 或诊断字符串构造。
- benchmark 必须包含 Native 对照，未经同机同负载测试不得声称优于外部框架。
- 当前受保护用户文件不得暂存、修改或回退。

## Task 3：World Context 与 Spawn/Destroy/IsA

**Files:** P49.3 文件组。

**Interfaces:**
- Consumes: Task 2 class ordinal and package plan。
- Produces: `ObjectSpawnActor`、`ObjectDestroyActor`、`ObjectIsA` dispatch kinds and generated C# API。

- [x] **Step 1: 建立 Runtime 安全合同**

覆盖 invalid World、out-of-range ordinal、wrong base class、bad transform address、Spawn failure、stale handle、double Destroy、cross-world Actor、candidate reload rejection 和 slot reuse generation。

- [x] **Step 2: 注入 World**

Runtime Session 从 owner 获取 World 并以 weak reference 写入 invocation context。World invalid 时在进入 UE Spawn 前失败。

- [x] **Step 3: 实现 ObjectSpawnActor**

从 class plan 读取 UClass，从 Guest Memory 读取固定 36-byte Transform，调用 World Spawn，成功后注册 object handle，将 slot/generation 写回 Guest。失败不留下 handle。

- [x] **Step 4: 实现 ObjectDestroyActor**

Registry resolve 后检查 World 和 Actor state，Destroy 成功才 ReleaseHandle。重复/stale handle 不访问复用对象。

- [x] **Step 5: 实现 ObjectIsA 与安全基类转换**

动态 IsA 只做 handle resolve 和 cached UClass 检查。静态向上转换由生成 facade 复制 slot/generation，不产生 host crossing。

- [x] **Step 6: 热重载副作用保护**

HostEffectJournal 非空时 Spawn/Destroy 以 `binding_reload_effect_unsupported` 拒绝；IsA 保持只读可用。不得提前实现不完整回滚。

- [x] **Step 7: 批次验证与提交**

先运行 Runtime/ObjectLifecycle focused filter 和受影响 .NET host；批次结束执行 Bindings/Runtime no-clean build 一次。提交：

```text
feat(runtime): add world object lifecycle bindings
```
