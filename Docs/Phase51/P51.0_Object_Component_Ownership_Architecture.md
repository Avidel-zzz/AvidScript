# Phase 51 UObject/Component 所有权架构设计

> 状态：已批准。用户已授权 Phase 50 完成后自动规划并实施 Phase 51，不再设置逐步审批等待。
>
> 平台：UE5.8 源码版，Win64 Editor 优先；移动端、Cook 与 Shipping 延后。
>
> 主线：C# -> Roslyn Semantic -> Guest IR -> WASM -> WAMR -> UE。

## 1. 阶段目标

Phase 51 把 Phase 50 的 typed handle、object type graph 和通用 `UFUNCTION`
调用扩展为可用于实际游戏逻辑的 UObject/Component 闭环：

- 用声明式 profile 授权可构造 UObject 与 ActorComponent；
- 用一个通用 factory capability 创建对象，不为每个 UClass 手写 Host API；
- 显式表达 Outer、所有权、注册和 Session 清理策略；
- 查询 Actor 上已有的 typed Component；
- 创建、查找、Attach、Detach 和销毁动态 Component；
- C# 返回项目自定义 typed handle，保持 upcast 零 crossing；
- 热路径不按名称查找 UClass、UFunction、Component 或 factory；
- reload candidate 不得留下不可回滚的对象和组件副作用；
- Session stop 能确定性清理脚本拥有的对象，不能泄漏或误删 Engine/项目对象。

本阶段不是“手写更多 UE API”。普通 `UFUNCTION` 继续走 descriptor + cached
`ProcessEvent`，只有构造、所有权和 Attach/Detach 这类不能安全等价为普通
`UFUNCTION` 的跨生命周期能力进入固定 capability family。

## 2. 方案选择

### 2.1 采用：descriptor v7 factory policy + Session ownership domain

Profile 显式声明 factory policy，descriptor 发布确定性的 `object_factories`，
package load 将其解析为 immutable `UClass` plan。Bindings 负责通用构造语义，
Runtime Session 负责强引用与清理，VM 只看 language-neutral import spec。

优点：

- class identity、构造权限和 lifetime policy 分离；
- 新增项目 UClass 只改 profile，不改 VM enum 或 Runtime switch；
- factory ordinal、object type ordinal 和 class reference ordinal 各自单一职责；
- 可以在 package load 阶段验证 abstract、Outer constraint 和 component 规则；
- ownership domain 能跨 live runtime replacement 存活，reload 不会丢失所有权账本；
- 后续 Cook dependency、对象池和 deterministic component key 有稳定扩展点。

### 2.2 不采用：从 UClass 继承关系自动开放构造

仅凭 `IsChildOf` 推断 `NewObject` 或 `CreateComponent` 会把“类型可解析”误当成
“脚本有权限构造”。它无法表达 abstract、Outer、注册方式、Session cleanup 和
项目安全边界，也会让新增反射类型意外扩大脚本权限。

### 2.3 不采用：每种操作或每个类手写 wrapper

把 `NewObject<Foo>`、`CreateComponent<Bar>` 和每个 Component 查询写成独立
WAMR wrapper，短期简单但会复制校验、诊断、reload 和 ownership 逻辑，API
覆盖速度与维护成本都无法接近 Puerts/UnLua 的通用绑定模型。

## 4. Profile schema v4

```json
{
  "schema_version": 4,
  "language": "csharp",
  "source_path": "Plugins/AvidScript/Samples/CSharp/ComponentGameplay/ComponentGameplay.cs",
  "binding_profile": {
    "package_name": "avidscript.project.component_gameplay",
    "self_class_path": "/Script/MyGame.MyScriptActor",
    "module_paths": [
      "/Script/MyGame"
    ],
    "class_references": [
      {
        "script_name": "InventoryState",
        "class_path": "/Script/MyGame.InventoryState",
        "base_class_path": "/Script/MyGame.InventoryState",
        "load_policy": "EditorLoad"
      },
      {
        "script_name": "SensorComponent",
        "class_path": "/Game/Blueprints/BP_SensorComponent.BP_SensorComponent_C",
        "base_class_path": "/Script/MyGame.SensorComponent",
        "load_policy": "EditorLoad"
      }
    ],
    "object_factories": [
      {
        "script_name": "InventoryState",
        "class_reference": "InventoryState",
        "kind": "new_object",
        "outer_base_class_path": "/Script/CoreUObject.Object",
        "ownership": "session"
      },
      {
        "script_name": "SensorComponent",
        "class_reference": "SensorComponent",
        "kind": "actor_component",
        "outer_base_class_path": "/Script/Engine.Actor",
        "ownership": "session",
        "registration": "register_instance"
      }
    ]
  }
}
```

规则：

- `object_factories` 只允许 schema v4；旧 profile 出现该字段立即失败；
- `script_name` 在 factory 表内唯一，并且必须是合法 C# identifier；
- `class_reference` 必须引用同一 profile 中唯一 class reference；
- `new_object` 的类必须是 concrete、非 CDO-only UObject；
- `actor_component` 的类必须派生 `UActorComponent` 且非 abstract；
- `outer_base_class_path` 必须是 UObject class，并进入 object type closure；
- `actor_component` 的 Outer constraint 必须派生 `AActor`；
- v4 默认不自动开放任何 class reference 的构造权限；
- profile hash 覆盖 kind、Outer constraint、ownership 和 registration；
- v1-v3 的 canonical 字节与既有 hash 语义不变。

## 5. Descriptor schema v7

Root 增加：

```json
{
  "object_factories": [
    {
      "stable_id": "sha256-stable-id",
      "ordinal": 0,
      "script_name": "SensorComponent",
      "class_reference_id": "class-reference-stable-id",
      "kind": "actor_component",
      "outer_type_id": "object-type-stable-id",
      "ownership": "session",
      "registration": "register_instance"
    }
  ]
}
```

合同：

- factory ordinal 按 stable id 排序后从 0 连续递增；
- `class_reference_id` 必须存在，且其 result type 与 factory class 相容；
- `outer_type_id` 必须指向 descriptor v7 object type graph；
- `new_object` 只允许 `registration == "none"`；
- `actor_component` 只允许 `registration == "register_instance"`；
- schema v7 selection/package hash 覆盖完整 factory table；
- schema v2-v6 不出现 `object_factories`，hash 与 parser 行为保持兼容；
- descriptor 有 factory 时必须发布 object type graph 和 class reference table；
- duplicate、dangling reference、非连续 ordinal 和非法 enum 全部失败关闭。

## 6. Immutable factory plan

Bindings package load 将每项 factory 解析为：

```text
FactoryPlan
  ordinal
  kind
  UClass* object_class
  UClass* required_outer_class
  object_type_ordinal
  ownership_policy
  registration_policy
```

加载时完成：

- class reference ordinal 与 UClass 解析；
- `IsChildOf`、abstract、deprecated 和 Outer constraint 验证；
- Component kind 与 registration policy 一致性验证；
- object result type ordinal 解析；
- UClass 强引用锚定。

运行时 `Construct` 只执行 ordinal index、handle resolve、`IsA`、UE 构造与 registry
注册，不读取 class path、script name 或 JSON。

## 7. 模块边界

### 7.1 AvidScriptEditor

- 解析 profile v4；
- 解析和验证 factory selection；
- 生成 object type closure、descriptor v7 与 canonical hash；
- 生成 typed factory token、object type token 和 C# facade；
- 发布 v7 binding slice 与 authorization provenance。

### 7.2 AvidScriptBindings

新增独立对象构造能力族，不把逻辑继续塞进
`AvidScriptBindingInvocation.cpp`：

- `AvidScriptObjectFactoryPolicy`：descriptor enum、静态合同和 plan；
- `AvidScriptObjectFactoryBinding`：Construct/Release/FindComponent；
- `AvidScriptSceneAttachmentBinding`：Attach/Detach；
- `IAvidScriptObjectOwnershipDomain`：Bindings 到 Runtime 的最小 ownership 接口。

Bindings 依赖 CoreUObject/Engine，不依赖 WAMR、C# 或 Runtime Session。

### 7.3 AvidScriptRuntime

新增 `FAvidScriptSessionObjectOwnership`，由 `FAvidScriptRuntimeSession` 持有，而不是
由可替换的 `FAvidScriptWasmRuntimeInstance` 持有。

职责：

- 通过 `FGCObject` 或等价 UE GC bridge 强持有 session-owned UObject；
- 记录 Component 的 Actor、creation kind 和 cleanup authority；
- 只允许释放当前 Session 创建的对象；
- Session stop 逆序销毁动态 Component、释放 handle、解除 UObject 强引用；
- candidate runtime 与 live runtime 共用同一 ownership domain，但 candidate 的
  不可逆调用在 Bindings reload effect gate 前被拒绝；
- reentrant unload 继续遵守 Phase 50 operation lease。

### 7.4 AvidScriptVM

VM 只注册以下固定 language-neutral import：

```text
avid_object_construct(factory_ordinal, outer_slot, outer_generation) -> i64
avid_object_release(slot, generation) -> i32
avid_actor_find_component(actor_slot, actor_generation, object_type_ordinal) -> i64
avid_scene_component_attach(child_slot, child_generation, parent_slot, parent_generation, rules) -> i32
avid_scene_component_detach(child_slot, child_generation, rules) -> i32
```

返回 handle 的 import 使用 packed `i64`；低 32 位是 slot，高 32 位是 generation。
VM 不包含 UObject、UClass、Outer 或 Component 类型。

### 7.5 C# Frontend/Semantic/Guest IR

- factory token 与 type token 都是 generated nominal readonly struct；
- token 只包含一个 private `int Ordinal`；
- 只有 generated literal getter 可以构造合法 token；
- `UE.NewObject`、`UE.CreateComponent` 与 `UE.FindComponent` 通过 token 静态类型返回
  对应 typed handle；
- object/component upcast 继续使用 Phase 50 的 Guest 内复制；
- lowering 识别稳定 intrinsic identity，不根据方法显示名猜测；
- token 不能与 `int`、class reference 或 object handle 隐式转换。

## 8. C# 用户 API

```csharp
AMyScriptActor self = UE.Self;

UInventoryState inventory = UE.NewObject(
    self,
    ProjectFactories.InventoryState);

USensorComponent sensor = UE.CreateComponent(
    self,
    ProjectFactories.SensorComponent);

USensorComponent existing = UE.FindComponent(
    self,
    ProjectTypes.SensorComponent);

UE.AttachTo(
    sensor,
    self.RootComponent,
    EAttachmentRule.KeepWorld,
    weldSimulatedBodies: false);

UE.Detach(sensor, EDetachmentRule.KeepWorld);
UE.Release(sensor);
UE.Release(inventory);
```

`Release` 只接受当前 Session ownership domain 记录的对象。查询获得的现有 Component
可以被调用和 Attach，但不能通过 `Release` 删除。

## 9. 所有权与清理

### 9.1 普通 UObject

- 必须有显式有效 Outer handle；
- Outer 必须满足 factory cached constraint；
- Session ownership domain 强持有对象；
- Session stop 或显式 `Release` 解除强引用并释放 handle；
- Outer 本身不被当成 GC 强引用的替代品。

### 9.2 ActorComponent

创建顺序：

1. resolve Actor Outer；
2. `NewObject<UActorComponent>`；
3. `CreationMethod = Instance`；
4. `Actor->AddInstanceComponent`；
5. `RegisterComponent`；
6. ownership record；
7. object registry handle。

任一步失败时按逆序补偿，不发布有效 handle。

清理顺序：

1. 验证 ownership authority；
2. Detach（若为 SceneComponent）；
3. `UnregisterComponent`；
4. `Actor->RemoveInstanceComponent`；
5. `DestroyComponent`；
6. release registry handle；
7. remove ownership record。

外部已经销毁的 Component 视为幂等 cleanup，但 stale handle 仍返回稳定诊断。

## 10. Attach/Detach

- child 与 parent 必须是 live `USceneComponent`；
- 两者必须处于同一 World；
- 不允许 self attach 或制造 attachment cycle；
- rules 使用固定 bit field，不传字符串；
- Phase 51 支持 KeepRelative、KeepWorld、SnapToTarget 三种规则；
- socket name 固定为 `NAME_None`；
- active runtime 允许调用；
- candidate reload 中 Attach/Detach 返回 `binding_reload_effect_unsupported`；
- 后续若加入 attachment journal，再单独升级 reload effect。

## 11. Reload 与生命周期

- factory policy 属于 package identity；
- reload candidate 可以查询现有 Component，但不能 Construct、Release、Attach 或 Detach；
- candidate 失败不会改变 ownership domain；
- candidate 成功替换 live runtime 后，Session-owned 对象继续存在；
- Session EndPlay/Stop 清理 ownership domain；
- reentrant callback 中 Stop/Unload 继续延迟到最外层 guest call 返回；
- cleanup 不触发新的 Guest callback。

## 12. 失败关闭类别

| 场景 | 类别 |
| --- | --- |
| profile v1-v3 声明 factory | `binding_profile_factory_schema_unsupported` |
| factory 引用不存在 | `binding_profile_factory_class_reference_missing` |
| abstract class | `binding_factory_class_abstract` |
| kind 与 class 不匹配 | `binding_factory_kind_mismatch` |
| Outer constraint 不匹配 | `binding_factory_outer_type_mismatch` |
| factory ordinal 越界 | `binding_factory_ordinal_out_of_range` |
| 构造阶段失败 | `binding_object_construct_failed` |
| Component 注册失败 | `binding_component_register_failed` |
| release 非 Session 对象 | `binding_object_not_owned` |
| query Actor/类型无效 | `binding_component_query_invalid` |
| query 无匹配 | 成功返回 invalid handle |
| attachment cycle | `binding_attachment_cycle` |
| cross-world attach | `binding_attachment_world_mismatch` |
| candidate 不可逆调用 | `binding_reload_effect_unsupported` |
| stale handle | 复用 registry generation mismatch |

## 13. 性能预算

| 操作 | 预算 |
| --- | --- |
| factory/type token 获取 | 0 crossing |
| Construct | 1 crossing |
| FindComponent first match | 1 crossing，O(n components) |
| Attach/Detach | 各 1 crossing |
| Release | 1 crossing |
| factory resolve | O(1) ordinal |
| type resolve | O(1) ordinal |
| warm Construct | 0 class load，0 name lookup |
| ownership lookup | 平均 O(1) object key |
| typed upcast | 0 crossing |

FindComponent 的 O(n) 是 UE Actor component list 的真实成本；本阶段不建立易失缓存。
benchmark 必须单独报告 component count，不能用单组件 Actor 伪装规模无关。

## 15. 验收标准

1. 新项目 UObject/Component 只改 profile 即可进入 typed C# surface。
2. descriptor v7 的 factory table、hash 与 backward compatibility 稳定。
3. Construct/Find/Attach/Detach/Release 均没有逐类 Host wrapper。
4. 普通 UObject 在 Session 活跃期间不会被 GC，Stop 后可回收。
5. 动态 Component 正确加入 Actor、注册、查询和清理。
6. 不能 Release 非当前 Session 创建的对象。
7. candidate reload 不留下对象或 attachment 副作用。
8. warm path class load/name lookup 为 0。
9. typed upcast 保持 0 crossing。
10. 一个真实 C# 脚本在 BeginPlay/Tick 中使用该闭环。
11. 完整 Automation 无非成功结果。
12. 所有人读文档使用中文。
