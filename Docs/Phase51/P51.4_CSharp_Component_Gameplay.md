# P51.4 C# Component Gameplay 实现报告

## 1. 阶段结果

P51.4 已建立从 C# 到 UE5.8 SceneComponent 生命周期的可运行闭环：

- C# 可以按项目 profile 创建自定义 `USceneComponent` 派生组件；
- 可以按 typed object token 查询 Actor 上已有的项目组件；
- 可以执行 Attach/Detach，并在 Host 边界校验 World、循环、句柄与规则；
- Tick 可以调用项目自定义 `UFUNCTION`；
- EndPlay 可以显式 Release 脚本创建的组件；
- Session ownership 会注销、移除并销毁动态组件，不影响 Actor 原有组件；
- 整条链路不需要为项目 UClass 或 UFUNCTION 编写专用 WAMR wrapper。

## 2. C# 使用方式

真实样例位于：

- `Samples/CSharp/ComponentGameplay/ComponentGameplay.cs`
- `Samples/CSharp/ComponentGameplay/ComponentGameplay.csharp-profile.json`

核心写法如下：

```csharp
AAvidScriptTypedTestActor self = UE.Self;

UAvidScriptTypedTestSceneComponent existing =
    UE.FindComponent(self, ProjectTypes.GameplayComponent);

UAvidScriptTypedTestSceneComponent created =
    UE.CreateComponent(self, ProjectFactories.GameplayComponent);

UE.AttachTo(
    created,
    existing,
    UE.AttachmentRule.KeepRelative,
    false);

created.ApplyGameplayPulse(deltaSeconds);

UE.Detach(created, UE.DetachmentRule.KeepWorld);
UE.Release(created);
```

`ProjectFactories` 和 `ProjectTypes` 由 descriptor v7 自动生成。项目新增组件时，只需在 profile 中声明 class reference 与 factory，不增加 C++ Host API。

## 3. 生命周期行为

### BeginPlay

1. `UE.Self` 获取 typed Actor handle；
2. `UE.FindComponent` 查询 Actor 原有的 typed 根组件；
3. `UE.CreateComponent` 创建、加入 instance component 列表并注册组件；
4. `UE.AttachTo` 将动态组件挂接到查询得到的根组件；
5. 调用项目 Actor 的普通 `UFUNCTION`。

### Tick

1. 检查动态 typed handle 是否有效；
2. 调用项目组件的 `ApplyGameplayPulse(float)`；
3. 调用项目 Actor 的 `ApplyGameplayValue(float)`。

两个函数继续走 descriptor、cached `UFunction*` 与 `ProcessEvent`，没有逐函数 native wrapper。

### EndPlay

1. `UE.Detach` 解除挂接；
2. `UE.Release` 验证当前 Session ownership；
3. 注销组件；
4. 从 Actor instance component 列表移除；
5. 销毁组件并释放 registry handle。

查询得到的 Actor 原有组件不是 Session-owned，脚本不能用 `Release` 删除它。

## 4. Attach/Detach ABI

```text
avid_scene_component_attach (iiiii)i
avid_scene_component_detach (iii)i
```

Attach 参数依次为 child slot、child generation、parent slot、parent generation、rules。Detach 参数为 child slot、child generation、rules。

规则不传字符串，也不在热路径做名称查询：

| 位 | Attach 含义 |
| --- | --- |
| `0..1` | `0=KeepRelative`、`1=KeepWorld`、`2=SnapToTarget` |
| `2` | weld simulated bodies |
| 其余位 | 保留，出现即失败关闭 |

Detach 只接受 `0=KeepRelative` 与 `1=KeepWorld`。P51.4 的 socket 固定为 `NAME_None`。

## 5. 安全边界

Bindings 在调用 UE attachment API 前完成以下检查：

- child 和 parent 都必须解析为 live `USceneComponent`；
- slot/generation 必须属于当前 registry；
- child 与 parent 必须处于同一有效 World；
- 不允许 self attach；
- 不允许把父节点挂到自己的后代上形成循环；
- rules 中不能包含保留位或非法枚举值；
- Host context 必须允许写操作；
- candidate reload 中 Attach/Detach 在副作用前失败关闭。

主要稳定诊断类别：

| 场景 | 类别 |
| --- | --- |
| 跨 World | `binding_attachment_world_mismatch` |
| self/cycle | `binding_attachment_cycle` |
| 非法规则 | `binding_attachment_rules_invalid` |
| candidate reload | `binding_reload_effect_unsupported` |
| 陈旧 generation | `generation_mismatch` |

成功热路径调用 registry resolve 时显式关闭 object path，因此不会构造 UObject path 字符串。

## 6. 架构位置

- `AvidScriptBindings` 持有 attachment 规则、句柄解析和 UE 操作；
- `AvidScriptBindingInvocation` 持有 package ordinal 与统一 dynamic dispatch；
- `AvidScriptRuntime` 继续只注入 registry、ownership、World、write policy 与 reload journal；
- `AvidScriptEditor` 根据 concrete factory class graph 判断是否发布 attachment capability；
- C# binding slice 按固定顺序验证 reflected、lifecycle、object type、factory、attachment imports；
- VM/WAMR 只看到整数 ABI，不依赖 UObject 或 USceneComponent。

只有存在 `USceneComponent` 派生 factory 时，package 才发布两个 attachment imports；普通 `UActorComponent` factory 不扩大该能力面。
