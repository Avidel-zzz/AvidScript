# P51.2 Session 对象所有权域实现报告

## 1. 本批次位置

本报告记录 Phase 51.2 Task 4 与 Task 5 的完成结果。descriptor v7 factory plan、Session
ownership domain、通用对象操作和 WASM host ABI 已闭合；typed C# facade 与 lowering 属于 P51.3。

## 2. 已实现能力

1. 新增独立的 `IAvidScriptObjectOwnershipDomain`，接口由 Bindings 定义，实现由 Runtime 私有目录持有。
2. `FAvidScriptRuntimeSession` 独占 ownership domain；可替换的 WASM Runtime instance 只借用 HostContext 指针。
3. 普通 UObject 由 `FGCObject` 和 `TObjectPtr` 显式强持有，不依赖 Outer 偶然存活。
4. 动态 ActorComponent 记录 weak authority、创建 Actor、handle、factory kind 和逆序清理顺序。
5. ownership domain 首次 Adopt 时绑定唯一 registry，并验证 handle 必须解析到同一 UObject。
6. 显式 Release 只允许当前 Session 创建的对象；wrong handle、wrong registry 和外部对象均失败关闭。
7. Session Stop 与成功 EndPlay 会先结束 Guest 生命周期，再释放 handle、逆序销毁动态 Component、解除 UObject 强引用。
8. 外部提前销毁 Component 后，Session cleanup 仍会回收其 registry handle，不重复销毁组件。
9. active guest call 中的 Stop、SetHostContext 与 ClearHostContext 均不会销毁 ownership ledger。
10. WorldSubsystem 不再在 `StopAndUnload` 因重入被拒绝后直接 Reset Session，而是在最外层 Tick 返回后释放。
11. 新增独立 `AvidScriptObjectFactoryBinding`，不把 UE 对象构造逻辑继续堆入反射调用器。
12. `Construct` 只使用缓存 factory ordinal、Outer handle 与 immutable `UClass*` plan；热路径不解析 class path、JSON 或成员名。
13. UObject 构造后由 Session 强持有；ActorComponent 按 `NewObject -> RegisterHandle -> Adopt -> AddInstanceComponent -> RegisterComponent` 完成事务。
14. ownership 接口改为 handle-centric authority，即使 Component 已被外部提前销毁，也能按原 handle 回收账本与 registry slot。
15. `Release` 只释放当前 Session 创建的对象，查询或宿主提供的外部对象不能借句柄删除。
16. `FindComponent` 使用缓存 object type ordinal；命中时复用 registry handle，未命中是成功的空 handle，不触发 WASM exception。
17. dynamic raw host ABI 已同时支持 `i32` 与 packed `i64` 返回，旧 ABI 不变。
18. schema v7 且实际声明 factory 的 package 才追加三个 import；v2-v6 package 的 import 集合保持不变。

## 3. 架构约束

- registry 只负责 slot/generation 身份，不负责 GC 或对象销毁。
- ownership domain 声明顺序早于 LiveRuntime，因此 C++ 逆序析构时 domain 晚于 Runtime 销毁。
- Component 构造事务必须按 `NewObject -> RegisterHandle -> Adopt -> AddInstanceComponent -> RegisterComponent` 推进；后续任何步骤失败都要逆序补偿。
- reload candidate 与 live runtime 可观察同一 domain；effect gate 已在任何对象变更前拒绝 candidate 的 Construct/Release，FindComponent 查询仍允许。
- cleanup 先撤销 authority 与 handle，再调用 UE5.8 `DestroyComponent()`；不重复手写 Unregister 或 RemoveInstanceComponent。
- 返回对象 handle 的 import 使用 packed `i64`，低 32 位为 slot，高 32 位为 generation；C# 侧按无符号位模式解包。
- 工厂/type resolve 均为 ordinal 数组索引；warm path 的 class load 与 reflected name lookup 为 0。

## 4. 独立复审修复

只读复审在首版实现后指出四个高价值风险，现已处理：

| 风险 | 处理 |
| --- | --- |
| registry 与 handle/object 未绑定 | Adopt 绑定唯一 registry，并通过 registry 反解校验对象身份 |
| context mutation 可绕过 operation lease | active guest call/mutation 中拒绝 Set/ClearHostContext |
| domain 先于 Runtime 析构 | 调整成员声明顺序并增加析构 invariant |
| WorldSubsystem 重入后仍 Reset | 增加 deferred release，与 Component 释放模型一致 |
| 外部销毁后无法按对象指针释放 | authority 改为 handle-centric，并增加 O(1) handle 反向索引 |
| 动态 import 只支持 i32 返回 | attachment 缓存 result kind，raw callback 按 `i`/`I` 写回 |
| factory package 可污染旧 schema | 只对 schema v7 且非空 factory plan 发布三个 capability import |

## 6. 当前限制与下一步

UE/Bindings/VM 运行时已经能够执行 `avid_object_construct`、`avid_object_release` 和
`avid_actor_find_component`，但普通用户 C# 还没有 generated factory/type token，也没有把
`UE.NewObject`、`UE.CreateComponent`、`UE.FindComponent`、`UE.Release` lowering 到这三个 import。

P51.3 将完成 typed C# surface、semantic artifact、Guest IR 与 WASM lowering，并用真实生成的
C# WASM 验证 packed `i64` 端到端返回。P51.4 再加入 Attach/Detach 和 BeginPlay/Tick gameplay sample。
