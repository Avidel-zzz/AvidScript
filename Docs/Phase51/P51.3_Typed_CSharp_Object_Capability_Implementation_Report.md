# P51.3 强类型 C# 对象能力实现报告

## 1. 本批次位置

P51.3 将 P51.2 已可执行的通用对象 Host ABI 接入生成式 C# API、semantic lowering、Guest IR
和 WASM。完成后，项目只需在 profile 中声明工厂，不需要为每个 UObject、Component 或
UFUNCTION 新增 WAMR wrapper 或 Runtime switch。

## 2. 已实现的 C# API

生成 reference source 现在提供：

```csharp
UInventoryState state = UE.NewObject(
    outer,
    ProjectFactories.InventoryState);

USceneComponent component = UE.CreateComponent(
    actor,
    ProjectFactories.SceneComponent);

USceneComponent found = UE.FindComponent(
    actor,
    ProjectTypes.SceneComponent);

bool released = UE.Release(component);
```

- `ProjectFactories.*` 发布 descriptor `object_factories[].ordinal`。
- `ProjectTypes.*` 只为当前有查询消费者的 ActorComponent 工厂发布 object type ordinal。
- `NewObject`、`CreateComponent` 和 `FindComponent` 返回具体生成代理类型。
- `Release` 按具体返回类型去重 overload。
- factory/type token 构造器为 `internal`，没有公开构造器或到 `int` 的隐式转换。
- `FindComponent` 接收 canonical `AActor`，不被某个工厂的 required Outer 类型错误收窄。

## 3. 模块化生成器

新增独立的 `AvidScriptEditorCSharpObjectFactoryRenderer`，负责：

1. 校验三项通用 binding spec 的 kind 与 ABI；
2. 解析具体结果类型、Outer 类型和稳定 ordinal；
3. 生成 nominal token、`ProjectFactories`、`ProjectTypes` 和 `UE` overload；
4. 生成三项 `AvidScriptNative` P/Invoke。

主 `AvidScriptEditorCSharpBindingRenderer` 只负责调用该模块并维持 manifest 顺序：

```text
reflected bindings
-> lifecycle imports
-> object type imports
-> object factory imports
-> packed owner import
```

factory-only v7 package 的 required import 数由 2 更新为 5；Runtime VM package 不包含 packed
owner import。

## 4. Nominal token 与防伪边界

Guest IR 新增两个互不兼容的值类型族：

```text
TObjectFactoryOfX -> factory_ref / i32
TObjectTypeOfX    -> object_type_ref / i32
```

只有生成的 `ProjectFactories` 或 `ProjectTypes` 精确属性 getter，才能使用对应的 internal
constructor 和非负 literal ordinal 创建 token。以下路径全部失败关闭：

- 用户脚本直接 `new Token(0)`；
- `default(Token)`；
- static field 的零初始化；
- 普通 `int -> token` conversion；
- factory/type token 家族串用；
- 使用错误家族的 ordinal projection；
- public constructor、额外字段、错误字段类型和错误 owner。

Guest IR 独立 validator 仍会再次检查 constant kind、projection operator 和 generic conversion，
不会只信任 C# lowering 的输出。

## 5. Packed handle 与性能

Construct 和 Find 的 ABI 为 `(i32,i32,i32)->i64`。C# 生成代码在寄存器中完成：

```text
call -> packed i64
packed -> i32 slot
packed >> 32 -> i32 generation
new concrete proxy(slot, generation)
```

该路径没有 Guest scratch address、临时 Guest Memory 或额外 Host crossing。现有 WASM backend
已经支持 `i64.shr_s` 和 `i32.wrap_i64`，因此无需新增 backend 特例。typed object proxy 的直接
上转型继续走 Guest 内部转换，Host crossing 为 0。

## 7. 当前限制与下一步

P51.3 已完成对象创建、查询和释放的 C# 到 WASM 静态闭环，但 SceneComponent 尚不能从脚本
Attach/Detach，当前也还没有真实 BeginPlay/Tick/EndPlay Component gameplay 样例。

P51.4 将新增两项通用 Scene attachment import、same-world/cycle/reload 副作用校验，并用真实
C# 脚本完成创建、查询、挂接、Tick 游戏逻辑和 EndPlay 清理。
