# P51.1 对象工厂描述符实施报告

> 状态：已完成。P51.1 只建立“声明、生成、发布、加载不可变计划”的闭环；对象实例的 Construct/Release 与 Session 所有权属于 P51.2。

## 本批目标

P51.1 将项目配置中的 UObject/ActorComponent factory 声明转换为 descriptor v7，并在运行时加载阶段形成不依赖字符串查找的不可变 factory plan。该批次同时保证 Actor 生命周期 class reference 与对象工厂 class reference 不会混用能力。

## 已实现能力

### Profile 与生成期约束

- Profile schema v4 支持 `object_factories`，当前 factory kind 为 `new_object` 与 `actor_component`。
- 每个 factory 显式声明 class reference、Outer 基类、Session ownership 和组件注册策略。
- Resolver 在生成前验证 class、Outer、abstract/deprecated、kind、registration 与 UE `ClassWithin` 约束。
- 未声明 factory 的旧 profile 继续使用旧 identity domain，避免无意义的 selection hash 漂移。

### Descriptor v7

- 新增稳定、连续 ordinal 的 `object_factories` 表。
- Factory stable id 由 `class_reference_id`、`kind`、`outer_type_id`、`ownership` 和 `registration` 组成。
- Object type closure 自动包含 factory concrete class、required Outer 及完整继承链。
- Canonical serializer 是 descriptor 的唯一写入 owner；v2-v6 canonical bytes 与 hash 保持兼容。
- Parser 对 dangling id、ordinal、未知 policy、registration mismatch 和 capability overlap 失败关闭。

### 能力分流

- Actor-derived class reference 只发布 Spawn/Destroy/IsA 生命周期能力。
- 非 Actor class reference 必须且只能由一个对象工厂拥有。
- Actor lifecycle 与 object factory capability 强制互斥；parser、renderer 和 runtime 使用同一 descriptor type graph 判定。
- Factory-only package 不再生成错误的 `ProjectClasses` 或 `SpawnActor` 表面。

### Runtime 不可变计划

- `FAvidScriptBindingPackage` 在 descriptor 激活时构建 `FAvidScriptObjectFactoryPlan`。
- Plan 缓存 concrete `UClass*`、required Outer `UClass*`、result object type ordinal、ownership 与 registration。
- Factory class 与 object type plan 共享 class load cache 和强引用 anchor；ordinal lookup 不再加载 class 或按名称反射。
- Runtime 在激活前验证继承、abstract/deprecated、factory kind、component registration、Outer 与 `ClassWithin`。
- Package 暴露 descriptor schema provenance 和 object factory count；manifest 必须与真实 descriptor schema、factory count 一致。

### 发布链闭环

- Build request、build plan、generator、emitter、binding slice、PowerShell package resolver 与 runtime reload 均支持 schema v7。
- Binding slice 保留完整 factory table、class reference 和类型闭包。
- Prepared Semantic 接受 schema v6/v7 typed Self，并继续验证精确 import 授权。
- 架构门禁覆盖 profile -> descriptor -> renderer -> immutable plan -> manifest provenance owner 链。

## 当前边界

P51.1 尚未提供以下运行时游戏逻辑 API：

- C# 侧还不能调用 `Construct<T>` 或 `Release`。
- Runtime Session 尚未持有 factory 创建对象的 GC 强引用。
- ActorComponent 尚未执行 RegisterComponent、AddInstanceComponent 或销毁清理。
- 尚未提供 FindComponent、Attach/Detach 与 transform rule。
- Reload candidate 阶段的 ownership side-effect 隔离尚未实现。

因此当前结果是“factory 声明可生成、发布并安全加载为不可变计划”，还不是“C# 已能创建并管理 UObject/Component”。

## 下一批

P51.2 将实现 Session ownership domain、通用 Construct/Release binding、对象注册表接入和清理顺序。完成后，C# 才会第一次获得通过 descriptor factory ordinal 创建 UObject/ActorComponent 的运行时能力。
