# Phase 51 独立复审报告

## 复审范围

本轮复审以 Phase 51 的最终对象/组件闭环为边界，重点检查：

- descriptor v7 factory、object type 与 runtime slice 的 owner 链；
- Session ownership、GC 强引用、Component authority 与 cleanup；
- candidate reload、重入调用和失败候选副作用隔离；
- C# authorization package、最终 Guest IR 与 runtime package 的跨制品 provenance；
- 架构门禁是否能阻止精确集合比较退化为子集比较。

复审由独立只读 agent 执行，不修改源码，也不把自审结果替代为复审结论。

## 发现与修复

### 1. 最终 Guest IR 未与 runtime 激活集绑定

初轮复审发现 build pipeline 只比较动态 import，没有比较最终 Guest IR 使用的 object type ordinal 与 runtime slice 的 `active_object_type_ordinals`。修复后：

- package resolver 从 hash 保护的 descriptor 读取显式激活集；
- final build 对两份有序集合执行长度与逐元素精确比较；
- 不一致返回 `ASBI4304 / binding_runtime_object_type_mismatch`；
- 失败时删除 WASM 与 manifest。

### 2. JSON shape 与负例真实性不足

第二轮复审发现 PowerShell 的 `@($Value)` 会把 JSON 标量包装成单元素数组，同时旧负例手工升级 legacy schema，既不是 canonical generator 产物，也只覆盖一个集合差异方向。修复后：

- `active_object_type_ordinals` 必须先满足原始值为 `System.Array`；
- BuildIntegration 自动选择 hash 完整的真实 schema v6/v7 发布包；
- 分别覆盖 Guest 使用未激活 ordinal 与 Runtime 激活未使用 ordinal；
- 单独覆盖 JSON 标量 shape 拒绝。

### 3. generated TryCast ordinal 漏出 provenance

真实负例证明 `AActor.TryCast(UObject)` 会在 Guest IR 中生成 `avid_object_type_is_a(..., ordinal)`，但旧提取器只扫描 nominal `object_type_ref` constant。修复后 bootstrap 与 final build 共用的提取逻辑同时覆盖：

- typed `object_type_ref` constant；
- `avid_object_type_is_a` 的第三个直接非负 `int32` constant。

因此 generated checked cast 所需 UClass 会自动进入 runtime slice 激活闭包，不要求脚本额外引用 `ProjectTypes`。

### 4. malformed Guest provenance 未稳定失败

第三轮复审发现 malformed `object_type_ref` 会被静默忽略，而 malformed intrinsic ordinal 会抛出未处理异常；此时 WASM 已经生成。修复后两类来源均严格解析，异常统一进入：

```text
ASBI4305 / guest_object_type_provenance_invalid
```

调用点会先删除 Guest IR、debug map、state、WASM 与 manifest，再发布稳定失败报告并以退出码 1 结束。
