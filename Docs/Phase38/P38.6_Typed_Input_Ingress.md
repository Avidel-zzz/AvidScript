# P38.6 Typed Input Ingress

## 目标

本阶段让 UE 输入系统可以通过单一类型化入口进入 AvidScript，并在 C# 中以 `InputEvent` 编写游戏逻辑。实现继续复用 Phase 38.3 的统一 gameplay event 信封和 `avid_on_gameplay_event`，没有为每个 Action、Trigger 或输入框架增加导出和 host API。

核心原则：

- Runtime 不依赖 EnhancedInput module。
- 项目可从 Enhanced Input、传统 Input、AI 或网络回放调用同一个入口。
- ActionId 和 TriggerEvent 是项目层稳定 ID，不在 Runtime 中手写注册表。
- C# callback 由 descriptor table 生成，不增加独立 WASM export。
- invalid payload 保持运行时健康，guest trap 按统一 session fault policy 卸载。

## UE 入口

```cpp
UFUNCTION(BlueprintCallable, Category = "AvidScript|Input")
bool DispatchScriptInput(int32 ActionId, int32 TriggerEvent, FVector Value);
```

调用方只需要把项目输入映射转换为两个非负 ID 和一个三分量值。组件构造：

```text
Type = Input
PrimaryId = ActionId
SecondaryId = TriggerEvent
ObjectHandle = empty
VectorValue = Value
```

输入不要求 UObject handle。Runtime 已统一校验 event type、非负 ID 和有限 float。

## 统一组件策略

`UAvidScriptComponent` 新增私有 `DispatchGameplayEvent`。碰撞和输入都经过这一函数，因此共享：

- Running lifecycle 检查
- Runtime Session 路由
- invalid_argument 不卸载
- trap 或 VM fault 先解绑 gameplay delegates，再卸载 runtime
- metrics、module id 和 event callback 统计
- root-cause diagnostics

这次重构移除了碰撞路径中重复的 dispatch/fault 代码，后续新增 Schema event 也不需要复制 teardown 策略。

## C# authoring

```csharp
public static void OnInput(InputEvent input)
{
    UE.Self.SetActorLocation(
        input.Value + new FVector(input.ActionId, input.TriggerEvent, 0.0f));
}
```

`InputEvent` 当前公开：

```csharp
public readonly struct InputEvent
{
    public readonly int ActionId;
    public readonly int TriggerEvent;
    public readonly FVector Value;
}
```

生成器映射：

| C# 表达式 | WASM 参数 | codegen |
| --- | --- | --- |
| `input.ActionId` | local 1 / primaryId | `f32.convert_i32_s` |
| `input.TriggerEvent` | local 2 / secondaryId | `f32.convert_i32_s` |
| `input.Value` | local 5-7 / vector xyz | 三个 f32 直接读取 |

`OnInput` 是 descriptor table 的 EventType 4 分支。它与碰撞 callbacks 共用唯一 `avid_on_gameplay_event` 导出和现有 typed Actor imports。

manifest 的机器可读 contract 已包含：

- `InputEvent`
- `OnInput`
- `input.ActionId`
- `input.TriggerEvent`
- `input.Value`

## 行为验证

真实 C# 工件收到：

```text
ActionId = 5
TriggerEvent = 2
Value = (1, 2, 3)
```

脚本把 owner Actor 设置为 `(6, 4, 3)`，同时证明三个字段都进入 codegen。

组件层还验证：

- `DispatchScriptInput` 通过 UE reflection 暴露为 BlueprintCallable。
- 成功输入更新统一 event count 和 last input 统计。
- ActionId 为 -1 时返回 false，runtime 保持 Running。
- EndPlay 后输入被拒绝。
- input callback 执行 unreachable trap 时，runtime 立即卸载，collision delegates 同步解绑，trap diagnostics 保留。

## 当前边界

- 入口尚未提供项目级 Action 名称到 ID 的生成资产；该能力应由后续 reflection/code generation 工具生成，而不是 Runtime 手写映射。
- 当前 `TriggerEvent` 是项目层整数协议，不直接暴露 Enhanced Input 枚举，避免 Runtime 模块耦合。
- source adapter 仍是受控 C# 子集。正式语义模型和诊断将在 Phase 39-42 收敛。
- Phase 38.7 将执行全模块、性能、reload 与完整自动化验证，并更新中文 authoring/architecture 文档。
