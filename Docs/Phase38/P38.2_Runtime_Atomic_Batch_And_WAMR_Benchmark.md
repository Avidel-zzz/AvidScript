# P38.2 Runtime 原子 Batch 与 WAMR 性能闭环

日期：2026-07-13
状态：完成

## 目标

把 P38.1 的通用 Guest Memory 借用视图接入 Runtime 和已有 typed Bindings，形成真实 WASM 到 UE Actor Transform 的批量闭环。本阶段没有增加新的 Actor Gameplay 方法；它建立的是生成式 Binding 可复用的批量路由和发布语义。

## Runtime Dispatcher

Runtime 新增 HandleActorGetTransformBatchImport，并使用三个会话级 Scratch Buffer：

- Handle Scratch：把每两个 uint32 Cell 转换为 slot 和 generation。
- Snapshot Scratch：接收 AvidScriptBindings 的类型化批量结果。
- Output Scratch：生成最终 9-float Wire 数据。

处理顺序为：

1. 验证 requested count 与输入、输出 View 形状完全一致。
2. 将 Cell 转换为 Handle，但不写 Guest 输出。
3. 调用 FAvidScriptActorBinding::GetActorTransforms 完成全批类型与生命周期验证。
4. 验证所有 double 值有限且可由 float 表示。
5. 生成完整 Output Scratch。
6. 仅在全部成功后一次性复制到 Guest 输出。

任一 Actor 失效、类型错误或数值无法表示时，输出缓冲区保持调用前状态，不发布部分结果。

## 行为测试

AvidScript.Runtime.Binding.TransformBatchDispatch 使用两个真实 Actor、真实 UObject Registry 和 Runtime Dispatcher：

- 成功批量返回两个 Transform 的 18 个 float。
- 第二个 Handle generation 失效时返回失败。
- 错误详情保留 failed index。
- 失败前后检查全部 18 个哨兵值，证明没有部分写入。

RED 阶段 Runtime 尚未路由 ActorGetTransformBatch，测试按预期失败；实现后 1/1 成功。

## 等价工作量 WAMR Benchmark

Benchmark 动态生成两份真实 WASM 模块：

- 标量模块：64 个 Actor 分别读取 Location、Rotation 和 Scale，共 192 次 WASM 到 Host crossing。
- 批量模块：一次 actor_get_transform_batch 读取同样 64 个完整 Transform，共 1 次 crossing。

两条路径都经过 WAMR、VM Host Adapter、Runtime Dispatcher、Object Registry 和 typed Bindings。本轮 Development Editor 数据：

| 路径 | Crossing | 平均耗时 |
| --- | ---: | ---: |
| 标量完整 Transform | 192 | 0.155265 ms |
| 批量完整 Transform | 1 | 0.032364 ms |

本轮批量路径约为标量路径的 4.8 倍速度。自动化只固定等价工作量、crossing 数量和样本完整性，不设置易受机器负载影响的速度比例断言。
