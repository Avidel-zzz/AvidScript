# P38.5 C# 生成式 Gameplay Callback Contract

## 目标

本阶段把 Phase 38.3 的统一 gameplay event 信封和 Phase 38.4 的 UE 碰撞委托接到 C# authoring 层。重点不是再增加三套手写 WASM 导出，而是证明一种可扩展的生成模式：

- C# 用户编写类型化方法。
- adapter 通过 callback descriptor table 识别方法。
- 所有方法编译到唯一的 `avid_on_gameplay_event` 导出。
- `AActor` 继续使用 host-owned slot/generation handle。
- `FVector` 直接映射统一事件信封的三个 float。
- 未声明 callback 的旧脚本仍获得兼容的 no-op 通用导出。

这条路线为后续正式语言前端和 UE Reflection Binding Generator 保留稳定 ABI，不形成逐 API 手写扩张。

## C# 使用方式

```csharp
public static void OnBeginOverlap(AActor otherActor, FVector location)
{
    otherActor.SetActorLocation(location + new FVector(0.0f, 10.0f, 0.0f));
}

public static void OnEndOverlap(AActor otherActor, FVector location)
{
    otherActor.SetActorLocation(location + new FVector(0.0f, 0.0f, 5.0f));
}

public static void OnHit(AActor otherActor, FVector normalImpulse)
{
    otherActor.AddActorWorldOffset(normalImpulse);
}
```

这些方法不需要各自声明 `UnmanagedCallersOnly`。导出和分派由生成器负责，脚本只表达游戏逻辑。

## 生成架构

`Build/BuildCSharpActorLifecycle.ps1` 中的 descriptor table 当前包含：

| C# 方法 | EventType | Actor 参数 | FVector 参数 |
| --- | ---: | --- | --- |
| `OnBeginOverlap` | 1 | `otherActor` | `location` |
| `OnEndOverlap` | 2 | `otherActor` | `location` |
| `OnHit` | 3 | `otherActor` | `normalImpulse` |

生成后的唯一通用函数签名为：

```text
avid_on_gameplay_event(
    i32 eventType,
    i32 primaryId,
    i32 secondaryId,
    i32 objectSlot,
    i32 objectGeneration,
    f32 vectorX,
    f32 vectorY,
    f32 vectorZ)
```

参数映射如下：

- `otherActor` -> `objectSlot + objectGeneration`
- `location` / `normalImpulse` -> `vectorX + vectorY + vectorZ`
- descriptor table 中存在、源码中未声明的方法 -> 不生成对应分支
- 所有模块仍导出 `avid_on_gameplay_event`，零分支函数为兼容 no-op

WASM Type、Function、Export、Code 四个 section 同步增加一个函数，import 数量保持不变。碰撞回调调用现有 typed Actor imports，没有引入 callback 专用 host API。

## 运行时闭环

真实工件执行链为：

```text
UE collision delegate
  -> UAvidScriptComponent
  -> FAvidScriptRuntimeSession
  -> FAvidScriptRuntimeEventRouter
  -> avid_on_gameplay_event
  -> generated C# event branch
  -> existing actor_set_location / actor_add_location_offset import
  -> OtherActor transform changes
```

`SourceAdapterArtifactLifecycleSmoke` 连续验证：

1. BeginOverlap 把 OtherActor 从 `(10,20,30)` 移到 `(10,30,30)`。
2. EndOverlap 把位置改为 `(10,30,35)`。
3. Hit 传入 `(1,2,3)`，最终位置为 `(11,32,38)`。
4. legacy Event 与三个 typed callbacks 共用统一事件统计，计数为 4。

这不是字符串形状测试，而是 WAMR 加载真实生成工件后对 UE Actor 的同步操作。

## 兼容性与修复

Editor 的 CustomMover profile 不声明 `OnEvent` 和任何碰撞 callback。验证结果：

- manifest subset 为 `actor_lifecycle_v12`
- 同时导出 legacy `avid_on_event` 与统一 `avid_on_gameplay_event`
- `generated_gameplay_callbacks` 是空数组
- 通用导出没有事件分支，可作为缓存 no-op 调用
- report/manifest 仍可绑定到 `UAvidScriptComponent`

本阶段还修复了 `Get-CSharpStaticFloatFields` 的嵌套数组返回错误。旧实现对零字段脚本误生成一个 WASM global，并写出 `static_float_fields: [null]`；现在零字段为真正空集合，单字段 ActorLifecycle 状态仍通过真实工件回归。

## 当前边界

- 当前 source adapter 仍是受控 C# 子集，不是完整 Roslyn/AOT 编译器。
- 当前 descriptor table 只包含 BeginOverlap、EndOverlap、Hit。
- 回调同步执行在 UE gameplay 线程，trap 仍按 Runtime Session fault 策略处理。
- Phase 38.6 将以同一统一事件协议接入 typed Input，不增加逐 action 手写导出。
- Phase 39-42 将把临时 source adapter 演进为正式前端、语义模型和 UE Reflection Binding Generator。
