# P47.2 对象引用失败可见性成果

## 结论

生成 C# 门面虽然不显式检查每个 native binding 的整数返回值，但真实 WAMR 动态 import 不会静默返回默认值：

1. Bindings Runtime 发现 receiver 的 slot 或 generation 无效。
2. 调度结果携带 binding_target_invalid 和详细原因返回 VM。
3. WAMR dynamic raw thunk 记录失败 import，并对当前 module instance 设置 exception。
4. VM Call 返回 host_import_failed。
5. Runtime Session 拒绝 BeginPlay 候选并保留结构化错误。

这一机制集中在 VM 边界，对全部自动生成 binding 生效，不需要在每个 C# 方法和属性中重复错误检查。

## 真实 C# 负例

P47.2 复用 P47.1 的真实五 import C# WASM，但把 owner 换成没有 RootComponent 的 AActor：

- RootComponent 属性 getter 合法返回空对象句柄；
- 随后的 USceneComponent.GetWorldLocation() receiver 为 (0, 0)；
- BeginPlay 以 host_import_failed 结束；
- RuntimeResult 保留 avid_ue_ 动态 import 名；
- 错误文本保留 invalid UObject handle；
- Actor scale 保持初始 (1, 1, 1)，证明脚本没有使用默认 FVector 继续执行。

## 能力边界

当前合同适合不可恢复的脚本编程错误和 stale receiver：立即停止本次脚本实例并向 UE 日志与 Editor presentation 暴露诊断。

后续若要支持可选组件等正常游戏分支，应设计零额外 host crossing 的 IsNull 或结构性空句柄判断；它不能削弱 stale generation 的 Runtime 校验，也不能用吞错和默认值替代。
