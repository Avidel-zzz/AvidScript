# P48.4 FName 描述符与 C# 门面结果

## 状态

已完成实现与专项验证。

本阶段把 UE 反射中的 `FName` 输入接入自动绑定生成链路，不增加按函数手写的运行时 API。当前边界是生成期与 C# 到 WASM 的数据表达；WAMR host 侧的严格解码与 `ProcessEvent` 调用留给 P48.5。

## 描述符契约

`FName` 使用以下唯一合法元数据元组：

| 字段 | 值 |
| --- | --- |
| `canonical_type` | `name:fname` |
| `kind` | `name_utf8` |
| `cpp_type` | `FName` |
| `size` | `4` |
| `alignment` | `4` |
| `abi_types` | `["i"]` |

这里的 4 字节值是 guest memory 中字符串数据块的地址，不是宿主侧 `FName` 对象布局。

首个代表性 UE API 为 `AActor::ActorHasTag(FName Tag)`。生成的 host import 签名是 `(iiii)i`：owner slot、owner generation、名称数据地址和隐藏的 bool 返回存储地址。

## 方向策略

- 支持按值输入与 `const FName&` 输入。
- `FName` 返回值、`out FName`、`ref FName` 均以 `unsupported_property_type` 失败关闭，并在错误来源中保留方向。
- 可读 `FName` 属性也会失败关闭，因为属性 getter 等价于尚未支持的 `FName` 返回值。
- renderer 会同时核对 type table 和具体 value 的完整元组；canonical type、kind、C++ 类型、size、alignment、ABI 或 direction 任一被篡改时，不生成部分 C# 代码。

## C# 使用形式

自动生成门面把 `FName` 输入投影为 `string`：

```csharp
bool hasPlayerTag = UE.Self.ActorHasTag("Player");
```

Editor 自动化会把真实 renderer 输出与 `Tests/Fixtures/BindingGeneration/P48_4_FNameActorHasTag.generated.cs` 逐字节比较；C# 测试读取同一个 fixture，再经过 Frontend、Semantic、Guest IR 和 WASM backend。这样 descriptor/emitter 与后端验证不能各自使用一份手写门面而发生漂移。

`"Player"` 被放入 `utf8_string` 数据段：

```text
06 00 00 00 50 6C 61 79 65 72 00
```

前四字节是 little-endian UTF-8 payload 长度，随后是 6 字节内容和终止零；调用指令传递该数据段地址。

## 剩余边界

- 当前 host invocation 尚未从 guest memory 解码 `name_utf8`，因此脚本产物还不能真正调用 `ActorHasTag`。
- P48.5 将实现长度边界、越界、内嵌 NUL、非法 UTF-8 和超长名称的失败关闭，并验证失败输入不会进入 `ProcessEvent`。
- `FName` 返回、`ref/out` 和属性读取需要独立的双向内存与所有权方案，不在本阶段提前放宽。
