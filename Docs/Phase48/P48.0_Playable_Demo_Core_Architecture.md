# P48.0 可玩 Demo 核心闭环架构

状态：设计已确认，等待实施计划确认

日期：2026-07-21

## 1. 阶段目标

Phase 48 的目标不是单纯增加绑定数量，而是让项目级 C# 脚本能够完成第一个可玩的游戏逻辑闭环。阶段结束时，开发者应能在一个普通 C# gameplay 文件中组合生命周期、输入或碰撞事件、条件分支、简单状态、Timer 和自动生成的 UE API，并通过现有构建与热重载链在 UE5.8 Editor 中迭代。

首个验收样例为“可重复收集物”：关卡中预放置的 Actor 持续旋转；玩家进入 Overlap 后，脚本根据事件对象和 Tag 判断是否收集，隐藏收集物并关闭碰撞；Timer 到期后恢复显示和碰撞。

本阶段继续遵守以下原则：

- C# 源码通过 Roslyn semantic、Guest IR 和确定性 WASM backend 编译，不恢复文本匹配 emitter。
- 普通 UE 函数通过反射 descriptor、生成 facade、最小 binding slice 和缓存 `ProcessEvent` 调用，不增加逐函数 VM enum、WAMR wrapper 或 Runtime switch。
- UObject 继续使用 slot/generation 代际句柄，不向 WASM 暴露裸指针。
- 只实现对多个 UE API 有复用价值的类型或事件能力，不为样例编写一次性 host API。

## 2. 本阶段范围

### 2.1 自然游戏事件入口

项目脚本获得以下可选入口：

```csharp
public static void OnBeginOverlap(AActor otherActor, FVector location);
public static void OnEndOverlap(AActor otherActor, FVector location);
public static void OnHit(AActor otherActor, FVector normalImpulse);
public static void OnInput(InputEvent input);
public static void OnTimer(int callbackId, int timerHandle);
```

Runtime 仍只向 WASM 调用稳定的统一事件导出。编译链生成或 lower 确定性的事件路由，把原始 event type、ID、object handle 和 vector payload 投影到自然 C# 入口。项目作者不应手动解释 `eventType` 或自行拼装对象句柄。

脚本未声明某个可选入口时，不生成无效调用；声明的入口签名不匹配时，在构建阶段返回带源码位置的结构化诊断。

### 2.2 可用于玩法的控制流和状态

正式项目构建至少验证以下组合：

- `if`、`else if`、`else`；
- `bool`、`int`、`float` 比较；
- `private static bool/int/float` 状态；
- 常量、局部变量、赋值和复合赋值；
- 在事件入口中调用生成的 UObject、标量和 struct API；
- Timer callback ID 分支。

Phase 41 已具备 CFG、branch 和 loop 表示。本阶段只修复真实 Demo 暴露的通用 lowering 缺口，不建立第二套控制流实现。

### 2.3 反射类覆盖扩展

`EngineGameplay` profile 从当前 `AActor`、`USceneComponent` 边界扩展到第一批通用 gameplay 类型：

- `UActorComponent`；
- `UPrimitiveComponent`；
- `APawn`；
- `AController`。

类规则继续批量发现成员，并由共享函数与类型策略决定是否接收。继承成员必须去重，生成的 C# 类型必须保持真实 owner type，不能把派生类 API 塞入 `AActor` facade。

新增类的对象返回值和 receiver 继续复用对象注册表。无效、空或 stale handle 在 Runtime 失败关闭，并映射为现有 `host_import_failed` 诊断。

### 2.4 FName 第一阶段

本阶段实现可用于普通 gameplay 参数的 `FName` 输入封送，首要目标是解锁 `ActorHasTag(FName)`、`ComponentHasTag(FName)` 等高频接口。

约束如下：

- descriptor 使用独立、稳定的 `FName` 类型身份，不把它伪装成整数或 UObject handle；
- guest ABI 使用经过范围验证的 UTF-8 span 或等价的确定性表示，host 端复制构造 `FName`；
- 首版支持脚本常量和受支持的 `FName` 值流；
- 如果 return、out/ref 或动态字符串构造无法在本阶段完整实现，类型策略必须按方向拒绝，不得用截断缓冲区或静默默认值伪装成功；
- `FString`、`FText` 与容器不因共享部分文本设施而被宣称支持。

## 3. 非目标

以下能力不进入 Phase 48：

- 动态 `SpawnActor`、资产加载和 `UClass` / `TSubclassOf` 完整闭环；
- `FString`、`FText` 的通用入参、返回值和可变字符串运行时；
- `TArray`、`TSet`、`TMap`；
- 任意递归 `UStruct`、完整 `FHitResult`、sweep 和 latent action；
- Delegate 自动订阅系统；
- UMG、Cook、Shipping、Android 和 iOS 验证；
- 为 Demo 添加某个 UE 函数的专用 native wrapper。

收集物由关卡预放置。动态世界创建闭环计划在 Phase 49 通过通用 class reference、world context 与对象创建能力处理。

## 4. 架构边界

### 4.1 Editor 绑定生成

Editor 侧负责：

1. 从 profile 中解析类边界；
2. 运行共享函数、属性和类型策略；
3. 生成兼容性报告与拒绝原因统计；
4. 生成 descriptor、C# facade 和 reference source；
5. 依据 Roslyn reachability 发布最小 runtime binding slice。

兼容性报告必须按拒绝类别和 C++ 类型聚合，例如 `unsupported_property_type:FString`、`unsupported_function_policy:Latent`。该报告作为后续类型阶段的真实优先级输入，避免按猜测扩展 API。

### 4.2 C# 编译链

C# 编译链负责：

1. 由 Roslyn 验证事件入口签名和普通 C# 语义；
2. 将自然事件入口映射到稳定 gameplay event export；
3. 将分支、状态、对象句柄和 generated binding call lower 到 Guest IR；
4. 只保留实际使用的 generated imports；
5. 生成带 source/semantic/Guest IR/WASM provenance 的报告。

事件路由属于语言到 Runtime 稳定 ABI 的适配，不属于 UE API 手写绑定表。

### 4.3 Runtime 与 VM

Runtime 和 VM 继续负责：

- 生命周期和统一 gameplay event 调用；
- guest memory 范围验证；
- object registry 解析和 generation 校验；
- 动态 raw import 注册；
- binding package 的缓存属性或函数调用；
- host 失败到 WAMR trap 和 C# 源码诊断的映射；
- reload 失败时保留旧 runtime。

本阶段不允许把 Tag、隐藏状态或碰撞状态写进 Runtime 特例。

## 5. 数据流

收集物 Overlap 的端到端路径如下：

1. owner Actor 的 UE collision delegate 进入 `UAvidScriptComponent`。
2. Runtime 将 event type、other Actor handle 和 FVector payload 写入统一 guest event ABI。
3. WASM 事件路由调用脚本声明的 `OnBeginOverlap`。
4. `otherActor.ActorHasTag(new FName("Player"))` 通过 generated facade 进入最小 binding import。
5. Runtime 从缓存调用计划解析 receiver，把 guest UTF-8 span 转换为 `FName`，并调用 `ProcessEvent`。
6. 条件成立后，隐藏与碰撞函数通过各自的 generated imports 执行。
7. Timer 到期进入 `OnTimer`，脚本恢复 Actor 状态。

任一步骤出现无效句柄、越界 span、descriptor 不一致或 UE 调用失败时，本次脚本调用立即失败，并保留可定位到 C# 方法和 binding identity 的诊断。

## 6. 性能要求

- UE 反射扫描、descriptor 解析和 `FProperty` / `UFunction` 查找只发生在生成或 package load 阶段。
- Tick 和事件热路径使用缓存调用计划，不按名称查找 UE 成员。
- `FName` 入参只进行必要的 guest span 验证和一次 host 构造，不创建永久 registry entry。
- Roslyn reachability 继续裁剪未使用 API，扩展授权 profile 不应线性扩大运行时 import 表。
- 自然事件路由不得为每次事件进行 JSON 解析、反射查找或堆上 descriptor 构造。

## 7. 错误处理

新增错误至少区分：

- 事件方法签名错误；
- 不支持的 `FName` 方向或构造形式；
- UTF-8 guest span 越界或非法；
- profile 类不可加载；
- generated binding 类型不兼容；
- receiver 空句柄或 stale generation；
- host `ProcessEvent` 调用失败。

构建期错误不发布新 manifest/WASM。运行期或 reload 候选错误不替换当前正常 runtime。正常的空对象分支继续使用结构性 `IsNull`，不能通过吞掉 host trap 获得默认值。

## 8. 验收与验证

### 8.1 功能验收

Phase 48 完成必须同时满足：

1. 项目 C# 文件可直接声明自然 Overlap、Hit、Input 和 Timer 入口。
2. 真实 C# Demo 使用 `if`、`bool/int/float` 状态、Actor handle、FVector 和 `FName` Tag 判断。
3. 收集物能在 UE5.8 Editor 中旋转、响应玩家 Overlap、隐藏、关闭碰撞并定时恢复。
4. Demo 使用的普通 Actor/Component API 全部来自反射生成和动态缓存调用路径。
5. 修改旋转速度或恢复时间后，自动构建与 reload 成功；失败版本保留旧 runtime。
6. compatibility report 显示新增 class profile 的接受数量和主要拒绝类型。

### 8.2 自动化范围

测试随风险分层，不为每个 UE 函数复制一份测试：

- .NET semantic/Guest IR/backend：事件入口签名、事件路由、真实分支和 `FName` ABI；
- Editor：profile 类扩展、继承去重、方向性类型策略和 generated facade；
- Bindings/VM：`FName` span 边界、缓存 `ProcessEvent`、对象句柄失败；
- Runtime：真实事件到 WASM、Timer 恢复和 reload 旧实例保活；
- 一个端到端 UE 自动化场景验证完整收集物行为。

除非共享 ABI 或模块公开布局发生变化，不执行完整 Editor target clean。优先执行受影响模块的增量构建，再运行 focused automation，最后运行完整 `AvidScript` 回归。

## 9. 十小时实施分组

| 分组 | 预算 | 产出 |
| --- | ---: | --- |
| P48.1 | 0.5 小时 | 基线验证、兼容性统计和 Demo 所需 API 核对 |
| P48.2 | 2 小时 | 自然 gameplay 事件入口与构建期签名诊断 |
| P48.3 | 1.5 小时 | 真实分支、比较和 bool/int/float 状态闭环 |
| P48.4 | 1.5 小时 | gameplay class profile 扩展与继承类型 facade |
| P48.5 | 2.5 小时 | `FName` 输入 ABI 与 Tag API 闭环 |
| P48.6 | 1 小时 | 真实 C# 收集物样例和 UE 运行验证 |
| P48.7 | 1 小时 | 回归、性能/覆盖证据、中文文档和阶段收尾 |

预算按依赖顺序动态调整。若 `FName` 完整安全实现超过窗口，可以先保留事件、控制流、class profile 和无 Tag 的可玩 Demo 作为中间成果，但 Phase 48 必须继续标记为进行中，不得收尾。不得用不完整 ABI 换取表面上的验收通过，剩余 `FName` 工作必须明确记录为未完成，不能静默降级。

## 10. Phase 49 输入

Phase 48 完成后，Phase 49 以“世界与对象创建闭环”为目标，优先设计：

- `UClass`、`TSubclassOf` 和类型安全的 class reference；
- World Context 注入和静态 Blueprint Function Library 调用；
- 通用 Spawn/Destroy；
- 组件查找与派生类型安全转换；
- 资产引用的内容路径、Cook 依赖和运行时加载策略。

该顺序让 Phase 48 先证明游戏逻辑可写，再让 Phase 49 解除必须预放置 Actor 的限制。
