# P48.5 FName Runtime 封送结果

## 状态

已完成实现与专项回归。

P48.4 已经能从 UE 反射生成 `string` 形式的 C# 门面和 WASM 数据地址；本阶段补齐 WAMR host 共用的动态反射 invocation，使 `name:fname` 输入能够从 guest memory 安全转换为 UE `FName`，再进入缓存的 `ProcessEvent` 调用。

## Runtime 类型契约

package load 新增独立的 `Name` runtime kind，且只接受以下完整组合：

- reflected property 必须是 `FNameProperty`；
- direction 只能是 `value` 或 `const_ref`；
- value 与 type table 必须同时匹配 `name:fname`、`name_utf8`、`FName` 和 `["i"]`；
- type table 的 `size` 与 `alignment` 必须都是 4。

kind、size 或其他元数据被篡改时，package load 以 `binding_property_contract_mismatch` 失败关闭，不发布半有效 package。

## Guest Memory 布局

WASM cell 传递一个 32 位 guest address，地址指向：

```text
[int32 little-endian UTF-8 byte length][payload bytes][00]
```

例如 `Player`：

```text
06 00 00 00 50 6C 61 79 65 72 00
```

host 依次执行：

1. 拒绝 address cell 高 32 位非零；
2. 读取 4 字节 little-endian 长度；
3. 要求字节长度不超过 `NAME_SIZE * 4`，当前 UE5.8 即 4096；
4. 用 64 位算术检查 `address + 4 + length + 1`，再一次读取 payload 与终止字节；
5. 要求终止字节为零，payload 内没有 NUL；
6. 按精确长度执行 UTF-8 到 TCHAR 再到 UTF-8 的逐字节 round-trip；
7. 要求转换后少于 `NAME_SIZE` 个 TCHAR code unit，即最多 1023；
8. 全部验证完成后才构造 `FName` 并写入 UFunction frame。

短名称使用 256 字节 inline buffer，较长输入才走堆分配，避免每次调用固定占用约 4 KiB 栈空间。

## 行为闭环

Editor runtime 自动化生成真实 `AActor::ActorHasTag(FName Tag)` package，注册带 `Player` tag 的测试 Actor，并验证：

- 合法 `Player`、多字节 UTF-8、四字节 Unicode codepoint 与合法 U+FFFD 都能通过 `ProcessEvent` 命中 Actor tag；
- 空字符串映射为 `NAME_None`；
- 1023 个 ASCII 字符可进入 `ProcessEvent`，1024 个被拒绝；
- 负长度、4097 字节前缀、地址高位、越界、内嵌 NUL、非零终止符均被拒绝；
- malformed、truncated、overlong、UTF-16 surrogate 和大于 U+10FFFF 的 UTF-8 均被拒绝；
- 每个失败输入都保持 bool 返回存储哨兵不变，且 `ProcessEventCallCount == 0`。

缺少 guest memory 时统一返回 `binding_frame_mismatch`；名称内容不合法时返回 `binding_argument_invalid`。

## 剩余边界

- 当前只支持 `FName` 输入；return、ref、out 与可读属性需要独立的双向 guest memory ABI。
- `FNAME_Add` 会把新的唯一名称加入进程级 Name Pool。可信游戏脚本可正常使用，但高频动态唯一名称仍需要缓存、统计与预算策略，不能把当前实现视为无限制字符串通道。
- 本阶段验证的是共享 dynamic host dispatch 与真实 `ProcessEvent`。P48.6 将让正式 C# 游戏脚本产物通过 WAMR 调用该能力，并组成可玩的拾取逻辑闭环。
