# P11.4 Phase 11 Closeout

日期: 2026-07-05
状态: Done

## 1. 结论

Phase 11 已完成 UE Editor 可用入口的第一版纵切。当前 `AvidScriptEditor` module 会在 Editor 启动后注册 `Tools > AvidScript > Run Sample Script`, 并通过 module-owned launcher 调用 Phase 10 command/reload service 编译并应用 sample `.avid` 脚本。

本阶段依旧保持 service-first: ToolMenus 只负责触发, compile/reload 语义由 `FAvidScriptEditorCommandLauncher`、`FAvidScriptEditorCommandService` 和 runtime reload session 承担。这样后续文件选择器、设置页、Content Browser action、watcher 或命令行自动化都能复用同一条路径。

## 2. 已完成内容

- P11.1 新增 `FAvidScriptEditorCommandLauncher`, 支持从 `.avid` source 构建默认 config, 持有 reload session, 注入 HostContext, 并映射 command result summary。
- P11.2 新增 `FAvidScriptEditorMenuRegistrar`, 通过 public ToolMenus API 注册可测试的 menu entry。
- P11.3 将 launcher 和 registrar 接入 `FAvidScriptEditorModule` 生命周期, 注册 `Tools > AvidScript > Run Sample Script` sample command。
- P11.4 完成 Editor target、完整 Editor automation 和完整 AvidScript automation 回归。

## 3. 验证矩阵

| 检查 | 结果 |
| --- | --- |
| Editor target build | `AvidTPSTemplateEditor Win64 Development` 返回 `Result: Succeeded`。 |
| full `AvidScript.Editor` automation | `Automation Test Queue Empty 26 tests performed`。 |
| full `AvidScript` automation | `Automation Test Queue Empty 61 tests performed`。 |

运行中仍可看到若干被测试刻意触发的 missing import、missing export、bad hash、empty/missing wasm warning。这些 warning 属于 fail-closed regression 的预期行为。Editor automation 中还出现一次外部 `LogHttp` timeout warning, 与 AvidScript 代码路径无关, automation 结果仍为 Success。

## 4. 当前可实现能力

Phase 11 完成后, PC Editor 中已经具备从菜单触发 sample 脚本编译并应用 reload 的路径:

```text
Tools > AvidScript > Run Sample Script
-> FAvidScriptEditorModule
-> FAvidScriptEditorCommandLauncher
-> InvokeAvidScriptFrontend.ps1
-> JSON report / built manifest
-> FAvidScriptEditorCommandService
-> FAvidScriptWasmReloadSession
-> Actor Host ABI
```

结合 Phase 6/7 的 `.avid` frontend、Phase 8/9 的 report/compile gate、Phase 10 的 reload execution, 当前已经可以验证自有脚本语言 `.avid` 到 WASM 再到 UE Actor 交互的最小闭环。

## 5. 明确未做

- 未做文件选择器或最近脚本列表; 当前菜单 command 固定指向 sample `.avid`。
- 未做 Project Settings / Editor Preferences, LDC/toolchain 路径仍依赖 wrapper 参数、PATH 或环境变量。
- 未做 Slate 面板、Message Log 类别、toast 通知或交互式 diagnostics UI。
- 未做 Content Browser asset/action、file watcher 或 IDE 插件。
- 未恢复 packaging 验证, 未做 Android/iOS 设备验证。

## 6. 下一阶段建议

Phase 12 建议进入 Editor file workflow and settings:

- 增加可测试的 source selection/config model, 让 Editor command 不再只能运行固定 sample。
- 增加项目级 toolchain/settings 读取层, 把 LDC/toolchain/output/report 路径从硬编码或环境变量中解耦。
- 增加 result presentation adapter, 后续可接 Message Log、notification 或 panel, 但第一步仍以 service + automation 为主。
- 保持 PC-first, mobile/packaging 继续作为后续 gate。

## 7. 剩余阶段估算

若目标是可内部试用的 PC Editor MVP, 还需要约 4 个 phase:

```text
Phase 12: Editor file workflow and settings
Phase 13: typed binding surface expansion
Phase 14: PC packaging/project asset workflow
Phase 15: diagnostics, profiling, and hardening
```

若目标是接近可公开 beta 的现代 UE 脚本语言方案, 预计还需要在 MVP 后追加约 3 个 phase:

```text
Phase 16: mobile runtime and packaging validation
Phase 17: sandbox/security/resource limits
Phase 18: documentation, samples, migration, and benchmark suite
```
