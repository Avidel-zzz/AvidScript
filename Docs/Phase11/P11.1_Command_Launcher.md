# P11.1 Editor Command Launcher

日期: 2026-07-05
状态: Done

## 1. 目标

P11.1 在 P10 command facade 之上增加可复用的 Editor launcher 层。launcher 负责 source path 默认配置、reload session 生命周期、HostContext 注入和用户可读 summary, 让后续 ToolMenus/模块命令只负责触发, 不承载 compile/reload 业务逻辑。

## 3. 实现内容

- 新增 `FAvidScriptEditorCommandLaunchConfig`, 支持 source、bindings、output、report、LDC 路径和 skip-compile。
- 新增 `FAvidScriptEditorCommandLaunchResult`, 汇总 source/report/manifest、reload applied 状态和底层 command result。
- 新增 `FAvidScriptEditorCommandLauncher`, 持有 `FAvidScriptWasmReloadSession`, 可注入 `FAvidScriptWasmHostContext`。
- `MakeDefaultConfigForSource` 默认使用插件 `Bindings/ActorHostBindings.avidscript.json`, 输出到 `Saved/AvidScriptGenerated/<source_name>`, report 输出到 `Saved/AvidScriptReports/<source_name>.frontend.report.json`。
- `CompileSourceAndApply` 复用 `FAvidScriptEditorCommandService`, 成功时应用 reload, 失败时输出 category/message/next action 与子进程 exit/stdout/stderr 摘要。
- `BuildAvidScriptActor.ps1` 的 wasm SHA256 从 `Get-FileHash` 改为 .NET `SHA256` API, 避免 UE 启动的 PowerShell 环境缺少该 cmdlet 时中断 report 生成。

## 4. 调试记录

P11.1 的真实 LDC 热重载测试初次失败在 `report_missing`: UE 自动化测试内没有生成 `built_manifest.frontend.report.json`。手动运行同一 wrapper 命令可以成功生成 report, 说明 LDC、source、bindings 和 report path 本身可用。

补充 launcher 失败摘要后, UE 日志显示根因是子进程 stderr:

```text
Get-FileHash : The term 'Get-FileHash' is not recognized as the name of a cmdlet
```

因此问题位于 UE-launched PowerShell 环境, 不是 WAMR reload、manifest loader 或 LDC 编译。修复为脚本内使用 .NET SHA256 计算, 并保留更可诊断的 launcher failure summary。

## 5. 当前能力

现在可以在 Editor 代码路径中通过 `FAvidScriptEditorCommandLauncher` 完成:

```text
.avid source -> frontend wrapper -> generated D -> LDC wasm -> manifest/report -> compile gate -> reload apply -> Actor Host ABI call
```

这已经能验证脚本语言 WASM 与 UE 交互, 但还不是用户可点击的 Editor 菜单入口。菜单注册和模块 sample command 留给 P11.2/P11.3。

## 7. 非目标

- 不注册 ToolMenus 菜单项。
- 不做 Slate/UMG 面板。
- 不做 file watcher。
- 不改变 `.avid` 语法、manifest schema 或 runtime ABI。
- 不提交 `Saved/` 中的 wasm/report 生成物。
