# Phase 63 移动端 AOT 架构

> 状态：架构冻结候选 v1
> 主线：平台变体 -> Android arm64 Wasmtime 预编译 -> 无 JIT 发布 -> 移动生命周期

## 1. 目标

Phase 63 在不回退 Win64 Wasmtime 性能主线的前提下，把 Phase 62 的内容寻址发布模型扩展到移动平台：

- 同一个逻辑 `ModuleId` 可发布多个不可变平台变体，resolver 按目标平台、架构和配置精确选择；
- Android arm64 使用 Wasmtime 45 官方 C API runtime，并且只执行发布期生成的预编译 artifact；
- 移动 Shipping 禁止 JIT fallback、开发路径和现场编译，平台不兼容时 fail closed；
- package identity 同时绑定 target triple、pointer width、endianness、CPU feature、VM build 和 artifact hash；
- 后台切换、World teardown、低内存通知和长帧不会让 Session 越过生命周期边界继续执行；
- iOS 明确保持无 JIT 合同，只有受控远程 Mac 工具链和可执行代码签名路径完成后才能标记支持。

本阶段不把 Windows 上的 schema/host 契约测试冒充 Android/iOS 真机验收。Phase 64 负责真实小型游戏
Demo、Android 设备闭环与 iOS 远程构建验证。

## 2. 后端矩阵

| 平台 | 主后端 | artifact | 运行策略 | P63 验证级别 |
| --- | --- | --- | --- | --- |
| Win64 x64 | Wasmtime 45 | `wasmtime_serialized_v1` | Development 可显式 JIT 回退，Shipping 仅预编译 | 保持 P62 基线 |
| Android arm64 | Wasmtime 45 | `wasmtime_serialized_v1` | Development/Shipping 均禁止设备端 JIT | 官方 runtime + 交叉预编译 + package/UBT 合同 |
| iOS arm64 | 未启用 | 保留 platform variant 接口 | 无 JIT、无 loose artifact、缺后端直接失败 | schema/选择/失败合同 |

WAMR 继续作为兼容后端与后续 iOS/XIP 候选，但 P63 不在没有官方 iOS 支持与真实签名证据时把它设为默认。

## 3. 官方依据

- Wasmtime v45.0.0 发布页提供 Android 相关修复，并发布 `aarch64-android` C API 资产：
  <https://github.com/bytecodealliance/wasmtime/releases/tag/v45.0.0>
- WAMR 官方文档说明 `wamrc --target=<arch>` 可生成 AOT，生产环境应让编译器与 runtime 使用完全相同版本：
  <https://github.com/wasm-micro-runtime/wasm-micro-runtime/blob/main/doc/build_wasm_app.md>
- WAMR XIP 可减少运行时 relocation 与可写 executable memory 需求，但仍存在已公开的 relocation 限制：
  <https://github.com/wasm-micro-runtime/wasm-micro-runtime/blob/main/doc/xip.md>

因此移动策略必须以平台变体和显式兼容键为核心，不能把任意 AOT 文件当作跨平台字节码。

## 4. 平台变体合同

Catalog 仍以 `module_id` 为逻辑身份，但模块项从单个 package 扩展为有序 `variants[]`。每个变体至少绑定：

- `platform`：`Win64`、`Android`、`IOS`；
- `architecture`：`x86_64` 或 `arm64`；
- `configuration`：`Development` 或 `Shipping`；
- `backend`、`artifact_format`、`target_triple`、`cpu_features`；
- `package_id`、descriptor 相对路径与 SHA-256；
- `runtime_build_identity` 与 minimum plugin/runtime version。

选择规则是精确匹配，不允许“同平台任取最新”“arm64 回退 x64”“Shipping 回退 Development”或未知字段静默忽略。
同一选择键只能存在一个变体，排序和规范 JSON 决定稳定 package identity。

## 5. Android Wasmtime 依赖

Android dependency lock 与 Win64 lock 分离，但共享 Wasmtime `45.0.0` 语义版本和许可证：

```text
Source/ThirdParty/Wasmtime/installed/
├─ Win64/v45.0.0-avidscript.1/
└─ Android/arm64/v45.0.0/
   ├─ include/
   └─ lib/libwasmtime.a
```

安装器必须验证官方 URL、archive SHA-256、精确文件集合、tracked license、ELF/static library 身份和托管 marker。
UBT 仅在 `UnrealTargetPlatform.Android` 且 `arm64` 时链接该库；缺失、hash 漂移或版本不一致在 UBT 前失败。
Android 不 staging Win64 DLL，也不启用 `FPlatformProcess::GetDllHandle` 路径。

## 6. 交叉预编译

发布期编译器从 canonical WASM 生成目标 artifact。输入包括：

- canonical WASM SHA-256；
- target triple `aarch64-linux-android`；
- 固定 compiler/runtime build identity；
- baseline arm64 CPU feature profile；
- fuel、epoch、memory 与 host-call resource policy；
- binding package identity。

产物先写入临时目录，经独立 inspect/deserialize-compatible 校验后原子发布。Android manifest 必须使用
`require_precompiled`，不出现 `wasmtime_jit` fallback。host 交叉编译成功只证明 artifact 构建合同；设备端
load/instantiate/BeginPlay/Tick/EndPlay 属于 Phase 64 真机 Gate。

## 7. Runtime 与生命周期

`FAvidScriptModuleResolver` 接收显式 platform context，返回已经验证的平台变体。Runtime 不读取 UBT 环境变量，
也不根据文件扩展名猜后端。

移动生命周期由 Runtime owner 统一转换为 Session 事件：

- App 进入后台：暂停新的 Tick/Timer/continuation 投递并记录有界状态；
- App 恢复：先验证 World、owner handle、module generation 和 deadline，再恢复队列；
- low-memory：清理未使用 module cache、debug map 和编译期数据，不破坏 live Session；
- World teardown：取消 continuation/delegate/timer，逆序卸载 VM，后台恢复不得复活旧 Session；
- 单帧超预算：fault 当前 Session，并保持其他 Session 与 World 可继续运行。

## 8. 模块边界

- `Build/`：平台 lock、安装器、交叉预编译、variant publisher、receipt/contract runner；
- `AvidScriptCore`：平台/架构/backend-neutral identity 值对象；
- `AvidScriptVM`：Android Wasmtime 静态 runtime、artifact compatibility 与无 JIT policy；
- `AvidScriptRuntime`：variant resolver、平台生命周期和 Session 隔离；
- `AvidScriptEditor`：选择发布 profile，不直接依赖 Android Wasmtime；
- `AvidScriptGenerated`：继续只消费 Runtime module reference。

依赖方向保持 `Generated/Editor -> Runtime -> VM -> Core`。平台分支不得散落进 binding codec、Guest IR 或游戏 API。

## 9. Gate

- 多平台 catalog 对相同输入确定性发布，选择键重复、缺失、路径逃逸和 hash 漂移全部拒绝；
- Android lock/install/verify/remove 合同验证官方 archive、marker、额外文件与 tamper；
- 交叉预编译结果包含正确 target triple，Android manifest 没有 JIT fallback；
- UBT 合同证明 Android arm64 链接静态 runtime 且不 staging Win64 DLL；
- resolver 正确选择 Android Development/Shipping 变体，并拒绝 iOS 未启用后端；
- 移动 pause/resume/low-memory/teardown 的 Session 状态机有自动化覆盖；
- Win64 P62 选择、发布和 Runtime 行为不回归；
- 阶段末集中执行 .NET、PowerShell、architecture、UE5.8 no-clean UBT 和必要 Automation。

## 10. 非目标

- 不在 Windows 上宣称 iOS 可构建、可签名或可上架；
- 不为移动端重新手写 UE API；
- 不允许 Shipping 设备端 JIT 或下载后执行新 native artifact；
- 不把单个 universal package 混装互不兼容的 native artifact；
- 不因移动支持破坏 Win64 Wasmtime 性能主线。
