# P63.C Android 交叉 AOT 与多平台发布

## 已实现

- VM artifact compile request 显式携带 target triple，缓存、attestation 与 compiler identity 均绑定目标平台；
- Wasmtime compiler profile 同时支持 `x86_64-pc-windows-msvc / x86-64-v3` 与
  `aarch64-linux-android / arm64-v8a`；
- Windows 受控性能工具链升级为 `patchset.2`，启用官方 `all-arch` feature，并增加受控
  `Engine::precompile_module` C API；
- Android artifact identity 绑定锁定的 `libwasmtime.a` SHA-256，不使用 Windows 编译器 DLL
  作为目标运行时身份；
- Android Runtime 只接受已验证的 `wasmtime_serialized_v1`，禁止 JIT 与松散 WASM 回退；
- C# Release、Commandlet、模块发布器与 catalog 支持 `Win64|Android`，Android Development
  和 Shipping 均固定 `require_precompiled`；
- package schema 严格校验 platform、architecture、target triple、CPU features 与 policy 组合。

## 验证中发现并修复

1. 首次交叉编译发现旧性能 DLL 未编入 AArch64 Cranelift 后端。工具链现锁定 `all-arch`，
   合同会阻止该 feature 再次丢失。
2. `Module::new + serialize` 只能生成本机可执行模块。artifact compiler 已改用
   `Engine::precompile_module`，并在 managed install/verify 中强制检查扩展导出。
3. UE 会提前消费全局 `-TargetPlatform` 参数。Commandlet 参数已命名空间化为
   `-AvidScriptTargetPlatform`，避免发布流程错误依赖本机 Android SDK 状态。
4. Android-only 模块写入全局 catalog 后，旧 UBT staging 会要求它也提供 Win64 变体，
   从而阻塞 Editor 构建。staging 现完整校验 catalog，但只装载当前目标唯一匹配的变体；
   其他平台模块会被跳过，多平台 catalog 不再互相污染开发流程。
