# P63.D 移动 Runtime 生命周期

## 已实现

- 新增 `FAvidScriptRuntimeLifecycleCoordinator`，集中接入 UE 的应用后台、前台恢复、
  低内存和 World cleanup 事件；Session 不各自绑定全局 delegate。
- 所有 Runtime Session 自动注册到协调器。应用进入后台后，Tick、事件、delegate 与
  module replacement 不再进入 Guest；恢复时统一校验 application generation、Runtime
  identity、module id、World 和 owner handle generation。
- 有效 Session 恢复后继续使用原 Runtime 与 continuation 队列；World 或 owner 已失效时，
  直接取消 delegate、inbound handler、Timer/continuation 并无 Guest 回调卸载，旧 Session
  不会在 foreground 时复活。
- 低内存通知清理 Wasmtime AOT 内存缓存和 Session Profiler 历史，不破坏 live Runtime，
  已签发 artifact attestation 继续有效。
- 生命周期状态与抑制、低内存、失效计数进入 Session snapshot，便于后续设备诊断。

## 架构边界

```text
UE Core/World delegates
        |
        v
RuntimeLifecycleCoordinator
        |
        +-- RuntimeSession pause/resume/generation gate
        +-- RuntimeSession teardown cancellation
        `-- AvidScriptVM artifact memory-cache release
```

平台事件只存在于 Runtime composition 层；Binding、Guest IR、生成类型和游戏 API 不包含
Android/iOS 分支。普通 World Session 在 cleanup 时采用无 Guest 回调卸载，避免在对象图销毁期间
重新进入脚本；生成式 `UWorldSubsystem` 则延后到 UE 的 `Deinitialize`，保证终止回调恰好进入 C# 一次，
随后由生成类型 Runtime Host 完成 Session 清理。

## Gate 回归修复

完整 Automation 首轮发现 `OnWorldCleanup` 早于 `UWorldSubsystem::Deinitialize`，原实现会提前
清空生成式 Session，使 C# `Deinitialize` 计数为 0。修复后仅延后生成式 WorldSubsystem 的硬失效；
Actor、Component 和普通 World Session 的 teardown 取消策略不变。现有
`AvidScript.GeneratedTypes.CSharpLifecycleKinds` 作为回归合同，不再新增重复测试。
