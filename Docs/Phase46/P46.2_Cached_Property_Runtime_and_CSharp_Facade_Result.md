# P46.2 缓存属性 Runtime 与 C# Facade 成果

> 状态：已完成
>
> 范围：只读 `UPROPERTY` binding，不包含属性写入与真实 C# 生命周期闭环

## 1. 本阶段解决的问题

P46.1 已能把反射属性写入 descriptor v4，但描述符还不能被 Runtime 调用，也不能进入正式 C# 发布链。P46.2 把 `property_get` 从静态元数据推进为可执行能力，并继续遵守“不为每个 UE API 手写 binding”的方向。

完成后的路径为：

`FProperty` 选择 -> descriptor v4 -> canonical C# emission -> 最小 binding slice -> package load 缓存 plan -> object handle 校验 -> guest memory 写回。

## 2. Runtime 实现

- package load 按 `owner_class + ue_member` 解析真实 `FProperty`，重新验证 Blueprint visibility、canonical type、stable identity 与 `(iii)i` ABI。
- invocation plan 缓存 `FProperty*`、调试路径和既有 return-value marshalling plan。
- dispatch 继续使用对象 registry 的 slot/generation 校验，不允许悬空或过期 UObject handle。
- 属性值通过既有 `WriteAvidScriptRuntimeValueToGuest` 写回 WASM 线性内存，不创建 `ProcessEvent` frame，也不执行 `UFunction`。
- 热路径不解析 JSON、不按名称查找属性、不包含 `CustomTimeDilation` 等逐属性 switch。

## 3. C# 与发布链

生成的 API 是普通只读属性：

```csharp
float dilation = UE.Self.CustomTimeDilation;
```

Renderer 在属性 getter 内调用对应的生成式 DllImport。Emitter 的 canonical regeneration 与 `CSharpBindingSliceService` 都按 `binding_kind` 分流，函数继续走函数选择，属性走属性选择，因此 bootstrap 语义闭包选中的属性 import 可以进入最终最小 runtime package。

## 4. 跨模块合同修复

聚焦测试首次在 Editor 模块实现 `IAvidScriptVmGuestMemory` 时，暴露了既有跨 DLL 合同缺口。本阶段补齐：

- `AvidScriptVM` owner 提供显式导出的接口构造与虚析构定义；
- 实际构造该接口的 Editor 声明对 `AvidScriptVM` 的直接私有依赖；
- owner、Bindings、Runtime、Editor 使用同一 no-clean target 命令重编译验证。

这使后续测试内存、调试工具或其他 VM memory adapter 可以在 VM 模块外合法实现接口。

## 5. 验证结果

- UE5.8 source build：`AvidScriptVM + AvidScriptBindings + AvidScriptRuntime + AvidScriptEditor` no-clean 编译链接成功。
- `AvidScript.Editor.BindingRuntime.ReflectedPropertyGet`：1/1 Success。真实读取 `AActor.CustomTimeDilation = 1.75` 到 guest memory，并验证 stale generation 被拒绝且内存不被改写。
- `AvidScript.Editor.CSharpBindingEmitter.PropertyGet`：1/1 Success。验证普通 C# 只读属性、真实 descriptor EntryPoint 与 manifest import 身份一致。
- `AvidScript.Editor.CSharpBindingSlice.Contracts`：覆盖 schema v4 属性授权包到最小 runtime slice 的 stable ID 与 Runtime load 合同。
- Architecture gate：锁定缓存 property plan、marshaller 复用、C# property renderer、kind-aware slice 与禁止逐属性生产代码。

## 6. 当前边界

P46.2 证明了 UE 反射属性可以通过正式 binding 管线被 Runtime 读取，但尚未证明一份用户 C# 游戏脚本已经编译成 WASM，并在 `BeginPlay` 或 `Tick` 中读取该属性后驱动可观察 UE 行为。该真实闭环属于 P46.3。

属性 setter 仍明确禁用。后续必须先解决 BlueprintSetter、replication/OnRep、config/editor-only/instanced policy 与 candidate reload transaction，不能直接写 `FProperty` 绕过引擎语义。
