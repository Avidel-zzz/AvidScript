# P46.3 真实 C# 属性游戏逻辑闭环成果

> 状态：已完成
>
> 结论：C# 用户脚本已能在 UE 生命周期中读取真实 `UPROPERTY` 并驱动游戏行为

## 1. 用户可见能力

正式 EngineGameplay facade 现在包含：

```csharp
[UnmanagedCallersOnly(EntryPoint = "avid_on_begin_play")]
public static void BeginPlay()
{
    float dilation = UE.Self.CustomTimeDilation;
    UE.Self.SetActorScale3D(new FVector(dilation * 2.0f, 3.0f, 4.0f));
}
```

测试 Actor 的 `CustomTimeDilation` 设置为 `1.25` 后，真实 C# -> WASM `BeginPlay` 把 X scale 设置为 `2.5`。这不是 C++ 直接 dispatch 或手工 WASM 夹具，而是完整 C# 游戏脚本构建与执行路径。

## 2. 正式 Profile 与最小包

- EngineGameplay 授权 profile 从 115 个函数扩展为 115 个函数加 1 个只读属性。
- Profile 仍是数据驱动选择；Runtime 与 Renderer 没有 `CustomTimeDilation` 专用 switch。
- 完整授权 descriptor 使用 schema v4，包含 116 个 binding。
- Roslyn reachability 只保留样例实际使用的属性 getter、`GetActorScale3D` 与 `SetActorScale3D`，最终 runtime slice 只有 3 个 binding。
- 测试中不可达的 `GetActorLocation` helper 不进入最终 package，证明属性加入授权面没有破坏最小能力裁剪。

## 3. Schema v4 消费链修复

真实两阶段构建发现两个旧消费者仍只允许 descriptor v2/v3：

1. `AvidScriptCSharpBindingPackage.ps1` 在 bootstrap package identity gate 拒绝 v4。
2. Runtime reload manifest loader 在最终 WASM package load 拒绝 `descriptor_schema_version=4`。

两处均保留原有 hash、path containment、package identity 与内容验证，只把允许版本集合扩展到 v4。Architecture gate 现同时锁定 PowerShell 与 Runtime 消费者。

## 6. 当前边界

P46 完成的是批量生成式只读属性链路。属性 setter、容器属性、delegate、多播事件、replication/OnRep 与脚本定义 UE 类型仍不在本阶段承诺内。

下一阶段应优先建立受控 property setter policy 与 reload transaction adapter，或扩展 object/struct/container marshalling；禁止通过直接裸写 `FProperty` 追求表面 API 数量。
