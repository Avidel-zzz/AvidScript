# P46 UE 反射属性绑定架构

> 状态：P46.3 完整闭环已验证
>
> 主线：UE5.8 Reflection -> Descriptor v4 -> C# Facade -> Guest IR -> WASM -> Cached Runtime Property Plan

## 1. 目标

P43-P45 已让 C# 通过生成式 `UFUNCTION` facade、最小 runtime package 和 WAMR 执行 UE 游戏逻辑，但 `UPROPERTY` 仍只能绕经手工 getter。P46 建立可批量扩展的反射属性管线，让 C# 能以正常 property 语法读取 UE 对象属性，并为后续受控写入、容器与脚本可编辑字段建立统一模型。

本阶段禁止为 `CustomTimeDilation`、`InitialLifeSpan` 等成员逐个新增 VM enum 或 Runtime switch。属性必须由 Profile、共享类型策略和 descriptor 自动产生。

## 2. 方案选择

### 2.1 不把属性伪装成 UFunction

把属性 getter 伪造成 `cached_process_event` binding 可以少改数据结构，但会让 `ue_function` 指向不存在的函数，并迫使 Runtime 在同一字段上猜测两种语义。该方案破坏 descriptor 的可审计性，也会阻碍 setter、通知和 replication policy，因此拒绝。

### 2.2 第一等 member binding

Descriptor v4 为每个 binding 增加：

- `binding_kind`：`function`、`property_get`，后续可增加 `property_set`。
- `ue_member`：真实 `UFunction` 或 `FProperty` 名。
- `dispatch_mode`：函数使用 `cached_process_event`，属性读取使用 `cached_property_get`。

v2/v3 parser 继续兼容历史 `ue_function`，在内存模型中归一化为 `binding_kind=function` 与 `ue_member`。新产物只写 v4。

## 3. 属性选择

Profile 对 class rule 增加属性发现开关、include/exclude 名称，并支持严格 explicit property。Resolver 对 `FProperty` 执行：

1. 限制在声明式 class 边界内，不扫描全部已加载对象。
2. 只接受 Blueprint visible 且可在 runtime 读取的实例属性。
3. 拒绝 editor-only、deprecated、delegate、容器、弱/软引用和未进入共享类型策略的类型。
4. 读取属性可以包含 Blueprint read-only；写属性必须另行满足 setter/replication/transaction policy。
5. 输出确定性排序、accepted/rejected 计数与结构化原因。

## 4. 类型与 ABI

属性复用 `FAvidScriptEditorReflectedTypePolicy`，不建立第二套类型映射。首版支持范围与函数参数一致：

- bool、整数、浮点和 enum；
- UObject handle；
- `FVector`、`FRotator`、`FTransform`。

实例 getter ABI 为 `(selfSlot:i32, selfGeneration:i32, returnAddress:i32) -> i32`。Runtime 通过对象 registry 验证 handle，在 package load 时缓存 `FProperty*` 和类型计划，调用时不做 JSON、名称查找或反射遍历。

## 5. C# 生成面

生成 facade 输出普通只读属性：

```csharp
public float CustomTimeDilation
{
    get
    {
        float value;
        _ = AvidScriptNative.Binding42(Slot, Generation, out value);
        return value;
    }
}
```

Roslyn reachability 会像处理 facade property getter 一样保留对应 DllImport，现有最小 binding slice 继续按 semantic callable closure 裁剪未使用属性。

## 6. Runtime 读取

Package load 对属性 getter 执行：

- 按 owner class 与 `ue_member` 一次性解析 `FProperty`；
- 重新核对 Blueprint visibility、访问策略、canonical type、ABI 与 stable identity；
- 缓存 object offset、`FProperty*`、value kind 和 guest storage contract；
- 将 import ordinal 与 invocation plan 一一绑定。

Dispatch 只解析对象 handle，并以目标 UObject 作为 property container 调用已有类型 marshaller 写回 guest memory。属性读取不分配 `ProcessEvent` frame，不执行 `UFunction`。

## 7. 写访问边界

P46.1-P46.2 不生成 setter。直接 `FProperty` 写入可能绕过 BlueprintSetter、replication/OnRep、push model、PostEditChange 和引擎不变量；candidate reload 还需要可逆 host-effect adapter。后续 setter 必须显式分类：

- 有 BlueprintSetter 时优先生成对应函数调用；
- 允许直接写的属性必须通过独立 policy；
- replicated/config/editor-only/instanced 等属性默认拒绝；
- candidate 写入没有 transaction adapter 时失败关闭。

## 8. 性能与安全

- 反射查找只发生在 package load，热路径使用 ordinal 与缓存计划。
- 属性 getter 不新增字符串 lookup、JSON 解析或动态分配。
- 对象 handle 和 expected class 每次调用仍由 registry 校验，避免悬空 UObject。
- package/selection/type/stable identity 全部进入内容哈希。
- property type 或 flags 与 descriptor 不一致时 load fail closed。

## 9. 首个真实闭环

P46.2 使用 UE5.8 `AActor.CustomTimeDilation`：

1. Profile 自动或显式选择 reflected property。
2. Descriptor v4 发布 `property_get`。
3. Facade 生成 `AActor.CustomTimeDilation`。
4. C# `BeginPlay` 或 `Tick` 读取该值并用既有生成式函数 binding 驱动可观察 Actor 行为。
5. UE Automation 验证真实 C# -> WASM -> property plan -> UObject 路径。

这条用例同时证明属性读取与现有函数调用、最小 package、生命周期和 debug map 可以组合，而不是孤立 parser 测试。

P46.3 已完成该闭环。正式样例在 `BeginPlay` 读取 `UE.Self.CustomTimeDilation`，由属性值决定 Actor X scale；同一 WASM 模块继续通过函数 binding 执行 Tick 与 transform 写入，并通过候选 reload transaction 的提交和回滚验证。
