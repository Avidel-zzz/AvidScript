# Phase 52 双向属性 Binding 实现报告

## 实现目标

Phase 52 把此前只读的 reflected property 接口升级为完整双向链路：项目通过 profile 显式授权可写属性，生成器发布稳定的 getter/setter 能力，C# 编译器只保留实际可达的访问器，WASM 通过缓存计划读写 UE 对象，并在 candidate reload 失败时恢复旧值。

本阶段没有为 `AActor.CustomTimeDilation` 等具体成员手写桥接。属性能力由 UE 反射、profile 选择和 descriptor 统一生成，示例中的成员只负责证明通用链路确实可用。

## Descriptor 与授权

descriptor schema v8 新增 `property_set` binding，并明确记录：

- `binding_kind`：区分 `function`、`property_get` 与 `property_set`；
- `write_policy`：区分 `direct` 与 `blueprint_setter`；
- `ue_function`：冻结 BlueprintSetter 对应的精确 `UFunction`；
- `reload_effect=reflected_property`：让 reload 事务识别可回滚写入；
- 稳定 ID 与 package hash：覆盖 setter 策略及其精确目标函数；selection hash 只标识 getter/setter 成员选择。

旧的只读 profile 不会因为 schema v8 支持而改变身份。只有显式声明 writable 的属性才会生成 setter，默认行为仍然是 fail-closed。

## C# 表面与编译链

生成的 C# facade 使用普通属性语法：

```csharp
AActor self = UE.Self;
self.CustomTimeDilation = 1.25f;
float current = self.CustomTimeDilation;
```

编译链完成了以下工作：

- getter 和 setter 分别拥有独立 capability，语义可达性按访问器精确裁剪；
- setter lowering 先求值 receiver，再求值右值，符合 C# 赋值顺序；
- 复合赋值只求值一次 receiver，避免属性链产生重复 UE 调用；
- scalar、object handle 与已支持的 inline UStruct 共用 descriptor ABI；
- 编译诊断保留原始 C# 文件、行号和列号；
- 生成代码中的 UE 对象 facade 是只读 struct，因此样例先把 `UE.Self` 缓存到局部变量，再执行属性写入。

## 运行时与回滚

Bindings 模块在 package load 时把属性解析成缓存执行计划。热路径不按字符串重新查找 class、property 或 setter function。

直接属性写入流程为：

1. 校验 packed object handle 与 owner authority；
2. 使用缓存 `FProperty*` 定位值；
3. 在 candidate transaction 中按对象和属性捕获首次写入前快照；
4. 执行类型匹配的 ABI 解码与写入；
5. candidate 成功时提交，失败时按逆序恢复。

对象属性快照使用强引用跨越 GC 窗口，避免回滚前目标 UObject 被回收。BlueprintSetter 由于可能包含不可逆副作用，在 candidate 阶段于 `ProcessEvent` 前拒绝执行；正常已激活 runtime 仍可使用显式授权的 setter。

## 游戏逻辑闭环

`Samples/CSharp/BidirectionalProperties` 是本阶段的可运行示例。它通过真实 profile 构建请求完成：

```text
C# source
  -> Roslyn semantic model
  -> accessor-level reachability
  -> Guest IR
  -> WASM
  -> runtime binding slice
  -> WAMR
  -> UE Actor
```

示例在 `BeginPlay` 写入 `CustomTimeDilation` 并设置 Actor scale，在 `Tick` 更新属性并用 `FVector` 读改写 scale，在 `EndPlay` 恢复初始状态。最终 focused Automation 已证明：

- profile 构建执行 bootstrap 与 final 两轮；
- runtime slice 只保留实际使用的 setter，不携带未使用 getter；
- manifest、WASM 与 runtime package 可以共同加载；
- `BeginPlay`、`Tick`、`EndPlay` 均进入 UE 对象；
- scalar 属性和 `FVector` 参数/返回值在真实运行时生效。

`K2_SetActorLocation` 尚未用于该样例，因为它同时依赖 sweep、`FHitResult` 和 out/ref UStruct 边界。Phase 52 没有用手写特例掩盖这个缺口，而是用当前已支持的 `GetActorScale3D/SetActorScale3D` 验证现有通用 FVector ABI；out/ref UStruct 将作为下一阶段的通用能力继续推进。

## 性能基线

最终 anti-fold focused benchmark 的 UE5.8 Development Editor / NullRHI 结果为：

| 路径 | P50 | P95 |
| --- | ---: | ---: |
| Native setter | 0.000000393 ms | 0.000000975 ms |
| Cached binding setter | 0.000196480 ms | 0.000212887 ms |
| WAMR setter | 0.001013475 ms | 0.001106841 ms |

11,776 次调用保持一次 import crossing，warm class lookup、reflected-name lookup 与重复 snapshot capture 均为 0。benchmark 通过跨调用 checksum 消费结果并禁止关键函数内联，替代了 P52.4 中会被编译器折叠的初步 native 数字。

## 兼容与剩余边界

本阶段保持 Phase 51 的 object/component、typed facade、runtime slice 与 package provenance 合同不变。当前仍未宣称覆盖：

- 任意 out/ref UStruct 和 `FHitResult`；
- `TArray/TMap/TSet` 等容器；
- multicast delegate、动态事件与脚本回调订阅；
- Cook、Shipping、Android 与 iOS；
- 与 Puerts、UnLua、AngelScript 的同机 Shipping benchmark。

这些边界将继续通过 descriptor 和通用 ABI 扩展解决，不转化成逐个手写 UE API。
