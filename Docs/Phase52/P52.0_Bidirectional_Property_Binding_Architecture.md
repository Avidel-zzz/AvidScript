# P52 双向属性 Binding 架构

## 目标

Phase 52 把现有只读 reflected property 链路升级为 descriptor 驱动、显式授权、缓存执行并支持 candidate reload 回滚的双向属性能力。用户 C# 应能用普通 `get`/`set` 属性编写 UE 游戏逻辑，新增属性不能进入手写 API 表，也不能在热路径按名称查找 `FProperty` 或 `UFunction`。

本阶段交付 scalar、enum、`FVector`、`FRotator`、`FTransform` 与 UObject handle 等现有 marshaller 已支持类型的 property setter。任意递归 `UStruct`、`TArray/TSet/TMap` 与通用 delegate 在 Phase 53/54 继续扩展，但必须复用本阶段建立的 member capability、write policy、缓存 plan 和 transaction contract。

## 当前缺口

Phase 46/47 已具备批量属性发现、descriptor `property_get`、缓存 `FProperty*` getter plan、自然 C# 只读属性、对象 handle 返回和 runtime slice 裁剪，但仍存在以下成熟度缺口：

1. profile 不能表达某个属性是否允许脚本写入；
2. descriptor 只有 getter，没有 setter identity、dispatch mode 与写语义；
3. Runtime 不能区分安全直接写与必须调用 BlueprintSetter 的属性；
4. candidate reload BeginPlay 中的属性写入无法回滚；
5. C# facade 无法生成 `set` accessor，真实脚本必须退回手写函数；
6. setter 性能与 warm lookup 预算没有冻结证据。

## 核心模型

### Profile access intent

属性选择从单纯 readable 扩展为显式 access intent：

- `read`：保持当前 getter 行为；
- `write`：必须由 profile 明确授权，默认关闭；
- include/exclude 与 strict explicit property 继续由共享 selection resolver 处理；
- 自动 discovery 不因属性表面为 BlueprintReadWrite 就自动开放写权限。

Profile schema 升级必须保持旧 schema 读取兼容。旧 profile 的所有属性均解释为 `read=true, write=false`。

### Descriptor v8 member capability

Descriptor v8 继续使用统一 `bindings` 数组，通过 `binding_kind` 区分：

- `function`；
- `property_get`；
- `property_set`。

每个 setter 具有独立 stable identity、ordinal、host import 与 canonical hash。setter value 作为一个 direction=`value` 的参数进入现有 type/value model；返回值为 `void`。Descriptor 同时发布：

- `ue_member`：属性名；
- `dispatch_mode`：`cached_property_set` 或 `cached_blueprint_setter`；
- `write_policy`：冻结生成期决策，不由 Runtime 猜测；
- `reload_effect`：必须为可回滚的 `reflected_property`，否则不能进入 writable selection。

Canonical serialization、selection hash、package hash、runtime slice 与 Guest provenance 都必须包含 setter，避免 authorization package 与 runtime package 对写权限产生分歧。

### Write policy

生成期独立 `PropertyWritePolicy` 负责资格判断。首批规则：

- 必须可在 Runtime 访问，且 profile 显式声明 write；
- 拒绝 `BlueprintReadOnly`、`EditConst`、config/global-config、editor-only、instanced/contains-instanced、delegate、container 和 unsupported type；
- replicated/RepNotify 属性在没有专用 replication adapter 前失败关闭；
- 存在有效 BlueprintSetter 时优先生成 `cached_blueprint_setter`，并复用 UFunction 参数/返回 ABI 校验；
- 没有 BlueprintSetter 时只允许 policy 明确认可的直接 `FProperty` 写入；
- UObject handle 写入必须校验 null、stale handle 与目标 class 协变关系；
- policy 结果和拒绝 category 进入 compatibility report，不靠 Runtime 静默降级。

### Immutable runtime plan

Package load 阶段完成：

1. 解析 descriptor v8 setter；
2. 解析并校验 owner `UClass*` 与 `FProperty*`；
3. 对 BlueprintSetter 一次性解析 `UFunction*` 和 frame layout；
4. 构建 ordinal 索引的 immutable setter plan；
5. 计算最大 scratch size；
6. 校验 descriptor type、实际 `FProperty`、setter parameter 与 dispatch mode 完全一致。

热路径只执行 ordinal lookup、object handle authority、marshaller decode、transaction prepare 与缓存 plan dispatch。禁止 JSON、字符串 lookup、反射遍历和每次调用堆分配。

### Candidate reload transaction

属性写入属于 Host effect。`IAvidScriptBindingHostEffectJournal` 扩展 property write prepare contract，按 `(object handle, property stable id)` 首次写入时捕获旧值；同一 candidate 重复写同一属性只保留第一个快照。

快照必须使用 `FProperty` 的 initialize/copy/destroy 语义和满足其 alignment 的 storage，不能对 FString、UObject、struct 等值做裸 `memcpy`。候选成功时提交并销毁快照；候选失败时逆序恢复，stale object 或 schema mismatch 产生稳定 rollback 诊断并保留旧 runtime。

初始 load 和正常 active runtime 不创建 journal，直接执行授权写入；candidate reload 只有在快照成功后才能修改 UE 对象。

### C# 与 Guest/WASM

Renderer 把成对 getter/setter 合并为自然 C# 属性：

```csharp
public float CustomTimeDilation
{
    get => Native.GetCustomTimeDilation(_handle);
    set => Native.SetCustomTimeDilation(_handle, value);
}
```

只有 setter 时仍可生成 write-only accessor，但默认 profile 不发布这种表面。Roslyn semantic、binding slice、Guest IR 与 WasmBackend 继续把 accessor 视为稳定 callable，不按 C# 方法名猜测 UE API。setter 的 reachability 只把实际使用的 import 和所需 object type 闭包带入 runtime package。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| `AvidScriptCore` | 不新增 UE、Roslyn 或 WAMR 类型。 |
| `AvidScriptEditor` | profile access intent、write policy、descriptor v8、C# facade 与 runtime slice。 |
| `AvidScriptBindings` | descriptor/parser/model、immutable getter/setter plan、marshaller 与 property host-effect 抽象。 |
| `AvidScriptRuntime` | property snapshot transaction、Session/reload 组合与 WAMR dynamic import 路由。 |
| `AvidScriptVM` | 继续只承载动态 import/call frame，不感知 FProperty。 |
| C# toolchain | 从 semantic callable metadata lower setter，不维护 UE API 表。 |

## 性能预算

- package load 后 warm property setter class load = 0；
- warm reflected-name lookup = 0；
- 直接 setter 每次调用恰好一次 WASM -> Host crossing；
- 无 candidate journal 时 setter 热路径不分配；
- 同一 candidate 对同一对象属性重复写只分配/捕获一次快照；
- 与同类型 getter 使用同一 benchmark harness，发布 P50/P95 与 native direct write 对照；
- Phase 52 不宣称跨机器百分比回归，先建立同机冻结基线。

## 安全与失败关闭

- descriptor 与真实反射 flags/type/owner 不一致：package load 失败；
- 未授权 setter import：runtime slice/provenance 失败；
- stale/wrong-type receiver 或 value handle：当前 call trap，不写属性；
- candidate snapshot 失败：拒绝写并触发候选回滚；
- BlueprintSetter trap/异常路径：按 host import failure 处理，旧 runtime 不被替换；
- 任何失败都不得发布部分 runtime package、WASM 或 manifest。

## 非目标

- replicated/RepNotify、push-model replication 与网络 RPC；
- config/editor-only/instanced property 写入；
- 任意递归 `UStruct`、容器属性与字符串所有权；
- delegate 订阅、latent/async 调用；
- Blueprint graph-defined function override；
- 移动端和 Shipping 性能验收。

## 阶段出口

Phase 52 只有在以下条件全部满足后才能 close：

1. schema/profile/descriptor/runtime/C# 全链路支持通用授权 setter；
2. 至少一个 scalar 和一个 struct/object 类型进入真实 C# -> WASM -> UE 游戏逻辑；
3. candidate success commit 与 failure rollback 均有真实 Runtime 证据；
4. runtime slice 和 Guest provenance 能拒绝未授权 setter；
5. warm lookup、crossing 与 setter P50/P95 已采样；
6. 独立审查无未解决 Critical/Important；
7. 集中 no-clean UE5.8 UBT 与完整 Automation Gate 通过。
