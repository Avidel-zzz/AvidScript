# Phase26 类型化 UE API 基础范围

## 目标

Phase26 开始把 C# gameplay API 从扁平静态函数升级为 UE 风格的强类型调用。首个纵切提供 `FVector`、`AActor` 和 `UE.Self`，并让脚本通过安全对象句柄操作 `UAvidScriptComponent` 的真实 owner Actor。

目标写法：

```csharp
UE.Self.SetActorLocation(new FVector(100.0f, 200.0f, 300.0f));
UE.Self.AddActorWorldOffset(new FVector(2.0f, 0.0f, 0.0f));
UE.Self.SetActorLocation(FVector.Zero);
```

## 本阶段交付

- C# `FVector` 顺序布局值类型，以及 `Zero` 常量。
- C# `AActor` 句柄包装，只保存 slot 和 generation。
- `UE.Self` 从宿主获取当前脚本 owner，不硬编码对象槽位。
- `owner_get_slot` 与 `owner_get_generation` 两个 WAMR host imports。
- `SetActorLocation` 与 `AddActorWorldOffset` 类型化写调用。
- 旧 `Actor.SetLocation` 与 `Actor.AddLocationOffset` 兼容路径。
- 使用非 1 号对象槽位的端到端测试。
- adapter contract `actor_lifecycle_v5`、中文使用文档和完整自动化回归。

## 安全与性能约束

- guest 永远不能接触 `UObject*` 或宿主地址。
- UObject 引用必须经过 object registry 的 slot/generation 校验。
- 高频 Transform 调用继续使用专用 ABI，避免逐帧反射分发和参数装箱。
- ABI 只使用明确宽度的标量，保持后续移动端 AOT 兼容性。
- Phase26 不 clean Editor Target，只做模块级增量构建。

## 非目标

- 任意 `UFUNCTION`、`UPROPERTY` 反射调用。
- `GetActorLocation()`、局部 `FVector` 表达式与向量运算。
- `FRotator`、`FTransform`、组件、Spawn、输入、Timer、Overlap、Hit 和委托。
- Android/iOS 打包验证。

这些能力将在后续 typed read、常用 UE 类型和绑定生成器阶段逐步加入。
