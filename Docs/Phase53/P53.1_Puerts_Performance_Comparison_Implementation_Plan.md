## 1. 执行原则

- 先完成一个架构批次，再集中进行构建与验收；
- parser、schema、fixture checksum 等秒级检查可以在批次内运行；
- UBT 与完整 Automation 只在 P53.2 集成点、P53.4 优化候选和 P53.5 Gate 运行；
- 阻塞性的 ABI、Guest Memory、生命周期和错误数据风险立即验证；
- 普通警告和非阻塞测试债务进入批次末统一修复；
- 人读文档使用中文；
- 三份现有用户文件保持未修改、未暂存；
- 第三方源码和二进制不进入 AvidScript Git。

## 8. 风险与处理

### Puerts 尚未正式支持 UE5.8

先固定官方提交并保留最小兼容 patch。若 V8 backend ABI 或引擎 API 变化导致无法在阶段预算内安全修复，状态机新增 Critical 债务并保留完整编译证据；AvidScript 不得因此虚构 Puerts 数据。

### 静态绑定生成链与反射链口径不同

分别报告两条 lane，并确保它们调用相同 fixture。反射 lane 用于默认广覆盖路径对标，静态 lane用于优化上限，不互相替代。

### V8 JIT 与 WAMR 预热模型不同

Cold 和 warm 分开，warmup 不计时。纯脚本、单 crossing 和脚本内批量 crossing 同时测量，避免只选择有利粒度。

### Editor 噪声

使用独立进程、多 run、MAD 和最小计时区间。噪声过大时增加 run，不放宽领先阈值。

### 为 benchmark 过拟合

优化必须位于正式 dispatcher、plan、marshal、registry 或 VM cache，并覆盖至少两个 fixture/类型合同；fixture 名称不得出现在生产 fast path。
