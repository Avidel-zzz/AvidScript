## 1. 结论

本轮没有为 benchmark 增加专用 API，也没有关闭 generation、stale handle、UObject 有效性或类型检查。优化仅取消了动态 binding 成功路径中无人消费的 `UObject::GetPathName()` 与结果字符串填充：

- 成功调用仍通过 `FAvidScriptObjectRegistry::ResolveObject`；
- 失败调用仍生成完整 category、slot、generation 和 next action；
- owner class 仍执行 `IsA` 校验；
- reload、ownership、Guest Memory 和 capability 合同不变。

正式 5 进程矩阵显示，涉及 UObject target resolve 的 workload 提升 `20.2%` 到 `34.9%`。十项 workload 的 AvidScript/Puerts Reflection 几何平均比率从 `6.99x` 降至 `5.73x`，相对 Puerts Static 从 `11.82x` 降至 `10.00x`。

## 4. 成本分层

正式 workload 与受控 A/B 可以给出以下稳定边界：

1. `pure_integer` 的 `58.12 ns/op` 主要暴露 WAMR fast interpreter 与 V8 JIT 的执行层级差距；
2. `callback_tick` 的 `477.48 ns/op` 和 `callback_empty` 的 `601.06 ns/op` 给出生命周期/回调 crossing 的量级；
3. `property_get_set` 的 `776.21 ns/op` 是当前最轻的 UObject binding 路径；
4. 简单 UFunction 位于 `917.80` 到 `977.12 ns/op`；
5. FVector 值与 ref/out 位于 `1130.94` 到 `1167.08 ns/op`；
6. `object_roundtrip` 仍受返回对象 lease/ownership 与 handle 写回影响，达到 `1321.08 ns/op`。

这说明继续微调 `FString`、局部 context 或 frame helper 已不是最高收益方向。下一数量级优化需要改变执行层和 binding tier，而不是继续堆叠零散分支。

## 5. 被拒绝的候选

本轮还验证并撤销了两项候选：

- 延迟动态 import 指标换算并缓存 invocation context：主要 workload 只有噪声级变化；
- 缓存 UFunction frame 初始化/析构属性链：复测后稳定收益约为 `0%` 到 `3%`，不足以覆盖额外复杂度。

两项候选均未进入最终运行时代码。该决策避免以复杂度换取不可重复的跑分。
