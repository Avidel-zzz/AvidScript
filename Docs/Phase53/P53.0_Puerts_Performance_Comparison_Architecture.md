# P53.0 Puerts 同机性能对标架构

> 状态：已批准，进入实施
>
> 日期：2026-07-26
>
> 平台：UE5.8 源码版、Win64、Development Editor、NullRHI

## 1. 阶段目标

Phase 53 建立第一套可公开复现的 AvidScript 与 Puerts 同机、同项目、同负载性能基准，并依据测量结果优化 AvidScript 的真实热路径。

本阶段固定比较四条执行路径：

1. Native C++：确认 fixture 与计时器自身成本；
2. Puerts V8 反射调用：代表普通项目默认使用的广覆盖路径；
3. Puerts V8 静态绑定：代表 Puerts 针对性能关键 API 的优化上限；
4. AvidScript C# -> WASM -> WAMR -> 缓存 Binding Plan：代表 AvidScript 正式用户路径。

阶段完成不以“跑出一组数字”为标准。若 AvidScript 在目标热路径落后，必须定位 CPU、crossing、封送、句柄解析、Guest Memory 或 ProcessEvent 层的具体成本，完成至少一轮实现优化并用同一套不可变 workload 复测。

## 2. 非目标

- 不在本阶段同时引入 Puerts Node.js、QuickJS、UnLua 或 AngelScript；
- 不把 UE5.6 与 UE5.8、Editor 与 Shipping、PC 与移动端数据混在一起；
- 不用不同语言实现不同算法后比较总耗时；
- 不用只测纯语言循环代表游戏脚本交互性能；
- 不为取得优势关闭 V8 JIT、跳过 Puerts 预热或隐藏 Puerts 静态绑定结果；
- 不把竞品源码、V8 二进制、构建产物或本机绝对路径提交到 AvidScript Git；
- 不在 AvidScript Runtime、VM、Bindings 或 Core 中引入 Puerts 依赖。

QuickJS 与移动端将在 PC/V8 基线稳定后进入后续阶段。

## 3. 依赖与版本固定

Puerts 只从 Tencent 官方仓库获取。安装清单必须记录：

- Git remote；
- immutable commit SHA；
- tag 或 release 名；
- V8 backend 版本；
- 下载地址；
- 每个外部归档的 SHA-256；
- UE5.8 兼容补丁的独立 diff 与原因；
- 安装时间和安装脚本版本。

优先验证官方最新 Unreal release。若该版本只支持较早 UE 版本而无法编译 UE5.8，则比较官方 release 与官方 `master`：

1. 选择能以最小补丁编译 UE5.8 的官方提交；
2. 将提交 SHA 固定到 tracked lock manifest；
3. 兼容补丁放在 benchmark 目录，不改写上游历史；
4. 安装脚本每次运行验证 remote、commit、dirty state 和归档 SHA-256；
5. 任一身份不匹配时失败关闭。

Puerts 与 V8 位于工程级 `Plugins/Puerts`，不进入 AvidScript 仓库。安装脚本不得读取或输出凭据。

## 4. 隔离架构

```text
AvidScript repository
  Benchmarks/PuertsComparison/
    AvidScriptPerfHarness/       # 中立 UE benchmark plugin 源码
    Scripts/                     # 安装、运行、聚合、验证
    Workloads/                   # C# 与 TypeScript/JavaScript 等价负载
    Schema/                      # 结果与 lock manifest schema
    Config/                      # 固定采样配置

UE project
  Plugins/AvidScript             # 被测正式插件
  Plugins/Puerts                 # 固定上游版本，不纳入 AvidScript Git
  Plugins/AvidScriptPerfHarness  # 指向 tracked harness 的本地挂接
  Saved/AvidScriptBenchmarks/    # 原始结果与日志，Git ignored
```

`AvidScriptPerfHarness` 依赖 AvidScript 和 Puerts，但 AvidScript 不反向依赖 harness。删除工程级 Puerts 与挂接后，AvidScript 的正式构建和发布行为保持不变。

## 5. 中立 Fixture

共享 `UObject` fixture 提供语义简单、可验证且覆盖常见封送面的 UFUNCTION：

- `NoOp()`；
- `AddInt32(int32 Left, int32 Right) -> int32`；
- 标量属性 get/set；
- `FVector` 输入、返回和 ref/out；
- `UObject`/`AActor` 参数与返回；
- 固定、可重放的混合 gameplay step。

每条脚本路径执行同样的迭代次数、输入序列和整数 checksum。计时结束后由 C++ 比较：

- 返回值；
- fixture 最终状态；
- checksum；
- 调用次数；
- AvidScript host crossing；
- warm path 名称查找、反射扫描和分配计数。

任一正确性条件不成立，该样本无效，不能参与性能排名。

## 6. Benchmark 矩阵

| 组别 | 测量方向 | 工作负载 | 主要指标 |
| --- | --- | --- | --- |
| Cold | Host 初始化 | VM 创建、模块加载、首调用 | elapsed、峰值/稳定内存 |
| Callback | UE -> Script | 空函数、BeginPlay、Tick | ns/call、P50、P95 |
| Pure | Script 内部 | 整数、分支、循环、checksum | ns/op、P50、P95 |
| Scalar | Script -> UE | NoOp、AddInt32、返回值 | ns/crossing、P50、P95 |
| Property | Script -> UE | 同一标量属性 get/set | ns/op、P50、P95 |
| Struct | Script <-> UE | FVector input/return/ref-out | ns/op、P50、P95 |
| Object | Script <-> UE | Actor handle、方法调用 | ns/op、P50、P95 |
| Batch | Script -> UE | N 次标量与一次批量等价操作 | crossing、摊销成本 |
| Memory | Host | warm idle、workload 后稳定集 | committed、working set |

Cold 与 warm 数据必须分开。V8 JIT 预热完成后才进入 warm sample；AvidScript 也执行同样数量的无计时 round。

## 7. 采样规则

- 每个 warm workload 至少 5 个独立进程 run；
- 每个进程 5 次 warmup、30 个正式 sample；
- 每个 sample 的迭代数经过校准，使计时区间不低于 5 ms；
- 所有 lane 使用同一迭代数，不单独为某一框架缩短 workload；
- 每个进程内轮换 lane 顺序，跨进程平衡顺序偏差；
- 使用 `FPlatformTime::Cycles64`，记录计时器频率；
- 报告 per-operation P50、P95、MAD、最小值和总操作数；
- 原始 sample 不删除；异常值只能标记并解释，主报告同时保留全量统计；
- 记录 CPU、内存、Windows、UE BuildId、Target、Configuration、commit 和 runtime 模式；
- 构建、Editor 启动与 benchmark 测量分开计时。

默认不把 Editor 启动时间算入 VM cold start。需要测完整启动时，另开指标并保持所有 lane 口径一致。

## 8. 公平性与防作弊合同

1. Native、Puerts 和 AvidScript 使用同一 fixture object；
2. workload 输入由 C++ 生成，固定 seed；
3. 结果参与 checksum，防止 JIT 或编译器消除工作；
4. Puerts 反射和静态绑定分别报告，禁止只选择较慢结果作为对手；
5. Puerts 使用官方建议 V8 配置，AvidScript记录 WAMR 执行模式；
6. 所有 binding cache 在 warmup 前完成，cold 测试另行记录；
7. 测量期间不输出逐调用日志；
8. 同一报告只能聚合相同 commit、引擎、配置和 workload schema；
9. 运行器发现插件 dirty、lock 不匹配或结果 schema 不同立即拒绝聚合；
10. benchmark 代码和原始结果 schema公开在仓库中。

## 9. 性能判定

不使用单一综合分数替代分项数据。阶段报告按以下层次陈述：

- **已领先**：同一 workload 的独立进程中位数和 P95 均优于对手，且差异大于测量噪声；
- **持平**：差异位于 5% 或两倍 MAD 内；
- **落后**：中位数或 P95 稳定落后超过 5%；
- **不可比较**：正确性、版本、配置或样本合同未满足。

Phase 53 的性能目标：

1. AvidScript 在 Scalar、Property、Struct 和 Object 四个主要交互组的几何平均 warm P50 不高于 Puerts V8 反射路径；
2. 上述任一主要组不得稳定落后 Puerts V8 反射路径超过 10%；
3. AvidScript 的生命周期 callback 与批量 crossing 必须单独给出结构计数；
4. Puerts 静态绑定作为性能上限完整报告；AvidScript 未达到时必须说明成本来源，禁止改称“未纳入目标”；
5. 若初始 baseline 未达标，至少完成一轮 profile-guided 优化和复测，阶段报告列出优化前后 delta；
6. 没有数据前不预先宣称 AvidScript 已领先。

## 10. 优化边界

允许的优先优化方向：

- cached ordinal 到 invocation plan 的分支和查表；
- host import dispatcher 的重复验证消除；
- thread-local/preallocated argument frame；
- blittable FVector fast path；
- object handle resolve cache 与 generation validation；
- 批量 crossing；
- WAMR exec env 与 function instance 缓存；
- 成功路径诊断、字符串和临时分配消除。

不允许：

- 为 benchmark fixture 名称写专用 fast path；
- 跳过生产路径的安全验证；
- 用未经用户 API 暴露的内部函数替代正式 C# binding；
- 为获得数字破坏 reload、ownership、Guest Memory 或 capability 隔离。

优化必须适用于一类 ABI、类型或调用计划，并有结构测试证明没有退化为手写 API 表。

## 12. 完成定义

- Puerts 和 V8 由 immutable lock 与 SHA-256 固定；
- UE5.8 兼容状态和全部补丁可重放；
- 四条 lane 在同一 fixture 上通过正确性校验；
- benchmark 可从脚本一键安装、构建、运行和聚合；
- 原始 JSON 与聚合报告携带完整 provenance；
- 至少完成一次首轮 baseline、一次瓶颈分析和一次复测；
- 每个主要 workload 都报告 P50、P95、MAD、操作数和结构计数；
- 未隐藏 Puerts 静态绑定、失败样本或 AvidScript 落后项；
- 生产 AvidScript 模块不依赖 Puerts；
- 中文结果文档明确“已领先、持平、落后、不可比较”的边界；
- 阶段债务中不存在 Blocker、Critical 或 Important；
- 候选提交通过集中构建、Automation、隐私扫描和 Phase Gate。
