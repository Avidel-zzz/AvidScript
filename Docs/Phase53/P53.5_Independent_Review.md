# P53.5 独立复审报告

> 日期：2026-07-26
>
> 结论：在“本机受信任用户与构建工具”威胁模型内，Critical 0、Important 0。Cold/RSS lane 隔离明确转入 Phase 54。

## 1. 复审范围

复审覆盖四条 lane 的公平性、校准与统计方法、Puerts 依赖来源、候选工程隔离、正式 runner 身份、WASM/manifest 身份、动态 UObject handle 优化和失败诊断。

正式数据必须同时满足：

- AvidScript 候选 commit/tree/clean 状态与 runner 所在 checkout 一致；
- Puerts 官方 commit、plugin tree、V8 asset SHA-256、安装 marker 和 1077 个受管文件摘要一致；
- 使用 `Engine/Binaries/Win64/UnrealEditor-Cmd.exe`，记录真实 EXE SHA-256 与版本；
- profile、request、calibration、result、aggregate schema 均固定 SHA-256；
- baseline 与 optimized 仅有一个生产源码文件、6 行 handle resolve 行为差异；
- 每个候选使用 1 个校准进程、5 个独立计时进程和 6000 条原始样本；
- 任意错误 checksum、错误 operation count、混合身份或被修改制品均失败关闭。

## 2. 复审发现与关闭

| 发现 | 严重度 | 关闭方式 |
| --- | --- | --- |
| handle resolve 成功路径优化会丢失失败诊断对象路径 | Important | 成功先关闭诊断构造；仅失败时以诊断模式重试，失败 category 与完整路径保留 |
| 正式 provenance 可由调用方字段伪造 | Critical | 重新读取候选 Git、项目 marker、Puerts lock/marker、WASM/manifest 和 Editor EXE 身份 |
| Puerts 安装只验证 marker，不验证安装内容 | Critical | schema v2 marker 增加内容 SHA-256 与文件数，正式 runner 原样重算 |
| 单次冷校准可能把低于 5 ms 的迭代数冻结 | Important | 达阈值后追加三次稳态确认，以中位数决定 |
| Puerts 与 AvidScript 计时边界不对称 | Important | Puerts receiver 进入同一 timed action，checksum 读取移出计时区间 |
| 工程 junction、Source/Config 与 runner checkout 可漂移 | Important | marker v2 固定 canonical path、内容摘要、候选 commit/tree，并在正式运行前复验 |
| Windows CRLF 导致依赖锁身份漂移 | Important | 锁文本先规范化换行再 SHA-256，并固定 `eol=lf` |
| Puerts C# UBT 项目会在源码树下生成 `obj` | Important | 只排除唯一已确认 C# 项目的精确 `bin/obj` 前缀，其他嵌套生成目录继续纳入摘要 |
| installer 与 sidecar 的 manifest 分隔符不一致 | Critical | 统一真实 tab 字节，并增加 installer marker 到 sidecar 重算的交叉合同 |
| fresh process Cold/RSS 是四 lane 组合包络 | Normal | 转入 Phase 54 的 lane 隔离 runner，不把组合内存归因给单一框架 |

两个独立复审任务在最终修复后均返回 `no Critical/Important`。

## 3. 威胁模型

正式门禁防止误选工程、假 fixture、旧二进制、调用方伪造字段、被修改依赖与候选漂移。它不承诺抵御已经拥有 `C:\UnrealEngine`、AvidScript 仓库和 benchmark 输出目录同等本地写权限的恶意进程。源码版 `UnrealEditor-Cmd.exe` 没有 Authenticode 签名；若要覆盖该威胁，需要外部可信构建、代码签名或独立制品透明日志，不能由同权限本机脚本自证。

## 5. 性能结论

按同一进程中的 Native C++ lane 归一化，目标 UObject workload 的 P50 ratio 改善如下：

| Workload | Baseline ratio | Optimized ratio | 改善 |
| --- | ---: | ---: | ---: |
| `property_get_set` | 1477.57 | 1056.13 | 28.52% |
| `vector_value` | 1390.36 | 1099.68 | 20.91% |
| `vector_ref_out` | 875.27 | 719.75 | 17.77% |
| `object_roundtrip` | 2233.59 | 1601.43 | 28.30% |

优化是有效的，但 AvidScript WAMR interpreter 仍未全面达到 Puerts V8。优化候选中 `vector_value` 为 `1463.42 ns/op`，Puerts reflection 为 `1543.10 ns/op`，AvidScript 约为其 `0.95x`；其余大多数 crossing 仍慢 `2.03x` 到 `16.07x`，纯整数解释执行差距约 `62.54x`。Phase 54 必须把工作重点转向 AOT/JIT 与生成式静态 thunk，而不是继续堆叠小型字符串优化。
