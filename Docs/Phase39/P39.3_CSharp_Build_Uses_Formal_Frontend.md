# P39.3 C# 构建链接入正式前端

状态：完成
日期：2026-07-13

## 本组实现

C# 构建链现在先运行独立 Roslyn 前端，再进入直接 ABI WASM 后端：

```text
BuildCSharpActorLifecycle.ps1
  -> InvokeCSharpFrontend.ps1
  -> <artifact>.csharp.frontend.json
  -> AST-selected script type / fields / method body spans
  -> existing verified WASM emitter
```

语法错误会返回退出码 1，但仍写入确定性 frontend JSON 和 C# build report；不会进入 Source Adapter、.NET/WASI publish fallback，也会删除同 artifact stem 的旧 manifest 与 WASM，避免旧工件伪装成本次成功。

## 已退役的正则职责

以下 PowerShell 文本解析函数已经删除：

- `Get-CSharpMethodBody`
- `Get-OptionalCSharpMethodBody`
- `Get-CSharpStaticFloatFields`

替代路径从正式 AST 中选择与源文件同名的脚本类型，或唯一具有 `BeginPlay`/`Tick` 的类型；字段声明直接读取 AST；方法体通过 Roslyn block Span 提取。WASM statement emitter 暂时保留，但它不再负责找到类型、字段或方法边界。

## 产物契约

build report 新增：

- `succeeded`
- `source.sha256`
- `source.script_type`
- `artifacts.frontend_file`
- `frontend.schema_version` / `frontend.version`
- 带 UTF-16 offset 与 0-based 起止位置的 Roslyn diagnostics

manifest source 同时记录 frontend artifact、schema version、source hash 与 AST-selected script type。当前 adapter 标识升级为 `avidscript-csharp-ast-adapter`，subset 为 `actor_lifecycle_v13`。

两项端到端行为：

1. 错误 C# 返回 1，report 为 `frontend_failed`，保留 Roslyn diagnostic/frontend JSON，不产生或残留 manifest/WASM。
2. 真实 ActorLifecycle 返回 0，report 为 `direct_abi_built`，report、manifest 与 frontend 的 source hash 一致，并识别 `ActorLifecycleScript`。

## 剩余风险

- statement/expression 到 WASM emitter 仍是迁移期 PowerShell 实现；Phase 40/41 将由语义模型和 Guest IR 取代。
- C# build report 的完整 Span 还未由 Editor C++ reader 消费，属于 P39.4。
- frontend 工具当前每次由 `dotnet build` 增量确认，后续增量构建服务可缓存工具版本。
