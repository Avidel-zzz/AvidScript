# P39.0 Roslyn 正式前端架构

状态：完成
日期：2026-07-13

## 本组完成内容

P39.0 确认 C# 正式前端采用 SDK 内置 Roslyn，而不是继续扩展 PowerShell 正则或手写 C# Lexer/Parser。前端以独立 .NET 工具存在，输出 AvidScript 自有版本化 JSON；UE Runtime、VM 与 Bindings 不增加 .NET 依赖。

## 核心决策

1. Roslyn 是 C# 词法、语法、Trivia 和源码范围的唯一真相来源。
2. AvidScript JSON 是跨进程稳定边界，后续 Phase 40/41 不直接依赖 Roslyn 对象。
3. Source Adapter 降级为迁移期 WASM 后端，Phase 39 起禁止继续用正则扩展语言能力。
4. Phase 42 前不新增逐个手写 UE API，优先建设 Reflection Binding Generator。
5. 测试聚焦真实前端行为：确定性、错误范围、AST 结构、构建 gate 与 Editor 定位。

## 模块边界

| 模块 | 职责 | 禁止承担 |
| --- | --- | --- |
| `AvidScript.CSharpFrontend` | Roslyn 解析、稳定模型映射、JSON 输出 | UE 反射、WASM 运行时 |
| `Build/*.ps1` | 工具定位、编排、报告汇总 | 词法、语法、语义分析 |
| Editor | 调用前端、读取报告、展示诊断 | 解析 C# 文本 |
| Runtime/VM/Bindings | 执行稳定 ABI 与脚本生命周期 | Roslyn/.NET 依赖 |

## 验证证据

- 本机 .NET SDK：`8.0.416`。
- Roslyn 程序集：`C:\Users\user0\.dotnet\sdk\8.0.416\Roslyn\bincore`。
- 依赖策略：使用 `MSBuildSDKsPath` 相对定位 SDK 内置程序集，不下载 NuGet 包。

## 剩余风险

- SDK 内置 Roslyn 路径属于工具链契约，需要在 CLI 启动时给出明确缺失诊断。
- JSON AST 不能机械镜像整棵 Roslyn 树，否则会形成不稳定且过大的协议。
- 旧 Source Adapter 仍含正则，必须在 P39.3 开始按职责删除，不能长期双轨扩张。
