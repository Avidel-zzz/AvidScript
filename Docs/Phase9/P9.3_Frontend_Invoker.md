# P9.3 Frontend Invoker

日期: 2026-07-05
状态: Done

## 1. 目标

P9.3 将 Phase 8 的 `InvokeAvidScriptFrontend.ps1` 接入 UE Editor C++ 层, 让 Editor module 能通过一个稳定的 service API 调用前端 wrapper, 等待进程结束, 再读取 JSON report。

本阶段仍不引入 UI、watcher 或 IDE adapter。目标是先建立后续菜单按钮、快捷命令和 reload gate 都能复用的最小调用层。

## 3. 行为

- 默认 wrapper 路径来自 `IPluginManager::FindPlugin("AvidScript")`, 指向 `Build/InvokeAvidScriptFrontend.ps1`。
- Windows Editor 下通过 `FPlatformProcess::ExecProcess` 调用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File ...`。
- 所有路径参数在进入 wrapper 前会转换为绝对路径并规范化分隔符。
- 当 `ReportPath` 为空时, 默认写入 `Saved/AvidScriptReports/<source>.frontend.report.json`。
- wrapper 退出后总是尝试读取 report。report 缺失或无效会保留 `report_missing` / `report_invalid` 等读取错误。
- 子进程退出码非 0、report `succeeded=false` 或存在 error diagnostic 时, invoker 返回 `frontend_failed`。
- 非 Windows 平台当前返回 `platform_unsupported`, 后续移动端/跨平台适配另开阶段处理。

## 5. 已验证场景

- `SkipCompileSuccessSmoke`: Editor C++ 调用 wrapper, wrapper 调用前端 `-SkipCompile`, report 成功读取, 最后 build result 为 `generated`。
- `UnknownBindingSmoke`: Editor C++ 调用 wrapper, wrapper 生成 `ASL1202` unknown binding diagnostic, invoker 返回失败且错误类别为 `frontend_failed`。

## 6. 剩余风险

- PowerShell invocation 目前是 Windows-only, 符合 PC-first 阶段目标。
- 当前测试使用 `-SkipCompile`, 不要求本机 LDC toolchain。真正 D/WASM 编译链路仍由 Phase 8 wrapper 和后续阶段继续覆盖。
- `frontend_failed` 目前是 coarse category, 具体错误信息需要从 `Report.Diagnostics` 或 `Stdout/Stderr` 读取。
