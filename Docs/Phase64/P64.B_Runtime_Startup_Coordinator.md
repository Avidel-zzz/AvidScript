# P64.B Runtime 启动协调器

## 已实现

`UAvidScriptWorldSubsystem` 现在只在显式提供 `-AvidScriptScenario=<id>` 时启动脚本编排。
未提供参数的 Game/PIE World 不再自动加载 embedded smoke，也不会承担额外 Tick。

启动协调器完成以下通用职责：

- 从项目 `Content/AvidScript/Startup/scenarios.json` 读取配置；项目未提供时查找插件同名路径。
- Development/Editor 可用 `-AvidScriptScenarioFile=<content-relative-path>` 覆盖文件；Shipping 拒绝覆盖。
- 校验 scenario 的 world 白名单，然后按 `world_host`、`existing_actor`、`spawn_actor` 创建目标。
- 统一挂载已有 `UAvidScriptComponent`，由 ModuleId 经 catalog 解析发布包，不增加玩法专用 Host API。
- 动态组件在已经 BeginPlay 的 World 中补齐 BeginPlay 和 Tick 注册时序。
- 重复激活同一 World/scenario 幂等；任一目标或 Runtime 启动失败时回滚本次所有组件和自有 Actor。
- `existing_actor` 排除本次激活生成的 Actor；World EndPlay/Deinitialize 回收组件和自有 Actor，
  不销毁外部 Actor。
- Build.cs 自动将项目或插件 Startup 目录中的 JSON 作为 UFS RuntimeDependency 纳入构建。

现有 packaged oracle 仍是独立、显式的验证入口，并且优先于普通 Startup Scenario。

## 验证

- UE5.8 `AvidTPSTemplateEditor Win64 Development` no-clean UBT：通过。
- `AvidScript.Runtime.StartupScenario.*`：`2/2` 通过。
- `AvidScript.Runtime.WorldSubsystemLifecycleSmoke`：`1/1` 通过，确认无 scenario 时保持空闲。
- Coordinator 测试覆盖三种目标、BeginPlay、Tick、幂等、外部 Actor 所有权、生成对象排除、
  不可用类失败关闭和原子回滚。

最终日志位于 `C:\tmp\AvidScript\P64A\startup-coordinator-final.log` 与
`C:\tmp\AvidScript\P64A\world-subsystem-idle.log`，本地日志不提交仓库。
