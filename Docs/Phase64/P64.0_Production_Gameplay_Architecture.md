# Phase 64 可玩脚本闭环与移动交付架构

状态：架构 v16，保留全部原始验收范围，补充类型化 Host 结构化失败与 callback 隔离合同

## 目标

Phase 64 把已经可执行的 C#、生成式 UE API、模块发布和 Runtime 生命周期组合成一个可直接启动的
真实游戏脚本闭环。首个纵向切片在 PC 上完成开发与打包验收，同时把同一模块推进到 Android arm64
UBT、包产物和可选真机运行；没有连接设备时只声明 device-ready，不伪造真机通过。

v1 的实施清单遗漏了原始目标中的 UI、落盘存档和长时间运行。v2 保留全部既有能力、PC 包验证及
Android 最低构建要求，在 P64.D 中补齐这些原始验收；不将工具就绪、自动事件送达或热重载状态迁移
解释为 UI 可玩、磁盘存档或长稳完成。

本阶段不以手写一组 Demo 专用 Host API 换取表面可玩。游戏逻辑只能使用 Reflection/Profile 生成的
UE facade、通用生命周期、事件、异步和模块包能力。

## 核心缺口

当前 `UAvidScriptComponent` 已能承载单个模块，但仍依赖用户手工把组件和 ModuleId 放进关卡。
成熟脚本框架还需要一个稳定的 composition 层，把“哪个模块在什么世界、挂到哪些对象”作为数据合同，
而不是散落在 Blueprint、关卡资产或项目专用 C++ 中。

## 分层设计

```text
Startup Scenario manifest
        |
        v
Startup schema + resolver          仅解析、规范化、限额、fail-closed
        |
        v
World startup coordinator          世界匹配、对象选择、生成/挂载、所有权与 teardown
        |
        v
UAvidScriptComponent               既有 Session、BeginPlay/Tick/EndPlay、碰撞与事件
        |
        v
Module catalog -> Runtime -> VM     既有发布、Binding、Wasmtime/WAMR
```

- `AvidScriptCore` 和 `AvidScriptBindings` 不感知关卡、Demo 或平台。
- startup schema 与路径解析属于 Runtime package/composition 边界。
- World coordinator 只管理宿主对象和组件，不编译 C#，不调用具体游戏 API。
- 示例可提供无游戏逻辑的可视化宿主壳；收集、旋转、隐藏、计时复活等行为全部在 C#。
- Android 工具链与 ADB 逻辑只存在于 `Build/`，不进入 Runtime。

## Startup Scenario 合同

首版 manifest 使用严格 JSON，顶层只允许：

- `schema_version`：固定为 `1`；
- `scenarios`：有界场景数组；
- `scenario_id`：规范化 ASCII 标识；
- `activation`：默认 `explicit`，由命令行或项目设置选择，禁止插件安装后自动改写所有关卡；
- `worlds`：规范化长包名白名单；
- `bindings`：ModuleId 与宿主选择规则；
- `target.mode`：`world_host`、`existing_actor` 或 `spawn_actor`；
- `target.class_path`、tag、数量与 transform：只允许结构化字段，不接受任意命令或绝对文件路径。

解析器拒绝重复键、未知字段、重复 scenario、路径穿越、无界数组、空 ModuleId、歧义匹配和不兼容
target 组合。运行时只从已验证 catalog 解析模块；Shipping 不允许 loose manifest 或 WASM fallback。

## 生命周期与所有权

1. `OnWorldBeginPlay` 选择显式 scenario，并冻结该世界的解析结果。
2. `existing_actor` 在已开始游戏的 Actor 集合中按 class/tag 选择；`spawn_actor` 使用受控 class path；
   `world_host` 创建无可见游戏行为的瞬态宿主。
3. 每个匹配对象最多挂载一个由 coordinator 所有的 `UAvidScriptComponent`；重复激活必须幂等。
4. 动态挂载后立即遵守 UE Component BeginPlay 语义，碰撞、Timer、事件和输入转发仍走现有 Session。
5. Actor 销毁、World teardown、应用后台恢复和模块故障都通过现有 generation/ownership gate 清理。
6. World 结束时 coordinator 先停止受管组件，再释放它创建的宿主；不持有跨 World 裸指针。

默认游戏世界不再运行 embedded smoke。Smoke 只能由自动化专用入口显式启用，避免插件安装后产生
隐形 Guest 工作负载。

## PC 纵向切片

参考场景使用项目现有可玩地图和输入，不修改模板游戏规则。AvidScript 负责：

- 通过 scenario 将 C# 模块挂到可交互宿主；
- 在 C# 中处理 `BeginPlay`、`Tick`、Overlap、Timer 和 `EndPlay`；
- 通过生成 facade 改变 Actor transform、可见性和碰撞；
- 从同一源生成 Development JIT、Development AOT 与 Shipping AOT 包；
- 提供一条构建并启动命令，以及机器可读运行报告。

验收报告至少包含 scenario/module/package 身份、匹配对象数、BeginPlay/Tick/Overlap/Timer/EndPlay 计数、
可观察 Actor 状态和进程退出码。无输入的合成调用只能作为自动化证据，不能替代人工可玩验收。

## Android 交付 Gate

Android 工具链解析必须固定并检查 UE5.8 所需版本：SDK platform `android-34`、Build Tools `35.0.1`、
CMake `3.22.1`、NDK `27.2.12479018`（r27c）与兼容 JDK。受控脚本优先使用进程级环境，不静默修改
用户级环境变量。

Gate 分为四层：

1. toolchain preflight：版本、目录、许可证和 clang/adb/gradle 输入完整；
2. Android arm64 UBT：插件、Wasmtime 静态库和 Generated Type 模块链接成功；
3. package：APK/AAB、arm64 native library、catalog、cwasm 与回执身份一致；
4. device：有 ADB 设备时安装、启动、收集报告并验证后台/前台恢复；无设备时明确为 `not_run`。

前三层通过不等于第四层通过。iOS 继续保持无 JIT fail-closed 边界，不在没有 Mac、签名和设备时宣称完成。

## UI 与存档合同

- 独立样例 `Samples/CSharp/UiSaveDemo`，模块 `avidscript.ui_save_demo`，不修改 PickupRush 游戏逻辑。
- 资产位于 `/AvidScript/Demos/UiSave`：`WBP_UiSave`、`BP_UiSaveHost`、`BP_PlayerSave`、`L_UiSave`。
- Blueprint 仅负责视觉构造、输入焦点和强引用数据壳；点击处理、分数变化、保存、读取与错误状态均由 C# 驱动。
- Host 公开 `RootWidget` 和 `SavedObject` 对象属性；Widget 公开 `CollectButton`、`SaveButton`、`LoadButton`、
  `ResetButton`、`ScoreText` 和 `StatusText`。SaveGame 公开 `Score` 整数属性。
- Binding Profile 使用 `AUiSaveHost`、`UUiSaveWidget`、`UPlayerSave` 别名及标准 Button/TextBlock、
  GameplayStatics、KismetTextLibrary API。只通过通用 Reflection、属性、委托与 UObject codec，不添加专用 Host import。
- UI 由标准 Widget Blueprint 创建流程初始化，不能用 `new_object` 替代 Widget 初始化。宿主用 UPROPERTY
  持有 Widget 和 SaveGame；Guest 仍只持有经校验的 ObjectHandle，不把本地静态 handle 当作 GC 强引用。
- 委托订阅属于 Session；EndPlay/reload 清理订阅、失效回调和 UI 挂载。缺档、错误存档类型或保存失败均可观察。
- 多实例事件通过通用 `AvidSubscriptions.IsCurrentSource(source)` 识别来源，Host ABI 为
  `env.event_is_current_source(i32 slot, i32 generation) -> i32`，仅追加静态 binding ordinal。
  来源由 Session 在同步派发期间以 RAII 保存/恢复，不改变 delegate 参数合同；查询沿用 registry、
  generation、capability 和 World 校验。回调外、已失效或无权访问的来源返回 false，不延长 UObject 生命周期。
- 明确指定 Actor Self 的 Profile 可以选择独立 UObject 的普通单播/多播委托，通过显式订阅绑定；
  这不会改变 Self 或授予网络权限，RPC/RepNotify inbound 仍要求其 owner 与 Self 继承兼容。
- 事件型 Guest 可以不导出 `avid_on_tick`。Runtime 在加载冷路径解析并缓存可选 Tick；仅明确的
  `missing_export` 可表示未提供该入口，错误签名和其他解析失败仍拒绝。manifest 明确要求 Tick 时仍强制校验。
  Session/Component 心跳保留，继续驱动 Timer、continuation 和 deferred inbound；不补空 Guest Tick，
  不关闭组件调度。Tick 调用计数仅统计真实 Guest 执行，无 Tick 时耗时为零，unload/reload 重置入口缓存。
- 后端提供通用 `ValidateExportSignature(handle, expected, error)`，复用 `FAvidScriptVmAbiSignature`
  核对参数 kind 及结果形状，不按 cell 数推断签名。Runtime 冷路径要求 Tick 为 `(F32) -> void`；
  Wasmtime/WAMR 使用实际函数类型，不执行 Guest、不重复按名称查找，不把 UE 入口名写入 VM。
  默认未实现返回 `export_signature_unsupported`，签名不匹配返回 `invalid_export`，均 fail-closed。
- 存档使用项目 `Saved/SaveGames` 下的独立示例 slot；验收使用唯一 slot 或隔离进程配置，不覆盖用户已有存档。
- Editor 资产生成器必须幂等且不覆盖用户修改过的样例资产；生成、编译和保存均通过 UE API。

## 压力与长稳合同

- UI `BeginPlay` 复用现有 `async/await` 与 `AvidContinuations.NextTickAsync()`：候选准备期只重置
  transient 状态并登记 continuation；UMG 挂载、文本写入及订阅在提交后的安全 Tick 执行。不新增 UI
  Host API、生命周期 ABI 或函数名白名单，也不放行无回滚能力的候选 Host 副作用。
- `ReloadConfiguredScript` 成功仅表示候选提交，不表示异步初始化完成；验收必须继续驱动真实 World，
  等待 Ready、零 pending continuation 与可观察的 UI 行为。提交后的脚本错误属于活跃实例故障，不能冒充
  可回滚的候选拒绝。被拒绝候选的准备队列、取消/退出的旧队列都不得再进入 Guest。
- Editor 重载使用三份正常 C# 编译产物：原版 Collect 加 1、正文变体加 2，以及在 await 前写 UI 的
  拒绝变体。三份 manifest/WASM 均固定身份、来自项目 Saved；不直接改 WASM 或伪造 hash。
  有界循环交替加载两个真实正文，保留分数，插入拒绝变体后继续调用旧正文，最后检查退出清理与迟到事件。
  发布包启动身份与后续 Editor loose-manifest 身份分开记录，不将该模式声明为包内重载验收。
- 存取穿插重载沿用同一 UI 样例和 `VerifyReload`，以显式选项增加 Save、Reset、Load、真实 GC。
  Save 优先使用宿主已有 `SavedObject`；新建对象写入宿主强引用后，在本次保存调用结束前释放 Session
  的临时 ownership，不把需要释放的句柄仅存入会被重载清空的 transient 字段。成功/失败 Save 都释放临时
  ownership，宿主强引用负责保活；Load 验证完成后才替换宿主对象。
- 借用授权仍为弱引用。Runtime lifecycle coordinator 在 UE `GarbageCollectComplete` 后通知 Session，
  仅删除已失效对象的 borrowed 登记并归还对应 registry lease。Session 处于 Guest 调用或候选事务时
  必须延迟到后续安全入口，不能破坏 borrowed checkpoint；活对象授权、其他 Session 的 lease 和 owned
  对象不变。清理为冷路径线性压缩，不在每次 Borrow/Host crossing 上扫描，也不每帧无条件扫描。
- 存取重载模式每轮检查落盘哈希、Reset/Load/失败候选不改文件、迁移后的分数和真实正文行为。
  GC 后旧存档对象应可回收，活跃 borrowed 登记允许比纯 UI 基线多一个当前存档对象，不随轮数增长。
  owned 条目在保存返回后为零；退出检查沿用现有组件合同，不能把它标为 World 销毁验收。
- 在上述游戏流程上执行重复订阅/取消、World 生命周期和方法体热重载，不增加独立虚构 workload。
- 记录运行时长、World/reload 数、有效 Session/handle/timer/subscription 数和内存趋势；每轮 teardown 后回到基线。
- 长时间运行须有真实起止时间与结束报告；短循环测试不能替代时长证据。网络闭环复用既有多进程 Demo，保留独立记录。
- World 验收使用独立 Editor 控制器，以标准 OpenLevel 重新加载真实 UiSave 地图，不手工调用
  Component EndPlay 来替代 World teardown。每个新 World 从 catalog 创建新 Session，C# 从磁盘恢复
  分数后继续收集、保存；观察真实 World cleanup、旧对象 GC 和新实例身份，禁止跨 World 强持有旧对象。
- `VerifyWorld` 默认至少完成 10 次 travel；持续模式同时满足最少轮数与请求时长才结束。每轮输出
  存档哈希链、Session/订阅/ownership、GC 后 UObject 数与进程 physical/virtual 内存，前三轮作为预热。
  仅实际完成至少 3600 秒且不少于 10 次 travel 时允许标记 long_run_verified；不据此宣称任意游戏无泄漏。
  请求参数、失败、退出与最终报告均有界，报告和存档仅写入隔离位置，不改变已有 Verify/VerifyReload。

## 类型化 Host 诊断合同

Wasmtime 的 typed/prepared Host 快路径不得把 Runtime 的具体绑定失败覆盖成统一文本。VM 公共层新增
只承载 `Category` 与 `Details` 的轻量失败值；import module/name 始终来自加载时已验证且不可变的
typed import 元数据，Runtime 返回值不能改写身份。dispatcher 提供失败路径专用的一次性消费接口，
成功调用不触发虚调用、不构造字符串，也不改变现有 prepared target 函数签名。

Runtime 暂存失败同时记录当前 callback epoch。消费必须同时匹配 module、name 与仍在栈顶的 epoch；
匹配后立即清空，失配时丢弃旧值并回退到通用拒绝，禁止跨 callback、reload 或重入层级串用。
嵌套 Guest 调用在自己的 callback frame 内完成失败消费，外层恢复后只能产生和消费外层 epoch 的错误。
具体 Binding `ErrorCategory` 与 `ErrorDetails` 分字段传递，不再把 category 拼进 details。

Wasmtime 只在 typed 调用返回非成功状态后消费该值，并将 import 身份、分类和详情写入既有
`FAvidScriptVmError`；无有效具体失败时保持现有 `host_import_failed` 回退。WAMR 不伪装成 typed
backend，其 semantic/dynamic Host 兼容路径通过结果对象传递同一分类语义。两个 backend 都在每次
顶层 VM 调用前清理自己的 pending failure，并保留 trap stack frame；C ABI 边界不传播 C++ 异常。
实现与验证范围见[类型化 Host 诊断实施合同](P64.D_Typed_Host_Diagnostics.md)。

## 性能与可维护性

World 内存归因沿用同一存档/切图流程，默认记录 VM 实例创建/销毁及有界制品缓存的只读计数，
不执行 Guest、不清缓存、不改预热基线。VM 公共诊断仅返回值，不暴露后端实现或引入 Editor 依赖。
Editor 每轮只测一次新完成周期的 JSON footprint 并累计，避免扫描全部历史产生二次方观测成本。
先执行约 100 次切图用于归因，短运行不得关闭一小时或无泄漏门槛；具体字段、口径与边界见
[内存归因实施合同](P64.D_Memory_Attribution.md)。
后续引擎侧采样放入 Editor 私有 WorldMemory 实现，保留既有 VM 公共接口；默认只读 Trace/FName，
LLM 显式启用并验证实际状态。未启用/未编译统计返回 null，不伪装成零；不强制刷新、trim 或清缓存。
该诊断运行有额外观测开销，不能与未启用 LLM 的进程绝对内存直接作性能比较。
原生分配栈复用 UE Memory Trace 和 Unreal Insights，不手写分配器 hook、不修改系统注册表。
仅 VerifyWorld 显式开启追踪，输出隔离的 trace 文件和每轮 GC 书签；采集与离线分析分别验收。
VirtualAlloc 预留/释放记录不是提交量或完整 Windows HeapAlloc 记录，不据此宣称全部原生内存已覆盖。
边界与执行方案见[原生分配追踪](P64.D_Native_Allocation_Tracing.md)。
调用帧由 Binding 独占初始化和析构，冷路径缓存需要释放的属性，不依赖原生 UFunction 的
DestructorLink 覆盖调用者创建的参数。Wasmtime backend 使用稳定 owner 身份与不回绕代际，
prepared call 可携带不透明的共享 TargetLifetime；卸载释放函数资源和 backend 的导出表所有权，
旧调用仅在持有者仍保留时保存失效记录，不为每次重载永久追加历史。调用热路径不增加引用计数操作。
具体兼容边界、独立写集与集中验证见[调用生命周期修复](P64.D_Invocation_Lifetime.md)。

修复后 Editor 一小时流程仍包含 Editor 模块、Blueprint 引脚延迟删除与线性保留的探针 JSON，
不能代表实际打包游戏内存趋势。下一轮复用已隔离的 `AvidScriptValidation` 插件，在正式 Win64
Development/Shipping AOT 包中增加独立 World probe；它执行同一 UiSaveDemo 的 Ready、Load、Collect、
Save、GC、OpenLevel 与最终恢复，不把测试逻辑写入 Runtime 或 C# 样例。短 write/read probe 与新 World
probe 通过公共抽象分离，默认入口及现有 schema 不变。

包内 World probe 逐轮 fail-closed 检查动作、存档哈希链、World cleanup、EndPlay、Session/owner/按钮
释放、新对象身份、AOT backend 与资源边界。内存只保留固定里程碑样本、汇总极值、累计通过数和滚动
SHA-256 证据链；失败时保留唯一当前轮，不保存全部历史。样本数量和 observer footprint 受固定上限
约束，不能随最长 10000 轮线性增长。先运行短包内流程与同口径合同，再根据趋势执行一小时；
Editor、Development、Shipping 三种口径分别报告，不把 `-nullrhi` 自动化替代视觉或物理输入。
具体字段、依赖方向与 Gate 见[包内 World 长稳合同](P64.D_Packaged_World_Soak.md)。

包内 UI 验收使用默认禁用、显式构建/运行启用的独立 Runtime 验证插件，源码放在
`Tests/Unreal/AvidScriptValidation`。仅该插件依赖 UMG，依赖方向为 Validation → Runtime/Core/UMG；
主插件不依赖验证插件，不将 Editor 探针或按钮业务逻辑迁入通用 Runtime。
Component 提供 Game Thread、无活跃 Guest/mutation 时可调用的只读值快照，复制 Session 计数和
后端身份；不放开 Editor-only Session getter，也不暴露指针或 Shipping 源码调试信息。
构建复用现有 Release/BuildCookRun/Receipt，显式选择地图与插件，保持无参数时的原有行为。
实际 Game 二进制、cooked 地图、模块包身份、AOT backend、独立存档目录和跨进程读回共同构成证据。
具体接口与写集见 [包内 UI 实施合同](P64.D_Packaged_UI.md)。

- startup manifest 每个 World 只解析一次，class/tag 选择结果有界；Tick 不重复扫描全世界 Actor。
- 组件进入后继续使用 prepared binding、静态 import、数据通道与 Wasmtime 既有快路径。
