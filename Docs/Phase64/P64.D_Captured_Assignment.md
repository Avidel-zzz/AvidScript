# P64.D 捕获赋值目标修复

## 根因与通用修复

Roslyn 将短路表达式赋值的左值捕获到 CFG 临时节点。原 Lowerer 只记录 local/parameter 的地址目标，遗漏 static field；无法找到原目标时，`StoreValue` 静默写入 capture 值副本。实际 UiSave IR 中，BeginPlay block12 读取旧 `Ready` 到 `capture:0`，block17 将短路结果写入该副本，没有 `global_store Ready`，block18 因而仍读到旧 false。

修复位于 `Tools/AvidScript.CSharpGuest/Lowering/CSharpFunctionLoweringContext.cs` 与 `CSharpOperationLowerer.cs`：记录稳定的 static field、local、parameter 存储目标，捕获赋值复用原存储写入路径，ref 参数仍通过原调用方地址写入。普通 RHS 捕获继续保持值快照；不同来源的只读合流不强制绑定为可写地址。无法证明目标稳定或类型不匹配时以 `ASCG1004` fail-closed，不再写临时副本兜底。实现不含 UI 或 UE 生命周期特判。

聚焦覆盖 static/local 的全部 16 种四项 `&&` 输入及两种旧值、短路调用顺序、RHS 快照、ref 原地址写回、只读合流，以及不支持的 aggregate/array 捕获拒绝。证据包含真实 C# 经 Roslyn 到 Guest IR 的有界控制流追踪、IR 校验和 WASM 生成，不将 managed 测试宣称为 WASM 执行验收。

## 保留边界与缓存

复杂 receiver、aggregate 字段或 array index 跨 CFG 的完整左值捕获，当前尚不能通用保留地址及求值顺序，仍明确 fail-closed；不静默复制或重新求值。该缺口限于不受支持的捕获目标，不声称所有普通 property/array 访问均不可用。

缓存无需 Schema/version 改号：`Build/AvidScriptCSharpCompilationCache.ps1` 的 `Get-AvidScriptCompilationCacheToolchainFingerprint` 递归哈希 CSharpGuest 等目录的 `.cs/.csproj`，排除 `bin/obj`；缓存身份还纳入 `sources_sha256`、`guest_compiler_sha256` 与 `dotnet_sha256`。`Build/AvidScriptCSharpCompilerWorker.ps1` 的 `Get-AvidScriptCompilerWorkerToolchainFingerprint` 同样包含 Lowerer 源码哈希。此次源码变化自动改变缓存与 worker 身份，无需人为升级语义 Schema。
