# P64.D UI 正文重载与资源观测

状态：20 轮真实正文重载与拒绝回滚通过。这里不替代包内 UI、World teardown、物理输入或长时间运行验收。

## 初始化合同

UI 原先在同步 BeginPlay 中调用 `UTextBlock.SetText`。实际重载探针显示候选状态迁移成功，
但反射写入被 `binding_reload_effect_unsupported` 拒绝，旧实例保留。拒绝是正确的安全行为：
任意 UFUNCTION 可能修改 Slate、广播事件或产生外部效果，复制 UObject 属性不能通用地撤销这些效果。

样例现在复用已有的受控异步生命周期：

```csharp
[UnmanagedCallersOnly(EntryPoint = "avid_on_begin_play")]
public static async void BeginPlay()
{
    CancelSubscriptions();
    await AvidContinuations.NextTickAsync();
    // 此后执行正常 UMG 初始化、订阅与显示。
}
```

候选准备期登记的 continuation 只有在 Session 提交后才进入活跃队列，下一安全 Tick 执行 UI 初始化。
候选失败、实例停止或 World 失效都沿原有 owner 清理，不另增 UI import、后端特判或新的生命周期 ABI。
初次启动也使用相同路径。提交成功与 UI Ready 分别观察；提交后的执行失败按活跃实例故障处理，
不承诺撤销已经对外发生的任意 UI 效果。

## 验收范围

- 三份正常 C# 编译的 manifest/WASM：基线 Collect 加 1、正文变体加 2、候选准备期非法写 UI 的拒绝变体。
- 拒绝变体先登记显式 continuation 再触发失败；该回调若错误恢复会改变 UI，必须在后续安全 Tick 检出。
- 固定各制品的路径、模块与 SHA-256，交替切换真实正文、迁移分数并继续按钮事件。
- 每轮等待异步初始化完成，检查订阅、continuation 和对象条目相对基线不增长。
- 最后走组件 EndPlay/注销，检查资源清理与迟到事件隔离。

进程先从正式发布包启动，随后用 Editor 支持的 loose manifest 执行正文切换；报告分别记录两种来源。
变体只存放在项目 Saved，通过正式编译入口产生，不能修改 WASM 字节或重写 hash 来伪造正文变化。
默认 20 轮、上限 100 轮的有界测试不是长稳报告；长稳仍需要实际时长与内存趋势。

## Session 资源快照

`FAvidScriptRuntimeSession::GetSnapshot()` 公开以下 owner 数据，不依赖测试专用接口，也不在 Tick 扫描对象：

| 字段 | 含义 |
| --- | --- |
| `OwnedObjectEntryCount` | Session 显式持有的对象登记条目，可能包含等待清理的已失效对象 |
| `BorrowedHandleEntryCount` | Session 已取得的 borrowed 授权条目，不等于 GC 强引用数 |
| `ActiveDelegateSubscriptionCount` | 活跃订阅数 |
| `PreparedDelegateSubscriptionCount` | 候选准备中的订阅数 |
| `PreparedContinuationCount` | 候选准备中的 continuation 数 |
| `PendingTimerCount/PendingContinuationCount` | 现有活跃 Timer/continuation 数 |

这些数用于定位生命周期累积，不代替进程内存、UE 对象堆或第三方 VM 分配统计。

## 复现与制品策略

准备原版、Collect 加 2 的正文变体，以及在 await 前登记 continuation 并调用 SetText 的拒绝变体。
三者均经正常 C# 编译，沿用相同 Binding Profile 与持久 Score 身份。使用 Editor 默认的
`PreferPrecompiled` 发布策略，或显式生成仅改变该执行策略的独立 manifest 副本；不得修改 WASM
正文、身份哈希或原始 Release 文件。副本继续通过 canonical/serialized 哈希与完整 loader 校验。

```powershell
pwsh -NoProfile -File Build/InvokeAvidScriptUiSaveDemo.ps1 `
  -Mode VerifyReload -ExpectedPackageId <当前启动包的package_id> `
  -ReloadBaselineManifestPath <绝对路径/baseline/ui_save_demo.avidscript.json> `
  -ReloadChangedManifestPath <绝对路径/changed/ui_save_demo.avidscript.json> `
  -ReloadRejectedManifestPath <绝对路径/rejected/ui_save_demo.avidscript.json> `
  -ReloadCycles 20 -TimeoutSeconds 240
```

三个 manifest 及其 canonical WASM 必须位于当前项目 Saved 内，不能使用 symlink/reparse 路径。
`VerifyReload` 不编译、不修改输入、不改 catalog；仅在隔离进程中切换组件配置，退出前恢复原配置。
报告固定各输入哈希、正文变化、Session 身份、每轮资源和后端信息，所有动作通过才成功。

本轮独立 Editor 配置位于项目 `Saved/AvidScript/UiSaveReload/editor-754c3a7a4d54419cba73006b7de79b0d`，
`derivation.json` 记录原始/副本 manifest 哈希、唯一语义变更 `execution.policy`、不变的 WASM/serialized
哈希和原文件保持证明。跨进程 loose attestation 不可信时按显式策略回退 JIT，没有接受外来本机代码。

## 流程纠偏

- 初始同步 UI 探针 run `reload-639c3864af1a486f8ab08af2f50f35dd` 的报告明确为失败；进程 exit 0
  不能将其解释为通过。该轮与 UBT 的终态确认有时间交叠，仅保留为诊断，不用于正式验收。
- 后续运行必须先取得 no-clean UBT 的最终成功与进程终态，再启动使用该模块的 UE 验收进程。
- 首次异步 UI 编译 run `63761780364945eabcd45e862c7965dc` 的 Semantic 无错误，但 Guest IR
  返回 `ASCG1001`；已由[初始化转换修复](P64.D_Async_Initializer_Conversion.md)解决，不能仅凭 Semantic 成功宣称 WASM 已生成。
- 首次预编译重载 run `bc3b83fd49024d5a888a2fdf96edb8fc` 在候选加载阶段返回
  `execution_attestation_invalid`，不是正文回滚失败。loose `RequirePrecompiled` 不能继承另一进程的信任；
  发布包与 Editor 跨进程配置须按各自合同处理，禁止仅为通过测试放宽 attestation。
- 聚焦 Automation 首轮沿用了旧的可选 PerfHarness 启动开关，但当前 target 没有该模块，因此未发现测试。
  本组用例不依赖它，按当前 target 去掉该开关后 11/11 通过；历史启动参数必须结合当前模块依赖复核。
- 同进程执行 PowerShell runner 时，Console JSON 不能可靠地由 PowerShell 流重定向捕获。后续使用独立
  `pwsh -File` 捕获 stdout，只回传摘要，避免将大报告直接写入对话。
- 恢复时曾猜测 `Private/Component` 路径；正确文件由 `rg --files` 定位为 `Private/AvidScriptComponent.cpp`。
  后续文件读取继续使用索引结果，不按概念猜目录。
- 图形验证遇到锁屏后停止，未进行真实鼠标输入；保留为未执行，继续推进无桌面依赖的工作。

## 剩余边界

本场景不执行 Save/Load，因此零 owned 条目不是跨重载存档对象无泄漏证明。后续需覆盖 Save/Load
穿插重载、World 销毁重建、真实持续时长和内存趋势；borrowed 登记条目也不等于 GC 强引用。
P64.D 原始目标、包内 UI、真实输入/视觉和移动平台验收保持未完成，不追加历史全量 Automation 数。
