# P64.D 类型化 Host 结构化诊断合同

状态：已实现并通过集中验证

## 问题

Runtime 的 prepared reflection 已能产生具体 Binding 分类和原因，但 Wasmtime typed callback 仅接收
`Succeeded/Rejected/FallbackRequired`。backend 在拒绝时重新生成通用 `host_import_failed`，导致
最终 `FAvidScriptVmError` 丢失 capability、写权限、接收者、codec 或 native guard 的真实分类。
Runtime 当前使用单个 pending 字符串槽；如果不约束身份与 callback 生命周期，后续失败还可能误读
上一层调用留下的原因。

WAMR 当前不提供 typed import 快路径，但 semantic/dynamic Host 失败也只把分类拼进 `Details`。
本节统一错误语义，不把 WAMR 宣称为 typed backend，也不改变 Guest ABI。

## 公开合同

- `FAvidScriptVmTypedHostFailure` 只包含 `Category`、`Details` 和清理操作，不包含 import 身份、堆栈或
  backend 指针。
- `IAvidScriptVmTypedHostDispatcher::ConsumeTypedHostFailure` 是可选的失败路径接口；默认返回 false，
  保持第三方 dispatcher 源码兼容。参数包含期望 module/name，返回值只能描述刚结束的同一 callback。
- Wasmtime 使用 `FAvidScriptWasmtimeTypedHostContext` 中已验证的 module/name 填写最终错误，拒绝 Runtime
  伪造或串用 import 身份。没有有效结构化失败时仍返回通用拒绝。
- `FAvidScriptHostCallResult` 与 `FAvidScriptDynamicHostCallResult` 增加独立 `ErrorCategory`，供 WAMR 和
  Wasmtime 的非 typed 兼容路径使用；既有 `Details` 不再承担分类编码职责。

## 生命周期与重入

1. `SetPendingHostImportFailure` 保存 category、details、module/name，以及当前
   `FusedCallbackFrameStack` 栈顶的 callback epoch；无活动 callback 时 epoch 为零。
2. typed backend 仅在本次 dispatch 返回非成功后消费。module、name 或当前 epoch 任一不匹配时，
   Runtime 清理旧槽并返回 false，backend 使用通用失败。
3. 成功路径不调用消费接口，不构造失败字符串。Wasmtime 只在 typed callback 拒绝后查询结构化失败；
   WAMR 在捕获异常与调用栈后清理实例异常，避免前次 Host 拒绝污染下一次入口。
4. 重入 Guest 调用拥有新的 callback frame/epoch。内层失败必须在内层 callback 返回时立即消费；
   外层恢复后产生的失败记录外层 epoch，因此两个错误不会互相冒充。
5. unload/reload 继续通过 `ResetHostImportState` 清理全部字段；消费成功、身份失配和 epoch 失配都
   一次性清空，不保留可再次读取的失败。

## 模块边界与非目标

- `AvidScriptVM` 定义传输值和 backend 映射，不依赖 Runtime、Bindings 或 Editor。
- `AvidScriptRuntime` 负责 callback epoch、失败生产与一次性消费；`AvidScriptBindings` 负责具体分类。
- 不改变 WASM import 名称、签名、prepared target 函数指针、module package 或 generated type schema。
- 不在成功热路径增加 `FString`、锁、反射查找或额外虚调用。
- 本节不建立完整异常系统，也不承诺 WAMR 获得 Wasmtime typed/JIT 性能。

## 已实现内容

- Runtime pending 槽现同时保存 callback epoch、module/name、category 与 details，并在消费、身份失配、
  epoch 失配、reload/unload 时一次性清理。
- Wasmtime typed Host 拒绝使用不可变 Host context 确认 import 身份，并把 Binding 产生的具体分类映射到
  最终 `FAvidScriptVmError`；成功热路径不查询失败通道。
- WAMR static/dynamic Host 桥接分别传递独立 category 与 details；一次失败被捕获后清除 WAMR exception，
  后续 Guest 入口可以继续执行。
- Reflection 的接收者撤权与只读拒写现在可直接得到
  `binding_receiver_capability_denied`、`binding_write_denied` 等具体分类，不再退化为通用错误。

## 验证门槛

- Wasmtime 实际 typed WASM：具体 category/details 透传，最终 module/name 与加载元数据一致，stack frame
  仍保留；无具体错误的 dispatcher 保持通用回退。
- 生命周期：错误只可消费一次；错误身份或 callback epoch 失配后不能复用；成功调用后的下一次失败
  不读取旧值。
- 重入：内外 callback 分别得到自身失败，内层错误不能覆盖或冒充外层 import。
- WAMR 实际 WASM：semantic/dynamic Host 失败保留结构化 category/details/import，下一次成功或失败
  不受旧 pending 状态影响。
- 集中执行受影响静态检查、no-clean UE5.8 Editor UBT 与 focused Automation；完整 Gate 仍在 P64.D
  候选冻结后统一执行，人工视觉验收不由这些测试替代。
