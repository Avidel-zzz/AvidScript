# P64.D 包内 UI 与存档

状态：架构 v10 冻结，实施中；不以 Editor 或历史 PickupRush 包代替本样例的包内验收。

## 目标与分层

将现有 UiSaveDemo 的同源 C#、自动生成 binding 和四个 UE 资产通过正式 Release/Cook 链路带入
Win64 Development/Shipping 包，以真实 Game exe 完成写档和新进程读回。C# 继续负责全部按钮、
分数与 SaveGame 逻辑，验证插件只触发正常 UE 事件并观察，不添加手写玩法 Host API。

- 验证源码：`Tests/Unreal/AvidScriptValidation`，插件与 Runtime 模块均名为 `AvidScriptValidation`。
- 描述符 `EnabledByDefault=false`，依赖主 AvidScript 插件；仅验证模块私有依赖 UMG，不反向依赖 Editor。
- 显式构建启用与运行探针启用分离。未请求探针时不注册 ticker，不创建文件，不退出游戏。
- `Tests/Unreal/.ubtignore` 阻止主插件 Tests 递归发现独立模块；由项目 Plugins 下的受控链接唯一发现。
  安装器先核对这一标记，再挂接；标记不放入独立插件的 Source 路径内。
- 复用现有受控插件挂接方式；不覆盖用户目录、不修改 `.uproject` 或全局 ini。最终 UBT/Cooker/Stage
  参数以源码 UE5.8 的实际 owner 为准，缺少任一启用层则 fail-closed。
- 验收包包含额外验证模块，应标明已插桩，不能宣称未插桩发行包通过。

## Runtime 只读合同

`UAvidScriptComponent::CaptureRuntimeDiagnostics(FAvidScriptRuntimeSessionSnapshot& OutSession,
FAvidScriptVmBackendInfo& OutBackend) const` 返回 bool。

只在 Game Thread、有活跃 Runtime 且无 Guest 调用/Session mutation 时成功；复制已有值快照及实际
后端信息，不进入 Guest，不改变 RuntimeStats、不清缓存。失败先清空两个输出，避免重用旧快照。
接口不暴露 Session/VM/UObject 指针、WASM 内存、源映射或原始 smoke result。Editor-only getter 原样保留。
按需捕获，不增加每 Tick/Host crossing 开销；包内工具与生产诊断可复用同一个普通 C++ 接口。

## 原生探针合同

独立模块使用 FTSTicker 管理唯一探针，卸载时注销；在 Game Thread 观察真实 World 与弱对象引用。

- CLI：`AvidScriptUiSavePackagedProbe=write|read`、`AvidScriptUiSaveReport=<绝对新json路径>`、
  `AvidScriptUiSaveExpectedPackage=<64hex>`、`AvidScriptUiSaveRunId=<32hex>`，并要求
  `AvidScriptScenario=ui_save_demo` 与显式隔离 `UserDir`。
- 仅接受实际 cooked Game，拒绝 Editor、commandlet 和不匹配地图。配置由编译宏读取，不能由 CLI 伪造。
- 地图 `/AvidScript/Demos/UiSave/L_UiSave`，唯一 `BP_UiSaveHost`，唯一模块 `avidscript.ui_save_demo`，
  Runtime 必须来自预期 package，startup scenario 活跃。UI Ready 后才开始动作，允许 Guest Tick 为零。
- write：Ready 0、Collect 1/2/3、Save 3，共 5 动作、4 次脚本事件；开始时无存档。
- read：另一进程 Ready 0、Load 3，共 2 动作、1 次事件；实际同一存档文件哈希不变。
- 每次广播标准 Button.OnClicked，跨至少一个后续安全 Tick 再核对 UI 文本、错误和回调计数。
- 实际 backend 必须 Wasmtime AOT / wasmtime_serialized，不能用发布文件存在代替执行模式证明。
- 原生总超时 90 秒；成功或失败写一次唯一报告后请求正常退出，失败不覆盖已有报告/存档。
- UserDir 必须与有效 ProjectSavedDir 的父目录一致，禁止落在项目、引擎、归档根及其危险父目录。
  报告必须在该 UserDir/Saved 下；存档仅为 `Saved/SaveGames/AvidScript_UiSaveDemo_v1.sav`。
  拒绝重解析路径与目录内其他存档，不枚举、清除或改写用户存档。

## 报告与外层校验

沿用 `schema_version=1`、`avidscript_ui_save_probe_passed/failed`，新增身份：
`process_mode=packaged_game`、`configuration=Development|Shipping`、`requires_cooked_data=true`、
`validation_plugin=AvidScriptValidation`、`run_id`。

其余必要字段：succeeded、failure_category、mode、process_id、input_kind、expected_module_id、
expected_package_id、map、user_dir、effective_saved_dir、save_path、initial_save_sha256、save_file_sha256、
save_file_bytes、save_file_exists、score_text、status_text、started_utc、finished_utc、elapsed_seconds、
timeout_seconds、runtime_snapshot_phase=final_active、runtime、startup、backend、resources、actions。
physical_click_verified/visual_verified/long_run_verified 均为 false，不复用 Editor 的通过标记。

runtime 沿用 module_id/package_id/resolved_from_package/runtime_loaded/begin_play/owner_registered/
owner_handle_valid/error_message/events/dropped_events。startup 沿用 scenario_id/active/error_category/error_message。
backend 字段形状与 World 报告一致，source 为 `CaptureRuntimeDiagnostics.BackendInfo`。
resources 包含 active_subscriptions=4、bound_buttons=4、owned_entries=0、borrowed_entries=7..8，
pending_timers/pending_continuations/prepared_continuations/prepared_subscriptions=0。
actions 包含 action、expected_score/status、observed_score/status、dispatch_frame/check_frame、passed。

外层同时验证配置、cooked 标记、两个不同 PID/RunId、完整动作/事件计数、后端、实际文件长度/哈希、
进程退出和唯一包身份。仅进程 exit 0、出现 Ready 或从 Editor 拷贝报告均不能通过。

## 写集与实现批次

1. 原生：独立验证插件；主线 Component 只读快照与聚焦回归。不修改主 Runtime 的模块依赖。
2. 工具：受控挂接、BuildCookRun 显式地图/插件参数、独立包内 UI runner 与必要合同。
   复用已验证 custom Binding package 和正式 Release，不重新实现编译、打包或 package receipt。

接口冻结后分写集并行，集中审查/修复后一次 no-clean 构建与包内运行；不为每个函数单独启动 UE。
本小节不关闭 P64：内存归因、包内其他异常/长稳、物理输入/视觉、网络长稳和移动端仍保留。

## 工具入口

1. `Build/InstallAvidScriptValidation.ps1 -Mode Install` 创建唯一受控链接；`Verify` 只读核对。
   然后使用原项目 Editor target 进行 no-clean 构建，额外传入 `-EnablePlugin=AvidScriptValidation`。
2. `Build/InvokeAvidScriptBuildCookRun.ps1` 保留原有 Release、Cook、回执流程，新增可选 `CookMaps`
   与 `EnablePlugins` 数组；默认空数组不改变其他样例。非法标识、重复值、命令注入在发布前拒绝。
3. `Build/InvokeAvidScriptUiSavePackaged.ps1 -BuildResultPath <本次BuildCookRun结果.json>` 重验真实回执，
   只启动归档内 `Binaries/Win64` 的实际 Game exe，不接受 Editor 或 bootstrap exe。每次使用全新隔离
   UserDir，write/read 共用其存档、使用不同 RunId、PID、日志和报告；不清理历史结果。

打包仍使用同一 `UiSaveDemoScript.cs`、`AvidScript.UiSaveDemo.csproj` 与已验证的 custom binding package。
现有 BuildCookRun 参数增加如下选择；两种配置使用不同且全新的 ArchiveRoot 和输出目录：

```powershell
-CookMaps /AvidScript/Demos/UiSave/L_UiSave `
-EnablePlugins AvidScriptValidation `
-PackagedOracleMode None
```

`None` 仅跳过要求 Tick/Timer 的旧玩法 oracle，随后必须执行本节专用 runner，不能把跳过解释为验收通过。
UBT 使用 `-EnablePlugin=`（多项用 `+`），Cooker 使用 `-EnablePlugins=`（多项用逗号）；不需要
ForeignPlugin 或默认开启 UniqueBuildEnvironment。额外验证模块默认禁用，移除链接前须先恢复普通 target。

共享路径、独占创建和存档目录保护已从 Editor CLI 无行为迁移至 `AvidScriptUiSaveCommon.ps1`。
包内报告校验独立位于 `AvidScriptUiSavePackagedReport.ps1`，复用进程执行器并核对其实际 PID；
不依赖 Editor CLI 的入口、全局 Mode 或完整 World 报告。原始 JSON 拒绝重复字段和不匹配类型。
