# P64.D 干净安装生成模块修复

## 问题

Phase 64 首轮完整 Gate 在冻结提交 `ba3dd46` 的 clean detached worktree 中执行 UE5.8 Editor UBT。
候选不包含 Git ignored 的项目生成物，编译在 `AvidScriptGeneratedRuntimeTests.cpp` 失败：

```text
fatal error C1083: cannot open include file 'AvidScriptGeneratedTypes.h'
```

主工作区此前已有本地生成的 `AvidScriptGeneratedTypes.h/.cpp`，因此 no-clean 构建不能暴露该问题。
失败日志保存在仓库外 `C:\tmp\AvidScript\P64Gate\ba3dd46-20260906-001\ubt.log`；该轮 Gate
不计为通过，也没有复制本机生成文件到候选目录绕过失败。

## 根因与合同

项目生成的 UHT shell 仍应保持未跟踪，但 Generated 模块中的 Runtime Automation 和网络夹具在
`WITH_DEV_AUTOMATION_TESTS` 下无条件包含项目专属头文件。插件因而错误地把“已运行过生成器”当成
首次安装的隐式前置条件。

修复把存在性判断收口到 `AvidScriptGenerated.Build.cs`：

- 头文件和源文件同时存在时启用 `AVIDSCRIPT_WITH_GENERATED_TYPES`；
- 两者同时缺失时正常编译空 Generated 模块，项目生成类型专项不注册；
- 只存在一个文件时抛出 `BuildException`，拒绝使用部分发布的 UHT shell；
- 两个路径即使尚不存在也登记为 `ExternalDependencies`，使文件出现、消失和内容变化都能使 UBT
  makefile 失效；否则 clean 构建后首次出现半份文件时不会重新执行 `Build.cs`。

该修复不提交占位 `AProjectile` 等样例类型，不改变 Runtime 对生成包的身份校验，也不新增专用 Host API。

## 定点验证

候选提交 `65e0689` 在独立项目中只复制受控 Wasmtime 安装，不复制任何 Generated Type 头/源：

| 场景 | 结果 |
| --- | --- |
| clean detached 架构检查 | 通过；commit `65e0689`，tree `15067be0` |
| 无生成类型 UE5.8 Editor UBT | 通过；39/39 actions，34.88 秒，`Result: Succeeded` |
| 已有生成类型 no-clean Editor UBT | 通过；8/8 actions，11.10 秒，生成模块及专项重新编译 |
| clean 后仅创建生成头 | UBT 因外部依赖出现而重建 makefile，按预期以 `RulesError` 拒绝，native exit `8` |

证据日志位于仓库外 `C:\tmp\AvidScript\P64Fix\65e0689-20260906-001`。以上是针对阻塞项的
修复验证，不替代重新冻结后的固定 .NET、PowerShell 合同和完整 AvidScript Automation。

## 防复发

完整 Gate 必须包含一条不携带 ignored 项目生成物的 UBT 路径；需要 Generated Type 行为的测试则先
通过正式生成/发布入口建立制品。两类环境分别证明“首次安装可构建”和“项目脚本可运行”，不能用
同一份带本机残留的工作区同时代替。
