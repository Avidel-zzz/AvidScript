# P64.D 包内 World 长稳与有界观测合同

状态：架构 v15 已冻结，实施中；不关闭 D07、人工视觉、网络或移动端 Gate。

## 目标

修复后的 Editor 一小时复验仍增长 Physical 322.965 MiB、Virtual 82.109 MiB。已知 Binding 字符串
参数帧和 backend 历史保留已消除，但 Editor Blueprint 引脚队列、工具线程、分配器保留与探针完整
JSON 历史尚未分开。下一批在正式 Win64 AOT 包中执行同一 World 生命周期，并让观测器自身有界，
取得更接近玩家进程的趋势。它是诊断与长稳证据，不是新的玩法实现。

## 模块边界

- 主插件 Runtime/Core/VM 不依赖验证模块，不新增 Demo 专用 Host API、生命周期 ABI 或 C# 旁路。
- `Tests/Unreal/AvidScriptValidation` 继续作为默认禁用、仅显式打包启用的 Runtime 验证插件。
- 公共 `IUiSavePackagedProbe` 只负责 `Start` 与析构；现有 write/read action probe 和新 world probe
  分别实现，报告与状态机拆文件，避免继续扩张一个探针类。
- 复用 `FUiSaveObservation`、`FUiSavePaths`、`CaptureRuntimeDiagnostics`、VM 只读内存快照和正常
  UMG/SaveGame/OpenLevel API。验证插件不访问 Editor-only Session getter，不持有旧 UObject 强引用。
- Editor 的现有完整历史报告保持兼容；包内 probe 采用有界证据 schema，不复制其线性历史设计。

## 入口合同

`Build/InvokeAvidScriptUiSavePackaged.ps1` 增加 `-Mode VerifyWorld`，默认 `Verify` 的双进程 write/read
行为、参数和结果保持不变。World 参数与 Editor 口径一致：

- `WorldCycles`：2..1000，默认 10；`SoakSeconds`：0..21600，默认 0。
- 原生参数：`AvidScriptUiSavePackagedProbe=world`、`AvidScriptUiSaveWorldCycles`、
  `AvidScriptUiSaveSoakSeconds`；同样要求 scenario、expected PackageId、RunId、隔离 UserDir。
- World 使用新的空 UserRoot，已有样例存档即拒绝；启动配置、receipt、exe 和 package 身份在运行前后
  都重新校验。外层超时至少为原生预算加 30 秒，不静默缩短时长。
- 自动化仍使用 `-nullrhi -unattended -nowrite`，只证明 headless 包内流程；可见窗口和物理点击由
  独立人工验收记录。

## 生命周期合同

每个新 World 必须从 `0/Ready` 和新 Session 开始。第一轮 Collect/Save，之后先 Load 上轮分数，
再 Collect/Save；每轮保存后至少停留 3 秒并确认状态、事件数和存档哈希不变，再通过 OpenLevel
重建同一真实地图。最后一次 travel 后还要在新 World 恢复最终分数，才可成功退出。

`OnWorldCleanup` 只读取停止后的诊断：Component/Guest EndPlay、Session/owner 释放、四个按钮解绑、
Widget 移出 viewport、宿主 SaveGame 引用清空且无迟到事件。新 World 就绪后强制 GC，旧 World、Host、
Component、Widget、SaveGame 弱引用必须全部失效，新对象 identity 必须不同。每轮活跃脚本实例为 1，
订阅/按钮为 4，owned/pending/prepared 为 0，borrowed 为 7..8；实际 backend 必须是 Wasmtime AOT
serialized，live backend 与缓存 entry/bytes 不随轮次增长。

## 有界证据

原生报告保留根 schema_version=1，并以 `mode=world` 增加 `world_lifecycle`：

- 请求/完成轮数、World/travel/cleanup 计数、真实时长、最终分数、存档 SHA-256、long_run_verified。
- `checks` 记录累计 action、cleanup、GC、resource 通过数；任一失败立即终止，不把累计数替代检查。
- `evidence_chain_sha256` 从 RunId、PackageId 和每轮规范化字段滚动计算，外层验证格式、最终计数与
  报告/文件身份；不允许根据日志补造缺失结果。
- `samples` 只保留固定里程碑 1、2、3、5、10、25、50、100、200、500、1000、2000、5000、10000，
  以及不重复的最终轮；最大 15 项。每项含 Physical/Virtual、UObject、VM live/cache、资源与哈希。
- 当前动作和当前轮对象在完成后释放；失败时仅附带 `failure_cycle`。报告内存估算、sample count/capacity
  必须写入，成功时 observer retained cycle/action 均不随总轮数增长。
- 第三轮继续作为预热基线；报告 baseline/final/peak 与 50、100、最终里程碑。工作集、提交量、
  UObject 和 VM 计数分别解释，不将 WASM 4 GiB 地址预留当作实际提交量。

## 实施与验收

1. 独立实现公共 probe 接口、packaged world 状态机、报告/内存采样和严格 PowerShell validator。
2. 合同覆盖默认 Verify 无漂移、参数/模式拒绝、报告字段类型与边界、样本上限、累计计数、证据链、
   路径与身份；纯字段矩阵直接调用生产 validator，不逐项启动进程。
3. 集中执行一次 no-clean Editor UBT、受影响合同、Development BuildCookRun 与短包内 World 流程。
   先看 50/100 轮趋势；候选与包身份冻结后再执行一小时，不为通过修改基线、trim 或清缓存。
4. Shipping 至少完成短 World 兼容运行；一小时先以 Development 取得归因，二者不可互相替代。
5. 结果更新 README、D07 与收尾文档，按小节精确提交推送。人工窗口反馈只更新 D03，不写入自动字段。

## 成功边界

包内趋势显著低于 Editor 且 observer 计数/footprint 有界，可把 Editor 专属与探针开销从产品增长中
剥离；仍有持续增长则按实际栈/模块继续修复。只有包内一小时流程、资源边界、趋势归因和必要修复
均有证据时，才评估 D07 是否 Verified。短测、exit 0、单一端点或用户视觉反馈均不能单独关闭它。
