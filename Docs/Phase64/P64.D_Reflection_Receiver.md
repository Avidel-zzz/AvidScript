# P64.D 通用 UObject 接收者授权

## 问题与实现

UI/存档联调中，`NewObject` 已成功创建 SaveGame，但生成的 `Score` setter 被 typed dispatcher 拒绝。
原因是 prepared reflection 的调用形状沿用了 Self 路径，解析器强制接收者等于脚本宿主。
普通 UObject 的属性并不具有这一限制，不能通过手写 SaveGame API 或放宽 Self 缓存解决。

- `AvidScriptBindings` 新增 `ResolveAvidScriptBindingReceiver`，复用既有 registry/type 解析，集中检查
  Game Thread、World 存活、对象所属 World 和 Session capability。Owner 仅豁免 capability；其他对象
  必须由 `HasCapability(handle, object)` 授权，支持 owned 与 borrowed，不把已注册当作已授权。
- 无 World 的对象可在授权后使用；有 World 的对象必须与宿主 World 相同。失效代际、失效对象、
  错误类型、缺少权限、跨 World 或后台线程访问均拒绝，失败不返回对象。
- Runtime prepared reflection 按完整 Owner handle 分流。Self 保留 fused receiver 与 native guard 缓存；
  非 Self 每次独立解析和检查 native guard，不读写 Self 的 callback frame 缓存。
- prepared dynamic 与普通 `BindingPackage.Dispatch` 使用相同授权入口；Self 解析失败不再退回仅检查
  registry 的路径。普通 fallback 也拒绝超出 32 位 ABI 的句柄，避免截断后误指向其他对象。
- 原写权限、属性事务、反射身份与 Session 生命周期仍有效。未新增 WASM import、descriptor 字段、
  SaveGame 专用 wrapper 或 VM 后端依赖。

## 边界

本节修复的是实例方法/属性的接收者授权，不声称完成所有对象参数、所有 UE 类型或所有委托签名。
Self 缓存的结构保持不变，但未重跑性能矩阵，不能将历史 benchmark 当作此候选的性能成绩。
typed Host 的具体拒绝原因仍保存在 Runtime，对外 VM 错误使用通用 `host_import_failed`；统一诊断透传
仍待补齐，不将本节错误原因的内部可查询性宣称为完整用户诊断。
UI 合成事件、跨进程存档、物理输入、视觉、热重载压力与长稳分别记录，不互相替代。
