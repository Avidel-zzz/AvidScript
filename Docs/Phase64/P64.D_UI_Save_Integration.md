# P64.D UI 与存档集成

状态：Editor 游戏进程的 UI/跨进程存档自动验证通过；人工输入、视觉、异常存档和长稳仍待验收。

## 实现范围

- `Samples/CSharp/UiSaveDemo`：C# 处理 Collect/Save/Load/Reset、分数、错误状态及订阅生命周期。
- Editor 资产生成器：通过 UE API 创建 Widget Blueprint、Actor 宿主、SaveGame 数据壳与地图；已有资产只校验，不覆盖用户修改。
- `AvidScriptPublishProfileBindings` commandlet：复用 Profile 服务和生成器，发布任意项目 profile，输出唯一报告和明确的包身份。
- `InvokeAvidScriptUiSaveDemo.ps1`：Prepare/Publish/Play/Verify 入口，复用正式发布链路，不按目录时间猜测 binding package。
- Editor 游戏进程探针：write/read/missing/gc 四个独立进程，读取真实 UI 文本与保存文件；明确不代替物理输入/视觉验收。
- 通用 `AvidSubscriptions.IsCurrentSource(source)`：只读来源查询，Session 在同步委托派发期间保存/恢复来源；回调外返回 false。

不增加按钮或存档专用 Host API。Blueprint 只构造 UI、设置输入焦点并持有强引用；临时 FText 在 SetText 完整复制后释放。

## 集成发现

- UE5.8 的 `IsInViewport` 声明于 `UWidget`，不是 `UUserWidget`；Profile 和样例已按声明类修正。
- descriptor 原先将委托 owner 限为 Actor 并强制与 Self 继承兼容，已通过通用独立 UObject 来源修复，网络 inbound 的 owner/authority 限制保持不变。
- `avid_value_release` 是数组/FText 共享能力，旧 loader 错误地据此要求完整数组能力组。现按每组独占能力判断是否启用，并保留组内完整性、签名、重复项与 legacy array 校验。
- 事件型样例未导出 Tick，现有 Startup 无 `tick_enabled` 开关；直接停 Component Tick 会阻断 continuation/inbound。按架构 v6 补可选 Guest Tick，仍保留 Session 心跳。
- 旧 VM prepared export 只有 cell 数校验，不能区分 `I32` 与 `F32`；新增通用后端 `ValidateExportSignature` 在冷路径校验真实参数/结果类型，不新增 WASM parser 或 UI 专用 ABI。
- Roslyn 捕获赋值曾写入临时副本而非 `Ready` 静态字段，已由[通用捕获目标修复](P64.D_Captured_Assignment.md)解决。
- SaveGame `Score` setter 曾误走 Self-only 接收者路径，已由[通用 UObject 授权](P64.D_Reflection_Receiver.md)解决，未增加存档专用 Host API。
- 实际 UE 进程在探针报告失败时曾返回 0；验收必须同时检查报告身份、动作、文本、存档哈希与失败字段，不能只看进程退出码。
- 不支持签名的负向 fixture 不能用于验证无关的 owner 去重；字符串委托的完整签名覆盖仍是独立缺口，不因更换 fixture 而被视为实现。
