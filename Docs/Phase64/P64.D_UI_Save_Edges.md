# P64.D UI 与存档异常流程

状态：五进程联调通过；异常流程与组件 EndPlay 已验证，World/图形/长稳验收继续保留。

## 范围与分层

在已有保存、重启读取、缺档和 GC 四进程之外，增加独立 `edges` 游戏进程。
它只操作本次新建的隔离目录，不复用或修改正常跨进程存档，也不触碰用户游戏存档。

- C# 样例继续负责按钮事件、错误提示、分数、强引用与取消订阅，不增加测试专用 Host API。
- `AvidScriptUiSaveDemoFixtures` 负责受控存档字节、哈希链与文件写锁。
- `AvidScriptUiSaveDemoEdges` 负责异常流程及组件生命周期断言。
- 原探针负责进程、地图和模块身份、UI 文本、动作记录与报告；PowerShell 独立核对报告和实际文件。

沿用已发布模块和现有 Binding Profile，无 WASM ABI 或运行时策略变更。错类型夹具使用
Editor-only 的具体 `USaveGame` 子类，不为正常游戏新增反射类型或项目接口。

## 冻结流程

| 步骤 | 触发与预期 |
| --- | --- |
| 1-5 | Ready、Collect 到 1 分、保存、Reset 到 0 分、重新读回 1 分；Reset 不改存档 |
| 6-7 | 写入其他 SaveGame 类型，Load 显示 `Wrong save type` |
| 8-9 | 写入 -1 分，Load 显示 `Invalid saved score` |
| 10-11 | 写入 1000000 分，Load 显示 `Invalid saved score` |
| 12-13 | 写入空文件，Load 显示 `Load failed` |
| 14-16 | 恢复合法夹具并持有禁止写入的文件句柄，Save 显示 `Save failed`，文件字节不变，然后释放写锁 |
| 17-18 | 组件 EndPlay 并注销；四按钮解绑、UI 移除、宿主存档引用清空、Session 与 Owner 授权释放；再广播 Collect 不进入 Guest |

四次失败 Load 必须保持原有分数和宿主 `SavedObject` 身份。正常脚本事件精确为 9 次，
最后的迟到 Collect 广播不增加事件数。空文件是 UE 明确定义的读取失败，不用随机坏字节触发
引擎反序列化器的未知行为；它不证明任意损坏文件都能安全读取。

## 安全与证据合同

夹具仅在正常 C# Save 创建文件之后接管该文件。每次覆盖或加锁前，检查安全路径、目录内唯一
文件与当前 SHA-256；任何外部更改都终止验证。夹具按错类型、负数、越界、空文件、合法值的
固定顺序记录前后哈希及字节数。失败或退出时也释放本探针持有的句柄，不修改全局 SaveSystem、
文件权限、其他 slot 或引擎目录。

报告使用原有版本 1 格式，新增 `edges` 模式强制校验的证据：

- `runtime_snapshot_phase=before_teardown`：主 runtime 记录明确是停止前快照，不伪装成最终存活状态。
- `edges.fixtures`：五个夹具的有序哈希链，从脚本创建的存档衔接到最终实际文件。
- Reset 与失败 Save 的前后哈希；四次失败 Load 的对象身份保持证明。
- `edges.teardown`：`kind=component_end_play`、Guest EndPlay、运行时停止、Owner 不再可解析、
  Session 消失、UI 脱离 viewport、宿主存档引用清空、四按钮无绑定、事件计数不变。
- 迟到事件前后计数均为 9，且 UI 文本不变；零丢弃事件和空错误字段仍是必要条件。
