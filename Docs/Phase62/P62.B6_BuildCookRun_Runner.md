# P62.B6 单入口 BuildCookRun Runner

## 目标

为 Win64 Development 与 Shipping 提供同一个无 UI 发布入口，固定执行“C# release -> BuildCookRun -> Game target receipt 校验”，让 CI 与 P62.D Gate 使用相同参数和失败协议。

## 已实现

- `Build/InvokeAvidScriptBuildCookRun.ps1` 接收 C# release 的源码、工程、模块、产物、输出、dotnet、可选 Binding/Generated Type manifest 路径及打包配置，并要求显式提供 `ArchiveRoot`。
- 引擎根固定为 `C:\UnrealEngine`；运行前同时验证 `Build.version` 为 UE5.8、`Engine/Source` 和 `RunUAT.bat` 存在。
- runner 先调用 `Build/InvokeAvidScriptRelease.ps1`，只接受与请求模块、配置一致的单行 JSON；release 成功后才允许启动 UAT。
- UAT 固定执行 Win64 `BuildCookRun` 的 `build/cook/stage/pak/archive`，保留 `-AdditionalCookerOptions=-SkipZenStore`，不传 `-clean`，也不选择或清理 Editor target。
- 每次 UAT 使用唯一输出日志；子进程通过 `ProcessStartInfo.ArgumentList` 启动，控制台只保留单行 JSON 成功或失败摘要。
- UAT 完成后按 `TargetName + Win64 + Configuration + Game` 精确选择回执；缺失、多个匹配或早于本次 UAT 的旧回执都会失败。选定回执随后交给现有 `Build/TestAvidScriptPackageReceipt.ps1`。
- `ArchiveRoot` 必须位于项目根下，并且只能不存在或为空。runner 不删除既有目录或内容。

## 当前验证

- PowerShell AST 解析通过。
- `Build/Contracts/TestAvidScriptBuildCookRunContracts.ps1` 覆盖参数 schema、UE5.8 源码引擎、release-before-UAT、无 `-clean`、Zen workaround、Development/Shipping、ArgumentList、单行 JSON、ArchiveRoot 安全和 receipt handoff。

本批次只完成脚本与 contract 验证，没有消耗真实 BuildCookRun 预算。Development/Shipping 的真实 cook、archive、receipt 与 packaged 启动证据统一留给 P62.D Gate。
