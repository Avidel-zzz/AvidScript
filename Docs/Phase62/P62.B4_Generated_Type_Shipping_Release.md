# P62.B4 Generated Type Shipping 发布

## 目标

让脚本定义 UE 类型不再停留在 Editor JIT 生成链。正式发布时先生成原生类型壳与类型清单，再通过统一无头 Release 入口编译 Runtime 模块，最终发布可由 Shipping 加载的预编译内容寻址包。

## 已实现

- C# BuildConfig 增加 Generated Type manifest 与导入开关，并在构建管线中拒绝缺失或未启用的清单。
- Release Commandlet 和 PowerShell runner 支持项目根内的 `GeneratedTypeManifestPath`，将其传入正式 C# 编译链。
- `BuildCSharpScriptTypes.ps1` 增加 `HeadlessRelease` 与 Development/Shipping 包配置；Shipping 未走无头预编译入口时直接失败。
- Generated Type Cook 发布器接受预编译执行后端；Shipping 只接受 `wasmtime_precompiled`，并把配置传给公共模块发布器。
- 原有 Editor/JIT 调用保持默认兼容，不会被迫启动无头 Editor。

## 验证

- Release contract：5/5 通过。
- Generated Type Cook contract：10/10 通过，新增 Shipping JIT 拒绝、预编译接受和无头路由检查。
- UE5.8 `AvidTPSTemplateEditor Win64 Development` 无清理增量编译通过。
- 真实 `ScriptDefinedTypes.cs`：生成 5 个 UE 类型，发布 Shipping package `3b813bb122566180c8397e9219753263c5024c95e0e138abd883bef5ffed142c`。
- package 使用 `wasmtime_serialized_v1` 与 `require_precompiled`，包含真实 `.cwasm`；Generated Type 指针为 schema v2，并与 catalog 中的模块和 package identity 一致。

完整 Win64 Shipping BuildCookRun 与 packaged executable 启动仍由 P62.D 集中验收。
