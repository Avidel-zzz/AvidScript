# P62.C4 共享 Epoch Watchdog

## 结果

本小节补齐 Wasmtime wall-clock 执行兜底。无限循环即使没有 fuel 上限，也会由独立于 GameThread 的共享
watchdog 推进目标 Engine epoch，并稳定返回 `execution_interrupted`。

## 架构

- 整个进程只创建一条 `AvidScriptWasmtimeEpochWatchdog` 线程，不为每个 Session 或每次 Tick 创建任务；
- 每个 Wasmtime Engine 注册轻量 token，最外层 guest entry 只执行 arm/disarm；嵌套 host reentry 不重置 deadline；
- worker 维护所有已 arm token 的最早 deadline，只在超时后推进对应 Engine，不影响 peer Engine；
- instantiate 与普通/prepared fast path 使用同一 watchdog，覆盖 WASM start function；
- unregister 与 epoch increment 共用临界区，Store/Engine 销毁前先注销 token，防止异步访问已释放 Engine；
- `EpochTimeoutMilliseconds` 属于后端无关预算合同；WAMR 对该能力继续 fail closed。

生产 Session 的 Wasmtime 策略使用 1 个 epoch deadline tick 与 100 ms watchdog。该值是防止 GameThread 长时间冻结的
保守上限，不替代 fuel 的确定性指令预算。

## 验证

- UE5.8 `AvidTPSTemplateEditor Win64 Development` no-clean UBT：成功，22 个增量 action；
- `AvidScript.VM.Wasmtime.ExecutionBudget`：`1/1` Success；
- 无 fuel 的 infinite loop 在 20 ms 测试 deadline 下返回 `execution_interrupted`，总耗时小于 2 秒；
- 被中断 backend 的下一入口成功，另一个同时注册的 peer backend 也成功；
- Automation 为 Queue Empty、TestExit、状态 0。

## 隔离边界

watchdog 能隔离 WASM guest 长时间执行，不能把 Wasmtime DLL 或 UE host C++ 原生崩溃转化为 Session 级错误。
原生崩溃仍依赖受控 runtime、崩溃上下文与发布回滚，文档和 README 不把它描述为进程级 sandbox。
