# P62.D1 打包后游戏脚本 Oracle

## 目标

在不新增测试地图和 Blueprint 资产的前提下，让 Development 与 Shipping 打包程序直接验证真实 C# 游戏脚本、Cook UFS 模块解析、UE 交互和单 Session 故障隔离。

## 实现

- `-AvidScriptPackagedOracle=<module-id>` 只在显式命令行下启用，不改变普通游戏启动路径；
- Release Commandlet 已验证 Editor 可启动后，UAT 使用 `-skipbuildeditor`，只构建正式 Game target；
- World Subsystem 动态创建两个 Actor 和 `UAvidScriptComponent`，两者都通过逻辑 `ModuleId` 从 Cook 后 catalog/package 加载；
- 健康实例运行 `GeneratedBindingLifecycleScript`，覆盖 `BeginPlay`、`Tick`、自动生成的 UE Reflection 属性/函数、Event、Timer、continuation 与 `EndPlay`；
- 故障实例通过保留的 `-62001` 事件触发整数除零 WASM trap，随后验证该 Session 被隔离，而健康实例继续 Tick；
- 结果写入 Project Saved 下的单个紧凑 JSON，并用进程退出码表达成功或失败；报告路径越出 Saved 根会 fail closed；
- 未重写的 Game receipt 只在本次唯一 UAT 日志包含精确输出路径时接受，并标记为 `uat_validated_existing` 后继续执行完整 hash 验证；
- JSON 包含配置、模块/包身份、生命周期计数、故障拒绝、World 继续运行、continuation 位移和有界错误摘要。

该 Oracle 验证的是受控 WASM Guest 故障隔离，不宣称能够隔离原生 C++ 或第三方 DLL 的进程级崩溃。
