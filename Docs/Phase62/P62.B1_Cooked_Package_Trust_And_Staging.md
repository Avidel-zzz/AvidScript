# P62.B1 Cooked Package 信任与 Staging

## 已实现

- `AvidScriptRuntime` 从默认 catalog 精确收集引用文件，并以 UFS staging；非 Editor 目标缺失 catalog 时直接失败；
- `LoadPublishedModule` 根据逻辑 `ModuleId` 重新解析默认 catalog，校验期望 package identity 后才加载 artifact；
- Cooked 默认目录可授予持久 `VerifiedPackage` trust，Editor 与松散 manifest 继续使用进程内 attestation；
- trust 随 `FAvidScriptRuntimeArtifact` 进入 Session 与 VM，Wasmtime 仍负责二次校验 artifact hash、target triple
  与 compiler build identity；
- Win64 Game/Client/Server target 强制使用受控 Wasmtime performance toolchain，并 staging DLL 与许可证；
- `UAvidScriptComponent` 的初始加载与 reload 均使用同一 published-module 入口。

## 验证

| 项目 | 结果 |
| --- | --- |
| UE5.8 no-clean UBT | Runtime 与 Generated 集中构建通过，7 个 action |
| Runtime artifact Automation | `AvidScript.Reload.RuntimeArtifactLoader` 1/1 通过 |
| Generated package Automation | `AvidScript.GeneratedTypes.CookedPackageLoad` 1/1 通过 |

本小节证明代码路径与 Editor 自动化合同；真实 Development/Shipping UFS receipt 与 packaged 启动仍属于 P62.D Gate。
