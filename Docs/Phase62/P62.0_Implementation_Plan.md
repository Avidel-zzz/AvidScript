# Phase 62 实施计划

## P62.A 模块资产与发布合同

1. 新增 `FAvidScriptModuleReference`、`FAvidScriptModuleCatalog`、`FAvidScriptResolvedModule` 与统一 resolver；
2. 实现 catalog/package schema v1、规范化逻辑 id、内容寻址身份、路径边界和严格额外文件检查；
3. 实现通用 C# release publisher：复制最小运行时依赖、剥离开发产物、原子发布 package 与 catalog；
4. `UAvidScriptComponent` 优先使用逻辑 module id，开发 manifest 仅作为非 Shipping 兼容入口；
5. Generated Type package 接入公共 resolver，不再固定 JIT 执行策略。

完成条件：同一输入重复发布身份稳定；Component 与 Generated Type 都能通过 module id 读取同一验证链；任意绝对路径、
目录逃逸、hash 漂移、重复 module 或多余文件均在 VM 创建前拒绝。

## P62.B Cook、Staging 与 Shipping Policy

1. UBT 从 catalog 读取精确依赖集，将脚本包作为 `UFS`、Wasmtime DLL 作为 `NonUFS`；
2. 增加干净 checkout release orchestrator，依次验证/安装 Wasmtime、构建 C#、生成 native shell、发布 package，并在缺失时
   早于 UBT/UAT 失败；
3. 增加 receipt validator，校验 staged type、目标路径、文件数、hash、runtime DLL、专用 export 与 license；
4. 发布 profile 区分 Development 与 Shipping；Shipping 强制 precompiled、剥离 source/Guest IR/semantic 和默认 Debug Map；
5. 建立 `CookedPackage` artifact trust 与 runtime build/target/CPU compatibility 校验；
6. 增加单入口 BuildCookRun runner，复用已知 UE5.8 Zen workaround，但不清 Editor target。

完成条件：Win64 Development 与 Shipping receipt 均只包含 catalog 白名单；Shipping 删除 `.cwasm`、修改 hash、改 target
或请求 JIT 时全部 fail closed。

## P62.C Session 故障与资源隔离

1. 扩展后端无关 execution budget contract，不把 Wasmtime 类型泄漏到 Runtime；
2. Wasmtime 配置 fuel、epoch interruption 和 Store limiter；WAMR 以 capability 明确支持或拒绝；
3. 统一 trap、fuel、epoch、memory limit 与 host failure 的稳定错误分类；
4. Session faulted 状态取消 timer、continuation、delegate、async load 与 ObjectHandle，并拒绝再次进入；
5. 添加有界诊断、重复错误抑制和 fault metrics。

完成条件：正常 workload 在预算内通过；无限循环、内存增长和 Guest trap 不冻结 GameThread，不影响另一个 Session，并在
World/Object teardown 后保持零悬挂 callback/handle。

## P62.D Win64 发布闭环与 Gate

1. 发布真实 C# gameplay fixture，覆盖 BeginPlay、Tick、UE property/function crossing、event/continuation 与 EndPlay；
2. 运行 Win64 Development BuildCookRun、启动 packaged executable，并用结构化 oracle 验证生命周期和干净退出；
3. 运行 Win64 Shipping BuildCookRun，证明 precompiled backend、UFS trust、版本兼容和无 JIT fallback；
4. 运行故障夹具，证明单 Session fail closed 与 World 继续运行；
5. 集中完成 .NET、no-clean UBT、Automation、architecture/privacy、package/receipt 和启动性能 Gate。

完成条件：外置 Gate 报告记录 frozen commit/tree、包身份、receipt、运行日志、进程退出和完整测试计数；README 只写已通过的
Win64 能力，并保留移动端与干净机器人工验收边界。

## 提交与验证节奏

- 架构、P62.A、P62.B、P62.C、P62.D/Gate 各自形成可独立审查的小节，完成后精确提交并立即推送；
- 实现期只运行格式、schema contract、console runner 和高风险最小探针；
- UBT、Automation、BuildCookRun 与 benchmark 在批次或阶段 Gate 集中执行；
- 普通 findings 进入一次集中修复，不做“小任务 -> 复审 -> 再复审”的串行链；
- README 与小节文档同批同步，能力声明必须已有当前证据。

## 验证预算

- UBT：实现期最多 3 次，阶段 Gate 1 次 no-clean；
- Automation：focused 最多 3 轮，完整 Gate 最多 2 轮；
- BuildCookRun：Development 最多 2 轮、Shipping 最多 2 轮；
- packaged 启动：每个候选配置最多 3 次；
- 性能：只在 execution budget 与启动成本候选冻结后运行固定矩阵。
