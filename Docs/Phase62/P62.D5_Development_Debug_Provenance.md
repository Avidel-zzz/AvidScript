# P62.D5 Development 调试来源闭环

## 问题

Development 发布包包含 `debug_map`，但旧发布策略同时删除了 Runtime 校验调试图所需的
`source` 与 `guest_ir` 来源信息。结果是包结构和哈希均有效，打包程序仍会在加载阶段以
`debug_map_manifest_invalid` 拒绝模块。

## 实现

- Development 包含调试图时，保留最小、不可执行的来源元数据：源码身份与源码、
  Frontend、Semantic、Guest IR 的 SHA-256，以及 Guest IR 模块身份。
- 不发布源码、Frontend、Semantic 或 Guest IR 文件，也不保留这些构建产物的路径。
- Shipping 继续移除调试图和全部来源信息。
- 发布时先校验来源对象形状和小写 SHA-256，错误在发布阶段失败，不延迟到游戏启动。

## 契约

模块发布契约检查 Development 的最小来源字段集合，禁止构建产物路径泄漏；原有
Shipping 契约继续检查 `source`、`guest_ir`、`semantic`、`debug_map` 均不存在。
