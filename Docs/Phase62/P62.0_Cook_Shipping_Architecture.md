# Phase 62 Cook 与 Shipping 架构

> 状态：架构冻结候选 v1
> 主线：模块资产 -> 内容寻址发布包 -> Cook 信任域 -> Shipping 预编译执行 -> 故障隔离

## 1. 目标

Phase 62 把 Editor 中可运行的 C# WASM 脚本升级为可随 UE5.8 Win64 游戏确定性发布的运行时资产：

- 游戏逻辑使用稳定模块身份，不在 Actor/Component 上保存开发机绝对路径；
- 发布包完整携带 Runtime manifest、canonical WASM、Wasmtime 预编译产物、Binding 依赖和可选诊断数据；
- Cook、Stage、Pak/IoStore 与运行时加载验证使用同一份内容寻址清单；
- Shipping 默认只执行受信任、版本兼容且预编译的字节，不静默回退 JIT；
- trap、超预算、内存增长失败和生命周期 teardown 只使当前 Session 失效，不让错误 Session 再进入 UE；
- BuildCookRun 后由真实 C# `BeginPlay/Tick/EndPlay` 与 UE 交互给出机器可判定结果。

本阶段先关闭 Win64。Android/iOS AOT、后台切换和平台包体门禁属于 Phase 63。

## 2. 当前基础与阻塞

已有基础：

- C# 构建链可发布 canonical WASM、Runtime manifest、Binding package、Debug Map 和 Wasmtime serialized artifact；
- `FAvidScriptRuntimeArtifactLoader` 已验证 canonical bytes、execution hash、target triple 与显式 fallback policy；
- `AvidScriptGenerated` 已有单包内容寻址目录与 UBT receipt staging；
- `FAvidScriptRuntimeSession` 已统一 BeginPlay、Tick、Event、continuation、reload、cancel 与 teardown；
- Wasmtime trap 已映射为结构化 Runtime 诊断。

当前不能宣称 Shipping 闭环，原因是：

1. `UAvidScriptComponent` 仍以 `FFilePath` 解析 `ProjectDir`，Cook 后没有稳定模块地址；
2. Generated Type 包固定为 `wasmtime_jit`，并以 loose `NonUFS` 文件发布；
3. serialized artifact 的 `attestation_id` 只存在于当前 Editor 进程内，新的 packaged 进程无法建立信任；
4. Wasmtime Store 尚无明确的 fuel、epoch 和 memory growth 预算；
5. 现有历史 packaged smoke 只覆盖 WAMR embedded module，不证明真实 C# 发布资产可运行；
6. 干净 checkout 没有在 UBT/UAT 前统一安装 Wasmtime、生成 native shell、发布 bundle 并冻结身份的 release 入口；
7. bundle 缺失时 `AvidScriptGenerated.Build.cs` 会直接跳过，Wasmtime 缺失时也会编译为 unavailable，可能产出
   “游戏启动成功但脚本未运行”的空包；
8. Wasmtime 官方 fallback 与 AvidScript performance runtime 的专用 export contract 不完全等价，不能只以头文件、
   import library 和 DLL 存在作为可用证明；Generated Type 调用失败也必须进入 Session fault lifecycle，不能丢弃错误。

## 3. 模块与发布合同

### 3.1 逻辑模块引用

Runtime 对外新增 `FAvidScriptModuleReference`，稳定字段为 `ModuleId`。Editor-only 兼容字段可保留开发 manifest，
但 Shipping 不解析任意文件路径。`UAvidScriptComponent`、Generated Type Runtime Host 与后续 Subsystem 共用同一
resolver，不各自维护路径规则。

模块身份必须：

- 使用非空、规范化、大小写稳定的逻辑 id；
- 不包含目录分隔符、父目录、盘符或 URI；
- 在 catalog 中唯一；
- 解析后同时返回 module id、package id、descriptor identity 与 trust domain。

### 3.2 发布目录

项目级发布根固定为：

```text
Content/AvidScript/Modules/
├─ catalog.json
└─ <module-id>/
   └─ <package-id>/
      ├─ package.json
      ├─ runtime.avidscript.json
      ├─ module.wasm
      ├─ module.wasmtime.cwasm
      ├─ bindings/package.json
      ├─ bindings/bindings.json
      └─ diagnostics/debug-map.json   # Development 可选，Shipping 默认剥离
```

`package-id` 是规范化 package descriptor 及全部运行时依赖 identity 的 SHA-256。发布采用临时目录、完整校验、
原子 rename；相同 package id 只能复用完全相同的文件集合。`catalog.json` 按 module id 排序并原子替换，禁止把
`Saved/`、源码、Guest IR、semantic artifact 或绝对路径带入发布包。

### 3.3 Catalog 与 Package Schema

Catalog schema v1 只保存：

- `schema_version`；
- 有序 `modules[]`；
- 每项的 `module_id`、`package_id`、项目 Content 相对 descriptor path、descriptor SHA-256；
- 可选 platform/configuration selection，不允许隐式“取最新目录”。

Package schema v1 绑定：

- module id、ABI/schema、package id；
- canonical WASM 与 serialized artifact 的 path/hash；
- compiler/runtime build identity、target triple、CPU feature contract；
- Binding package path/hash；
- diagnostics strip policy；
- execution policy、resource policy 和 minimum plugin/runtime version。

任何未知 schema、重复 module、hash 漂移、目录逃逸、额外文件、缺失依赖或版本不兼容都 fail closed。

## 4. Cook 与信任模型

### 4.1 Staging

- WASM、manifest、descriptor、Binding 和允许保留的 Debug Map 作为 `UFS` 进入 Pak/IoStore；
- `wasmtime.dll` 及平台动态库作为精确 hash 的 `NonUFS` runtime dependency；
- UBT 从 catalog 解析精确文件白名单，禁止目录通配式带入缓存、源码或旧 package；
- 受控 release 入口在 UBT/UAT 前完成依赖安装、C# 构建、native shell 与 package 发布；Shipping 缺任一输入时构建失败，
  不允许静默生成无脚本产品；
- receipt validator 同时验证 staged type、目标路径、文件数、SHA-256 和 runtime dependency；
- Development 与 Shipping 使用独立发布 profile，不共享可变 `current.json`。

### 4.2 Artifact Trust

Wasmtime serialized bytes 只能从两类信任域进入 `deserialize`：

1. 当前进程刚由受控 compiler 生成，并在内存 attestation registry 中授权；
2. Cook 时验证并写入受控 UFS package，运行时从只读发布根加载，且 package descriptor、hash、runtime build
   identity、target triple 与 Shipping policy 全部匹配。

任意开发路径、loose override、下载文件或只提供自报 hash 的外部 bytes 不具备 `CookedPackage` trust。
项目若面对恶意本地篡改，仍必须启用 UE Pak/IoStore 签名；插件不能把未签名游戏数据伪装成密码学可信。

Shipping 默认 `require_precompiled`，缺失或不兼容时直接拒绝模块。Development 可显式
`prefer_precompiled`，但 fallback 必须出现在诊断和统计中。

## 5. 运行时解析与生命周期

`FAvidScriptModuleResolver` 只在冷路径加载并验证 catalog/package，返回不可变
`FAvidScriptResolvedModule`。Runtime Artifact Loader 从该对象读取已验证 bytes，不重新按名称查找文件。

Session 加载顺序：

1. 解析逻辑 module id；
2. 验证 catalog、package、依赖、平台和 runtime compatibility；
3. 建立 artifact trust；
4. 校验实际 WASM imports/exports 和 Binding capability；
5. 实例化 VM，成功后才提交为 live Session；
6. BeginPlay 失败或任何 trap 时逆序清理，不保留半激活实例。

Component 的开发 manifest fallback 仅在非 Shipping 且显式允许时存在；嵌入式 smoke 不再作为用户模块缺失时的
静默成功路径。Generated Type Host 复用 resolver，并以附加 type manifest 扩展 package，不复制执行策略。

## 6. 故障与资源隔离

WASM 语言级隔离的边界是 Session，不是操作系统进程：

- 每次 Guest 入口配置 fuel 或等价指令预算；耗尽映射为稳定 `execution_budget_exceeded`；
- Wasmtime epoch interruption 为长时间运行提供 wall-clock 兜底，deadline 由 Runtime owner 推进；
- Store limiter 限制 linear memory、table、instance 和 growth；
- host import 仍受 GameThread、ObjectHandle、world、capability 和参数边界验证；
- trap/预算失败把 Session 标记为 faulted，取消 continuation/delegate/timer，释放 handle，并拒绝再次进入；
- 诊断有长度、帧数和重复日志预算。

Wasm trap、越界和资源滥用可以在同进程内隔离；Wasmtime DLL、UE host C++ 或平台原生崩溃不能由同进程 Session
完全隔离。Phase 62 不虚构进程级容错，原生崩溃依靠受控 runtime 版本、崩溃上下文和发布回滚；可选进程外
sandbox 属于未来高隔离部署方案。

## 7. 版本兼容

兼容键至少包含：

- AvidScript ABI 与 Runtime package schema；
- Binding descriptor schema 与 package identity；
- VM backend、Wasmtime runtime build identity 和 artifact format；
- target triple、pointer width、endianness 和 CPU feature profile；
- canonical WASM hash、serialized hash 与 compiler build identity。

不匹配时返回稳定 category 与 next action。Shipping 不现场重编译以掩盖版本问题；重新发布 package 是唯一修复路径。

## 8. 模块所有权

- `Build/`：release publisher、catalog、receipt validator、BuildCookRun runner；
- `AvidScriptEditor`：从 C# build result 创建预编译发布输入，不进入 packaged Runtime；
- `AvidScriptRuntime`：module reference、resolver、package validator、Shipping policy、Session fault lifecycle；
- `AvidScriptVM`：artifact trust、runtime compatibility、fuel/epoch/store limiter 与 trap 分类；
- `AvidScriptGenerated`：消费公共 module resolver，只保留 generated UClass/registry glue；
- `ThirdParty/Wasmtime`：精确版本、hash、license 与平台 runtime dependency。

依赖方向保持 `Generated/Editor -> Runtime -> VM -> Core`，Build 只消费版本化 JSON，不解析 C++ 私有状态。

## 9. Gate

- publisher 对相同输入连续两次产生相同 package id、文件集合和 SHA-256；
- 干净 checkout 可由单一 release 入口重建全部被 `.gitignore` 排除的工具链与 generated 产物；缺失 bundle、专用 runtime
  export 或 Wasmtime identity 时在 UAT 前失败；
- catalog/path/schema/hash/额外文件/版本/backend 的负例全部 fail closed；
- Development packaged game 运行真实 C# BeginPlay、至少 120 Tick、一次 UE property/function crossing 和 EndPlay；
- Shipping packaged game证明 `require_precompiled`，没有 JIT fallback，且 staged artifact 来自 UFS 发布根；
- trap、无限循环或等价预算夹具只终止当前 Session，World 可继续 Tick 并完成干净退出；
- Wasmtime DLL hash、license、receipt、Pak/IoStore 文件存在性与 packaged log oracle 全部通过；
- UE5.8 no-clean UBT、AvidScript Automation、architecture/privacy 和必要性能预算集中通过。

人工验收保留：从干净机器安装 packaged build、杀毒软件/权限环境、真实图形窗口和输入体验。自动日志不能替代这些检查。

## 10. 非目标

- 不在 P62 宣称 Android/iOS AOT、移动端后台切换或真机通过；
- 不把所有脚本塞入一个全局 bundle，也不为每个 API 手写 staging；
- 不用 loose `NonUFS` 脚本文件冒充受信任 Shipping package；
- 不用 embedded smoke 替代真实 C# artifact；
- 不把 Wasm trap containment 描述为原生进程崩溃隔离；
- 不以清理 Editor target 或反复全量构建推进实现。
