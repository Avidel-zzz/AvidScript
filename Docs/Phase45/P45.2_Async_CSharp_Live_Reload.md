# P45.2 C# 异步热重载

> 状态：已完成。验证环境为源码版 UE5.8、Win64 Editor Development。

## 阶段结论

P45.2 已把项目级 C#+WASM 自动热重载从“主线程同步构建”升级为可取消、可观测、失败保活的异步流水线：

1. 文件保存仍由 DirectoryWatcher、350ms debounce 和 single-flight coordinator 合并。
2. PowerShell、Roslyn、Guest IR 与 WASM 构建在外部进程中异步执行。
3. Editor 主线程只负责推进 job、验证 completion 身份和提交 Actor binding，不再等待外部构建完成。
4. Stop 会终止 PowerShell、dotnet 及其子进程树，并立即让 job 进入 Canceled。
5. 构建失败或取消会恢复之前已经提交的 report、manifest 与 WASM 字节。
6. 候选 runtime 绑定失败时，旧的内存 runtime 与 Tick 继续运行。

当前 Win64 Editor 已经具备接近成熟脚本插件的核心开发循环：在 C# 中编写 UE Actor 生命周期逻辑，保存后后台构建 WASM，并在运行中事务式切换。

## 快速使用

### 1. 创建工作区

在 UE Editor 中执行：

```text
Tools > AvidScript > Create Project C# Gameplay Workspace
```

默认用户工作区位于：

- `<Project>/Scripts/AvidScript/GameplayScript.cs`
- `<Project>/Scripts/AvidScript/AvidScript.Gameplay.csproj`
- `<Project>/Scripts/AvidScript/default.csharp-profile.json`
- `<Project>/Scripts/AvidScript/global.json`

生成的 IDE facade 位于 `<Project>/Intermediate/AvidScript/CSharpWorkspace`，正式可加载产物位于 `<Project>/Saved/AvidScriptCSharpGuest/ProjectGameplay`。

### 2. 选择 Actor 并启动

1. 在关卡中选择承载脚本的 Actor。
2. 执行 `Tools > AvidScript > Start Project C# Auto Live Reload`。
3. 初始 Workspace、Build 与 Bind 全部成功后，文件监听才会启动。
4. 修改并保存 `GameplayScript.cs`，新的构建会在后台运行。

也可以先执行 `Build And Bind Project C# Gameplay Script` 单独验证初始构建和绑定，再启动自动热重载。

Start 会固定初始 Actor。之后改变 Editor selection 不会把 reload 悄悄切换到另一个对象。当前一个 Editor 模块只允许一个活动 session；切换目标前先 Stop。

### 3. 编写 C# 游戏逻辑

下面是当前模板的完整生命周期形状。`UE.Self` 是绑定 Actor 的 typed handle，`FVector`、`FRotator` 与 Actor API 来自 reflection binding generator，不需要逐个手写桥接：

```csharp
using System.Runtime.InteropServices;

namespace AvidScript;

public static class GameplayScript
{
    private const float RotationSpeedDegreesPerSecond = 90.0f;

    public static int Main() => 0;

    [UnmanagedCallersOnly(EntryPoint = "avid_on_begin_play")]
    public static void BeginPlay()
    {
        UE.Self.SetActorScale3D(new FVector(1.0f, 1.0f, 1.0f));
    }

    [UnmanagedCallersOnly(EntryPoint = "avid_on_tick")]
    public static void Tick(float deltaSeconds)
    {
        FRotator rotation = UE.Self.GetActorRotation();
        UE.Self.SetActorRotation(
            new FRotator(
                rotation.Pitch,
                rotation.Yaw + RotationSpeedDegreesPerSecond * deltaSeconds,
                rotation.Roll),
            false);
    }

    [UnmanagedCallersOnly(EntryPoint = "avid_on_timer")]
    public static void OnTimer(int callbackId, int timerHandle)
    {
    }

    [UnmanagedCallersOnly(EntryPoint = "avid_on_event")]
    public static void OnEvent(int eventId, float value)
    {
    }

    [UnmanagedCallersOnly(EntryPoint = "avid_on_gameplay_event")]
    public static void OnGameplayEvent(
        int eventType,
        int primaryId,
        int secondaryId,
        int objectSlot,
        int objectGeneration,
        float x,
        float y,
        float z)
    {
    }

    [UnmanagedCallersOnly(EntryPoint = "avid_on_end_play")]
    public static void EndPlay()
    {
    }
}
```

保存后无需再次点击 Build。默认监听 `.cs`、`.csproj`、`.props`、`.targets` 与 `.json`，同一保存窗口内的变化会合并为一次构建。

### 4. 停止

执行 `Tools > AvidScript > Stop Project C# Auto Live Reload`。Stop 是幂等操作；构建正在运行时，它会取消整棵外部进程树、回滚未提交产物并注销 watcher/ticker。模块卸载也执行同一停止路径。

## 异步状态与进度

`FAvidScriptEditorCSharpAsyncBuildProgress` 提供以下字段：

- `Stage`：当前阶段。
- `ElapsedSeconds`：当前 job 已运行时间。
- `LatestOutputLine`：最新一行外部进程输出。
- `OutputLineCount`：累计输出行数。
- `bCancelRequested`：是否已经请求取消。

公开阶段为：

| 阶段 | 含义 |
| --- | --- |
| `Idle` | 尚未启动 |
| `Preparing` | 读取 profile 并准备共享构建计划 |
| `BootstrapRunning` | 生成或验证完整反射授权输入 |
| `PublishingBindingSlice` | 根据实际引用发布最小 runtime binding slice |
| `FinalRunning` | 构建正式 WASM、manifest 与 report |
| `ReadyToBind` | 构建成功，等待主线程提交 Actor binding |
| `Failed` | 构建或验证失败 |
| `Canceled` | 显式取消，结果不可提交 |

这些信息目前通过 service result 与日志供 Editor 集成使用；尚未实现独立的进度窗口或取消按钮，菜单 Stop 是当前用户入口。

## 架构职责

| 模块 | 唯一职责 |
| --- | --- |
| Build Invocation | 统一同步和异步路径的 PowerShell 参数、report 解析与最终验证 |
| Build Pipeline | 编排 bootstrap、binding slice、final build 与正式产物事务 |
| Build Process | 封装 `FMonitoredProcess`、线程安全输出快照和 kill-tree |
| Async Build Backend | 持有 profile、pipeline 与 invocation 的阶段编排 |
| Async Build Job | 持有 process、公开阶段、进度、取消与单次结果消费 |
| Live Reload Service | 持有 watcher、ticker、session、request/job identity 与 Stop 生命周期 |
| Component Binding | 仅在 Editor 主线程对固定 Actor 提交候选 runtime |

`FMonitoredProcess` 的 delegate 只写入线程安全 pending state。反射授权包生成、报告验证、binding slice 发布、Actor 有效性检查和 runtime reload 都由 Editor 主线程 ticker 推进。

completion 必须同时匹配 session generation、request id、active job serial、固定 Actor path 与有效 `TWeakObjectPtr`。Stop、Actor 销毁或旧请求返回的结果都不能进入 Bind。

## 事务与失败语义

### 构建产物事务

在 final invocation 前，BuildPipeline 会把已提交的 report、manifest 与 WASM 备份到：

```text
<Project>/Intermediate/AvidScript/CSharpBuildTransactions/<guid>
```

- 构建和共享 Finalize 全部成功：提交新产物并删除备份。
- 编译失败、进程启动失败、显式取消或 job cleanup：恢复旧文件的精确字节。
- 旧文件原本不存在：失败时删除本次产生的新文件。
- 回滚失败：返回 `artifact_rollback_failed` 并保留备份目录供恢复。

因此，构建失败后 `BuildResult` 仍保留本次结构化错误，但正式路径重新指向之前已提交的可运行产物。

### Runtime 绑定事务

构建成功并不等于 runtime 一定接管。`ReadyToBind` 之后还要验证 manifest、ABI、imports/exports、实例化与候选 BeginPlay：

- 绑定成功：新 runtime 接管，旧 runtime 才被释放。
- 绑定拒绝：返回 `reload_rejected`，旧内存 runtime 和 Tick 保持有效。

这里需要区分两个事务边界：候选绑定失败时，这次构建已经是一个有效的磁盘提交，所以不会把正式磁盘产物回滚到上一个版本；被保留的是旧的内存 runtime。下一次保存可以继续构建并重试绑定。

候选 BeginPlay 已经执行的 UE host-side 写入目前没有通用回滚，脚本初始化仍应避免在可能失败的步骤前制造不可逆副作用。

真实场景额外证明：

- 双阶段 C# 构建期间 CoreTicker heartbeat 持续增长，Editor 主线程没有被外部构建阻塞。
- 90 度/秒脚本成功 reload 到 180 度/秒，新 Tick 行为生效且只提交一次。
- 写入错误 C# 后，manifest 与 WASM 字节不变，旧 180 度/秒 runtime 继续 Tick。
- 有效构建的候选 manifest 被绑定层拒绝后，`reload_rejected` 计数正确，旧 runtime 继续 Tick。
- Stop 真实终止 PowerShell -> dotnet MSBuild -> PowerShell 子进程树，job 进入 Canceled，正式三件套与旧 runtime 均保留。

所有 focused 与全量 UE 日志均验证 Found、全部 Success、非成功 0、Queue Empty、TestExit、`RequestExitWithStatus(1, 0)` 与进程退出码 0。

## 当前限制

P45.2 已解决高频 Editor 迭代中的同步卡顿和取消问题，但还不能宣称达到 Puerts、UnLua 或成熟 AngelScript 集成的完整程度：

- 只完成 Win64 Editor 验证；Cook、Staging、Shipping、Android 与 iOS 尚未闭环。
- reload 不迁移 guest 静态字段、managed heap、协程 continuation、Timer/Event 队列。
- 候选生命周期产生的 host-side UE 写入没有通用 rollback。
- 尚无 source map、C# 调用栈定位、断点、变量查看与 IDE 调试协议。
- 当前一个 Editor 模块只维护一个固定 Actor session。
- service 内部保证单飞，但不同外部调用方之间还没有全局 profile/build 锁。
- 构建进度已有数据契约，但还没有专用 Editor 面板。
- reflection binding 已避免逐 API 手写，但默认授权面仍不是完整 UE API 目录。

## 下一阶段建议

建议 P45.3 优先实现“脚本实例模型与 guest state migration 第一版”，让热重载不再重置关键游戏状态：

1. 定义稳定字段标识、版本化 snapshot schema 与迁移失败诊断。
2. 在候选 runtime 激活前导出旧状态，在新 runtime BeginPlay/恢复阶段导入。
3. 对不兼容字段执行显式默认值或拒绝策略，禁止静默错位。
4. 保持现有 BuildPipeline、AsyncJob 与 Actor binding 边界不变。
5. 用可阅读的 C# 样例验证计数器、向量与基础值类型跨 reload 保留。

完成首个可验证切片预计需要约 3 到 5 小时；覆盖引用对象、Timer/Event、协程与 host-write rollback 则需要后续独立阶段继续深化。
