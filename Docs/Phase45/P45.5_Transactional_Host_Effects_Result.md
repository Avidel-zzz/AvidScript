# P45.5 候选热重载宿主副作用事务阶段成果

## 阶段目标

P45.5 解决候选 C# + WASM runtime 在 `BeginPlay` 中已经修改 UE 对象、随后又加载失败时留下半生效游戏状态的问题。本阶段把生成式 binding policy、动态反射调用、静态 ABI、RuntimeSession 和 UE 对象恢复连接成同一条事务链：候选成功则提交，候选失败则恢复已覆盖的 transform，旧 runtime 继续运行。

## 已实现能力

- Binding Descriptor 升级到 schema v3，每个函数必须携带 `reload_effect`。生成器使用中央精确表分类，不依赖函数名模糊匹配，也不为每个 UE API 新增 VM switch 或手写 host import。
- v2 descriptor 仍可加载：只读函数归一化为 `none`，非 const 函数归一化为 `unsupported`，因此旧 package 不会被错误当成可回滚写入。
- 当前可逆 effect domain 为 `actor_transform` 与 `scene_component_transform`。同一对象、同一 domain 在候选期间只保存一次原始 `FTransform`，重复写入不会重复分配 snapshot。
- Actor 静态 ABI 已覆盖位置、位置增量、旋转和缩放写入；SceneComponent 静态 ABI 已覆盖世界位置写入。动态生成 binding 也通过同一 journal 接口进入 transaction。
- 动态 dispatcher 的固定顺序为：解析 target、检查写权限、解码参数、准备 host effect、执行 `ProcessEvent`、写回 out/return。snapshot 或 policy 失败时不会调用 `ProcessEvent`。
- 未声明 adapter 的非 const 动态 binding 在候选 `BeginPlay` 中返回 `binding_reload_effect_unsupported`。同一 binding 在普通 live Tick/Event context 中没有 transaction，仍保持原有授权行为。
- RuntimeSession 只在 reload candidate 的 `BeginPlay` 中创建 `TOptional<FAvidScriptHostEffectTransaction>`。初次加载、旧 runtime、成功切换后的 Tick/Event/Input 都不持有 journal 指针。
- 候选 `BeginPlay` 成功后 transaction commit，写入保留；发生 WASM trap、host import 拒绝或其他生命周期失败时逆序 best-effort rollback，随后卸载候选，旧 runtime、scheduler 和 manifest 保持有效。
- reload 结果公开 transaction attempted/committed、rollback attempted/succeeded、captured/restored/failed 数量和首个 host-effect 错误来源，便于 Editor UI 与日志诊断。

## 当前可逆范围

| Effect domain | 当前入口 | 回滚数据 |
| --- | --- | --- |
| `actor_transform` | Actor location、location offset、rotation、scale；生成式动态 `SetActorScale3D` | `AActor::GetActorTransform()` |
| `scene_component_transform` | SceneComponent world location | `USceneComponent::GetComponentTransform()` |
| `none` | const / BlueprintPure 查询 | 不创建 snapshot |
| `unsupported` | 尚无 adapter 的非 const binding，例如 `SetVisibility` | 候选阶段在 `ProcessEvent` 前拒绝 |

扩展 UE API 时，新增函数先由 descriptor generator 分类。只有新的副作用语义无法映射到现有 domain 时，才增加独立 adapter；不能退回“一个 API 一个 import/一个回滚函数”的维护方式。

## C# 使用方式

脚本写法不需要显式操作 transaction。候选边界由 RuntimeSession 自动建立：

```csharp
using System.Runtime.InteropServices;

namespace AvidScript;

public static class GameplayScript
{
    [UnmanagedCallersOnly(EntryPoint = "avid_on_begin_play")]
    public static void BeginPlay()
    {
        UE.Self.SetActorScale3D(new FVector(2.0f, 3.0f, 4.0f));
    }

    [UnmanagedCallersOnly(EntryPoint = "avid_on_tick")]
    public static void Tick(float deltaSeconds)
    {
        FVector scale = UE.Self.GetActorScale3D();
        UE.Self.SetActorScale3D(new FVector(scale.X + deltaSeconds, scale.Y, scale.Z));
    }
}
```

初次加载会直接执行 `BeginPlay`。热重载时，同一写入会先保存 Actor transform：新脚本成功则保留缩放；如果写入后 WASM trap，则恢复热重载前缩放，旧 C# runtime 的下一次 Tick 仍可继续读写 Actor。

## 分层职责

- `AvidScriptEditor`：反射选择、effect policy 分类、descriptor v3 和 C# facade/package 生成。
- `AvidScriptBindings`：公开非 owning journal 合同，在静态 ABI 与动态 `ProcessEvent` 前准备 effect；不拥有 transaction。
- `AvidScriptVM`：只转发动态 host call 和 guest memory，不包含 UObject 或 transaction 类型。
- `AvidScriptRuntime`：HostEffectTransaction 保存/恢复 UE transform；RuntimeSession 负责 candidate-only 生命周期编排。
- C# 游戏代码：只表达游戏逻辑，不感知 snapshot、commit 或 rollback 实现。

## 已知边界

- 本阶段没有尝试回滚 Spawn/Destroy、RPC、delegate 绑定、异步任务、Timer、网络发送、音频、磁盘或外部服务副作用；这些写入在获得专用 adapter 前必须保持 `unsupported`。
- transaction 当前只包围 reload candidate 的 `BeginPlay`。live Tick/Event/Input 的错误隔离仍依赖现有 runtime 生命周期，不进行逐帧 UE 世界快照。
- rollback 是逆序 best-effort。对象句柄失效、对象被销毁或 UE 拒绝恢复 transform 时会继续恢复其他 entry，并报告 failed count 与首个错误来源。
- 当前完成的是 PC Editor/source-build 闭环。Cook/Shipping、移动端 WAMR 配置、调试器、性能基准扩面和更完整 UE 类型/API 覆盖仍属于后续 phase。
- 本阶段让 C# + WASM 热重载的已覆盖 transform 写入具备可靠事务语义，但插件整体尚未达到 Puerts、UnLua 或 Unreal AngelScript 的完整成熟度。

## 结论

P45.5 已消除已覆盖 transform 在候选 `BeginPlay` 失败后的半生效状态，并把未知写入默认拒绝、可逆写入生成式分类、真实 C# 动态调用和旧 runtime 保活统一到一个可验证框架中。后续可以在不扩大 VM 手写 API 面的前提下，按 effect domain 增加组件属性、容器值与受控对象生命周期 adapter。
