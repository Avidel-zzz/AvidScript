# Phase 45：C# 自动 Live Reload 架构

> 状态：P45.0 设计已定稿。首个实现切片为 P45.1，验证平台为源码版 UE5.8、Win64 Editor Development。

## 1. 目标

Phase 45 把 Phase 44 的手动“编辑 -> Build And Bind -> 事务 reload”推进为稳定的高频迭代循环。

P45.1 的成功标准：

1. 只监听项目用户工作区 `Scripts/AvidScript`；
2. 只把 C# 源码、项目与 profile 相关文件变更视为构建输入；
3. 连续保存经过 debounce 后最多启动一次构建；
4. 构建期间的新变更只形成一个 trailing build，不并发启动第二条流水线；
5. 启用时固定目标 Actor，不受之后 Editor selection 改变影响；
6. build 或 reload 失败时旧 runtime 继续 Tick；
7. watcher、ticker 与目标对象在模块关闭时完整释放；
8. 手动 Build And Bind 始终可用，自动模式不是启动 Editor 的强制副作用。

## 2. 方案比较

### 方案 A：分层协调器，复用现有同步构建流水线

使用 UE `DirectoryWatcher` 收集文件事件；纯 C++ coordinator 负责过滤、防抖、single-flight 与 trailing build；Editor service 固定弱引用目标 Actor，并复用 Workspace、Profile、Build 和 ComponentBinding service。

优点是改动集中、行为可验证，不复制编译或 reload 逻辑。缺点是 P45.1 的外部 PowerShell 构建仍会短暂阻塞 Editor 主线程。

### 方案 B：把 watcher 和状态直接写入 Editor module

代码量最少，但菜单、文件系统、时间状态、构建、Actor 绑定和生命周期会重新耦合到一个 owner，难以测试，也会延续用户已经指出的“大文件承担全部职责”问题。

### 方案 C：立即重写为全异步双阶段构建

使用 `FMonitoredProcess` 异步执行 bootstrap/final 两个 PowerShell 进程，并在中间完成 runtime binding slice。体验最好，但当前 BuildService 还把 reflection package 生成、进程调用、report 解析和 publication 编排放在一个同步入口；直接放入线程池会触碰非线程安全的 UE reflection/UObject 路径。

### 决策

P45.1 采用方案 A，先形成可用且不会破坏旧 runtime 的自动闭环。P45.2 在保持 coordinator 与 watcher API 不变的前提下，把 build executor 替换为 `FMonitoredProcess` 驱动的异步双阶段 job；不在 P45.1 预埋另一套编译实现。

## 3. 模块边界

### 3.1 Coordinator

`FAvidScriptEditorCSharpLiveReloadCoordinator` 是不依赖 UObject、DirectoryWatcher、菜单和具体编译器的状态机。

职责：

- 验证 workspace root 与 debounce 配置；
- 过滤 workspace 外路径、目录事件与不相关扩展名；
- 合并同一批和连续批次的路径；
- 分配单调递增 request id；
- 保证任意时刻最多一个 active build；
- 记录构建期间的新变更，并在完成后安排一个 trailing build；
- 统计 observed、ignored、coalesced、started、succeeded、failed 和 canceled。

Coordinator 只由 Editor 主线程驱动。它不读取文件内容，也不执行构建。

### 3.2 Editor Live Reload Service

`FAvidScriptEditorCSharpLiveReloadService` 负责 UE Editor 适配：

- 注册与注销 `IDirectoryWatcher` callback；
- callback 只复制原始 change data 到 MPSC queue，不访问 Actor 或执行构建；
- Core ticker 在主线程排空 queue 并驱动 coordinator；
- 通过 `TWeakObjectPtr<AActor>` 固定启用时的目标 Actor；
- 加载 profile，调用既有 `FAvidScriptEditorCSharpBuildService`；
- 成功后调用 `FAvidScriptEditorComponentBindingService::ApplyCSharpReportToActor`；
- 输出稳定的 result、diagnostic category、last request 与统计。

Service 不生成 Roslyn 代码、不解析 reflection descriptor、不操作 WAMR。它只编排现有 ownership boundary。

### 3.3 Editor Module

`FAvidScriptEditorModule` 只拥有 service 生命周期与菜单命令：

- `Start Project C# Auto Live Reload`：先执行一次正式 Workspace Build And Bind；成功后以本次绑定 Actor 为固定 target 启动 watcher；
- `Stop Project C# Auto Live Reload`：取消 pending 请求并注销 watcher/ticker；
- 模块 `ShutdownModule` 总是先停止 live reload，再释放菜单与其他 service。

菜单 handler 不实现文件过滤、debounce、构建或 binding。

## 4. 状态机

```text
Stopped
  | Start
  v
Watching -- relevant change --> Debouncing
   ^                              | deadline reached
   | no pending                   v
   +--------------------------- Building
                                  | change while active
                                  +--> pending trailing build
```

状态转换规则：

1. `Start` 清空上一轮统计外的瞬态状态，建立新的 session generation。
2. 每次 relevant change 把 deadline 更新为 `Now + DebounceSeconds`。
3. `Poll` 只有在没有 active request 且 deadline 到期时返回 build request。
4. active build 期间的任意数量变更只保留一个 pending generation。
5. `Complete` 只接受当前 request id；过期 completion 不得覆盖新 session。
6. `Stop` 使当前 generation 失效并清空 pending。P45.1 可取消尚未启动的构建；P45.2 才会终止已经启动的外部进程树。

## 5. 文件过滤

默认相关扩展名：

- `.cs`
- `.csproj`
- `.props`
- `.targets`
- `.json`

路径必须在 normalized workspace root 内。`Intermediate` 与 `Saved` 不在监听根目录，因此 generated facade、report、manifest、WASM 和 semantic cache 不会反向触发构建。

`FCA_Added`、`FCA_Modified`、`FCA_Removed` 与 `FCA_RescanRequired` 都形成输入失效；目录变化与其他扩展名忽略。默认 debounce 为 350ms。

## 6. Target 与事务边界

启用自动模式时，先执行一次正式 Build And Bind，并从成功结果中的 `UAvidScriptComponent` 取得 owner Actor。后续重建使用这个弱引用，不读取当前 selection。

成功构建后，BindingService 对同一个 Component 执行 Phase 44 的事务 reload：

- 成功时提交新 runtime 与 manifest path；
- manifest 或候选 lifecycle 失败时恢复旧 path；
- 旧 module、Tick 与 gameplay delegates 保持有效；
- 失败不得因为自动模式而额外 dirty 原本干净的 Actor package。

如果 target 已销毁，service 返回 `live_reload_target_unavailable` 并停止继续构建，避免把结果误绑定到新 selection。

## 7. 错误与诊断

稳定类别至少包括：

| Category | 含义 |
| --- | --- |
| `live_reload_workspace_invalid` | workspace root 不存在或越界 |
| `live_reload_watcher_unavailable` | DirectoryWatcher module 或平台 watcher 不可用 |
| `live_reload_watch_registration_failed` | callback 注册失败 |
| `live_reload_target_unavailable` | 固定 Actor 已销毁或无效 |
| `live_reload_profile_failed` | profile 无法加载 |
| `live_reload_build_failed` | 正式 C# pipeline 失败 |
| `live_reload_binding_failed` | report 应用或事务 reload 被拒绝 |
| `live_reload_stopped` | 用户或模块生命周期停止 |

失败只更新 service result 与日志，不删除旧 runtime，不自动重试同一输入。下一次文件变更可以发起新 request。

## 8. 测试策略

测试覆盖与风险对应，不为私有 getter 堆叠无意义断言：

1. coordinator：过滤、350ms debounce、连续保存合并；
2. coordinator：active build 期间变更只形成一个 trailing request；
3. coordinator：Stop/session generation 使旧 completion 失效；
4. service：watch register/unregister 与 callback queue 生命周期；
5. service：selection 改变后仍绑定固定 Actor；
6. service：build 失败不调用 binding；
7. service：reload 拒绝后旧 Component 继续 Tick；
8. module：Start/Stop command ownership与 shutdown 清理；
9. 最终运行增量 UBT、focused filters、architecture gate 与完整 `AvidScript` automation。

## 9. P45.2 延伸

P45.2 将增加独立 async build job：

1. 主线程准备 reflection authorization 与 immutable build plan；
2. `FMonitoredProcess` 执行 bootstrap，支持输出采集与进程树取消；
3. 主线程验证 report 并发布最小 runtime binding slice；
4. `FMonitoredProcess` 执行 prepared final build；
5. completion 回到 coordinator，只有最新 generation 可以 bind/reload。

该替换不改变 watcher、target 或 transaction API，避免 P45.1 成为一次性实现。
