# P45.4 C# 显式状态契约与字段演进架构

## 1. 阶段目标

P45.4 在 P45.3 的宿主槽位迁移基础上增加面向脚本作者的声明式状态契约，使 C# 游戏脚本能够明确控制哪些字段跨热重载保留，并在字段重命名后继续恢复旧状态。

本阶段采用渐进兼容策略：既有未标注脚本继续使用 P45.3 的安全字段隐式迁移；新项目可以在脚本类型上启用严格模式，只迁移显式标有 `[AvidPersist]` 的字段。候选实例仍必须在迁移和 `BeginPlay` 全部成功后才能替换旧实例，任何契约、读取、映射或写入失败都保留旧 runtime。

## 2. C# 作者 API

生成的 C# facade 提供以下契约类型：

```csharp
namespace AvidScript;

public enum AvidStateMode
{
    Compatible = 0,
    Explicit = 1,
}

[AttributeUsage(AttributeTargets.Class, Inherited = false, AllowMultiple = false)]
public sealed class AvidStateContractAttribute : Attribute
{
    public AvidStateContractAttribute(AvidStateMode mode = AvidStateMode.Compatible)
    {
        Mode = mode;
    }

    public AvidStateMode Mode { get; }
    public int Version { get; set; } = 1;
}

[AttributeUsage(AttributeTargets.Field, Inherited = false, AllowMultiple = false)]
public sealed class AvidPersistAttribute : Attribute
{
}

[AttributeUsage(AttributeTargets.Field, Inherited = false, AllowMultiple = false)]
public sealed class AvidTransientAttribute : Attribute
{
}

[AttributeUsage(AttributeTargets.Field, Inherited = false, AllowMultiple = true)]
public sealed class AvidStateAliasAttribute : Attribute
{
    public AvidStateAliasAttribute(string formerName)
    {
        FormerName = formerName;
    }

    public string FormerName { get; }
}
```

推荐的新项目写法：

```csharp
[AvidStateContract(AvidStateMode.Explicit, Version = 2)]
public static class GameplayScript
{
    [AvidPersist]
    [AvidStateAlias("TotalRotationDegrees")]
    private static float AccumulatedRotationDegrees;

    [AvidTransient]
    private static int DebugFrameCount;
}
```

## 3. 状态选择规则

### Compatible

- 未标注的安全、可变、静态字段继续迁移。
- `[AvidPersist]` 显式确认字段参与迁移。
- `[AvidTransient]` 排除字段。
- 没有 `[AvidStateContract]` 的旧脚本等价于 `Compatible, Version = 1`。

### Explicit

- 只有 `[AvidPersist]` 字段参与迁移。
- 未标注字段和 `[AvidTransient]` 字段不进入 schema。
- `[AvidStateAlias]` 只能用于实际参与迁移的字段。

### 通用限制

- `const`、`readonly`、实例字段以及不属于导出脚本 owner 的字段不迁移。
- `[AvidPersist]` 与 `[AvidTransient]` 不能同时存在。
- 显式持久化但无法表示为安全 Guest 值槽位的字段是构建错误，不能静默跳过。
- alias 必须是合法的 C# 标识符，不能等于当前字段名，不能重复，也不能指向另一个当前字段或另一个 alias。
- contract version 必须位于 `1..65535`；候选版本低于旧版本时拒绝迁移。

## 4. Semantic 契约

`AvidScript.CSharpSemantic` 新增专用状态投影，而不是把 Attribute 源码文本交给后续阶段：

```text
SemanticStateContract
  owner_type_id
  policy
  version
  fields[]
    symbol_id
    disposition = implicit | persist | transient
    aliases[]
```

`SemanticSymbol` 同时记录字段的 `is_const` 与 `is_readonly`。`SemanticStateContractProjector` 通过 Roslyn symbol identity 识别 facade 中定义的 AvidScript 属性，读取编译期常量参数，生成确定性排序的结构化模型，并产生 `ASSTATE` 诊断。Guest schema projector 只消费该模型、Semantic symbol 和 Guest IR，不重新解析 C# 源码。

Semantic artifact 升级为 schema 6、semantic version 1.6。缓存 key 已包含工具链指纹和 Semantic 版本，因此旧 cache 不会被误当成新契约。

## 5. State Schema v2

新编译器发布 `state_migration.schema_version = 2`：

```json
{
  "schema_version": 2,
  "strategy": "host_snapshot",
  "policy": "explicit",
  "contract_version": 2,
  "owner_type_id": "type:global::AvidScript.GameplayScript",
  "slots": [
    {
      "stable_id": "state:type:global::AvidScript.GameplayScript:AccumulatedRotationDegrees",
      "aliases": [
        "state:type:global::AvidScript.GameplayScript:TotalRotationDegrees"
      ],
      "type_fingerprint": "<sha256>",
      "offset": 16,
      "size": 4,
      "alignment": 4
    }
  ]
}
```

alias 在工具链中展开为完整 stable ID，UE runtime 不需要理解 C# 字段命名。slot 和 alias 分别按 ordinal 排序；serializer、build report 和 manifest 保持确定性。

Runtime loader 同时接受 schema v1 和 v2：

- v1 视为 `policy = compatible`、`contract_version = 1`、无 alias。
- v2 强制校验 policy、version、alias 顺序、唯一性和全局无歧义。
- 新编译器只生成 v2；v1 仅作为旧产物热重载兼容输入。

## 6. 迁移匹配算法

候选 schema 预先建立两个只读索引：

1. `stable_id -> candidate slot`。
2. `alias stable_id -> candidate slot`。

遍历旧 slot 时：

1. exact stable ID 命中优先。
2. exact 未命中时再查询 alias。
3. 命中后仍要求 type fingerprint 与 size 完全一致。
4. 未命中视为删除字段并跳过。
5. 候选未被命中的 slot 视为新增字段并保留初始化值。

所有旧值先读取到宿主 pending write 集合，完成全部匹配与读取后才写入候选实例。alias 不允许触发隐式数值转换、结构重排或任意脚本代码；因此 runtime 的事务边界和性能上界与 P45.3 一致。

## 7. 分层职责

### Editor facade

- 独立 `CSharpStateContractRenderer` 负责生成 Attribute 与 enum 定义。
- 反射 binding renderer 只组合语言契约片段和 UE API facade，避免把状态规则散落到函数绑定逻辑。

### Semantic

- `SemanticStateContractProjector` 识别并验证声明。
- `SemanticDocument` 保存结构化状态契约。
- 无效声明在 Guest lowering 前以稳定 `ASSTATE` code 失败。

### CSharpGuest

- `CSharpGuestStateContractResolver` 根据 policy 选择字段。
- `CSharpGuestStateSchemaProjector` 负责安全类型指纹、Guest layout 和 v2 schema。
- PowerShell 只转发、校验版本和发布结构化产物，不复制 Attribute 规则。

### Runtime

- manifest loader 校验 v1/v2 和 alias 全局唯一性。
- `StateMigration` 服务拥有 exact/alias 匹配、版本门禁、快照与写入。
- `RuntimeSession` 仍只负责编排候选生命周期。

## 8. 错误与可观测性

构建阶段使用稳定诊断：

- `ASSTATE1001`：互斥 Attribute 或重复契约。
- `ASSTATE1002`：非法、重复或冲突 alias。
- `ASSTATE1003`：contract version 越界。
- `ASSTATE1004`：alias 用于不参与迁移的字段。
- `ASSTATE1005`：显式持久化字段不是安全 Guest 值槽位。

Runtime 使用结构化 category：

- `state_migration_version_regression`。
- `state_migration_incompatible`。
- `state_migration_read_failed`。
- `state_migration_write_failed`。

Reload result 增加 alias 命中槽位数。日志仍只记录计数、stable ID 和 category，不打印字段值。

## 9. 验证策略

- Semantic 测试覆盖兼容/严格模式、字段 disposition、修饰符与每个非法契约诊断。
- Guest 测试覆盖确定性 v2 schema、alias 展开、显式 unsafe 字段失败和未标注兼容行为。
- Manifest 测试覆盖 v1/v2、alias 排序、重复、当前 ID 冲突和版本范围。
- StateMigration 测试覆盖 exact 优先、alias rename、版本回退、类型不兼容和旧 runtime 保活。
- 真实 C# workspace 自动热重载测试把 `TotalRotationDegrees` 重命名为 `AccumulatedRotationDegrees`，证明新代码行为与旧状态同时生效。
- 完成后运行 .NET、PowerShell、架构门禁、UE5.8 增量编译、聚焦自动化和完整 `AvidScript` automation。

## 10. 非目标与后续

P45.4 不实现用户定义 Save/Load 回调、隐式数值转换、容器序列化、UObject 句柄恢复、协程或 Timer 队列迁移。后续版本转换应通过显式 converter ABI 或版本化 Save/Load hook 完成，不能在宿主按类型名猜测转换。

P45.4 完成后，C# 热重载将具备可声明、可审计、可重命名演进且向旧脚本兼容的基础状态契约。
