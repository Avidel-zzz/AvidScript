# P45.1 C# 自动热重载

## 阶段结论

P45.1 已在 UE5.8 源码版的 Win64 Editor 上闭合第一版项目级 C# 自动热重载流程：

1. 在 Editor 中选择一个 Actor，显式启动 Project C# Auto Live Reload。
2. 插件创建或刷新项目 C# 工作区，并执行正式的 Workspace -> Build -> Bind。
3. 初始绑定成功后，监听工作区内的 C# 与工程配置文件。
4. 文件变化经过 350ms debounce 后，重新执行 Profile -> Build -> Bind。
5. 运行中的 `UAvidScriptComponent` 通过事务 reload 切换到新 WASM。
6. 编译、绑定或候选 runtime 失败时，已提交的旧 runtime 保持可用。

这已经能够支持在 C# 中编写 Actor 的 `BeginPlay`、`Tick` 与现有 gameplay event 逻辑，并在 PC Editor 中形成“编辑源码、保存、自动编译、运行中生效”的闭环。

## 快速使用

### 1. 启动自动热重载

1. 打开关卡并选择需要承载脚本的 Actor。
2. 执行 `Tools > AvidScript > Start Project C# Auto Live Reload`。
3. 等待 Output Log 出现启动成功日志。

Start 命令会先完成一次真实构建和绑定。只有初始 Build 与 Bind 都成功后，DirectoryWatcher 才会开始监听；失败不会留下半启动 watcher。

默认项目工作区位于：

- `<Project>/Scripts/AvidScript/GameplayScript.cs`
- `<Project>/Scripts/AvidScript/AvidScript.Gameplay.csproj`
- `<Project>/Scripts/AvidScript/default.csharp-profile.json`
- `<Project>/Scripts/AvidScript/global.json`

生成的 IDE facade 位于 `<Project>/Intermediate/AvidScript/CSharpWorkspace`，构建产物位于项目 `Saved` 目录。创建或刷新工作区时，不会覆盖用户已经修改的 C# 源码和工程文件，除非调用方明确要求覆盖。

### 2. 编写游戏逻辑

`GameplayScript.cs` 可以直接使用生成的 UE facade。下面的脚本在 BeginPlay 设置缩放，并在 Tick 中旋转当前绑定 Actor：

```csharp
using System.Runtime.InteropServices;

namespace AvidScript;

public static class GameplayScript
{
    private const float RotationSpeedDegreesPerSecond = 180.0f;

    public static int Main() => 0;

    [UnmanagedCallersOnly(EntryPoint = "avid_on_begin_play")]
    public static void BeginPlay()
    {
        UE.Self.SetActorScale3D(new FVector(1.0f, 1.0f, 1.0f));
    }

    [UnmanagedCallersOnly(EntryPoint = "avid_on_tick")]
    public static void Tick(float deltaSeconds)
    {
        FRotator rotation = UE.Self.GetActorRotation();
        UE.Self.SetActorRotation(
            new FRotator(
                rotation.Pitch,
                rotation.Yaw + RotationSpeedDegreesPerSecond * deltaSeconds,
                rotation.Roll),
            false);
    }
}
```

`UE.Self` 始终代表启动命令成功绑定的固定 Actor。`FVector`、`FRotator` 和 Actor 方法来自生成绑定，不需要为每个 API 手写一层桥接。

保存源码后，监听器会自动触发构建。当前会监听这些扩展名：

- `.cs`
- `.csproj`
- `.props`
- `.targets`
- `.json`

### 3. 停止自动热重载

执行 `Tools > AvidScript > Stop Project C# Auto Live Reload`。Stop 是幂等操作，可以重复执行。Editor 模块卸载时也会先停止 watcher 和 ticker，再释放菜单与模块资源。

## 调度语义

### 固定目标

Start 成功后，service 保存 `BindingResult.Component->GetOwner()` 得到的 Actor。之后即使用户选择了另一个 Actor，自动 reload 仍只作用于最初绑定的对象，不会重新读取 Editor selection。

同一 Editor 模块当前只维护一个活动的项目级自动 reload session。重复 Start 会返回 `live_reload_already_running`，不会重复构建或注册第二个 watcher。需要切换目标时，先 Stop，再选择新 Actor 并 Start。

### Debounce 与 trailing build

文件变化由 DirectoryWatcher callback 写入线程安全 MPSC 队列，callback 本身不执行构建。Editor game thread ticker 负责排空队列和运行 coordinator。

- 默认 debounce 为 350ms。
- 同一时间窗口内的多次变化合并为一次构建。
- 构建期间收到的新变化不会并行启动第二个构建。
- 当前构建完成后，新变化会形成一次 trailing build。

这避免了保存 C# 文件时由 IDE 产生的连续文件事件造成重复编译，也保证同一 session 内只有一个 Build/Bind 事务在执行。

### 目标销毁

固定 Actor 在构建前或构建期间被销毁时，service 会返回 `live_reload_target_unavailable` 并停止当前 watcher。选择新的 Actor 后需要重新执行 Start。

## 失败与事务保证

自动 reload 的错误结果同时保留阶段 category 和底层 cause category，用于区分 Profile、Build、Binding 与 runtime reload 失败。

- Profile 或 C# Build 失败：不会进入 Bind，旧 runtime 不变。
- Bind 或候选 runtime 失败：事务拒绝候选 manifest，恢复旧配置路径，旧 runtime 继续 Tick。
- watcher 注册失败：Start 失败且不进入 running 状态。
- Stop 或模块卸载：拒绝新的 callback，注销 watcher，移除 ticker，并让旧 generation completion 失效。

当前事务保证的是 runtime 激活与配置路径的一致性。候选 BeginPlay 已经对 UE 对象产生的 host-side 写入还没有通用回滚机制，因此脚本初始化仍应避免在可能失败的步骤前产生不可逆副作用。

## P45.1 已验证场景

- 运行中的 Actor 完成初始真实 C# Build/Bind，并加载 `csharp_project_gameplay`。
- 把 Tick 旋转速度从 90 改为 180 后，连续两次文件变化只触发一次真实构建。
- 事务 reload 成功后，Actor 的 Tick 行为使用新旋转速度。
- 随后写入错误 C# 源码，自动构建失败，已提交 runtime manifest 不变，旧 Tick 继续执行。
- selection 漂移后 reload 仍作用于初始 Actor。
- 重复 Start、重复 Stop、Actor 销毁、构建中 Stop、watcher callback 生命周期均有回归覆盖。
- runtime 候选 manifest 或 BeginPlay 被拒绝后，旧 runtime 继续 Tick 的事务行为由 Component、ComponentBinding 与 RuntimeSession 回归覆盖。

## 当前限制

P45.1 是可用的 PC Editor 同步版本，还不是最终的跨平台生产方案：

- Build 与 Bind 当前在 Editor game thread 同步执行，保存源码时可能短暂阻塞 Editor。
- 当前只验证 Win64 Editor；Cook、Shipping、Android 与 iOS 尚未完成验收。
- 当前没有 guest state migration；成功 reload 会创建新的 runtime 状态并重新执行候选生命周期。
- 当前没有候选 host-side 写入的通用 rollback。
- 当前没有构建进度 UI、取消按钮或异步进程诊断面板。
- 当前一个 Editor module 只维护一个固定 Actor session。

## P45.2 目标

下一阶段优先把同步 Build 从 game thread 移到可管理的异步外部进程任务，并保持现有 coordinator、executor、binding transaction 与固定目标边界不变。P45.2 需要补齐：

1. 异步 job 状态与主线程 completion commit。
2. Stop、模块卸载和新 generation 对旧 job 的取消或结果丢弃。
3. 构建进度、耗时、stdout/stderr 与结构化错误展示。
4. Editor 无长时间卡顿的真实保存到 reload 验收。
5. 为后续多目标 session、Cook/Shipping 和移动端适配保留扩展点。
