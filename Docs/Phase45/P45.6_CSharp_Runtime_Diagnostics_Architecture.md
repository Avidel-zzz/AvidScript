# P45.6 C# Runtime 诊断与函数级调用栈架构

> 状态：设计已批准，等待实施
>
> 平台：源码版 UE5.8，Win64 Editor Development 先行
>
> 主线：C# -> Semantic -> Guest IR -> WASM -> WAMR

## 1. 背景

P45.5 已让候选 `BeginPlay` 的已覆盖宿主写入具备事务语义，但 C# 脚本发生 WASM trap 时，用户目前只能看到 `trap`、export 名和 WAMR 异常文本，无法直接判断是哪个 C# 方法出错。

成熟脚本框架必须把运行时故障返回作者源码，同时不能为了调试能力给正常 `Tick` 增加持续 host crossing、字符串查找或逐语句日志。P45.6 建立低开销的函数级 C# 调用栈闭环，并保留 WAMR 原始函数 offset，作为后续指令级 sequence point 的兼容基础。

## 2. 目标与非目标

### 2.1 目标

- WAMR trap 后在 VM 私有层提取结构化 WASM frame，而不是把上游文本泄漏为公共协议。
- 构建阶段从正式 Semantic 与 Guest IR 生成确定性的 C# debug map。
- manifest 使用 SHA-256 绑定 debug map、Guest IR 与源码 provenance，防止错配诊断。
- Runtime 把 WASM function index 映射为项目相对 C# 文件、方法签名和声明 span。
- `BeginPlay`、`Tick`、Timer、Event、Gameplay Event 以及热重载候选失败使用同一诊断模型。
- 没有 debug map、debug map 损坏或 WAMR 无 frame 时仍保留原始 trap，诊断增强不得掩盖根因。
- 正常生命周期调用不新增 host import，不解析 JSON，不遍历调用栈。

### 2.2 非目标

- P45.6 v1 不承诺精确到表达式或 WASM 指令的 C# 行号。
- 不实现断点、单步、变量查看、远程调试协议或 IDE debug adapter。
- 不在每条 C# 语句前写入 source-location marker。
- 不改变 C# 语言子集、热重载事务、状态迁移或 binding authorization 规则。
- 不在本阶段完成 Cook/Shipping strip policy 和移动端调用栈验证。

## 3. 方案比较

### 3.1 方案 A：函数级 sidecar debug map，推荐

`AvidScript.CSharpGuest` 根据 Semantic callable、Guest function 顺序和 import 数量生成 debug map。WAMR 仅在 trap 路径提供 function index/offset，Runtime 负责源码映射。

优点：正常路径零额外 crossing；职责清晰；可验证 provenance；无需依赖 fast interpreter 内部 offset 与原始 WASM byte offset完全一致。

代价：v1 只能定位到方法声明 span，表达式级定位留给后续版本。

### 3.2 方案 B：逐 sequence point 写入全局位置

WASM 在潜在 trap 或每条语句前更新 source-location marker，trap 后由 VM 读取。

优点：可以更快得到精确语句位置。

代价：改变生成代码与热路径；需要定义 marker 内存所有权、嵌套调用恢复和优化边界；当前不适合作为性能优先的默认方案。

### 3.3 方案 C：直接暴露 WAMR 文本调用栈

Runtime 原样保存 `wasm_runtime_dump_call_stack_to_buf` 输出。

优点：实现最少。

代价：公共合同绑定上游文本格式，无法验证源码 provenance，也无法提供稳定的 C# 方法身份。该方案仅可作为内部采集实现，不能成为产品接口。

## 4. 架构决策

采用方案 A。数据流为：

```text
SemanticDocument + GuestModule
  -> CSharpGuest DebugMapProjector
  -> <artifact>.csharp.debug.json
  -> Build manifest debug_map + SHA-256
  -> Runtime reload validation
  -> immutable RuntimeDebugMap

WAMR trap
  -> AvidScriptVM private call-stack capture
  -> FAvidScriptVmError.StackFrames
  -> RuntimeDebugMap function-index lookup
  -> FAvidScriptWasmDiagnosticFrame
  -> Component / Editor structured presentation
```

模块职责保持：

- `AvidScript.CSharpGuest`：知道 Semantic symbol 与 Guest function 的对应关系，生成语言侧 debug map。
- `AvidScriptVM`：只知道 WASM function index、raw offset 和可选 raw function token，不知道 C#、源码路径或 UE。
- `AvidScriptRuntime`：验证并持有 debug map，把通用 VM frame 映射为脚本诊断。
- `AvidScriptEditor`：显示结构化诊断；不解析 WAMR 文本，不重新读取 Semantic artifact。

## 5. Debug Map 合同

debug map schema v1 至少包含：

```json
{
  "schema_version": 1,
  "debug_version": "1.0",
  "module_id": "project_gameplay",
  "source": {
    "id": "Scripts/AvidScript/GameplayScript.cs",
    "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
  },
  "provenance": {
    "frontend_sha256": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb",
    "semantic_sha256": "cccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccc",
    "guest_ir_sha256": "dddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddd"
  },
  "functions": [
    {
      "wasm_function_index": 7,
      "guest_function_id": "function:symbol:method:AvidScript.GameplayScript.Tick(float)",
      "method_symbol_id": "symbol:method:AvidScript.GameplayScript.Tick(float)",
      "display_name": "GameplayScript.Tick(float)",
      "span": {
        "line": 18,
        "column": 5,
        "end_line": 24,
        "end_column": 6
      }
    }
  ]
}
```

约束：

- `source.id` 必须是规范化项目相对路径，不允许盘符、UNC、绝对路径或 `..` 逃逸。
- function index 等于 `GuestModule.Imports.Count + function ordinal`，按 WASM 规范的 index space 计算。
- function index、Guest function ID 与 method symbol ID 必须唯一。
- debug artifact 原样保存 `SemanticSpanFactory` 的 Roslyn 零基行列和 end-exclusive span；Runtime 映射为公开诊断 frame 时才转换成一基行列，Editor 不重复加一。
- `guest_ir_sha256` 必须来自本次实际发布的 canonical Guest IR bytes。
- 数组按 function index 排序，JSON 属性顺序固定，重复构建必须字节确定。

## 6. Manifest 与加载

现有 manifest schema v1 增加可选 `debug_map` 对象：

```json
"debug_map": {
  "file": "project_gameplay.csharp.debug.json",
  "sha256": "eeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeee",
  "schema_version": 1
}
```

这是向后兼容的可选扩展：旧 manifest 继续加载并返回 raw trap；新 C# 正式构建必须发布该字段。Runtime 验证：

1. 路径必须由 manifest 目录安全解析；
2. 文件 SHA-256 必须匹配；
3. schema、module id、source hash、frontend/semantic/Guest IR provenance 必须与 manifest 一致；
4. function index 必须唯一且在已观察到的 WASM function index 范围内；
5. 任一 debug map 验证失败时拒绝新 manifest，错误类别使用稳定的 `debug_map_*` 前缀。

debug map 是 C# 构建产物的一部分，不进入 binding package，也不影响 runtime import slice。

## 7. WAMR Frame 采集

Win64 WAMR 静态库启用 `WAMR_BUILD_DUMP_CALL_STACK=1`。`AvidScriptVM` 在 `wasm_runtime_call_wasm` 返回失败后、exec env 已停止执行时：

1. 先读取原始 exception；
2. 调用 `wasm_runtime_get_call_stack_buf_size`；
3. 使用有上限的临时 UTF-8 buffer 调用 `wasm_runtime_dump_call_stack_to_buf`；
4. 私有 parser 接受上游的 `$f<index>` 与十六进制 offset 行；
5. 输出 `FAvidScriptVmStackFrame { FunctionIndex, FunctionOffset, RawFunctionToken }`；
6. 采集失败只留下空 frames，不覆盖原 exception。

buffer 大小和 frame 数必须有硬上限，畸形或超长行 fail closed。公共 VM header 不包含 WAMR 类型。

## 8. Runtime 诊断模型

`FAvidScriptVmError` 增加通用 `StackFrames`。Runtime 映射后在现有 smoke/reload result 中公开只读诊断 frame：

- `FunctionIndex`
- `FunctionOffset`
- `FunctionName`
- `SourceFile`
- `Line` / `Column` / `EndLine` / `EndColumn`
- `bSourceMapped`

公开 Runtime frame 的行列是一基值，适合日志、编辑器跳转和 Blueprint/C++ 消费；debug map artifact 内部仍是零基 Roslyn span。

首帧是直接故障位置，其后是调用者。无法映射的 frame 仍保留 function index 与 offset。Editor 展示示例：

```text
AvidScript trap: Exception: unreachable
at GameplayScript.Tick(float) (Scripts/AvidScript/GameplayScript.cs:18:5)
wasm frame: function=7 offset=0x002a
```

## 9. 性能与内存

- debug map 只在 module load/reload 时解析一次，随后使用按 function index 构建的不可变查找表。
- trap stack 只在失败路径分配；正常 `BeginPlay`、`Tick`、Timer 与 Event 不采集 frame。
- 不新增 WASM import，不在生命周期热路径做字符串查找。
- debug map 大小与函数数线性增长；加载时设置 function/frame/文件大小上限。
- Shipping 后续可以通过 artifact policy 去除源码路径和 debug map，Runtime 自动退化为 raw trap。

## 10. 错误与兼容策略

- 旧 WAMR lib 未启用 stack API：构建或 architecture gate 直接拒绝，不能静默宣称具备调用栈。
- 旧 manifest 无 debug map：允许加载，`bSourceMapped=false`。
- 新 C# manifest 声明 debug map 但文件缺失、hash 错误或 provenance 错配：manifest load fail closed。
- WAMR trap 无 frame：保留原异常类别、export 与 next action。
- debug map 不能读取工作区外源码；它只保存项目相对 identity，不负责打开文件。
- P45.6 不依赖 WAMR fast interpreter offset 的源码精确性；offset 仅作为 raw evidence 保留。

## 11. 验证策略

聚焦验证只覆盖真实边界：

- CSharpGuest：真实 Semantic + Guest IR 生成稳定 debug map；function index 包含 import 偏移；重复/错配被拒绝。
- Build contract：debug map 与 Guest IR 原子发布；manifest hash/provenance 正确；缺失或篡改失败关闭。
- VM：真实 WAMR trap 返回至少一个结构化 frame；无 trap 的 Tick 不采集 stack。
- Runtime：有效 map 映射函数，旧 manifest raw fallback，hash/source/module/Guest IR 错配拒绝。
- Editor/Component：真实生成 C# artifact 在 `BeginPlay` 或 `Tick` trap 后显示项目相对源码与方法，reload 失败时旧 runtime 继续 Tick。
- 性能：健康 Tick 路径的 host import 数和调用栈采集次数保持 0 增量。
- 收尾：固定 .NET、PowerShell parser/contracts、architecture gate、UE5.8 增量 build、聚焦 automation 与完整 `AvidScript` automation。

## 12. 后续扩展

P45.6 v1 稳定后，debug map schema 可向后兼容增加 sequence points。只有在验证 WAMR offset 语义或建立低开销 source marker 后，才把首帧定位从方法声明提升到表达式；不得用未经验证的 fast-interpreter offset 伪造精确行号。

P45.6 收口后进入 P46 生成式 `UPROPERTY` 与更广 UE 类型交互，让诊断能力服务于下一轮 API 面扩展。
