# Phase 45.2：异步 C# Live Reload 架构

> 状态：设计已定稿。目标平台为源码版 UE5.8、Win64 Editor Development；P45.2 不改变 guest ABI、WAMR runtime 或现有事务 reload 语义。

## 1. 阶段目标

P45.2 消除 P45.1 构建期间对 Editor 主线程的长时间阻塞，并补齐主动取消、进度与过期结果隔离。

验收标准：

1. PowerShell、Roslyn 前端、语义分析和 WASM backend 在 `FMonitoredProcess` 线程中运行；
2. Editor ticker 在构建期间持续响应，watcher 仍可接收并合并 trailing change；
3. Stop、模块关闭或固定 Actor 销毁会取消活动进程树；
4. 进程输出、当前阶段、持续时间与最终诊断可查询；
5. 只有当前 session 的最新活动 request 可以进入 Actor 事务 reload；
6. 构建、取消、report 或 binding slice 失败时旧 runtime 继续 Tick；
7. 同步手动 Build And Bind 入口继续复用同一 invocation/report contract，不产生两套编译语义。

## 2. 线程与所有权边界

### 2.1 主线程

主线程负责：

- 加载并标准化 profile；
- 生成 reflection authorization binding package；
- 检查固定 Actor 生命周期；
- 解析 bootstrap report；
- 根据 `used_imports` 发布最小 runtime binding slice；
- 验证 job/request/session generation；
- 调用 `ApplyCSharpReportToActor` 完成事务 reload；
- 更新 coordinator、service result 与菜单可见状态。

这些步骤可能访问 UE reflection、`UObject`、Editor module 或文件发布状态，禁止移入监控线程。

### 2.2 监控线程

`FMonitoredProcess` 只负责：

- 启动隐藏的 `powershell.exe`；
- 执行 bootstrap 或 final build invocation；
- 按行收集 stdout；
- 记录退出码、取消信号与运行时间；
- 在取消时终止 PowerShell 及其子进程树。

UE5.8 的 `OnOutput`、`OnCompleted` 与 `OnCanceled` delegate 从监控线程调用。delegate 只写 `TSharedPtr<..., ESPMode::ThreadSafe>` 状态并向 MPSC queue 投递事件，不访问 service、job、Actor 或其他 UObject。

## 3. 组件划分

### 3.1 Build Invocation Contract

从现有同步 invoker 中提取三段共享能力：

1. `Prepare`：创建输出目录并生成 executable、parameters、working directory；
2. `Run`：同步入口继续使用 `ExecProcess`，异步入口使用 `FMonitoredProcess`；
3. `Finalize`：根据退出码和 report 填充统一的 `FAvidScriptEditorCSharpBuildResult`。

命令行转义、report contract、semantic cache audit 与结构化错误只能有一份实现。

### 3.2 Async Process

`IAvidScriptEditorCSharpBuildProcess` 隔离 Engine 进程 API，向 job 暴露：

- `Launch(invocation)`；
- `Poll(completion, output)`；
- `Cancel(kill_tree=true)`；
- `IsRunning()`。

生产实现持有 `FMonitoredProcess`；自动化测试使用可控 fake，不启动真实进程。

### 3.3 Async Build Job

`FAvidScriptEditorCSharpAsyncBuildJob` 是单请求状态机，不拥有 Actor：

`Preparing -> BootstrapRunning -> PublishingBindingSlice -> FinalRunning -> ReadyToBind`

失败与停止终态：

`Failed / Canceled`

Job 持有 immutable request identity、标准化 build plan、bootstrap/final result 和进程适配器。`Tick` 只在主线程调用，跨线程事件通过 process adapter 的队列消费。

显式 binding package 的 profile 跳过 bootstrap 与 slice，直接进入 `FinalRunning`。自动 slicing profile 才执行完整双阶段流水线。

### 3.4 Live Reload Service

Service 将 P45.1 的同步 `ExecuteBuild` 依赖替换为 async job factory：

1. coordinator 到期后创建一个活动 job；
2. 后续 ticker 轮询 job，不阻塞；
3. 构建期间 watcher change 继续进入 coordinator 的 trailing generation；
4. job `ReadyToBind` 后先验证 request/session/target，再在主线程绑定；
5. coordinator 完成当前请求并按已有规则安排 trailing build；
6. Stop 先拒绝新 callback，再取消 job 进程树，最后使 generation 失效。

Service 同时保留同步 executor 兼容路径，直到 P45.2 的真实构建与取消回归通过；最终默认构造器只使用 async job。

## 4. 构建流水线

### 4.1 Prepare

主线程标准化 profile 与默认路径，验证 source/project/build script/package 路径。自定义源码且未显式提供 binding package 时，发布完整 EngineGameplay authorization package。

输出 immutable plan：

- normalized final config；
- authorization package path；
- 是否需要 automatic slice；
- bootstrap 临时根目录与 config；
- 最终 report、manifest、WASM 路径；
- request/session identity。

### 4.2 Bootstrap

后台执行 bootstrap invocation。结束后主线程使用共享 finalizer 校验 process result 与完整 report contract，再验证 `binding_package.used_imports` provenance。

bootstrap 临时目录归 job 所有，在任意终态析构或显式 cleanup；不得删除 committed final artifacts。

### 4.3 Binding Slice

若 `used_imports` 为空，final build 设置 `OmitRuntimeBindingPackage`。否则主线程调用既有 slice service，从 authorization descriptor 发布 content-addressed 最小 runtime package。

该步骤失败直接进入 `Failed`，旧 runtime 不受影响。

### 4.4 Final

后台执行 prepared final invocation。共享 finalizer 验证 report、manifest、WASM 与 semantic cache metadata，并聚合 bootstrap/final invocation counts。

成功只进入 `ReadyToBind`，不直接操作 Actor。

### 4.5 Bind Commit

Service 在主线程执行三重门禁：

1. 活动 job identity 仍匹配；
2. coordinator 仍接受当前 session/request/change generation；
3. 固定 Actor 仍有效。

通过后才调用事务 binding；任一门禁失败均丢弃 completion，禁止覆盖新 session 或重新读取 selection。

## 5. 取消语义

- 用户 Stop：`Cancel(true)`，终止 PowerShell 与 dotnet 子进程树；
- 模块关闭：与 Stop 相同，并在销毁 service 前排空 completion；
- Actor 销毁：取消活动 job，返回 `live_reload_target_unavailable`；
- 新文件变化：不抢占当前构建，只形成一个 trailing build；
- launch 失败：同步进入 `Failed`，不产生伪运行状态；
- canceled delegate：只写 thread-safe completion，主线程归类为 `live_reload_build_canceled`。

Job 析构不等待长时间进程自然退出；先请求 kill tree，再释放由 `FMonitoredProcess` 管理的监控线程。取消后的 report 或 artifact 永远不能进入 bind commit。

## 6. 进度与诊断

公开进度至少包含：

| 字段 | 含义 |
| --- | --- |
| `Stage` | Preparing、Bootstrap、BindingSlice、Final、Binding、Completed |
| `RequestId` | 当前 coordinator 请求 |
| `ElapsedSeconds` | job 已运行时间 |
| `LatestOutputLine` | 最近一行工具输出 |
| `OutputLineCount` | 已采集输出行数 |
| `bCancelRequested` | 是否已请求取消 |

稳定错误类别增加：

- `live_reload_build_launch_failed`
- `live_reload_build_canceled`
- `live_reload_bootstrap_failed`
- `live_reload_binding_slice_failed`
- `live_reload_final_build_failed`
- `live_reload_stale_completion`

底层 report category 继续写入 cause category，避免丢失 C# 编译器与 semantic diagnostic。

## 7. 验证顺序

1. invocation prepare/finalize 与现有同步行为等价；
2. fake process 覆盖 launch、output、success、failure、cancel；
3. job 覆盖 direct final 与 bootstrap/slice/final 状态转换；
4. service 覆盖非阻塞、trailing、Stop cancel、Actor destroy 与 stale completion；
5. 真实 C# 自动重载证明 ticker 在后台构建时继续运行；
6. 真实取消证明 PowerShell/dotnet 进程树退出且旧 runtime 继续 Tick；
7. 增量 UE5.8 UBT、focused automation、architecture gate 与完整 AvidScript automation。

## 8. 非目标

P45.2 不实现 guest state migration、host-write rollback、源码断点映射、Cook/Shipping 或移动端运行时。这些能力继续在后续 Phase 单独建立 contract，不能因异步构建完成而提前宣称成熟闭环全部完成。
