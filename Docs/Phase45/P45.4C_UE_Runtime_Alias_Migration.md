# P45.4C UE Runtime Alias Migration

## 功能

- `FAvidScriptWasmStateSlot` 增加 `Aliases`，状态迁移 manifest 保留实际 `SchemaVersion`、`Policy` 与 `ContractVersion`。
- UE loader 同时接受 state migration schema v1 和 v2。v1 归一化为 `compatible`、版本 `1`、无 alias；v2 严格校验 policy、版本范围、slot/alias ordinal 顺序、全局 ID 无歧义和既有的类型、范围、对齐及布局限制。
- migration service 分别建立 primary 与 alias 索引。旧 stable ID 优先命中候选 primary，未命中时才查 alias；命中后仍要求 type fingerprint 和大小完全相同。
- 候选 `ContractVersion` 小于旧版本时，以 `state_migration_version_regression` fail closed。`FAvidScriptWasmReloadResult` 与 session 增加并转发 alias 命中计数。
- 写入前先读取全部旧 runtime 值和候选旧值。写阶段发生错误时，已写入项按逆序恢复候选旧字节，避免部分迁移状态留在 candidate；session 不拥有任何匹配或内存读写逻辑。

## 兼容性

- schema v1 继续可作为历史热重载输入，且无需补写 v2 字段。
- 新 v2 alias 只能表达稳定 ID 重命名，不能触发数值转换、结构重排、用户回调或脚本执行。
- 本实现不包含 C# Attribute/facade、Task 4 自动热重载闭环或其他状态转换策略。

## 验证

- RED：先新增 v1 默认、合法 v2、alias 顺序/重复/current ID 冲突、exact 优先、rename alias、版本回退、类型不兼容及第二次 `WriteStateBytes` 失败后候选回滚断言；增量 Runtime 编译因新合同字段缺失失败。
- GREEN：使用 UE 自带 .NET 10 对 `AvidScriptRuntime` 做非 clean、`-MaxParallelActions=1 -NoUBA` 增量构建；随后运行 manifest contract（1 项）和 state migration/session rollback（2 项）automation，均为 Success、0 Fail、Queue Empty、TestExit，进程退出码 0。
- 公开 Runtime 结构改变后，对 `AvidScriptEditor` 运行相同约束的增量构建，并执行 `Build/CheckAvidScriptArchitecture.ps1`。

## 已知边界

- 逆向恢复依赖候选 guest memory 在预检成功后仍可写；生产 WAMR 后端的同一已加载线性内存满足这一前提。automation 使用一次性第二写失败注入，明确证明第一项会恢复。
- 若底层 VM 在恢复阶段发生独立、持续的外部写入故障，结果仍会以 `state_migration_write_failed` 拒绝候选；该后端故障不允许把 candidate 设为 live runtime。
