# P45.6 C# Runtime 诊断与函数级调用栈成果

> 状态：已完成实现与完整回归
>
> 主线：C# -> Roslyn Semantic -> Guest IR -> WASM -> WAMR -> UE5.8

## 1. 本阶段解决的问题

P45.6 把 C# 脚本的 WASM trap 从“只有 WAMR 异常文本”提升为可归因到 C# 方法的结构化诊断。作者现在能够看到项目相对源码、方法签名、函数声明行列，以及原始 WASM function index/offset；Editor 不需要理解 WAMR 文本或重新读取 debug artifact。

该能力覆盖初次加载、运行中生命周期调用和事务式 reload candidate。候选 `BeginPlay` 失败时，诊断会返回 C# 作者层，同时旧 runtime 与已提交宿主状态继续可用。

## 2. 最终架构

- `AvidScript.CSharpGuest` 从 Roslyn Semantic 与 Guest IR 投影确定性的 debug map。
- 构建流水线原子发布 WASM、Guest IR、state schema、debug map 与 manifest，并记录各自产物 SHA-256。
- `AvidScriptVM` 只采集通用 WASM frame，并提供不依赖 WAMR 的 WASM module layout inspector。
- `AvidScriptRuntime` 验证 provenance、实际 WASM index space 与 export alias，再将 frame 映射为 C# 方法。
- `AvidScriptEditor` 只展示 Runtime 的结构化结果，不解析 WAMR，也不读取编译产物。

模块职责保持为：VM 不知道 C#，Guest 编译器不知道 UE 对象，Editor 不拥有 Runtime 映射规则。

## 3. Debug Artifact 合同

debug map schema v1 公开以下关键字段：

- `module_id`：Guest IR module identity。
- `imported_function_count` / `defined_function_count`：完整 WASM function index space。
- `source.id` / `source.sha256`：项目相对 C# 源文件身份与内容哈希。
- `provenance.frontend_artifact_sha256`：本次 canonical frontend JSON bytes 的哈希。
- `provenance.semantic_sha256` / `guest_ir_sha256`：本次编译链产物哈希。
- `functions[].wasm_function_index`：方法对应的真实 WASM function index。
- `functions[].span`：Roslyn 零基、end-exclusive 的函数声明 span。

构造函数等非方法 Guest function 仍占用 index，但不会发布伪造的源码位置，因此方法表允许存在空洞。Runtime 将声明 span 转换为公开的一基行列，Editor 不再次换算。

## 4. 真实 WASM 布局核验

Runtime 不再信任 manifest 自报的函数数量。VM inspector 会解析实际 WASM 的 import、function 与 export section，并执行以下检查：

- manifest、debug map、实际 WASM 的 import/defined function 数量三方一致。
- function export index 落在实际 index space 内，重复或损坏 section 被拒绝。
- WAMR 只返回命名 export 时，先由真实 export 表恢复 function index，再做 C# 映射。
- 布局损坏使用 `debug_map_wasm_layout_invalid`，声明错配使用 `debug_map_wasm_layout_mismatch`，均失败关闭。

这消除了伪造 manifest 偏移、稀疏 constructor index 和命名 export frame 无法映射三类风险。

## 5. C# 作者体验

真实生成示例在 `BeginPlay` 中调用普通 C# helper `SetScale`，helper 通过生成式 UE binding 修改 Actor scale。测试会在最终 WASM 中把该 helper 改为 trap，并验证 Editor 输出类似：

```text
AvidScript trap: Exception: unreachable
at GeneratedBindingLifecycleScript.SetScale(...) (Samples/CSharp/GeneratedBindingLifecycle/GeneratedBindingLifecycleScript.cs:行:列)
wasm frame: function=索引 offset=偏移
```

同时覆盖直接在 exported `BeginPlay` 内 trap 的情况，确认命名 export 也映射到真实 C# `BeginPlay` 声明。

## 6. 性能边界

- 健康 `BeginPlay`、`Tick`、Event、Timer 不采集调用栈。
- debug map 与 WASM layout 仅在 load/reload 时验证一次，运行时持有不可变查找表。
- trap frame 只在失败路径分配，不增加正常 Tick 的 host crossing。
- 当前只承诺函数声明级定位；WAMR raw offset 作为证据保留，不伪装为表达式级源码位置。

## 8. 已知边界

- 尚未提供表达式级 sequence point、断点、单步或变量查看。
- canonical path 当前是词法边界；Windows junction 的最终物理目标验证必须在后续 Editor 打开源码前补齐。
- Shipping/Cook、Android/iOS 产物裁剪与移动端调试策略尚未在本阶段验证。
- 当前能力是运行时诊断基础设施，不代表完整 C# IDE debugger 已完成。
