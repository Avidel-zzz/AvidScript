# P45.5 候选热重载宿主副作用事务架构

## 1. 问题与目标

P45.3/P45.4 已保证候选 WASM 的 Guest 状态迁移、`BeginPlay` 和 runtime 切换在旧 runtime 仍存活时完成。当前仍存在一个宿主侧事务缺口：候选 `BeginPlay` 使用与 live runtime 相同的 writable host context，可以先修改 Actor 或 SceneComponent，再因为 trap、host import 失败或后续校验失败而被拒绝。此时旧 runtime 虽然继续 Tick，UE 对象状态却可能已经被候选污染。

P45.5 的目标是为候选 `BeginPlay` 建立显式、可审计、fail-closed 的宿主副作用事务边界：

- 可逆写入在执行前记录最小快照，候选失败时逆序恢复。
- 无法证明可逆的写入在 `ProcessEvent` 或静态 binding 执行前拒绝。
- 候选成功时保留已经应用的写入，并在清除事务指针后切换 live runtime。
- live `Tick`、事件、输入和正常初次加载保持现有立即写入语义。
- effect policy 来自生成式 binding descriptor，不在 runtime 按函数名猜测，也不为每个 UE API 新增一个 host import。

## 2. 方案比较

### 方案 A：全部延迟为 command buffer

候选 `BeginPlay` 只记录写命令，成功后统一执行。它能避免失败候选触碰 UE 状态，但写后读会观察到旧值；带返回值、out/ref 参数或依赖前序写入的反射调用也无法通用模拟。要解决这些问题需要完整 shadow object model，范围过大。

### 方案 B：通用 UObject 属性快照

非 const `ProcessEvent` 前序列化 receiver 的全部属性，失败后写回。该方案保留写后读语义，但 UFunction 可能 Spawn/Destroy 对象、修改其他对象、广播 delegate、触发 overlap、启动异步工作或写入引擎全局状态。仅恢复 receiver 属性不能构成真实事务，直接采用会制造错误安全感。

### 方案 C：显式 effect policy + 可逆 journal

Binding descriptor 声明每个函数在候选 reload 中的 effect domain。Runtime 只允许已经注册事务 adapter 的 domain；adapter 在首次写入前保存语义快照，写入仍立即执行，因此候选内读操作能观察新值。未知或不可逆写入在调用前拒绝。

P45.5 采用方案 C。第一版支持 Actor transform 和 SceneComponent transform，其他非 const reflected binding 归一化为 `unsupported`。这是一条可扩展的安全协议，而不是对任意 UE 副作用作不可验证的承诺。

## 3. 范围与非目标

### 3.1 本阶段支持

- 静态 ABI 的 Actor location/rotation/scale、Actor location offset 和 SceneComponent world location。
- 动态 reflected binding 中被 descriptor 标记为 `actor_transform` 或 `scene_component_transform` 的调用。
- 同一对象、同一 effect domain 在事务内只记录一次原始快照。
- 多对象写入按首次触碰顺序记录，失败时逆序 best-effort 恢复全部对象。
- 候选 trap、host import 失败、transaction policy 拒绝和显式候选激活失败后的旧 runtime 保活。

### 3.2 非目标

- Spawn/Destroy、Attach/Detach、组件创建、delegate 广播、音频、粒子、网络 RPC、Gameplay Ability、异步任务和文件/网络访问的通用回滚。
- 将 Unreal Editor 的 undo transaction 当作 runtime rollback。
- 对未知 UFunction 自动推断副作用。
- 跨线程或跨 world 的宿主事务。
- 回滚 Timer/Event 队列；候选 timer 仍属于候选 runtime，候选卸载时一并丢弃。
- 改变 live runtime 正常调用的写入行为。

## 4. Binding Descriptor v3

生成器从 schema v2 升级到 v3，并为每个 binding 增加必填字段：

```json
{
  "schema_version": 3,
  "bindings": [
    {
      "ue_function": "SetActorScale3D",
      "is_const": false,
      "reload_effect": "actor_transform"
    }
  ]
}
```

允许值：

- `none`：无宿主写入；const/pure binding 必须使用该值。
- `actor_transform`：只允许 Actor transform transaction adapter。
- `scene_component_transform`：只允许 SceneComponent transform transaction adapter。
- `unsupported`：live 调用仍按现有授权执行，但候选 `BeginPlay` 中必须在调用前 fail closed。

兼容规则：

- Parser 同时读取 v2 和 v3。
- v2 的 const binding 归一化为 `none`，非 const binding 归一化为 `unsupported`；因此旧 package 可以加载，但不会在候选阶段获得未经声明的写权限。
- 新 generator 只生成 v3；slice、manifest、cache 和 package publication 必须保留原始 policy。
- `reload_effect` 进入 package identity/hash；policy 变化必须使 package hash 变化，但 binding stable ID 继续只表达函数签名身份。

## 5. Policy 生成

新增独立的 Editor policy resolver。它接收已经通过 selection/type policy 的 `UFunction`，输出 effect domain：

1. `FUNC_Const` 或 Blueprint pure -> `none`。
2. 中央声明表中明确列出的 Actor transform 函数 -> `actor_transform`。
3. 中央声明表中明确列出的 SceneComponent transform 函数 -> `scene_component_transform`。
4. 其他非 const 函数 -> `unsupported`。

中央声明表只描述副作用安全类别，不生成 wrapper、不复制 ABI lowering，也不扩大授权面。新增可逆 domain 必须同时提供 adapter、descriptor 测试和候选失败回滚测试；仅把函数加入 allowlist 不算完成。

## 6. 组件边界

### 6.1 AvidScriptBindings

新增语言无关合同：

- `EAvidScriptBindingReloadEffect`：effect domain 枚举。
- `IAvidScriptBindingHostEffectJournal`：在写入前请求 snapshot/authorization。
- `FAvidScriptBindingInvocationContext::HostEffectJournal`：可选、非 owning 指针。

动态 `FAvidScriptBindingPackage::Dispatch` 在参数和 target 校验完成后、`ProcessEvent` 前执行：

1. live context 没有 journal：维持现有行为。
2. 候选 context + `none`：继续调用。
3. 候选 context + 可逆 domain：调用 `PrepareEffect`，成功后才执行 `ProcessEvent`。
4. 候选 context + `unsupported`：返回 `binding_reload_effect_unsupported`，不得执行 `ProcessEvent`。

### 6.2 AvidScriptRuntime

新增独立 `Private/HostEffects/FAvidScriptHostEffectTransaction`，实现 journal 接口并拥有：

- transaction state：`Open / Committed / RolledBack`。
- 按对象与 effect domain 去重的 snapshot 索引。
- 保留首次触碰顺序的 journal entry。
- Actor/SceneComponent transform adapter。
- commit、逆序 best-effort rollback 和结构化结果。

`FAvidScriptWasmRuntimeInstance` 不拥有事务生命周期，只把 `HostContext.HostEffectJournal` 转发给静态 handler 和动态 invocation context。

### 6.3 RuntimeSession

`FAvidScriptRuntimeSession` 是候选事务唯一 owner：

- 初次加载不创建 transaction。
- reload 在状态迁移成功后创建 transaction，并只把指针注入 candidate context。
- 候选 `BeginPlay` 失败时先 rollback，再清除 candidate context 并卸载候选。
- 候选成功时 commit，随后把 candidate context 恢复为普通 live context，再卸载旧 runtime、attach scheduler 并切换 manifest。
- transaction 指针不得进入 `LiveRuntime`，不得跨 Tick 保存。

## 7. Snapshot 与恢复语义

Actor adapter 保存：

- weak Actor identity；
- object handle slot/generation；
-完整 `FTransform`。

SceneComponent adapter保存同等 identity 与 component world transform。恢复前再次验证 weak object、registry handle generation、对象类型和 world 有效性。恢复调用与正常 binding 相同的无 sweep/teleport 语义，不能直接写内部字段。

若 Actor transform 自动带动 RootComponent，且脚本随后又直接修改该 component，两项按首次触碰分别记录并在失败时逆序恢复。单个恢复失败不能阻止其余 entry；结果保存第一个恢复失败 source，并报告 attempted/restored/failed 数量。

日志和 reload result 只记录 module、function/effect、对象 path、计数和 error category，不记录具体 transform 数值。

## 8. 错误分类

- `binding_reload_effect_unsupported`：候选调用了未声明可逆策略的动态写 binding。
- `host_effect_snapshot_failed`：对象、handle、类型或 transform snapshot 无效。
- `host_effect_transaction_invalid_state`：commit/rollback 顺序非法或 transaction pointer 过期。
- `host_effect_rollback_failed`：至少一个 entry 未恢复；继续尝试其余 entry，并保留旧 runtime。
- 原有 trap/host import category 保持根因；reload result 另带 host-effect rollback 状态，不能用 rollback category 覆盖原始候选失败。

`FAvidScriptWasmReloadResult` 增加：transaction attempted/committed、rollback attempted/succeeded、captured/restored/failed object count 和首个 effect error source。

## 9. 生命周期数据流

```text
validate manifest/package
  -> build candidate runtime
  -> migrate guest state
  -> open HostEffectTransaction
  -> inject candidate-only journal
  -> candidate BeginPlay
       -> read: direct
       -> reversible write: snapshot once -> execute now
       -> unsupported write: reject before execution
  -> BeginPlay failed
       -> rollback reverse -> clear context -> unload candidate -> keep old runtime
  -> BeginPlay succeeded
       -> commit -> clear candidate journal
       -> detach/unload old runtime
       -> attach candidate scheduler -> switch live manifest
```

## 10. 验证策略

### 10.1 Descriptor/Policy

- v3 生成与 parser round-trip。
- v2 const/non-const 安全归一化。
- invalid/missing effect 拒绝。
- policy 进入 package hash，slice 保留 policy。
- const 被错误标为写 domain、非 const 被标为 `none` 时 fail closed。

### 10.2 Transaction service

- 同对象重复写只 snapshot 一次。
- Actor 与 component 多 entry 逆序恢复。
- 中间恢复失败后继续恢复其余 entry。
- stale handle/object destroyed/跨 world 请求拒绝。
- commit 后 rollback、rollback 后 commit 均拒绝。

### 10.3 Runtime integration

- 静态 Actor 写入后 candidate trap，Actor transform 恢复且旧 Tick 继续。
- 动态 reflected SetActorScale3D 后 candidate trap，scale 恢复。
- unsupported reflected write 在 `ProcessEvent` 前拒绝，接收对象没有变化。
- 成功 candidate 的 transform 写入保留，journal 指针清除，后续 live Tick 正常写入。
- 初次加载与非 reload live 调用行为不变。

### 10.4 最终门禁

- 全部 .NET 自有测试宿主、PowerShell contract/parser、architecture gate。
- UE5.8 普通增量 Editor build；禁止 clean target。
- P45.5 focused automation 和完整 `Automation RunTests AvidScript`。
- 中文结果文档、`AGENTS.md` 错误记录、安全扫描、分组提交与普通 push。

## 11. 完成标准

P45.5 完成后，可以声明：候选 reload 对已声明可逆的 transform 写入具备宿主侧事务回滚；未知写入在候选阶段 fail closed；旧 runtime 在候选失败后继续运行且已覆盖的 UE transform 状态保持原值。

不得声明任意 UFunction、Spawn/Destroy、RPC、delegate 或异步副作用已经可回滚。后续扩展必须增加新的 effect domain 和对应 adapter，不能把 `unsupported` 静默改成允许。
