# P45.4 C# 显式状态契约阶段成果

## 阶段目标

P45.4 为 C# + WASM 热重载建立声明式状态契约，使游戏脚本可以明确区分需要跨重载保留的状态、临时状态和字段重命名，并由 Semantic、Guest schema、UE runtime 到真实工作区热重载形成完整闭环。

## 已实现能力

- 生成的 `AvidScript` C# facade 提供 `AvidStateMode`、`AvidStateContractAttribute`、`AvidPersistAttribute`、`AvidTransientAttribute` 与可重复的 `AvidStateAliasAttribute`。
- 未声明契约或使用 `Compatible` 时，继续迁移现有可安全表示的隐式字段；使用 `Explicit` 时，只有 `[AvidPersist]` 字段进入状态 schema，`[AvidTransient]` 字段不会跨重载保留。
- Semantic 层负责 Attribute 解析、冲突诊断和版本校验，Guest 层只消费结构化契约并生成 State Schema v2，不在构建脚本或 UE runtime 中重复字段选择逻辑。
- State Schema v2 保存 policy、contract version、稳定字段 ID、递归类型指纹、大小、布局和 alias；旧 State Schema v1 仍可读取，并归一化为 compatible、版本 1、无 alias。
- UE runtime 对重命名字段先匹配当前稳定 ID，未命中时才匹配 alias。每个候选槽只能被一个旧槽认领，类型指纹或大小不同、版本回退、alias 冲突都会在切换 runtime 前拒绝候选。
- 状态写入是候选侧事务：先完成全部匹配与读取，再写候选；中途失败时逆序尝试恢复全部已写槽，旧 runtime、scheduler、manifest 与 Tick 能力保持可用。
- 项目 C# starter 已启用显式契约；真实自动重载用例完成 `TotalRotationDegrees` 到 `AccumulatedRotationDegrees` 的字段重命名，并证明累计值通过 alias 保留且新 Tick 逻辑生效。

## C# 使用方式

```csharp
using AvidScript;

[AvidStateContract(AvidStateMode.Explicit, Version = 2)]
public static class GameplayScript
{
    [AvidPersist]
    [AvidStateAlias("TotalRotationDegrees")]
    private static float AccumulatedRotationDegrees;

    [AvidTransient]
    private static int FramesSinceReload;

    public static void Tick(float deltaSeconds)
    {
        AccumulatedRotationDegrees += 90.0f * deltaSeconds;
        FramesSinceReload++;
    }
}
```

字段重命名时，alias 填旧字段名，并提高契约版本。当前字段名始终优先于 alias；不能用 alias 合并两个旧字段，也不能借 alias 绕过类型兼容检查。

## 分层职责

- C# facade：只提供声明 API，不参与字段发现。
- Roslyn Semantic：把源码 Attribute 投影为经过诊断的结构化状态契约。
- CSharpGuest：选择安全 Guest 槽位并生成版本化 schema。
- Build pipeline：验证并原子发布 semantic、schema、manifest 与 WASM 产物。
- UE manifest loader：严格读取 v1/v2 schema 并验证边界、顺序和唯一性。
- StateMigration service：负责 exact/alias 匹配、版本检查、内存迁移和候选回滚。
- RuntimeSession：只编排候选生命周期与转发迁移结果，不拥有匹配算法。

## 已知边界

- 当前只迁移 manifest 明确列出的安全值槽；字符串、数组、引用、对象句柄、堆地址、计时器、协程和 VM 栈不会被整块复制。
- 类型兼容目前要求递归类型指纹和字节大小完全一致，不提供整数宽度转换、结构重排、用户迁移回调或脚本迁移函数。
- alias 只表达字段重命名，不表达多字段合并、拆分或任意数据转换。
- 候选 guest memory 若在恢复阶段持续发生底层写故障，无法恢复的候选字节可能残留；候选仍会被拒绝，绝不会替换正在运行的旧 runtime。
- 本阶段完成的是可靠的状态契约与热重载闭环，不代表调试器、Cook/Shipping、移动端和完整 UE API 覆盖已经达到 Puerts、UnLua 或 Unreal AngelScript 的成熟度；这些仍属于后续 phase。

## 结论

P45.4 已把 C# 字段声明、Roslyn 分析、WASM 状态布局、UE 候选迁移和真实游戏脚本热重载连成同一条可验证链路。项目现在具备显式控制跨重载游戏状态和安全处理字段重命名的基础能力，后续可以在此契约上继续扩展类型覆盖、调试体验和发布平台能力。
