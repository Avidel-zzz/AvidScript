# P45.4D C# Facade 与真实 Rename Alias 热重载

## 范围

P45.4D 为生成的 `AvidScript` C# facade 补齐声明式状态契约，并将项目 workspace 的真实 C# 自动热重载用例扩展为字段 rename alias 迁移闭环。

## 实现

- 新增 `FAvidScriptEditorCSharpStateContractRenderer`，稳定生成 `AvidStateMode`、`AvidStateContractAttribute`、`AvidPersistAttribute`、`AvidTransientAttribute` 与可重复的 `AvidStateAliasAttribute`。
- `FAvidScriptEditorCSharpBindingRenderer` 只组合该语言契约片段和反射 API facade；state renderer 不读取 binding 类型、函数数量或 authorization package 内容。
- `GameplayScript.cs` starter 启用 `[AvidStateContract(AvidStateMode.Explicit)]`，只将跨 reload 累积状态 `TotalRotationDegrees` 标为 `[AvidPersist]`。旋转速度是常量配置，不进入持久化 schema。
- 真实 workspace 自动重载从 `TotalRotationDegrees` 改为 `AccumulatedRotationDegrees`，保留 `[AvidPersist]` 并声明 `[AvidStateAlias("TotalRotationDegrees")]`。用例验证 alias migration attempted/applied、`StateMigrationAliasedSlotCount >= 1`、旧累计值保留、新 Tick 逻辑生效，以及 active runtime 与原 Actor 仍正确。
- architecture gate 校验独立 state contract renderer 的必要 facade surface，并拒绝其依赖反射 binding 内容。

## RED 与 GREEN

先增加 facade、starter 和 rename alias 断言。初次 `AvidScript.Editor.CSharpBindingEmitter` 发现 4 项，其中 Determinism 与 GameplayProfile 失败：生成 facade 缺少状态契约类型。这确认 RED 的失败原因是功能缺失，而不是测试拼写或环境问题。

实现后，新增 renderer `.cpp` 的常规模块级构建立刻报告 `Invalidating makefile for AvidTPSTemplateEditor (source file added)`；未使用 clean。生成 facade 的确定性测试还直接以空 binding package 调用 renderer，并确认其状态契约片段与默认反射 package 完全相同。

## 验证

使用 UE bundled .NET 10 执行：

```powershell
& "<EngineRoot>\Engine\Build\BatchFiles\Build.bat" AvidTPSTemplateEditor Win64 Development "-Project=<ProjectRoot>\AvidTPSTemplate.uproject" -WaitMutex -NoHotReloadFromIDE -Module=AvidScriptEditor -MaxParallelActions=1 -NoUBA
```

模块构建成功。聚焦自动化均以 `-DDC-ForceMemoryCache`、`-TestExit="Automation Test Queue Empty"` 运行，日志中的 `RequestExitWithStatus(..., 0)` 确认进程退出状态为 0：

- `AvidScript.Editor.CSharpBindingEmitter`：发现 4，成功 4，失败 0。
- `AvidScript.Editor.CSharpWorkspaceService`：发现 2，成功 2，失败 0。
- `AvidScript.Editor.CSharpLiveReload`：发现 16，成功 16，失败 0。
- `AvidScript.Editor.Module.CSharpWorkspaceBuildAndBindSelectedActor`：发现 1，成功 1，失败 0；包含真实编译、WASM reload、rename alias 迁移和既有 rejected-candidate rollback。

未运行完整 `AvidScript` 自动化套件，符合 P45.4D 的聚焦验证范围。

## 剩余风险

本组仅验证现有 `float` 累积字段的真实 rename alias 路径。其他可持久化类型和多 alias 组合仍由 P45.4A-C 的 schema、resolver 与 runtime migration 聚焦用例覆盖，Task 5 再负责完整回归。
