# P45.3 C# Guest 状态迁移架构

## 1. 阶段目标

P45.3 为 C# + WASM 自动热重载补齐可控的游戏状态迁移。脚本修改并成功构建后，新 WASM 实例不再无条件从零状态开始，而是在旧实例仍存活时恢复兼容的静态游戏字段，再执行新版本的 `BeginPlay`。

本阶段保持现有事务边界：候选实例只有在加载、导出校验、状态迁移和 `BeginPlay` 全部成功后才替换旧实例。任一步失败都卸载候选，旧实例继续响应 `Tick` 和事件。

## 2. 方案比较

### 方案 A：复制整个 WASM 状态区

实现最短，但字段偏移变化会静默写错数据，并可能复制字符串、数组、对象句柄或堆地址。该方案无法为成熟脚本框架提供可靠升级语义，因此不采用。

### 方案 B：脚本导出 Save/Load 钩子

扩展性最好，可承载容器和自定义版本升级，但会立即扩大语言 ABI、编译器和用户 API，并要求脚本作者手写迁移逻辑。它适合作为后续高级能力，不作为第一版基础闭环。

### 方案 C：宿主按稳定槽位迁移

构建工具从 Semantic + Guest IR 生成状态槽位清单；UE 宿主按稳定字段 ID 匹配旧、新槽位，仅在类型指纹和尺寸完全一致时复制字节。字段偏移可以变化，新增字段保留新初始化值，删除字段自动忽略。

P45.3 采用方案 C。它不需要逐个手写 UE API，也不把 WAMR 细节泄漏到 RuntimeSession，并为后续复合值类型和显式 Save/Load 钩子保留演进空间。

## 3. 第一版支持边界

支持迁移：

- 脚本主类型中由 C# 编译器降低为 Guest global 的静态字段。
- 标量：`bool`、整数、`float`、`double`。
- 枚举。
- 所有成员递归满足安全条件的纯值结构。

暂不迁移：

- `string`、数组、引用类型、WASM 堆对象和裸地址。
- UObject/Actor 句柄。
- 定时器、事件队列、协程、异步任务和 VM 调用栈。
- 多实例共享状态、自定义版本转换和用户定义 Save/Load 钩子。

当前 Semantic 模型尚未区分 `const`/`readonly`。工具链会按“脚本主类型的静态 Guest global”筛选；常量槽位即使被纳入也不会改变编译期常量引用的行为。后续 Semantic 增加字段修饰信息后再收紧策略。

## 4. Manifest 契约

根 manifest 继续使用 `schema_version = 1`，新增可选 `state_migration` 对象，因此旧 manifest 仍可加载并保持“热重载重置状态”的既有行为。

```json
{
  "state_migration": {
    "schema_version": 1,
    "strategy": "host_snapshot",
    "owner_type_id": "type:global::Game.GameplayScript",
    "slots": [
      {
        "stable_id": "state:type:global::Game.GameplayScript:Score",
        "type_fingerprint": "<sha256>",
        "offset": 16,
        "size": 4,
        "alignment": 4
      }
    ]
  }
}
```

槽位按 `stable_id` 序列排序。稳定 ID 只由 owner type identity 与字段名组成，不嵌入字段类型；因此类型变化仍会命中同一槽位并由指纹 fail-closed 地拒绝。类型指纹由结构化 Guest 类型图递归计算，包含类型 ID、kind、storage、尺寸、对齐，以及结构字段 ID、偏移和成员类型指纹。禁止通过拼接非结构化源码文本生成指纹。

## 5. 迁移判定

只有同时满足以下条件才尝试迁移：

1. 当前存在旧运行时。
2. 新旧 `module_id` 相同。
3. 新旧 manifest 都声明 `host_snapshot`。
4. 新旧 owner type identity 相同。

随后按稳定 ID 求交集：

- 指纹与尺寸相同：从旧实例读取并写入候选实例。
- 新增或删除字段：跳过，不视为错误。
- 同稳定 ID 但指纹或尺寸不同：迁移失败，拒绝候选。

宿主限制最多 1024 个槽位、单槽最多 64 KiB、一次迁移总计最多 1 MiB。Manifest 加载阶段拒绝空 ID、非法 SHA-256、负数/溢出范围、重复 ID、非法对齐与重叠槽位。

## 6. 分层职责

### Toolchain

- `AvidScript.CSharpGuest`：从 Semantic + Guest IR 投影确定性状态迁移 schema，并原子写入独立 JSON 产物。
- `InvokeCSharpGuestCompiler.ps1`：编排 Guest IR、状态 schema 与 WASM 产物。
- `BuildCSharpActorLifecycle.ps1`：读取结构化 schema 并嵌入最终 manifest，不在 PowerShell 中复制类型系统规则。

### VM

- `IAvidScriptVmBackend` 提供可选的语言无关 Guest memory 能力。
- WAMR backend 返回已有的 `IAvidScriptVmGuestMemory` 实现。
- VM 继续负责地址合法性校验和内存翻译。

### Runtime

- `FAvidScriptWasmRuntimeInstance` 只暴露窄化的状态字节读写接口。
- 独立 `StateMigration` 服务负责 manifest 配对、快照读取、候选写入和结构化错误。
- `RuntimeSession` 只负责编排：构建候选 -> 迁移 -> `BeginPlay` -> 原子切换。

## 7. 生命周期顺序

```text
旧实例保持 Running
  -> 加载并验证候选 WASM
  -> 根据旧 manifest 读取兼容槽位快照
  -> 写入候选实例
  -> 候选 BeginPlay
  -> 成功：Detach/Unload 旧实例并 Attach 候选
  -> 失败：Unload 候选，旧实例不变
```

迁移位于 `BeginPlay` 之前，因此新版本 `BeginPlay` 能读取恢复后的字段；若脚本在 `BeginPlay` 中显式重置字段，则以新脚本行为为准。

## 8. 可观测性

Reload result 增加：

- 是否尝试迁移。
- 成功迁移槽位数与字节数。
- 跳过的新增/删除槽位数。
- 迁移失败 category 和具体 stable ID。

日志不得打印字段值，避免把游戏状态或潜在敏感数据写入 Editor 日志。

## 9. 后续演进

P45.3 的宿主槽位协议是基础层，后续可以在不破坏它的前提下增加：

- UObject 弱句柄的重新解析。
- 容器的受控序列化。
- `[AvidPersist]`、`[AvidTransient]`、字段别名和版本转换属性。
- 用户定义 Save/Load 钩子。
- PIE 多实例隔离、Cook/Shipping 和移动端恢复验证。

## 10. 完成定义

- 工具链可重复生成字节一致的状态 schema。
- Manifest loader 能 fail-closed 地校验 schema。
- 真实 WAMR 旧实例到候选实例可迁移基础状态。
- 真实 C# 自动热重载用例证明 `Tick` 累积状态跨版本保留。
- 不兼容 schema、越界读写与候选 `BeginPlay` 失败均保留旧实例。
- 增量 UE5.8 Editor 编译、架构门禁、聚焦自动化与完整 AvidScript 自动化通过。
