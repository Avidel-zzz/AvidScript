# Phase 55 预绑定调用边界与标量 ABI 架构

> 决策：采用 A 路线，优先让常用单次 UE 调用和生命周期 callback 达到或领先 Puerts Static；纯执行层 P95 作为独立债务保留，不与本阶段热路径改造混在一起。

## 1. 背景与问题

Phase 54 已证明 Wasmtime typed empty import 的物理 P50 为 `4.5785 ns`、P95 为
`6.315 ns`。这说明 Wasmtime 的 unchecked host ABI 不是 Generated S1 标量、
属性和 callback 落后的主要原因。

Phase 54 正式结果如下：

| Workload | AvidScript | Puerts Reflection | Puerts Static | 当前状态 |
| --- | ---: | ---: | ---: | --- |
| scalar Generated S1 P50 | 54.12 ns | 103.88 ns | 27.70 ns | 领先 Reflection，落后 Static 1.95x |
| property Generated S1 P50 | 197.09 ns | 99.93 ns | 60.42 ns | 落后 Reflection 1.97x，落后 Static 3.26x |
| callback empty P50 | 385.86 ns | 134.92 ns | 137.45 ns | 落后 Static 2.81x |
| FVector Generated S1 P50 | 199.97 ns | 1282.53 ns | 1053.81 ns | 已明显领先 |

代码审阅确认，Generated S1 成功路径仍在每次调用中重复执行：

1. Wasmtime backend 通过 `IAvidScriptVmTypedHostDispatcher` 虚接口分发；
2. Runtime 按 binding ordinal 重新取得 plan；
3. plan 再次验证 generated lease、shape、receiver mode 和函数指针；
4. Self capability 以 callback epoch 为缓存边界，跨 Tick 重新访问对象注册表；
5. host effect 即使没有 journal，也重复进入 package plan；
6. int32 getter 先校验 guest memory，再调用，再次借用 guest memory写回；
7. UE 到 WASM callback 使用通用 checked `wasmtime_func_call`，重复进行已在加载期证明过的类型检查。

这些检查本身是正确的，但放在 warm call 中的位置不正确。Phase 55 将其移动到加载期，
并为不可静态消除的撤销、对象生命周期和 reload 状态保留 O(1) fail-closed 检查。

## 2. 目标

Phase 55 交付以下能力：

- generated typed import 在 Runtime load 时形成地址稳定的预绑定 call cell；
- Wasmtime host trampoline 直接调用 call cell，不再按 ordinal 进入虚 dispatcher；
- Self capability 可跨 callback 复用，但受 object-registry revision、reload epoch、
  weak object、class 和 world 共同约束；
- int32 property getter/setter 使用独立 typed ABI，getter 不再经过 guest memory；
- 已验证的 Wasmtime lifecycle/event export 使用 prebound unchecked call；
- lifecycle/event 成功路径只更新轻量 outcome，完整 smoke/diagnostic result 在失败或
  显式请求快照时才物化；
- semantic reflection、qualified native direct、旧 property ABI 和 unsupported shape
  继续作为兼容路径；
- 正式 benchmark 同时验证正确性、provenance、P50、P95、MAD 和 fallback 状态。

## 3. 非目标

- 不更换 Wasmtime；
- 不删除 WAMR 或 semantic reflection fallback；
- 不按 fixture 名称、UFUNCTION 名称或单个 UE API 编写特例；
- 不为了跑分关闭 write policy、reload journal、world、class、generation 或 package
  revocation 检查；
- 不在本阶段扩展 FVector、object、container 或 ref/out API 覆盖；
- 不把 Phase 54 controlled-runtime P95 债务伪装成本阶段成果；
- 不在每个小改动后重复运行 Editor Target 全构建和正式矩阵。

## 4. 方案比较

### 方案 A：预绑定 call cell 与专用标量 ABI

加载期把 binding plan、generated entry、receiver class、write policy 和 host effect
元数据冻结为 Runtime-owned call cell；VM 只持有 opaque context 和 shape-specific
函数指针。

优点：

- 直接处理已经测量出的固定成本；
- 不破坏模块边界，VM 不依赖 UObject 或 Bindings 类型；
- 可保留 semantic fallback 与 fail-closed reload；
- 同一结构可继续扩展 FVector、object 和未来批量 ABI。

缺点：

- 需要同时修改 VM contract、Bindings plan、Runtime 生命周期和 source emitter；
- property ABI 需要兼容旧 descriptor。

### 方案 B：只优化现有 Runtime dispatcher

保留 ordinal 和虚接口，只缓存更多 plan 字段并压缩分支。

优点是改动小；缺点是无法消除 VM 到 Runtime 的间接层，也无法解决 property guest
memory 和 callback checked call。预计只能获得局部收益，难以跨过 Puerts Static。

### 方案 C：继续扩大 data-oriented batch

让更多游戏逻辑通过 command buffer 摊薄 crossing。

该方向已经在 Small/Dense gameplay 领先，但不能替代 Tick 中常见的单次属性访问、
标量函数和 callback。它保留为后续 API 扩展方向，不是 Phase 55 主线。

最终选择方案 A。

## 5. 模块边界

### 5.1 AvidScriptVM

`AvidScriptVM` 只定义后端无关的 prepared target 契约：

```cpp
using FAvidScriptVmSelfI32PairTarget =
	EAvidScriptVmTypedHostStatus (*)(
		void* Context,
		int32 SelfSlot,
		int32 SelfGeneration,
		int32 Left,
		int32 Right,
		int32& OutValue);

using FAvidScriptVmSelfPropertyI32GetTarget =
	EAvidScriptVmTypedHostStatus (*)(
		void* Context,
		int32 SelfSlot,
		int32 SelfGeneration,
		int32& OutValue);

using FAvidScriptVmSelfPropertyI32SetTarget =
	EAvidScriptVmTypedHostStatus (*)(
		void* Context,
		int32 SelfSlot,
		int32 SelfGeneration,
		int32 Value,
		int32& OutValue);

struct FAvidScriptVmPreparedTypedHostTarget
{
	void* Context = nullptr;
	FAvidScriptVmSelfI32PairTarget SelfI32Pair = nullptr;
	FAvidScriptVmSelfPropertyI32GetTarget SelfPropertyI32Get = nullptr;
	FAvidScriptVmSelfPropertyI32SetTarget SelfPropertyI32Set = nullptr;
};
```

`FAvidScriptVmTypedHostImport` 增加 prepared target。VM load 必须验证 shape、WASM
签名和对应函数指针完全匹配；不匹配直接拒绝实例化。

VM contract 不包含 `UObject`、`UClass`、`FProperty`、generated entry 或 registry。

### 5.2 AvidScriptBindings

Bindings 继续拥有 descriptor、plan、lease 和 generated entry。新增加载期只读快照：

```cpp
struct FAvidScriptPreparedGeneratedBinding
{
	uint32 BindingOrdinal = MAX_uint32;
	FAvidScriptGeneratedBindingLease Lease;
	const FAvidScriptGeneratedBindingEntry* Entry = nullptr;
	UClass* ExpectedClass = nullptr;
	FProperty* ReflectedProperty = nullptr;
	EAvidScriptBindingReloadEffect ReloadEffect =
		EAvidScriptBindingReloadEffect::Unsupported;
	bool bPropertyWrite = false;
	bool bRequiresWriteAccess = false;
};
```

`FAvidScriptBindingPackage::BuildPreparedGeneratedBindings` 在 Game Thread 一次性：

- 验证 ordinal、lease、entry、shape、receiver 和 descriptor identity；
- 生成与 `BuildTypedHostImports` 相同顺序的快照；
- 不执行 UObject resolve；
- 不把 Bindings 类型泄漏给 VM。

旧的 `TryGetGeneratedBinding` 保留给兼容和诊断路径，prepared path 不再每次调用它。

### 5.3 AvidScriptRuntime

Runtime 新增 `FAvidScriptPreparedGeneratedHostCall`。它持有 Bindings 快照、Runtime
指针和 shape-specific 执行函数。实例用
`TArray<TUniquePtr<FAvidScriptPreparedGeneratedHostCall>>` 保证 context 地址在
`VmBackend->Load` 到 `VmBackend->Unload` 期间稳定。

加载顺序：

1. Binding package 创建 prepared binding snapshots；
2. Runtime 创建全部 call cells；
3. Runtime 将 opaque context 和静态 target 写入 typed imports；
4. VM backend 验证 imports 并实例化；
5. load 失败时先卸载 backend，再销毁 call cells。

卸载顺序：

1. 禁止新 guest call；
2. `VmBackend->Unload()` 等待 active call 退栈；
3. 清空 typed imports；
4. 销毁 call cells 和 binding package；
5. 增加 reload epoch 并清空 Self capability。

### 5.4 Generated source

新增两个明确 shape：

- `property_i32_get`，WASM 签名 `(ii)i`；
- `property_i32_set`，WASM 签名 `(iii)i`。

旧 `property_i32_get_set`、`(iii)i` 继续可解析，但不参与新的领先 Gate。生成器根据
descriptor invocation kind 选择 get 或 set，不按属性名特判。

getter 直接把 int32 放入 WASM result；setter 的第三个参数就是 value。两者的 C
bridge failure 仍变为 host-import trap，不把错误码与业务值混在一起。

## 6. Self capability 与撤销

跨 callback 复用 Self 不能绕过 handle revocation。`FAvidScriptObjectRegistry` 新增
单调 `Revision`：

- Register、Acquire、Release、Reset 或 slot generation 变化时递增；
- `0` 永远不是有效 revision；
- 只在 Game Thread 读写；
- getter 为 O(1)，不分配。

`FAvidScriptSelfCapability` 记录：

- weak object；
- owner handle；
- Runtime reload epoch；
- object registry revision。

prepared call 的 Self fast path必须同时满足：

- 当前在 Game Thread 且 callback epoch stack 非空；
- Host world 不 stale；
- guest 提交的 slot/generation 等于 owner handle；
- registry pointer 与 revision 未变化；
- weak object 仍有效；
- object 满足 expected class 和 world。

任一条件不满足时只允许走一次完整 `ResolveObject`；成功后刷新 cache，失败则拒绝。
HostContext 变化、reload、unload、registry mutation 或 weak object 失效都不能复用旧
raw pointer。

## 7. Host effect

prepared cell 固定 `bRequiresWriteAccess`、property/function kind、reflected property 和
reload effect。

成功 warm path：

- 只读调用：不进入 journal；
- 写调用且 write policy 不允许：立即拒绝；
- 写调用且 journal 为空：直接执行；
- reload transaction 中 journal 非空：调用 Bindings 的 prepared effect helper，
  保留 reflected property snapshot、unsupported effect 和 ownership 语义。

不允许为了 benchmark 永久缓存 journal 为空，因为 reload candidate 可以在实例存活
期间切换 invocation context。

## 8. Wasmtime callback

`ResolveExport` 已缓存函数、参数 kind、参数 cell 数和 result cell 数。该证明足以在
每次 call 的 handle identity、generation 和 cell count 检查通过后使用
`wasmtime_func_call_unchecked`。

callback 是 UE 到 WASM 的反向调用，不属于 typed host call cell。Runtime 为
BeginPlay、Tick、EndPlay、Timer 和 Event 分别持有 prebound export frame：

```cpp
struct FAvidScriptVmPreparedExportCall
{
	FAvidScriptVmExportHandle Handle;
	uint32 ExpectedCellCount = 0;
	uint32 ExpectedResultCellCount = 0;
};
```

backend load 成功后一次性解析 required exports；optional export 在第一次发现后冻结。
warm callback 不再把 ASCII export name 转成 `FString`，也不再重复进入 resolve。

C shim 新增 raw cell 调用：

- `wasmtime_val_raw_t` buffer 大小为 `max(parameter_count, result_count)`；
- 按缓存 kind 从 VM cell 转成 raw union；
- 调用 unchecked API；
- trap/error 继续走现有 failure 对象和 stack frame 映射；
- unsupported reference type 在 resolve 阶段拒绝；
- checked API 保留为诊断对照 lane，不作为 production warm path。

现有 `Tick` 等 API 每次都会重建完整 `FAvidScriptWasmSmokeResult`，其中包含多个
字符串、backend identity、metrics 和 diagnostic arrays。Production warm path 改为：

```cpp
enum class EAvidScriptWasmResultDetail : uint8
{
	FailureOnly,
	FullSnapshot
};
```

- Runtime core call 始终返回轻量成功/失败状态；
- `FailureOnly` 成功时只更新 Runtime 内部 counters，不清空或复制完整 result；
- trap、host import failure、stale export 或 lifecycle failure 时无条件物化完整诊断；
- `FullSnapshot` 保留当前测试、Editor 工具和显式诊断行为；
- RuntimeSession/Component production Tick 使用 `FailureOnly`；
- benchmark 的 production lane 必须测量 `FailureOnly`，另设 full-snapshot diagnostic
  lane，禁止把诊断对象成本归咎于 Wasmtime；
- 两种 detail policy 的 lifecycle state、host count、timer/event 顺序和失败诊断必须
  等价。

这项优化不建立 benchmark-only export，也不静默丢失失败信息。

## 9. 性能 Gate

### 9.1 正确性 Gate

- UE5.8 no-clean `AvidTPSTemplateEditor Win64 Development` 构建通过；
- focused Automation 零失败；
- generated package revoke、stale handle、world mismatch、class mismatch、read-only
  write 和 reload journal 均 fail-closed；
- property get/set checksum、host count 和 operation count 与 semantic oracle 一致；
- callback BeginPlay/Tick/EndPlay/Timer/Event 生命周期顺序不变；
- formal sample 的 candidate commit、tree、runtime hash、artifact hash 和
  `fallback_used=false` 完整。

### 9.2 性能领先 Gate

正式矩阵使用一个独立 calibration process 和五个全新 timed Editor process。每个
process、lane、workload 先执行 5 次 warmup，再记录 30 个 timed sample；单 sample
校准到至少 5 ms。lane 顺序继续使用 balanced rotation。

进程是统计 replicate，不能把 150 个 sample 当作 150 个独立进程样本。统计量定义：

- P50：`median(process_p50)`；
- P95：`median(process_p95)`，不使用五进程下等于最差值的 `P95(process_p50)`；
- MAD50：`MAD(process_p50)`；
- MAD95：`MAD(process_p95)`；
- 稳定性：`MAD50/P50 <= 5%`、`MAD95/P95 <= 10%`，最差 process-P50
  不超过正式 P50 的 `1.15x`。

Phase 54 micro evaluator 当前只发布 P50。P55.4 必须先补齐 process-P95、MAD50、
MAD95 和 process win 统计，随后才能执行正式 Gate。

Puerts Reflection 与 Puerts Static 均正式测量。每个指标使用两者的较快值作为
headline comparator；Native 只作为 floor，AvidScript Semantic 只作为 fallback
正确性参考。

每个 workload 同时满足以下条件才标记“领先”：

- scalar/property 的 AvidScript/best-Puerts P50 与 P95 均 `<= 0.90`；
- callback 的 AvidScript/best-Puerts P50 与 P95 均 `<= 0.85`；
- P50 和 P95 分别满足
  `candidate + 2 x MAD_candidate < comparator - 2 x MAD_comparator`；
- 至少 `4/5` timed process 的 process-P50 获胜；
- correctness、identity、fallback 或 provenance 任一失败即取消排名。

绝对目标和成本域：

| Workload | 成本域 | P50 | P95 |
| --- | --- | ---: | ---: |
| `scalar_add_int32` | guest-to-host、bound Self、UE function | `<= 25 ns` | `<= 35 ns` |
| `property_i32_set` | crossing 与 UE write，Guest Memory 为零 | `<= 20 ns` | `<= 30 ns` |
| `property_i32_get` | crossing 与 UE read，Guest Memory 为零 | `<= 30 ns` | `<= 45 ns` |
| `property_get_set` | 一次 set 与一次 get | `<= 50 ns/pair` | `<= 75 ns/pair` |
| `callback_empty` | host-to-guest、epoch enter/exit、guest body | `<= 120 ns` | `<= 180 ns` |
| `callback_tick` | 完整 Tick lifecycle callback | `<= 150 ns` | `<= 225 ns` |

分层诊断 Gate：

- typed empty P50/P95 不高于 `5.04/6.95 ns`；
- typed i32 pair P50/P95 不高于 `4.99/7.47 ns`；
- prepared bound no-op P50/P95 不高于 `15/22 ns`；
- split property、scalar 和 callback 的 timed success path 中，guest-memory
  borrow/read/write bytes 必须为零；
- 旧 property ABI 只进入 diagnostic lane，并准确记录 `2N` borrow 和 `4N` write
  bytes；
- unchecked cached export 的 P50/P95 均不高于同进程 checked lane 的 `0.80x`；
- 10,000 次 callback bind/revoke/rebind 后 active cell/lease 为零，stale invocation
  拒绝率 100%，epoch begin/end 完全相等且最终 stack depth 为零；
- cached bind+revoke P95 `<= 10 us`，cached reload-rebind P95 `<= 25 us`，这两项只
  表示生命周期工程门槛，不与 Puerts 混作性能领先。

防回退：

- Small Generated P50/P95 不高于 `87.96/99.50 ns`；
- Dense Data P50/P95 不高于 `132.50/141.17 ns`；
- FVector P50 不高于 `209.97 ns`；P95 与同次兼容 lane 比较且不超过 `1.05x`；
- pure integer 仅做执行层噪声控制，本阶段不要求关闭 P54-PERF-001。

### 9.3 Stop/Go

- 任一 correctness、identity、clean-tree、fallback 或 route-count 失败时禁止进入
  formal；
- split property 仍访问 Guest Memory，或 callback 正式 lane 仍命中 checked API
  时禁止进入 formal；
- diagnostic P50 达到 scalar `<= 30 ns`、property pair `<= 65 ns`、
  callback empty `<= 150 ns`，且 prepared/unchecked 相对兼容 lane 改善至少 20%
  后才运行 formal；
- typed-empty P95 达到 best-Puerts scalar P50 的 70% 时停止继续微调 dispatcher，
  转向 batching 或 runtime 方案；
- scalar、三条 property、两条 callback 与 lifecycle 必须逐项通过，禁止用综合分数
  掩盖单项失败；
- 性能 Gate 未全过不阻止正确架构批次完成，但 Phase 55 性能状态必须为 `NO-GO`，
  建立可复现 Important debt，并禁止“全面领先”或“单调用领先”表述。

## 11. 完成定义

Phase 55 完成表示：

- 四个实现批次都有代码、合同测试和中文证据；
- phase workflow 进入 closed 或明确记录未通过性能 Gate 的后续债务；
- 主分支和远端包含可复现候选；
- 文档只声明正式数据支持的领先项。

它不自动表示 AvidScript 已全面领先 Puerts、UnLua 或 UnrealEngine-Angelscript。
