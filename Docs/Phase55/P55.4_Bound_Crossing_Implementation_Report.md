# P55.4 预绑定调用边界实现报告

> 状态：实现完成；阶段末统一验收待执行

## 目标与边界

Phase 55 不扩展手写 UE API 清单，而是缩短所有生成绑定和生命周期回调共同经过的
固定路径。完整普通 `UFUNCTION` 仍由反射语义路径保证覆盖，Generated S1 和
Data-Oriented lane 负责已证明 shape 的性能。

本阶段冻结了三条约束：

1. 快路径不能绕过对象代际、capability、热重载 revision 和 UE 线程语义；
2. ABI shape 在加载期验证，热调用只消费已经证明的不可变调用单元；
3. 性能结论只接受干净候选、同机多进程正式矩阵，不用单次最好值宣称领先。

## 已实现内容

### P55.1 预绑定调用单元

- 将 binding descriptor、预解析接收者、typed thunk、策略和命中计数组织为
  prepared host call cell；
- 对象注册表增加单调 revision，Self 缓存只在 revision 变化时重新解析；
- Tick 热路径使用 `FailureOnly` 结果详情，成功调用不再复制完整诊断字符串和快照；
- 面向外部调用者的完整可观测结果保持不变，失败路径仍保留完整错误上下文。

### P55.2 拆分属性 ABI

- 新增独立 `i32` getter 与 setter import，去掉每次属性操作中的运行时 opcode 分派；
- 生成器按 descriptor shape 产生对应 C++ bridge 和 WASM 签名；
- Data-Oriented 写入 lane 直接绑定 split setter，同时保留旧 getter/setter ABI 的兼容回退；
- real generated、semantic、data-oriented 三种 C# profile 均通过加载与正确性准备。

### P55.3 Wasmtime 已验证导出

- lifecycle export 在实例化阶段完成名称和签名验证；
- 已验证导出使用 Wasmtime unchecked typed call，避免每个 BeginPlay、Tick 和 EndPlay
  再做动态签名检查；
- 生命周期名称集中为静态常量，scheduler、session 与 backend 的结果详情策略统一；
- 失败时仍恢复 backend identity、trap 和可诊断状态，不以性能换取静默错误。

### 集成修正

正式 profile 暴露了两个跨层问题并已修复：

- split getter 仍被一处加载器硬编码为旧 `(iii)i` 签名，现改为统一从 binding shape
  推导；
- Data-Oriented lane 只接受旧 getter/setter binding，现可准备并直接调用 split
  setter。

这两项说明 ABI 变更必须审计所有消费者，而不仅是生成器与主调用路径。

## 正式性能结果

正式候选为 commit `ae27606c0f763480c50ff644bd100be62342eb50`，tree 为
`5b603a2b4fa8101d9fcbfd1d64b6c8d897ed4b64`。Gameplay 与 micro 均采用
`1` 次校准、`5` 个独立进程、每进程 `5` 个 warmup 和 `30` 个 timed sample；
所有观测正确，未启用 fallback。

| 指标 | Phase 55 | 对照 | 结论 |
| --- | ---: | ---: | --- |
| Generated S1 scalar P50 | 52.95 ns | Puerts Static 31.72 ns | `1.67x`，未领先 |
| Generated S1 property P50 | 104.75 ns | Phase 54 197.09 ns | 改善 46.85%，仍未达 50 ns |
| Generated S1 callback P50 | 212.23 ns | Phase 54 385.86 ns | 改善 45.00%，仍是 Puerts `1.45x` |
| Generated S1 FVector P50 | 58.83 ns | Phase 54 199.97 ns | 降至基线 `0.294x`，通过 |
| Small frame P50 | 87.18 ns | Puerts Static 138.62 ns | `0.629x`，通过 |
| Dense frame P50 | 129.52 ns | Puerts Static 237.34 ns | `0.546x`，通过 |

Small 与 Dense 的 P95 和 `2 x MAD` 分离也同时通过，不是依赖一次偶然样本的胜出。
12 个集中性能 Gate 共通过 3 个、失败 9 个。因此可以确认 AvidScript 已在这两个
组合游戏逻辑 workload 上领先 Puerts，但不能宣称整体或所有 crossing 已绝对领先。

相同 12-kernel WASM 上，Wasmtime/V8 P50 几何均值比为 `0.9770`，P50 赢得
`9/12`；P95 几何均值比为 `1.0108`，P95 只赢得 `6/12`。这说明执行层平均值接近，
但 tail latency 仍未达到 `0.95x` 的领先标准。

物理 typed empty import P95 为 `6.903 ns`，已经很低；但它只能解释完整 scalar
边界成本约 20%。下一阶段的主要目标不应继续压缩空 trampoline，而应融合 receiver
解析、调用帧、结果写回和 lifecycle dispatch。

## 架构结论

预绑定调用单元、registry revision、split property ABI 和 unchecked export 均已证明
方向有效，尤其属性、callback 与 FVector 的改善显著。剩余差距集中在完整调用帧，
不是 Wasmtime 单条 import 本身，也不是 UE API 覆盖数量。

Phase 56 应优先完成：

1. 生成式 fused call frame，把 receiver slot、参数区、返回区和策略编译为连续布局；
2. 将 capability、revision 与对象有效性检查分层为 reload slow path 和最小热检查；
3. 对 lifecycle callback 使用批量/直接入口，减少 session、scheduler、backend 间复制；
4. 审计 Wasmtime Cranelift 配置、fuel/epoch/stack guard 与 P95 抖动来源；
5. 保留 semantic reflection fallback，禁止为追求 benchmark 逐个手写 UE API。
