# P43.3 按脚本语义裁剪 Binding Slice 架构

## 目标

P43.2 已让自定义 C# 脚本默认获得 115 个 Gameplay binding，但完整 facade 也会让未调用 API 进入 Guest IR 和 WASM import。P43.3 要把完整 Profile 保留为编译授权上界，再从 Roslyn 语义图派生每个脚本的最小使用集合，最终让 descriptor、facade、WASM 和运行时调用计划共享同一份 binding slice。

## 不采用的路线

- 不在 WASM 二进制生成后删除 import。此时已经丢失 C# callable、属性 getter 和类型依赖关系。
- 不在 PowerShell 中扫描 facade 或用户源码文本。文本匹配无法正确处理重载、别名、属性、构造函数和间接 helper 调用。
- 不维护逐函数白名单。完整能力面仍由 UE 反射 Profile 产生，裁剪依据只来自实际语义调用闭包。

## 分层设计

### Semantic Reachability

`AvidScript.CSharpSemantic` 从所有 WASM export callable 出发，遍历可达 CFG 中的完整 symbol ID：

- 普通调用、构造函数和运算符直接指向 method symbol；
- property symbol 通过 `AssociatedSymbolId` 解析 getter；
- 用户 helper、生成 facade wrapper 与最终 `DllImport` 使用同一套递归闭包；
- 递归调用以 stable method ID 去重；
- 没有 export 的分析型输入进入 `all_callables_compatibility` 模式，保持工具和库分析兼容。

语义产物显式记录 root callable、reachable callable 和 reachable import，不直接写 UE binding stable ID。Semantic 层只认识 C# 与 ABI，不依赖 UE descriptor 格式。

### Guest IR Slice

`AvidScript.CSharpGuest` 只降低 `reachable_callable_ids` 中的函数和 import。Schema 4 旧产物没有 reachability 时继续使用全部 callable；Schema 5 产物必须提供合法、闭合且确定排序的 reachability。

类型和静态状态暂不在 P43.3A 裁剪，避免在函数闭包尚未稳定时同时引入类型活性分析。WASM import 数量先获得主要收益。

### Package Authorization

完整 binding package 是允许调用的上界。构建阶段要求每个实际 `avidscript.*` import 都存在于已验证 package manifest；未使用的 package import 不再被当作错误。构建报告和脚本 manifest 记录实际使用 import 对应的 stable ID、ordinal 和签名。

这仍然是失败关闭模型：脚本不能通过裁剪引入 package 之外的动态 import。

### Minimal Runtime Package

P43.3B 由 Editor 消费 P43.3A 的 stable ID 使用集合，从同一 Gameplay Profile 派生最小 selections，并重新生成 descriptor、facade 和内容寻址 package。显式指定的项目 package 默认不被重写；Editor 自动选择的 Gameplay package 才进入自动切片。

深入映射后，最终构建采用“完整 authorization facade + 最小 runtime package”双契约。完整 facade 保证不可达 helper 仍可引用 Profile 内合法 API；最小 runtime package 必须覆盖所有实际 WASM 动态 import，并成为最终 manifest 唯一加载的反射 package。两者通过 stable ID 子集和独立 hash provenance 绑定。

P43.4 再缓存第一次完整 Profile 分析结果，消除双遍构建的重复成本。

## 正确性边界

- export 是游戏生命周期入口，所有正式可加载 C# 脚本必须至少有一个 export；
- CFG 中不可达 block 不贡献调用边；
- property 解析在多个候选 accessor 时保守纳入所有匹配项，不能静默漏掉依赖；
- 未解析到 callable 的普通符号不自动视为 host import；现有 Semantic/Guest 支持策略继续负责失败关闭；
- reachable import 顺序固定为 module、name、method symbol ID，保证 JSON 与缓存 key 确定。

## 阶段拆分

### P43.3A：语义与 WASM import 裁剪

- Semantic schema v5 与 reachability；
- Guest 函数/import 过滤；
- binding package 子集授权；
- 构建报告记录 used stable IDs；
- 证明示例脚本只保留两个动态 UE import。

### P43.3B：最小运行时 package

- stable ID 到完整 Profile selection 的生成式映射；
- slice descriptor/facade/manifest 内容寻址发布；
- 编译授权 package 与运行时 package 分离；
- Editor bootstrap、slice 生成、final build 两阶段编排；
- 零动态 binding 时沿用无 runtime package 路径；
- 运行时只缓存 slice invocation plan；
- 完整 BeginPlay/Tick 与篡改拒绝回归。
