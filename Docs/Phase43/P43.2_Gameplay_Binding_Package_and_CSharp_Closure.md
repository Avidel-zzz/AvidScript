# P43.2 Gameplay Binding 包与 C# 完整闭环

## 阶段结论

P43.2 已把 P43.1 的声明式 Gameplay Profile 接入默认自定义 C# 构建。当前源码版 UE5.8 上，普通自定义脚本在未显式指定 `binding_package_path` 时，会自动获得：

- `avidscript.engine.gameplay` 内容寻址绑定包；
- Actor 与 SceneComponent 的 115 个可兼容反射函数；
- 由同一 descriptor 生成的 C# facade、WAMR import 与缓存 ProcessEvent 调用计划；
- BeginPlay、Tick、EndPlay、Timer 和 Gameplay Event 生命周期出口。

原八函数 `avidscript.engine.core` 包及 `PublishDefault()` 仍保留为兼容入口。显式绑定包路径始终覆盖 Editor 默认选择。

## 生成与发布架构

`FAvidScriptEditorCSharpBindingEmitter` 新增：

- `EmitEngineGameplay()`；
- `PublishEngineGameplay()`。

Default 与 Gameplay 两类包共用 `PublishGeneratedPackage()`：

1. descriptor、reference source 和 manifest 先完整生成；
2. 三个文件写入独立 staging 目录；
3. manifest SHA-256 作为最终内容地址；
4. 已存在目录必须逐字节匹配，否则以 `package_conflict` 失败；
5. 并发发布命中同一内容地址时复用已提交的不可变包。

这避免了两套发布事务和错误处理逐渐漂移。

## 真实兼容性结果

115 个 binding 的 facade 探针一次成功，没有出现：

- C# 类型名碰撞；
- Actor/SceneComponent handle 固有成员碰撞；
- 参数投影后的重载签名碰撞。

因此本阶段没有引入自动重命名，也没有删除函数。后续发现碰撞时仍返回结构化错误；在别名兼容规则正式定义前，不静默改变用户 API 名称。

## Ref/Out Flow Capture 修复

完整 facade 第一次进入 Guest IR 时暴露了真实编译缺口：Roslyn 会把 `GetActorBounds(..., out FVector, out FVector, ...)` 的引用参数投影为 `flow_capture_reference`。旧 lowering 只保存捕获值，无法恢复其可寻址来源，报错：

```text
ASCG1004: Block 7 operation 'flow_capture_reference' is not addressable.
```

修复后的 `CSharpFunctionLoweringContext` 同时记录 flow capture 的值存储与可选地址来源：

- 捕获普通值时沿用原有 local load/store；
- 捕获 local 并作为 ref/out 使用时生成该 local 的地址；
- 捕获 ref/out parameter 时直接转发调用者地址，不复制成临时值地址；
- 同一 capture 改变地址目标时失败关闭。

该能力属于通用 C# lowering，不包含 `GetActorBounds` 或 UE 类型专用分支。

## 已验证闭环

- Gameplay descriptor、facade、manifest：115/115 binding，重复生成字节一致；
- 内容寻址发布：首次提交与重复复用通过；
- C# Guest 回归：17/17；
- `CustomProfileSmoke`：Roslyn、Semantic、Guest IR、WASM backend 全链路通过；
- `GeneratedCSharpLifecycle`：运行时加载 115 个动态 import；
- BeginPlay/Tick：真实修改 UE Actor scale；
- 篡改 descriptor SHA-256：以 `binding_package_hash_mismatch` 拒绝加载；
- `CSharpBindingEmitter` 自动化：4/4；
- 架构门禁：通过。
- UE5.8 完整 `AvidScript` 自动化：160/160，非成功结果 0，队列正常结束；
- 自动化启动前仍有 UE UnifiedError 自测的 13 条既有日志，不计入 AvidScript 结果。

## 当前限制

P43.2 的 executable reference source 会把完整 facade 投影到 Guest IR，因此使用两个 API 的脚本目前也会携带整个 115 import 包。运行行为正确，但编译产物体积和实例化成本还不是最终形态。

P43.3 将从 Roslyn 实际调用符号派生每脚本 binding slice，并从同一 Profile 重新生成最小 descriptor、facade 与运行时包。裁剪依据来自语义图，不维护逐函数手写列表。
