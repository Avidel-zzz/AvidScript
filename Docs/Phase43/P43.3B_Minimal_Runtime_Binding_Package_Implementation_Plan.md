# P43.3B 最小运行时 Binding Package 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 让自动生成的 C# Gameplay 脚本以完整 115 binding package 作为编译授权，同时让最终 manifest 和 Runtime 只加载生命周期实际使用的最小 binding package。

**架构：** Editor 先用完整 package 在隔离 bootstrap 目录构建并读取 stable ID 使用集合，再由独立 Slice Service 生成内容寻址的 runtime package，最后以“完整 authorization facade + 最小 runtime package”执行正式构建。显式项目 package 保持单遍；零动态 binding 不生成空 package。

**技术栈：** UE5.8 C++、UE Reflection、Roslyn Semantic schema v5、C# Guest IR、PowerShell 构建编排、WAMR Runtime、UE Automation。

## 全局约束

- 源码引擎固定为 `C:\UnrealEngine`，只做低并发增量编译，禁止清理 Editor Target。
- 人读文档使用中文。
- 不扫描 C# 文本、不手写 UE API 表、不复制 descriptor renderer 或 package publisher。
- stable ID 是跨完整 package 与 slice package 的唯一映射身份；ordinal 只在各自 package 内有效。
- 自动切片只用于“自定义源码且未显式指定 `BindingPackagePath`”。
- 两份用户自有文档不得修改、暂存或提交。
