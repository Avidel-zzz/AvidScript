# P43 可扩展 UE 反射 API 面架构

状态：设计完成，依据持续推进授权进入实现

## 背景

P42 已打通以下完整链路：

```text
C# 游戏逻辑
  -> Roslyn semantic
  -> Guest IR
  -> WASM
  -> Binding Package
  -> WAMR 动态 import
  -> 缓存 ProcessEvent 调用计划
  -> UE Actor
```

当前主要限制不再是“能否调用 UE”，而是默认 Binding Package 仍由八个手工函数组成。若继续逐个添加 API，会重复 Puerts、UnLua 等方案长期维护手写绑定表的成本，也无法向用户解释某个 UFunction 为什么没有进入脚本表面。

## 方案比较

### 方案 A：全引擎无差别扫描

扫描所有已加载 `UClass` 和 `UFunction`，自动生成一个巨型包。

优点是表面覆盖最大。缺点是包体、生成耗时、API 稳定性、Editor-only 污染和 C# 名称冲突都难以控制，不适合作为移动端与项目增量构建的基础。

### 方案 B：继续维护函数白名单

保持 `MakeDefaultSelections()`，按需求逐个增加函数。

优点是短期稳定。缺点是扩展成本与 API 数量线性增长，无法达到成熟脚本方案所需的覆盖面，因此不采用。

### 方案 C：声明式 Profile 加兼容性解析器

Profile 声明类边界、显式函数和 include/exclude 过滤器。Resolver 批量发现候选函数，并通过统一函数策略与类型策略得到可接受选择和结构化拒绝原因。

该方案兼顾覆盖、确定性、可审计性和后续增量生成，作为 P43 的正式方向。

## 核心边界

### Selection Types

只保存声明式输入和解析结果，不访问 UE 反射：

- `FAvidScriptReflectedFunctionSelection`：精确的类路径与函数名；
- `FAvidScriptReflectedClassSelection`：类路径、include 和 exclude；
- `FAvidScriptBindingSelectionProfile`：包名、类规则和显式函数；
- `FAvidScriptBindingSelectionIssue`：严重性、稳定类别和来源；
- `FAvidScriptBindingSelectionResolveResult`：候选数、接受数、拒绝数和问题列表。

### Function Policy

负责 UFunction 级别的资格判断：

- 必须是 `BlueprintCallable` 或 `BlueprintPure`；
- 排除 Editor-only、delegate、网络请求/响应、latent 和 custom thunk；
- 不负责参数类型投影。

该策略从 descriptor generator 中抽离，Resolver 与 Generator 必须共用同一实现。

### Selection Resolver

负责把 Profile 解析成确定性精确选择：

1. 加载每个类路径；
2. 只枚举该类声明的函数，不重复继承函数；
3. 应用 include/exclude；
4. 应用 Function Policy；
5. 使用 `FAvidScriptEditorReflectedTypePolicy` 验证完整签名；
6. 按 `OwnerClassPath.FunctionName` 排序并去重；
7. 返回接受列表和结构化兼容性问题。

显式函数代表用户明确意图，默认严格失败。类扫描中的不兼容函数属于兼容性报告，不阻止其他函数生成。

### Descriptor Generator

现有 `Generate()` 保持严格语义和向后兼容。新增 `GenerateFromProfile()`：

```text
Profile
  -> Resolver
  -> accepted exact selections
  -> existing deterministic Generate()
```

Descriptor schema v2、稳定 ID、package hash 和 ABI 规则均不改变。

## 分阶段交付

### P43.1：选择解析与兼容性报告

- 提取 Function Policy；
- 实现声明式 Profile 与 Resolver；
- 实现 `GenerateFromProfile()`；
- 提供 Actor 与 SceneComponent 的 gameplay profile；
- 验证批量发现、过滤、拒绝原因和确定性。

### P43.2：Gameplay 包与 C# 完整闭环

- 对完整 facade 执行类型名、成员名和重载签名探针；
- 在没有真实冲突时保持 UE ScriptName，不提前改变公共 API；
- 将默认自定义 C# 构建切换到 115 函数 gameplay profile；
- 修复完整 facade 暴露的通用 ref/out flow capture lowering；
- 保留八函数兼容入口和显式绑定包优先级。

### P43.3：按脚本语义裁剪 Binding Slice

- 从 Roslyn semantic artifact 收集脚本实际使用的 generated callable；
- 计算调用闭包和所需 UE binding stable ID；
- 从同一 Profile 派生最小 descriptor、facade、manifest 与运行时包；
- 让未使用 API 不进入 Guest IR、WASM imports 和运行时 invocation plan；
- 记录完整 Profile 与脚本 slice 的双重 provenance。

### P43.4：项目配置与增量生成

- 从项目配置文件加载 Profile；
- 内容哈希缓存类反射快照、语义使用集合与兼容性报告；
- 仅在 Profile、相关反射签名或调用集合变化时重新发布包；
- Editor 展示接受、跳过、裁剪和失败原因。

### P43.5 及后续：类型面扩展

按共享类型策略扩展 `FName`、`FString`、软/弱对象引用、数组、集合、常用 Gameplay struct 和委托事件。每种类型只实现一次 descriptor、VM frame、C# facade 与运行时 marshalling，不为单个 UE API 编写专用桥接。

## 错误语义

- `profile_empty`：没有类规则或显式函数；
- `duplicate_class_rule`：同一路径出现多次类规则；
- `class_missing`：类路径无法解析；
- `function_missing`：显式 include 或显式函数不存在；
- `function_not_callable`：不是脚本可调用函数；
- `function_not_allowed`：命中运行时安全排除规则；
- `unsupported_property`：返回值或参数尚无共享类型投影；
- `duplicate_selection`：解析后出现重复精确选择。

错误类别是工具、Editor UI 和 CI 的稳定契约，不依赖自然语言消息做判断。

## 性能原则

- Profile 限制反射扫描边界，不扫描全部已加载类型；
- 只枚举类自身声明的 UFunction，避免继承链重复；
- Resolver 不序列化临时 descriptor，也不启动子进程；
- 输出稳定排序，后续可直接接入内容哈希缓存；
- 运行时仍只加载最终精确 descriptor，不携带 Editor Profile 或兼容性报告。

## P43.1 验收标准

- 相同 Profile 在同一 UE5.8 反射快照上产生完全相同的选择顺序和 descriptor；
- gameplay profile 接受的函数数量明显大于当前八函数白名单；
- `K2_GetActorLocation`、`SetActorScale3D` 等已验证 API 保持可用；
- `K2_SetActorLocation` 等含未支持签名的函数被报告而不破坏其他发现结果；
- 显式缺失函数和无效类路径继续失败关闭；
- 不新增手写运行时 UE API dispatcher。
