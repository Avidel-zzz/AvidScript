# P43.1 选择 Profile 与兼容性报告

状态：已完成

## 本阶段解决的问题

P42.5 已经允许 C# 通过 WASM 和动态反射绑定调用 UE，但默认包仍只包含八个手工函数。P43.1 新增声明式类 Profile 与兼容性解析器，让 API 覆盖面由 UE Reflection 和共享类型策略共同决定，不再依赖逐函数维护列表。

本阶段没有替换默认八函数包。原因是批量 descriptor 虽然已经确定性生成，C# facade 的成员名和重载碰撞仍需要在 P43.2 进入统一预检；在此之前保持默认包稳定，可以避免 Editor 自动构建流程产生不可控变化。

## 代码结构

### 数据契约

`AvidScriptEditorBindingSelectionTypes.h` 只包含无反射逻辑的数据结构：

- `FAvidScriptReflectedFunctionSelection`：精确函数选择；
- `FAvidScriptReflectedClassSelection`：类边界、include 与 exclude；
- `FAvidScriptBindingSelectionProfile`：包名、类规则和显式函数；
- `FAvidScriptBindingSelectionIssue`：稳定拒绝类别与来源；
- `FAvidScriptBindingSelectionResolveResult`：候选、接受、拒绝计数和问题列表。

运行时不依赖这些 Editor Profile 类型。最终仍只加载 descriptor v2 和由它产生的不可变 Binding Package。

### 函数策略

`AvidScriptEditorReflectedFunctionPolicy` 从 descriptor generator 中抽离，统一判断 UFunction 是否具备脚本调用资格：

- 接受 `BlueprintCallable` 与 `BlueprintPure`；
- 拒绝 Editor-only、delegate、网络请求/响应、latent 与 custom thunk；
- 参数和返回类型交给现有 `AvidScriptEditorReflectedTypePolicy`。

Generator 与 Resolver 共用同一策略，避免批量发现和精确生成出现判断漂移。

### 选择解析器

`AvidScriptEditorBindingSelectionResolver` 执行以下流程：

```text
Profile
  -> 排序类规则
  -> 加载 UClass
  -> 仅枚举类自身声明的 UFunction
  -> include/exclude
  -> Function Policy
  -> Reflected Type Policy
  -> 稳定排序的 accepted selections + issues
```

类扫描中的不兼容函数会进入报告，但不会阻止同类中的其他兼容函数。显式函数代表用户明确意图，默认严格失败并清空部分结果。

### Descriptor 接线

`FAvidScriptEditorBindingDescriptorGenerator::GenerateFromProfile()` 先调用 Resolver，再把精确选择交给原有 `Generate()`。因此以下契约没有改变：

- descriptor schema 仍为 v2；
- canonical identity 与 stable ID 规则不变；
- selection hash 与 package hash 仍是确定性的；
- WAMR import 和运行时 ProcessEvent 调用计划不增加专用分支。

## 使用示例

```cpp
const FAvidScriptBindingSelectionProfile Profile =
    FAvidScriptEditorBindingDescriptorGenerator::MakeEngineGameplayProfile();

TArray<FAvidScriptReflectedFunctionSelection> Selections;
FAvidScriptBindingSelectionResolveResult ResolveResult;
if (!FAvidScriptEditorBindingSelectionResolver::Resolve(
        Profile,
        Selections,
        ResolveResult))
{
    // 使用 ErrorCategory、ErrorSource 和 Issues 做工具诊断。
}
```

直接生成 descriptor：

```cpp
FString DescriptorJson;
FAvidScriptBindingSelectionResolveResult SelectionResult;
FAvidScriptBindingDescriptorGenerateResult DescriptorResult;
const bool bGenerated =
    FAvidScriptEditorBindingDescriptorGenerator::GenerateFromProfile(
        Profile,
        DescriptorJson,
        SelectionResult,
        DescriptorResult);
```

自定义类规则中，`IncludeFunctions` 为空表示扫描该类全部声明函数；`ExcludeFunctions` 始终优先。显式函数通过 `ExplicitFunctions` 增加，`bStrictExplicitFunctions` 默认为 `true`。

## 实际覆盖规模

在当前源码版 UE5.8 上，内置 gameplay profile 选择 Actor 与 SceneComponent 两个类边界：

- 候选 UFunction：221；
- 当前类型策略直接接受：115；
- 结构化跳过：106；
- 原默认包：8。

接受面已经覆盖位置、旋转、缩放、组件访问以及大量使用 scalar、enum、object handle、FVector、FRotator 和 FTransform 的函数。被跳过项主要涉及尚未支持的复杂 struct、字符串、容器和特殊调用语义。

这 115 个函数来自同一套通用 descriptor、ABI、frame marshalling 和缓存 ProcessEvent 路径，没有新增 115 个手写 runtime API。

## 错误类别

- `package_name_missing`：Profile 没有稳定包名；
- `profile_empty`：没有类规则或显式函数；
- `duplicate_class_rule`：同一类路径重复；
- `class_missing`：无法解析类路径；
- `function_missing`：include 或显式函数不存在；
- `function_not_callable`：UFunction 不具备脚本调用 flag；
- `function_not_allowed`：命中安全排除规则；
- `unsupported_property`：签名包含尚未支持的共享类型；
- `duplicate_selection`：类发现与显式函数重叠。

## 验证结果

- UE5.8 AvidScriptEditor 增量编译：通过；
- `AvidScript.Editor.BindingSelection`：4/4；
- 架构门禁：通过；
- 完整 `AvidScript` 自动化：159/159，非成功结果 0，队列正常结束；
- gameplay profile 重复解析与重复 descriptor 生成：字节和顺序确定性通过。

自动化启动前出现的 13 条 `LogAutomationTest: Error: Condition failed` 来自 UE 自身 UnifiedError 启动自测；P42.5 两份基线日志有相同数量和相同位置，不属于 AvidScript 测试结果。

## 下一阶段

P43.2 将把生成 C# 的以下问题前移到兼容性解析阶段：

- C# 类型名碰撞；
- handle 固有成员与 UE 方法名碰撞；
- ScriptName 与参数类型映射后的重载签名碰撞；
- 稳定别名与显式重命名。

通过 descriptor 与 facade 双重预检后，Editor 默认自动发布才能从八函数包切换到扩展 Profile。
