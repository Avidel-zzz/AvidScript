# P43.4 Prepared Semantic 复用完成报告

> 状态：已完成并通过源码版 UE5.8 Win64 Editor 全量验证

## 1. 阶段目标

P43.3B 的自动自定义 C# 构建需要执行 bootstrap 与 final 两次构建。两遍使用相同 C# 源码和完整 authorization package，区别只在 final 使用裁剪后的 runtime package，因此第二次 Roslyn Frontend 与 Semantic 分析属于重复工作。

P43.4 在不削弱双包安全边界的前提下，让 final 复用 bootstrap 已验证的 Frontend/Semantic 产物。Guest IR、WASM Backend、authorization/runtime 子集校验和正式发布仍在 final 重新执行。

## 2. 已实现闭环

自动自定义 C# 构建现在执行以下流程：

1. BuildService 发布完整的 engine gameplay authorization package。
2. bootstrap BuildOnce 执行 Frontend、Semantic、Guest IR 和 WASM，生成 prepared report。
3. BindingSliceService 根据实际可达 stable ID 集合发布最小 runtime package。
4. final BuildOnce 验证 prepared report、源码、authorization identity、artifact 路径和 SHA-256。
5. Frontend/Semantic 被事务式复制到 final output，final 不再启动这两个 Roslyn 阶段。
6. final 重新执行 Guest IR、WASM Backend、双包子集校验，并发布正式 report、manifest 与 WASM。
7. BuildService 返回后删除本次调用的 bootstrap 临时目录。

`build_reuse.prepared_report_file` 和 `prepared_report_sha256` 是复用审计来源。它们可以记录本次调用内的临时 bootstrap report；`artifacts.*` 与 manifest 中的可加载产物路径只指向 final output，不依赖已删除的 bootstrap artifact。

## 3. 调用次数变化

| 构建路径 | BuildOnce | Frontend | Semantic | Guest IR | WASM Backend |
| --- | ---: | ---: | ---: | ---: | ---: |
| P43.3B 自动模式 | 2 | 2 | 2 | 2 | 2 |
| P43.4 自动模式 | 2 | 1 | 1 | 2 | 2 |
| 显式 package 单遍模式 | 1 | 1 | 1 | 1 | 1 |

自动模式中的 Frontend 与 Semantic 调用数各减少 50%。本阶段没有把不稳定的本机墙钟时间写成性能承诺，稳定可验证指标是进程调用计数和产物契约。

## 4. 可信复用条件

Prepared Semantic helper 只做验证与复制，不启动 dotnet/powershell，不读取 C# 源文本，也不决定 package 策略。复用必须同时满足：

- prepared report 为 schema 1、`direct_abi_built`、`succeeded=true`；
- 当前源码路径和 SHA-256 与 report 完全一致；
- authorization package name/hash、manifest、descriptor、reference source 及 used imports 身份完全一致；
- Frontend/Semantic 源 artifact 均位于 prepared `output_root` 内；
- report 中的 artifact SHA-256 与文件实际内容一致；
- Frontend schema 1/version 1.0 与 Semantic schema 5/version 1.5 provenance 一致；
- final destination 使用同目录临时文件和双文件事务发布；
- prepared report 与 final report 不允许自引用。

任一条件失败都返回 `prepared_semantic_invalid`，不静默退回第二次完整 Roslyn 分析，也不保留可加载 manifest/WASM。

## 5. 失败分类

| 诊断码 | 含义 |
| --- | --- |
| `ASBI4401` | 源码路径或 SHA-256 不一致 |
| `ASBI4402` | authorization package 或 used import 身份不一致 |
| `ASBI4403` | report、schema、artifact 或 SHA-256 无效 |
| `ASBI4404` | artifact 路径逃逸、report 自引用等路径契约失败 |

双文件复制具备回滚语义。即使第二个 final artifact 发布失败，也会恢复替换前状态，不留下 Frontend/Semantic 半更新组合。

## 6. UE 交互实测

`AvidScript.Editor.BindingRuntime.GeneratedCSharpLifecycle` 在真实 WAMR 和 UE 世界中验证了完整链路：

- 自动构建计数为 `Build=2 / Frontend=1 / Semantic=1`；
- authorization package 包含 115 个生成绑定；
- runtime package 只保留 2 个实际可达绑定；
- 最终 WASM 保留 2 个 `avid_ue_*` 动态反射导入；
- C# `BeginPlay` 通过生成的 `UE.Self` binding 修改 Actor 的 `FVector` scale；
- C# `Tick` 通过 Runtime Session 和 live scheduler 读取并更新该 `FVector`；
- 被篡改的 binding descriptor hash 仍以稳定类别拒绝加载。

这说明复用没有绕开 UE 生命周期、对象句柄、反射绑定、WASM guest memory 或 runtime package 校验。

## 8. 架构边界

- BuildService：拥有自动/显式 package 策略、bootstrap/final 编排和计数聚合。
- BuildInvoker：只规范化一次 PowerShell 构建调用并透传 prepared report 参数。
- PreparedSemantic helper：只验证 prepared provenance 并事务发布两个 semantic artifact。
- BindingSliceService：只根据 stable ID 集合生成最小 runtime package。
- BuildCSharpActorLifecycle：继续拥有 Guest IR、WASM、双包校验和正式发布流水线。

架构门禁已经编码这些职责，防止后续把 Roslyn 调用、源码扫描或 package 决策塞进 helper。

## 9. 后续边界

P43.4 只在一次 BuildService 调用内复用 prepared semantic，不包含：

- 跨 Editor 会话的内容寻址持久缓存；
- 工具链版本指纹、缓存驱逐和损坏恢复；
- Guest IR 或 WASM artifact promotion；
- Cook、移动端或 packaged build 缓存验证；
- 常驻后台编译服务。

下一阶段应把当前 provenance 协议提升为内容寻址缓存键，并先验证并发发布、工具链失效和损坏回退，再考虑复用 Guest IR/WASM。这个方向能继续降低迭代时间，同时保持现有 fail-closed 安全边界。
