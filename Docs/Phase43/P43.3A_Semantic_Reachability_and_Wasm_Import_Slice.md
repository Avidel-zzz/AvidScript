# P43.3A 语义可达性与 WASM Import 裁剪

## 阶段结论

P43.3A 已把完整 Gameplay Profile 从“每个脚本必须携带的 import 全集”改成“脚本允许使用的授权上界”。Roslyn Semantic 从六个生命周期 export 出发计算调用闭包，Guest IR 和 WASM 只保留闭包内实际使用的 host import。

`GeneratedBindingLifecycleScript.cs` 的实测结果：

| 指标 | P43.2 | P43.3A |
| --- | ---: | ---: |
| Gameplay Profile binding | 115 | 115 |
| Semantic reachable callable | 作为全量投影 | 15 |
| Semantic reachable import | 115 个动态 import 加运行时 import | 4 |
| WASM 动态 UE import | 115 | 2 |

两个动态 import 分别对应 `GetActorScale3D` 和 `SetActorScale3D`。`UE.Self` 属性 getter 所需的 `owner_get_slot` 与 `owner_get_generation` 仍作为两个 `env` import 保留。

## Semantic Schema v5

Semantic contract 从 schema v4 / semantic 1.4 升级到 schema v5 / semantic 1.5，新增 `reachability`：

- `mode`：正式脚本为 `export_roots`；无 export 的分析输入为 `all_callables_compatibility`；
- `root_callable_ids`：全部 WASM export method stable ID；
- `reachable_callable_ids`：递归调用闭包；
- `reachable_imports`：闭包内 import 的 method ID、module 与 name。

闭包计算位于独立 `SemanticReachabilityProjector`，遍历 Roslyn 已绑定的 CFG symbol ID。普通 method、构造函数、运算符、转换和 property accessor 共享同一条 symbol 解析路径，不读取 C# 文本，也不认识 UE API 名称。

## Guest IR 消费

Schema 5 产物进入 Guest 前会验证：

- roots 与 reachable IDs 唯一且稳定排序；
- root 必须是 export 且属于 reachable 集合；
- reachable ID 必须存在于 callable 集合；
- reachable import 必须与 reachable callable 的 import 精确一致；
- compatibility 模式必须覆盖全部 callable。

验证通过后，Guest 只降低 reachable function 和 import。Schema 4 历史/测试产物没有 reachability 时继续降低全部 callable，兼容路径没有被隐式改变。

## Package 子集授权

`package.json.required_imports` 现在作为授权集合。正式构建执行：

1. 验证 package、descriptor 与 facade 的 hash 和 identity；
2. 从 Guest IR 读取实际 `avidscript.*` import；
3. 每个实际 import 必须存在于 package 授权集合；
4. 未使用的 package import 不再触发 mismatch；
5. report 与 script manifest 写入命中的 stable ID、ordinal、module、name 和 signature。

未知动态 import 仍以 `ASBI4203` 拒绝，裁剪没有放宽脚本权限。

## 当前边界

P43.3A 的运行时 manifest 仍引用完整 `avidscript.engine.gameplay` package，因此 Runtime 会解析并缓存 115 个 invocation plan。WASM 已经只导入两个，但 package 体积和运行时计划尚未同步收缩。

P43.3B 将消费 `used_imports[].stable_id`，由 Editor 从同一 Profile 重新生成最小 descriptor、facade 和内容寻址 package，再用 slice facade 做最终 Semantic 编译。完成 P43.3B 后，WASM import、运行时 package 和 invocation plan 才会全部使用同一个两函数 slice。
