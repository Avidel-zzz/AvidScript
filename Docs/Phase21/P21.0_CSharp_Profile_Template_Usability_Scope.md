# P21.0 C# Profile Template And Usability 范围

## 目标

Phase20 已经能从默认 C# profile JSON 执行 build-and-bind, 但用户仍需要手写整个 `default.csharp-profile.json`。Phase21 的目标是补上最小可用性层: Editor/service 能生成一个默认 C# profile 模板, 用户只需要修改 `source_path` 或直接使用默认 ActorLifecycle 样例验证链路。

这一阶段优先解决“我第一次怎么得到一份正确的 C# profile 文件”。

## 交付内容

- 扩展 C# profile service, 支持写入默认 profile 模板。
- 模板默认指向插件内的 `Samples/CSharp/ActorLifecycle/ActorLifecycleScript.cs`。
- 模板使用独立的 profile module/artifact/output root, 避免和固定 ActorLifecycle 构建入口互相覆盖。
- 写入逻辑默认不覆盖已有 profile, 防止误删用户已编辑的 JSON。
- Editor module 增加“创建/确保默认 C# profile”入口配置。
- 自动化覆盖模板生成、幂等不覆盖、生成后可被 `LoadProfile(...)` 读取。

## 默认模板策略

默认 profile path:

```text
Saved/AvidScriptCSharpProfiles/default.csharp-profile.json
```

默认 source:

```text
Plugins/AvidScript/Samples/CSharp/ActorLifecycle/ActorLifecycleScript.cs
```

默认 module/artifact:

```text
module_id: csharp_profile_actor_lifecycle
artifact_stem: profile_actor_lifecycle
```

默认 output root:

```text
Saved/AvidScriptCSharpGuest/Profiles/profile_actor_lifecycle
```

## 本阶段边界

- 不做 Slate 文件选择器。
- 不做 profile 列表管理。
- 不覆盖用户已有默认 profile, 除非显式传入 overwrite。
- 不扩大 C# source adapter 语法子集。
- 不做 packaging/mobile 验证。

## 验收标准

- profile service 能写出默认 C# profile JSON。
- 第二次生成默认 profile 时默认不覆盖已有文件。
- 生成的 profile 能被 `LoadProfile(...)` 读取并映射到有效 build config。
- Editor module 提供稳定菜单 entry config 和可测试 API。
- `AvidScriptEditor` module build、相关 Editor 自动化和完整 `AvidScript` 自动化通过。
