# P59.D5b Generated Type Editor 热重载路由

## 目标

把 D5a 的 Runtime 事务核心接到真实 C# 类型生成流程。开发者重新运行
`BuildCSharpScriptTypes.ps1` 后，Editor 自动识别方法体变化并更新活跃实例；反射结构变化不会误入热重载，
而是明确要求 native rebuild。

## 分层

- `AvidScriptGeneratedTypeReloadClassification.ps1`：根据生成 Header/CPP 的路径、内容哈希和长度计算
  `native_structure_sha256`，不解析或猜测 C# 文本。
- `FAvidScriptEditorGeneratedTypeReloadPolicy`：验证 descriptor schema、结构指纹与 package 链，并把
  `body_only` 调用到 `ReloadPackageFromDescriptorFile`。
- `FAvidScriptEditorGeneratedTypeReloadService`：监听原子发布的 package descriptor，在 Game Thread
  合并文件事件、去重 package id、拒绝断裂的 previous-package 链。
- Runtime Host：继续重新比较真实 Registry shape；构建分类只决定冷路径路由，不构成执行授权。

解析、应用策略和文件监听分别拥有独立文件，Editor module 只负责创建与销毁 watcher，Runtime module
不反向依赖 Editor。

## Descriptor 合同

package descriptor 新增 `reload`：

```json
{
  "schema_version": 1,
  "classification": "body_only",
  "native_structure_sha256": "...",
  "previous_native_structure_sha256": "...",
  "previous_package_id": "..."
}
```

分类只有三种：

- `initial_install`：没有可验证的旧 package；
- `body_only`：前后 native shell 身份完全相同；
- `native_rebuild_required`：生成 Header/CPP 任一身份发生变化。

旧 descriptor 没有 `reload` 时，构建脚本会验证旧 type manifest 哈希并计算一次兼容基线。新 descriptor
已内嵌结构指纹，因此即使上次构建中途失败，也可以保留上一代发布身份用于下一次分类。

## Editor 行为

1. Editor 启动时记录 `AvidScriptGenerated` 已安装的 package id，不重复安装；
2. watcher 只消费最终 descriptor 路径，忽略临时文件和无关输出；
3. 同一 Tick 的重复文件事件合并，相同 package id 直接忽略；
4. `previous_package_id` 必须等于服务记录的当前 package，否则拒绝过期或乱序发布；
5. `body_only` 调用 D5a 多实例事务；
6. `native_rebuild_required` 不触碰 Runtime，报告 no-clean UE5.8 UBT 与 Editor restart；
7. Runtime 若发现构建分类遗漏的 shape drift，仍升级为 `NativeRebuildRequired`。

## 验证

- PowerShell 分类合同：`PASS`，覆盖 initial/body-only/structural、legacy baseline 和内嵌基线；
- 真实 `ScriptDefinedTypes.cs` 生成链：5 个类型，输出
  `native_structure=24ca9f93...beff22`、`reload_classification=body_only`；
- UE5.8 no-clean `AvidScriptEditor` 增量构建：成功；
- `AvidScript.Editor.GeneratedTypes.ReloadService`：`1/1 Success`，覆盖事件合并、重复包、结构路由、
  rescan 与 stale chain 拒绝；
- 架构门禁新增构建分类、Editor policy 与 Runtime 二次验证合同。

## 使用边界

方法体变化现在可在 Editor 运行期间自动更新。新增/删除类型、属性、函数，改变签名、继承、反射 flag、
ordinal 或生成 ABI 时仍需执行受控 no-clean UBT 并重启 Editor；本节不尝试原地重建 `UClass`。
