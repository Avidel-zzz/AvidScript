# P59.0 LLVM AOT 后端实施计划

## 目标

以 PC-first 的 WasmEdge LLVM AOT 候选解决 `P57-D06-ControlledLeadership`，同时保持
WASM-first、backend-neutral、可验证 artifact 和移动端回退边界。

## P59.A 决策型可行性

- 锁定 WasmEdge 0.17.x source/release、license、LLVM/runtime/compiler 身份和 Win64 产物 SHA-256；
- 用仓库外下载/构建缓存生成可复现 SDK，仓库只保留 lock、metadata 和 build recipe；
- 完成最小 C API 实例：加载 Universal AOT、注册 typed host import、读写 guest memory、调用 export、trap；
- 定义 AOT manifest/schema/cache key 和负向身份用例；
- 在不修改 kernel 的前提下运行冻结 12-kernel 矩阵；
- 若不具备性能或 host/artifact 可行性，立即转向 Wasmer LLVM，不开始 UE adapter。

## P59.B VM backend

- 扩展 backend/artifact enum 与工厂，保持 Runtime/Bindings 零 WasmEdge 类型泄漏；
- 实现 config/engine/store/module/instance 所有权与失败清理；
- 复用现有 static/dynamic/typed import 注册语义；
- 实现 guest memory view、export handle generation、prepared call、trap/stack diagnostic；
- 只接受 `VerifiedPackage` AOT artifact，身份不一致 fail-closed；
- 添加 backend 合同与关键负向用例，不为每个 API 手写测试。

## P59.C 产物与 Runtime

- 实现 canonical WASM -> LLVM AOT 的受控 sidecar，不在 UE Runtime 内编译；
- 实现原子发布、内容寻址缓存和 manifest/schema 验证；
- 实现 Win64 `Auto/Aot` selection，缺失产物时按显式 policy 回退；
- 接入 BeginPlay/Tick/event 现有 Session 生命周期，不建第二套 scheduler；
- 固化 Cook/stage 文件范围，Shipping 不携带 compiler；
- 冻结 Linux/mobile manifest 兼容性，但不将 Android 解释器写成 AOT 支持。

## P59.D 集中 Gate

- 一次集中代码/架构/所有权/安全审查；
- 受影响 .NET/PowerShell/backend 合同；
- UE5.8 `AvidTPSTemplateEditor Win64 Development` no-clean 构建；
- 完整 `Automation RunTests AvidScript`；
- 冻结 12-kernel 矩阵，报告 p50/p95/MAD/胜率/correctness/fallback；
- 干净候选、架构 Gate、attestation、close 和逐小节远端提交。

## 验证预算

- UBT：2 次；
- UE Automation：2 次；
- 完整 Gate：2 轮；
- P59.A 在仓库外运行 compiler/runtime 探针和冻结 benchmark，不计入 UE Automation 启动。

## 小节提交

每个可独立审查的架构、依赖锁定、backend、artifact pipeline、Runtime 集成或 Gate 小节，
在本小节集中验证后精确白名单提交并立即推送 `origin/main`。单条命令、一次下载或
单个测试不制造碎片提交。
