# P59 C# 脚本定义 UE 类型实施计划

## 目标

让 C# 声明的 Actor、Component 和 Subsystem 成为真实 UE 反射类型，支持属性、函数、继承、覆写和
Blueprint 子类，同时保持 WASM-first、Session-owned、backend-neutral 和 fail-closed。

## P59.A 语义声明合同

- 在 generated facade 中加入规范 `[UClass]`、`[UProperty]`、`[UFunction]` 与标记基类；
- Roslyn 投影 `ue_type_declarations`，稳定排序类型和成员身份；
- 解析 Actor/Component/WorldSubsystem/GameInstanceSubsystem 根类别与脚本继承；
- 规范化 class/property/function flags、category、replication 与 override 信息；
- 同步 semantic Schema、cache、prepared artifact、Guest validator 和架构检查；
- 高风险负向用例覆盖伪属性、非法继承、重复 engine name 和无效 member contract。

交付结果：确定性、可序列化、可验证的 UE Type Declaration Contract。此批次不生成 C++。

## P59.B UHT Shell 与生成模块

- 新建独立 Editor codegen owner，不把 C++ rendering 塞进 semantic 或 Runtime；
- 从验证合同生成 `.generated.h` 使用方、UCLASS/UPROPERTY/UFUNCTION 声明和统一 thunk；
- 生成 module manifest、输入 hash、输出 hash、UE/version identity；
- 原子发布到项目生成目录；缓存命中不启动 UHT/UBT；
- 用受控入口运行 no-clean UHT/UBT，并明确结构变化的 Editor reload 边界；
- 生成代码只引用稳定 Runtime dispatcher，不为每个 UE API 手写 wrapper。

交付结果：示例 C# Actor 产生可加载的真实 `UClass`。

## P59.C Runtime 类型与实例

- 实现 manifest/UClass 注册和双向稳定索引；
- 建立 UObject -> Session-owned script instance；
- 复用 ObjectHandle、prepared export、prepared codec 和 teardown fence；
- 接入 BeginPlay/Tick/EndPlay 与普通 UFUNCTION thunk；
- 实现脚本继承、override route、parent call 和 generation-safe reload；
- teardown 自动取消 continuation、async load、delegate 与 network callbacks。

交付结果：C# Actor/Component/Subsystem 可承载真实游戏逻辑。

## P59.D Blueprint 与集成 Gate

- Blueprint 以脚本 UClass 为父类创建、保存、重新加载和运行子类；
- 验证 BlueprintCallable/ReadWrite、默认值 owner、RepNotify 与 override；
- 验证 Actor、Component、WorldSubsystem、GameInstanceSubsystem 生命周期；
- body-only reload 与结构 rebuild/reload 路由准确；
- 集中执行 .NET、PowerShell、no-clean UE5.8 UBT、完整 Automation、架构检查和性能矩阵；
- 保留人工 PIE、Blueprint asset 和网络拓扑验收。

交付结果：形成从 C# 类型声明到 Blueprint/Runtime 游戏逻辑的完整闭环。

## 持续性能债务

LLVM AOT 研究不再占用 P59 主线。`P57-D06/P59-D01 ControlledLeadership` 转移到 P65 发布级门禁，
但 P59 每个 Runtime 热路径仍必须跑受影响 benchmark，禁止以“以后优化”为理由引入按名称查找、
重复反射或每调用分配。
