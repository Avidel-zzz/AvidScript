# P59.D4 Generated Type 四类生命周期闭环

## 目标

让 C# 脚本定义的 Actor、ActorComponent、WorldSubsystem 和 GameInstanceSubsystem 都能通过 UE 自己的
生命周期入口建立 Session、执行游戏逻辑并按 owner 销毁，重点补齐可实际调度的 Tick。

## Tick 自动启用

此前生成器可以输出 `Tick`/`TickComponent` override，但没有自动设置 Primary Tick。仅有虚函数并不能让
UE 帧循环调用脚本。

生成器 `1.6` 现在只为真正声明 Tick lifecycle 的两类对象写入：

```cpp
PrimaryActorTick.bCanEverTick = true;
PrimaryActorTick.bStartWithTickEnabled = true;
```

或：

```cpp
PrimaryComponentTick.bCanEverTick = true;
PrimaryComponentTick.bStartWithTickEnabled = true;
```

没有 Tick override 的类型不会生成这些设置，也不会承担额外每帧成本。WorldSubsystem 继续使用
`UTickableWorldSubsystem` 的原生调度合同。

生成器版本矩阵已同步到正式构建入口、Runtime Registry、架构门禁和固定测试夹具，避免旧生成缓存
被错误复用。

## C# 生命周期样例

- `Projectile`：`BeginPlay`、`Tick`、`EndPlay`；
- `HealthComponent`：`BeginPlay`、`Tick`、`EndPlay`；
- `EncounterSubsystem`：`Initialize`、`Tick`、`Deinitialize`；
- `ProfileSubsystem`：`Initialize`、`Deinitialize`。

每个入口只更新对应的 C# 声明 UPROPERTY 计数。状态仍由生成 UClass 的原生属性拥有，生命周期函数
通过既有 type/member ordinal、ObjectHandle 和 Session 路由进入 Wasmtime。

## 真实 UE 验证

`AvidScript.GeneratedTypes.CSharpLifecycleKinds` 执行：

1. 创建 Game World，获取自动初始化的 `UEncounterSubsystem`；
2. Spawn `AProjectile`，创建、挂接并注册 `UHealthComponent`；
3. 由 World BeginPlay 进入 Actor 与 Component 的 C# BeginPlay；
4. 执行一次真实 `World->Tick`，确认 Actor、Component、WorldSubsystem 均被 UE 调度到 C#；
5. 调用公开 `AActor::Destroy`，由 UE 触发 Actor 与 Component EndPlay；
6. 销毁 World，在 Session teardown 前执行 WorldSubsystem Deinitialize；
7. 创建独立 `UGameInstance` 与 dummy world，自动初始化 `UProfileSubsystem`；
8. 调用 `UGameInstance::Shutdown`，验证 GameInstanceSubsystem Deinitialize 后再清理 world/context。

测试使用 StrongObjectPtr 保留待验收对象，不直接调用 protected Actor EndPlay，也不为测试增加公开壳层 API。
