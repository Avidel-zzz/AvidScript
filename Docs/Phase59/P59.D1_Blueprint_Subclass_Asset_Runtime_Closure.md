# P59.D1 Blueprint 子类资产与 Runtime 闭环

## 目标

验证 C# 生成的原生 `UClass` 不只出现在反射表中，还能成为真实 Blueprint 资产的父类，并在资产
保存、卸载、重新加载和实例运行后继续进入 AvidScript Runtime。

## 实现边界

本节没有把 Blueprint/Kismet 依赖加入 Runtime。验证位于 `AvidScriptEditor` 的 Editor-only
Automation 中，通过反射加载 `/Script/AvidScriptGenerated.Projectile`，因此生成模块仍保持：

```text
AvidScriptGenerated -> AvidScriptRuntime
AvidScriptEditor     -> Kismet / UnrealEd
```

## 真实资产流程

Automation 使用 GUID 创建唯一的 `/Game/BP_AvidScriptP59D1_*` 包，并执行：

1. 以 C# 生成的 `AProjectile` 为父类创建 Blueprint；
2. 编译并检查 `Damage` UPROPERTY 与 `Activate` UFUNCTION；
3. 验证 `Damage` 可由 Blueprint 读写、`Activate` 可由 Blueprint 调用；
4. 在 Blueprint CDO 中把继承的脚本默认值 `Damage=25` 覆写为 `40`；
5. 保存 `.uasset`，卸载包，再从磁盘重新加载；
6. 验证 CDO 覆写仍为 `40`，父类仍是脚本生成 UClass；
7. Spawn Blueprint Actor，触发 UE `BeginPlay`；
8. 通过 `ProcessEvent` 调用 `Activate(2.0f)`。

测试使用 `ON_SCOPE_EXIT` 销毁 World、卸载包并删除唯一临时 `.uasset`。验证结束后 Content 根目录
没有 `BP_AvidScriptP59D1_*.uasset` 残留。

## Runtime 结果

Blueprint 实例的实际 UClass 不在脚本注册表中，但 Runtime Host 会沿 UClass 祖先寻找最近的脚本
生成类型。因此它绑定到 `Projectile` Session，并复用 P59.C 的 prepared ordinal 路由：

- 继承的 C# `BeginPlay` 把 `HasBegunPlay` 写为 `true`；
- Blueprint `ProcessEvent` 进入生成的 native thunk，再进入 C# WASM `Activate`；
- `Damage` 从 Blueprint CDO 默认值 `40` 更新为 `80`；
- `ActivationCount` 从脚本默认值 `1` 更新为 `2`。

这证明 Blueprint CDO 是 Blueprint 覆写值的 owner，脚本默认值仍由生成 native CDO 提供，Runtime
激活不会重新写默认值或覆盖 Blueprint 资产状态。

## 验证

- 源码版 UE5.8 no-clean UBT：新增测试文件后一次 `-gather`，随后普通增量 `4` actions 成功；
- `AvidScript.Editor.GeneratedTypes.BlueprintSubclass`：`1/1 Success`；
- 临时资产残留：`0`。
