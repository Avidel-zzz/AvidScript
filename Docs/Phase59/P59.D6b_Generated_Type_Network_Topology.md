# P59.D6b 脚本定义类型真实网络拓扑

## 目标

把 D6a 的 UHT 网络壳层从单进程 authority 证明提升为真实独立进程传输，验证脚本定义 Actor 可以直接
承载联网游戏逻辑，而不是只拥有看起来正确的反射 flag。

## 闭环

每个远端连接由服务器生成一个 owner-only `AProjectile`：

1. 客户端等待 generated Runtime Session 与 C# `BeginPlay` 激活；
2. 客户端调用 C# 声明的 Reliable Server RPC `ServerSubmitDamage(41)`；
3. UE callspace 把调用送到 authority，服务器执行 C# WASM body，写入原生 replicated `Damage`；
4. 服务器调用 C# 声明的 owning Client RPC 与 Reliable NetMulticast；
5. UE 属性复制在客户端自动触发 `OnRepDamage`，回调进入客户端 C# WASM；
6. 每个进程写出独立 JSON，编排器校验 role、PID、Actor 数量、计数、值、authority 与 active Session。

产品路径仍是 UHT RPC/replication -> generated ordinal dispatcher -> Wasmtime，不增加自定义网络协议、按函数
名称分支或项目 API wrapper。

## 编排复用

`RunAvidScriptNetworkTopology.ps1` 新增 `-Contract GeneratedTypes`，默认值仍是原有
`RuntimeComponent`。两种合同共享：

- free TCP port 分配；
- 隐藏启动与只回收本轮 PID；
- NetDriver listen 探测；
- role timeout、原子结果文件、日志和 SHA-256；
- dedicated/listen 拓扑与结果聚合。

Generated 模块只在 `WITH_DEV_AUTOMATION_TESTS` 下启用 Harness；Shipping 产品路径不包含测试编排逻辑。

## 验证结果

命令：

```powershell
pwsh Build/RunAvidScriptNetworkTopology.ps1 `
  -Contract GeneratedTypes `
  -Topology All `
  -TimeoutSeconds 75 `
  -SkipProfileBuild
```

- UE5.8 no-clean Editor UBT：4 个增量 action，成功；
- dedicated：1 server + 2 remote clients，3/3 role 成功；
- listen：1 server + 1 remote client，2/2 role 成功；
- server：每个 owner Actor 的 `Damage=41`、`ServerRpcCount=1`、`MulticastCount=1`，RepNotify/Client
  ack 不在 authority 本地误执行；
- client：`Damage=41`、`ServerRpcCount=0`、RepNotify 至少一次且最终值为 41、Client ack 与 multicast
  各一次；
- 五个进程均保持 generated Runtime instance active；
- aggregate：
  `C:\tmp\AvidScriptNetworkTopology_GeneratedTypes_20260831T021605154Z_81480_746cc23d\aggregate.json`；
- aggregate SHA-256：`82a211f55fe4d2afaec3e70c87db7354145f2c65109317e926aacadc2bdec11b`。

## 边界

该证据覆盖本机独立进程、loopback、可靠 RPC 和普通 replicated property。跨机器、丢包、断线重连、
FastArray/custom delta、网络预测与回滚仍未实现；人工 PIE/网络玩法验收继续保留为阶段 Gate 的人工项。
