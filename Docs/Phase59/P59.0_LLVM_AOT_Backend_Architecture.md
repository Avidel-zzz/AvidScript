# P59.0 LLVM AOT 性能后端架构

## 状态

状态：架构冻结候选。

Phase 59 承接 `P57-D06-ControlledLeadership`，目标是在不修改冻结 workload、WASM 字节和
0.95 领导性门槛的前提下，引入一个独立于 Cranelift 的 LLVM AOT 候选后端。
P59 是 PC-first 性能后端阶段；C# 反射类型创作、Actor/Component 原生 shell 与 Blueprint 派生
顺延到 P60，避免把两个高风险架构合并进同一 Gate。

## 后端决策

### 已排除：Wasmtime 内部策略切换

Wasmtime 当前公开 compiler strategy 是 Cranelift 和 Winch；两者可以 JIT 或 AOT，但都不是
LLVM codegen。因此 `WasmtimeSerialized` 可以继续作为生产基线和缓存格式，但不能作为
P59 的独立 codegen 候选。

### 主候选：WasmEdge LLVM AOT

P59.A 优先评估 WasmEdge 0.17.x：

- 提供 C API，适合从 `AvidScriptVM` adapter 封装；
- `WASMEDGE_USE_LLVM` 支持 LLVM AOT/JIT，编译优化级别包含 O0-O3/Os/Oz；
- AOT 输出可以是平台原生动态库，也可以是带 AOT custom section 的 Universal WASM；
- Windows 提供 `wasmedge.dll`，官方文档明确支持 Windows 10。

P59 默认评估 Universal WASM AOT 形式，避免将任意项目内容当作普通 DLL 加载。
不论格式如何，AOT 部分都是原生代码，必须作为受信任 Cook 产物管理，不接受运行时下载或
用户任意生成的 AOT artifact。

### 备选：Wasmer LLVM

Wasmer 也提供 LLVM compiler backend 和 C API，但当前源码构建要求 LLVM 22.1.x，Rust/C API 打包与
UE Windows 依赖面更大。只有 WasmEdge 在 P59.A 冻结矩阵上不达标或缺少必要的 host import/
artifact contract 时，才启动 Wasmer LLVM 备选；不在同一批次并行集成两个新 runtime。

## 模块边界

| 模块 | 职责 | 禁止事项 |
| --- | --- | --- |
| `AvidScriptVM` | backend adapter、AOT artifact 验证、host import、memory/export/trap 统一语义 | 不认识 `UObject`、`UClass` 或 C# 类型名 |
| `AvidScriptEditor`/Build sidecar | 从 canonical WASM 生成内容寻址 AOT 产物和 manifest | 不在游戏运行时启动 LLVM compiler |
| `AvidScriptRuntime` | Session 选择策略、受信任 artifact 加载、显式 fallback 策略 | 不直接调用 WasmEdge C API |
| `AvidScriptBindings` | 继续拥有 host capability 与 binding package | 不为 AOT 后端复制一套 UE API |

## 后端与 artifact 合同

P59 在既有 `IAvidScriptVmBackend` 上扩展，不修改 Runtime/Bindings 调用方式：

- `EAvidScriptVmBackendKind` 新增 `WasmEdge`；
- `EAvidScriptVmArtifactFormat` 新增 `WasmEdgeUniversalAot`；
- `EAvidScriptVmExecutionMode` 使用已有 `Aot`；
- backend 能力必须报告 `Aot | PrecompiledArtifact | GuestMemory | StructuredStack`，缺失能力不允许伪装成功；
- 未验证 AOT 产物一律 `fail-closed`，只有显式 `bAllowFallback` 才能回退 Wasmtime/WAMR；
- 正式 benchmark 固定 `fallback=false`。

AOT manifest 至少绑定：

- canonical WASM SHA-256 与 AOT artifact SHA-256；
- WasmEdge/runtime/compiler/LLVM 版本与构建身份；
- target triple、CPU feature set、optimization level 和 WebAssembly feature set；
- AvidScript host ABI 版本、module layout 哈希和 binding package 哈希；
- compiler tool 哈希、artifact schema 和生成时间；
- 平台和 Cook profile。

cache key 为以上所有身份的 canonical hash。任一字段不匹配时拒绝加载，不在热路径
重新编译或猜测兼容性。

## 安全与生命周期

- canonical WASM 仍先通过现有 layout/import 验证；被验证的 WASM 哈希必须与 AOT manifest 一致；
- AOT 产物只能从内容寻址包和 Cook manifest 解析，禁止从任意绝对路径加载；
- host import 继续按 Session 注册，未知 module/name/signature/ordinal 拒绝实例化；
- trap、fuel/interrupt 和 guest memory 范围错误映射为现有 `FAvidScriptVmError`，失败后 Session 不可继续 Tick；
- artifact 卸载顺序为停止调用、失效 export handle、释放 instance/store/module，最后释放 engine/config；
- 不允许 LLVM 编译器进入最终游戏 Runtime 包。

## 平台策略

- Win64 PC 是 P59 唯一必须完整落地的平台；
- Linux PC 只冻结 manifest/target contract，不阻塞首个 Win64 Gate；
- Android 官方 WasmEdge 当前只支持解释器运行，P59 不宣称移动端 LLVM AOT；
- 移动端继续通过现有 backend selection 选择可用的解释/AOT 方案，P59 不删除 WAMR 或 Wasmtime。

## 性能验收

### 冻结纯执行矩阵

完全复用 P57.13 的 12-kernel identical-WASM 协议：每 kernel 5 个独立进程、5 次 warmup、
30 次 timed sample、CPU0、correctness failure 0、fallback false。不修改 Puerts commit、V8 资产、
kernel bytes、样本数或统计口径。

| 指标 | 门槛 |
| --- | ---: |
| p50 几何均值 WasmEdge LLVM AOT / Puerts V8 | `<= 0.95` |
| p95 几何均值 WasmEdge LLVM AOT / Puerts V8 | `<= 0.95` |
| p50 kernel 胜率 | `>= 60%` |
| p95 kernel 胜率 | `>= 60%` |
| MAD 几何均值 | `<= 1.25` |

### UE 集成不回归

- 同一 WASM 的 import/export/layout 结果与 Wasmtime 基线一致；
- BeginPlay/Tick/event 生命周期语义不变；
- host crossing 数不增加，不以合并或删除游戏语义换取分数；
- load/instantiate 和峰值内存单独报告，不用热循环数据隐藏启动成本。

## 批次边界

- `P59.A`：WasmEdge LLVM AOT 依赖锁定、C API 最小实例、artifact 身份和冻结矩阵可行性；
- `P59.B`：`AvidScriptVM` backend adapter、host import、guest memory、export/trap 与 AOT artifact loader；
- `P59.C`：Editor/Build compiler sidecar、内容寻址缓存、Runtime selection、Cook 与 Win64 包语义；
- `P59.D`：一次集中审查、UE5.8 no-clean 构建、Automation、冻结 12-kernel 和严格 Gate。

P59.A 是决策 Gate：如果 WasmEdge 缺少必要的 host import/artifact 能力，或在冻结矩阵上无法形成
明确领先，则停止深度 UE 集成，用同一协议评估 Wasmer LLVM。不为了沉没成本把未达标后端
强行接入 Runtime。

## 非目标

- 不降低或更换 P57-D06 门槛；
- 不通过手写 UE API 或减少 host 语义获取 benchmark 领先；
- 不在 P59 实现 C# 反射类型、Actor/Component native shell 或 Blueprint authoring；
- 不清理 Editor target；
- 不将 LLVM compiler 或未信任 AOT 产物带入 Shipping Runtime。
