# P59.C2b Native UProperty Ordinal Codec

## 目标

让 C# 方法体读写脚本声明的 `UPROPERTY` 时，直接访问生成 UObject shell 中的原生属性，避免在
Guest 内保存第二份字段状态。属性发现和 ordinal 编译属于加载冷路径，方法执行热路径只保留 prepared
import 与 packed ObjectHandle。

## 共享合同

`SemanticUeTypeRuntimeContract.BuildPropertyPlans()` 是 Guest compiler 与 UHT generator 的唯一计划源：

- UE type declaration 顺序决定 dense type ordinal；
- 同一类型内 property/function stable id 的 ordinal 排序决定 member ordinal；
- getter/setter 能力来自 canonical Roslyn symbol/accessor；
- import identity 为 `avid_ue_property_<typeOrdinal>_<memberOrdinal>_<get|set>`；
- owner type、value type、读写能力和 import identity 同时进入 Guest 与生成 manifest。

generator manifest 升级为 schema 3 / generator 1.2。每个属性记录 getter/setter import；不可写属性的
setter identity 为空。结构变化会同时重建 shell、manifest 与 WASM，不允许旧 ordinal 跨结构版本复用。

## Guest lowering

- 只有实际被可达方法体调用的属性 import 才进入 Guest IR/WASM；
- property 与 field 两种 C# `UPROPERTY` 表面使用同一计划；
- 读操作参数为 `owner ObjectHandle`，返回规范属性值；
- 写操作参数为 `owner ObjectHandle + value`，返回 `void`；
- 派生脚本类访问基类属性时，先按已验证的声明继承图做零成本 handle 上转型；
- `base.Method()` 与普通脚本父类调用复用同一 handle 上转型合同；
- 非继承 receiver、缺失 getter/setter、未知类型或重复计划全部 fail-closed。

同一源码模块包含多个 UClass 且没有 Guest state slot 时，state projector 发布 module-owned 空 schema；
native UPROPERTY 随 UObject 存续，不参与 Guest snapshot。若多 UClass 模块出现 Guest-owned state，仍拒绝
编译，直到后续版本提供按实例 owner 的状态 schema，不能任意选择一个类型冒充 owner。

该批次只发布编译与 manifest 合同。下一小节由 Runtime 读取 manifest，冷路径把 import 绑定为
`FProperty` prepared codec；方法执行时不解析 import 名、不遍历反射属性。
