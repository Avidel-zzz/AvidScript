# P59.1 C# 脚本定义 UE 类型架构

> 状态：架构冻结候选 v2
>
> 主线：C# -> Roslyn -> UE Type Declaration Contract -> UHT Shell -> WASM Runtime
>
> 平台：PC-first，保持 Cook、Shipping 与移动端边界

## 1. 目标

P59 让项目开发者直接用 C# 声明可被 Unreal Reflection、Blueprint 和 AvidScript Runtime
共同识别的游戏类型，而不是只把脚本附着到预先手写的 C++ Actor：

- C# 定义 `Actor`、`ActorComponent`、`WorldSubsystem` 和 `GameInstanceSubsystem`；
- 使用 `[UClass]`、`[UProperty]`、`[UFunction]` 声明反射表面；
- 支持脚本类型继承、脚本方法覆写和稳定的父调用合同；
- 生成真实 `UClass`，允许 Blueprint 以脚本类型为父类创建子类；
- 类型结构进入受控 UHT/UBT 冷路径，方法体继续编译为 WASM；
- 复用现有 Session、ObjectHandle、Reflection binding、continuation 和网络语义；
- 不为每个脚本类或 UE API 手写 C++ glue。

## 2. 非目标

- P59 不把 CLR 或 Roslyn 嵌入 UE Runtime；
- 不在运行中的 Shipping 进程动态制造任意 `UClass`；
- 不承诺结构变更可以无 Editor reload 生效；
- 不在本阶段完成 Interface、默认参数、完整 delegate 和 Blueprint 新声明函数语义，它们属于 P60；
- 不把 LLVM AOT 后端替换成 P59 主目标。性能领导力是持续门禁，在 P65 发布级验收前必须关闭；
- 不以逐个 API wrapper 或每个 flag 组合的穷举测试换取表面覆盖率。

## 3. 用户表面

规范声明使用生成的 `AvidScript` facade：

```csharp
using AvidScript;

namespace Game;

[UClass(Blueprintable = true, BlueprintType = true)]
public partial class Projectile : AvidActor
{
    [UProperty(EditAnywhere = true, BlueprintReadWrite = true, ReplicatedUsing = nameof(OnRepDamage))]
    public float Damage { get; set; } = 25.0f;

    [UFunction(BlueprintCallable = true)]
    public void Activate(FVector direction)
    {
        Self.SetActorLocation(Self.GetActorLocation() + direction);
    }

    [UFunction]
    private void OnRepDamage()
    {
    }
}
```

标记基类只存在于编译期 facade，不代表 CLR 对象：

- `AvidActor`
- `AvidActorComponent`
- `AvidWorldSubsystem`
- `AvidGameInstanceSubsystem`

它们提供 `Self` 和受支持的虚方法签名。Roslyn 负责类型检查，Guest lowerer 将实例访问转换为
Session-owned script instance 和当前 `ObjectHandle`；UE Runtime 不创建托管对象。

## 4. 分层与所有权

```text
C# source + generated facade
  -> CSharpSemantic: UeTypeDeclarations
  -> CSharpGuest: method body Guest IR / WASM exports
  -> Editor UHT Shell Generator: deterministic .h/.cpp + manifest
  -> UHT/UBT: reflected native shell module
  -> Runtime Type Registry: UClass <-> stable script type id
  -> Session Dispatch: UObject lifecycle/event -> prepared WASM export
```

### 4.1 CSharpSemantic

唯一负责：

- 识别规范属性和标记基类；
- 解析脚本继承图与类型类别；
- 生成稳定类型、属性、函数和参数身份；
- 规范化 class/property/function flags 与 metadata；
- 在任何生成或编译前 fail-closed 拒绝不合法声明。

它不了解 UHT 文件布局，不生成 C++，也不依赖 UE Runtime。

### 4.2 Editor UHT Shell Generator

唯一负责把验证后的声明合同转换成确定性 native shell：

- 每个脚本类型生成一个真实 `UCLASS`；
- `UPROPERTY` 和 `UFUNCTION` 由合同集中渲染；
- 函数 thunk 只携带稳定 member id，统一进入 Runtime dispatcher；
- 不为函数体生成专用手写 binding；
- 输出内容寻址 manifest、输入 hash、生成器版本和 UE 版本；
- 原子发布到项目生成模块，并由受控 UBT/UHT 构建。

### 4.3 Runtime Type Registry

Runtime 只读取已验证 manifest 和已加载 `UClass`：

- `StableTypeId -> UClass`；
- `UClass -> ScriptTypeDescriptor`；
- `StableMemberId -> prepared export/codec plan`；
- `UObject/ObjectHandle -> Session-owned script instance`。

任何 class path、父类、ABI、manifest hash 或 module identity 不一致都拒绝注册，不回退到名称猜测。

### 4.4 Session Dispatch

生成 shell 的生命周期和函数 thunk 进入既有 Session：

- `BeginPlay`、`Tick`、`EndPlay`、continuation、delegate、RPC 和 RepNotify 不建立第二套 scheduler；
- Game Thread、world、generation、activation serial 和 teardown fence 继续由 Session 验证；
- prepared export handle 在 reload 后按 generation 失效；
- 脚本实例销毁先取消 continuation/subscription，再释放状态和 ObjectHandle。

## 5. UE Type Declaration Contract

P59.A 在 semantic artifact 中新增按稳定身份排序的 `ue_type_declarations`：

```text
UeTypeDeclaration
  type_id
  symbol_id
  engine_name
  kind
  base_type_id
  flags[]
  metadata[]
  properties[]
  functions[]
```

成员合同不复制可从 semantic symbol/callable 唯一取得的信息，只保存生成 UE 类型需要的规范化信息：

- Property：`symbol_id`、`name`、`type_id`、flags、category、replicated_using；
- Function：`method_symbol_id`、`name`、flags、category；
- Metadata：排序后的 key/value，禁止重复 key；
- Span：诊断使用 primary source span，不进入运行时热路径。

Schema 增长必须同步 serializer、cache、prepared semantic、Guest validator、生成器和架构检查。
旧 schema 仍可由兼容读取器解析，但不能伪造 P59 声明。

## 6. 合法性规则

### 6.1 Class

- 必须是 primary source 中顶层、非泛型、非 static 的 `partial class`；
- 必须直接或间接继承规范标记基类；
- 脚本继承图必须无环，类别必须与根标记基类一致；
- engine name 必须是合法 UE 标识符，并在一个生成模块内唯一；
- engine name 保存不含 C++ `A`/`U` 语言前缀的 UE 反射逻辑名；生成器根据 `kind` 添加 C++ 前缀；
- `Abstract`、`Blueprintable`、`BlueprintType`、`NotPlaceable` 等转换为固定 flags；
- canonical attribute identity 不匹配的同名伪属性不产生声明。

### 6.2 Property

- 只允许实例字段或非索引属性；
- 类型必须通过现有递归 UE value capability；
- `BlueprintReadOnly` 与 `BlueprintReadWrite`、可编辑与只读组合必须自洽；
- `ReplicatedUsing` 必须解析到本类型或基类中签名合法的实例函数；
- auto-property backing field 不作为第二个 UPROPERTY 输出。

### 6.3 Function

- 只允许非泛型实例方法；
- 参数和返回值必须通过现有 callable/type capability；
- Blueprint、RPC、RepNotify 和 override flags 使用同一规范化合同；
- override 必须绑定唯一父声明，签名不一致时 fail-closed；
- 函数 stable id 决定 shell thunk 与 WASM export，不在热路径按名称查询。

## 7. 生成与增量编译

输入 hash 包含：

- canonical C# source hash；
- semantic schema 与 UE type contract version；
- generated facade/binding descriptor hash；
- 目标 UE 版本、平台和生成器版本；
- 直接父类型合同 hash。

方法体变化只重建 WASM 并走现有 reload。类、属性、函数签名或反射 flag 变化属于结构变化，
重建生成模块并明确提示 Editor reload。缓存命中时不得启动 UHT/UBT。

## 8. Blueprint 子类

Blueprint 看到的是生成 module 中的真实 native shell `UClass`：

- 可继承性由 `Blueprintable` 控制；
- Blueprint override 通过 UE `ProcessEvent`/native event 规则进入 shell；
- shell 再按 dispatch policy 调用脚本实现或父实现；
- Blueprint CDO/default 与脚本默认值的 owner 明确，禁止双写；
- 删除或不兼容重命名类型时生成迁移诊断，不静默替换 class path。

## 9. 性能约束

- 反射发现、manifest 验证、member route 和 codec 编译全部在模块注册冷路径；
- thunk 热路径使用 stable ordinal、prepared export 和 prepared codec；
- 不进行字符串 class/function 查找，不重复遍历 `FProperty`；
- 每个实例不复制完整 descriptor；共享 immutable type plan，实例只保存 Session/handle/state；
- P59 Gate 分开报告 native shell dispatch、prepared WASM export、property access 和 lifecycle crossing。

## 10. 安全与生命周期

- 只有项目受控生成目录可参与 UHT shell 构建；
- manifest 和生成源码必须内容寻址并在加载前复核；
- Runtime 不加载编译器，不信任脚本传入的 class/member ordinal；
- CDO、archetype、Editor preview、PIE world 和 teardown 状态显式区分；
- World/Object teardown 自动取消实例拥有的 continuation、async load、delegate 和 network callback；
- Shipping 只携带已构建 shell、验证 manifest 和 WASM artifact。

## 11. Phase 批次

- `P59.A`：Roslyn UE type declaration contract、规范属性表面、Schema/validator/diagnostic；
- `P59.B`：确定性 UHT shell generator、manifest、增量生成模块和受控构建入口；
- `P59.C`：Runtime type registry、Session instance、继承/覆写/父调用和生命周期闭环；
- `P59.D`：Actor/Component/Subsystem、Blueprint 子类、网络/热重载/Cook 集成和集中 Gate。

## 12. 验收

P59 完成必须同时证明：

1. 示例 C# Actor 生成真实 `UClass`，可在 Editor 中放置并执行 `BeginPlay/Tick`；
2. C# Component 可挂到 Actor，Subsystem 可按对应 UE 生命周期创建和销毁；
3. `[UProperty]` 可由 Blueprint 读写，支持至少一个 RepNotify 闭环；
4. `[UFunction]` 可由 Blueprint 调用，脚本继承与 override/parent call 行为确定；
5. Blueprint 能以生成脚本 Actor 为父类创建并运行子类；
6. body-only reload 不重建 shell，结构变化明确要求受控 rebuild/reload；
7. Object/world teardown 后无旧 Session 回调；
8. no-clean UE5.8 build、完整 AvidScript Automation、架构 Gate 和相关 benchmark 通过；
9. 人工 PIE/Blueprint 资产保存与重新打开验收单独记录，不由 Automation 冒充。

## 13. 路线纠偏说明

`P59.0_LLVM_AOT_Backend_Architecture.md` 保留为已完成的后端研究记录，不再是 P59 的权威架构。
原因是长期产品路线明确把 P59 定义为脚本 UE 类型，而 `P57-D06-ControlledLeadership` 可以跨阶段持续优化，
不能用性能后端替代决定 Puerts/UnLua 级成熟度的类型定义闭环。
