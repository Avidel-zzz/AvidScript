# P59.B2 确定性 UHT Shell 生成内核

## 结果

新增独立工具 `AvidScript.UeTypeGenerator`，其依赖方向固定为：

```text
AvidScript.CSharpSemantic
  -> AvidScript.UeTypeGenerator
  -> manifest + Public/Private shell source
```

生成器不依赖 Guest、Editor 或 Runtime，也不重新解析 C#。输入必须通过 P59.B1 的共享合同校验。

## 生成合同

P59.B2 初始 manifest schema 1 / generator 1.0 记录：

> P59.C2a 为函数增加 canonical WASM export identity 后，当前 manifest 已升级为 schema 2 /
> generator 1.1；schema 1 仍只用于追溯本节最初交付。

- semantic schema/version 与 semantic artifact SHA-256；
- module、UE version 与 generation key SHA-256；
- stable type id、symbol id、dense type ordinal、engine/C++ name、kind、native base；
- stable property/function id 与统一 member ordinal；
- 规范 flags、Category、RepNotify、C++ 类型、参数方向和原始可见性；
- 每份生成 source 的路径、SHA-256 与字节长度。

type/member ordinal 由稳定 symbol identity 决定。脚本继承的 header 输出采用拓扑顺序，因此 ordinal
不会因为满足 C++ 声明顺序而漂移。

## Shell 表面

当前可生成：

- `AActor`、`UActorComponent`、`UTickableWorldSubsystem`、`UGameInstanceSubsystem` 派生 shell；
- `UCLASS`、`UPROPERTY`、`UFUNCTION` specifier；
- script base/override、Blueprint event 与 RPC `_Implementation` 形态；
- Actor/Component/Subsystem native lifecycle 签名映射；
- Replication 的 `GetLifetimeReplicatedProps` 与 `DOREPLIFETIME`；
- 调用 `FAvidScriptGeneratedTypeDispatcher` 的统一 type/member ordinal thunk。

普通函数 body 不做名称查找，也不生成逐 UE API wrapper。参数地址与可选返回槽通过统一 dispatcher
合同传递，prepared codec 和 Session route 由后续 Runtime 批次拥有。

## 类型映射

本节支持 primitive、`FString`、常用数学结构、基础 UObject/Actor/Component 引用、脚本类型引用与
递归数组。没有确定 native identity 的类型在发布前 fail-closed，禁止按短类名猜测。

## 发布语义

发布器只写固定相对路径：

- `Public/AvidScriptGeneratedTypes.h`；
- `Private/AvidScriptGeneratedTypes.cpp`；
- `AvidScriptGeneratedManifest.json`。

source 先发布，manifest 最后发布；每个文件使用同目录临时文件后原子替换。字节一致时保持文件和
时间戳不变，后续构建入口可据此避免无意义 UHT/UBT。

## 验证

- 固定 .NET SDK：`8.0.416`；
- generator Release build：0 warning / 0 error；
- `AvidScript.UeTypeGenerator.Tests`：`4/4`；
- 覆盖：字节确定性与拓扑、四类 native lifecycle、未知类型拒绝、原子发布与完整缓存命中。

## 当前边界

本节尚未把 source 接入真实 UE module，也尚未实现 `FAvidScriptGeneratedTypeDispatcher`。因此输出是
可审查的 UHT shell 候选，还不能宣称真实 `UClass` 已加载。下一小节建立永久生成模块、Runtime
dispatcher 冷路径合同与受控 Build 入口，然后用 UE5.8 no-clean UBT/UHT 验证实际反射类型。
