# P59.D5a Generated Type Body-only Package Reload

## 目标

解除 Generated Type Runtime Host 对“替换 package 时必须零活跃实例”的限制，让正在运行的 C# Actor、
Component 和 Subsystem 可以安全接收 body-only WASM 更新，同时把反射结构变化准确路由到 Native rebuild。

## 公开合同

Runtime Host 新增：

- `ReloadPackage`：消费已经验证的 Registry 与 Runtime Artifact；
- `ReloadPackageFromDescriptorFile`：复用 install 的路径、哈希、schema、module 和 backend 验证；
- `FAvidScriptGeneratedTypePackageReloadResult`：报告候选实例数、已重载数、已回滚数、结构原因和
  live package 是否被保留；
- `BodyOnlyApplied`、`NativeRebuildRequired`、`Rejected` 三种稳定 disposition。

## 结构兼容边界

body-only 比较覆盖：

- type 数量、稳定 type id、type ordinal 与实际 `UClass*`；
- member 数量、稳定 member id、member ordinal 与 property/function kind；
- 实际 `FProperty*`、`UFunction*`；
- getter/setter import、function export 与 lifecycle 标记。

任意一项改变都不进入 Session reload，而是返回 `NativeRebuildRequired`。这意味着新增/删除属性、函数、
类型，改变签名、继承、ordinal 或 ABI route 都不会被误当作脚本 body 更新。

## 多实例事务

body-only 更新运行在 Game Thread 冷路径：

1. 完整加载并验证 candidate descriptor 与 bytes；
2. 比较当前和候选 Registry shape；
3. 对每个 active instance 调用已有 `RuntimeSession::ReloadArtifact`；
4. 只有全部 Session 成功后才替换 Host package snapshot；
5. 任一 Session 失败时，对已成功实例按逆序重新加载 previous artifact；
6. 如果回滚本身失败，Host teardown 全部 generated type Session 与 ObjectHandle，禁止混合版本继续运行。

现有 Session 仍拥有状态迁移、continuation/delegate teardown、候选 Runtime 激活和单实例 rollback；Host
只负责跨实例的一致提交，不建立第二套 VM reload 实现。

## 自动验证

`AvidScript.Runtime.GeneratedTypes.RuntimeHost` 在同一个真实 Host 中验证：

1. 安装旧 descriptor，激活 UObject 并执行旧 WASM；
2. 原子改写 WASM/runtime manifest/package descriptor；
3. active instance body-only reload 成功，导出结果切换为 `37`；
4. 改变稳定 type identity 后返回 `NativeRebuildRequired`；
5. 结构拒绝后同一对象继续执行结果 `37`；
6. 激活第二个对象，注入“第一个成功、第二个前失败”；
7. 断言 `candidate=2`、`reloaded=1`、`rolled_back=1`；
8. 两个对象最终都继续执行 previous body `37`。

故障注入入口只存在于 `WITH_DEV_AUTOMATION_TESTS`，不进入 Shipping API。

## 验证结果

- UE5.8 Editor no-clean UBT：成功，9 个增量 action；
- `AvidScript.Runtime.GeneratedTypes.RuntimeHost`：`1/1 Success`；
- descriptor 的损坏哈希拒绝、install、ObjectHandle、幂等 Begin/End 与 ClearPackage 既有断言继续通过。

## 边界与下一步

本节提供 Runtime 事务核心和可调用 descriptor API。它尚未自动监视 C# 文件，也没有决定何时调用 UBT。
P59.D5b 负责让构建产物输出结构分类，并由 Editor 服务把 body-only 结果调用本 API，把 structural 结果明确
报告为 rebuild required。
