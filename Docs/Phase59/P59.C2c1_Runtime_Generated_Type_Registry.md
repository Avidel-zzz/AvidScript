# P59.C2c1 Runtime Generated Type Registry

## 目标

把 C# UE Type 生成结果从“可供 UHT 编译的壳代码”推进为 Runtime 可直接消费的不可变注册表。
该小节只建立冷路径解析与反射缓存，不提前混入 Session、WASM 实例或参数 codec 的生命周期。

## 已实现

- manifest 升级为 schema 4 / generator 1.3；每个类型显式记录完整 `class_path`，格式固定为
  `/Script/<ModuleName>.<EngineName>`，Runtime 不通过 `A/U` 前缀猜测类路径。
- `FAvidScriptGeneratedTypeRegistry::BuildFromJson` 只允许在 GameThread 构建注册表，并严格校验：
  schema、generator、ASCII module name、稠密 type/member ordinal、稳定 ID 唯一性、import/export
  唯一性和 canonical function export 格式。
- 构建阶段一次性解析并缓存 `UClass`、`FProperty` 和 `UFunction`。非 lifecycle 函数必须解析到
  UFunction；lifecycle 允许没有反射 UFunction，但仍保留 canonical WASM export。
- 属性必须由 manifest 所属的精确 UClass 声明，继承成员不会被错误重复绑定。
- 发布结果为 `TSharedPtr<const FAvidScriptGeneratedTypeRegistrySnapshot>`。后续调用可用 type/member
  ordinal 直接索引，不在热路径执行名字查找、JSON 解析或 UE 反射搜索。
- 数量上限为 4096 个类型、每类型 65536 个成员；任何不完整或冲突输入都 fail closed，且不会发布
  部分注册表。

## 验证证据

- UeTypeGenerator：`4/4 passed`。
- 真实 `BuildCSharpScriptTypes.ps1`：4 个类型，schema 4 / generator 1.3；生成的四个
  `class_path` 均为 `/Script/AvidScriptGenerated.*`。
- UE5.8 增量 UBT：6 个动作，`Result: Succeeded`；未清理 Editor target。
- focused Automation `AvidScript.Runtime.GeneratedTypes.Registry`：发现 1 条，执行 1 条，
  `Result={Success}`，Queue Empty，退出状态 0。
- 自动化覆盖有效注册表、ordinal/stable-id/UClass 三种查找、FProperty/UFunction 缓存、重复 member
  ordinal、错误 class path 和旧 schema 拒绝。

## 当前边界

注册表已经把 manifest 的字符串身份冻结成 Runtime 反射指针和 ordinal 表，但 Session 尚未持有该快照，
也尚未把函数 export 预解析为 VM prepared call。下一小节 P59.C2c2 将完成 Session 所有权、实例注册、
prepared export 缓存与首条无参数 UFunction 调用闭环。
