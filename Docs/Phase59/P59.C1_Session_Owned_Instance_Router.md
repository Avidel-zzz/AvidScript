# P59.C1 Session-owned 实例路由内核

## 结果

`AvidScriptRuntime` module 现在在启动时安装唯一的 `FAvidScriptGeneratedTypeRouter`，在关闭时先从
`FAvidScriptGeneratedTypeDispatcher` 卸载并等待已有调用排空。生成 module 仍只看稳定 dispatcher ABI，
不依赖 Session、VM backend 或项目对象。

每个脚本对象由其生命周期 owner 提供：

- `UObject` 弱身份；
- 当前 `FAvidScriptObjectHandle`；
- 实现 `IAvidScriptGeneratedTypeInstance` 的 Session-owned instance；
- move-only `FAvidScriptGeneratedTypeInstanceRegistration`。

router 只保存一份轻量 route，不复制类型 descriptor。生成 thunk 进入 router 后按对象身份找到实例，
再原样传递 stable type/member ordinal、native 参数槽和可选结果槽，热路径不做 class/function 名称查找。

## Fail-closed 与生命周期

以下情况全部拒绝注册或调用：

- 非 Game Thread；
- 无效 ObjectHandle；
- CDO、archetype 或已进入销毁状态的 UObject；
- 同一 Receiver 的竞争注册；
- router 尚未安装或 Receiver 没有实例 route；
- dispatch 回调期间注册、注销或销毁 registration。

registration 析构时自动注销。回调内重入注销会返回失败并保留原 route，要求 Session owner 在调用栈
退出后执行 teardown；这与 continuation、delegate 和 runtime unload 的既有 fence 方向一致。

## 验证

- 源码版 UE5.8 no-clean `AvidTPSTemplateEditor Win64 Development`：成功，6 actions；
- focused Automation `AvidScript.Runtime.GeneratedTypes.Dispatcher`：发现 1 条，`Success`，退出码 0；
- 覆盖无实例 fail-closed、CDO/无效 handle 拒绝、竞争注册拒绝、Receiver/handle/ordinal 透传、
  回调内 teardown fence、正常注销和注销后 fail-closed。

## 当前边界

本节完成的是生产 router 和 Session-owned instance 的所有权合同。`FAvidScriptRuntimeSession` 尚未实现
`IAvidScriptGeneratedTypeInstance`，也尚未从 manifest 编译 member ordinal 到 prepared WASM export 的
route plan。因此生成的 `BeginPlay`、Tick 和普通 `UFUNCTION` 仍会在“无实例注册”处安全返回默认值。

P59.C2 将建立不可变 type/member plan，并让 Runtime Session 以 generation-safe prepared export 执行
首个生成 `UFUNCTION`；之后再接 Actor/Component/Subsystem 生命周期与继承/parent call。
