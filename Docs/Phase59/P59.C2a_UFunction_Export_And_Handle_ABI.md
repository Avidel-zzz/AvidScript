# P59.C2a UFunction Export 与 ObjectHandle ABI

## 结果

脚本定义 UE 方法现在拥有跨 Semantic、Guest、WASM 和 UHT manifest 一致的执行身份：

```text
method_symbol_id
  -> SHA-256 lower hex 前 128 bit
  -> avid_ue_<32 hex>
```

唯一实现位于 `SemanticUeTypeRuntimeContract`。Guest lowerer 与 UHT generator 都调用该公共合同，Runtime
后续只读取 manifest 中的 `export_name`，不在 C++ 重新实现 hash 或按函数名猜测。

## 编译合同

- 非 `BlueprintImplementableEvent` 的 UFunction 和生命周期方法成为 Semantic reachability root；
- Guest 为每个 root 生成 canonical WASM export；
- 脚本定义 UE 类的实例参数降低为既有 `handle / i64 / 8 bytes`，与 packed
  `FAvidScriptObjectHandle` 一致；
- 不创建 CLR object，也不新增第二种对象句柄；
- generator manifest 升级为 schema 2 / generator 1.1，每个函数记录 `export_name`；
- `BuildCSharpScriptTypes.ps1` fail-closed 要求 schema 2 / generator 1.1。

## 当前边界

正式 Guest compiler 对完整样例继续 fail-closed，首个阻断点是
`Projectile.Activate()` 对 native `UPROPERTY Damage` 的读写尚无 Guest getter/setter route。由于该函数
未降低，compiler 同时拒绝发布它的 canonical export。这是正确的失败行为，不通过删掉样例逻辑绕过。

下一小节建立按 type/member ordinal 编译的 prepared self-property get/set codec；完成后重新运行完整
样例 Guest/WASM 构建，再把 manifest member plan 接入 P59.C1 的 Session-owned router。
