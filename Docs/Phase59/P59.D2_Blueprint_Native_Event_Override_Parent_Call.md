# P59.D2 Blueprint NativeEvent 覆写与 Parent Call 闭环

## 目标

让 C# 脚本定义的 `UFunction` 成为 UE 标准 `BlueprintNativeEvent`，并证明 Blueprint 子类可以覆写该事件、
保存为真实资产、重载后通过 Parent Call 回到 C# WASM 游戏逻辑。

## 实现

### C# 声明

`Projectile.Activate` 现在使用：

```csharp
[UFunction(BlueprintCallable = true, BlueprintNativeEvent = true, Category = "Projectile")]
public virtual void Activate(float damageScale)
```

生成器输出标准 UE 壳层：

```cpp
UFUNCTION(BlueprintCallable, BlueprintNativeEvent, Category="Projectile")
void Activate(float damageScale);
virtual void Activate_Implementation(float damageScale);
```

`Activate_Implementation` 继续使用稳定 type/member ordinal 与 packed ObjectHandle 派发到 Wasmtime，
没有在热路径新增名称查找、反射遍历或分配。

### 脚本继承合同

派生 C# 类型不需要重复声明 `BlueprintNativeEvent`。生成规划器在冷路径沿脚本父类链解析同名 override，
继承会改变 C++ 实现入口的四类标记：

- `blueprint_native_event`
- `server`
- `client`
- `net_multicast`

因此 `ExplosiveProjectile.Activate` 正确生成为：

```cpp
virtual void Activate_Implementation(float damageScale) override;
```

如果派生声明显式改变父函数的实现形态，生成器会 fail-closed。`BlueprintCallable`、`Category` 等展示与
调用元数据不会被这条规则隐式传播。

生成器版本由 `1.4` 提升到 `1.5`，正式构建入口、Runtime 注册表、架构门禁和固定测试夹具已同步。

## Blueprint 真实资产验证

`AvidScript.Editor.GeneratedTypes.BlueprintSubclass` 在 Editor 中执行以下真实流程：

1. 以 `/Script/AvidScriptGenerated.Projectile` 创建 Blueprint；
2. 创建 `Activate` override graph，并确认存在一个 `UK2Node_CallParentFunction`；
3. 编译后确认 Blueprint 自有的 `Activate` 为非 Native bytecode；
4. 把 Blueprint CDO 的 `Damage` 从 C# 默认值 `25` 改为 `40`；
5. 保存 `.uasset`，卸载 package，再从磁盘重载；
6. 确认 override bytecode 与 CDO 值仍然存在；
7. Spawn Actor，进入继承的 C# `BeginPlay`；
8. `ProcessEvent(Activate, 2.0)` 进入 Blueprint bytecode，再经 Parent Call 进入 C# WASM；
9. 最终断言 `Damage == 80`、`ActivationCount == 2`。

测试使用唯一临时资产名，并在退出路径卸载 package、删除 `.uasset`，不污染项目 Content。
