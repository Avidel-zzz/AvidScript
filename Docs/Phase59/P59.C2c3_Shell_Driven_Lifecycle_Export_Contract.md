# P59.C2c3 Shell 驱动生命周期导出合同

## 目标

让脚本定义 `UClass` 的对象生命周期只由生成的 UE shell 驱动，同时保持现有 Runtime Session 的模块
装载 ABI。一次 UE `BeginPlay/Tick/EndPlay` 只能进入一次对应的 C# 对象方法。

## 已实现

- 含脚本定义 UE 类型的 Guest 模块自动生成三个模块级兼容 export：
  `avid_on_begin_play`、`avid_on_tick`、`avid_on_end_play`。
- 兼容 export 使用独立、无状态、无指令的 synthetic Guest IR 函数；其中 Tick 保留 `(float)->void`
  ABI，其余为 `()->void`。它们只服务 Session 装载和生命周期状态迁移，不执行对象游戏逻辑。
- C# 生命周期覆写继续生成 `avid_ue_<stable-hash>` canonical export，生成的 Actor、Component 或
  Subsystem shell 通过 type/member ordinal dispatcher 调用该 export。
- 若同一个 UE 生命周期覆写又声明为模块级 `avid_on_begin_play`、`avid_on_tick` 或
  `avid_on_end_play`，Guest 编译以 `ASCG1016` fail closed，防止 canonical 与全局入口指向同一函数。
- 已存在的独立模块级 lifecycle export 不会被覆盖；兼容 shim 只补齐缺失入口，export identity 保持唯一。
- 不含脚本定义 UE 类型的普通 C# 模块保持原有全局生命周期语义，不受该合同影响。

## 执行所有权

```text
UE UObject lifecycle
  -> generated UHT shell
  -> ordinal dispatcher
  -> Session prepared canonical export
  -> C# instance method

Session activation/reload state transition
  -> module-global compatibility export
  -> no-op synthetic function
```

该边界避免为脚本定义类型建立第二套 scheduler，也不在热路径增加反射或字符串查找。后续实例接线必须
确保 generated shell 是对象生命周期的唯一外部时钟，并把 continuation/timer pump 与该时钟衔接。

## 验证范围

- `AvidScript.CSharpGuest.Tests` 完整回归 `117/117 passed`；
- Guest 测试验证 canonical export 与兼容 export 使用不同 function id；
- 验证 Tick shim 的 `float32` ABI、空函数体、export identity 唯一性和真实 WASM 编译；
- 验证生命周期方法别名到全局入口时以 `ASCG1016` 拒绝；
- 正式 `InvokeCSharpGuestCompiler.ps1` 已将四类型样例编译为真实 WASM：5 个 canonical UE export、
  3 个 lifecycle compatibility export、2 个 ordinal UPROPERTY import，退出码 0；
- debug-map 仅保留真实 C# 方法映射，三个 synthetic shim 不伪造源码 span。

本小节只冻结编译产物合同。对象创建时自动建立 Session/route、shell 驱动 continuation pump 和真实 PIE
生命周期验收仍属于后续 P59.C 小节。
