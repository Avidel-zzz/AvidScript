# P59.C2c4b 生成 Shell 与 Runtime Host 接线

## 目标

让真实 Actor、ActorComponent、WorldSubsystem 与 GameInstanceSubsystem 的原生生命周期自动创建和释放
脚本实例，不再要求游戏代码手工调用 Runtime Session API。

## 已实现

- 每个生成类型都声明原生 activation/teardown hook，即使 C# 没有覆写对应生命周期：
  - Actor、ActorComponent：`BeginPlay` / `EndPlay`；
  - WorldSubsystem、GameInstanceSubsystem：`Initialize` / `Deinitialize`。
- activation 顺序固定为 `Super -> RuntimeHost.BeginInstance -> canonical C# lifecycle export`；失败时不进入
  canonical 方法，也不发布半初始化实例。
- teardown 顺序固定为 `canonical C# lifecycle export -> RuntimeHost.EndInstance -> Super`，保证脚本仍可在
  EndPlay/Deinitialize 中访问有效的 receiver handle 和 UE API。
- Host 的 Begin/End 改为幂等，适配脚本生成类继承产生的 native `Super` 链。
- Host 根据 receiver 的实际 UClass 向上查找 registry 中最派生脚本类型；Blueprint 派生类也能绑定到其
  最近的脚本生成基类，而不是错误使用当前 native shell 的静态 ordinal。
- shell 的普通 UFunction 和 Tick thunk 仍直接走现有 ordinal router/prepared call，不增加第二层查找。

## 继承语义

基类 shell 可能先在 `Super::BeginPlay` 中建立最派生实例 Session。其静态 base type ordinal 与 Session 的
runtime type ordinal 不一致，因此 base canonical thunk fail closed；回到最派生 shell 后，同一 Host activation
幂等命中，随后仅最派生 canonical thunk 执行。EndPlay 反向执行并幂等释放，避免重复 Session 或 handle。

## 当前边界

自动 hook 已进入生成源码，但 Runtime Host 仍需要由 C2c4c 安装 registry + `.avidscript.json` artifact。
在 package 尚未安装时，activation 会记录明确错误并跳过脚本调用。
