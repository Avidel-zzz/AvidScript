# P59.C2c4f 脚本祖先路由与父类调用闭环

## 目标

让一个最派生的 C# 脚本实例同时正确承接三类调用：

- UE 虚调用进入派生脚本 `override`；
- 未覆写的 UFUNCTION 和生命周期通过父类原生壳层进入父类脚本；
- C# `base.Method()` 在 WASM 内直接调用父类脚本函数。

## 原问题

Runtime Host 已能按对象真实 UClass 解析最派生脚本类型，但 Session 只缓存该类型的一组
`PreparedCalls`。父类壳层携带父类 `TypeOrdinal` 调度时，会被“必须等于最派生类型序号”的检查拒绝。

这会影响两类真实用法：

- 派生对象调用未覆写的父类 UFUNCTION；
- 派生对象由父类壳层接入 `BeginPlay` 等生命周期。

WASM 内的 `base.Activate()` 并不存在这个问题。Guest IR 已将其降低为父类脚本函数的直接调用，
不经过 UE Host，也不产生额外反射或路由开销。

## 实现

Session 私有状态新增按类型序号稠密索引的 `PreparedTypeRoutes`。每条启用路由保存该脚本祖先类型的：

- 已解析 VM export handle；
- 已缓存调用形状；
- 成员序号到 prepared call 的直接映射。

Runtime 候选加载时遍历注册表，只为当前 receiver 满足 `IsA(Type.Class)` 的脚本类型准备路由。
兄弟类型和无关类型保持禁用。全部准备成功后，路由表与候选 Runtime 一起原子提交；失败时保留旧
Runtime 和旧路由，不污染在线实例。

热路径不再要求请求类型序号等于最派生类型，而是执行：

1. 校验 receiver、ObjectHandle、Session 与 Runtime generation；
2. 以 `TypeOrdinal` 直接索引祖先路由；
3. 以 `MemberOrdinal` 直接索引 prepared call 和调用形状；
4. 使用固定 call frame 进入 Wasmtime。

热路径没有名称查找、UFunction 查找、继承遍历和动态分配。

## C# 使用示例

```csharp
public partial class Projectile : AvidActor
{
    public virtual void Activate(float damageScale) { /* 修改 UE 原生属性 */ }

    public int GetActivationCount()
    {
        return ActivationCount;
    }

    protected override void BeginPlay()
    {
        HasBegunPlay = true;
    }
}

public partial class ExplosiveProjectile : Projectile
{
    public override void Activate(float damageScale)
    {
        base.Activate(damageScale * 2.0f);
    }
}
```

派生对象通过 `AProjectile*` 调用 `Activate(2.0f)` 时，UE 虚调用先进入派生导出，WASM 再直接调用
父类脚本函数，最终把 `Damage` 从 `25` 更新为 `100`。同一对象调用未覆写的
`GetActivationCount()`，会通过父类类型序号路由到父类导出。
