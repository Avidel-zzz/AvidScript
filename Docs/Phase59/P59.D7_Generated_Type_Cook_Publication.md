# P59.D7 Generated Type Cook 发布闭环

## 目标

让 C# Generated Type 的 WASM、类型 manifest、调试映射与 Binding package 脱离开发机 `Saved/`
目录，形成可由 UBT 暂存、可由非 Editor Runtime 加载的确定性发布物。

## 已实现

- `BuildCSharpScriptTypes.ps1` 在发布 Editor 热重载 descriptor 后，自动生成
  `Content/AvidScriptGenerated/<package-id>/` 内容寻址 bundle；
- bundle 固定包含类型 manifest、Runtime manifest、WASM、debug map 与两份 Binding 文件，
  `current.json` 以原子替换方式指向当前 package；
- 发布器验证所有输入 SHA、限制路径不得逃逸项目根，并清除仅属于编译期的 `Saved/` provenance 路径；
- Binding `package.json` 会同步改写 descriptor 相对路径，随后逐层重算 Binding manifest、Runtime
  manifest 与最终 package id；
- `AvidScriptGenerated.Build.cs` 使用 `EpicGames.Core.JsonObject` 解析 pointer，只登记当前 package 的
  六个 `NonUFS` RuntimeDependency，并把 pointer 与 bundle 文件加入 `ExternalDependencies`；
- Editor 优先加载 `Source/AvidScriptGenerated/AvidScriptGeneratedPackage.json` 保持热重载体验；非 Editor
  只读取 `Content/AvidScriptGenerated/current.json`；
- `Content/AvidScriptGenerated/` 是可再生构建产物，已加入 `.gitignore`，不会把项目脚本二进制提交到插件仓库。

## 发布布局

```text
Content/AvidScriptGenerated/
  current.json
  <package-id>/
    type-manifest.json
    runtime-manifest.json
    generated_types.wasm
    generated_types.debug.json
    bindings/package.json
    bindings/bindings.json
```

## 验证

- PowerShell Cook publication contract：通过，覆盖确定性发布、项目根边界、输入篡改拒绝、路径重写；
- 真实 C# ScriptDefinedTypes 生成：5 个 UE 类型，3 个 generator cache hit，bundle 发布成功；
- UE5.8 no-clean `AvidTPSTemplateEditor Win64 Development`：成功；
- Target receipt：只包含 `current.json` 与当前 package 的六个 NonUFS 文件，不包含两个旧 package id；
- `AvidScript.GeneratedTypes`：发现 7 项、成功 7 项、失败 0 项；
- `AvidScript.GeneratedTypes.CookedPackageLoad` 使用 isolated Runtime Host 从 Cook 布局完成 SHA、Binding
  identity、WASM 与 debug map 的真实加载。

## 失败复盘

1. Build.cs 首版使用 `System.Text.Json`，与 UE5.8 bundled .NET 10 RulesAssembly 的引用不兼容；已改用
   UBT 自带 `EpicGames.Core.JsonObject`。
2. 已位于插件 Content 的文件不能用相同 source/target 注册 RuntimeDependency；已改为单路径 overload。
3. 首版只重写 Runtime manifest，遗漏 Binding `package.json` 的 descriptor 文件名；真实 Runtime load
   正确 fail-closed，现已同步重写嵌套 manifest 并逐层重算 SHA。

对应预防规则已写入 `AgentHarness/lessons/rules.json`。
