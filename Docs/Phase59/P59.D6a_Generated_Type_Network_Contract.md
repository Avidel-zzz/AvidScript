# P59.D6a 脚本定义类型网络合同

## 目标

让 C# 脚本定义 Actor/Component 的 replicated property 与 Server、Client、NetMulticast UFUNCTION
形成标准 UE 网络壳层，并在进入 UHT 前拒绝 UE 不支持的声明。

## 实现

- `Projectile` 新增 Reliable Server、Client 与 NetMulticast 方法；函数体继续编译到 WASM，C++ 壳层只负责
  UE callspace 与 ordinal dispatcher。
- Actor 声明 replicated property 或 RPC 时生成 `bReplicates = true`；ActorComponent 对应生成
  `SetIsReplicatedByDefault(true)`，不要求开发者再维护一份原生构造函数。
- World/GameInstance Subsystem 不具备 UE 网络 callspace；其 replicated property 或 RPC 在 Semantic
  projection 和共享 artifact validator 两层 fail closed。
- C# 名称区分大小写，UE 反射名称不区分。类型名、反射成员名与 UFUNCTION 参数名现在按
  `OrdinalIgnoreCase` 校验；参数不得遮蔽同一 UClass 的反射成员。
- 生成器合同版本从 `1.6` 提升到 `1.7`，构建脚本、Runtime registry、测试 fixture 与架构门禁同步更新。

## C# 示例

```csharp
[UFunction(Server = true, Reliable = true)]
public void ServerSubmitDamage(float submittedDamage)
{
    Damage = submittedDamage;
    ServerRpcCount += 1;
}

[UFunction(Client = true, Reliable = true)]
public void ClientConfirmDamage(float confirmedDamage) { /* C# body */ }

[UFunction(NetMulticast = true, Reliable = true)]
public void MulticastObserveDamage(float observedDamage) { /* C# body */ }
```

这些方法生成标准 `UFUNCTION(Server/Client/NetMulticast, Reliable)` 和 `_Implementation`，不存在按项目
API 手写 Host wrapper，也不在热路径按名称查找。

## 边界

本节证明声明、UHT flags、自动复制开关和 authority 进程内执行。Client 到 Server、Server 到 owning
Client、NetMulticast 与 replicated property/RepNotify 的真实跨进程传输由 P59.D6b 验收；本节结果不能
替代该双端证据。
