# P14.0 C# Source Adapter Scope

## Status

- Status: Done
- Date: 2026-07-06

## Goal

Phase 14 turns the Phase 13 C# sample from a diagnostic-only artifact into a real AvidScript direct ABI WASM artifact.

The selected route is a constrained C# source adapter:

- read the C# lifecycle source file
- extract `BeginPlay()` and `Tick(float deltaSeconds)`
- compile supported `Actor.SetLocation(...)` statements into a small direct ABI WASM module
- write a normal `.avidscript.json` manifest
- keep the .NET/WASI route as fallback diagnostic only

## Why This Route

Phase 13 proved the local .NET WASI output does not export `avid_on_begin_play` or `avid_on_tick`. Waiting on full .NET direct export support would block UE interaction validation.

The source adapter keeps the user-facing authoring syntax in C# while producing the exact WASM ABI the current runtime already supports.

## Supported Subset

Current subset:

- static `BeginPlay()` lifecycle method
- static `Tick(float deltaSeconds)` lifecycle method
- `Actor.SetLocation(float x, float y, float z)` calls
- numeric float literals such as `100.0f`
- `deltaSeconds`
- `deltaSeconds * numeric literal`
- addition of supported expressions, for example `100.0f + 120.0f * deltaSeconds`

Current self binding:

- generated WASM calls `env.actor_set_location`
- owner/self actor is represented as slot `1`, generation `1`
- this matches the per-component/per-session first owner registration model used by the current smoke tests

## Non-Goals

- full C# semantic compilation
- arbitrary method calls/classes/properties
- managed .NET runtime embedding
- mobile packaging validation
- final Editor UX
