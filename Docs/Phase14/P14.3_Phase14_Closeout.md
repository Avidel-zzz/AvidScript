## 现在能做到什么

开发者可以在当前支持子集内编辑 C# 样例，然后运行：

```powershell
powershell -ExecutionPolicy Bypass -File Plugins/AvidScript/Build/BuildCSharpActorLifecycle.ps1
```

脚本会在以下目录生成可加载的 WASM + manifest：

```text
Saved/AvidScriptCSharpGuest/ActorLifecycle
```

生成模块导出：

- `avid_on_begin_play`
- `avid_on_tick`

生成模块导入：

- `env.actor_set_location`

## 剩余缺口

这还不是完整 C# 编译器。它是一个 PC-first 的实用桥接方案，用于尽快验证 C# gameplay 语法与现有 WASM binding 的闭环。

重要剩余工作：

- `UAvidScriptComponent` 仍需要 manifest path/runtime-load 模式，而不是只加载 embedded smoke module。
- self Actor 绑定需要变成显式 host context 或 `self` import，不能长期假设 slot `1`、generation `1`。
- Editor command/settings 需要接入 C# adapter 路线。
- 诊断信息需要定位到不支持的 C# 源码行。

## 推荐下一阶段

Phase 15 应该把生成的 C# 产物接入 UE 组件生命周期：

- 在 `UAvidScriptComponent` 上暴露 manifest path 或 script source path
- 在 `BeginPlay` 加载生成的 manifest/WASM，而不是 embedded smoke module
- 在 `TickComponent` 调用 `avid_on_tick`
- 用自动化验证组件级生命周期

这一步会把当前能力从 runtime proof 推进成关卡内可用的 gameplay 工作流。
