# Phase 61 实施计划

## P61.A 增量构建与结构化诊断

1. `P61.A1` 完整编译产物 cache：确定性 fingerprint、原子 publish、严格 restore、损坏隔离和 build report 指标；
2. `P61.A2` persistent compiler worker：版本化 JSON-lines、Roslyn workspace 重用、取消/超时/崩溃回退；
3. `P61.A3` 诊断统一：所有编译 stage 使用稳定 code/span/stage/source hash，Editor 支持源码导航；
4. 建立 no-op、方法体编辑、binding 变化和 toolchain 变化的增量性能矩阵。

完成条件：Editor 连续构建同一 C# workspace 时可证明完整 cache hit 不启动四个编译工具；修改方法体只失效必要节点，错误能定位到 C# span。

## P61.B 指令级 Source Map 与调用栈

1. DebugMap schema v2 与兼容读取；
2. Guest IR sequence point 和 WASM backend offset 回填；
3. Runtime 二分映射、async resume/host crossing frame 合并与 reload generation 校验；
4. Editor 调用栈模型与源码导航。

完成条件：同步、异步、递归与 UE crossing trap 均能稳定映射到语句级 C# span，v1 artifact 继续按函数级兼容。

## P61.C 断点、单步与变量查看

1. debug probe ABI、capability negotiation 与 Debug/Release instrumentation policy；
2. Session debug lane、pause/resume/step 状态机与 teardown/reload 取消；
3. debug frame、lexical scope 和有界变量 snapshot；
4. Editor breakpoint/session/view-model，不在 GameThread 上做阻塞等待。

完成条件：PIE 中可在 C# 语句断下、查看受支持变量、单步并继续；World teardown、热重载和客户端断开均能自动回收调试状态。

## P61.D Profiler 与 IDE Workspace

1. lock-free/bounded profiler event buffer 与 UE Trace 输出；
2. Guest、UE crossing、continuation、reload 和 compile/cache 事件；
3. Editor snapshot/过滤/导出模型；
4. `.slnx`、`.editorconfig`、source index 与 Visual Studio/Rider/VS Code 打开命令。

完成条件：Profiler disabled 性能门禁通过，enabled 数据可关联 source map；workspace 刷新不覆盖用户文件。

## P61.E 集成与 Gate

- 固定 .NET/PowerShell/UE5.8 Automation/architecture 全量 Gate；
- no-clean Editor UBT；
- 增量构建与 profiler 性能矩阵；
- 人工 PIE 断点、变量、源码跳转和三类 IDE workspace 验收清单；
- README 只更新已验证能力和边界；
- attestation、close、推送并核对远端 SHA。

## 提交与验证节奏

- 每个可审阅小节精确 whitelist 提交并立即推送；
- 普通小节只跑静态、console 与必要 focused 证据；
- 一个大批次结束后统一 UBT/Automation，P61.E 再做完整 Gate；
- 非阻塞问题登记后批次末集中处理，不串行化重复复审；
- freeze 前运行完整 Phase commit-range whitespace、隐私与受保护 dirty 预检。

## 验证预算

- UBT：实现批次合计最多 4 次，阶段 Gate 1 次 no-clean；
- Automation：focused 最多 3 轮，完整 Gate 最多 2 轮；
- benchmark 固定 workload/warmup/sample，不以重跑择优掩盖失败。
