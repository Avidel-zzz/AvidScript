# P61.B1b Runtime Sequence Point 映射

## 已实现

- Runtime DebugMap loader 同时接受 v1/`1.0` 与 v2/`2.0`，版本组合不匹配时 fail-closed；
- v2 provenance 额外验证 DebugMap 中的 WASM SHA-256 与已校验 manifest/WASM 一致；
- 每函数最多 `16384` 个 sequence point，单 module 最多 `262144` 个，artifact 仍受 `4 MiB`
  总大小限制；
- loader 验证 offset 单调、Guest instruction/semantic operation identity 唯一、kind、hidden 与
  C# span 合法；
- trap frame 使用二分查找解析最后一个 `offset <= function_offset` 的可见 sequence point，
  hidden 点向前回退；
- frame 暴露 `SourceKind` 与 `bSequencePointMapped`，便于 Editor 区分语句级映射和函数级回退；
- v1 或落在首个 sequence point 之前的 frame 继续映射到函数声明 span，不伪造语句位置。

## 复杂度与边界

- 加载复杂度为 `O(N)`，所有字符串、函数数、sequence point 数和 artifact 字节数有界；
- 单帧映射为 `O(log P)`，其中 `P` 是该函数的 sequence point 数；
- 映射过程不进行名称反射、不读取源码文件，也不分配新的索引结构；
- async resume 的精确序列点已由 `P61.B1c` 补齐；UE host crossing 的逻辑帧合并属于后续
  `P61.B2`。
