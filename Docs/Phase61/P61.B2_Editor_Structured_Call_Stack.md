# P61.B2 Editor 结构化调用栈

## 已实现

- Runtime diagnostic frame 使用强类型 `Wasm / CSharp / HostImport / HostEntry` 分类；
- VM trap 保留原始函数 index、offset 与 token，同时把 Guest frame 映射到 C# sequence point；
- host import 失败在栈顶加入 `HostImport`，每次 UE 调用 Guest 的失败在栈底加入 `HostEntry`，
  可观察 `UE -> C# -> UE` 边界；
- Runtime frame 携带 Debug Map 的 source SHA，Editor 导航继续执行项目相对路径、目录逃逸、
  文件存在性与 SHA 校验；
- `FAvidScriptEditorCallStack` 将 Runtime 证据投影为独立展示模型；
- AvidScript Message Log 为可导航帧生成 `Open source` action token，点击后通过当前源码访问器
  打开精确行列；不可映射帧仍保留 WASM 证据，不伪造源码位置。

## 架构边界

- Runtime 不依赖 Editor、Message Log 或源码访问器；
- Result Presenter 只携带结构化模型，Message Log 发布与源码打开分别由独立服务负责；
- 所有额外分配都位于失败诊断路径，不进入 Tick 成功热路径。
