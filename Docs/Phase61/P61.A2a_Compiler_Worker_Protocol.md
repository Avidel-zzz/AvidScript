# P61.A2a Persistent Compiler Worker 协议

## 范围

本小节建立可长期驻留的 C# 编译进程与稳定 IPC 合同，但尚未替换现有 Build 脚本的
one-shot 调用。构建链路自动连接、超时/崩溃回退和 Roslyn workspace 复用属于
`P61.A2b`。

## 已实现

- 新增 `AvidScript.CSharpCompilerWorker`，在同一进程内调用 Frontend、Semantic、
  Guest IR 与 WASM backend，避免通过子进程重复启动各阶段 CLI；
- 协议使用严格的 JSON-lines v1，未知字段、错误版本、无效 stage、非绝对路径、
  非法 source id 与 toolchain fingerprint 不匹配均 fail-closed；
- 使用 Windows named pipe 和 `CurrentUserOnly`，每个请求拥有 request id、stage、
  worker instance id、耗时、退出码和有界诊断；
- 空闲超时只覆盖等待下一连接，不会取消已接收的长编译请求；支持显式 `shutdown`，
  Worker 实例标识在连续请求间保持稳定；
- WASM backend 的命令行入口已抽为可复用 API，命令行程序行为保持不变。

## 验证

固定 .NET SDK `8.0.416` 下：

```powershell
dotnet build Tools/AvidScript.CSharpCompilerWorker/AvidScript.CSharpCompilerWorker.csproj --configuration Release
pwsh -NoProfile -File Tools/AvidScript.CSharpFrontend.Tests/CompilerWorkerProtocolTests.ps1
```

结果：Worker 项目 `0 warning / 0 error`；协议测试在同一 Worker 实例完成
`ping -> Frontend -> Semantic -> Guest IR/WASM -> invalid-version -> shutdown`，并验证连接建立后
超过 idle timeout 仍可完成请求。

## 剩余边界

- Build 脚本目前仍使用 one-shot 编译器，本小节不能宣称编辑器构建已经减少进程启动；
- Roslyn metadata/reference syntax tree 的跨请求复用尚未接入；
- Worker crash、请求 timeout、自定义 Guest compiler 与 fallback 策略将在 `P61.A2b` 验证。
