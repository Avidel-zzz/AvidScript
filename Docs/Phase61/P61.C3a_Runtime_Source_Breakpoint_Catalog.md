# P61.C3a Runtime 源码断点目录

## 目标

为 Editor 调试会话提供稳定的源码断点候选，避免 Editor 重复解析 Debug Map 或依赖 Runtime 私有结构。

## 已实现

- 新增 `FAvidScriptDebugBreakpoint`，包含稳定 probe ID、WASM 函数位置、项目相对源码、源码 hash、
  C# 函数名、序列点类型和一基源码 span；
- `FAvidScriptWasmDebugMap` 只枚举非隐藏且真实带 probe 的序列点；
- 目录按 WASM 函数索引和函数内指令偏移确定排序；
- `FAvidScriptRuntimeSession::GetDebugBreakpointCatalog` 只读取当前 live manifest 中已经验证的 Debug Map；
- 无 live module、缺少 Debug Map 或旧版无调试元数据时 fail-closed，并清空输出。

## 架构边界

- Runtime 负责 Debug Map provenance、schema 和 WASM layout 校验；
- Editor 只消费公开目录并维护用户断点，不接触 JSON artifact；
- probe ID 是执行绑定身份，源码路径与 span 用于展示和邻近行解析；
- 当前小节不宣称 Editor 已能点击设置断点，交互模型由 `P61.C3b-C4` 完成。

## 验证

- `AvidScript.Runtime.Diagnostics.DebugMapValidation` 覆盖过滤、顺序、源码身份、hash、函数、kind 与一基坐标；
- `AvidScript.Runtime.Diagnostics.ManifestRuntimeIntegration` 覆盖 Session 查询和缺失 Debug Map 的拒绝路径；
- Runtime 模块使用 UE5.8 no-clean UBT 构建；
- 阶段末再执行 Phase 61 集中 Gate。
