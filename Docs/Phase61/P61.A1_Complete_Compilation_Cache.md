# P61.A1 完整编译产物缓存

## 目标

在不改变 Runtime manifest 与 WASM 加载合同的前提下，为 C# 构建链增加第二层内容寻址缓存。
当源码、binding、编译配置和工具链均未变化时，构建可以直接恢复 Guest IR、DebugMap、
状态 schema、WASM 与 WASM inspection，不再启动 Frontend、Semantic、Guest IR 或 WASM backend。

## 已实现

- 保留原有 Frontend/Semantic cache，并增加独立的完整编译产物 cache；
- 缓存键覆盖 Frontend/Semantic 哈希、模块、配置、data lane、授权与运行时 binding package；
- 工具链指纹覆盖锁定源码、实际 Guest compiler 与实际 `dotnet` 可执行文件内容；
- 条目按 key 加锁，通过同根 staging 目录原子发布；
- restore 校验 schema、key、工具链、Semantic 身份、固定文件名和每个产物 SHA-256；
- 损坏条目移入 `.corrupt` 后回退真实编译，成功后重新发布；
- 导入与发布路径必须唯一、无 reparse point，并且不能位于 cache 根目录内；
- build report 增加 `compilation_cache` 与四类产物复用字段；
- Editor BuildService、pipeline 聚合、结构化报告和结果面板已接入同一元数据合同。

缓存条目包含：

1. `guest_ir.json`；
2. `debug_map.json`；
3. `state_schema.json`；
4. `module.wasm`；
5. `wasm_inspection.json`；
6. 带完整哈希和 provenance 的 `entry.json`。

## 兼容修复

真实冷/热验证暴露并修复了原语义缓存的两个 StrictMode 边界：拒绝路径未初始化
`CorruptEntryPath`，以及 winner 校验直接访问可省略的空 artifact 字段。修复后仍会拒绝任何
非空 loadable artifact 引用，不会放宽 immutable Semantic cache 的安全边界。
