# P61.D1b Runtime Profiler 埋点

## 目标

在不让 Editor 依赖 Runtime 私有实现的前提下，把 `P61.D1a` 的有界事件通道接入真实脚本执行路径，
让一次 C# 游戏逻辑调用能够关联 Guest 执行、UE crossing、异步 continuation、reload 和生命周期事件。

## 已实现

- 每个 `FAvidScriptRuntimeSession` 独立拥有 profiler buffer，并通过公开 snapshot API 向上层提供只读数据；
- Session 记录 Runtime load、Tick、普通 Event、Gameplay Event、Delegate、continuation、debug resume、
  reload 与 EndPlay；
- WASM host dispatcher 在统一入口记录静态 Binding 和动态 Reflection host call，避免为每个 UE API 手写埋点；
- 事件仅保存数值化 kind、operation、epoch、probe、correlation、耗时和结果，热路径不分配字符串；
- profiler 开关、buffer 和 UE Trace channel 相互独立，关闭 buffer 后不会继续写入 Session 快照；
- reload 候选 Runtime、HostContext 切换和 teardown 均维持同一个 Session-owned profiler 生命周期。

## 验证

- `AvidScript.Runtime.Profiling`：`3/3` 通过，覆盖事件环、禁用快路径和真实 Session 的 load/Tick/host call；
- `AvidScript.Editor.Debugging.PIEIntegration`：`1/1` 通过，真实 Debug C# WASM 覆盖 Tick guest work、
  带 probe 的 UE crossing、reload 与 continuation；
- `AvidScriptEditor` UE5.8 增量构建：`3/3` action 通过；
- Runtime 公开布局变更后执行 no-clean `AvidTPSTemplateEditor` 重链接：`12/12` action 通过。

## 边界

- 本小节只交付采集与关联数据，不包含 Editor 聚合、过滤、时间线和导出界面；
- profiler disabled 的独立性能预算由 `P61.D1c` 固化；
- PIE 用例在验证调试交互后 detach debugger，再推进 World frame，以免保留的 Tick 断点重新挂起异步链。

## 复发预防

`FAvidScriptWasmHostContext` 是 Runtime 与 Editor 消费方共享的公开布局。修改该布局后，只构建 Runtime
会让旧 Editor DLL 继续按旧偏移读取字段。以后这类变更必须执行一次 no-clean Editor consumer 重链接，
禁止通过 target clean 解决。
