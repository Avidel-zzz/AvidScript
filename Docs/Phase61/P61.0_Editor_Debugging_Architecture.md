# Phase 61 编辑器与调试架构

> 状态：架构冻结候选 v1
> 主线：增量构建 -> 结构化诊断 -> 指令级 source map -> cooperative debugger -> Profiler/IDE

## 1. 目标

Phase 61 把现有 C# 构建、热重载、DebugMap 和 Editor 命令升级为可持续使用的游戏脚本开发环境：

- 无变化构建不再启动 Frontend、Semantic、Guest IR 或 WASM backend；
- 编译错误、运行时 trap 与异步恢复帧都能定位到项目相对 C# 源码；
- 断点、暂停、继续、单步和变量查看使用同一套后端无关协议；
- Profiler 统一采集 Guest 函数、UE crossing、continuation 和 GC/handle 成本；
- IDE workspace 可被 Visual Studio、Rider 和 VS Code 直接打开，不覆盖用户文件。

## 2. 已有基础

当前主线已经具备：

- Roslyn Frontend 与 Semantic artifact，以及受控 semantic cache；
- Guest IR、WASM inspection、状态 schema 与内容寻址 Runtime manifest；
- function-level DebugMap、Wasmtime/WAMR stack frame 和 Editor 诊断展示；
- Project C# workspace、异步构建、DirectoryWatcher、事务式热重载；
- Session-owned continuation、对象句柄和 reload generation。

P61 扩展这些合同，不建立第二套编译器、scheduler、对象模型或 VM 生命周期。

## 3. 分层设计

### 3.1 Incremental Build Coordinator

`Build/` 负责确定性 fingerprint、缓存命中、原子发布和命令行合同；Editor 只提交请求并消费机器报告。

完整编译缓存以以下输入为键：

- Frontend/Semantic artifact hash；
- authorization/runtime binding package identity；
- Guest IR、WASM backend 与 ABI toolchain fingerprint；
- configuration、data-lane fusion、debug instrumentation policy；
- schema/version 和目标后端。

缓存只保存可重定位产物：Guest IR、DebugMap、state schema、WASM 和 inspection。最终 report、manifest 与项目路径始终在活动构建目录重新生成。命中项必须验证 hash、provenance、module id、导入导出和 binding capability，异常项隔离后 fail closed 到正常编译。

后续 persistent compiler worker 使用版本化 JSON-lines 协议维持 Roslyn workspace 与 lowering graph；worker 崩溃不得污染最后成功产物，Editor 可回退到一次性进程。

### 3.2 Diagnostic Model

编译与运行诊断统一为不可变记录：

- stable code、severity、stage、message；
- project-relative source id 与 source hash；
- 1-based line/column/end span；
- module/build/reload generation；
- related frames、notes 和可执行 next action。

用户可见文案不携带绝对用户目录。原始 stderr 仅保存在本地诊断附件，不作为结构化身份。

### 3.3 DebugMap v2

DebugMap v2 在 v1 function mapping 上增加有序 sequence points：

- WASM function index 与 function-relative offset；
- Guest instruction/semantic operation identity；
- C# source span；
- hidden、statement、call、await、return 等 kind；
- 可选 lexical scope 与 debug slot layout。

WASM backend 是 offset 的唯一权威来源；Guest projector 不能猜测编码长度。Runtime 继续验证 source/frontend/semantic/Guest IR/WASM layout provenance，并以二分查找解析最近且不越界的 sequence point。

### 3.4 Cooperative Debug Runtime

调试构建在稳定 sequence point 插入 `avid_debug_probe`，Release/Shipping 默认不插入。probe id 由 module identity、method symbol 和 sequence point 稳定派生。

启用断点时，编译器把可观察局部值写入受控 debug frame，再通过 Session debug lane 产生 pause continuation。暂停、继续和单步复用 Session generation 与 teardown 取消，不阻塞 UE GameThread，也不暴露原始 WASM 内存或 `UObject*`。

首版变量查看覆盖标量、值类型、字符串摘要、ObjectHandle 与容器摘要；展开操作必须有深度、元素数与字节预算。

### 3.5 Profiler

Profiler 使用固定容量、单生产者事件缓冲：

- Guest function enter/leave；
- UE prepared call 与 VM crossing；
- continuation schedule/resume/cancel；
- reload、cache hit/miss 与 compile stage；
- handle/value heap 高水位。

关闭采集时 hot path 只允许一个可预测分支；开启时按线程批量提交到 UE Trace/Editor snapshot，不在调用路径格式化字符串。

### 3.6 IDE Workspace

Workspace generator 负责 `.slnx`/project、`.editorconfig`、generated facade ownership、diagnostic/source-map index 和可选 VS Code/Rider 元数据。用户源码、IDE 配置与 generated 文件分区；刷新默认只覆盖生成区。

## 4. 所有权与依赖方向

- `Tools/AvidScript.CSharp*`：语义、sequence point、debug slot 与诊断生成；
- `Tools/AvidScript.WasmBackend`：最终指令 offset 与 debug section/layout；
- `Build/`：缓存、worker 协议、artifact publication 与 workspace CLI；
- `AvidScriptVM`：stack frame、debug probe host import、后端 capability；
- `AvidScriptRuntime`：debug session、pause continuation、变量 snapshot 与 profiler event；
- `AvidScriptEditor`：命令、面板模型、源码导航、IDE 启动与结果展示。

依赖必须保持 `Editor -> Runtime -> VM -> Core`；Tools 与 Runtime 只通过版本化 JSON/ABI 交互。

## 5. 性能与安全门禁

- warm no-op build：P50 目标小于 100 ms，四个编译工具 invocation 均为 0；
- 单文件方法体编辑：P50 目标小于 500 ms，不重建 binding package；
- source-map lookup：P50 小于 2 us，不进行名称反射；
- profiler disabled：典型 Tick workload 增量小于 1%；
- profiler enabled：事件缓冲不分配、丢弃可计数、不得阻塞 GameThread；
- debug frame、变量展开、路径与 artifact 大小全部有界；
- Shipping 默认拒绝 debugger attach、绝对路径和未签名 debug artifact。

## 6. 不在本阶段伪装完成的内容

- 不把函数级 trap 映射宣称为指令级 source map；
- 不把日志打印宣称为断点或变量查看；
- 不把单次进程 cache hit 宣称为 Roslyn 增量 workspace；
- 不把 Automation 截图或源码回读代替人工 IDE、断点和 PIE 操作验收；
- P62/P63 的 Shipping、签名策略和移动端调试只冻结接口，不提前宣称通过。
