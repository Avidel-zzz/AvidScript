# P61.C2b1 协作式暂停 Frame

## 本节完成

- 冻结两阶段暂停协议：`avid_debug_probe` 只返回决策，`avid_debug_suspend` 在 Guest 完成
  spill 后提交稳定 probe、resume route 与 frame，提交成功才进入 `Paused`。
- 新增 `avid_debug_frame_read`，continue/step 恢复时以不可伪造的 Session token 读取一次 frame；
  token、尺寸或状态不匹配时 fail-closed。
- frame 上限为 `4096` 字节，VM 在进入 Runtime 前校验地址、长度和读写方向。
- Wasmtime 与 WAMR 共用静态导入目录；WAMR native wrapper 已完成只读/可写 Guest 内存翻译。
- Runtime 将 suspend/read 路由到 Session debug lane；reload、unload、detach 会使旧 token 与 frame
  失效，断点集合仍按 Session 生命周期管理。
- `Suspending -> Paused -> Resuming -> Running` 明确区分“命中意图”和“可恢复暂停”，避免
  Editor 在 frame 尚未保存时错误显示已暂停。

## 当前边界

Host/VM 侧的暂停存储闭环已经完成，但 Guest 编译器尚未生成 spill、resume route 和恢复 export。
因此当前 C# 产物仍只调用 probe，不能宣称真实断点已经可用。`P61.C2b2` 将对受支持的同步入口
生成可恢复状态机并消费本节 ABI。
