# P3.3 Minimal WASM Import Bridge

日期: 2026-07-03
状态: Done

## 范围

P3.3 将 AvidScript 从“UE 调 WASM export”推进到“WASM guest 调 host import”的最小闭环。本阶段只注册 deterministic smoke import, 不引入 UObject/Actor 真实 gameplay ABI, 不做反射路径, 不做移动端或 packaged 验证。

目标路径:

- WASM guest 在 `avid_on_begin_play` 中调用 `avidscript.host_add_i32(41)`。
- Host import 返回 `42`, 并在 runtime result 中记录 call count、input、result 和 host import timing。
- 缺失 import 在 load 后 instantiate 前被 preflight 拦截为 `missing_import`。
- Host-side import failure 被转成 `host_import_failed`, Editor 不崩溃。

WAMR native symbols:

```text
module: avidscript
import: host_add_i32(i32) -> i32
import: host_fail_i32(i32) -> i32
```

注册策略:

- `AcquireWamrRuntime` 在 refcount 从 0 进入 1 时初始化 WAMR 并注册 AvidScript native symbols。
- `ReleaseWamrRuntime` 在 refcount 回到 0 时 unregister native symbols 并 destroy WAMR runtime。
- native symbol array 为静态存储, 满足 WAMR “注册后数组需长期有效且可被排序修改” 的要求。
- `wasm_runtime_set_user_data` 将当前 `FAvidScriptWasmRuntimeInstance` 绑定到 exec env, host import 回调通过 `wasm_runtime_get_user_data` 回到 instance 记录结果。

Import preflight:

- `LoadModule` 在 `wasm_runtime_load` 成功后、`wasm_runtime_instantiate` 前遍历 `wasm_runtime_get_import_count/get_import_type`。
- 对 function import 只信任 `wasm_import_t.linked`, 避免同名但签名不匹配的 import 被名字检查误放行。
- 未链接 import 返回 `missing_import`, diagnostic 中包含 `import=module.name`。

## 初步结论

P3.3 已证明 WAMR guest 可以通过 registered native symbols 调回 AvidScript host。当前实现保持 fail-closed: 缺失 import、host import 内部失败都会转成结构化 diagnostics, 不崩 Editor。

这为后续真实 UE host ABI 打下了桥: 下一阶段可以在此基础上选择把 P2.1/P2.2 的 handle registry 与 Actor binding 映射为 WASM import, 或先进入 P3.4 热重载工作流设计。

## 风险

- 当前只覆盖 deterministic `i32 -> i32` smoke import, 尚未覆盖 handle、float/vector、string/memory pointer 或 batch ABI。
- 当前 import module 名固定为 `avidscript`, 后续正式 ABI 需要版本化命名或 manifest 声明。
- Host import timing 只是 host callback 内部 smoke timing, 不是完整 guest->host crossing benchmark。
- 当前验证为 Editor/NullRHI Development, 未做 packaged/shipping 或移动端。
