# P3.5 Android Runtime Pre-Adaptation

日期: 2026-07-03
状态: Done

## 1. 目标

P3.5 为 AvidScript 的 Android runtime 接入做预适配设计。本阶段只写策略文档, 不修改 `WAMR.Build.cs`, 不构建或提交 Android 静态库, 不做 Android packaging 或设备运行验证。

目标:

- 明确 WAMR Android 构建入口、NDK/CMake 输入和目标 ABI。
- 定义 Android 静态库输出目录和命名约定。
- 规划 `WAMR.Build.cs` 后续 Android branch points。
- 明确移动端 runtime 文件加载策略与限制。
- 定义何时可以把 Android 二进制加入插件仓库。

## 2. 当前基线

已完成:

- WAMR source-vendored snapshot: `WAMR-2.4.4`, commit `8c18e3f68b16c4bcaf05996b2636f6ed2b4cf629`。
- Win64 静态库: `Source/ThirdParty/WAMR/lib/Win64/Release/libiwasm.lib`。
- `WAMR.Build.cs` 已按 headers + platform library guard 输出 `AVIDSCRIPT_WITH_WAMR=1/0`。
- P3.1-P3.3 已在 Win64 Editor 验证 runtime benchmark、host binding benchmark 和 minimal WASM import bridge。

本地 WAMR snapshot 中可用 Android 入口:

- `Source/ThirdParty/WAMR/upstream/product-mini/platforms/android/CMakeLists.txt`
- `Source/ThirdParty/WAMR/upstream/core/shared/platform/android/shared_platform.cmake`
- `Source/ThirdParty/WAMR/upstream/core/shared/platform/android/platform_internal.h`

WAMR upstream Android CMake 默认会构建 shared `iwasm`, 同时也定义 static `vmlib` target。AvidScript 后续优先接入 static `vmlib`, 与当前 Win64 static link 策略保持一致。

## 3. Android ABI 范围

首轮目标:

| ABI | WAMR target | 用途 | 状态 |
| --- | --- | --- | --- |
| `arm64-v8a` | `AARCH64` | 真机主路径 | Required |
| `x86_64` | `X86_64` | Emulator / CI 可选路径 | Optional |

暂缓:

| ABI | 原因 |
| --- | --- |
| `armeabi-v7a` | 32-bit 移动端价值较低, 还会放大 ABI/包体/测试矩阵。 |
| `x86` | 32-bit emulator 价值低。 |
| `riscv64` | UE Android 支持与设备覆盖暂不作为 MVP 范围。 |

首轮 Android runtime 支持口径:

- PC-first/mobile-aware, 不把 Android 设备 smoke 放进 P3.5。
- 不启用 AOT/JIT/Fast JIT。
- 不启用 WASI、pthread、wasi-threads。
- 不启用 multi-module。
- 不把 Editor watcher/hot reload 带到移动端。

## 4. 构建输入

建议使用 UE 配置过的 Android SDK/NDK, 并让 WAMR CMake 看到以下环境变量:

```text
ANDROID_HOME=<Android SDK root>
ANDROID_NDK_LATEST_HOME=<Android NDK root>
```

WAMR Android CMake 会读取:

```text
$ANDROID_NDK_LATEST_HOME/build/cmake/android.toolchain.cmake
ANDROID_HOME
ANDROID_NDK_LATEST_HOME
ANDROID_ABI
ANDROID_PLATFORM
WAMR_BUILD_TARGET
```

建议固定:

```text
ANDROID_PLATFORM=24
CMAKE_BUILD_TYPE=Release
```

`ANDROID_PLATFORM=24` 与 WAMR Android CMake 当前默认值一致, 也避开较低 API 上部分 POSIX fallback 的不确定性。若项目 Android minSdk 后续低于 24, 需要专门重测 WAMR platform layer。

## 5. 建议 CMake 配置

`arm64-v8a`:

```powershell
cmake -S "<Plugin>/Source/ThirdParty/WAMR/upstream/product-mini/platforms/android" `
  -B "<Plugin>/Source/ThirdParty/WAMR/build/Android/arm64-v8a/Release" `
  -G Ninja `
  -DCMAKE_BUILD_TYPE=Release `
  -DWAMR_BUILD_TARGET=AARCH64 `
  -DANDROID_ABI=arm64-v8a `
  -DANDROID_PLATFORM=24 `
  -DWAMR_BUILD_INTERP=1 `
  -DWAMR_BUILD_FAST_INTERP=1 `
  -DWAMR_BUILD_AOT=0 `
  -DWAMR_BUILD_JIT=0 `
  -DWAMR_BUILD_FAST_JIT=0 `
  -DWAMR_BUILD_LIBC_BUILTIN=1 `
  -DWAMR_BUILD_LIBC_WASI=0 `
  -DWAMR_BUILD_MULTI_MODULE=0 `
  -DWAMR_BUILD_LIB_PTHREAD=0 `
```

```powershell
  -DWAMR_BUILD_INTERP=1 `
  -DWAMR_BUILD_FAST_INTERP=1 `
  -DWAMR_BUILD_AOT=0 `
  -DWAMR_BUILD_JIT=0 `
  -DWAMR_BUILD_FAST_JIT=0 `
  -DWAMR_BUILD_LIBC_BUILTIN=1 `
  -DWAMR_BUILD_LIBC_WASI=0 `
  -DWAMR_BUILD_MULTI_MODULE=0 `
  -DWAMR_BUILD_LIB_PTHREAD=0 `
  -DWAMR_BUILD_LIB_WASI_THREADS=0 `
  -DWAMR_BUILD_SIMD=0 `
  -DWAMR_BUILD_MINI_LOADER=0
cmake --build "<Plugin>/Source/ThirdParty/WAMR/build/Android/x86_64/Release" --target vmlib
```

注意:

- WAMR Android CMake 默认 `WAMR_BUILD_AOT=1` 和 `WAMR_BUILD_LIBC_WASI=1`; AvidScript 首轮必须显式关闭, 与 Win64 spike 口径一致。
- `vmlib` 是 static target, 预期产物通常为 `libvmlib.a`。
- 如果后续选择 shared `iwasm`, 需要额外处理 UE Android UPL/APL、runtime dependencies 和 `.so` 打包; 当前不建议首轮采用。

## 6. 预期输出目录

建议输出并纳入候选库搜索的路径:

```text
Source/ThirdParty/WAMR/lib/Android/arm64-v8a/Release/libvmlib.a
Source/ThirdParty/WAMR/lib/Android/x86_64/Release/libvmlib.a
```

可选兼容候选:

```text
Source/ThirdParty/WAMR/lib/Android/arm64-v8a/Release/libiwasm.a
Source/ThirdParty/WAMR/lib/Android/x86_64/Release/libiwasm.a
```

`build/Android/*` 继续作为 ignored generated output。只有经过验证并决定固化的 `lib/Android/*/Release/*.a` 才允许进入 Git。

建议未来新增构建脚本:

```text
Build/BuildWAMRAndroid.cmd
```

脚本职责:

1. 验证 `ANDROID_HOME` 与 `ANDROID_NDK_LATEST_HOME`。
2. 对目标 ABI 循环调用 CMake configure/build。
3. 复制 `libvmlib.a` 到 `Source/ThirdParty/WAMR/lib/Android/<abi>/Release/`。
4. 输出 build options 摘要和库 hash。

## 7. Build.cs Branch Points

后续修改 `Source/ThirdParty/WAMR/WAMR.Build.cs` 时建议保持现有 fail-closed guard:

```text
headers exist + platform library exists -> AVIDSCRIPT_WITH_WAMR=1
otherwise -> AVIDSCRIPT_WITH_WAMR=0
```

Android 分支建议:

```csharp
if (Target.Platform == UnrealTargetPlatform.Android)
{
    foreach (string Abi in new[] { "arm64-v8a", "x86_64" })
    {
        AddCandidate("lib/Android/" + Abi + "/Release/libvmlib.a");
        AddCandidate("lib/Android/" + Abi + "/Release/libiwasm.a");
    }
}
```

说明:

- UE 引擎 ThirdParty 模块常见做法是注册多个 Android ABI 库, 由 toolchain/filter 选择实际架构。
- 如果后续决定只支持 arm64, 可以只注册 `arm64-v8a`。
- Android static link 可能需要系统库 `log`、`android`、`dl`、`m`; 具体写法需要在实际 Android target link 时验证。
- 不需要 UPL/APL 的前提是只链接 static `libvmlib.a`; 若切换 shared `.so`, 必须新增 Android plugin receipt。

建议候选库搜索顺序:

```text
Win64:
  lib/Win64/Release/iwasm.lib
  lib/Win64/Release/libiwasm.lib
  lib/Win64/Release/vmlib.lib

Android:
  lib/Android/<abi>/Release/libvmlib.a
  lib/Android/<abi>/Release/libiwasm.a
```

## 8. 移动端 Runtime 文件策略

PC Editor:

- 开发迭代使用 `Saved/AvidScript/HotReload/<ModuleId>`。
- 支持 watcher 和手动 reload command。

Android:

- 首版只加载 packaged/promoted module, 不支持 Editor watcher。
- 推荐使用 `Content/AvidScript/Modules/<ModuleId>/module.wasm` 与 `module.avidscript.json`。
- `.wasm` 视为数据文件, 由 host runtime 读取 bytes 后交给 WAMR。
- 不在 Android 首轮实现外部下载脚本、运行时编译或 JIT。
- manifest validation、ABI/export/import validation 和 fail-closed diagnostics 必须保留。

后续 packaging 恢复时需要确认:

- `.wasm` 是否作为 Non-UFS 文件保留原始 bytes。
- Android packaged 路径下是否能通过 UE file helper 直接读取。
- manifest hash 是否基于实际读取 bytes 计算。
- 如果 `.wasm` 被压缩进 pak/io store, WAMR loader 是否仍只接收完整内存 bytes, 不依赖 OS 文件路径。

## 9. Implementation Gate

Android 二进制加入仓库前必须满足:

1. 构建脚本可重复生成 `arm64-v8a` static library。
2. 记录 WAMR commit、CMake flags、NDK path/version、Android API level。
3. `WAMR.Build.cs` Android branch 在缺库时仍定义 `AVIDSCRIPT_WITH_WAMR=0`, 不阻断 Win64。
4. Android target link 验证通过。
5. Win64 Editor module build 和 `AvidScript` automation 回归通过。
6. 第三方 license 仍指向 vendored WAMR `LICENSE`。

未满足 gate 前:

- 不提交 `lib/Android/*`。
- 不修改 packaging 流程。
- 不承诺 Android runtime 可运行。

## 10. 验证计划

后续真正实现 Android 支持时按以下顺序验证:

| 阶段 | 命令/动作 | 验收 |
| --- | --- | --- |
| A | 运行 `BuildWAMRAndroid.cmd` | 生成 `libvmlib.a`, 输出 flags/hash。 |
| B | 修改 `WAMR.Build.cs` Android branch | 缺库时 Win64 不受影响。 |
| C | Android target build | 链接通过, 无 missing symbol。 |
| D | Win64 module build | 现有 PC 路径不回退。 |
| E | `Automation RunTests AvidScript` | PC 回归通过。 |
| F | Android device smoke | 读取 packaged `.wasm`, 调用 `avid_on_begin_play` 和 `avid_on_tick`。 |

P3.5 不执行上述构建, 只固定方案。

## 11. 风险

- WAMR Android CMake 默认 shared `iwasm` 更完整, 但 UE 插件首轮更适合 static `vmlib`; static target 的系统库依赖需要实际 Android link 验证。
- UE Android multi-ABI 过滤行为需要在真实 target build 中确认。
- Android packaging 对 `.wasm` 数据文件的读取路径尚未验证。
- 移动端热重载不应复用 PC Editor watcher 模型。
- 关闭 AOT/JIT 有利于移动端权限和稳定性, 但会牺牲部分性能; 需要后续设备 benchmark 才能决定是否引入 AOT。

## 12. 下一步

Phase 3 的计划内小组到 P3.5 结束。建议下一步新增 P3.6 / Phase 4.0: External WASM Module Loading And Actor Host ABI。

该小组目标:

- 从磁盘读取真实 `.wasm` 与 manifest。
- 把 manifest JSON 转成 runtime reload manifest。
- 注册 `actor_get_location` / `actor_set_location` 等最小 UE host ABI。
- 让 `UAvidScriptComponent` 将 owner actor handle 暴露给 guest。
- 用一个真实外部 `.wasm` 文件验证脚本到 UE 的交互闭环。
