# P3.4 Hot Reload Workflow Design

日期: 2026-07-03
状态: Done

## 1. 目标

P3.4 将 P2.4 已完成的 staging reload + rollback 核心, 扩展为后续可实现的 Editor 热重载工作流设计。本阶段只做设计文档, 不新增 C++、Editor UI、文件 watcher 或编译器工具链代码。

目标:

- 定义真实 `.wasm` 文件与 `.avidscript.json` manifest 的落盘约定。
- 定义 PC Editor 优先的 watcher 和手动 reload command 流程。
- 复用 `FAvidScriptWasmReloadSession` 的 staging validation 与 rollback 语义。
- 预留状态迁移 hook, 但不在当前阶段实现 guest state migration。
- 说明从当前 P3.3 到“脚本语言 WASM 与 UE 交互验证”的最短路径。

## 2. 当前基线

已具备:

- P2.4: `FAvidScriptWasmReloadSession` 支持 initial load、reload、manifest ABI/export 校验、staging runtime、失败回滚。
- P2.1/P2.2: UObject handle registry 与 Actor host binding 已经有 C++ automation 验证。
- P2.3: `UAvidScriptComponent` 已能注册 owner actor 并驱动 embedded smoke runtime。
- P3.3: WAMR native import bridge 已能让 guest WASM 调用 host import, 并能把 missing import 与 host-side failure 转成结构化 diagnostics。

尚未具备:

- 从磁盘读取真实脚本工具链生成的 `.wasm`。
- JSON manifest parser 与 manifest 文件版本化。
- Editor 文件监听和手动 reload 命令。
- 将 WASM import 直接映射到 P2.1/P2.2 的 handle/Actor binding。
- `UAvidScriptComponent` 改用 reload session 驱动 live runtime。
- guest state migration schema。

## 3. 文件布局

PC Editor 热重载先使用 project `Saved` 目录, 避免把频繁生成的临时文件交给 UE asset/cook 管线:

```text
<Project>/Saved/AvidScript/HotReload/<ModuleId>/
  module.wasm
  module.avidscript.json
  module.pdb or module.dwarf     # optional
  module.map                     # optional
```

后续进入 packaging 或可分发样例时, 再引入 promoted runtime 目录:

```text
<Project>/Content/AvidScript/Modules/<ModuleId>/
  module.wasm
  module.avidscript.json
```

热重载 watcher 只把 manifest 文件视为 reload signal。外部编译器或 build tool 必须先完整写入 `.wasm`, 再以 atomic rename 或同等方式写入 manifest, 避免 UE 读到半写入的 WASM。

建议写入顺序:

```text
1. write module.wasm.tmp
2. fsync/close module.wasm.tmp
3. rename module.wasm.tmp -> module.wasm
4. compute wasm hash
5. write module.avidscript.json.tmp
6. fsync/close module.avidscript.json.tmp
7. rename module.avidscript.json.tmp -> module.avidscript.json
```

## 4. Manifest 草案

文件名建议固定为 `module.avidscript.json`, 内容示例:

```json
{
  "schema_version": 1,
  "module_id": "example.player_controller",
  "abi_version": 1,
  "runtime": {
    "target": "wasm32",
    "runtime": "wamr",
    "platform": "Win64",
    "configuration": "Development"
  },
  "wasm": {
    "file": "module.wasm",
    "sha256": "replace-with-real-hash",
    "byte_size": 4096
  },
  "exports": {
    "required": [
      "avid_on_begin_play",
      "avid_on_tick"
    ],
    "optional": [
      "avid_on_end_play",
      "avid_on_reload_prepare",
      "avid_on_reload_commit",
      "avid_on_reload_rollback"
    ]
  },
  "imports": {
    "required": [
      "avidscript.host_add_i32"
    ],
    "optional": [
      "avidscript.actor_get_location",
      "avidscript.actor_set_location"
    ]
  },
  "build": {
    "toolchain": "avidc",
    "toolchain_version": "0.1.0",
    "source_language": "AvidScript",
    "build_timestamp_utc": "2026-07-03T00:00:00Z",
    "build_id": "replace-with-build-id",
    "source_hash": "replace-with-source-hash"
  },
  "debug": {
    "source_map": "module.map",
    "debug_symbols": "module.dwarf"
  },
  "migration": {
    "state_schema_version": 1,
    "strategy": "none"
  }
}
```

必填字段:

- `schema_version`: manifest 文件格式版本。
- `module_id`: stable module identity, 用于 component/world 绑定和 reload 诊断。
- `abi_version`: host/guest ABI 兼容边界, 当前应匹配 `FAvidScriptWasmReloadManifest::SupportedAbiVersion`。
- `wasm.file`: 相对 manifest 所在目录的 wasm 文件路径。
- `wasm.sha256`: 防止 watcher 读到旧文件或半写文件。
- `exports.required`: 激活前必须存在的 guest exports。
- `imports.required`: 激活前必须 linked 的 host imports。

可选字段:

- `debug.source_map` / `debug.debug_symbols`: 用于未来错误栈、断点或 source location 映射。
- `migration`: 未来状态迁移 schema, 当前只允许 `strategy = "none"`。
- `build`: 便于 Editor UI 和日志显示本次 reload 来源。

## 5. Editor Workflow

建议新增一个后续 Editor-only module: `AvidScriptEditor`。Runtime module 继续只持有 runtime、manifest model、file loading helper 和 reload session, 避免把 editor-only dependency 带进游戏 runtime。

### 5.1 Watcher 自动热重载

```text
File watcher sees module.avidscript.json changed
  -> debounce by ModuleId
  -> parse manifest JSON
  -> resolve wasm path
  -> verify wasm exists, size, hash
  -> build runtime manifest
  -> route to owning script component or world runtime
  -> call ReloadModule(bytecode, manifest)
  -> on success: publish reload result and update Editor notification
  -> on failure: keep live runtime and show structured diagnostics
```

Watcher 规则:

- 只监听 `module.avidscript.json`, 不直接监听 `.wasm`。
- 对同一 `module_id` 做 debounce, 建议 100-300 ms。
- 每次 reload 都必须重新读取 manifest 与 wasm bytes, 不复用上次失败的 staging runtime。
- reload 只能在 game thread 最终应用; 文件 IO 和 hash 可在 worker thread, 但 `FAvidScriptWasmReloadSession` 切换 live runtime 要回到安全线程边界。
- PIE 未运行时, watcher 可以记录 pending reload; PIE 运行后再由 component/world runtime 绑定。

### 5.2 手动 Reload Command

Editor command 用于更可控的验证和调试:

```text
AvidScript.ReloadModule <ModuleId>
AvidScript.ReloadAll
AvidScript.DumpModules
AvidScript.DumpLastReloadError <ModuleId>
```

手动 command 与 watcher 走同一条 parser/validation/reload 路径, 不能绕过 staging validation。这样 automation、UI 按钮、控制台命令看到的错误分类保持一致。

### 5.3 Component/World 接入点

当前 `UAvidScriptComponent` 直接持有 `FAvidScriptWasmRuntimeInstance`。后续接入热重载时建议改为:

- component 持有 `FAvidScriptWasmReloadSession`。
- `BeginPlay` 使用 manifest + wasm bytes 调 `LoadInitialModule`。
- `TickComponent` 调 `TickLive`。
- 热重载 manager 通过 `module_id` 找到目标 component/session, 调 `ReloadModule`。
- reload 成功后, component runtime stats 记录 active module、reload count、last build id。
- reload 失败后, component 继续 tick 旧 live runtime, 并记录 `FAvidScriptWasmReloadResult`。

## 6. Migration Hook 设计

P3.4 不实现状态迁移, 但保留四个 optional export 作为未来 ABI:

```text
avid_on_reload_prepare(old_schema_version: i32, new_schema_version: i32) -> i32
avid_on_reload_commit() -> void
avid_on_reload_rollback() -> void
avid_on_end_play(reason: i32) -> void
```

未来完整 reload 顺序:

```text
1. validate manifest and bytecode
2. instantiate staging runtime
3. validate required exports/imports
4. call staging avid_on_begin_play or future avid_on_reload_prepare
5. if migration strategy is none:
     swap live runtime
6. if migration strategy is host_snapshot:
     export old state through host-owned schema
     import state into staging runtime
     swap live runtime
7. on swap success:
     call optional old avid_on_end_play(reload)
     call optional new avid_on_reload_commit()
8. on any failure:
     destroy staging runtime
     call optional live avid_on_reload_rollback()
     keep old live runtime
```

状态迁移安全规则:

- guest 不能持有 raw `UObject*`; 仍只能通过 host handle 访问 UObject。
- host-owned handles 必须在 reload 后重新验证, 不能假设旧 handle 永久有效。
- migration failure 必须 fail closed, 保留旧 runtime。
- migration schema version 必须在 manifest 中声明, 不允许隐式推断。

## 7. Diagnostics

P3.4 后续实现时建议沿用现有结构化错误分类, 并补充文件层错误:

| Category | 含义 | Next Action |
| --- | --- | --- |
| `manifest_parse_failed` | JSON 不合法或 schema version 不支持 | 修正 manifest 或升级 runtime parser |
| `manifest_invalid` | 必填字段缺失或格式错误 | 重新生成 manifest |
| `wasm_file_missing` | manifest 指向的 wasm 不存在 | 检查 build 输出路径 |
| `wasm_hash_mismatch` | wasm hash 与 manifest 不一致 | 确认写入顺序与缓存 |
| `abi_mismatch` | guest ABI 与 host runtime 不匹配 | 使用匹配 ABI 重编译脚本 |
| `missing_export` | required export 缺失 | 修正脚本入口或编译器输出 |
| `missing_import` | required host import 未 linked | 修正 import module/name 或 host binding |
| `host_import_failed` | host API 返回失败 | 查看 host-side diagnostics |
| `migration_failed` | 状态迁移失败 | 回滚并检查 schema |

每次 reload result 至少记录:

- previous module id
- candidate module id
- active module id
- build id
- wasm sha256
- success/rejected counters
- error category
- failed export/import name
- next action

## 8. PC 到移动端的边界

PC Editor:

- 支持 watcher 与手动 reload command。
- 使用 `Saved/AvidScript/HotReload` 做快速迭代。
- 允许 debug/source map 字段存在但不要求消费。

移动端:

- 不依赖 Editor watcher。
- 首版移动端只加载 packaged/promoted module。
- Android/iOS 的 wasm 文件放置、签名、压缩和可读路径要由 P3.5 继续设计。
- 移动端默认关闭频繁热重载, 只保留 manifest validation 与 fail closed runtime load。

## 9. 到真实脚本语言 WASM 验证 UE 交互的最短路径

当前 P3.3 已经证明:

```text
WASM guest -> WAMR import bridge -> UE host C++ callback
```

要验证“某个脚本语言编译出的 `.wasm` 与 UE 交互”, 还需要一个很薄的 P3.6/P4.0 小阶段:

1. 从磁盘读取 `module.wasm` 与 `module.avidscript.json`。
2. JSON manifest 转为 `FAvidScriptWasmReloadManifest`。
3. 注册最小真实 host ABI, 例如:

```text
avidscript.actor_get_location(handle, out_x, out_y, out_z) -> i32
avidscript.actor_set_location(handle, x, y, z) -> i32
```

4. 将 `UAvidScriptComponent` 的 owner actor 注册为 handle, 并把 handle 暴露给 guest。
5. 编写一个由外部工具链生成的 `.wasm` 示例, 在 `avid_on_begin_play` 或 `avid_on_tick` 中调用 host actor binding。
6. 使用 automation 或 PIE 日志验证 Actor location 被读取/设置, 失败时旧 runtime 不崩溃。

如果只做 PC Editor 上的“真实 `.wasm` 文件调用 UE host API”验证, 可以在下一个编码小阶段完成最小闭环。若要同时确定 D/C# 等 guest toolchain 的工程模板、标准库封装和调试体验, 需要再拆 2-3 个小阶段。
