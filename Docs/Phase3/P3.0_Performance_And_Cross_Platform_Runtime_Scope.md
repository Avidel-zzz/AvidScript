# P3.0 Performance And Cross-Platform Runtime Scope

日期: 2026-07-02
状态: Done

## 1. 范围调整

Phase 3 从 “Performance, Packaging, And Android Spike” 调整为 “Performance And Cross-Platform Runtime Spike”。

根据当前项目决策, packaging 暂时跳过。Phase 3 不执行 cook/stage/pak/package regression, 也不把 Windows packaged pipeline 作为本阶段阻塞项。

## 2. 目标

Phase 3 聚焦三件事:

- 建立 WAMR runtime 操作成本基线。
- 建立 host binding 成本基线, 为后续脚本语言性能预算服务。
- 提前设计 Android/iOS runtime 分层, 防止 PC-only 实现锁死移动端。

## 3. 小组拆分

| 小组 | 目标 | 验收 |
| --- | --- | --- |
| P3.0 | 范围与指标预算 | 本文档、项目 tracker、Phase 3 log 更新完成。 |
| P3.1 | Runtime microbenchmark | Automation 输出 WAMR load/instantiate/begin/tick/unload 多轮统计。 |
| P3.2 | Host binding overhead benchmark | Automation 输出 direct C++、registry resolve、Actor binding 成本对比。 |
| P3.3 | Minimal WASM import bridge | WASM module 能调用一条 host import, 并有 success/failure automation。 |
| P3.4 | Hot reload workflow design | 形成 watcher/editor command/manifest/migration schema 设计, 不要求实现 UI。 |
| P3.5 | Android runtime pre-adaptation | Android WAMR build strategy 与 Build.cs platform branch 方案完成。 |

## 4. Packaging Deferred

Packaging 延后到 Phase 3 之后或单独 Phase:

- 不跑 `RunUAT BuildCookRun`。
- 不维护 archive output。
- 不把 ZenStore 或 packaged smoke 作为本阶段验收。
- Phase 1 的 Windows packaged Development smoke 仍作为历史证据保留。

## 5. 验证底线
