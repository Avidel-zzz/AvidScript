# P19.2 C# Profile Build Service 实现

## 实现内容

Phase 19 将 Phase 18 的固定 C# ActorLifecycle 构建入口拆成可复用 profile 模型。默认 ActorLifecycle 行为保持兼容, 但 Editor build service 和 PowerShell wrapper 现在可以接收自定义 C# source、project、module id、artifact stem、输出根目录、report 路径和 manifest 路径。

## 主要接口

`FAvidScriptEditorCSharpBuildConfig` 新增字段:

- `SourcePath`
- `ProjectPath`
- `ManifestPath`
- `ModuleId`
- `ArtifactStem`

`FAvidScriptEditorCSharpBuildResult` 会回填同一组 profile 字段, 方便 Editor UI 或后续 service 显示实际构建目标。

`FAvidScriptEditorCSharpBuildService` 新增:

- `BuildProfile(...)`
- `GetDefaultActorLifecycleSourcePath()`
- `GetDefaultActorLifecycleProjectPath()`
- `GetDefaultActorLifecycleManifestPath()`
- `GetDefaultActorLifecycleModuleId()`
- `GetDefaultActorLifecycleArtifactStem()`
- `MakeReportPathForOutputRoot(...)`
- `MakeManifestPathForOutputRoot(...)`

`BuildActorLifecycle(...)` 现在代理到 `BuildProfile(...)`, 因此 Phase 18 的菜单入口保持可用。

## Build Wrapper 参数

`BuildCSharpActorLifecycle.ps1` 新增参数:

```powershell
-SourcePath
-ProjectPath
-ModuleId
-ArtifactStem
-ReportPath
-ManifestPath
```

未传参数时仍使用默认 ActorLifecycle sample:

- `ModuleId = csharp_actor_lifecycle`
- `ArtifactStem = actor_lifecycle`
- `OutputRoot = Saved/AvidScriptCSharpGuest/ActorLifecycle`

自定义 profile 会按 `ArtifactStem` 生成文件名, 例如:

```text
custom_mover.csharp_adapter.wasm
custom_mover.avidscript.json
custom_mover.csharp.report.json
```

## 失败路径

`BuildProfile(...)` 会在调用 PowerShell 前验证:

- build script 是否存在。
- source file 是否存在。
- project file 是否存在。
- output/report/manifest 目录是否可创建。

失败会写入结构化 `ErrorCategory` / `ErrorMessage`, 不会继续绑定 Actor。

## 当前价值

到本小组结束, C# gameplay authoring 不再被固定样例文件名限制。下一阶段只要加 UI 或 profile 持久化, 就可以把任意符合当前 C# source adapter 子集的 `.cs` 文件交给同一条构建与绑定链路。
