## 阶段结论

Phase25 已完成 C# gameplay 最小生命周期闭环：

```text
UE BeginPlay -> avid_on_begin_play
UE Tick      -> avid_on_tick(deltaSeconds)

```

C# 脚本现在可以在 BeginPlay 初始化 Actor，在 Tick 中维护脚本状态并更新 Actor，在 EndPlay 中执行清理或最终状态写回。

## 独立审查修复

首次独立审查给出 Not ready to merge，发现四项生命周期边界未被原测试覆盖：

- 成功 reload 直接替换旧 runtime，没有调用旧 guest EndPlay。
- guest EndPlay 产生副作用后 trap，重复关闭路径可能再次进入 guest。
- 组件把“收到 UE EndPlay”与“guest EndPlay 导出成功执行”混为同一个统计字段。
- 显式空 `EndPlay(){}` 会被 PowerShell mandatory string 参数拒绝。

修复后，reload 使用“加载并验证 candidate、结束并卸载旧 guest、调用 candidate BeginPlay”的转换顺序；runtime 缓存首次 EndPlay 成功或失败结果；组件新增 `bComponentEndPlayObserved`，`bEndPlayCalled` 只表示 guest 导出成功；adapter 允许空方法体并收紧 optional EndPlay 声明匹配。

新增 `AvidScript.Reload.EndPlayTransitionOrderSmoke` 与 `AvidScript.Runtime.WasmActor.EndPlayFailureIdempotencySmoke`，并用真实空 EndPlay C# fixture 验证 adapter 产出 `direct_abi_built`。
## 本阶段错误记录

首次完整回归在 `AvidScript.Editor.CommandLauncher.BuiltManifestReloadSmoke` 中访问冲突。根因不是脚本逻辑，而是公开 runtime 结构增加字段后只重编了 `AvidScriptRuntime`，旧 `AvidScriptEditor.dll` 仍使用旧结构布局，造成跨模块 ABI 写越界。

处理方式是仅增量编译 `AvidScriptEditor`，没有 clean Editor Target。原崩溃用例随后单独通过，完整 97 项回归也通过。防错规则已写入 `AGENTS.md`：公开头文件中的跨模块结构、类布局或 inline API 变化后，必须同步增量编译直接消费者模块。

## 当前边界

- C# 中的 `Actor` 仍是手写静态 facade，`FVector` 尚未成为 C# 值类型。
- host ABI 仍以 slot/generation 和标量参数为主。
- 尚未支持旋转、缩放、组件查询、输入、Timer、Overlap/Hit、任意 UObject 引用和移动端验证。

下一阶段进入类型化 UE API 基础：先实现 C# `FVector` 值类型与 `Actor` 对象引用包装，再扩展 Transform API。
