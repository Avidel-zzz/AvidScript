# P25.2 C# EndPlay Runtime 与 Adapter 实现

状态: Done

## 实现内容

### Runtime

- `FAvidScriptWasmRuntimeInstance::EndPlay(...)` 调用可选 `avid_on_end_play`。
- 新模块执行成功后记录 `bEndPlayCalled` 与 `EndPlayCallMs`。
- 旧 WASM 缺少 EndPlay 导出时返回成功 no-op，保持向后兼容。
- 重复 EndPlay 调用保持幂等，不重复执行 guest 清理逻辑。
- `Unload(...)` 保留 BeginPlay、EndPlay、Tick 与 metrics 最终状态。

### Reload 与组件

- `FAvidScriptWasmReloadSession` 新增 `EndPlayLive(...)`。
- `UnloadLive()` 在卸载已 BeginPlay 的 live runtime 前尝试 EndPlay。
- `UAvidScriptComponent::ReleaseRuntime()` 在 owner handle 仍有效时先执行 guest EndPlay，再卸载 runtime，最后由组件 EndPlay 释放 owner。
- guest EndPlay 失败会记录结构化错误，但不会阻止必要的宿主资源卸载。

### C# source adapter v4

- 新增第三个内部函数和导出：BeginPlay index 2、Tick index 3、EndPlay index 4。
- 解析可选 C# `EndPlay()`；旧源码没有该方法时仍生成空 EndPlay 导出。
- manifest/report 的 `required_exports` 增加 `avid_on_end_play`。
- `source.subset` 更新为 `actor_lifecycle_v4`。
- adapter contract 记录 `BeginPlay`、`Tick`、`EndPlay` 三个生命周期事件。

## 默认样例行为

```csharp
[UnmanagedCallersOnly(EntryPoint = "avid_on_end_play")]
public static void EndPlay()
{
    Actor.SetLocation(0.0f, 0.0f, 0.0f);
}
```

自动化验证 Actor 在 BeginPlay 后位于 `(100, 200, 300)`，连续两个 Tick 后位于 `(104, 200, 300)`，EndPlay 后回到 `(0, 0, 0)`。
