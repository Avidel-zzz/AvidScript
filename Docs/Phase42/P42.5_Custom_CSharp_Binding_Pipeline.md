# P42.5 自定义 C# Binding 完整闭环

状态：已完成
完成日期：2026-07-17

## 阶段结论

P42.5 已经把 Phase 42 前四组建立的生成器、动态 WAMR import 和缓存反射调用接入正式 C# 构建与 UE 生命周期。

当前可以从一份用户 C# 源码完成以下闭环：

```text
用户 C# 生命周期源码
  -> Roslyn syntax/semantic
  -> 生成 facade 作为可执行参考源码
  -> Guest IR
  -> 确定性 WASM
  -> 脚本 manifest + Binding Package 身份
  -> Runtime Session 事务装载
  -> WAMR 动态 raw import
  -> 缓存 UE Reflection invocation plan
  -> UObject/Actor/FVector
```

真实自动化已经验证：

- C# `BeginPlay` 调用 `UE.Self.SetActorScale3D(new FVector(2, 3, 4))`；
- C# `Tick(0.5f)` 读取当前 `FVector`，再把 X 从 `2.0` 更新为 `2.5`；
- 调用经过正式 WASM、WAMR、动态 import 和 `ProcessEvent`，不是 C++ 测试替代调用；
- descriptor 哈希被篡改时，Runtime 在候选 VM 激活前失败关闭。

## 实现分组

### P42.5-A：可执行参考源码

普通 `--reference-source` 继续只参与 Roslyn 编译和类型检查。新增的 `--executable-reference-source` 会把生成 facade 的以下内容投影到正式 semantic artifact：

- 类型和成员符号；
- `DllImport` callable ABI；
- 方法体与控制流图；
- 生成 wrapper 对 native import 的调用。

Semantic 层以多 compilation unit 工作，不在 PowerShell 中拼接 C# 文本。跨文件重复 namespace 被视为合法 C# 声明合并，其他稳定 symbol id 冲突仍然失败。

生成 facade 使用的 `_ = Native.Invoke(...)` 由 Guest lowering 按 C# discard 语义处理：右值只执行一次，不生成无效存储。

### P42.5-B：Binding Package 构建契约

`BuildCSharpActorLifecycle.ps1` 新增 `-BindingPackagePath <package.json>`。自定义源码必须持有明确的生成包，构建器会验证：

- package schema、名称和内容身份；
- package manifest、descriptor、reference source 的 SHA-256；
- descriptor schema 与 package identity；
- package 内 required imports 的唯一性；
- Guest IR 中 `avidscript.*` 动态 imports 与 package 完全一致。

构建报告与脚本 manifest 都记录 package、descriptor 和生成 C# reference source 的路径及哈希。`ModuleId`、文件名和输出目录不再承担 API 授权职责。

### P42.5-C：Runtime 事务装载

`FAvidScriptWasmReloadManifestLoader` 在读取 WASM 后继续校验 Binding Package：

- package manifest 和 descriptor 文件存在且哈希一致；
- `package.json` schema、package identity 和 descriptor identity 一致；
- descriptor 路径不能逃出 package 目录；
- `package.json` required imports 与 descriptor 生成的 VM imports 一致；
- descriptor 能构建为不可变的缓存反射调用包。

`FAvidScriptRuntimeSession` 只把验证后的不可变 package 传给候选 VM。动态 UE import 缺少 package 时返回 `binding_package_missing`；候选装载、链接或 `BeginPlay` 失败时，不会发布为 live runtime。

### P42.5-D：Editor 用户工作流

`FAvidScriptEditorCSharpBuildService` 对非默认 C# 源码执行以下策略：

1. profile 显式配置 `binding_package_path` 时使用该内容寻址包；
2. 未配置时，由 Editor Reflection Binding Emitter 自动发布或复用默认包；
3. 把最终 `package.json` 路径显式传给 PowerShell 构建链；
4. 构建成功后继续使用原有 build-and-bind 工作流绑定选中 Actor。

因此普通用户不需要手工搜索 `Saved/AvidScriptGeneratedBindings`，但 CI、回放构建和固定 SDK 版本仍可在 profile 中指定包路径。

## C# 样例

完整样例位于：

`Samples/CSharp/GeneratedBindingLifecycle/GeneratedBindingLifecycleScript.cs`

核心逻辑：

```csharp
using System.Runtime.InteropServices;

namespace AvidScript;

public static class GeneratedBindingLifecycleScript
{
    [UnmanagedCallersOnly(EntryPoint = "avid_on_begin_play")]
    public static void BeginPlay()
    {
        UE.Self.SetActorScale3D(new FVector(2.0f, 3.0f, 4.0f));
    }

    [UnmanagedCallersOnly(EntryPoint = "avid_on_tick")]
    public static void Tick(float deltaSeconds)
    {
        FVector scale = UE.Self.GetActorScale3D();
        UE.Self.SetActorScale3D(new FVector(
            scale.X + deltaSeconds,
            scale.Y,
            scale.Z));
    }
}
```

当前 direct ABI 仍要求声明六个生命周期导出；样例文件包含其余四个空实现。

## Profile 使用方式

profile 可以省略 `binding_package_path`，让 Editor 自动发布默认包：

```json
{
  "schema_version": 1,
  "language": "csharp",
  "source_path": "Plugins/AvidScript/Samples/CSharp/GeneratedBindingLifecycle/GeneratedBindingLifecycleScript.cs",
  "module_id": "csharp_generated_binding_lifecycle",
  "artifact_stem": "generated_binding_lifecycle",
  "output_root": "Saved/AvidScriptCSharpGuest/GeneratedBindingLifecycle"
}
```

需要固定依赖时，可以增加：

```json
{
  "binding_package_path": "Saved/AvidScriptGeneratedBindings/avidscript.engine.core/<manifest-hash>/package.json"
}
```

## 稳定错误分类

- `ASBI4201` / `phase42_binding_required`：直接调用 PowerShell 构建自定义源码但没有提供 package；
- `ASBI4202` / `binding_package_invalid`：package schema、路径或哈希无效；
- `ASBI4203` / `binding_import_mismatch`：Guest IR 动态 imports 与 package 不一致；
- `binding_package_missing`：Runtime manifest 声明动态 UE imports，但没有已验证 package；
- `binding_package_hash_mismatch`：package manifest 或 descriptor 文件哈希不一致；
- `binding_package_identity_mismatch`：脚本 manifest、package.json 与 descriptor 身份不一致；
- `binding_package_import_mismatch`：package.json 与 descriptor 的动态 imports 不一致。

## 性能与架构约束

- JSON 解析、反射查找、`UFunction/FProperty` 解析和调用计划构建只发生在 package load；
- 热路径通过 package ordinal 访问不可变 invocation plan；
- 参数 frame 使用预计算大小、对齐和复用 scratch，不在每次 Tick 做反射遍历；
- WAMR 细节继续留在 `AvidScriptVM`，UE 反射类型继续留在 Runtime/Bindings；
- 新增普通 UE UFunction 不需要扩展 VM enum、手写 native wrapper 或 Runtime switch。

## 当前可用边界

现在已经可以用 C# + WASM 编写真实的 Actor 生命周期游戏逻辑，但还没有达到 Puerts/UnLua 的 UE API 广覆盖程度。

当前默认生成包只覆盖首批 8 个 Actor/SceneComponent 函数和基础 `FVector/FRotator/UObject handle` 投影。以下内容仍属于后续阶段：

- 扩大 Reflection selection 与批量 API 覆盖；
- UObject/Actor/Component 生命周期失效通知与更完整的类型继承；
- 属性、数组、Map、Set、字符串和更多 UE struct；
- delegate、Blueprint event、异步/latent 调用；
- 调试器、异常栈、热重载状态迁移和开发诊断；
- PC packaging、Android/iOS runtime 与 AOT 验证；
- dead-code elimination，避免未使用的 facade import 进入最终模块。

下一阶段应优先建立“可配置反射 API 面 + 批量类型策略 + 自动兼容性报告”，继续扩大生成式覆盖，而不是回到逐个手写 API。
