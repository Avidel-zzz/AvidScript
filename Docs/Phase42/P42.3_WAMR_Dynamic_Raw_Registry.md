# P42.3 WAMR 动态 Raw Native 注册

## 目标

P42.3 把 Binding Descriptor 生成的 import package 接入 WAMR，使新增普通 UE API 不再要求新增 `EAvidScriptHostBindingId`、手写 `NativeSymbol` 包装函数或扩展 Runtime switch。

WAMR 仍然只存在于 `AvidScriptVM` 私有实现中。公共 VM 契约只暴露稳定 ID、ordinal、module、import name、signature、raw argument cells 和 guest memory 接口，不暴露任何 WAMR、UObject 或反射类型。

## 已实现能力

- `FAvidScriptVmBindingPackage` 描述一个不可变的 VM 绑定包。
- `FAvidScriptVmDynamicImport` 保存完整 stable id、package-local ordinal、module、import name 和 WAMR raw signature。
- WAMR backend 在加载 module 前验证并注册动态 raw native。
- 同一个全局 import symbol 可以被多个 Runtime instance 复用。
- 每个 Runtime instance 保留自己的 attachment 到 ordinal 映射，因此相同 raw symbol 可以在不同 package 中使用不同 ordinal。
- raw trampoline 从 WAMR function attachment 取得 import 元数据，从 exec env user data 取得当前 VM bridge。
- 动态调用通过 `IAvidScriptHostDispatcher::DispatchDynamicHostCall` 进入上层，不进入旧的手写 binding switch。
- guest memory 通过语言无关的 `IAvidScriptVmGuestMemory` 暴露，支持后续 ref/out/return marshalling。
- host dispatcher 返回的 `int32` 状态写回 raw argument frame 的返回槽。
- host 拒绝调用时记录稳定错误、设置 WAMR exception，并让当前 guest 调用失败关闭。

## 注册表生命周期

动态注册表以 `module + import name` 为全局 key，entry 保存：

- stable id；
- raw signature；
- UTF-8 module/import/signature 存储；
- `NativeSymbol`；
- function attachment；
- 引用计数。

加载顺序为：

1. 校验 package 和所有 import。
2. 获取 WAMR runtime lease。
3. 获取或创建动态 raw registration。
4. 在注册表锁保护下执行 `wasm_runtime_load`。
5. module instantiate 后由当前 backend 保存 attachment 到 ordinal 的局部映射。

卸载顺序为：

1. 销毁 exec env。
2. deinstantiate module。
3. unload module。
4. 释放动态 registration 引用。
5. 最后一个引用释放时注销 WAMR native symbol。
6. 释放 WAMR runtime lease。

该顺序保证 WAMR module 不会引用已经注销的动态 symbol。

## Package 安全契约

加载前会验证：

- package name 只能包含安全 token 字符；
- package hash 必须是小写 SHA-256；
- package 至少包含一个 import；
- stable id 必须是小写 SHA-256；
- ordinal 必须从零开始连续并与数组位置一致；
- module 必须是 `avidscript`；
- import name 必须是安全 token；
- raw signature 只允许 `i/I/f/F` 参数并返回 `i32` 状态；
- 参数数量不得超过固定上限；
- stable id、module/import key 和 ordinal 不得重复；
- 动态 import 不得覆盖已有手写静态 import；
- 已注册的同名 import 不得更改 stable id 或 signature。

所有失败都在 module load 前或 host trampoline 内失败关闭，不允许带着部分注册状态继续运行。

## 代码边界

- `AvidScriptVmBackend.h`：语言无关的动态 package、call frame 和 guest memory 公共契约。
- `AvidScriptWamrDynamicRegistry`：WAMR 私有全局注册、引用计数、冲突检测和 raw trampoline。
- `AvidScriptWamrBackend`：package attachment、module 生命周期和每实例 ordinal 路由。
- `AvidScriptWamrHostBindings`：继续承载现有静态 host import，不负责生成式 API 扩张。

## 验证结果

- `AvidScript.Architecture.VM.DynamicRawRegistrySmoke`：两个 backend 复用同一个全局 raw symbol，并分别收到自己的 package-local ordinal。
- `AvidScript.Architecture.VM.DynamicRawRegistryFailure`：覆盖缺失 package、重复 ordinal、同名 identity 冲突和释放后重新注册。
- 真实 WASM fixture 传入 `i32 41`，动态 dispatcher 收到参数并返回 `42`。
- 定向测试 `2/2` 通过。
- UE5.8 Win64 Editor 模块级增量构建通过，使用 `-MaxParallelActions=1 -NoUBA`，未清理 Editor Target。
- Phase 42 完整回归最终计入全量 `AvidScript` 自动化 `153/153`。

## 当前边界

P42.3 只解决“生成 import 如何进入 WAMR”。它不解析 Binding Descriptor，也不认识 UFunction、FProperty、FVector 或 UObject。

descriptor 到真实 UE 调用的缓存反射计划由 P42.4 实现；自定义 C# profile 自动选择、发布并加载对应 package 的正式用户工作流属于 P42.5。
