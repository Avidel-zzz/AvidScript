# P42.2 C# Facade 与绑定包发布

## 目标

P42.2 将 P42.1 的 Binding Descriptor v2 转换为可被 Roslyn 编译的 C# reference source，并把 descriptor、生成源码和 manifest 作为同一个内容寻址绑定包发布。

本阶段不手写 UE API facade，也不把新 API 加入 VM enum 或 Runtime dispatch switch。新增普通 UE API 的输入仍然只有授权后的 `owner_class + function_name` selection，C# 方法、ABI import、类型布局和稳定 identity 均由 descriptor 生成。

## 已实现能力

- 生成 `FVector`、`FRotator`、`FTransform` 值类型。
- 生成 `AActor`、`USceneComponent` 等 UObject handle proxy。
- 生成 `UE.Self`，从当前脚本 owner 的 slot/generation 构造类型安全的 `AActor` proxy。
- 区分 public proxy 与 internal Native 层，游戏脚本看不到 raw ABI 构造和 import 调用。
- 支持 instance/static 方法、value/const/ref/out/return、默认参数、enum、object handle 与首批结构体投影。
- 枚举成员名与数值写入 descriptor，参与类型 stable id 与 package identity，并生成可直接使用的 C# enum 成员和 enum 默认值。
- 数值默认值采用完整字符串、范围和有限值校验；`1junk`、整数 `1.5`、溢出值等不会被截断后写入 C#。
- 按 descriptor ordinal 生成确定性的 `DllImport` 声明。
- 对 C# 类型名、方法签名、生成辅助成员、import、stable id 与 descriptor 契约冲突执行失败关闭。
- UObject 类型即使当前只选择静态方法，只要还出现在参数或返回值中，就保持为可传递的 typed handle struct。
- 发布不可变的内容寻址 package；相同内容重复发布复用既有目录，内容冲突不会覆盖旧包。

## 代码结构

P42.2 已拆分为以下职责边界：

- `AvidScriptEditorBindingDescriptorIdentity`：构造类型稳定 identity，枚举定义变化会进入 hash。
- `AvidScriptEditorBindingDescriptorModel`：解析并验证 descriptor v2，不依赖 C# 渲染细节。
- `AvidScriptEditorCSharpSyntax`：集中处理 C# identifier 与 keyword 转义。
- `AvidScriptEditorCSharpDefaultValueFormatter`：严格解析并生成 scalar、enum、object 默认值表达式。
- `AvidScriptEditorCSharpBindingRenderer`：纯生成 C# reference source 与 package manifest。
- `AvidScriptEditorCSharpBindingEmitter`：负责 canonical descriptor 校验、hash 汇总、不可变目录发布和冲突处理。

该结构保持 WAMR 私有于 VM；P42.3 可以消费 descriptor/package contract，而无需依赖 C# 文本生成内部实现。

## 生成包

默认输出根目录为：

```text
<Project>/Saved/AvidScriptGeneratedBindings
```

包目录结构为：

```text
<output-root>/<package-name>/<package-sha256>/
  bindings.v2.json
  AvidScript.Bindings.generated.cs
  package.json
```

`package-sha256` 使用完整 `package.json` 的 manifest SHA-256，因此 descriptor、generated source 或 emitter 版本任一变化都会得到新的不可变目录。manifest 同时记录 descriptor package hash、descriptor SHA-256 与 generated source SHA-256。发布先写入短路径 staging 目录，再在同一卷内提交到最终内容地址，避免暴露半写入包。

## C# 使用形态

真实 smoke sample 位于 `Samples/CSharp/GeneratedBindingSmoke/GeneratedBindingSmoke.cs`：

```csharp
using AvidScript;

public static class Gameplay
{
    public static FVector ReadLocation()
    {
        return UE.Self.GetActorLocation();
    }

    public static void ApplyScale(float scale)
    {
        UE.Self.SetActorScale3D(new FVector(scale, scale, scale));
    }
}
```

游戏脚本只使用正常的 C# 类型和方法。slot、generation、ordinal、import 名称及结构体展开均留在生成层内部。

## 验证结果

- UE5.8 `AvidScriptEditor` 模块级增量构建成功，未执行 Editor Target clean；低内存环境使用 `-MaxParallelActions=1 -NoUBA`。
- renderer/service/default formatter/syntax 拆分后的 unity-enabled 增量构建成功。
- `AvidScript.Editor.CSharpBindingEmitter` 3/3：确定性、类型投影、签名冲突、不可变发布与防覆盖全部通过。
- .NET 定向回归通过：CSharpFrontend 7/7、CSharpSemantic 39/39；新增用例证明 reference source 内的编译错误会让 semantic 失败关闭。
- UE5.8 全量 `AvidScript` 自动化 149/149 通过，退出码 0。
- 真实生成的 `AvidScript.Bindings.generated.cs` 作为 reference source 交给 Roslyn semantic 1.4，其自身 diagnostics 不再被过滤。
- `GeneratedProjectionSmoke.cs` 使用生成 enum 默认值、对象 proxy 与静态方法完成语义分析：schema 4、5 methods、5 callables、0 diagnostics。
- 默认 `GeneratedBindingSmoke.cs` 保持 3 methods、3 callables、0 diagnostics。
- `InvokeCSharpFrontend.ps1` 现在从插件根目录读取 `global.json`，并在构建前强制核对精确 SDK 版本，避免 SDK 漂移。

## 当前边界

P42.2 证明了 `descriptor -> C# facade -> Roslyn` 的生产链路，但生成 import 还未由 WAMR 动态注册，descriptor 也还未在 Runtime 构造 cached `UFunction/FProperty` invocation plan。

因此，本阶段可以编写并静态验证使用生成 UE API 的 C#；要让这些新增 import 在 BeginPlay/Tick 中真实执行，还需要：

1. P42.3：VM-private WAMR raw native 动态注册与 package attachment。
2. P42.4：Runtime cached reflection invocation 与通用参数 frame。
3. P42.5：自定义 C# profile、Guest IR lowering、WASM、生命周期和 UE 交互完整闭环。

`ASBI4201` 仍保持失败关闭，直到 P42.3-P42.5 的执行链路具备完整 package/hash/import 验证。
