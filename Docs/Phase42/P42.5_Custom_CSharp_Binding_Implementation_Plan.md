# P42.5 自定义 C# 绑定闭环实施计划

状态：已完成

实现与验证记录见 [P42.5 自定义 C# Binding 完整闭环](P42.5_Custom_CSharp_Binding_Pipeline.md)。

## 目标

让用户只编写生命周期与游戏逻辑 C# 源码，并通过同一个内容寻址 Binding Package 完成：

```text
用户 C# + 生成 facade
  -> Roslyn semantic
  -> Guest IR
  -> WASM
  -> 脚本 manifest
  -> Runtime Session
  -> WAMR 动态 import
  -> 缓存反射调用
  -> UE Actor
```

本阶段不增加手写 UE API 表，不恢复 AST 适配器，也不通过目录猜测选择绑定包。

## 架构决定

### 1. Binding Package 是显式构建输入

`BuildCSharpActorLifecycle.ps1` 接收生成包的 `package.json`。构建器必须验证：

- package manifest schema；
- package name 与 package hash；
- descriptor 和生成 C# 源码的 SHA-256；
- Guest IR 中所有 `avidscript.*` 动态 import 都属于该包；
- 生命周期使用的静态 `env.*` import 可继续共存。

脚本 manifest 与结构化 build report 都记录 package manifest、descriptor、reference source 的路径和哈希。

### 2. 生成 facade 是可执行参考源码

普通 `reference source` 只参与 Roslyn 类型检查。生成 facade 需要额外标记为 `executable reference source`，其声明、方法体、`DllImport` 和控制流会进入 semantic artifact。

该能力由 Semantic 层实现，不在 PowerShell 中拼接源码。这样可以保持多文件 C# 语义、稳定符号身份和后续增量编译空间。

### 3. Runtime 按 manifest 事务加载绑定包

Reload manifest loader 同时读取并校验 WASM 与 descriptor。`FAvidScriptWasmReloadManifest` 持有不可变 `FAvidScriptBindingPackage`，Runtime Session 构建候选 VM 时一次性传入。

候选 VM、动态 native 注册、反射调用计划或 BeginPlay 任一环节失败时，旧运行时保持不变。

## 验收标准

- 自定义 C# 源码不再触发 `ASBI4201`，但缺少或损坏绑定包时必须失败关闭；
- 用户源码可以在 `BeginPlay` 或 `Tick` 中调用生成的 `UE.Self` API；
- Guest IR/WASM 的动态 imports 与绑定 descriptor 一致；
- Runtime 从脚本 manifest 自动装载绑定包；
- 真实 Actor 状态由 C# 生命周期代码通过 WASM 和缓存反射调用修改；
- 原有 .NET、Runtime、Editor 与 AvidScript 全量回归通过。
