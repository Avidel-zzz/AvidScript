# P42.4 Runtime 缓存反射调用

## 目标

P42.4 把 Binding Descriptor v2 转换为不可变的 Runtime invocation package，并通过 P42.3 的动态 raw import 在真实 WAMR 生命周期中调用 UE UFunction。

核心要求是把 JSON、字符串查找、反射遍历和 ABI 校验全部放在 package load 阶段。BeginPlay、Tick、事件和普通函数调用只执行 ordinal 索引、参数转换和缓存的 `ProcessEvent`，不在热路径重新扫描反射。

## 已实现能力

- `AvidScriptBindings` 提供共享的 Descriptor v2 model、identity 和 parser。
- Editor 生成器继续负责从 UE Reflection 产生 descriptor，但 Runtime 不再依赖 Editor 私有 model。
- `FAvidScriptBindingPackage::LoadDescriptor` 一次性完成 schema、engine version、selection hash、package hash、stable identity 和反射快照校验。
- 每个 binding 缓存 owner class、UFunction、FProperty、参数方向、类型 kind、对象类型、argument offset、guest storage size 和写权限要求。
- package 同时生成 VM-private 可消费的 `FAvidScriptVmBindingPackage`。
- Runtime instance 持有不可变 binding package，并在 load 时一次性预分配 invocation scratch。
- 动态 import 通过 ordinal 直接定位 invocation plan。
- 实例方法使用 `{slot, generation}` 解析目标对象，不假设 owner 固定在 registry slot 1。
- stale、null 或类型不匹配的 UObject handle 会失败关闭。
- 非 const reflected function 需要显式 `AllowWrites` host policy。
- value 参数可以直接从 WAMR raw cells 解码。
- ref/out/非 void return 使用 guest memory 地址读写。
- void return 不再错误占用一个 guest 输出地址。

## 首批类型与 ABI

当前 Runtime marshalling 支持：

- `bool`；
- `int8/uint8/int16/uint16/int32/uint32/int64/uint64`；
- `float/double`；
- UE enum；
- UObject typed handle；
- `FVector`；
- `FRotator`；
- `FTransform`；
- void/value/const_ref/ref/out/return 方向。

scalar 校验同时比较 canonical type、C++ type 和 WASM ABI type。即使两个类型宽度相同，例如 `float` 与 `int32`，descriptor 被篡改后也不会被错误接受。

## 调用帧与性能

每个 invocation plan 缓存：

- 完整 function frame size；
- function 最小 alignment；
- package required scratch size；
- raw argument count；
- guest memory 是否必需。

scratch 在 Runtime load 时按 package 最大需求预分配。每次调用只在该缓冲内计算对齐地址，并复用同一块内存：

1. 校验 ordinal、argument count、guest memory 和 write policy。
2. 解析或取得调用目标。
3. 在预分配 scratch 内对齐完整 UFunction frame。
4. 初始化 frame 并写入参数。
5. 调用缓存的 `ProcessEvent`。
6. 把 ref/out/return 写回 guest memory。
7. 销毁 frame 中需要析构的属性。

完整 frame size 而不是仅 `ParmsSize` 用于初始化和销毁，避免未来绑定带局部属性或更高对齐要求的 UFunction 时越界。热路径没有 JSON 解析、字符串 lookup、UFunction/FProperty 遍历或每次调用堆分配。

## Runtime 集成

`FAvidScriptWasmRuntimeInstance::LoadModule` 新增可选 binding package：

- package 有效时，把 VM package 交给 WAMR backend；
- 按 package required scratch size 预分配调用缓冲；
- 动态 host call 进入同一个 Runtime host dispatcher；
- Runtime 把 object registry、owner handle 和 actor write policy 传给 binding invocation；
- unload 时释放 binding package 和 scratch。

现有手写 host imports 继续工作。生成式 binding 与旧 ABI 可以在迁移期间并存，但普通新增 UE API 的默认扩展路径已经不再需要修改 VM enum 和 Runtime switch。

## 真实生命周期验证

P42.4 使用真实 WASM fixture 导入生成的：

```text
avidscript.avid_ue_e493dae7c6aae6c7
```

该 import 对应：

```text
/Script/Engine.Actor::SetActorScale3D(
  void;
  NewScale3D:value:struct:/Script/CoreUObject.Vector
)
```

测试流程为：

1. 由默认 UE Reflection selections 生成 descriptor。
2. Runtime 加载 descriptor 并构造包含 8 个 binding 的缓存 package。
3. 创建真实 Game world、初始化 actors for play，并生成 Authority Actor。
4. 把 RootComponent 注册到 slot 1，把 Actor 注册到 slot 2，证明调用不依赖硬编码 owner slot。
5. 直接通过缓存 package 调用 `SetActorScale3D`，验证通用参数 frame。
6. 在只读 host context 中加载同一 WASM，BeginPlay 以 `binding_write_denied` 失败，Actor 状态不变。
7. 在可写 host context 中重新加载同一 package。
8. WASM BeginPlay 读取 owner slot/generation，调用动态 reflected import，把 Actor scale 从 `(1,1,1)` 改为 `(2,3,4)`。

定位过程中确认了一个重要 UE 语义：`SetActorScale3D` 的反射函数带 `BlueprintAuthorityOnly`。未调用 `InitializeActorsForPlay` 的测试世界会让 `ProcessEvent` 按 callspace 规则吸收调用，而原生 C++ 直调仍会成功。最终测试改为真实 Authority 世界，生产 binding 层不绕过 UE 权限与网络语义。

## 当前可以做到什么

底层执行链已经成立：

```text
Binding Descriptor
  -> Runtime immutable package
  -> WAMR dynamic raw import
  -> cached reflected invocation
  -> UObject handle resolution
  -> ProcessEvent
  -> UE Actor state change
```

这意味着 AvidScript 已经具备“生成式 UE API 可以在 WASM BeginPlay 中真实执行”的核心技术闭环，不再只是 facade 或静态语义验证。

## 下一阶段

P42.5 需要把这条底层闭环接入正式自定义 C# profile：

1. 根据 C# 使用的 generated imports 选择并验证 binding package。
2. 把 descriptor/package hash 写入 Guest IR、WASM manifest 和 build report。
3. 编译阶段验证 required imports 属于授权 package。
4. Editor bind/reload 时事务式加载对应 package。
5. 让用户编写的 C# `BeginPlay`、`Tick` 和 gameplay event 直接使用生成 facade。
6. 删除 `ASBI4201` 对已具备完整绑定包的自定义 profile 阻断。

在 P42.5 完成前，P42.4 的执行能力已经通过真实 fixture 验证，但普通用户还不能只创建一个任意 C# profile 就自动获得这套 generated binding。
