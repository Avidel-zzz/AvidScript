## 当前可实现的工作流

现在 PC Editor 侧已经具备以下最小闭环：

1. 写 C# 生命周期脚本。
2. 运行 `BuildCSharpActorLifecycle.ps1` 生成 direct ABI WASM、manifest 和 report。
3. 在 Editor 中选中目标 Actor。
4. 调用 `FAvidScriptEditorComponentBindingService::ApplyCSharpReportToSelectedActor`。
5. Actor 获得 `UAvidScriptComponent`，组件保存 C# manifest 路径。
6. PIE/BeginPlay 时组件加载 C# WASM，执行 `BeginPlay` 和 `Tick` 游戏逻辑。

## 剩余风险

- 目前还没有用户可点击的菜单/按钮来调用 C# report 绑定服务。
- C# source adapter 仍是受限子集，仅覆盖当前 Actor lifecycle sample。
- Editor selection 服务当前只使用第一个选中 Actor，批量绑定留给后续阶段。
- 移动端与 packaged C# 产物策略仍未验证。

## 下一阶段建议

Phase 17 应该把该服务做成真正可用的 Editor 入口：例如 LevelEditor 工具菜单或轻量 command，让用户选择/使用最新 C# report，并把结果绑定到当前选中 Actor。该阶段也应补充面向用户的 C# 使用说明。
