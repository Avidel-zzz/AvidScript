# 仓库策略

## 边界

- `Plugins/AvidScript` 是独立 Git 根；模板工程根不是本插件的 Git 根。
- Git 命令、Diff、暂存、提交和远端操作都从插件根执行。
- 默认分支为 `main`。未经用户明确要求，不提交、不推送、不改写历史。
- `C:\UnrealEngine` 是 UE5.8 源码引擎根；工程文件位于插件根的 `../../AvidTPSTemplate.uproject`。

## 文件所有权

- `Source/` 保存 UE 模块；`Tools/` 保存 C# 前端、Guest IR 和生成工具；`Build/` 保存受控入口；`Docs/` 保存中文设计与阶段证据。
- `Binaries/`、`Intermediate/`、`Saved/`、`DerivedDataCache/`、工具缓存和机器日志不得进入 Git。
- 第三方源码、许可证、集成元数据和有意维护的样例可跟踪；下载缓存、构建目录和本机设置不可跟踪。
- 新文件先确认 owner 模块和依赖方向。禁止为了方便把 VM、Binding、Runtime、Editor 或工具链实现堆进同一模块。
- 拆分或新增 UE cpp 时考虑 Unity Build 会合并翻译单元：共用 helper 保持单一定义，私有 helper 使用领域限定名；同一命名空间下的匿名命名空间不能防止跨 cpp 重定义。不通过关闭 Unity 或清理 target 绕过命名冲突。

## 工作树

- 编辑前读取 `git status --short --untracked-files=all`，把已有变化视为用户或当前 Phase 的资产。
- 不回退、不覆盖、不格式化与任务无关的变化。相关文件已有改动时，先读完整 Diff，再在其上工作。
- 暂存必须使用精确路径白名单；提交前再次检查 staged Diff、未跟踪文件、凭据和机器路径。
- 生成内容应由 owner 工具产生。不要用临时字符串替换模拟结构化生成器。

## 检索

- 文件发现优先 `rg --files`；内容发现优先 `rg -n` 或 `rg -F`。
- 目标路径必须来自仓库索引。不要猜测概念命名的头文件、测试项目或样例路径。
- Windows 路径通配符放入 `rg -g`，不要把 `*` 作为待打开的字面路径。
- 一个 shell 调用只产生一个逻辑动作或证据域；独立读取用并行工具或拆分调用。

## 文档

- 面向人阅读的计划、实现、验收、使用和事故说明默认使用中文。
- API、类型、命令、路径、日志和源码标识符保持原语言。
- 文档只记录稳定决策、实现结果、验证证据、限制和下一步，不复制大段历史日志。
